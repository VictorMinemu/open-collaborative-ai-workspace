## Phase Goal

See 07.18-01 (the hub). **This plan's slice:** on the device, ChatGPT accounts for Codex live in account slots, one
`CODEX_HOME` each, signed in through Codex's own device-code login (started from Settings through the server, or from
the terminal), and the daemon tells the server which slots it has. Tokens stay in each slot's `auth.json`, refreshed by
Codex itself; nothing about them leaves the device.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → daemon | `account.login` / `account.logout` commands |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.18-08-01 | Information disclosure | ChatGPT tokens leaving the device | high | mitigate | The daemon never reads `auth.json`; frames carry label, plan, usage only (tests) |
| T-07.18-08-02 | Information disclosure | e-mail in frames | medium | mitigate | `readCodexAccount` drops it; frame schema has no e-mail field |
| T-07.18-08-03 | Tampering | removing a slot deletes shared history | high | mitigate | Links unlinked before the directory is removed; test asserts the default `sessions/` survives |
| T-07.18-08-04 | Information disclosure | other local users reading slots | medium | mitigate | Slot directory 0700, `slots.json` 0600 |
| T-07.18-08-05 | Denial of service | many slots or parallel logins | low | mitigate | 10 slots per device; one login per slot |
| T-07.18-08-06 | Information disclosure | the user code in logs or ack errors | medium | mitigate | Never logged; stripped from failure messages |
</threat_model>
