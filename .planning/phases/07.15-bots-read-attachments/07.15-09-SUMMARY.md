# Phase 07.15 Plan 09: Attachments in bot DMs, proven in the browser Summary

**The paperclip is on in personal and team bot DMs, and a 15-test Playwright spec (desktop and 390 px phone) proves that the bot reads images, PDFs and CSVs, refuses images on text-only models, answers files-only messages, stays inside the thread in channels and copies files into its sandbox. The e2e fake cell answers for the bot through `/attachments/read`.**

## Accomplishments

- `dm-view.tsx`: `canAttach = !disabled && !deactivated && !dm.archivedAt`. The bot term is gone, and the comment points to 07.15 / ADR-0037. Bot DMs use the same composer, limits and presigned upload path as person DMs.
- Fake cell (`e2e/support/fake-cell-plugin.ts`):
  - `withAttachmentIds` turns `{{attachment:N}}` into the turn's N-th file id for any tool. An index outside the list is never sent and reads `refused (not_found)`.
  - `attachmentRead` posts `{eventId, agentId, attachmentId}` to `/attachments/read` and renders `read <name>: <first content line>`, `image <name> (<mimeType>)` or `refused (<code>)`.
  - `turnAttachmentsSuffix` appends ` [attachments: name:access,…]` only on turns that list files, so other specs' replies are unchanged (PD-12).
  - `attachmentRequests` records each call. The header comments document all of the above.
- `bot-attachments.spec.ts`: 7 tests run on both projects: the owner's case, a text-only model, a files-only message, team bot DMs (E1 plus a turned-off bot and a deactivated person), a channel thread (SC2), a CSV in the sandbox (SC3) and long file names.
- UX fixes found by the new checks:
  - The paperclip is 44 × 44 on phones, and the composer is no taller.
  - The "Enter to send" hint passes axe contrast.

## Decisions Made

See `key-decisions`. In short:
- The touch target is fixed at its source in the shared composer, but only for the control this phase turns on.

- The order assertions accept both upload orders, because PD-04's "upload order" is a race when two files are dropped together.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Accessibility] Paperclip touch target 32 px on phones**
- **Found during:** Task 3. The plan asks for at least 44 × 44 on mobile.
- **Issue:** the composer's paperclip is `size-8` (32 px) at every width.
- **Fix:** `max-md:size-11 max-md:-my-1.5` in `composer.tsx`. The 44 px box overlaps the composer's 6 px padding, so the row height is unchanged. This affects every chat composer on phones (hit area only). The AI chat composer is a separate component and is unchanged.
- **Files modified:** apps/web/components/chat/composer.tsx
- **Verification:** the spec measured 32 → 44 on the mobile project. The 390 screenshots show the row height unchanged.
- **Committed in:** a41ecc08

**2. [Rule 1 - Accessibility] Composer hint fails axe contrast**
- **Found during:** Task 3, while running axe on the DM view.
- **Issue:** `text-muted-foreground/80` at 11 px measured 3.61:1 on white (`#86868d`). The hint is desktop only and also exists in `ComposerHint` for channels.
- **Fix:** dropped `/80` in both places.
- **Files modified:** apps/web/components/chat/dm-view.tsx, apps/web/components/chat/composer.tsx
- **Verification:** axe passes on the DM view in light and dark on both projects.
- **Committed in:** a41ecc08

**3. [Test correction] Turned-off bot's DM**
- The plan says "a disabled team bot's DM shows it disabled". In the product, disabling a bot archives its DMs (03.1 D-04), and the DM opens as "This chat isn't available" with no composer.
- The spec asserts that behaviour: `dm-missing`, no composer, no paperclip. No product change.

**4. [Test correction] Order of two dropped files**
- Two files dropped together upload in parallel, so the turn may list `invoice.pdf` before `photo.png`.
- The suffix assertion accepts either order. The positional reads `{{attachment:0}}` and `{{attachment:1}}` still read both files.
- Seen once on desktop. No product change: the listing order is the upload order, as PD-04 says.

**5. [Test robustness] Drop before the drop zone is armed**
- A drop dispatched right after navigation can land before the attachments config arms the drop zone. `addFiles` now waits for the paperclip first.

**6. [Scope] PDF fixture and extra coverage**
- The PDF is built inline in the spec, a one-page Helvetica text object with an xref. The minimal PDF in `attachments.spec.ts` has no text, and e2e does not import `apps/api` test helpers.
- Extra checks beyond the plan:
  - the 25 MB refusal in the bot DM tray, as E1's "same limits";
  - a deactivated person's DM (must_haves);
  - a long-file-name test (the orchestrator's 390 requirement);
  - the delivered mention's empty `message.text` for E2.

**7. [Process] Commit granularity**
- Task 1 is one `feat` commit, not separate test and feat commits. The unit tests and the spec depend on the fake-cell code they test. RED was still run and observed before GREEN, as recorded under Task Commits.
