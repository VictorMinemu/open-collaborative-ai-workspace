# Phase 07.17 Plan 17: One bot turn per opened item, and the per-order journey Summary

**Each item a fan-out run opens now gets its own `agent.automation_item.v1` turn in its own card's thread. The turn runs as the automation's run-as person, starts tainted and is unattended, and it is offered the bot's 07.16 Work Zone tools. A retry never creates a second turn, because the event id is derived from the item. An integration test proves the whole per-order flow at the API: session, card moves, wake and `@logistics`.**

## Intended change (CLAUDE.md plan mode, PD-03)

The plan touches permissions, policy, audit and tenant data. This is the change, stated before the work:

- **New trigger.** Item turns use `trigger: "automation_item"`. They are unattended like a run (no browser tools, no attachment listing). They get the Work Zone offer through 07.16's `workZoneOfferFor`, unchanged, with the run-as person as the asker and `tainted: true`. Run turns (`trigger: "automation"`) still never get Work Zone tools. `ocw_conversation_open` stays limited to run deliveries.
- **New delivery.** It reuses `buildMentionEvents` and `turnPolicy` with no new decision code. It re-checks the bot (live and a member), the run-as person's read access (`isReadable`, kinds `["channel"]`) and the root, and records a skip with its reason otherwise.
- **Unchanged.** No permission check, RLS policy, cap or approval gate changes. Starting a session still goes through the 07.16 start route (the flag path or the proposal), and card moves still go through plan 08's gate. Audit rows and job payloads carry ids only.

## Accomplishments

- `automation-items.ts` mirrors `deliverAutomationRun`:
  - It locks the item row and does nothing unless the row is still `queued`.
  - It runs the PD-09 checks in order: `paused`, `agent_disabled`, `agent_not_member`, `bot_not_readable`, `target_not_postable`. If no event is built, the reason is `agent_daily_limit`.
  - It reads the item from the root: the card's title and description, or the channel message's body.
  - It builds the turn with `buildMentionEvents`, appends `agent.automation_item.v1` (with the escalation views) to `cell:<org>`, marks the row `delivered` with the event id and audits `automation.item_delivered`.
- `fan-out.ts` gets three additions:
  - `itemEventId`: a UUID v8 from the SHA-256 of `automation_item:<itemId>`, built the same way as the 07.16 wake ids.
  - `deliverItemJob`: finds the item with no user, then delivers as the run-as person. A refusal is recorded as a skip with its reason; any other error is retried.
  - `registerFanOutWorker`: `automation.item` with `localConcurrency` 3, registered next to `registerRunner`.
- `mentions.ts`: `automation_item` is unattended and gets the Work Zone offer. The consult offer and the open-tool offer stay off for it (the turn is tainted, and only run deliveries get the open tool).
