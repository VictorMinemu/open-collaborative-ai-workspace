# Phase 07.15: Bots read attachments - Research

**Researched:** 2026-11-07
**Domain:** Agent Channel API (bot turns, tools, taint, audit), chat attachments (Garage, ADR-0015), OpenClaw 2026.9.7 cell plugin, server-side text/PDF extraction
**Confidence:** HIGH for the codebase seams (read this session); MEDIUM for the PDF library and the OpenClaw media path (probed or doc-read, not run in a real cell)

## Summary

Almost all of the plumbing exists. Attachments are rows in `app.attachments` that point to a message, stored in Garage
under id-only keys. `artifact/index.ts` already exports server-side byte reads (`readAttachmentBytes`,
`attachmentRowsForMessages`). AI chats already classify files and wrap text as untrusted (`ai-chat/attachments.ts`:
`aiAttachmentKind`, `untrustedFileBlock`, `labelName`, a strict UTF-8 decode). `ocw_sandbox_import` was **already
built in 07.8-25**: it copies a conversation attachment into the bot's workspace under the F-8 `audienceCovers` rule.
Bots cannot use it today only because no turn tells them the ids. The phase is mainly about three things: put the
attachment metadata on the turn, add one API-decided read tool, and turn on the paperclip.

**Images should go through the tool, not OpenClaw's native inbound media.** The pinned OpenClaw 2026.9.7 has a native
`media` field on the inbound context. It writes the bytes to a temp file in the cell, can run "media understanding"
through other configured providers (`tools.media.*`) and copies files into OpenClaw's own sandbox. That bypasses the
per-call decision, the audit and the taint. ADR-0029 spike (ii) already proved the other path in a real cell: a tool
result `{type:"image"}` reaches the model when the model is declared `input: ["text","image"]`. That is what
`ocw_browser_screenshot` uses, so `ocw_attachment_read` returns images the same way.

PDF text: use **`unpdf`** (MIT, zero dependencies, ships a serverless PDF.js build with the worker inlined). This
session confirmed that it extracts text on Node 24.22.1, both directly and inside a `worker_threads` Worker. It parses
on the event loop, so extraction must run in a Worker with `resourceLimits`, a timeout that ends in `terminate()`, a
page cap and an output cap. Pass `isEvalSupported: false` and `verbosity: 0`.

**Primary recommendation:** add an optional `TurnContext.attachments` (metadata only, decided per bot in
`turnPolicy`) and a new self-validated, non-approvable tool `ocw_attachment_read` (route `POST
/agent-channel/v1/attachments/read`). It returns extracted text or an image, taints the turn, and counts against its
own per-turn budget stored in two new additive `agent_turns` counters. Also tighten the existing `ocw_sandbox_import`
precheck: only files linked to a live message, and in a channel only files in the turn's thread. Then remove the `!bot`
gate in `dm-view.tsx`.

## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Where people can attach
- **D-01:** The paperclip is enabled in personal and team bot DMs, channels and threads where bots answer, and AI chats
  with personas (already allowed), with the existing size/type limits and upload path (presigned, API as the only ACL,
  ADR-0015). Remove the `!bot` gate in `dm-view.tsx` only together with the bot-side reading (no paperclip that the bot
  ignores).

#### How the bot gets them
- **D-02:** The turn the API hands to the cell (the claim / turn context) lists the attachments of the messages the turn
  reads, as metadata only (attachment id, file name, media type, size, message id), decided server-side: the attachment
  belongs to a message in the conversation this turn answers, and the asker can read it (agent ∩ human, the existing
  conversation readable set). Never another conversation's files.
- **D-03:** Content is fetched by the bot through Agent Channel tools decided in the API (never Garage or presigned URLs
  in the cell): `ocw_attachment_read` (returns extracted text for text-like types, or the image for image-capable models,
  with caps) and an import into the sandbox workspace (extend `ocw_sandbox_import` if it fits, else a new
  `ocw_sandbox_import_attachment`). Research decides whether images should instead ride OpenClaw's native inbound media
  for vision models (ADR-0029 spike (ii): images from a plugin tool reach the model only with image input).
- **D-04:** If the bot's model cannot read a type (no image input, unsupported document), the tool answers with an
  explicit, human-readable reason so the bot tells the person; the turn context also says so.

#### Extraction
- **D-05:** Server-side in the API (or a worker it owns), never by executing the file: plain text, Markdown, CSV, JSON,
  source code, and PDF text via a pure-JS extractor with a time limit, page limit and output cap; character set
  detection for text. Caps (defaults, tunable): 64 000 characters per file, 200 000 per turn, 20 attachments per turn.
  Any new dependency passes the license guard (permissive only).
- **D-06:** Extraction results may be cached per attachment version (sealed or plain is a research question: attachment
  bytes are already in Garage under the same ACL); cache never widens access.

#### Rules
- **D-07:** Every read and import is audited (`bot.attachment_read`, `bot.attachment_imported`: actor/agent/user,
  conversation, attachment id, media type, bytes, outcome) without content.
- **D-08:** Attachment content is untrusted input: a read taints the turn like other third-party content (ADR-0026 taint
  rules), so changing-data tools need approval afterwards where those rules say so.
- **D-09:** Results stay in the conversation (F-8, ADR-0029): an imported file in the sandbox is subject to the
  workspace's audience rules; a personal bot's workspace receives only files from conversations its owner reads.
- **D-10:** Tenant isolation and the audience rule are proven by tests (another org, another conversation, a member who
  left, a deleted message/attachment).

#### Upgrade
- **D-11:** No data migration unless research finds the turn context needs a stored field; existing attachments become
  readable to bots from the upgrade on, under these rules. `ocw upgrade` is enough.

### Claude's Discretion
- Tool names and shapes; where extraction lives; the PDF library choice (permissive license); caching.

### Deferred Ideas (OUT OF SCOPE)
- OCR for scanned PDFs and images of text; audio/video transcription.
- DOCX/XLSX/PPTX extraction unless a reliable permissive pure-JS path exists (otherwise: import to the sandbox, where the
  bot's tools can convert them).
- Bots attaching files to their own replies (Phase 12 artifacts).

### Pattern 1: Attachment metadata on the turn (BRA-02, D-02, D-04)

**Where:** `buildMentionEvents` already loads `historyRows` (≤ `HISTORY_LIMIT = 50`, `deletedAt` null) and runs in the
message's transaction, after `postMessage` has linked the attachments. Add one `attachmentRowsForMessages(tx,
[mention.messageId, ...historyRows.map(m=>m.id)])` per mention. Then, **per bot** inside the loop, pass the rows to
`turnPolicy`, which writes `turn.attachments`.

The contract is additive and optional, so older plugins parse it:

```ts
// packages/contracts/src/bot-capabilities.ts (sketch; names are discretion)
export const TurnAttachmentKind = z.enum(["image", "text", "pdf", "other"]);
export const TurnAttachment = z.object({
  id: Id, messageId: Id,
  name: z.string().max(255),            // sanitized at upload; labelName() again in the plugin
  mediaType: z.string().max(127),
  size: z.number().int().nonnegative(),
  kind: TurnAttachmentKind,
  /** How this bot can read it here: "read" (ocw_attachment_read), "import" (sandbox only), "none". */
  access: z.enum(["read", "import", "none"]),
  /** Fixed server sentence when access ≠ "read" (e.g. "This bot's model can't see images"). */
  note: z.string().max(200).optional(),
});
// TurnContext: attachments: z.array(TurnAttachment).max(20).optional(),
//              maxAttachmentReads / maxAttachmentChars: z.number().int().optional()
```

Rules:
- Newest first, the current message's files first, at most 20 (D-05). Say "N more files earlier in this conversation"
  in the block when there are more.
- `access` is decided per bot. An image is `read` only if `modelAcceptsImages(bot.modelProvider, bot.modelId)`. A text
  or PDF file is `read` always. `other` (zip, docx, xlsx, …) is `import` when the sandbox tools are offered on this turn,
  otherwise `none` with a note. D-04: the turn says so up front.
- The plugin renders one context block, `{label: "Attachments in this conversation", type: "attachments"}`, with
  one line per file (id, name, kind, size, message id, and the note) plus one fixed sentence: "Read one with
  `ocw_attachment_read`; copy one into your sandbox with `ocw_sandbox_import`." It also tags the matching `chat_window`
  entries with `attachments: [names]`. Never put file content in the turn.
- **A files-only message has `body: ""`.** Keep `message.text` as it is (structural rule, ADR-0019). The plugin uses a
  fixed body when the text is empty (`"(sent N attachments; see the Attachments block)"`) so OpenClaw has something to
  answer. [ASSUMED: how OpenClaw 2026.9.7 handles an empty `bodyForAgent`; check in the real-cell smoke.]
- Applies to `agent.mention.v1`, reply-mode and AI chat persona deliveries (all go through `buildMentionEvents`). Card
  actions, automation runs and consult replies carry none (out of scope).

### Pattern 2: `ocw_attachment_read` route (BRA-02, BRA-04, D-03, D-07, D-08)

Mirror `memory-files.ts`: a cell route, `withTenant({organizationId: cell.organizationId, userId: null})`, refusals
returned as `{refused: code}` with a 200 so the bot gets a sentence. `no_trigger` stays 403, as on every Agent Channel
route. Order:

1. **tx1**: `liveTurn` (the agent's delivered turn, and its human still reads the conversation; a thread is judged
   through its parent) → `ocw_attachment_read` is in `turn.tools`, else `policy_changed` → the row rule:
   - `row` exists under RLS (another org: absent → `not_found`), `row.conversationId === turn.conversationId`,
     `row.status === 'ready'`, `row.messageId !== null`, `row.workPromptId === null`;
   - the message exists and `deletedAt IS NULL` (a message delete also sets the attachment's status to `deleted`,
     `chat/message-actions.ts:194`; check both);
   - **channel turns:** the message is in the turn's thread (`message.id = root OR message.threadId = root`, where
     `root = turn message's threadId ?? turn message's id`, derived from `agent_turns.message_id`, no new column). DMs,
     groups and AI chats are conversation-wide (flat).
   → kind and model check (`image` with no image model → `model_no_images`; `other` → `unsupported_type` with
   "import it into your sandbox"; text over the input cap → truncated, not refused) → **claim**:
   `claimToolCall(..., flags: {untrustedOutput: true, sideEffecting: false}, countCall: false, target: row.id,
   metadata: {attachmentId, conversationId, kind})`, plus the attachment budget in the same conditional UPDATE (see
   below).
2. **Outside any transaction**: fetch and extract (Pattern 3). Storage errors → `unavailable`. The extractor's own
   failures → `extraction_failed` / `timeout` / `encrypted`.
3. **tx2**: add the produced characters to `agent_turns.attachment_chars` (conditional, capped). Write
   `finishToolCall` and the **`bot.attachment_read`** audit: `actorKind: "agent"`, `agentId`, `userId`, `resourceType:
   "attachment"`, `resourceId`, `metadata: {eventId, conversationId, attachmentId, kind, mediaType, bytes, chars,
   truncated, pages?, outcome}`. Never the name, the text or a path.

**Budget (the stored field D-11 allows):** `MAX_TOOL_CALLS_PER_TURN = 8` cannot hold 20 reads. Add two additive
columns, `agent_turns.attachment_reads integer not null default 0` and `attachment_chars integer not null default 0`,
and count them in the claim's conditional UPDATE (`attachment_reads < 20`). Do not count the call against the cap of 8
(`countCall: false`). This is the race-free pattern `sandbox_calls` already uses (`agent_turns.sandbox_calls`, schema
`app.ts:706`). Since the characters are known only after extraction, reserve them up front: before the fetch, check
`attachment_chars < 200_000`; after extraction, cut the text to `min(64_000, 200_000 − used)`; then add. This is a
schema-only migration with defaults (no data migration), generated with `pnpm --filter @ocw/db generate`.
`schema-guard.int.test.ts` and the upgrade baseline must stay green.

**Taint (D-08):** `untrustedOutput: true` sets `agent_turns.tainted` and calls `taintReturnTurns` inside the claim.
Every side-effecting tool afterwards (`ocw_memory_save`/`write`, `ocw_board_card`, `ocw_sandbox_share`, consult,
proposals) is refused `tainted` unless an ADR-0026 grant covers it. Expected consequence, to state in ADR-0037: "read
this file and remember X" fails the memory write in that turn, as it does after a web fetch. The plugin guard sets
`t.tainted = true` locally (`flags.untrustedOutput`).

**Not approvable:** `isApprovableTool` admits only `ocw_http_request`, `ocw_record_update` and
`/^ocw_(sandbox|browser)_[a-z0-9_]+$/` (`packages/contracts/src/tool-approvals.ts:63-69`). **Do not name the read tool
`ocw_sandbox_*`.** `ocw_attachment_read` is automatically never approvable, which is right for a read of the
conversation's own file.

**Offered:** on every delivered turn whose conversation kind is `channel | dm | group | ai_chat` (and threads), while
object storage is configured, like `ocw_agent_card`, so a file from an earlier session turn can still be re-read. Also
add it in the cell-wide `assemble(…, null, …)` view so it lands in the bot's `alsoAllow` (`cellAgentCapabilities`).
Flags in `toolFlags`: `{untrustedOutput: true, sideEffecting: false}`.

### Pattern 3: Bounded extraction (D-05, D-06)

```ts
// apps/api/src/modules/artifact/extract/pdf.ts (sketch)
import { Worker } from "node:worker_threads";
const PdfResult = z.object({ totalPages: z.number().int(), pages: z.number().int(), text: z.string() });
export async function pdfText(bytes: Uint8Array, caps = { pages: 100, chars: 64_000, ms: 10_000, heapMb: 256 }) {
  const worker = new Worker(new URL("./pdf-worker.mjs", import.meta.url), {
    workerData: { data: bytes, maxPages: caps.pages, maxChars: caps.chars },
    transferList: [bytes.buffer],
    resourceLimits: { maxOldGenerationSizeMb: caps.heapMb, maxYoungGenerationSizeMb: 32 },
    execArgv: [],             // never inherit `--import ./src/telemetry.ts` / tsx
    stdout: true, stderr: true, // swallow PDF.js console output (it can echo document strings)
  });
```

- **Text kinds.** Sniffing stores `application/octet-stream` for anything without magic bytes (text, CSV, JSON, code),
  and `ACTIVE` types (HTML, SVG, XML, JS) are also stored as octet-stream (`artifact/sniff.ts`). Classify as `text` when
  `contentType` is `text/*` or JSON, **or** the declared type is `text/*` or JSON, **or** the extension is in a fixed
  allow-list (`txt md markdown csv tsv json jsonl yaml yml toml ini log xml html svg ts tsx js mjs py rb go rs java kt c
  h cpp cs php sh sql …`). Then the bytes must decode as text (no NUL in the first 8 KB, outside UTF-16). Browsers
  declare `.ts` as `video/mp2t` and `.csv` as `application/vnd.ms-excel` on Windows; bot-shared files have
  `declaredType = contentType = octet-stream` (`storeServerAttachment`). So the extension rule is required. SVG, HTML and
  XML are returned **as text, never rendered**.
- **Text decode:** `rangeGet(key, 256 KiB)` (64 000 characters ≤ 256 KiB in UTF-8). Then: BOM (UTF-8, UTF-16LE/BE) →
  `new TextDecoder("utf-8", {fatal: true})` on the slice with any incomplete trailing sequence trimmed (a range cut can
  split a character; decoding with `{stream: true}` then dropping the tail avoids a false "not UTF-8") → UTF-16 when the
  NUL pattern says so → `windows-1252`. Report `truncated` when `row.sizeBytes > bytes read` or characters > cap. Wrap
  the result with `untrustedFileBlock(name, text)`.
- **Images:** `large.webp` when `hasRenditions` (EXIF-free, ≤ 2048 px, made by sharp at upload; no decode at read time),
  else the original only for `INLINE_IMAGE_TYPES` up to `SANDBOX_LIMITS.previewImageMaxBytes` (5 MiB, the screenshot
  ceiling). Return base64 with `mimeType` (`image/webp` for renditions; Anthropic and OpenAI accept webp). Charge an
  image as one read and 0 characters.
- **PDF caps (defaults):** input ≤ `OCW_ATTACHMENT_MAX_BYTES` (25 MiB) read with `readAttachmentBytes(…, row.sizeBytes)`;
  100 pages; 64 000 characters; 10 s wall clock; 256 MB heap. Encrypted or invalid → `extraction_failed` with a fixed
  reason (unpdf throws `InvalidPDFException` / `PasswordException`; the former was observed in the probe). A scanned PDF
  (0 characters) → "this PDF has no text layer (scanned); OCR is not available".
- **Concurrency:** one in-process semaphore (2 workers per API process). When it is full, answer `busy` with "try again
  in a moment" instead of queuing without bound.
- **Cache (D-06):** **no persistent cache in this phase.** Optional: an in-memory LRU keyed by `attachmentId + sha256 +
  extractor version`, bounded (~8 MB of text), consulted only **after** the full decision of step 1, so a cache hit
  never skips an access check. Do not write derived text to Garage (that would add an `AttachmentPart`, sweeper purge
  and upgrade surface for no measured need).

### Anti-Patterns to Avoid

- **OpenClaw native `media` for images:** bytes would land on the cell disk, "media understanding" could call other
  configured providers (`tools.media.*`), and files would be copied into OpenClaw's own sandbox. None of it goes through
  the decision, the audit or the taint. Reject (see State of the Art).
- **Presigned URLs or Garage keys in the turn or the tool result:** never. The bytes travel in the API's response only.
- **Inlining file text into the turn context:** D-02 says metadata only, and D-08 needs the read to be a claimed,
  tainting call.
- **Importing `ai-chat` internals from `agent-channel`:** move the pure helpers to `artifact`, or go through the
  module's `index.ts`.
- **Extracting on the API event loop:** a crafted PDF would freeze every request.
- **Logging extraction errors with `err.message`:** PDF.js messages can quote document strings. Log `err.name` only, as
  the storage code already does.

## Common Pitfalls

### Pitfall 1: Text files look like `application/octet-stream`
**What goes wrong:** the bot is told "can't read this file" for a CSV or Markdown file.
**Why:** `file-type` has no signature for text, and ACTIVE types are downgraded on purpose (`sniff.ts`).
**How to avoid:** use the declared type plus the extension allow-list, then require a successful text decode.
**Warning signs:** test with `.md`, `.csv` (declared `application/vnd.ms-excel`), `.ts` (declared `video/mp2t`) and a bot-shared `.csv`.

### Pitfall 2: The local cap of 8 in the cell guard
**What goes wrong:** the 9th tool call of a turn is blocked by the plugin even though the API would allow it.
**How to avoid:** give the tool its own guard counter and `turn.maxAttachmentReads`; add a unit test in `tool-guard.test.ts`.

### Pitfall 3: Import precheck accepts unlinked uploads
**What goes wrong:** Alex uploads a file in a shared channel, never sends it, and a bot turn can import it by id.
**How to avoid:** one shared row rule (Pattern 2) for read and import; add a regression test.

### Pitfall 4: Worker inherits `--import tsx --import ./src/telemetry.ts`
**What goes wrong:** the worker boots OpenTelemetry, or fails under vitest.
**How to avoid:** set `execArgv: []` and write the worker as a plain `.mjs` file (the pattern this session's probe verified). Zod-parse the worker's message on the parent side.

### Pitfall 5: PDF.js console noise and eval
**What goes wrong:** PDF.js writes `console.warn` lines ("Warning: Indexing all PDF objects" was observed) that bypass pino. With eval allowed, CVE-2024-4367 class bugs apply.
**How to avoid:** `verbosity: 0`, `isEvalSupported: false`, `stdout/stderr: true` on the Worker. PDF.js ≥ 4.2.67 fixes CVE-2024-4367; unpdf 2.1.0 bundles 6.4.299 [CITED: unjs/unpdf README; GitLab advisory].

### Pitfall 6: Split multibyte character at the range cut
**What goes wrong:** a valid UTF-8 file over 256 KiB is reported as "not text".
**How to avoid:** trim the incomplete trailing sequence before the strict decode.

### Pitfall 7: Thread scope in channels
**What goes wrong:** a channel turn lists or reads files from unrelated threads of the same channel. Not a leak (the human reads the channel), but it breaks D-02 "messages the turn reads".
**How to avoid:** derive the root from `agent_turns.message_id` → `messages.thread_id ?? id`.

### Pitfall 8: Subscription models and images
**What goes wrong:** `modelAcceptsImages("openai-codex", …)` is `false` (fails closed). The owner's personal bots may run on the ChatGPT plan, so images will answer "can't see images" for them.
**How to avoid:** ship the explicit note (D-04). Treat enabling Codex image input as a separate, smoke-verified change (Open Question 1).

### Pitfall 9: Mirror drift
**What goes wrong:** the plugin's `agent-channel-protocol.ts` copy does not get `TurnContext.attachments`, so the plugin drops the field.
**How to avoid:** update both copies; `plugin-contract.test.ts` parses a fixture that includes the field.

### Pitfall 10: Taint surprises
**What goes wrong:** after a read, memory writes and board moves in the same turn are refused.
**How to avoid:** this is intended (D-08). Make sure the refusal sentence reaches the user, and cover it in a test (`attachments.int.test.ts`: read → `ocw_memory_save` refused `tainted`).

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Bot reads another conversation's or org's file by guessing an id | Information disclosure | RLS + `conversationId === turn.conversationId` + thread scope + live message; tests per D-10 |
| Reading a file still pending, unlinked (someone else's draft), deleted or a Work Zone image | Information disclosure | `status = ready`, `messageId` not null, `workPromptId` null, message `deletedAt` null (fixes the existing import gap) |
| Member removed from the channel mid-turn | Elevation | `liveTurn` re-decides at every call → `no_trigger` |
| PDF bomb / pathological PDF (deep objects, huge streams) | DoS | Worker `resourceLimits`, 10 s `terminate()`, 100 pages, 25 MiB input, 2 concurrent |
| PDF.js code-execution class bugs | Elevation | `isEvalSupported: false`; PDF.js ≥ 4.2.67; isolated worker without app secrets in `workerData` |
| Zip bombs (docx/xlsx) | DoS | Not extracted in the API (deferred); imported as opaque bytes to the sandbox (quota-bound) |
| Image bombs | DoS | Rejected at upload (`ImageTooLargeError`); reads serve the stored rendition only |
| Prompt injection via file content | Tampering | Labelled untrusted block; read taints the turn → side-effecting tools refused unless an ADR-0026 grant covers them; never merged into instructions |
| Content leak in audit/logs/activity | Information disclosure | Audit metadata without name/content/path; a leak test asserting the file's marker string appears in no audit row and no log line |
| SSRF | — | None: no outbound URL; bytes come from Garage with server credentials |
| Data moving to a wider audience (workspace) | Information disclosure | F-8 `audienceCovers` on import. **Residual (documented in ADR-0037):** a bot can `ocw_sandbox_write` text it read, the same as message text today; not new |
