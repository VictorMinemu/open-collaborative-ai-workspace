## Phase Goal

**As a** member of a team that works in the workspace, **I want to** hold my whole daily conversation there — channels grouped by department and team, DMs and group DMs with people and bots, messages I can edit, delete, react to, pin, save and link to, @channel/@here and notifications I control, search and files — **so that** I do not need a second chat tool and every message stays attributed, editable under audit and delivered in realtime.

**This plan's slice (tracer):** drop an image on a channel → progress → send → the other member sees the preview live and opens it in a lightbox (composer → presign → Garage → complete → POST message with `attachmentIds` → `message.created` with attachments → message grid). Planner decisions P-01 … P-12 are in `04-01-PLAN.md` (P-05, P-08, P-09, P-10).

Output: message linking and hydration, `lib/upload.ts`, attachment components, composer integration, `message-attachments.int.test.ts`, `e2e/tests/attachments.spec.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /conversations/:id/messages` (`attachmentIds`) | Untrusted attachment ids |
| browser → Garage (presigned PUT) | File bytes leave the browser directly to storage |
| API/Garage → browser (previews) | Image renditions rendered in the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-12-01 | Elevation of privilege | linking someone else's or another conversation's attachment (IDOR) | high | mitigate | `linkAttachments` requires same uploader, same conversation, status ready, unlinked; 409 otherwise; int tests |
| T-04-12-02 | Tampering | malicious file rendered inline | high | mitigate | Only webp renditions are shown as images; originals only via attachment-disposition download (Plan 04 sniffing); file cards never embed content |
| T-04-12-03 | Information disclosure | downloads after delete | medium | mitigate | Delete marks attachments deleted (04-01); download/preview 404; test |
| T-04-12-04 | Denial of service | huge or many files from one composer | low | mitigate | Client checks + server limits (size, 10 per message, presign rate limit) |
| T-04-12-05 | Spoofing | preview URLs pointing elsewhere | low | mitigate | URLs are API-relative paths from the DTO joined with the configured API base; the API redirects only to the configured storage endpoint |
</threat_model>
