# Phase 07.17.1.1 Plan 06: The two bot file limits in the API Summary

**The organization's "largest file a bot moves" (25 MiB default, capped by `OCW_ATTACHMENT_MAX_BYTES`) and the bot's own narrower limit are stored, validated, audited and shown with their ceilings; `loadBotFileLimit` computes the applied limit (lowest wins, source named).**

## Performance

- **Duration:** about 25 min
- **Tasks:** 2 (TDD, RED and GREEN commits each)
- **Files modified:** 5

## Accomplishments

- `GET /api/v1/work-zone-policy` answers `botFileMaxBytes` (26214400 when never saved) and `serverFileMaxBytes`. `PUT` saves it, audits `work_zone_policy.updated` with `botFileMaxBytes` in `changed` (once), and refuses a value above the ceiling with 400 `invalid_work_zone_policy`, `details.field: "botFileMaxBytes"`, message "Bots can move files up to 50 MB on this server". Nothing is written, not even the other keys in the same body.
- `PUT /api/v1/agents/:id/work-zone-profile` stores `fileMaxBytes` (null = the organization's). A value above the organization's limit gets 400 `invalid_work_zone_profile`, field `fileMaxBytes`, "At most 25 MB, the organization's limit.". A body without the key keeps the stored value. The view has `profile.fileMaxBytes` and `limits: { organizationFileMaxBytes, serverFileMaxBytes }`.
- `loadBotFileLimit(tx, profile, serverMaxBytes)`: bot 10 / org 25 / server 1 GiB gives `{ 10 MiB, bot }`; a 5 MiB server gives `{ 5 MiB, server }`; the organization lowered to 5 MiB gives `{ 5 MiB, organization }` while the profile still stores 10 MiB; no profile gives the organization's value. It is not exported from the module's `index.ts` (07 owns it in this wave; 11 exposes it).

## Decisions Made

- Only an explicit body value is checked against the organization's limit. Re-checking a kept stored value would make an older client's unrelated save fail after the organization lowered its limit. The lower limit still applies at every call.
- `limits` is on the empty view too, so plan 09's form can offer the field before the first save.
- The policy's above-ceiling 400 carries `details.field` with the profile's `invalid()` shape (the plan's fallback, because the existing policy 400s carried no field).
