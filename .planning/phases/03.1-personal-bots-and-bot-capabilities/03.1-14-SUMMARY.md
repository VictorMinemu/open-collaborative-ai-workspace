# Phase 3.1 Plan 14: Sandboxed stdio MCP servers bridged to HTTP (optional compose profile) Summary

**Landed.** Vetted, pinned stdio MCP servers now run only in a separate, hardened `ocw-mcp-sandbox` sidecar. A ~300-line bridge built on the official SDK 1.30.0 transports (`StdioClientTransport` ↔ `StreamableHTTPServerTransport`) exposes each one to the cell as `http://mcp-sandbox:8080/<id>/mcp`.

The cell treats it like any remote MCP server. The 03.1-09/10 path is unchanged: probe, `toolFilter`, call-time gate, taint and `bot.tool_call` audit. No third-party MCP code runs inside the OpenClaw gateway container. This closes the stdio clause of BOT-08 (SC6 "cell-sandboxed stdio" option), pending the CI real-cell run.

## What was built

- **Bridge** (`bridge.mjs`):
  - Serves only the ids in `servers.json`. An unknown id returns 404 and spawns nothing.
  - One child per MCP session.
  - A session ends on DELETE, child exit, idle timeout or shutdown, and the child is killed with it.
  - At most 16 sessions; the 17th gets 503 with `Retry-After`.
  - Allowlist validation: refuses `npx`/`npm`/`uvx`/`pip`/`-y`, unsafe ids, loader-hijack env names and missing entry files. `node bridge.mjs --check` runs at image build.
  - `/healthz` endpoint.
- **Image** (`Dockerfile`):
  - Base `node:24.21.0-bookworm-slim` (the cell's base).
  - `npm ci --omit=dev --ignore-scripts` from the committed lock; files root-owned.
  - `USER node`, no `EXPOSE`, healthcheck on `/healthz`.
- **Supply chain.**
  - Exact pins; the SDK is 1.30.0, the same version as the cell and OpenClaw, with a single copy in the tree.
  - 107 packages, all with sha512 integrity from registry.npmjs.org.
  - Resolved with `--before=2026-09-28`. The newest package is `hono@4.13.9` (2026-09-24), 11 days old. `hono`, `@hono/node-server`, `ip-address` and `zod` match `pnpm-lock.yaml`.
- **Compose** (profile `mcp-sandbox`, off by default):
  - `user: node`, `read_only`, `cap_drop: [ALL]`, `no-new-privileges:true`, `init`, `pids_limit: 128`, `mem_limit: 512m`, `cpus: 1`.
  - tmpfs `/tmp` (`noexec,nosuid,nodev,size=64m`).
  - No ports, volumes, secrets or env.
  - Only network `mcp-sandbox` (`internal: true`), shared with `openclaw` alone. `openclaw` keeps `default`.
  - `api` gets `OCW_MCP_SANDBOX_URL` / `OCW_MCP_SANDBOX_SERVERS` (empty by default).
  - `compose.e2e.yaml` still validates; its `networks: !override` on openclaw is unaffected.
- **README:**
  - threat model, including the residual risk: children share one uid, so bake only servers you would trust together;
  - how to add a server (review, pin, lock with `--before`, allowlist, rebuild);
  - why runtime installs are forbidden;
  - how to enable the profile.
- **Smoke scenario `sandbox`.** Insert-only changes, plus a separate `sandbox_cleanup` in the EXIT trap, so it merges cleanly with other edits to the script. Contents are in "What CI cell-smoke must show".

## Deviations from Plan

**1. [Rule 2 - Security] Additions beyond the behaviour list.**
- Origin header refused (403).
- 4 MB request and child-message cap (413).
- Non-initialize POSTs are rejected before anything is spawned.
- The SDK's default inherited variables are stripped from the child.
- Child stderr is discarded.
- `--check` validation runs at image build.
- Compose sets `init: true`, `cpus: 1`, a size-capped `noexec` tmpfs and an explicit `user: node`.

**2. [Rule 3 - Blocking] The smoke builds the sandbox image when `SMOKE_BUILD=1`.** The plan selected the scenario only by `SMOKE_ONLY=sandbox` or an existing image. CI runs all scenarios with `SMOKE_BUILD=1` and no image, so the scenario would always have been skipped there. The local default run without the image still prints `SKIP sandbox (image not built)`.

**3. [Plan wording] The smoke gives the sidecar its own internal network**, joined by the cell, instead of putting it on the shared smoke network. This mirrors compose and proves the sidecar cannot reach the API. Subnet `SMOKE_SANDBOX_SUBNET`, default `10.231.76.0/24`.

**4. [Plan wording] Idle semantics.** An open SSE stream counts as activity (see Decisions). The test proves both halves.

**5. [Plan wording] Files outside the plan's list:** `infra/mcp-sandbox/.dockerignore` (keeps a local `node_modules` out of the build context).

**6. [Disk rule] No local image build.** 668 MB free is below the plan's 1 GB threshold. The plan says Task 2 slips in that case, but the coordinator assigned the real-cell proof to CI. So the scenario was written and committed, the bridge was proven in a real hardened container without building, and the CI run is the open item. Nothing slipped in code.
