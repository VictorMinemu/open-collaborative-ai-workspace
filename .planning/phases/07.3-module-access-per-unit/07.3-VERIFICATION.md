### Info notes (not gaps)

1. **Bot DM history stays readable by API while Bots is off.** `GET` on an existing bot DM conversation is decided by
   `channel.read`, not `bot.read`. The bot never answers, though: `chat/index.ts:506`. The DM is hidden in every web list
   and its deep link shows the off state (`dm-view.tsx:157-160`). This matches D-05 (3) and ADR-0024:70 ("hidden"), so it
   is by design. If the owner wants the API to refuse it too, that is a follow-up decision.
2. **The Settings "AI chat" account entry keys on `ai_chat.use`**, while its page gates on the module (`ai_chat.read`):
   `account-nav.ts:12` vs `settings/ai-chat/page.tsx:18`. Both hide when the module is off. With only a hand-written
   `ai_chat.use` deny, the entry hides but the page still renders. This is cosmetic and harmless.
3. **The card reads member roles for wording only** (`module-access-card.tsx:392`: "an admin" vs "an organization
   admin" in the read-only reason). Editability itself comes from the API's `canEdit`. This is not policy.
4. **A lead's unit-wide off reaches organization admins who are members of that unit.** This is intended and documented
   (ADR-0024 Consequences, DEMO.md) and pinned by `module-access.int:488`. The person-level ceiling (D-05 (1)) holds.
5. **The local `main` ref in this worktree is stale** (c2cad95, 2026-09-25). AGENTS.md was compared against
   `origin/main` (28e274b), which is the base the branch merged.
