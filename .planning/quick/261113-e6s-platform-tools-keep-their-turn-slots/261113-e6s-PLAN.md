# Platform tools keep their turn slots

## Problem (owner UAT, v0.3.2 on ocw.autofy.ing)

A bot with many organization MCP tools on (the 07.17 "enable all read/write" buttons) fills a turn's
`TURN_TOOLS_MAX` (128) inside `assemble()` (`apps/api/src/modules/bot-capabilities/turn-policy.ts`), because catalog
tools are added there up to the cap. Every turn-scoped platform tool added afterwards in `computeTurn` then finds no
room and is dropped silently:

- the six `ocw_work_session_*` tools (`kept + 6 <= MAX` fails) → the 07.5 proposal tools stay, so the bot proposes a
  session the person must Start ("Created by the workspace · Proposed", no outside-content notice);
- the sandbox (8) and browser (7) families (`assembled.tools.length >= MAX_TURN_TOOLS` → skipped) → "no background
  execution, no PDF tools";
- `ocw_task_start` (withheld `turn_full`), `ocw_attachment_read`, `ocw_consult_agent`.

## Fix

1. `packages/contracts/src/bot-capabilities.ts`: export `TURN_PLATFORM_RESERVE` = the number of turn-scoped platform
   tools `computeTurn` may add after `assemble` (SANDBOX_TOOL_NAMES + BROWSER_TOOL_NAMES + WORK_SESSION_TOOL_NAMES +
   TASK_TOOL_NAMES + attachment read + consult + conversation open; computed from the arrays, 27 today) and
   `TURN_CATALOG_TOOLS_MAX = TURN_TOOLS_MAX - TURN_PLATFORM_RESERVE`. Doc comment: why (organization tools never take a
   platform capability's place; 128 is the provider limit).
2. `assemble()`: catalog tools (the final loop over `catalog`, i.e. every non-platform name, including proxied logical
   names) stop at `TURN_CATALOG_TOOLS_MAX` total turn tools; platform tools added in `assemble` keep the plain
   `MAX_TURN_TOOLS` check. Result: after `assemble`, at least `TURN_PLATFORM_RESERVE` slots are free, so every later
   platform addition fits. Keep the existing eviction code paths (conversation open, task control) unchanged.
3. `toolsOverLimit` follows automatically (it uses `assemble`); update its doc comment.
4. `apps/web/components/bots/tools-section.tsx` warning copy: "A turn carries at most {TURN_CATALOG_TOOLS_MAX} tools
   from MCP servers and plugins, so the platform's own tools always fit. Turn off the ones this bot does not need."
   Update `tools-section.test.tsx`.

## Tests (failing first)

- Unit/int test in the existing turn-policy/capabilities suites: a bot with more usable catalog tools than
  `TURN_CATALOG_TOOLS_MAX` and an active Work Zone offer gets all six `ocw_work_session_*` tools and no
  `ocw_start_work_zone`/`ocw_work_zone_projects`; with the sandbox on it gets the sandbox family; `tools.length <=
  TURN_TOOLS_MAX`. Prefer extending `work-session-offer.int.test.ts` / `capabilities.int.test.ts` where a "full turn"
  fixture already exists.
- Update existing tests that assert the old 128-catalog fill (e.g. the PR #71 cap test, `toolsOverLimit` counts,
  task-offer `turn_full` cases): the expected counts move by the reserve. Do not weaken any permission assertion.
- `packages/contracts/src/bot-capabilities.test.ts`: reserve equals the sum of the arrays + 3.
