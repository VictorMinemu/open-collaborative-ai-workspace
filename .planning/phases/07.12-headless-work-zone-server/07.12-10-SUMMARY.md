# Phase 07.12 Plan 10: The headless Linux server proof in a clean container — Summary

**A clean `node:24.22.1-bookworm-slim` container, with only `curl git ca-certificates` added, installs the runtime from
the isolated API under dash as user `node`. `ocw-runtime setup --yes --service none` prints the link, the owner approves
it in the web, and the device comes online with `repo`. Sam starts a Claude Code session on it from the web and gets the
fake runtime's reply. The container's `doctor --json` shows 0 fail and leaks no token or home path, and `service install`
refuses with the own-supervisor line. The proof passed twice end to end.**

## What was built

- **`scripts/headless-server-proof.sh`** (opt-in, never in `pnpm verify`). Run it with
  `bash scripts/e2e-isolated.sh --cmd "bash scripts/headless-server-proof.sh"`. Linux hosts add
  `OCW_E2E_API_HOST=0.0.0.0`; Docker Desktop on macOS needs nothing more. Steps:
  1. Checks preconditions (docker, `OCW_E2E_API_URL`/`OCW_E2E_BASE_URL`, an explicit API port, `/health`, no
     container with the same name).
  2. Builds the bundle, then checks that `GET /api/v1/runtime/version` serves this exact sha. The API caches the first
     bundle it reads.
  3. Prepares the offline fake npm and the four pinned packages.
  4. Starts `docker run -d --init --name ocw-headless-proof-$$ --add-host host.docker.internal:host-gateway <pinned
     image> sleep infinity`.
  5. As root, runs `apt-get install -y --no-install-recommends curl git ca-certificates`.
  6. Checks that the container can reach `/health` (it fails with the `OCW_E2E_API_HOST` hint otherwise).
  7. Checks that `/bin/sh` is dash and creates a committed `~/work/repo`.
  8. Runs `curl …/install.sh | OCW_SERVER_URL=… OCW_INSTALL_ALLOW_HTTP=1 sh`.
  9. Requires exactly one npm call, carrying `--omit=optional --ignore-scripts`.
  10. Runs the Playwright `setup` project.
  11. Runs `docker exec -d -u node sh -c 'ocw-runtime setup --yes --name proof-server --project ~/work/repo --service
      none && OCW_RUNTIME_FAKE=1 OCW_RUNTIME_UPDATES=off exec ocw-runtime run'`.
  12. Polls `setup.log` for the `?pair=` link (90 s) and requires it to be on the workspace's web URL.
  13. Runs the proof spec, then checks that `setup.log` has `Registered` and `No service installed`.
  14. Prints the facts, removes the container, then prints `headless-server proof: ok` as its last line.

  On failure the trap prints the last 40 lines of `install.log`, `setup.log` and `run.log` and removes the container.
  `PROOF_KEEP_LOG=1` keeps those logs and the facts in a temp directory.
- **`e2e/proof/headless-server.proof.ts`** (skipped unless `PROOF_PAIR_URL` is set):
  1. The admin signs in and runs `approvePairingInUi`. The link must be on `BASE_URL`'s origin.
  2. It polls until `proof-server` is online with `repo` available (60 s). The platform must be `linux`, and the
     dialog must show `pair-connected`.
  3. `ensureMember` Sam, then `shareDevice(…, "acceptEdits")`.
  4. Sam opens `/work-zone`, picks New session › `repo` › Claude Code › Auto-accept edits and starts the session. It
     waits for `assistant-message` to contain "I'll start by reading", then for `session-view` `data-status="idle"`.
  5. `docker exec` runs `doctor --json`: exit 0, no `fail`, `pairing`/`server`/`daemon` ok, `service` warn, neither the
     device token nor `/home/node` in the raw JSON.
  6. `service install` exits 1 and contains "under your own supervisor".
  7. In `finally`: the session is archived and the device revoked through the admin API (200). The facts file is
     written there too.

  `docker exec` is only allowed into a container named `ocw-headless-proof-<pid>`.

## Deviations from Plan

### Auto-fixed / adjusted

**1. [Rule 3 - Blocking / executor safety rule] No real npm registry: an offline fake npm**
- **Issue:** The plan has the real npm install the pinned Claude Agent SDK in the container. This run's instructions
  forbid calling the real npm registry.
- **Fix:** For install.sh's command only, `/opt/ocw-proof/bin/npm` comes first on PATH. It is a small node script,
  written by the proof script and copied in with `docker cp` (no mount). It:
  - refuses anything but `install --prefix <abs> … --omit=optional --ignore-scripts <name>@<x.y.z>…`;
  - checks each exact pin against the package copied from this checkout's lockfile install (dereferenced, nested
    `node_modules` excluded, versions checked against the manifest);
  - copies those packages into `<prefix>/node_modules` and logs its argv.

  `npm_config_registry` points at the closed `127.0.0.1:9`, so the real npm, if it ran, could not reach a registry.
  The SDK that ends up beside the bundle is the real 0.3.282, and it loads: install.sh's `version` check and the
  daemon import it statically. The MCP and Anthropic SDK peers are copied without their own dependencies. That is
  enough here, because the fake runtime never loads them.
- **Effect:** install.sh's npm step is proven for its arguments and layout, not against a live registry. 06's unit
  tests and a real server install cover that.
- **Files:** `scripts/headless-server-proof.sh`

**2. [Rule 3 - Blocking] First-run setup before pairing**
- **Issue:** The API answers `503 setup_required` until the workspace exists, so `ocw-runtime setup` cannot start a
  pairing before Playwright's `setup` project has run.
- **Fix:** The script runs `--project setup` first, as `cell-proof.sh` does. It then runs the proof with
  `--project proof --no-deps` on the one file.

**3. Plan-text adjustments (no rule)**
- **One commit for both tasks.** Both tasks change the same two files and were proven by one end-to-end run. Splitting
  the commit would have left an intermediate state that was never run.
- **Sam's mode is `acceptEdits`** (grant and session). The plan only says "a Claude Code session". With `default`, the
  fake runtime's edit would wait for an approval.
- **Extra checks:**
  - the link's origin is the web URL;
  - the device reports `linux`;
  - the dialog shows "connected";
  - doctor exits 0;
  - the session is archived before the revoke;
  - `setup.log` has `Registered` and `No service installed`.
- **Isolation:** the stack ran on its own ports and projects. The plan's "verify" line counts on the wrapper, and the
  wrapper prints its own log path after the proof's ok line, so the script's last line is the ok line, not the
  wrapper's.
  - Throwaway `.env`: `node scripts/setup-env.mjs --ports 51 --project ocw-e2e-071210` (never read).
  - `OCW_E2E_API_PORT=4490 OCW_E2E_WEB_PORT=3490 OCW_E2E_FAKE_PORT=4491 OCW_E2E_STORAGE_PORT=4492
    OCW_E2E_STORAGE_PROJECT=ocw-e2e-storage-071210`.
