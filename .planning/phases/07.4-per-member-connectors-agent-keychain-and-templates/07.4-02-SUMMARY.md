**One drizzle migration (`20261013221007_connectors_keychain_templates`) gives all 07.4 data a home under forced tenant RLS. PostgreSQL itself refuses per-member modes on the stdio sandbox, malformed personal/unit keys, plaintext secret references, duplicate connections and duplicate active shares.**

- `mcp_servers`: `auth_mode` (default `org_secret`, so every existing server keeps today's behaviour),
  `member_header_name`/`member_header_prefix`, `oauth_scopes`, `oauth_status`; `auth_mode = 'org_secret' or

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `HEAD_ONLY` moved into Task 1**
- **Issue:** Without it, `upgrade.int` fails at the Task 1 commit, so `pnpm verify` is red.
- **Fix:** Appended the folder name to `HEAD_ONLY` in Task 1. Task 2 added the N-1 MCP-server assertions.
- **Commit:** 2f5321b3

**2. [Rule 1 - Bug] NULL hole in `vault_items_secret_ref_check` (found by the Task 2 test before any commit)**
- **Issue:** `secret_ref ->> 'provider' in (...)` is NULL for an object without `provider`, and a CHECK accepts NULL.
  `{"value":"sk-..."}` would have been stored.
- **Fix:** `coalesce(secret_ref ->> 'provider', '')`. The uncommitted migration folder was deleted and regenerated,
  so the name changed from `20261013220603_…` to `20261013221007_…` (never committed under the old name).
- **Commit:** 2f5321b3

**3. [Rule 3 - Blocking] `secret-ref-migration.int.test.ts` guard narrowed (file outside this plan's list)**
- **Issue:** The guard `not.toMatch(/model_providers|secret_ref/)` on every later migration fired on
  `vault_items.secret_ref`. Renaming the column would break the cross-plan contract (plans 07 and 10).
- **Fix:** The guard is now `/model_providers/`. Any statement that rewrites `model_providers.secret_ref` must name the
  table, so the guard keeps its intent.
- **Commit:** 2f5321b3

**4. [Rule 2 - Defence in depth] Extra database bounds mirroring the 07.4-01 contracts**
- Handle format, name lengths, template description length, injection is an object, `secret_ref` is a
  SecretReference object, `readers_at_grant >= 0`, `tool_grants` array <= 64, id arrays <= 16,
  `agents.template_version >= 1`, `oauth_status` values, and indexes on every new table's organization_id or
  lookup path.
- **Commit:** 2f5321b3

**5. Test expectation:** deleting a unit that still has keys raises `23001 restrict_violation`, not `23503`. The
expectation was corrected; the schema behaves as specified.

**6. TDD commit shape:** there are no separate RED commits, because the orchestrator requires `pnpm verify` to be
green before every commit. RED was shown locally:
- the RLS seeds failed on the missing `auth_mode` column;
- the constraints test failed on the `secret_ref` hole and the restrict code.
