## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Security] Composite foreign keys carrying the organization**
- **Found during:** Task 1
- **Issue:** The plan specified plain `references devices.id` / `secrets.id` / `accountPoolAccounts.id`. FKs bypass RLS,
  so a plain id FK would let a row point at another organization's device, secret or account; every table since 07.4
  uses composite keys for this reason.
- **Fix:** `account_pool_accounts_device_fk` (org, device_id) → devices cascade, `account_pool_accounts_secret_fk`
  (org, secret_id) → secrets `SET NULL ("secret_id")`, `work_sessions_pool_account_fk` (org, pool_account_id) →
  accounts `SET NULL ("pool_account_id")`, plus the target `account_pool_accounts_org_id_uq`. A test proves each refuses
  another organization's id. Same cascade and set-null behaviour as planned.
- **Commit:** 02e2a873, 4819b589

**2. [Rule 3 - Blocking] rls-isolation fixtures for the new tables**
- **Found during:** Task 2
- **Issue:** `rls-isolation.int.test.ts` requires a fixture row in `seedOrg()` for every org-scoped table (a Task 2
  verify command); the file was not in the plan's list.
- **Fix:** seeded a token account (with a `pool_token` secret), a device slot and a Claude policy per organization,
  and added a 07.18 case (forced RLS, seeded, cross-tenant zero, TRUNCATE refused).
- **Commit:** 4819b589

**3. [Rule 3 - Blocking] Snapshot formatting**
- `pnpm lint` flagged the generated `snapshot.json` format; formatted with Biome (no schema drift). Commit 62d2cddd.
