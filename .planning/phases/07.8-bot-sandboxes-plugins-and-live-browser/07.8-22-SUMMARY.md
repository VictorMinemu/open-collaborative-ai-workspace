# Phase 07.8 Plan 22: Live view of a bot's browser (desktop web) Summary

**A reader clicks Watch on a bot's browser step and sees the page live in a 320 px window that floats bottom-right,
drags and snaps to corners (keyboard too), survives navigation and closes without touching the bot. The large view lets
the member the bot works for take control, type, click, scroll and paste into the page, with the takeover bar, the
amber ring, the paste footer and the 9-minute "Still there?" warning; Hand back returns to watching. While they are in
control, every other reader sees "Private sign-in in progress" and receives no frame, and what they type reaches the
live-view socket and nothing else.**

## What the tests prove

- **Tracer:** Watch → `live-window` at right 16 / bottom 96 / 320 wide; `data-state` `connecting` then `live`; host
  `panel.fake.test`, chip "Live"; ≥ 3 new frame URLs in 3 s; one upstream stream on the fake; the announcement "Live view
  of Scout's browser opened. Press F6 to reach it."; F6 in and out; navigation to another channel keeps it live; Close
  removes it and the fake's stream closes (viewers 0) while the page stays open.
- **Control:** Expand → the fake's viewport 1280×800, Take control focused; Alex (not the requester) gets no Take control
  and "Only Sam Lee can take control here."; Take control → `controlling`, takeover bar, paste footer,
  `role="application"` + `aria-roledescription="remote browser"`, frame focused, Minimize hidden; typing raises the
  fake's key count; Escape stays in the page; Shift+Esc focuses Hand back, never sends Escape, and releases the Shift
  it sent; `page.clock.fastForward("09:01")` → "Still there? Control goes back to Scout in … s." + Keep control, which
  renews the lease; Hand back → toast "Scout continues.", `live`, the fake's takeover off.
- **Drag:** dropped near the left → `bottom-left` at x 256 (rail 240 + 16); still `bottom-left` after a reload; ArrowUp →
  `top-left` with "Moved to top left".
- **Takeover privacy (F-5, T-07.8-22-01):** while Sam controls, Alex's view is `private` with "Private sign-in in
  progress" and "Sam Lee is signing in. …", no frame image, and **zero binary frames** for 2.5 s while Sam's keep
  arriving; after Hand back Alex's frames resume.
- **Input never leaves the page (P-10, T-07.8-22-02):** Sam types and pastes `OCW-SENTINEL-TYPED-8842`. The typed key
  frames and one `{"type":"text"}` frame on Sam's live-view socket carry it; no other WebSocket frame of either page, no
  request body, no console message, no DOM text, no local or session storage does.
- **Performance (T-07.8-22-04):** 10 s at 8 fps: ≥ 40 frames drawn, **no long task over 50 ms**, at most **2** live blob
  URLs at any time.
- **A11y:** axe (no serious or critical) on `live-window` (live) and `live-expanded` (watching, in control, idle warning)
  in light and dark, and on each scripted state's window; `unnamedControls()` empty; icon buttons' names equal their

## Deviations from Plan

### Auto-fixed and added (Rules 1–3)

1. **[Rule 2] API and contracts (outside `files_modified`).** The plan needed facts the API did not send:
   - `LiveStateFrame.requesterName` (the watch-only line and "Waiting for {person} to sign in"), sent only with the page;
     a `no_permission` or private viewer never gets it (tested).
   - The live view's **heartbeat**: the plan's 20-second silence timeout assumed a periodic state frame; 16 sends states
     only on change and a static page sends no frame. `heartbeat()` resends each viewer's last state every 10 s.
   - `ActivityStep.contextOpen` ("whose context is open (server flag)"): computed in `chat/activity.ts` `activityFor`
     with one query over the list's context ids; never stored (tested). A cached reply keeps its flag until refetched;
     Watch on a page that closed meanwhile shows the Ended state.
2. **[Rule 2] Semgrep `ocw.live-input-logging` now covers `apps/web/components/browser/`** (`*.test.tsx` excluded),
   proven by a mutation.
3. **[Rule 1] Held modifiers.** Shift+Esc sends Shift down before the chord is recognised, and focus then leaves the
   frame, so the remote page kept Shift held. Modifiers (never characters) are now released on blur and on Shift+Esc.
4. **[Rule 1] The amber ring** was an inset ring on the frame area, hidden by the absolutely positioned image; it is now
   an overlay above it.
5. **[Rule 3] `bot-activity.tsx` and `message-list.tsx`** pass the reply's author (the bot) to the step rows so Watch
   can open the view with the bot's name and avatar.
6. **[Rule 2] Watch is 44×44 below 768** (`max-md:min-w-11`): the existing `bot-activity` mobile touch-target check
   would otherwise fail on browser steps now that Watch shows there.

### Plan text vs. what was built

7. **The sentinel's second literal** came in its own `test(e2e)` commit: the first version held it once, as `SENTINEL`.
8. **"Ana" is Alex.** The e2e actors are Sam, Alex and the admin; Alex plays the reader who is not the requester.
9. **`live-window-states-1440` is a composite** of the real window's markup per state (the app has no visual harness
   route): each state is produced by a scripted live-view server (`page.routeWebSocket`), the window cloned, and the
   tiles laid out on one review page (images inlined as data URLs). Error is produced by a bare 4403 close.
10. **IME composition.** `compositionend` is wired and unit-tested, but a desktop browser raises IME composition only in
    editable elements, and an editable frame would put the composed text into the DOM (P-10). Paste is the supported
    path for non-Latin input on desktop (the footer says so). Candidate below.
11. **Phone widths** render the same small window as a stopgap until 07.8-26's dock; the spec skips the mobile project.
12. **Desktop app (Electron)** is not touched: it bundles the web renderer, so the live view comes with it; no
    desktop-specific test was added.

No permission check, RLS policy, approval gate or existing assertion was weakened. The 07.8-20 activity rows keep their
markup (17 existing `browser.test.tsx` cases green; `bot-activity` and `browser-approvals` e2e green on both projects).
