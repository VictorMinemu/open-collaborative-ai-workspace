## Phase Goal

See `07.11-01-PLAN.md`. **This plan's slice:** never interrupt anyone (D-03, D-03a): the adapters say how many turns
of their runtime are in flight and can retire their idle CLI processes so the next turn starts on the new binary; the
daemon launches the CLIs with their own updaters off (D-12); and a per-runtime gate holds new turns while an update
runs. 07 wires these into the daemon.

<objective>
Add `activeTurns()`, `retireIdle()` and `refreshInstall()` to the adapter contract and implement them in the Claude,
Codex and fake adapters (lazy resume on the next turn), disable the CLIs' own background updaters in every process the
daemon launches, make the fake runtime report a fake CLI's version, and build the pure `RuntimeGate` (PD-07, PD-14).

Purpose: RTU-04's "no turn is cut, idle processes recycled, queued turns start on the new version"; RTU-02's single
update authority.
Output: adapter changes with tests, `maintenance/gate.ts` with tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| daemon → CLI processes | The adapters own process lifetime; retirement must not lose a member's turn or session |
| member turns ↔ update | A shared device runs several members' sessions; one member's update must not cut another's turn |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.11-05-01 | Denial of service | retiring a busy session | high | mitigate | `retireIdle` skips running, approval-waiting and queued sessions; tests for both adapters |
| T-07.11-05-02 | Denial of service | a turn admitted during the update | high | mitigate | Synchronous admission + `closeIfIdle` (Task 3 race test) |
| T-07.11-05-03 | Tampering | the CLI updating itself mid-session (two authorities) | medium | mitigate | `DISABLE_AUTOUPDATER=1`, `check_for_update_on_startup=false` on every daemon-launched process (D-12) |
| T-07.11-05-04 | Information disclosure | daemon credentials in the relaunched process | medium | mitigate | Wake-up launches reuse `childEnv`/`codexChildEnv` (OCW_* and API keys stripped) |
| T-07.11-05-05 | Repudiation | Codex session approvals forgotten after a recycle | low | accept | Asked again once (Pitfall 10); recorded in ADR-0032 |
</threat_model>
