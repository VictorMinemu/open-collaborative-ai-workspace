## Phase Goal

See `07.16-01-PLAN.md` (PD-18, E17). **This plan's slice:** the device facts the bypass-after-outside-content rule needs
(D-08: "a bypass-mode session then only on a device marked as an isolated server"): a host kind the server never had
(headless service vs desktop) and the owner's local isolated-server mark, both reported by the daemon only and stored
like `full_access_opt_in`, plus the FakeDevice helpers later integration tests drive sessions with.

<objective>
Report and store the device's host kind and isolated-server mark end to end (FakeDevice and the real daemon → hub →
`devices` → `GET /devices`), add the local CLI and config with its environment override, mark service units and the
desktop launch, and add the FakeDevice turn and approval helpers (D-03, D-19, PD-18, A-02).

Purpose: the agent layer's `isolated` term (06/07) and the Settings fact (13) read these columns; trust model = ADR-0012's
Full access opt-in.
Output: daemon config, CLI and frames; API hub and DTO; unit and integration tests; service units and desktop launcher.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device owner's shell → daemon config | Local only; the server can never call it |
| device → API | Hello and capabilities frames on the authenticated device socket |
| web → API | No route accepts the two facts |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.16-05-01 | Elevation of privilege | a compromised web account marks a device isolated | high | mitigate | No user route writes the columns (PATCH test as owner and admin asserts the row); only frames from the device's own socket do (Pitfall 9) |
| T-07.16-05-02 | Spoofing | a desktop daemon claiming to be a service | medium | accept | The device owner's local control is the trust root (same as `full-access on`); the desktop launcher sets `desktop`; recorded in ADR-0038 |
| T-07.16-05-03 | Elevation of privilege | isolated mark on a non-service host | high | mitigate | The API stores `false` unless `host_kind = 'service'`; the daemon reports it only for service hosts; tests both sides |
| T-07.16-05-04 | Information disclosure | local paths in the host decision | low | mitigate | install.json and the entry path are read on the device; only the enum crosses the wire |
