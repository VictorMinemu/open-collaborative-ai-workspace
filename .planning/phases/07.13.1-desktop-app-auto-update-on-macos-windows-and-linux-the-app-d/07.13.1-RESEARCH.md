# Phase 07.13.1: Desktop app auto-update on macOS, Windows and Linux - Research

**Researched:** 2026-11-26
**Domain:** Electron app self-update for unsigned builds (electron-updater 6.x, NSIS, AppImage, a custom macOS swap), release pipeline, daemon idle gate
**Confidence:** HIGH for Windows, Linux and the macOS refusal (read from source). MEDIUM for the custom macOS swap (OS behaviour; the owner must test it).

## Summary

The app has everything it needs except the installer step. The release workflow already sets the packaged app's version from the tag. electron-builder already produces per-user NSIS, AppImage and an ad-hoc signed `.app`. The daemon already has an all-gates idle decision (ADR-0040 § 7). On Windows (NSIS) and Linux (AppImage), the stock electron-updater 6.8.11 updaters work on unsigned builds as they are. On Windows the signature check is skipped when `app-update.yml` has no `publisherName`, and electron-builder only writes one when there is a certificate. AppImage has no signature step at all. Two things break today:

1. **Renamed assets.** The release workflow renames the files, and `latest*.yml` records the original basename, so the manifest would point at files that do not exist.
2. **No publish configuration.** Without it, electron-builder writes neither `app-update.yml` nor `latest*.yml`.

**macOS is different.** Squirrel.Mac, which both Electron's `autoUpdater` and electron-updater's `MacUpdater` use, checks the new bundle against the running app's designated requirement. For our ad-hoc build that requirement is `cdhash H"…"`, the hash of that one build, so every new release fails by construction. `MacUpdater` also opens a loopback HTTP listener to feed Squirrel. So on macOS we reuse electron-updater's check, download and sha512 verification through a small `BaseUpdater` subclass, and install with our own verified swap. That means:

- a `zip` target;
- extraction with `ditto`;
- `codesign --verify --deep --strict` and a bundle id and version check;
- the extracted app kept beside the installed one;
- a detached helper that swaps the app by rename after the app (and its daemon) exit, then relaunches it.

**`.deb` keeps today's notice.** electron-updater's `DebUpdater` runs `pkexec`/`sudo /bin/bash -c 'dpkg -i …'`, then `apt-get install -f -y`, as root. That does not fit this repo's posture. `.deb` users keep today's "Update available" link, worded to say the AppImage updates itself.

**Primary recommendation:** Add electron-updater 6.8.11. Use `NsisUpdater` and `AppImageUpdater` as they are, plus an `AdhocMacUpdater extends BaseUpdater`, all on the GitHub provider of the canonical repository. Give each file its release name in electron-builder itself (no renaming), and publish `latest*.yml`, the mac zip and the blockmaps. Before any install or restart, ask the daemon over the control socket to hold every gate (new strict `appUpdateHold`). The org ∩ device 07.11 level decides between a background download plus install when idle, and notify-only. A click works at any level.

## Owner constraints (no CONTEXT.md yet)

There is no `07.13.1-CONTEXT.md`. These constraints come from the owner's request as relayed by the orchestrator, and the planner must treat them as locked:

- The app finds, downloads, verifies and installs a newer release by itself on macOS, Windows and Linux. The bundled daemon updates with it.
- Builds stay unsigned: macOS ad-hoc (`identity: "-"`, no Developer ID, no notarization), Windows without Authenticode. No paid services. An Apple Developer ID is an optional later path only.

- No listening TCP port. No absolute host paths in logs. Self-hosting keeps working.
- The app installs or restarts only when no Work Zone turn runs on its daemon (ADR-0040's rule).

## Findings by question

### 1. Windows: NSIS per-user oneClick + electron-updater, unsigned

- **It works unsigned.** `NsisUpdater.verifySignature` returns `null` (pass) when `app-update.yml` has no `publisherName`. [VERIFIED: NsisUpdater.js 6.8.11, `publisherName = (await this.configOnDisk.value).publisherName; if (publisherName == null) { return null; }`] electron-builder writes `publisherName` only from `signtoolOptions.publisherName` or the signing certificate's CN. With neither, `computedPublisherName` resolves to `null`. [VERIFIED: app-builder-lib/out/codeSign/windowsSignToolManager.js:18-28; publish/PublishManager.js:202-207]
  - Recommendation: set `win.verifyUpdateCodeSignature: false` explicitly, with a comment "until Authenticode (Phase 9)", so the build can never ask for one. Add a package check asserting `app-update.yml` has no `publisherName`.
- **Install.** `doInstall` runs the downloaded installer with `--updated`, plus `/S` when silent and `--force-run` to relaunch, as the current user. Our per-user oneClick installs to the user profile, so no UAC (`isAdminRightsRequired` false). [VERIFIED: NsisUpdater.js `const args = ["--updated"]; if (options.isSilent) args.push("/S"); if (options.isForceRunAfter) args.push("--force-run");`]
- **The installer kills processes under the install directory.** `CHECK_APP_RUNNING` → `KILL_PROCESS` runs `Get-CimInstance Win32_Process | ? {$_.Path.StartsWith('$INSTDIR')} | Stop-Process`. Our daemon runs as `OCW.exe` from the install directory with `ELECTRON_RUN_AS_NODE`, and its CLIs run from `resources\daemon\node_modules`, so the installer would kill them all. This is why the idle hold and the daemon stop must finish before the installer starts. Our `before-quit` → `shutdown()` already stops the daemon before electron-updater's `quit` handler runs. [VERIFIED: app-builder-lib/templates/nsis/include/allowOnlyOneInstallerInstance.nsh; apps/desktop/src/main/daemon-launch.ts:28-40 `command: node ?? ctx.execPath`; index.ts `before-quit`]
- **Assets it needs:**
  - `latest.yml`, with `version`, `files[{url, sha512, size}]` and `path`;
  - the installer `.exe`;
  - optionally `<installer>.exe.blockmap` for differential download.

  `url` is `path.basename(event.file)`, the name electron-builder gave the file. [VERIFIED: app-builder-lib/out/publish/updateInfoBuilder.js:134 `const url = path.basename(event.file);`]
- **The rename breaks it.** release.yml copies `"OCW Setup "*.exe` to `$name-windows-x64-setup.exe` [VERIFIED: .github/workflows/release.yml:123 `windows-x64) cp "OCW Setup "*.exe "../../../out/$name-windows-x64-setup.exe" ;;`]. `latest.yml` would still say `OCW Setup 0.5.1.exe`, a 404. **Fix:** name the files in electron-builder (`nsis.artifactName: OCW-v${version}-windows-x64-setup.${ext}`) and upload as built.
- **SmartScreen.** It looks at the Mark-of-the-Web on a downloaded file. A file that electron-updater writes through Electron `net` carries none, so a silent update shows no SmartScreen prompt; Defender still scans it. [ASSUMED]
- **Differential download** builds the new file from the old installer cached in `%LOCALAPPDATA%\<updaterCacheDirName>`. It works only after the first update, falls back to a full download on any error, and the result is still sha512-checked. The old blockmap URL is computed by replacing the version string in the path, which works with `…/download/v0.5.1/OCW-v0.5.1-…` names. [VERIFIED: providers/Provider.js:24; AppUpdater.js:726 "sha512 checksum mismatch after differential download"] Recommendation: upload the `.exe.blockmap` (cheap) and keep differential on.

**release.yml changes for Windows:** add `publish` (github) to electron-builder.yml so `latest.yml` is written (with `--publish never`, uploads stay with `gh`). Set `nsis.artifactName`. Collect `OCW-v*-windows-x64-setup.exe`, its `.blockmap` and `latest.yml` with no rename.

### 2. Linux: AppImage yes, `.deb` no

- **AppImage.** `AppImageUpdater.isUpdaterActive()` is false unless `APPIMAGE` is set (the AppImage runtime sets it).
  - `doInstall` unlinks the running AppImage file and moves the new one next to it. If the old file name contains a version (`/\d+\.\d+\.\d+/`), the new file keeps its own versioned name and `appimage-filename-updated` is emitted; otherwise it overwrites the old name.
  - It then relaunches it (`isForceRunAfter`) or runs it with `APPIMAGE_EXIT_AFTER_INSTALL`.
  - It needs a writable directory. [VERIFIED: AppImageUpdater.js 6.8.11:17-27, 72-114]
  - Manifest: `latest-linux.yml` for x64 (no arch suffix). [VERIFIED: updateInfoBuilder.js:51-59 `getUpdateInfoFileName`, `getArchPrefixForUpdateFile` returns `""` for x64] AppImage blockmaps are embedded (`appendBlockmap`), so no extra file is needed.
- **`.deb`.** electron-updater 6.x does have `DebUpdater`, picked when `resources/package-type` contains `deb` (electron-builder's FpmTarget writes that file). [VERIFIED: main.js:51-61; app-builder-lib targets/FpmTarget.js:140] It runs `dpkg -i` through `pkexec`/`gksudo`/`kdesudo`/`beesu`/`sudo` wrapping `/bin/bash -c '<cmd>'`. If dpkg fails it runs `apt-get install -f -y`, and the `apt` path adds `--allow-unauthenticated --allow-downgrades --allow-change-held-packages`. [VERIFIED: DebUpdater.js:27-80, LinuxUpdater.js:33-83] electron-builder's docs say the same: "deb, rpm and pacman updates are installed as root through an elevation helper such as `pkexec` or `sudo`", and for deb "`dpkg` checks none at all". [CITED: electron.build/docs/features/auto-update]
- **Recommendation for `.deb`.** Do not use `DebUpdater`. Construct the updater class ourselves, and never use the `autoUpdater` getter that picks by `package-type`. On a `.deb` install (no `APPIMAGE`), keep today's `update-check.ts` notice. Change the label to "Update available (v…): download the .deb, or use the AppImage, which updates itself". This is a link to the release page, so no new privileged code. A one-click "download the verified .deb and open it with the system installer" (`shell.openPath`) is possible, but which handler opens a local `.deb` varies by distro (App Center, GNOME Software, Archive Manager). [ASSUMED] So it is not recommended for this phase.

### 3. macOS without a Developer ID

- **Squirrel.Mac refuses ad-hoc updates.** Its `SQRLCodeSignature` takes the running app's designated requirement (`SecCodeCopySelf` → `SecCodeCopyDesignatedRequirement`). It then validates the update bundle against it with `SecStaticCodeCheckValidityWithErrors(staticCode, kSecCSCheckNestedCode | kSecCSStrictValidate | kSecCSCheckAllArchitectures, requirement, …)` and fails with "Code signature at URL %@ did not pass validation". [CITED: github.com/Squirrel/Squirrel.Mac/blob/master/Squirrel/SQRLCodeSignature.m] Our build's designated requirement is the cdhash of that one build. [VERIFIED: `codesign -d -r- apps/desktop/release/mac-arm64/OCW.app` → `designated => cdhash H"aa11e286e3d88ea2a9a2ab6cd8c8274f52dd6cf9"`, `Signature=adhoc`, `TeamIdentifier=not set`] Any rebuilt app has a different cdhash, so every update fails. Electron and electron-builder both state it: "Your application must be signed for automatic updates on macOS. This is a requirement of Squirrel.Mac." [CITED: electronjs.org/docs/latest/api/auto-updater] and "macOS application must be signed in order for auto updating to work." [CITED: electron.build/docs/features/auto-update]
- **`MacUpdater` also listens on TCP.** It starts `http.createServer().listen(0, "127.0.0.1")` to proxy the zip to Squirrel. [VERIFIED: MacUpdater.js 6.8.11:130-211]
- **Custom minimal design:**
  1. **`zip` target** (`mac.target: [dmg, zip]`, arm64). electron-builder writes `latest-mac.yml` with both files and their sha512 ("`zip` target for macOS is required…, otherwise `latest-mac.yml` cannot be created"). [CITED: electron.build] electron-builder 26.16.1 zips the mac app with 7-Zip `-snl` to keep framework symlinks. Its comment warns that 7-Zip 24.09 "dereferences symlinks by default" and that without `-snl` a `.framework Versions/Current` breaks. [VERIFIED: app-builder-lib/out/targets/archive.js:56-58, 168-173] That is why CI must verify the zip (step 7).
  2. **`AdhocMacUpdater extends BaseUpdater`:**
     - `doDownloadUpdate` picks the `.zip` from `provider.resolveFiles(info)` and calls `this.executeDownload({ fileExtension: "zip", … })`. electron-updater downloads it into its cache and checks `sha512` from `latest-mac.yml`, as on the other platforms. [VERIFIED: AppUpdater.d.ts:188 `protected abstract doDownloadUpdate`, :205 `protected executeDownload`; BaseUpdater.d.ts:12 `protected abstract doInstall(options: InstallOptions): boolean`; AppUpdater.js:559-566 passes `sha512: fileInfo.info.sha512` to the download]
     - The download `task` then prepares the staged app (step 3), because `doInstall` must be synchronous ("must be sync (because quit even handler is not async)"). [VERIFIED: BaseUpdater.js:41]
  3. **Stage.** Find the running bundle: `app.getPath("exe")` → `…/OCW.app`. Refuse with the fallback notice when:
     - it is under `/Volumes/` (running from the dmg);
     - it contains `/AppTranslocation/`;
     - its parent directory is not writable.

     Otherwise extract the zip with `ditto -x -k <zip> <parent>/.ocw-update-<version>/` (same volume as the installed app, so the swap is a rename). Then check:
     - `codesign --verify --deep --strict <staged>/OCW.app` exits 0;
     - `CFBundleIdentifier` is `dev.ocw.desktop`;
     - `CFBundleShortVersionString` equals `updateInfo.version`;
     - the staged app has `Contents/Resources/daemon/bin/ocw-runtime`.

     Clear quarantine (`xattr -dr com.apple.quarantine`; normally there is none, see below). Any failure removes the staging directory and leaves the installed app untouched.
  4. **Swap on quit, with a detached helper.** `doInstall` spawns `process.execPath` with `ELECTRON_RUN_AS_NODE=1`. It runs a small JS helper written to the staging directory, with argv `[appPid, installedPath, stagedPath, resultFile]` (no shell, so no quoting issues with spaces), `detached: true`, `stdio: "ignore"`, `unref()`. The helper:
     - waits for `appPid` to exit (bounded, about 60 s), and for the daemon pidfile's pid to exit;
     - renames `OCW.app` to `.OCW.app.old-<ts>`, then the staged app to `OCW.app`, and renames the old one back if the second rename fails;
     - removes the old bundle;
     - writes `update-result.json` in `userData` (outcome and version only, never a path);
     - runs `/usr/bin/open <installedPath>`.

     A running app cannot `open` itself again: `open` would bring the running copy to the front, so the helper waits for exit first. [CITED: flaviocopes.com/mac-app-updates.md]
  5. **`/Applications` not writable** (a standard user; `/Applications` is `root:admin 775`) → no elevation. Show "Update available (v…)" with the release link, as today. Admin users, the normal developer case, can write `/Applications`. [ASSUMED]
  6. **App Translocation and the dmg** → offer "Move OCW to Applications to get automatic updates", using Electron's `app.moveToApplicationsFolder()`. It handles running from a disk image (it detaches the image), asks for administrator authorization when the destination is not writable, and clears quarantine on relaunch. It does **not** handle translocation explicitly, so the check comes first. [CITED: electron_bundle_mover.mm: `ContainingDiskImageDevice`, `AuthorizedInstall`, `xattr -d -r com.apple.quarantine`; electronjs.org/docs/latest/api/app "if the user cancels the authorization dialog, this method returns false"]
  7. **CI proof (macOS runner).** Extract the built zip with `ditto -x -k` into a temp directory. `codesign --verify --deep --strict` must pass, the bundle id and version must match, and the daemon check from `check-package.mjs` must run from the extracted app.
- **Quarantine and Gatekeeper.** Files downloaded by a non-sandboxed app's own HTTP client get no quarantine attribute, so the swapped app launches without Gatekeeper's first-run block. [CITED: flaviocopes.com/mac-app-updates.md: the non-sandboxed download "doesn't add one"] We still strip it defensively, as Electron's mover does.
- **Pitfalls:**
  - **arm64 only.** `mac.target` is `arm64`. An Intel Mac cannot run the app at all, so there is nothing to update.
  - **Code must be signed on Apple silicon.** An ad-hoc signature satisfies that, and a broken seal (symlinks lost) makes the app not launch. Hence `codesign --verify` before the swap.
  - **The identity changes every build.** TCC permissions (Files and Folders, Accessibility) and the Keychain ACL of "OCW Safe Storage" (the safeStorage device token) are tied to the code identity. After each update macOS may prompt again, or deny Keychain access; then `ConfigStore.token()` returns `null` and the person re-pairs. Manual updates do the same today. [CITED: flaviocopes.com "An ad-hoc signed app gets a new identity with every build, so it has to ask again after each update"] [ASSUMED for the Keychain ACL detail]
  - **App Management privacy (macOS 13+).** macOS can block one app from modifying another app's bundle. The same-Team-ID exemption does not apply to ad-hoc builds. Whether renaming a whole bundle triggers it for ad-hoc apps is not documented. [ASSUMED; see Risks R1] This is owner UAT.

### 4. Integrity

- **What electron-updater verifies.** The downloaded file's sha512 (base64) must equal `files[].sha512` in `latest*.yml`, after a full or differential download and again for a cached file. A cached file with a different sha512 is deleted and downloaded again. [VERIFIED: DownloadedUpdateHelper.js:114-126; AppUpdater.js:559-566, 652, 726] The manifest comes from the same release, over HTTPS from `github.com` (GitHub provider: `…/releases.atom`, then `…/releases/latest` with `Accept: application/json`, then `…/releases/download/<tag>/latest*.yml`; it avoids the API rate limit). [VERIFIED: providers/GitHubProvider.js:40-175]
- **It protects against** corruption, truncated or partial downloads, mixed-up assets, a stale cache, and on-path tampering beyond what TLS already blocks.
- **It does not protect against** anyone who can write release assets: they upload a new file and a matching `latest*.yml`. That means a leaked token with `contents: write`, a compromised step inside a release job, or the GitHub account. On macOS an ad-hoc `codesign --verify` proves the bundle is internally consistent, not who built it.
- **Ed25519 over the manifest, with the key in GitHub secrets.** It helps only against someone who can write assets but not run the signing job. The signer signs whatever the build job produced, so a compromised build dependency still ships. With **GitHub immutable releases** enabled, published assets "can't be added, modified, or deleted", the tag is locked, and GitHub generates a Sigstore release attestation. The remaining window is the draft, exactly where the signature would be added anyway. [CITED: docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases; github.blog changelog 2025-10-28]
- **Recommendation (proportional):**
  - No Ed25519 now.
  - The owner turns on **immutable releases** (repository setting, free). release.yml already drafts, uploads everything and publishes last. `workflow_dispatch --clobber` then works only on drafts.
  - Add `persist-credentials: false` to the checkouts of jobs that hold `contents: write`. Today the `desktop` job checks out with the default (credentials persisted in `.git/config`) and then runs `pnpm install` with lifecycle scripts for `esbuild`, `sharp`, `@biomejs/biome`, `protobufjs` and `electron`. [VERIFIED: release.yml desktop job (checkout without `persist-credentials`, `permissions: contents: write`); pnpm-workspace.yaml `allowBuilds`]
  - Include `latest*.yml` in `SHA256SUMS`.
  - Record ASVS V10.3.1 ("updates … digitally signed") as an accepted deviation until Phase 9 signing (Developer ID, Authenticode), which brings a publisher signature the device can check against a stable requirement.

### 5. The idle gate, the UI, and the org level

- **What the app can learn today.** `status` returns `sessions[]`, but not whether a turn runs. [VERIFIED: apps/local-runtime/src/daemon.ts:921-948, fields `paired, connected, serverUrl, deviceName, queuedFrames, runtimes, projects, fullAccessOptIn, fullAccessSource, isolatedServer, isolatedServerSource, host, browser, runtimeUpdates, sessions`]
  - The daemon's own decision is `RuntimeGate.closeIfIdle` / `admitted` with `activeTurns()`, and ADR-0040's all-gates step (`allIdle()`: every gate `admitted === 0` and every runtime `activeTurns(id) === 0`; `closeAllIfIdle()` closes them in the same synchronous step). [VERIFIED: apps/local-runtime/src/maintenance/gate.ts; self-update-job.ts:583-597]
  - Reading `status` and then stopping would leave a race: a prompt admitted between the read and the SIGTERM would be cut ("The device restarted").
- **Recommendation: two strict, local-only control commands**, on the same model as `runtimeCheck` and `reloadConfig`:
  - `appUpdateHold` (`{ drain: boolean }`, strict). It reuses the all-gates step, extracted from `self-update-job.ts` into a shared helper. It refuses while a 07.11 CLI job is past `pending` (`maintenance.jobActive`) or a self-update holds. It answers `{ held: true }` or `{ held: false, running: n }`. `drain: true` (a click) closes every gate at once and resolves when idle. Bounds:
    - 30 min, like `SELF_UPDATE_MAX_HOLD_MS`, then the gates reopen;
    - an auto-release about 2 min after `held` if the daemon is not stopped, in case the app died between hold and quit.
  - `appUpdateRelease` reopens the gates after a cancelled or failed install.

  Then the app quits normally. `before-quit` → `supervisor.stop()` → the daemon's `stop()` seals the gates (07.17.1 WR-01). A prompt held at a closed gate never started, so ADR-0040 § 14 / PD-27 re-queues it after the restart. Add a `status.appUpdate` block (`holding`, `running`) for the "Waiting for N sessions" line. The daemon is always the app's own bundled one, so the app and the command ship together. An **external** daemon (`externalDaemon`, started by hand) is not stopped by the app, so no hold is needed. A paused runtime is not running, so there is nothing to hold.
- **The UI**, in the tray, the Runtime menu and the onboarding window only (D-18: never the web app):
  - "Check for updates…" (always);
  - "Downloading v0.5.1… 42%" (disabled);
  - "Restart to update to v0.5.1";
  - "Update waits for 2 sessions to finish…" (disabled, after a click while turns run);
  - fallback: "Update available (v0.5.1)", the release link (`.deb`, dmg or translocated, unwritable folder, unsupported platform);
  - on macOS outside Applications: "Move OCW to Applications to get automatic updates".

  `autoInstallOnAppQuit = true` installs a downloaded update on any normal quit. A quit already stops the daemon, so this adds no new way to cut a turn. Recommended "restart by itself" for the `automatic` level only: when the update is ready, `appUpdateHold({ drain: false })` succeeds, and the person is away (`powerMonitor.getSystemIdleTime() ≥ 30 min`, checked every minute). Otherwise wait for a click or a quit. This mirrors ADR-0032's "opportunistic first" without ever restarting under someone typing.
- **The org level (07.11).** The app reads `status.runtimeUpdates.effectiveLevel`. When it is absent (daemon unreachable, older, or unpaired), use `effectiveRuntimeUpdatesLevel(null, local)` semantics, i.e. `notify`. [VERIFIED: packages/contracts/src/runtime-maintenance.ts:84 `export const RuntimeUpdatesLevel = z.enum(["automatic", "notify", "off"]);`, :99-107 "`org === null` … counts as `notify`: never install unattended without a server that audits (D-10)" and `const orgLevel = org ?? "notify";`; apps/desktop/src/shared/ipc.ts `DesktopRuntimeUpdatesLevel = z.enum(["automatic", "notify", "off"])`]

  | Effective level | Check | Download | Install |
  |---|---|---|---|
  | `automatic` | daily | in the background | on quit, by itself when idle and the person is away, or on "Restart to update" |
  | `notify` | daily | only after a click ("Download and restart") | after a click |
  | `off` | no automatic check | — | "Check for updates…" still works: a click decides at any level, as ADR-0040 § 8 / D-09 does for `ocw-runtime` |

  The bundled runtime is replaced with the app, so ADR-0040's self-update stays `not_installed` for the desktop daemon, unchanged.

### 6. Versioning

- The packaged app already carries the release version. release.yml runs `npm pkg set version="${TAG#v}"` in `apps/desktop` before `pnpm --filter @ocw/desktop package`. [VERIFIED: .github/workflows/release.yml:107-112] electron-builder reads that version into the asar's `package.json` (`app.getVersion()`), into the `version:` of `latest*.yml` and into `${version}` in artifact names. electron-updater compares semver (`gt(latest, current)`; `allowDowngrade` false by default). [VERIFIED: AppUpdater.js:339-362]
- The repository's `0.1.0` is the dev value. electron-updater is inactive unpackaged (`isUpdaterActive`: `this.app.isPackaged || this.forceDevUpdateConfig`). [VERIFIED: AppUpdater.js:277-283] A **locally packaged** build (`pnpm package`, 0.1.0) would see every release as newer. Gate the updater on a build flag set only by release.yml: an esbuild `define` from `OCW_RELEASE_BUILD=1`, the env var exported in the desktop job. Local packages and forks never self-replace with upstream.
- **Pre-releases.** electron-updater sets `allowPrerelease` to true when the current version has a pre-release part. [VERIFIED: AppUpdater.js:218] Set `allowPrerelease = false` after construction so an `-rc` build never moves along `rc` channels (it updates to the next stable release), matching `update-check.ts`'s `STABLE_TAG`. On GitHub, `getLatestTagName` uses `/releases/latest`, which never returns a pre-release. [VERIFIED: GitHubProvider.js:158-175]
- **Rule:** the app version follows the tag (already true), like the runtime (ADR-0040 § 13, `check-runtime-version.mjs`). Optionally extend that check to assert `apps/desktop` is set from the tag. No change to the repository's `0.1.0`.

### Recommended structure
```

├── app-update.test.ts
├── mac-update.ts          # AdhocMacUpdater (extends BaseUpdater): zip pick, stage, verify, spawn helper
```

### Anti-patterns to avoid
- **Using the `autoUpdater` getter from electron-updater.** It would pick `MacUpdater` (Squirrel and a TCP listener) and `DebUpdater` (root bash). Construct `NsisUpdater`, `AppImageUpdater` or `AdhocMacUpdater` explicitly.
- **Deciding idleness from `status.sessions`** in the app. Ask the daemon to close the gates.
- **Renaming assets after the build.** It breaks `latest*.yml`. Name them in electron-builder.
- **Logging with electron-updater's default `console` logger.** It prints installer, cache and AppImage paths.
- **Extracting the mac zip with a JS unzip library.** It loses symlinks and breaks the seal. Use `ditto -x -k`.
- **Staging the mac app in `userData` and copying it into `/Applications`.** A copy is not atomic. Stage beside the installed bundle and rename.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---|---|---|---|
| Release discovery, YAML manifest, redirects, caching, sha512, progress | own GitHub client and hasher | electron-updater GitHub provider + `executeDownload` | Edge cases: atom feed, rate limits, partial cache, differential download |
| Windows install | own silent installer runner | `NsisUpdater` + NSIS `--updated /S --force-run` | The installer handles running processes, shortcuts and relaunch |
| AppImage replace | own file swap | `AppImageUpdater` | Handles versioned names and relaunch |
| Mac zip extraction and seal check | JS unzip, own signature parsing | `ditto -x -k`, `codesign --verify --deep --strict` | Symlinks, xattrs and nested code |
| Move to Applications / dmg / quarantine | own mover | `app.moveToApplicationsFolder()` | Handles disk images, admin authorization and quarantine |
| "No turn is running" | polling in the app | the daemon's gates (ADR-0040 § 7) | Synchronous, race-free, already tested |

## Common Pitfalls

### Pitfall 1: Squirrel.Mac and the ad-hoc designated requirement
**What goes wrong:** "Code signature at URL … did not pass validation" on every update. **Why:** the designated requirement is `cdhash H"…"` (one build). **Avoid:** `AdhocMacUpdater`; never construct `MacUpdater`. **Warning sign:** any import of `MacUpdater` or Electron's `autoUpdater` on darwin. Add a test that `createUpdater("darwin")` is an `AdhocMacUpdater`.

### Pitfall 2: Renamed assets and missing manifests
**What goes wrong:** a 404 on `files[].url`, or `ERR_UPDATER_CHANNEL_FILE_NOT_FOUND`. **Why:** the rename step, or no `publish` configuration (then no `latest*.yml` and no `app-update.yml`; `getOrCreateDownloadHelper` needs `updaterCacheDirName` from `app-update.yml`). [VERIFIED: AppUpdater.js:542-552] **Avoid:** per-target `artifactName`, a `publish` block, and `check-update-manifest.mjs` in CI.

### Pitfall 3: The NSIS installer kills the daemon and its CLIs
**What goes wrong:** a running turn is cut if the installer starts while the daemon lives. **Avoid:** install only from the `quit` event, after `shutdown()` and after a successful hold. Never call `quitAndInstall` before `appUpdateHold` returns `held`.

### Pitfall 4: The mac zip loses framework symlinks
**What goes wrong:** "a sealed resource is missing or invalid"; the app does not launch on Apple silicon. **Why:** archiver behaviour changed across 7-Zip versions (see the comment in app-builder-lib `archive.js`). **Avoid:** CI extracts with `ditto` and runs `codesign --verify --deep --strict`; the app verifies the staged bundle again before the swap.

### Pitfall 5: The identity changes every build (macOS)
**What goes wrong:** Keychain or TCC prompts after an update, or the safeStorage token becomes undecryptable and the device shows "Pair this computer". **Avoid:** cannot be avoided without a Developer ID. State it in the release notes and the ADR. `ConfigStore.token()` already degrades to `null` (re-pair) rather than crashing. [VERIFIED: apps/desktop/src/main/config-store.ts:83-90]

### Pitfall 6: AppImage file name and launchers
**What goes wrong:** the new file is `OCW-v0.5.1-linux-x86_64.AppImage`, so a `.desktop` shortcut to the old versioned path breaks. **Avoid:** listen to `appimage-filename-updated` and tell the person once. The README can suggest renaming the AppImage to `OCW.AppImage`, which is then overwritten in place. [VERIFIED: AppImageUpdater.js:89-100]

### Pitfall 7: Local or fork builds replaced by upstream
**What goes wrong:** a `pnpm package` build (0.1.0) or a fork's build downloads the canonical release. **Avoid:** the `OCW_RELEASE_BUILD` define gate. The repository constant stays where `update-check.ts` has it (`REPO = "VictorMinemu/open-collaborative-ai-workspace"`).

### Pitfall 8: Paths in logs
electron-updater logs `Executing: <installer path>`, cache directories and `APPIMAGE`. Use `logger = null` (NoOpLogger) plus fixed error sentences mapped from `ERR_UPDATER_*` codes. [VERIFIED: AppUpdater.js:65-67 `this._logger = value == null ? new NoOpLogger() : value;`]

### Pitfall 9: The first update is manual
v0.5.0 has no updater, so the first release with it is installed by hand once. Say so in the release notes, as ADR-0040 did.

```ts
// Source: electron-updater 6.8.11 typings (AppUpdater.d.ts:188,205; BaseUpdater.d.ts:12) — shape only
import { BaseUpdater, type DownloadUpdateOptions } from "electron-updater";
class AdhocMacUpdater extends BaseUpdater {
  protected doDownloadUpdate(o: DownloadUpdateOptions) {
    const files = o.updateInfoAndProvider.provider.resolveFiles(o.updateInfoAndProvider.info);
    const zip = files.find((f) => f.url.pathname.endsWith(".zip"));
    if (!zip) throw new Error("no zip in the release");           // → fallback notice
    return this.executeDownload({
      fileExtension: "zip", fileInfo: zip, downloadUpdateOptions: o,
      task: async (dest, opts) => {
        await this.httpExecutor.download(zip.url, dest, opts);      // opts carries sha512 → verified
        await stageAndVerify(dest, o.updateInfoAndProvider.info.version); // ditto, codesign, plist
      },
    });
  }
  protected doInstall(): boolean { return spawnSwapHelper(); }       // sync: detached, unref
}
```

## Open Questions (RESOLVED)

1. **Unattended restart at `automatic`.** RESOLVED by CONTEXT D-08: at `automatic` the app restarts by itself only when the daemon holds idle and the person has been away ≥ 30 min (plan 03).
   - What we know: install-on-quit covers people who quit. A menu-bar app may run for weeks.
   - Recommendation: restart only when the daemon holds idle and the person has been away 30 min. The alternative is "never unattended; click or quit only". Owner choice in discuss.
2. **Server visibility.**
   - What we know: the device reports `appVersion` on every connect (07.13 D-18).
   - What's unclear: whether Settings › Devices should show "Updating" or an audit row.
   - Recommendation: none this phase. The version change after reconnect is enough.
   - RESOLVED: no server visibility this phase; the device's `appVersion` after the reconnect is enough.
3. **A newer app with an older self-hosted server.**
   - What we know: ADR-0040 keeps Device Link fields optional and the API accepts the previous protocol.
   - What's unclear: a server several releases behind its desktop apps.
   - Recommendation: the org level `off` is the admin's brake. Do not cap the update to the server's version (that would couple the app to the workspace, against "canonical GitHub releases").
   - RESOLVED: the org level `off` is the brake; no cap to the server's version.

### Applicable ASVS Categories
| ASVS Category | Applies | Standard Control |
|---|---|---|
| V2 Authentication / V3 Session | no | — (public releases, no credentials) |

### Known Threat Patterns
| Pattern | STRIDE | Mitigation |
|---|---|---|
| Asset and manifest replaced on the release | Tampering | Immutable releases; `persist-credentials: false`; sha512; mac `codesign --verify` |
| Feed redirected (config or env) | Spoofing | Feed set in code (`setFeedURL`), test override only when unpackaged |
| Downgrade to a vulnerable build | Tampering | `allowDowngrade = false`, `allowPrerelease = false` |
| Root code execution on Linux | Elevation | No `DebUpdater`; no pkexec or sudo path |
| A turn cut by an install | DoS / integrity | `appUpdateHold` before any quit-for-update; install only after daemon stop |
| Host paths in logs | Info disclosure | NoOpLogger, fixed sentences, a result file without paths |

## Recommended design: locked-decision candidates

- **D-01 Updaters.** electron-updater 6.8.11, constructed per platform: `NsisUpdater` (Windows), `AppImageUpdater` (Linux, `APPIMAGE` set), `AdhocMacUpdater extends BaseUpdater` (macOS). Never the `autoUpdater` getter, `MacUpdater`, `DebUpdater`, Squirrel or a listening port.
- **D-02 Source.** The GitHub provider of `VictorMinemu/open-collaborative-ai-workspace`, set in code with `setFeedURL`, over HTTPS. Stable releases only (`allowPrerelease = false`, `allowDowngrade = false`). Active only in release builds (`OCW_RELEASE_BUILD` define); a test feed only when unpackaged.
- **D-03 Assets.** electron-builder names every file with its release name (`OCW-vX-macos-arm64.dmg|.zip`, `-windows-x64-setup.exe`, `-linux-x86_64.AppImage`, `-linux-amd64.deb`) and writes `app-update.yml` and `latest.yml`, `latest-mac.yml`, `latest-linux.yml` (`publish: github`, still `--publish never`). release.yml uploads them, the mac zip and the `.exe`/`.zip` blockmaps without renaming. `SHA256SUMS` covers them. `check-update-manifest.mjs` gates every runner.
- **D-04 Integrity.** sha512 from the release manifest (electron-updater) plus, on macOS, `ditto` extraction, `codesign --verify --deep --strict`, bundle id `dev.ocw.desktop` and the version. Immutable releases on; `persist-credentials: false` in release jobs with write access. No Ed25519 now. ASVS 10.3.1 recorded as a deviation until Phase 9 signing.
- **D-05 macOS install.** Stage beside the installed bundle. A detached helper (Electron as Node, argv only) waits for the app and the daemon to exit, swaps by two renames with rollback, writes a path-free result and relaunches with `open`. No elevation. Fallback link from a dmg, a translocated path or an unwritable folder, plus "Move OCW to Applications" (`app.moveToApplicationsFolder()`).
- **D-06 Linux `.deb`.** No auto-install. Today's notice, with "or use the AppImage, which updates itself".
- **D-07 Idle gate.** New strict, local-only control commands `appUpdateHold { drain }` and `appUpdateRelease`, reusing ADR-0040's all-gates step (extracted), excluding running 07.11 CLI jobs and the self-update. Bounded at 30 min, auto-release after 2 min without a stop. A quit-for-update happens only after `held`; PD-27 re-queues held prompts.
- **D-08 Levels.** The org ∩ device 07.11 level (`status.runtimeUpdates.effectiveLevel`; unknown counts as notify). `automatic`: background download, install on quit or by itself when idle and the person is away for ≥ 30 min. `notify`: download and restart on a click. `off`: no automatic check. "Check for updates…" works at every level (ADR-0040 D-09 parity).
- **D-09 UI.** Tray, Runtime menu and onboarding window only (never the web app): check, progress, "Restart to update", "Waiting for N sessions…", the fallback link. electron-updater's logger off; fixed sentences; no paths.
- **D-10 Version.** The app version is the tag (release.yml's existing `npm pkg set`). The repository keeps `0.1.0` as the dev value. The first updating release is installed by hand once (release notes).

## Risks

- **R1** macOS App Management or TCC blocks the swap for ad-hoc bundles (A3). Unknown until UAT; the fallback link keeps people unblocked.
- **R2** Re-pairing or Keychain prompts after each mac update (A4). Inherent to ad-hoc; a Developer ID removes it.
- **R3** An electron-builder 7-Zip change breaks the mac zip seal. Caught by the CI `ditto` + `codesign` check.
- **R4** Supply chain: whoever controls the repository's releases controls code on every device (same as today's manual updates). Reduced by immutable releases and credential hygiene, not removed.
- **R5** electron-updater internals the subclass relies on (`executeDownload`, `httpExecutor`) can change in a 6.x minor. Exact pin; the e2e catches drift on upgrade.
- **R6** AppImage launchers pointing at the old versioned file name.
- **R7** Silent NSIS with an unexpected running process (an external tool under `INSTDIR`) gets killed by the installer.

## ADR outline: ADR-0046 "The desktop app updates itself from the GitHub releases, unsigned, never cutting a turn"

- **Status:** Accepted on landing. Builds on ADR-0005, ADR-0032, ADR-0034, ADR-0040. **Completes, without editing:** ADR-0032 "Our own daemon and desktop app do not update themselves here (Phase 9)" and ADR-0040 Consequences "Deferred: desktop app auto-update (signed builds, MVP 2)", in the ADR-0040 table style. **Supersedes:** 07.13 D-18's "no silent install".
- **Context:** unsigned builds; the owner's request; Squirrel.Mac's designated-requirement check (the evidence above); the `DebUpdater` posture.
- **Decision:**
  1. updaters per platform (D-01);
  2. source and channel (D-02);
  3. assets and manifests (D-03);
  4. integrity and its limit (D-04, ASVS deviation);
  5. the macOS install (D-05);
  6. `.deb` (D-06);
  7. the idle hold (D-07);
  8. levels (D-08);
  9. UI and logging (D-09);
  10. version (D-10).
- **Consequences:**
  - the first update is manual;
  - the mac identity changes each build (prompts, possible re-pair);
  - immutable releases;
  - fork and local builds never self-update;
  - Phase 9 adds Developer ID and Authenticode. A Developer ID would let the app check a stable requirement (`anchor apple generic and certificate leaf[subject.OU] = "<TEAM>"`) before the swap, which is real publisher authenticity. It would also end the Gatekeeper "Open Anyway" step, keep the Keychain/TCC identity stable across updates, and qualify for the same-Team-ID App Management exemption. Authenticode enables `publisherName` verification.
- **Validation:** the test map above; the owner UAT on two real releases.
