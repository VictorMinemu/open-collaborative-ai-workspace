# Phase 07.8 Plan 12: `@ocw/egress-policy` and the `sandbox-egress` proxy Summary

**A sandbox's only way out is now a CONNECT / absolute-URI proxy that decides with the same code as the API's 07.4
egress guard. The proxy recognises each bot by the network it arrived on, resolves each host once, connects only to the
address it checked, and never lets one bot reach another bot or the proxy itself. A 31-check real-Docker smoke proves
this.**

## Gate (Task 1), approved by the orchestrator

- `FROM node:24.21.0-bookworm-slim@sha256:d6aa754f16b3197301076f047b5def2f02ea1dbbc2ca920407d46d7ec7f87b20` is the same
  digest as `infra/sandbox/sbx/Dockerfile` (04).
- No apt package and no npm package. The image copies two workspace packages' sources: `@ocw/egress-policy`
  (`index.ts`) and the `@ocw/sandboxd` egress files (`main.ts`, `proxy.ts`). Node 24 strips the types natively. The
  package.json diffs add only `"@ocw/egress-policy": "workspace:*"` (api, sandboxd), plus the new package with
  `@ocw/config` as its devDependency.
- Runs as non-root (10002:10002), with a read-only root, `CapDrop ALL`, `no-new-privileges`, `--init`, and a tmpfs at
  `/run/ocw-egress` (smoke flags; sandboxd applies them in 13).

## What was built

- **`@ocw/egress-policy`** (AGPL-3.0-only, Node built-ins only).
  - The 07.4 block lists, `REFUSED_NAMES`, `normalizeHost`, `classifyAddress`, `hostPortOf` (returns null; the API
    wrapper still throws `bad_url`), `parseHostPort` and `formatHostPort` moved out of the API.
  - `PLATFORM_SERVICE_NAMES` gains `sandboxd` and `sandbox-egress`.
  - New: `matchAllowHost` (exact, `host:port`, `*.domain` without the apex), `compileCidrs` (throws on any bad entry),
    `decideHost` and `decideAddress`.
- **`apps/api/src/lib/egress.ts`** imports these back and keeps its undici integration. `egress.test.ts` and
  `egress.int.test.ts` are unchanged (`git diff 3f62b262` on both is empty) and pass.
- **`proxy.ts`.**
  - Handles CONNECT and absolute-URI `http://` requests. It returns 400 for https absolute URIs, user info and
    origin-form requests.
  - The policy is chosen by the arrival network's local address (an IPv4-mapped prefix is stripped). An unknown
    address gets `unknown_network`.
  - Name rules run before any DNS lookup. Each request triggers exactly one lookup, every answer is decided, and the
    proxy connects to the first answer it decided on.
  - Hop-by-hop headers are stripped both ways, including those named in `Connection`, and `Host` is preserved.
  - There is no TLS interception, no caching and no body logging. Connect timeout is 10 s; idle timeout is 5 min.
  - Decision lines are deduplicated per (network, host, port, reason), with a bound of 10 000 entries.
  - Anything unexpected becomes a refusal; the client never hangs.
- **`main.ts`.** Listens on 0.0.0.0:3128. It reads `/run/ocw-egress/policy.json` at start and on SIGHUP. A missing or
  invalid file loads `EMPTY_POLICY`, which refuses everything.

## Security-review fix (coordinator, MEDIUM; fixed in `a63e5820`)

- **Issue.** At `6423f5d0`, `decide()` built the `EgressHostPolicy` from the per-bot entry only. `bot_network` and
  `proxy_self` therefore never applied, and bot A could reach bot B through the shared proxy (cross-tenant SSRF).
- **Fix.**
  1. The policy file carries `botNetworks` (compiled with `compileCidrs`) and `ownAddresses`.
  2. Both are required and non-empty. Otherwise the file is invalid and every request is refused (`unknown_network`);
     the smoke proves this in the real container.
  3. `decide()` always passes them. Own addresses also include every non-loopback interface address
     (`os.networkInterfaces()`, read per request, because networks get attached at runtime).
  4. Every subnet the proxy is attached to is refused as `attached_network`. The only exception is an exact
     `host:port` that the arrival network lists as a private host (a fixture). Bot networks never get that exception.
  5. `proxy_self`, then `bot_network`, then `attached_network` come before the host rules and the private-host
     allowlist. Literal IPs skip the name pre-check, so `10.89.3.2:3128` gives `proxy_self`, not `port`.
- **Tests, written first (RED: 18 failures before the change).**
  - A missing or empty `botNetworks` or `ownAddresses` refuses the file.
  - With `EMPTY_POLICY`, every CONNECT is refused before any lookup.
  - A throwing policy source gives 403 instead of hanging.
  - A DNS answer at bot B's IP gives `bot_network`, even though it is listed as a private host.
  - An answer at the proxy's own address, from the file or from an interface, gives `proxy_self`.
  - An attached-network answer gives `attached_network`, except for the allowed fixture.
- **Smoke.** A and B share one proxy. A cannot reach B's container by address or by name, cannot tunnel to it, and
  cannot reach the proxy's own address on B, even though all of them are listed. A control shows the proxy container
  itself can reach B's listener, so each refusal is the policy and not the network.

### Smoke checks (real Docker 29.6.2)

- **Preflight and image.** Docker ≥ 26. The proxy image user is 10002:10002.
- **Containment of client A** (the real sbx image as 10001 on an internal network):
  - `curl --noproxy '*' https://1.1.1.1` fails.
  - `getent hosts example.com` fails.
  - The fake site cannot be reached directly.
- **Fail closed.** With no policy, the proxy answers `unknown_network`.
- **Private host allowed.** With `fake-site.local:8080` in the private hosts, an absolute-URI request returns 200 and
  a CONNECT tunnel (`curl -p`) returns 200.
- **Refused by name or address:**
  - `sandboxd:8090` → `platform_host`;
  - `sandbox-egress:3128` → `platform_host`;
  - `169.254.169.254` → `refused_address`;
  - `:8081` → `port`.
- **Without the allow entry:**
  - `:8080` → `port`;
  - `:80` → `attached_network`;
  - CONNECT → 403.
- **Shared hop.**
  - Controls: B's listener answers inside B, and the proxy container itself can reach B.
  - A (mode public) reaches the fixture; B (mode off) gets `egress_off`.
  - A → B by IP gives `bot_network`, and by name `bot_network`.
  - A → B through a CONNECT tunnel gives 403.
  - A → the proxy's address on B gives `proxy_self`, and on A also `proxy_self`.
  - A has no direct route to B.
- **Fail closed after a reload.** An empty `botNetworks` produces "policy invalid", and every request gets
  `unknown_network`. A valid policy then restores access (200).
- **Decision lines.**
  - The allowed line is present.
  - No line carries a path (`__stats` is absent).
  - Every stdout line has exactly the keys `{allowed, host, network, port, reason}`.
- **Hardening.**
  - `CapEff` is 0.
  - Neither `/app` nor `/run/ocw-egress` is writable by the proxy.

## Deviations from Plan

1. **[Coordinator / security review] Policy key `botNetworks`** instead of the plan's `blockedCidrs`; the coordinator
   named it. The plan also gains `attached_network`, the interface-derived own addresses, and fail-closed when either
   list is empty. See the section above.
2. **[Rule 3] `apps/sandboxd/tsconfig.json`** (not in `files_modified`) sets `allowImportingTsExtensions: true`. The
   image runs `main.ts` on plain Node, which needs `./proxy.ts` written with its extension. No tsx and no build step
   ship in the image.
3. **[Rule 3] `scripts/guard/guard.test.mjs`** (not in `files_modified`) proves the path allowance. Semgrep's `--test`
   ignores rule `paths`, so a fixture under `.semgrep/tests/` can only prove the flag; it now has the
   `node:net` / `node:http` lines. The scan cases are:
   - `apps/sandboxd/src/egress/{main,extra}.ts` are flagged;
   - `proxy.ts` passes;
   - `egress/sub/proxy.ts` is flagged, so the allowance is that exact file.
4. **Semgrep scope.** `ocw.raw-egress` now includes `/apps/sandboxd/src/egress/` and excludes exactly `proxy.ts`
   (comment naming ADR-0029). It does not cover the rest of `apps/sandboxd/src`: `docker.ts` (the Engine API over the
   Unix socket) and `server.ts` (the broker listener) legitimately import `node:http`, and covering them would need
   more than the plan's one-file exclusion.
5. **[Rule 1] A throwing policy source left the client hanging.** This was found in RED: an unhandled rejection in
   `decide()` meant no response was ever written. `decideSafely` now turns it into a 403.
6. **Port rule detail.** `fake-site.local:8080` without an allow entry is refused as `port` (an earlier step than
   `refused_address`). The smoke checks `:80` separately to prove the address and attached-network refusal.
7. **TDD notes.**
   - Some Task 3 behaviours already held after Task 2: identity by local address, pinning against rebinding, reload
     applying to new connections, and query-free lines. Their tests are characterisation tests and passed on first run
     once the snapshot shape compiled.
   - The package test for `attached_network` was written in the same step as the code. Its rename from `bot_network` to
     `attached_network` was RED first (2 failures).
   - The Semgrep cases were RED against the old rule.
8. **Smoke client image.** The real `sbx` Dockerfile is used, tagged `ocw-sandbox-egress-client:smoke-<sha>`, so it
   never collides with 04's `ocw-sandbox-sbx:smoke-<sha>`.

   proxy's real egress network is exercised in 13 or 24.

   tunnels. Revisit with the 13 limits.
