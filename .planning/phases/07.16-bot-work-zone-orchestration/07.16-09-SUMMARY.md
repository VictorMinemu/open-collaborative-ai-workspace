# Phase 07.16 Plan 09: Plugin wake event and the Work Zone context blocks Summary

**`agent.work_session.v1` wakes the bot in its card's thread as a mention-shaped turn with a "Work Zone session update" block, and every turn with `turn.workZone` tells the model its device, projects, models, modes and sessions in a "Your Work Zone" block**

- **Duration:** 8 min
- **Started:** 2026-11-09T19:12:20Z
- **Completed:** 2026-11-09T19:20:33Z
- **Tasks:** 2 (tracer + 1)
- **Files modified:** 6 (2 created)

## Accomplishments

- Bridge: a `case AgentChannelEventTypes.workSession` like the consult reply. It parses with the mirror's `AgentWorkSessionEvent`, warns with the seq and the field path only, and skips (and reports `failed` if the turn may belong to a chain). Valid events go through `handleWorkSession` → `runTurn`. The type is also in `TURN_EVENT_TYPES`.
- `mapWorkSessionEvent`: the mention mapping on the card message, so the sender, thread, `inReplyToMessageId`, tools, flags, taint and `workZone` are exactly a mention's. A leading block follows: "Your Work Zone session <id> finished a turn and nothing is queued. Status: idle. 2 approvals are waiting. People who can decide: @ana, @sam. You can't approve runtime requests; mention one of these people when the session waits. Read more with ocw_work_session_read." The summary travels as one-line data.
- "Your Work Zone" block, last in the turn's blocks: `billing-server (online)`, `Claude Code`, `<id> · billing-api` lines and "3 more projects are not listed.", `claude-opus-4 (default), claude-sonnet-4`, `low, high`, "Off by default; you may turn it on.", "Supervised by default; at most Full access.", "After outside content: you can't start or prompt; you'll propose instead.", `<id> · billing-api · running`. It closes with the four tools and "You can only control sessions you started."
- Mode labels: shared, not duplicated. Plan 08's local `MODE_LABELS`, `RUNTIME_LABELS` and `STATUS_LABELS` moved to `work-zone-labels.ts`. The session tools' output is unchanged (all 26 tests in `work-session-tools.test.ts` pass).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The shared mode labels need their own module**
- **Found during:** Task 2
- **Issue:** The plan says to share plan 08's mode labels. They were private in `work-session-tools.ts`, and that module imports `tool-guard.ts`, which imports `mention-mapper.ts`. Importing them from the mapper would create a load-order cycle.
- **Fix:** Moved the mode, runtime and status labels to `work-zone-labels.ts` (type-only imports). Both modules import them from there.
- **Files modified:** work-zone-labels.ts (new), work-session-tools.ts (not in `files_modified`)
- **Verification:** `work-session-tools.test.ts` passes unchanged; the full plugin suite passes
- **Committed in:** 32457739

### Interpretations

**2. The plan's "subscribed type list" is `TURN_EVENT_TYPES`.** The bridge has no subscription filter; that set drives `rawChainFacts`. A wake whose payload is invalid and whose turn lists `ocw_consult_agent` therefore reports `failed`, like every other turn-like event.

**3. Wording beyond the plan's minimum.**
- When deciders exist, a "People who can decide: @…" line comes before the D-10 sentence.
- With waiting approvals but no deciders, the block still says "You can't approve runtime requests." (T-07.16-09-03).
- The read hint appears only when the run has the tool.
- An empty model or effort list reads "Leave it out; the session uses the runtime's default."

**4. Plan 08's deviation 4 (`withTurnScopedTools`), checked for wake turns.** A wake turn's `allowedTools` contains the four session tools whenever the bot's snapshot lists `ocw_agent_card`. Every non-disabled bot's snapshot lists it, and `bridge-work-session.test.ts` asserts it. This matches the hub (PD-17: the API decides the offer per delivery). No later plan needs to change it, as long as `GET /cell` keeps listing `ocw_agent_card` for bots with a profile. If plan 11 or 21 serves a bot without `ocw_agent_card`, it must revisit this.
