# Phase 07.13.1 Plan 03: Desktop update controller Summary

**The desktop app's update brain exists and is proven with fakes. The 07.11 level decides when it checks, downloads and
installs. "Restart to update" quits only after the daemon answers `held` (or when no daemon of the app's own runs). The
install starts only from the `quit` event. The unattended restart happens only at `automatic`, through `hold(false)`,
after 30 min of system idle. Each platform gets its one allowed updater on the canonical GitHub feed, and Semgrep
refuses the forbidden ones.**

## What exists now (for plans 04-07)

- **`AppUpdateController(deps)`**
  - Methods: `start()`, `stop()`, `onDaemonStatus({ reported, level, appUpdate })`, `check("auto" | "click")`,
    `restart()`, `holdThen(action)`, `cancelWait()`, `setFallbackNotice({ version, url } | null)`, `onQuit()`, `view()`.
  - Deps are exactly the plan's list:
    - `hold(drain)` returns `Promise<unknown>`; the controller parses the answer with `AppUpdateHoldAnswer` itself, so
      plan 05 may pass the raw control result.
    - `daemon()` returns `"ours" | "paused" | "stopped" | "external"`.
  - `UPDATE_SENTENCES` holds the fixed sentences: `checkFailed`, `checksumMismatch`, `noUpdateFile`,
    `macPrepareFailed`, `holdTimedOut`, `runtimeUnreachable`, `upToDate`.
- **`UpdaterLike`**
  - `on` / `removeListener` for `download-progress`, `update-downloaded` and `error`.
  - `checkForUpdates`, `downloadUpdate`, `quitAndInstall`, and the optional `prepareDownloaded({ version, downloadedFile })`.
  - The controller calls `prepareDownloaded` on every `update-downloaded`, so a cached download is staged too.
  - A rejection becomes the fallback phase: link `…/releases/tag/v<version>` and the "could not be prepared" sentence.
  - The `quitAndInstall` match at line 61 is the interface declaration; the only call is in `onQuit`.
- **`createPlatformUpdater({ platform, env, mode, createMac })`** returns `{ updater: AppUpdater | null, fallback }`.
  - `fallback` is one of `deb`, `unsupported`, `not_release`, `dev`, or the macOS reason (`dmg`, `translocated`,
    `unwritable`, `not_bundle`).
  - `createMac` returns `{ ok: true; updater: AppUpdater } | { ok: false; reason }` (`MacUpdaterResult`). The factory
    applies the same flags and the GitHub feed to the macOS updater, so plan 04's class must not set its own feed.
- **`updaterMode({ isPackaged, releaseBuild, env })`** returns `github`, `test` (with `feedUrl`, `configPath` and
  `macTestApp` (absolute or null)), or `off`.
  - The test mode needs `OCW_DESKTOP_UPDATE_FEED` (loopback http, no credentials) and `OCW_DESKTOP_UPDATE_CONFIG`
    (absolute).
- **Views:**
  - `appUpdateMenuModel(view)` lists items top to bottom: notice line, primary line, Move, Check. Actions:
    `check`, `restart`, `cancelWait`, `openRelease` (with `url`), `moveToApplications`.
  - `onboardingUpdateView(view)` returns an `OnboardingUpdate` or `undefined`.
  - Extra phase `restarting`: "Restarting to update to v0.5.1…" (disabled; onboarding `waiting`).
- **`appImageNameNotice(prev, next)`** gives one sentence naming both plain file names, else null.

## Decisions Made

See `key-decisions` in the frontmatter. These two matter most for plan 05:
- `reported: false` keeps the last level.
- A failed or unreadable hold answer releases the gates quietly.

## Deviations from Plan

**1. [Rule 2 - Missing critical] Release the gates when the hold answer is lost**
- **Found during:** Task 2
- **Issue:** A hold request that times out or returns an unreadable answer may still have closed the daemon's gates
  (drain). Without a release they would stay closed until the daemon's 30-min bound.
- **Fix:** `endWait(..., release: true)` on that path. The test asserts `release` is called once.
- **Commit:** 34233acc

**2. Semgrep fixture: a usage line is a finding too**
- **Found during:** Task 3
- **Issue:** Semgrep resolves an imported name to its module, so the line that uses the forbidden imports also
  matches. It is annotated `ruleid:` in the fixture; this is desirable for real files.
- **Commit:** c3f773a2

Otherwise the plan was executed as written; every file is inside `files_modified`.
