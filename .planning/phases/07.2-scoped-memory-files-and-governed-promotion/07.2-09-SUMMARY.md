# Phase 07.2 Plan 09: Memory proposals and the `memory.write` approval kind Summary

**An agent's proposal into memory is now an immutable proposal and a pending `memory.write` approval, mirrored as a
server-composed card in the conversation where it was asked (scope, readers, findings, a masked excerpt, the taint and
extended-scan warnings, "Review changes"). A person allowed to decide it makes the server write exactly that revision,
as the bot on behalf of the human; shared memory needs a second person, private memory only its owner.**

## Intended change (plan mode, written before editing)

**Files (all under `apps/api/src/modules/memory/`):** `detect.ts` (+ `detect.test.ts`), `proposals.ts`,
`approval-kind.ts`, `proposals.int.test.ts`, `index.ts`. Nothing outside the module.

**Kind `memory.write`** (mode `server_apply`, resource type `memory_proposal`, TTL 14 days), built by a factory in
`createMemoryService` (its hooks need the permission service, the memory file operations and the scanner) and
registered there on `deps.approvals`.

**Hash tuple** (fixed order, from the stored proposal only): `[proposal.id, proposal.scope_id, proposal.file_id ?? null,
proposal.path, proposal.op, proposal.base_version ?? null, sha256Hex(proposal.content)]`. The content hash is
recomputed from the stored text, never read from `content_sha256`.

**Approver rules (`canDecide`, live at every read and decision):**
- personal-like scope (a person's private memory, a personal bot's notebook): `memory.write` on (scope, path), which
  the resolver grants only to the owner; RLS also hides the proposal from anyone else, admins included;
- every other scope (unit, organization, team-bot notebook): `memory.promote` on (scope, path) and the decider is not
  the human the proposal was made for (no self-approval);
- a missing proposal (cascaded with its unit, bot or a forgotten scope; or hidden by RLS): nobody decides (fail
  closed). `view` returns the generic `fields` view with the UI-SPEC copy "This memory no longer exists." and the
  code `scope_gone`; `hashInput` throws 409 `scope_gone`; `apply` returns `scope_gone`; `audience` is empty;
  `isPrivate` is true. The inbox and decisions never 500 (WINDOWS 137).
- `audience`: the owner (personal-like) or everyone holding `memory.promote` on the path except the requester.
- `isPrivate`: true for personal-like scopes (decision notes audited as `noteChars`).

**Proposal flow (`createMemoryProposal(tx, deps, input)`):** turn (`unknown_turn`) → the human's lens → path grammar
(`path_invalid`) → scope alias (`personal` = the bot with the turn's human, `agent` = the bot's notebook, else an id;
`not_found`) → `memory.read` for the agent acting for the human (`denied`) → op preconditions (`create` on a live path
→ `version_conflict`; `replace` needs the file (`not_found`) and `baseVersion` equal to its version
(`version_conflict`); `append` creates when missing) → one tool call counted with a conditional update (`cap_reached`
at `MAX_TOOL_CALLS_PER_TURN`), reading `tainted` (a tainted turn may propose, flagged) → pending cap per (bot, human)
under an advisory lock (`too_many_pending` at 20) → `scanChange` (secret → `secret_detected`, nothing stored) → size
of the result (`too_large`) and the scope's file limit for `create` (`scope_full`) → reader count (`usersAllowed`
over members; personal-like = 1) → insert the immutable proposal → `approvals.request` with the card target from the
turn (conversation, in reply to the human's message, thread root of that message) → audit
`memory.proposal_created` `{proposalId, approvalId, scopeId, scopeKind, op, findingKinds, readerCount, tainted}`.
Refusals are audited as `memory.proposal_refused` `{reason}` with ids only. Never a path or content in audit rows.

**Detector (`scanChange`):** added text only (create: all; replace: the lines `diffLines` adds; append: the appended
body, offsets and lines in the resulting file), layer 1 (`detectSensitive` with the added line numbers), layer 2 (the
scanner on the added text, spans mapped back to the result; overlapping builtin spans win; Presidio warn findings
rebuilt from the surviving spans; `info` markers passed through). Caps for the view (WINDOWS 126): at most 200 spans
(by offset) and 50 findings.

**Card (`card()`):** title "{Create|Rewrite|Append to} {path}" (≤ 200), fields Memory ("{label} · {Private|Bot|
Department|Team|Project|Everyone}"), Readers ("Only you" | "1 person" | "{n} people"), Found (kind names or "Nothing
found"), Bot's note (when given); summary = the change excerpt (≤ 600 characters, added lines prefixed "+ ", every
span masked with `maskSample`); warnings "{bot} read web or tool content in this turn." (tainted) and "Extended scan
unavailable — review the text yourself" / "Extended scan incomplete — review the text yourself"; Open action "Review
changes" → `/memory/proposals/<approvalId>`. Presidio spans reach the card through an in-process hand-off from the
proposal call (they are not stored); `view` recomputes layer-1 spans and shows Presidio findings by line.

**Apply:** `writeFile` (`create`, or `update` with `expectedVersion = base_version`) or `appendToFile`, with the
`approved` actor (the bot on behalf of the human, `approvalRequestId`); domain errors become result codes:
`memory_version_conflict`/`memory_not_found` on replace → `stale_base`, `memory_path_exists` → `path_exists`, a missing
proposal or scope → `scope_gone`, `secret_detected`, `memory_scope_full` → `scope_full`, `memory_file_too_large` →
`too_large`, any other domain error → `apply_failed`.

**Tests:** `detect.test.ts` (unit, fake scanner) and `proposals.int.test.ts` (real PostgreSQL + Redis, one stack; its
`OCW_PRESIDIO_URL` points at an in-test fake analyzer that answers nothing by default, a PERSON span on demand, and is
finally closed so the port refuses): tracer, view spans (create and append), four-eyes, owner approves personal on a
tainted turn in the card, admin 404 and no events, stale base, path exists, tampering, race, deny, secret, caps,
denied scope, Presidio person and closed port, expiry, private and shared notes, the 200-span cap (126) and a unit
deleted under a pending proposal (137).

## Deviations from Plan

### Interpretations and interface changes

1. **`createMemoryWriteKind(deps)` instead of `export const MEMORY_WRITE_KIND`.** The hooks need the permission
   service, the file operations and the scanner, which exist only inside `createMemoryService`; the kind id is the
   exported `MEMORY_WRITE = "memory.write"`. `MemoryService.propose(tx, input)` is added so 07.2-11 calls the service
   (it owns the scanner and the hand-off); `createMemoryProposal(tx, deps, input)` stays exported.
2. **Missing proposals (WINDOWS 137) fail closed.** Who could decide a proposal whose scope is gone cannot be
   established, and for a personal proposal "missing" also means "hidden by RLS", so nobody may decide it. Inbox and
   detail answer cleanly and read `scope_gone`; a decision gets the primitive's answer for a request one may not
   decide (404 for a former decider, 403 `not_approver` for the requester); the request stays pending until it
   expires. A decision that ever reached the hash would get 409 `scope_gone`, and `apply` returns `scope_gone`. Turning
   such a request into `failed/scope_gone` needs a primitive-level hook (broken-windows candidate 1).
3. **View spans are layer 1 only.** Presidio spans are not stored (no column, and re-calling Presidio on every GET is
   wrong); its findings are stored and listed, and the UI-SPEC's line-level fallback covers them. The card's excerpt
   does mask Presidio spans, through an in-process hand-off from the proposal call to the card hook.
4. **No `not_in_turn` / `memory_off` checks here.** They depend on the turn offering `ocw_memory_propose`, which 07.2-11
   adds with the Agent Channel route; this function checks everything else the plan lists.
5. **Extra refusals** beyond the plan's list, all existing `MemoryToolRefusal` values: `path_invalid`, `not_found`
   (missing scope, or a missing file for `replace`), `too_large` (the resulting file), `scope_full` (a new file in a
   full scope).
6. **Presidio in the integration suite.** One stack whose `OCW_PRESIDIO_URL` points at a fake analyzer in the test
   file (answers nothing by default, a PERSON span on demand, then closed so the port refuses), instead of a second
   stack: the same env wiring and client, half the containers.
7. **Lead promotion in the four-eyes test** needs the organization role first (`lead_requires_role`), so the test
   promotes Sam's role and unit membership and restores both afterwards.

## Broken-windows candidates (not written to WINDOWS.md, as instructed)

1. **A request whose proposal cascaded stays `pending` until it expires** (its card too). Decisions are 404/403, not a
   terminal `failed/scope_gone`. Fix in the primitive: a kind hook such as `gone(tx, row)` that lets the service close
   the request as `failed` with the kind's code, mirroring the card.
2. **Presidio runs inside the proposal's transaction** (up to `OCW_PRESIDIO_TIMEOUT_MS`, 2 s, holding the
   (bot, human) advisory lock and a pooled connection). Fine at this scale; moving the scan before the transaction
   needs the base content read twice.
3. **`canDecide` and `audience` cost** a proposal and scope load plus resolver decisions per call; `audience` runs
   `usersAllowed` over all members on every announcement. The inbox calls `canDecide` per row (WINDOWS 133).
4. **The `personal` and `agent` aliases create the scope** (`ensureScope`) before the read decision, so a refused
   proposal can still leave an empty scope with its `MEMORY.md`. 07.2-11 should also decide whether `personal` is
   DM-only for proposals, as it is for `write`.
5. **A refused secret or size still uses one tool call** of the turn (the plan's order: count, cap, then scan).
6. **View spans omit Presidio entities** (deviation 3); the web shows them by line only.
7. **`MemoryProposalView.requestedBy.agent` is required** (Known Stubs); 07.6 needs it nullable.
8. **4 pre-existing biome warnings** in `apps/local-runtime`.
