# Phase 07.15 Plan 07: Delivery lists the turn's attachments per bot Summary

**Every delivered bot turn now lists, as metadata only, the files of the messages it reads (the current message first,
then the history window newest first, at most 20), says per bot whether each is `read`, `import` or `none` with a fixed
note, and offers `ocw_attachment_read` only when one of them reads.**

## Intended change (CLAUDE.md plan mode: permissions, tenant data)

- `buildMentionEvents` loads the ready rows of the current message and of the history window it already computes (the
  same `messageScopeFilter`, live messages only) with one `attachmentRowsForMessages` call, and passes them in listing
  order to `turnPolicy`. Automation and consult turns pass none.
- `turnPolicy` builds the list with `buildTurnAttachments` after `computeTurn` and before the `agent_turns` insert. That
  happens only while object storage is configured and for channel, thread, DM, group and AI chat turns. The import's F-8
  decision (`audienceCoverFacts` + `audienceCovers`, with the chat's readable set, the import route's own pair) is asked
  lazily and at most once.
- `ocw_attachment_read` is added with `ATTACHMENT_READ_FLAGS` (untrusted output, not side-effecting) when an entry is
  `read` and the 64-tool cap allows. The budget fields travel only with the tool.
- No permission check, RLS policy or approval gate changed. The list grants nothing: 08's read route and 03's import
  route re-decide every call.
