# Phase 07.18 Plan 08: Codex account slots, device-code sign-in, `ocw-runtime account` Summary

A device can now keep several ChatGPT accounts for Codex side by side, one `CODEX_HOME` slot each, sharing the default
Codex home's `sessions/`. The server hears every slot (`accounts.sync`, no e-mail, no token, no path). An admin starts a
ChatGPT sign-in through `account.login` and the daemon runs Codex's own device-code login under that slot's home. A
device owner does the same from the terminal with `ocw-runtime account add codex`. A Work Zone session can start on a
slot.

## What was built

- **Task 1 (tracer): slots on disk, reported, usable at start** (`2e13a4ce` test, `1c5de3f1` feat)
  - `CodexSlotStore` writes `<ocw home>/accounts/codex/<slotId>/` with mode 0700.
    - `sessions` is a symlink to the default Codex home's `sessions/`, created if missing. On win32 it is a junction.
    - `config.toml` is linked when the default home has one (POSIX only).
    - `slots.json` (0600) holds id, label, origin, creation time and the plan.
    - Ten slots at most. A duplicate id is refused. An id that is not a uuid never reaches the file system.
    - `remove` unlinks both links before it removes the directory. The test checks that the shared history survives.
  - `defaultCodexHome(env)` is `CODEX_HOME`, else `$HOME/.codex`.
  - Daemon:
    - `accounts.sync` goes out after `capabilities` in every handshake, and again whenever a slot changes while connected.
    - `runtimeAccountOf` turns a `device_slot` account into `{ kind, ref, label, slotId, codexHome }`. An unknown slot is
      refused with "account slot not found on this device".
- **Task 2: sign-in and sign-out from the server** (`b26e69ce` test, `6fb198ef` feat)
  - `codex-protocol.ts`: `looseObject` schemas for `account/login/start` (device-code variant, https URL, 4-32 character
    code), `account/login/completed`, `account/read` (type and plan only), `account/logout` and the rate-limit
    snapshot / window. Plan 11 needs the rate-limit ones.
  - `codex-login.ts`: each call spawns one app-server with `CODEX_APP_SERVER_ARGS`, `codexChildEnv` (API keys removed) and
    `CODEX_HOME` = cwd = the slot. The login has a 15-minute bound. Failures are classified:
    - `denied`, `expired` (also when the bound runs out) and `cancelled` (abort, which also cancels at Codex);
    - `unsupported` when Codex lacks the device-code variant (A-08: "Update Codex on this device and try again") or no
      Codex is installed;
    - `failed` for everything else.

    The app-server is always stopped at the end. The user code is never logged.
  - Daemon `account.login` runs outside the session chains, through Codex's gate, one at a time per slot. It sends, in
    order: the `code` frame, the `completed` frame (with the plan), `accounts.sync`, then the ack. On failure it sends
    `failed` with the code and a sanitized message with the user code removed, removes a slot it created, and acks with
    an error. `account.logout` cancels a running sign-in of that slot, signs the slot out, removes it, re-syncs and acks.
    An unknown slot acks ok. Daemon stop aborts running sign-ins.
- **Task 3: `ocw-runtime account`** (`f46c2062` test, `ab0e0da3` feat)
  - `account add codex [--label]` prints the link and the code, waits for the sign-in, then prints "Signed in (plan:
    plus). The server lists it under Settings › Account pool; an admin turns it on." The slot gets `origin: "cli"`. The
    default label is "Codex account <n>". Ctrl-C exits 130 and a failure exits 1; both remove the slot.
  - `account list` prints one line per slot. `account remove codex <slotId|label>` signs the slot out and removes it. An
    unknown or ambiguous slot, or bad usage, exits 2 with the usage line.
  - The value-less `reloadAccounts` control command (strict). The daemon re-reads the slots and sends `accounts.sync`.
    The CLI calls it after add and remove; when no daemon is running, the next handshake reports the slots.
  - `fake-codex/fake-codex-accounts.mjs` is a test-only fake `codex app-server` that handles the account methods only.

## Deviations from Plan

1. **[Rule 2 - Correctness] The plan is stored in `slots.json`.** The plan lists id, label, origin and creation time.
   `planType` is added (no secret) so `accounts.sync` and `account list` can report the plan without spawning one
   app-server per slot on every handshake. "Refined by account/read" happens at sign-in.
2. **[Rule 2 - Security] More checks than planned.**
   - Slot ids are checked as uuids before any path is built.
   - `remove` refuses to delete a `sessions` that is a real directory rather than a link.
   - The verification URL must be https.
   - Codex's stderr is drained unread, because it may echo the user code.
3. **[Rule 3] Test-only fake `codex`** (`accounts/fake-codex/fake-codex-accounts.mjs`, not in `files_modified`). The CLI
   test runs the real bin as a subprocess, so it needs a real executable fake, like `maintenance/fake-cli`.
4. **[Design] Existing daemon test updated.** "buffers events while offline" now expects `accounts.sync` in the
   handshake order. The renamed test "refuses a device_slot account whose slot is not on this device" keeps its
   assertion.
5. **[Design] Logins go through Codex's `RuntimeGate`** so a CLI update never swaps the binary under a running sign-in.
   The plan does not mention it.
