## Phase Goal

A bot can take on a request that needs many turns and keep working on it **by itself** until it is done: it starts a
task, continues its own work in the same thread without a person re-prompting, is woken when its long sandbox processes
or its Work Zone sessions finish, can wait on a timer, reports progress on a live task card people can **Stop**, and is
bounded by budgets so it never runs away (owner, 2026-11-12: "el bot debe ser más proactivo y que haga las tareas y que
pueda hacer tareas de larga duración"; no more "no tengo ejecución en segundo plano"; CONTEXT D-01 … D-14; BTASK-01 …
BTASK-11).

**This plan's slice (tracer, contract tier):** the phase's vocabulary in `packages/contracts` and its mirror in the
plugin. Plus this hub: plan map, shared files, cross-plan names, planner decisions PD-01 … PD-28, edge coverage,
prohibitions, flagged assumptions, source coverage. Every later 07.17.1.1.2 plan cites this hub.

- **PD-05 State machine (D-01, D-02, D-12; RESEARCH Data model).** Start → `running`, `turns_used = 1`,
  `current_event_id = started_event_id = the start turn`. A control call is accepted only when the task is `waiting` or
  the calling turn is the task's `current_event_id` (else `task_busy`): one execution authority per task. Continue →
  `waiting`, `wait_seq + 1`, `nudged = false`, and the wait: no `waitFor` and `afterSeconds` absent or 0 → `turn`
  (`wake_at` = now + 30 min backstop); `afterSeconds = n > 0` → `timer` (`wake_at` = now + max(n, 5 s)); `waitFor:
  { processId }` → `process` when the task's `bot_task_processes` row is `running` (`wake_at` = `afterSeconds` ? now +
  n : the row's `deadline_at`), a row already ended → `turn` (listed in the next turn's `finishedProcesses`), no row →
  `wait_unknown`; `waitFor: { workSessionId }` → `session` when `bot_work_sessions.task_id` is this task and the session
  is not ended (`wake_at` = now + (`afterSeconds` or 60 min)), else `wait_unknown`; every `wake_at` capped at
  `deadline_at`. Delivery of a wait → `running`, `turns_used + 1`, `current_event_id = taskEventId(id, wait_seq)` (08)
  or the Work Zone wake's event id (10). Finish → `done` (outcome `done`) or `failed` (outcome `blocked`). Stops →
  `stopped` (budget_turns, budget_time, daily_limit, access_lost, bot_unavailable, policy_off, stopped_by_person) or
  `failed` (no_progress, error); every terminal transition sets `finished_at`, clears the wait and bumps `wait_seq`, so a
  queued job finds nothing to deliver.
- **PD-06 Delivery readiness (Pitfalls 2, 7).** The handler delivers a waiting task only when `wake_at <= now()` and
  the task's current turn reported done (`agent_turns.done_at`) or is older than 30 min (lost). The turn-done hook (08)
  marks `done_at` for task turns, shortens a `turn` or `nudge` wait to now + 5 s and enqueues one job at
  `greatest(wake_at, now() + 5 s)` for any waiting task; for a `running` task whose current turn ended without continue
  or finish it applies D-12: the first time `waiting` with kind `nudge` (`nudged = true`), the second time
  `stopTask(no_progress)`. Jobs carry `{ organizationId, taskId }` only and no `singletonKey` (a queued backstop must not
  swallow the earlier job); extra jobs are harmless because the handler decides under `FOR UPDATE` with the derived id.
