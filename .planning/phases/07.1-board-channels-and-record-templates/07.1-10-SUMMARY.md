# Phase 07.1 Plan 10: Agent Channel board API Summary

**Agents now read a board, create cards in it, move cards and set their waiting state through the Agent Channel, and only on a board channel's turn. The conversation and the human come from `agent_turns`, never from the request. Each call is decided as the agent acting for that human, counted against the turn's budget, refused once the turn is tainted, and audited with both the agent and the human. Agents never edit card text.**

## Plan-mode record (permission, audit and tenant paths; approval delegated per P-15)

| Step | Where | Decision |
|---|---|---|
| Offer | `turn-policy.ts` `turnPolicy` → `assemble` | One indexed lookup of `conversations.layout`. `ocw_board_card` is added only when the turn's conversation is a `channel` with `layout = board`. Flags are `{untrustedOutput: false, sideEffecting: true}`. The cell-wide view (null kind) and `currentTurnTools` never include it, and no other tool's rule changes. |
| Gate (tx 1, committed) | `agent-channel/board.ts` `gateTurn` | Steps, in order: <br>1. Load `agent_turns` by `eventId` (RLS keeps it to the cell's tenant).<br>2. A missing turn, or another agent's: 403 `no_trigger`.<br>3. The turn does not offer `ocw_board_card`: 403 `not_in_turn`.<br>4. The conversation is not a board channel, or has no `boards` row: 400 `not_a_board`.<br>5. One conditional UPDATE counts the call, unless the turn is `tainted` (403) or at `MAX_TOOL_CALLS_PER_TURN` (403 `cap_reached`).<br>Each refusal is audited as `agent.board.refused`. |
| Act (tx 2, tenant user = the turn's human) | `chat/board/service.ts` `assertAgentOnBoard` | A write on an archived board gets 410 `channel_archived`. Then `channel.post` (or `channel.read` for the read) is decided for `{agent}` on the agent's facts, and for `{agent, onBehalfOfUserId: turn.userId}` on the agent's and the human's facts. A denial is `AuthzDeniedError` (403 with layer and reason; the handler audits `authz.denied`). |
| Create | `createBoardCard` (author agent) | The idempotent retry key is `board:<idempotencyKey>`. The card lands in the turn's board, `board.card_upserted` is emitted, and `board.card.created` is audited with `actorKind: agent`, `agentId` and `userId` = the human. The route then runs `chatEvents.messagePosted` as an agent post: mentioned humans are notified, and no agent is woken. |
| Update | `updateBoardCard` (actor agent) | Card text (title, description, fields) is 403 `not_author` (P-03). The route catches it from the raw body before the schema strips it, and the service refuses it too. A card that is not on the turn's board is 404 `card_not_in_board`. Moves and the waiting state follow 07.1-03's lock/version/rank order. |
| Refusals from chat | `board.ts` `onTurn` | Any `HttpError` other than a resolver denial is audited as `agent.board.refused` in its own transaction, with the error code as the reason. Audits carry ids and reasons only. |

## Deviations from Plan

1. **[Orchestrator directive] 403 `no_trigger` instead of 404 `unknown_turn`.**
   - **Plan:** an unknown event, another bot's event, or org B's cell token with org A's event is 404 `unknown_turn`.
   - **What I did:** I followed your "Must hold": board routes follow PR #25, so a call that answers no live turn of this agent is 403 `no_trigger`. The conversation check is implicit, because the conversation is the turn's. The human is re-checked at call time through the agent ∩ human decision.
   - **For 07.1-14:** its guard should expect `no_trigger` on the three agent routes.
2. **[Design] Every call counts, retries and reads included.** The tracer asserts that `tool_calls` grew by 5: create, retry, two patches and the read. The plan said 4. Counting the retry is the conservative reading, because a looping or replaying cell spends budget. The count is committed before the act, so failed calls count too.
3. **[Contract] Create answers 201, and 200 on a retry.** The plan's behaviour said 200; I followed the `AgentChannelBoardCreateCard` contract comment.
4. **[Scope] `chat/index.ts`** is not in `files_modified`. It gained only two exports, `readAgentBoard` and `AgentBoardActor`. No parallel W4 plan touches it (09, 11 and 12 are web only).
5. **[Design] The P-03 refusal is enforced twice.** The contract schema strips unknown keys, so a `title` in an agent PATCH would have been silently dropped. A `preValidation` hook therefore records whether the raw body named `title`, `description` or `fields`, and the route answers 403 `not_author`. The service also refuses agent text edits on its own.
6. **[Spec detail] Confused-deputy reasons.** The plan said "403". The resolver answers `channel.post` / `not_a_member` on writes and `channel.read` / `private_channel` on the read, and the test asserts both.
7. **[Scope] Org B card.** To test "a `messageId` of org B", I created a real org B board and card: Eve is moved to her own organization, as in 07.1-05. That card stays at version 1 / `none`.

## Open items

- **07.1-13 (blocking for the plugin tool):**
  - `ocw_board_card` is not in the cell-wide `alsoAllow` (`GET /cell`, null kind), because the plan keeps the cell view unchanged. The plugin must expose the tool in a way OpenClaw allows on board turns: either the turn's tool list alone, or adding it to the cell view there, which changes `GET /cell` lists.
  - The plugin's `tool-guard.ts` must treat `ocw_board_card` as self-validated, as it does `ocw_memory_save`. Otherwise `/tool-calls` would gate it, and `currentTurnTools` does not know the layout, so the call would be refused `policy_changed`. It would also be counted twice.
  - Keys: use `<eventId>:board:<n>`. The API stores them as `board:<key>`.
- **07.3 mid-turn module change:** a board call does not re-decide `bot.read` for the human mid-turn. That matches `ocw_agent_card` and memory today. Turn delivery is gated by 07.3 (`authorReads`), so a human with Bots off never gets such a turn.

  - add `AGENT_BOARD_CROSS_TENANT_ROUTES` (this file) to the registry guard;
  - add the new audit action `agent.board.refused` to whatever audit catalogue the gate documents.
