## Phase Goal

See `07.16-01-PLAN.md`. **This plan's slice:** the only migration of the phase (D-16: additive; bots without a profile
behave exactly as today), with tenant RLS on every new table, the audience backstop on the bot side table, the wake queue
in the job catalog, and the upgrade proof.

<objective>
Add the four tables and the nine columns of the hub's Database contract to the Drizzle schema, generate the migration
`bot_work_zone`, narrow the composite `SET NULL` actions by hand where Drizzle cannot, add the RLS backstop and TRUNCATE
revokes in `post-migrate.sql`, register `work_session.bot_sync` in the job catalog, and prove constraints, RLS, the
backstop and the N-1 → N upgrade on ephemeral PostgreSQL (D-01, D-03, D-06, D-08, D-09, D-15, D-16, D-19, D-20).

Purpose: every API plan reads and writes these rows; the side table keeps the hot session row and its DTO untouched.
Output: schema, generated migration with header, post-migrate policy, queue catalog, three test files extended or new.
</objective>
