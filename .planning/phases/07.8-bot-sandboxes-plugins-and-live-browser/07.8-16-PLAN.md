<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser client → live-view socket | Authenticated viewers; input frames from one person only |
| controller ↔ other viewers | During a takeover or a member session, other viewers must see nothing |
| API instances | Lease state shared through PostgreSQL and Redis |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.8-16-01 | Information disclosure | other viewers watching a sign-in (usernames, OTPs) | critical | mitigate | Controller-only fan-out during a lease, zero-frame acceptance test (Task 2) |
| T-07.8-16-02 | Information disclosure | owner watching a member's signed-in account | high | mitigate | Member-only frames while a session is loaded (Task 2) |
| T-07.8-16-03 | Information disclosure | typed secrets in logs, spans, audit, events, Redis | critical | mitigate | No logging on the route, sentinel sweep, Semgrep rule (Task 2) |
| T-07.8-16-04 | Spoofing | someone else taking control | high | mitigate | Resolver `browser.control` = requester only; one lease via conditional update (Task 2) |
| T-07.8-16-05 | Elevation of privilege | viewing after access is lost | high | mitigate | Live re-authorization on the invalidation bus (Task 3) |
| T-07.8-16-06 | Denial of service | slow viewers or many contexts | medium | mitigate | One upstream per context, latest-frame-wins, streams only while watched (Tasks 1, 3) |
</threat_model>
