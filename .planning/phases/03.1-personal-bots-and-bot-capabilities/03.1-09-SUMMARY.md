# Phase 3.1 Plan 09: MCP server registry API and the fake MCP server Summary

Organization Admins can register an MCP server (streamable HTTP, SSE, or a vetted server of the stdio sandbox) with header credentials that go straight into the secret store and never come back out; the cell is asked to discover the tools, and recorded tools become per-bot capabilities capped by the org and personal-bot policy and by per-human deny rules, which admins can now create through the rules API.

## What was built

- **Contracts** (`contracts/mcp.ts`, exported): the plan's interface, except `UpdateMcpServerRequest` (see Deviations 1). `McpServer.headers` is `[{name, hasValue: true}]`; there is no field that could carry a value or secret id.
- **Agent Channel (additive)**: `mcp.probe` event (`McpProbeEvent`), `CellMcpServer` (`headers: [{name, envName, value}]`, `tools` = raw MCP tool names for `toolFilter.include`), `CellSnapshot.mcpServers` (default `[]`), `AgentChannelMcpProbeResult` (≤ 200 tools, error ≤ 300 chars).
- **Rules API**: `CreatePermissionRuleRequest` accepts `tool` for `bot.tool.use` (and patterns matching it), so an admin can deny one MCP tool to a role, unit or user (the 03.1-03 follow-up note).
- **modules/mcp**
  - `names.ts`: `safeServerName` (`m` + first free 8-hex slice of sha256(id)), `openclawToolName(s)` (OpenClaw mirror), `cellEnvName` (`OCW_MCP_<SAFE>_<i>`).
  - `url-policy.ts`: `checkMcpUrl`: https anywhere not refused; http only to single-label compose hosts or 10/8, 172.16/12, 192.168/16 literals; never loopback, `0.0.0.0/8`, `169.254/16` (incl. metadata), `100.100.100.200`, `::`, `::1`, `fe80::/10`, IPv4-mapped IPv6, `fd00:ec2::254`, `localhost`/`*.localhost`, `metadata(.google.internal)`, `instance-data`; never userinfo; numeric IPv4 forms normalised by WHATWG URL.
  - `service.ts`: create (validate, safe name, `secrets.put(kind mcp_credential)` per header, insert, audit `mcp.server.created {name, safeName, transport, host, sandboxServer, headerNames, flags}`, `cell.config.changed tools.updated`, `mcp.probe`); update (name, URL, sandbox server, header keep/replace with old secret rows removed, flags; audit `mcp.server.updated {changed, host?, headerNames?, flags}`); delete (grants, server + tools by cascade, secrets; audit `mcp.server.deleted`; `tools.updated`); `probeMcpServer` (audit `mcp.server.probe_requested {probeId}`); `requestProbe`; `recordProbeResult` (newest probe only; ok → tool rows replaced with names computed here, `read_only`/`destructive` only from explicit hints, grants of vanished tools deleted, `ready`; not ok → `error` + redacted detail; audit `mcp.server.probed {ok, toolCount, removedTools?}`; `tools.updated`); `cellMcpServers` (the only place values are revealed).
  - `routes.ts`: six routes, all `authz: user` + `mcp.manage`; GET responses `cache-control: no-store`; list includes `sandbox {available, servers}`.
- **Secrets / env**: `put` kind widened; `OCW_MCP_SANDBOX_URL`, `OCW_MCP_SANDBOX_SERVERS` (names validated `[a-z0-9_-]`).
- **Fake MCP** (`infra/fake-model/fake-mcp.mjs`, no dependencies): streamable HTTP (single JSON responses, `Mcp-Session-Id` on initialize and required afterwards — 400 missing / 404 unknown, notifications → 202, DELETE ends the session → 204, GET → 405), legacy HTTP+SSE (`GET /sse` endpoint event, `POST /sse/messages?sessionId=` → 202 + `event: message`), versions `2025-11-25`, `2025-06-18`, `2025-03-26` (unsupported → newest), tools `echo` (readOnlyHint) and `write_note` (destructiveHint), JSON-RPC errors for unknown tools/methods/parse, optional bearer token (401 + `WWW-Authenticate`). Mounted in `server.mjs` before every other route; the Dockerfile copies it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `UpdateMcpServerRequest` without create defaults**
- **Found during:** Task 1. The interface's `CreateMcpServerRequest.partial().omit({transport})` still applies the create defaults in Zod 4 (checked: `parse({personalAllowed:true})` → `{headers:[], orgEnabled:true, personalAllowed:true, trustedChaining:false}`), so any flag PATCH would have dropped every header and reset flags. Defined explicitly with every field optional; contract and integration tests cover it.
- **Commit:** 0417d3c

**2. [Rule 3 - Blocking] `/cell` returns `mcpServers: []`**
- `CellSnapshot.mcpServers` has a default, so the `/cell` route's response typing required it. One line in `agent-channel/index.ts` (not in the plan's files; 03.1-07 edits the same file elsewhere): `mcpServers: [] as CellSnapshot["mcpServers"]`, with a comment that 03.1-10 wires `cellMcpServers` there. No credential is delivered until then.
- **Commit:** 0417d3c

**3. [Orchestrator note] Rules API accepts a tool on `bot.tool.use`**
- `packages/contracts/src/organization.ts` (not in the plan's files): `TOOL_PERMISSIONS = ["work_session.approve", "bot.tool.use"]`. Unit-tested in `mcp.test.ts` (kept out of `contracts.test.ts`, which 03.1-08 edits in parallel) and end to end in `mcp.int.test.ts` (POST `/permission-rules` deny on `<safe>__echo` → `denied_for_you`, absent from the turn; DELETE restores it).
- **Commit:** 0417d3c

**4. [Rule 3 - Blocking] Fake-model image and old bind-mounted smoke**
