# Phase 07.18 Plan 11: Codex runs under each slot and switches slots on a limit Summary

Each Codex Work Zone session now runs under the `CODEX_HOME` of the ChatGPT slot the server chose. Between turns it can
move to another slot: the adapter stops the app-server, starts one under the new slot and `thread/resume`s the same
thread. It reports usage-limit and unauthorized turns (once per turn, before `prompt.completed`, with the reset of the
exhausted window) and every rate-limit reading. A device whose own Codex login is signed out still reports a model
catalog, collected under its first signed-in slot.

## What was built

- **Task 1 (tracer): a session under its slot's CODEX_HOME** (`32386d41` test, `47c27b9c` feat)
  - `Session.account` holds the slot (ref, label, slotId, codexHome) or null. `spawnSessionServer(id, cwd, account)`
    sets `CODEX_HOME` = the slot home on `codexChildEnv(process.env, false)`. Without an account the env is exactly as
    before, and a parent `CODEX_HOME` passes through.
  - `start` and `wake` both use the session's account, so a retired slot session wakes under the same home.
  - `capabilities.supportsAccounts = ["device_slot"]`. A token account is refused before anything is spawned.
  - Security header: billing is the device's own login or the platform's slot. Tokens stay in the slot's `auth.json`,
    written and refreshed by Codex. The adapter never reads that file.
- **Task 2: switching slots between turns** (`8523d61d` test, `7179b645` feat)
  - `async useAccount(sessionId, account)`:
    - the same ref (compared with a pending switch first) does nothing;
    - an idle session stops its app-server as `retireIdle` does (its end is not the session's end) and goes dormant
      under the new account;
    - during a turn the new account is kept as `pendingAccount` and applied right before the next turn, in both
      `dispatch` and `compact`.
  - The next turn wakes through the existing `wake` path: one spawn, then `initialize`, `thread/resume` (same thread
    id, same thread params), then `turn/start`. `null` resumes under the default home with no `CODEX_HOME` override.
  - A-02 fallback: a resume that fails after a switch throws `AccountSwitchError`. The turn fails with `session.error`
    "This conversation could not continue on the next account. Start a new session." No thread is started. The
    session stays dormant under the new account and is not failed.
  - `ACCOUNT_SWITCH_FAILED_MESSAGE` moved to `runtime.ts`. `claude-runtime.ts` re-exports it, so the existing imports
    still work.
- **Task 3: limits, usage, catalog under a slot** (`3a8c5cdd` test, `a2bfcea4` feat)
  - `codex/limits.ts` (pure):
    - `codexLimitSignal(n, lastWindows)`: `turn/completed` with `turn.error.codexErrorInfo === "usageLimitExceeded"`,
      or a final `error` (`willRetry: false`) carrying it, gives `usage_limit`. The reset is the latest `resetsAt`
      among windows at 100 % or more (epoch seconds, or milliseconds above 1e12), else null.
    - `unauthorized` gives `auth_failed`. `rateLimitExceeded`, object variants and others give null.
    - `codexUsage` turns the present windows into `primary` / `secondary` (percent clamped 0-100, one decimal). With
      no window it returns null.
    - `mergeCodexWindows` keeps a window that a rolling update leaves out; an explicit null clears it.
  - Adapter:
    - `noteAccount` runs first in `onNotification`, before the mapper's events. `account/rateLimits/updated` updates
      the remembered windows and reports `usage`. A limit is reported once per turn (`limitReported` is reset at
      `dispatch` and `compact`), with the running prompt id.
    - After every slot app-server start (start and wake), one `account/rateLimits/read` runs without blocking and is
      reported the same way.
    - Sessions on the device's own login never read the limits.
  - `CodexRuntimeOptions.catalogHome` is asked only when `detect()` says the default home is signed out. `model/list`
    then runs under that home, with no API key and no thread or turn.
  - Daemon:
    - `RuntimeFactoryContext.codexCatalogHome` returns the first slot whose `auth.json` exists (existence only).
    - It is passed to the default `CodexRuntime` and to a test's runtime factory. The daemon and the factory share one
      `CodexSlotStore`.
    - `collectCatalogs` no longer skips a signed-out Codex when a slot is signed in.

## Deviations from Plan

1. **[Rule 2 - Correctness] A slot session never gets an API key.** The plan says the slot env lacks the API keys. That
   now holds even with `codex.useApiKey` on, so a slot always bills the slot's subscription (D-15). Commit `47c27b9c`.
2. **[Design] A switch asked during a turn waits for it.** The plan describes the idle case. A busy session keeps the
   account pending and applies it before the next turn, so a switch never cuts a turn. Commit `7179b645`.
3. **[Design] The shared A-01/A-02 message moved to `runtime.ts`.** `claude-runtime.ts` is not in `files_modified`. It
   now re-exports the constant instead of defining it, with no change in behaviour. Commit `7179b645`.
4. **[Rule 1 - Bug] The daemon skipped every signed-out runtime's catalog.** `collectCatalogs` had a
   `!info.loggedIn` guard, so `catalogHome` alone would never run. The guard now lets Codex through when a slot is
   signed in. Commit `a2bfcea4`.
5. **[Design] `catalogHome` may be async** (`() => string | null | Promise<string | null>`), because the slot store
   reads its file on every call.
6. **[Design] The runtime factory takes a second argument** (`RuntimeFactoryContext`). This lets a test drive the real
   wiring. Existing one-argument factories still type-check.
7. **[Rule 2] Windows are cleared on a switch.** Without this, a limit on the new account could take the previous
   account's reset time.

## Notes

- Titles (`generateTitle`) still run under the default home. A title is an ephemeral model turn, so it is not moved to
  a slot (the plan allows only the catalog there, "no turn"). On a pool-only device, a title request fails as a failed
  ack, as before.
- A-02 (resume under another `CODEX_HOME` with the shared `sessions/`) still needs owner UAT with two real ChatGPT
  accounts. The fallback is built and tested.
