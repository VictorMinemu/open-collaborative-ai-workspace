## Phase Goal

See `07.12-01-PLAN.md`. **This plan's slice:** the device side of terminal pairing (D-03), project removal by any
handle (D-07) and the daemon's own environment file for service secrets (D-12).

Add the device-code client to `ocw-runtime enroll` (no `--code`), sharing one `saveEnrollment` with the typed-code flow;
let `remove-project` take a directory, a name or an id with the daemon up or down; read `~/.ocw/service.env` at `run`
with the mode check; update the unpaired-daemon message for headless servers.

Purpose: 08's `setup` pairs through `pairByDeviceCode`; 05 reports service.env names; 04's units stay secret-free.
Output: `pair.ts`, `service-env.ts` (+ tests), `saveEnrollment`, `ProjectRegistry.resolveRef`, CLI cases.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → CLI | Pairing answers are parsed by the contracts before anything is written |
| service.env → daemon | A local file that may hold a long-lived token |
| terminal output → issue reports | Pairing output is often pasted |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.12-03-01 | Information disclosure | device code / token in output | high | mitigate | Output shows only the user code and the link; Task 1 asserts neither secret appears in stdout or stderr |
| T-07.12-03-02 | Information disclosure | service.env readable by others | high | mitigate | Refused unless 0600 and owned by the user; values never logged (Task 3) |
| T-07.12-03-03 | Spoofing | the owner shown to the server admin | medium | mitigate | "Paired with <org> as <owner>" printed and stored (`pairedWith`), so the server admin sees who controls it (RESEARCH Pitfall 3) |
| T-07.12-03-04 | Tampering | token over plain http | medium | mitigate | Warning on non-loopback `http://` (install.sh refuses it in 06) |
| T-07.12-03-05 | Tampering | removing the wrong project | low | mitigate | Ambiguous names refuse with candidates |
</threat_model>
