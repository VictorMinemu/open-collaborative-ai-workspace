## Phase Goal

"desde devices que lo pueda actualizar con un click": in Settings › Devices a headless server's OCW Local Runtime updates
to the build its workspace serves with one click, and by itself at the device's effective 07.11 level, never cutting a
running turn, verifying every download and restarting through the service manager (ROADMAP Phase 07.17.1; RSU-01 …
RSU-08; CONTEXT D-01 … D-12).

**This plan's slice (tracer, contract tier):** the phase vocabulary in `packages/contracts` and the minimal type
adoption that keeps every workspace compiling. Plus this hub: plan map, shared files, cross-plan names, planner decisions
PD-01 … PD-27, edge coverage, prohibitions, flagged assumptions, source coverage. Every later 07.17.1 plan cites it.

## Planner decisions (PD-01 … PD-27)

- **PD-01 Split.** 11 plans in 5 waves by real dependencies and file ownership (plan map). Fine granularity: 2–3 tasks
  per plan, ≤ 6 source files per task (tests, fixtures and harnesses aside).
- **PD-02 Tracers.** Each plan leads with a production-quality tracer of its own tier. API end to end: 09 T1; device end
  to end: 10 T1; browser: 11 T1 (CI) and the owner's Server-1 UAT (11 T3). The real systemd restart is proven only in
  that UAT (no test may run a real service manager).
- **PD-03 Executor rules (every 07.17.1 plan).**
  - Stay on `feat/07.17.1-runtime-self-update`; never switch branches; locate code by symbol (line numbers are hints
    from `b8c3f667`). Another agent may work in the same worktree: `git add` explicit paths only; on `index.lock`, wait
    a few seconds and retry.
  - Every pnpm and node command under Node 24.22.1: `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; nvm use 24.22.1`.
  - **Local evidence:** unit and web tests, `pnpm typecheck --force`, Biome (`pnpm exec biome check <paths>`), and the
    task's own integration files **one file at a time** (`pnpm exec vitest run --project integration <file>`; Docker
    works, disk is tight: prune stopped testcontainers after a run). The e2e, `gate:compose` and the full `pnpm verify`
    run on the PR's CI only; each `<verify>` lists them under `<ci>`.
  - **CI protocol.** At the end of every plan: `pnpm lint && pnpm guard && pnpm typecheck && pnpm exec vitest run
    --project unit --project web`, commit, push the branch (the first push opens the draft PR), record the CI run URL and
    result in the SUMMARY with `gh pr checks`. A red CI job in a file the plan owns is fixed before the next wave; a
