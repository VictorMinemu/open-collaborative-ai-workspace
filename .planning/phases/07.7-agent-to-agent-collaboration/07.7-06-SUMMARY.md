# Phase 07.7 Plan 06: Turn done, consult replies and Stop Summary

**A consulted bot's answer comes back: when its turn reports done, the hop closes exactly once and the asking bot gets
`agent.consult_reply.v1` as a new turn for the same human in the same thread (nested chains in order, handoffs and
failures handled, taint and cost following the human); the chain's human or a moderator can stop it at any time.**

## Working notes (plan mode, P-19: audit, tenant isolation, permissions)

Intended diff, applied as written:

- **Done route** (`chains.ts`, registered in the cell scope from `index.ts`): tx0 with no user binds `(eventId,
  agentId)` to a turn of this cell's organization (RLS; otherwise 404 `unknown_turn`) and finds its chain (`chain_id`,
  or a chain whose `root_event_id` is the event). No chain → 200, nothing written. tx1 runs as the turn's human: thread
  stream lock → if the turn answers a hop and is not waiting for its own consult, the conditional `pending →
  answered|failed` update with `answer_message_id = reply_message_id` → `announceConsults([question, answer])` →
  `deliverConsultReply` → audit `agent.consult.answered|failed` (ids only, incl. `returnEventId`) → complete the chain
  under its row lock when nothing is pending and either this is the root bot's turn or no return turn was delivered.
- **Reply capture**: `recordChainReply` in the existing `/messages` `onInserted` hook (next to `finishActivity`) and a
  new `onInserted` on `/cards` when the post names an `eventId`. `findTurn` / `resolveReplyTarget` / `noTrigger` are
  untouched (acceptance grep = 0).
- **Stop authority**: the caller must hold `channel.read` on the chain's channel (else 404 `chain_not_found`, the same
  as a missing or foreign id) and be the chain's human or hold `message.delete_any` there (else 403
  `not_chain_owner`). Both decided by the resolver for the request (`perms.can`).

## Deviations from Plan

### Auto-fixed / adjusted

**1. [Rule 1 - Bug] The return turn named the consulted bot as the requester (plugin)**
- **Found during:** Task 1 (05's note, checked against the mapper)
- **Issue:** with `origin` on `agent.consult_reply.v1`, `mapMention` rendered the question's "Consult request" block
  ("Asked by @bea … @bea receives your answer"), false for a return turn; without it, the time block and the gate's
  sentences named Bea (the message author) instead of Víctor.
- **Fix:** `mapConsultReply` drops `origin` before `mapMention`, passes `origin.onBehalfOf` as the requester (turn
  blocks) and sets `MappedMention.requesterName`, which `openclaw-port.ts` prefers over the sender. The answer stays
  Bea's message structurally. Outside the plan's file list (no other 07.7 plan touches these files).
- **Commit:** `ce951533`

**2. [Rule 1 - Bug] A child that closes before its parent turn's done (Pitfall 6 race)**
- The interface's rule ("this event opened a pending consult hop") let Bea's first turn close Archie's hop with
  "Checking with Carl" when Carl's done arrived first. `waitsForChild` also holds the parent when the child was
  already returned to this bot as a return turn. Tested.

**3. [Rule 2 - Correctness] Lock order**
- Done and Stop take the thread's stream lock before touching hop or chain rows (the consult route's order), so a
  Stop or a done racing a consult in the same chain waits instead of deadlocking; completion re-reads pending hops
  under the chain's row lock.

**4. [Rule 2 - Correctness] The chain's human must still read the channel at return time**
- `buildMentionEvents` does not check the structural author's access; `deliverConsultReply` checks it first, like
  `emitCardAction` and `deliverAutomationRun` (no turn is metered for a reply chat would refuse). Automatic cancel
  stays 07.7-09's.

**5. [Contract] `AgentChainCancelResponse`** added to `packages/contracts/src/agent-chains.ts` (contracts first; the
  web plan 07.7-10 calls the route).

**6. [Interface] `cancelChain(tx, {core}, chainId, {byUserId: string | null, reason})`** — `byUserId` is nullable so
  07.7-09's automatic cancel records a system actor.

**7. [TDD note]** Task 1 and Task 3 went RED first (14 tracer tests failing on the missing route; the Stop tests failed

## Notes for later plans

- **07.7-09 (sweeper / auto cancel):** use `deliverConsultReply(tx, deps, hop, "timed_out")` after your own conditional
  `pending → timed_out` update (it reads the chain, checks the human still reads, carries taint, re-types, appends;
  null = nothing delivered → complete the chain like `turnDone` does). For automatic cancel use `cancelChain(tx, {core},
  chainId, {byUserId: null, reason: "auto"})` (system actor in the audit). Take the thread's stream lock before hop and
  chain rows (`lockNextSeq(tx, convTopic(conversationId))`), the order done and Stop use. `noAnswerSentence` gives
  "@bea did not answer in time.".

  return turns; a no-answer return turn's `message.author` is the human, an answered one's the consulted bot.
