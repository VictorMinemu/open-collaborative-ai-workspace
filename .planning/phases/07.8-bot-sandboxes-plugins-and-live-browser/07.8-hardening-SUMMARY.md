# Phase 07.8 gap: hardening before the gate (plan 29) Summary

**The bot browser now runs Chrome 156 stable (156.0.8078.47) on playwright-core 1.64.1. A fresh browser's first
request was sometimes never answered: sandboxd attached to `brw` with a 2-byte JSON body that could reach the agent's
stdin. That is fixed at its root and proven 20/20 on fresh starts (1 hang in 10 before). `brw` now writes structured
diagnostics that sandboxd logs only through a strict allowlist. A private-host change reaches sandboxd at once, and a
test proves a DM never gains a human participant.**

## Task 2 (SHOULD): a fresh browser's first contextOpen never answered

**Diagnosis.** First I added the structured logs, then reproduced the hang with the new
`run-stack-smoke.sh --only coldstart`: fresh browsers, each first `contextOpen` sent right after `browserEnsure`,
as the API does.

- **Before the fix:** 9 of 10 first opens answered; round 5 timed out at 15 s.
- **The failing round's log:** the agent's `stdin_first` was **2 bytes**, received before sandboxd had written
  anything. Then no `op_start` followed. Every passing round's `stdin_first` was 117 bytes, the request line itself.

**Root cause.** `openAgentLink` attached with `docker.hijack(…, {})`, which sent `{}` as the request body.

- Once the Engine hijacks the connection, those 2 bytes can reach the container's stdin. This is a race: usually
  they are lost before stdin is wired up.
- When they did arrive, the agent read `{}{"contextId":…}` as one line and answered "not JSON" with `id: null`.
- sandboxd's pending request then had no answer until the caller's deadline, so the API reported
  `service_unavailable`.
- A retry worked because later lines were clean.

**Fix.**
- `docker.hijack(path, null)` sends no body: `Content-Length: 0` and no content type. The `brw` attach and the egress
  proxy follower both use it. Exec start keeps its JSON body.
- **Defence in depth, not a retry:** every request is written as `\n{json}\n`. The agent skips empty lines, so any
  stray bytes become their own refused line and are never glued to a request.
- The e2e journey's one-time retry is removed, so a regression now fails the spec.

**Logs.** The agent writes one JSON object per stderr line:

```
{ brw: 1, ev, t, … }
```

- **Events:** `start`, `launched` (ms, posture), `sandbox_fallback`, `launch_failed` (code and a fixed reason), `ready`,
  `stdin_first` (bytes), `op_start` and `op` (op name, context id, ms, outcome code; every op except `contextInput`),
  `open_phase` (context, page, cdp), `op_error` (error class name), `bad_line` (bytes), `crashed`, `exit` (reason).
- **What sandboxd forwards.** It parses stderr against `AgentDiag`, a strict zod schema that refuses unknown keys. The
  schema allows:
  - fixed enums for events, ops, phases, postures and runtimes;
  - `^[a-z_]{1,32}$` codes and `^[A-Za-z]{1,40}$` error names;
  - uuid context ids and bounded integers.
  - No field can carry a URL, a host, page text, typed input, a cookie or a message.
- **How it is logged.** Lines that pass go into sandboxd's own log as `brw <ev>` with the bot's org and agent ids.
  Lines over 1 KiB, non-JSON text and Chromium's raw launch lines are dropped.
- **sandboxd's own lines:** it also logs each start as `brw started`, `brw ready` (posture, ms) and `brw not ready`
  (code, ms).
- **The Semgrep live-input rule** now also covers sandboxd's function-style writers (`log`, `writeLog`, `brwLog`),
  with 4 new fixture cases. The rule passes.

**After the fix:** `--only coldstart` with 20 fresh browsers gave 20/20. The slowest first open took 66 ms, every
`stdin_first` was 118 bytes (the newline plus the line), and there were 0 `bad_line` events. The browser was ready in
274 to 339 ms.

## Task 3 (SHOULD): `PUT /keychain/private-hosts` pushes the policy

- **What changed.** After the commit, the route calls `onPrivateHostsChanged(organizationId)`, which `app.ts` wires to
  `pushPolicy`. This is the same path a settings change, kill or resume takes.
- **Failure handling.** `pushPolicy` never throws: with sandboxd down the list is still saved, and the next push
  repairs sandboxd.
- **What is pushed.** The organization's current policy, with its current version. sandboxd accepts an equal version.
- **Integration test** (`settings.int.test.ts`, a recording proxy in front of the fake sandboxd):
  - the new list and the emptied list are each pushed once, with the current settings and version;
  - a lead, a member, a platform host and a loopback host each push nothing;
  - with sandboxd down the list is saved, and the next change pushes;
  - **cross-tenant:** organization B's change pushes B's policy only, and A's list is unchanged.
  - RED by mutation (the call commented out): 3 of the 4 new tests failed.

## Task 4: DM participants (confirmed, no MUST)

- **Result:** a DM cannot gain a human participant. No D-13 change was needed.
- **Test:** `dm-audience.int.test.ts`, 8 tests. It covers Sam's team-bot DM and a human DM.
- **Paths refused** (the human set never changes):
  - `POST /channels/:id/members`, by any caller including the organization admin (DM membership is fixed: the
    `DM_FIXED` precondition, and channel-only routes answer 404 for DMs);
  - `/join` by non-participants;
  - a mention of people in the DM;
  - the AI chat grant and participant routes on a DM id;
  - organization B's admin (404).
- **Another member's DM** with the same bot is their own conversation.
- **Database invariant:** no bot DM has more than one human, and no DM more than two.

## Deviations

1. **Chromium source** (a decision, explained above): the CfT stable build, not playwright-core's own beta pin. Both
   archives come from Google's official bucket, sha256-pinned.
2. **Verify scope.** `pnpm verify` and `pnpm typecheck --force` ran on the final tree, which holds all four commits,
   directly before committing. Each intermediate commit was not verified separately: the four are independent slices
   of that verified tree, and one commit was split from a shared file by staging blobs.
3. **[Rule 3] Smoke assertion.** `browser-smoke.mjs` asserted the agent's old free-text fallback line. It now asserts
   the structured `sandbox_fallback` and `launched … container-only` lines, plus `launch_failed …
   no_usable_sandbox` under the runsc claim.
4. **[Rule 2] Semgrep rule extended.** The new logging goes through function-style writers, which the rule's
   `$LOG.$LEVEL(...)` pattern did not see.
5. **e2e environment.** A `.env` was generated with `pnpm ocw setup --ports 48 --project ocw-hard-e2e` for
   `e2e-isolated.sh`. It was never read, and it was deleted at the end. The `ocw-hard-e2e` compose project and the
   `ocw-e2e-storage` containers, volumes and network this run created were removed. Leftovers: no `ocw.namespace=*`
   container, no `:e2e`, `:smoke-*` or dangling image.
6. **Local Playwright browser.** The 1.64.1 headless shell (`chromium_headless_shell-1248`) was installed into the
   user's Playwright cache, next to the older revisions, which are kept.
