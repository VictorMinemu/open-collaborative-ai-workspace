# Phase 07.2 Plan 05: Presidio detector layer 2 Summary

This plan adds a Presidio client to the API. It is off without a URL, works within one overall 2 s deadline, and on any failure returns the visible `extended_scan_unavailable` info finding. It also adds an optional `pii` compose profile. That profile runs Microsoft's pinned analyzer image with the Spanish spaCy model added. The container is hardened and reachable only from the API, over an internal network.

## What was built

### Task 1: client (tracer)

The client sends one `POST <base>/analyze` per language, all under one shared `AbortSignal.timeout`. Each request carries:
- the scanned text
- the language
- the nine `PRESIDIO_ENTITIES`
- `score_threshold: 0.5`

**Response handling:**
- The body is parsed with Zod.
- Entity types outside the map are ignored. Only the object's own keys count, so `"constructor"` cannot reach the prototype.
- Duplicate spans across languages are merged.
- Samples are masked with `maskSample`, and line numbers are 1-based.
- The output is `{ findings, spans }`, each finding with `source: "presidio"` and `severity: "warn"`.

**Failure handling.** Every failure returns exactly `[extended_scan_unavailable]` and logs one warning: status 500, invalid JSON, a body that fails the schema, offsets outside the text, connection refused, or a timeout. The warning holds only `{ presidio: { errorClass, status } }`.

**Size limit.** Text over 100 KiB is cut at a code point boundary, then back to the last line break. The remainder is not scanned, and an `extended_scan_partial` info finding is added.

**URL handling:**
- A path in the base URL is kept, so the client posts to `/prefix/analyze`.
- Credentials in the URL are moved to a Basic `authorization` header, because fetch refuses URLs that contain credentials.

### Task 3: `pii` profile

**Derived image:**
- Built from the digest above, adding the hash-pinned model.
- At build time it loads both `es_core_news_md` and `en_core_web_lg`, so a broken model fails the build.
- Configuration files: `analyzer-config.yaml`, `nlp-config.yaml` and `recognizers.yaml`, all for `es` and `en`.
- Sets `GUNICORN_CMD_ARGS=--no-control-socket` (see deviation 3).
- Runs as `USER 1001`.

**Service** (`infra/presidio/compose.yaml`, profile `pii`):
- no ports, no volumes, `read_only`
- tmpfs `/tmp`
- `cap_drop: [ALL]`, `no-new-privileges`
- `pids_limit: 128`, `mem_limit: 1536m`, `cpus: 1.0`
- healthcheck on `/health`
- network `pii` only, which is `internal: true`

**compose.yaml:**
- Includes the new file.
- The api joins `default` and `pii`, and gets `OCW_PRESIDIO_URL`, `OCW_PRESIDIO_LANGUAGES` and `OCW_PRESIDIO_TIMEOUT_MS`, each with an empty default.
- The header comment lists the new profile.

**INSTALL.md** has a new section, "Sensitive-data scan (optional `pii` profile)". It covers how to enable the profile, isolation, resources, options, the fail-open marker, the size limit and licences. The "What runs" paragraph now lists four profiles.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 - Bug] Presidio offsets are code points, JS strings are UTF-16**
- **Found during:** Task 3, live probe. An emoji before an entity shifts every later offset.
- **Problem:** without conversion, the masked sample, the line number and the span would point at the wrong characters, or fall past the end.
- **Fix:**
  - `utf16Boundaries()` maps code-point indices to UTF-16 indices. When the text has no surrogates it does nothing.
  - The bounds check uses the code-point length.
  - Two new tests: astral characters before a NIF, and an end offset that is within the UTF-16 length but past the code-point length (marker).
- **Files:** `apps/api/src/lib/presidio.ts`, `presidio.test.ts`
- **Commit:** d02187b4 (included before the Task 1 commit)

**2. [Rule 3 - Blocking] The image's `ANALYZER_CONF_FILE` lists only `en`**
- **Problem:** with only the NLP and registry files from the plan, `AnalyzerEngineProvider` builds the engine with `supported_languages: [en]` and refuses `es`.
- **Fix:** added `infra/presidio/analyzer-config.yaml` (`supported_languages: [es, en]`), and the Dockerfile sets `ANALYZER_CONF_FILE` to it. This file is not in the plan's `files_modified`.
- **Commit:** 633c51da

**3. [Rule 3 - Blocking] gunicorn 25 control socket on a read-only root**
- **Problem:** the image's gunicorn tried to create `gunicorn.ctl` in `/app` and logged `Control server error: [Errno 30] Read-only file system`.
- **Fix:** the Dockerfile sets `GUNICORN_CMD_ARGS=--no-control-socket`. The log is clean after that.
- **Commit:** 633c51da

**4. [Rule 2 - Correctness] Spanish phone detection**
- **Problem:** the stock `PhoneRecognizer` uses the regions `US, UK, DE, …`. Spain is not among them, and `UK` is not a valid region code. Its context words are English only, and its base score of 0.4 is below the client's 0.5 threshold.
- **Fix:** `recognizers.yaml` sets `supported_regions: [ES, GB, US, FR, DE, IT, PT]` and adds Spanish context words.
- **Verified live:** "Mi móvil es el +34 612 345 678" gives PHONE_NUMBER at 0.75, boosted by "móvil".
- **Limit:** a bare national number like "612 345 678" is still not detected by Presidio. Layer 1 (07.2-04) already flags Spanish national phones.

**5. [Rule 2 - Security] URL credentials**
- **Problem:** fetch refuses URLs that contain credentials, so `OCW_PRESIDIO_URL=http://user:pass@…` would always fail open.
- **Fix:** the credentials move to a Basic header. A test proves the password never reaches the log.

**6. Plan said "URL undefined" for the default**
- The existing `optionalUrl` pattern yields `null`. The env test asserts `null`, and the scanner accepts `string | null | undefined`.

## Broken-windows candidates (not written to WINDOWS.md, as instructed)

1. **The `pii` network is created in every compose project, even with the profile off.** This matches `mcp-sandbox`. `compose.e2e.yaml` already warns that hosts with many projects can exhaust Docker's default address pools, and this adds one more internal network per project (gate, e2e, demo on its next `up`).
2. **Recreating the api on the next `docker compose up`.** Adding the `pii` network to the api changes its config hash, so existing installs (and the demo, when its owner next runs `up`) recreate the api container once. This is harmless, but worth a line in the phase release notes.
3. **Presidio Spanish accuracy is unmeasured beyond fixed samples.** In a probe, `es_core_news_md` tagged the verb "Vive" as LOCATION and missed "Pedro" in "Llama a Pedro". It does not detect bare national phone numbers. This needs the owner's manual check listed in VALIDATION (real documents).
4. **No `pnpm ocw enable pii`.** The profile is enabled by two `.env` lines, unlike proxy, observability and vault. A one-line enable command would match the other profiles.
5. **The wheel's sha256 is only as trustworthy as the GitHub download.** The release publishes no digest for 2024 assets. The pin protects against later changes, not against a compromise before 2026-10-12.
