shared account on it: sign in once with OAuth for the whole organization, or use OAuth client credentials, besides the
existing organization headers, member sign-in and member keys. When OAuth cannot work, the admin sees which step failed
and how to fix it.

### Gaps Summary

No gaps. The goal holds in the codebase. An admin can register a server in any of five modes. Organization sign-in and
client credentials keep one sealed organization account per server; the API refreshes it serially and revokes it on
Disconnect; switching mode or deleting the server destroys it after a confirmation. Every member's bot uses that
account only through the API connector proxy, never in the cell. When sign-in fails, the dialog and the row name the
step with a fixed fix line. The existing three modes pass their unchanged suites.
