# Phase 3.1 Plan 04: Capability enforcement in the cell, keyless search, fail-closed tool gate Summary

The cell now enforces each turn's capabilities with three independent guards: an allowlist config, a per-run tool cap and a fail-closed `before_tool_call` gate that asks the API. Internet access goes through a managed, hookable DuckDuckGo search, or SearXNG with the optional `search` profile. Every call is decided again by the API at call time and audited with bot, human, tool and host. CI builds the shipped cell image and runs the real-container smoke. The local Docker VM could not boot a smoke cell (details below).

## What was built

- **Lockdown v2** (`render-config.mjs`). Global `tools.deny = DANGEROUS_TOOLS`, which mirrors the contracts list exactly and has no `*`. `tools.web.search` is `{enabled, provider: duckduckgo|searxng, maxResults: 5, openaiCodex: {enabled: false}}` and `tools.web.fetch` is `{maxCharsCap: 20000, maxRedirects: 3}`. Other settings: `session.dmScope: per-channel-peer`, `userTimezone: UTC`, `compaction.memoryFlush.enabled: false`, and `plugins.allow` = `ocw, openai, duckduckgo, searxng`. The bundled plugins load from `/opt/ocw/plugins/<id>`. `OCW_BUNDLED_PLUGINS=none` disables them. A missing plugin directory is skipped with one log line, and the provider falls back to DuckDuckGo.
  - Every config key was checked against the 2026.9.7 docs in the image.
- **Bundled plugins.** Exact pins plus the npm sha512 `dist.integrity` (`bundled-plugins.json`). The installer aborts on a mismatch (tested with a forged pin) and runs no lifecycle scripts. The Dockerfile build stage installs them, root-owned and read-only.
  - `docker build --check` reports no warnings.
- **CI.** The `images` job now also builds `infra/openclaw/Dockerfile` as `ocw-openclaw:ci`. The new `cell-smoke` job runs `node --test 'infra/**/*.test.mjs'`, builds the plugin, then runs `SMOKE_BUILD=1 bash infra/openclaw/test/run-container-smoke.sh` (every scenario, offline). Both jobs first free disk space on the runner.
- **Compose.** New `searxng` service under the `search` profile, pinned to `searxng/searxng:2026.10.4-d48c4b555@sha256:76b0bf28…`, with settings mounted read-only and no ports. `OCW_SEARXNG_URL` and `OCW_BUNDLED_PLUGINS` are set on `api` and `openclaw`. `infra/searxng/settings.yml` enables the `json` format and turns off the limiter and the image proxy.
- **Fake model.**
  - `[[call <tool> <json>]]` directives: one tool call per step, in order. A namespaced `x__<tool>` also matches. A tool that is not offered gets the reply `Tool X not offered`.
  - The reply ends with `[tools: N | sorted,names]`.
  - Results are summarised by search titles, with OpenClaw's untrusted-content markers removed.
  - Fake SearXNG at `GET /search`.
- **Plugin gate** (`tool-guard.ts`, registered from `registerFull` with no matcher and priority 10 000):
  - It blocks when there is no active turn for the session, the session belongs to another bot, the tool is not in the turn, a cap is reached (8 calls, 5 web calls), or the call is side-effecting after untrusted output.
  - It asks `/tool-calls` for every tool except `ocw_memory_save`, with a 10 s timeout. A denial, error or timeout blocks the call.
  - Afterwards it reports `{status, resultCount, provider, finalUrl?, durationMs}`.
  - Logs carry ids and reason codes only.
- **Port.**
  - `toolsAllow = turn.tools ∩ the bot's snapshot tools`; when that is empty it also passes `disableTools: true`.
  - `beginTurn`/`endTurn` wrap each dispatch, and one run at a time per session key (a promise lane).
  - `ChannelStructuredContext` adds "Current time for <name>" and, in DMs only, "Your notes about <name> (private to this conversation)".
  - It logs `turn <eventId> → session <key> (tools: …)`.
  - It purges the state of removed bots.
- **Reconciler.** Each bot entry is `{profile: minimal, alsoAllow?: tools minus dangerous, deny: DANGEROUS_TOOLS}`. `tools.web.search.provider` comes from the snapshot, only when this cell loaded that provider's plugin.
- **API** (`tool-calls.ts`, inside the cell scope, `authz: cell`):
  - Checks run in order: `unknown_turn` → `not_in_turn` → `policy_changed` (`currentTurnTools(tx, perms, …, core.env)` for the stored human and conversation kind) → `bad_url` → one conditional `UPDATE agent_turns` for caps and taint (`cap_reached` / `tainted`).
  - Writes an `agent_tool_calls` row and audits `bot.tool_call`: actor agent, user = the human, `metadata {tool, sourceKind, target (host only), reason, queryChars}`.
  - `/tool-calls/:callId/result` updates the row and audits `bot.tool_call.completed {tool, status, resultCount, provider, finalHost, durationMs}`. Retries are idempotent, and an unknown call returns 404.

## Facts the plan asked to record

- **Plugin-set log line:** OpenClaw prints `http server listening (N plugins: <sorted ids>; …)` and lists only plugins loaded at startup (`server-startup-log`, `loadedPluginIds` where `status === "loaded"`). Both search plugins declare `activation.onStartup: false`, so a boot may show `2 plugins: ocw, openai` until the first search. The smoke accepts exactly those four ids and fails on any other id or on a skipped bundled plugin. The real line is unobserved until CI runs.
- **Offered tool names seen by the fake model:** unobserved in a real cell (see Deviations). The capabilities scenario asserts `[tools: 2 | web_fetch,web_search]` with internet on and `[tools: 0]` off. The unit and contract suites assert the dispatch gets exactly `toolsAllow: ["web_fetch","web_search"]` / `[]` + `disableTools`.
- **Hook contract observed in the image docs and dist (2026.9.7):**
  - `before_tool_call` gets `event {toolName, params, toolCallId?, runId?}` and `ctx {agentId, sessionKey, sessionId, runId, toolCallId, abortSignal?, requester?}`. It returns `{block, blockReason}` (terminal). Default timeout 15 s, fail closed. Matchers cannot be wildcards.
  - `after_tool_call` is an observer and is not awaited. It gets `{toolName, params, runId, toolCallId, result, error, durationMs}` with the same ctx.
  - Neither hook needs `allowConversationAccess`, and the manifest needs no hook declaration (`docs/plugins/hooks.md`, `hooks/tool-policy.md`, `hooks/reference.md`, `dist/builtin-openclaw-*.mjs`, `dist/hook-helpers-*.mjs`).
- **Transcript purge finding:** the docs show per-agent state (session rows and transcripts in `agents/<id>/agent/openclaw-agent.sqlite`, archives in `agents/<id>/sessions/`) is cleaned up only by `openclaw agents delete`. Removing the agent from the roster through `mutateConfigFile`, which is what the plugin does, keeps it. So the purge is implemented and unit-tested. Paths are limited to `ocw-*` ids under an absolute state dir, and there is no purge when OpenClaw refused the removal. The `dm-isolation` smoke asserts the directory is gone and that no agent-state file contains the secret. The real-cell observation is pending CI.
- **Local cell image:** **not built.** The Docker VM had about 683 MB of disk free, and the plan requires at least 1.5 GB. The shipped image is built by the CI `images` job (`ocw-openclaw:ci`). The smoke bind-mounts the working-tree plugin, renderer, entrypoint, fake model and host-installed bundled plugins, so it does not need a rebuild.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `:?` guard on the SearXNG secret broke `docker compose config`**
- Compose interpolates every service, including those of inactive profiles, so the plan's `${OCW_SEARXNG_SECRET:?…}` made the required `docker compose config -q` fail.
- Fix: default to SearXNG's placeholder key, which SearXNG refuses to start with (checked in `searx/webapp.py`). The variable is still effectively required, and both config checks pass. Documented in compose.yaml and the README.
- **Commit:** b27df15

**2. [Rule 1 - Bug] The plugin-set hardening check would have failed on a correct cell**
- The plan's check expected all four plugins in the boot line. The search plugins load lazily (`onStartup: false`), and the boot line lists only loaded ids, sorted.
- Fix: the check accepts only the four permitted ids and fails on a skipped bundled plugin.
- **Commit:** 7fe4c23

**3. [Rule 2 - Correctness] Search provider switch only for a loaded plugin; strictest flags; agent-mismatch block**
- The reconciler never selects a provider whose plugin this cell did not load.
- The API uses the stricter of the delivered and the current flags.
- The gate blocks a session whose OpenClaw agent is not the turn's bot.
- **Commit:** 7fe4c23

**4. [Rule 1 - Bug] Fake-model result summary**
- The plain "first 200 chars of the result" could cut off before the search title when OpenClaw wraps the JSON payload in text.
- Fix: titles are taken from the embedded JSON, with untrusted-content markers removed. Test added.
- **Commit:** 2e2bf89

**5. [Plan wording] Files not changed**
- `bridge.ts`: the mapper already receives the snapshot agent, so its `capabilities.tools` reach `mapMention` without a change.
- `openclaw.plugin.json`: only the description changed. The image docs show tool hooks need no manifest declaration and no `allowConversationAccess`.

**6. [Plan sequencing] Task 3 tests passed on first run**
- The Task 2 implementation already had the single conditional UPDATE, local caps, taint, `endTurn` on abort and per-session state.
- Only the purge (`agentStateDirFor`) and the parity test were RED (3 failing) before the Task 3 code.

**7. [Environment] Real-cell smoke not run locally (SC3 cell half pending CI)**
- The smoke cell was OOM-killed during OpenClaw's boot under the orchestrator-mandated `--memory 1g`, at both the 512 MB and 320 MB heap caps. The VM had about 0.9 GB available and full swap; the demo cell alone uses about 0.97 GB.
- Per the orchestrator's rule, it was not retried without the cap.
- The new CI `cell-smoke` job is where the real-cell path (`capabilities`, `dm-isolation`, plus `mention`, `dm`, `signin`) gets proven.
- Recorded in `.planning/WINDOWS.md` as unrun-verify (ids 4 and 5). The smoke also gained an optional `SMOKE_CELL_MEMORY` cap. The fixture generators and the web fixture's parse and map through the built plugin were exercised locally.
