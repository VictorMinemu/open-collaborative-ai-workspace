# Phase 07.9 Plan 11: Work Zone projects index, project page, routing fix Summary

People find their team projects from a new **Projects** link in the Work Zone sidebar, open one, and see exactly the
sessions their audience allows in it; admins and team leads create projects in a two-field dialog. The layout no longer
treats `/work-zone/projects…` as a session (R8). Per D-14, a lead of the parent unit opens the project page too, and
its Sessions list still shows only what that person may see.

## Intended change (CLAUDE.md plan mode, API part)

D-14 ("managing a project opens its page") was assigned to plans 11 and 13 after the hub, and no API plan implemented
it: `GET /work-projects/:unitId` required `work_session.read`, which the `not_in_project` precondition refuses to a
parent lead outside the project. The change: the detail route answers when the caller holds `work_project.manage` on
the project **or** `work_session.read`; the index lists projects the caller can open or manage. Both are resolver
answers; no rule is copied, the precondition is untouched, every other caller keeps the identical unknown-id 404.
Session lists are unaffected (`GET /work-sessions` still decides each session).

## Deviations from Plan

1. **[Rule 2 / D-14] API change in `work-session/projects.ts` (04's file, 12 may touch it for RLS).** D-14 was decided
   after the hub and assigned to 11 and 13; without it a parent lead had no way into the page. Two small hunks (detail
   route, index filter) plus one integration case. 12 should rebase cleanly; if it conflicts, keep both.
2. **[Rule 2] New session is absent when the viewer can start on none of the project's repositories.** The UI-SPEC
   says disabled-with-tooltip only when no repository is online. For a member without `device.use` (or a D-14 manager
   without project access) "none is online" would be false, so the button is absent for them.
3. **[Rule 1] Ready status chip contrast (`meta.tsx`).** The reused `WorkZoneHome` row's "Ready" chip failed axe (2.5:1,
   09's broken-window candidate). Fixed with the Badge success pill colours (also improves the home page).
4. **[Rule 2] `ServerUnreachable` gained an optional `title`** (default unchanged) for "Couldn't load projects." and
   "Couldn't load this project.".
5. **A malformed id (400) and 403 read as the no-access state**, like 404 (no existence leak; the e2e covers it).
6. **Devices link got `max-md:h-11`** next to the new Projects link so the two rows match at 390 (touch rule); both now
   sit in one `mt-auto` group. Desktop look unchanged.
7. **Test ids:** `projects-index` wraps the whole page (header included, so axe sees the header); the pure body is
   `projects-index-body`. Added `project-no-access`, `project-new-session`, `project-sessions-more`,
   `project-sessions-footnote`, `new-project-parent(-option)`, `new-project-submit`.
8. **Settings tab not built here** (plan: 13's slice). `?tab=settings` is parsed and the page carries `data-tab`; 13
   adds the tab bar and the panel to `project-page.tsx`.
9. **`useWorkZoneOrgSync`** is mounted once by `WorkZoneShell`, which wraps the project pages; nothing new was mounted.
   The other three mounts (devices settings, agent card, approvals) are on other pages and outside this plan.
10. **TDD:** RED observed for the routes unit test and the D-14 integration case. The component tests and the e2e spec
    were written alongside the components, so their RED was not observed separately.
11. **Branch name** `wt/07.9-11` (the coordinator's) is outside the executor's `agent-*` allow-list; commits were made
    there as instructed.
