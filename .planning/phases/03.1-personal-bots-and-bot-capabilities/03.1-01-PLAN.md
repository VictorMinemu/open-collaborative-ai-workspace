## Phase Goal

**As a** member of an organization, **I want to** have my own private bot that lives as a direct chat in my sidebar and answers every message, and to give every bot (mine or the team's) explicit, admin-governed capabilities (internet, memory, reply mode, time context, a daily limit, MCP servers and OpenClaw Marketplace plugins), **so that** I get a useful assistant without exposing my conversations to anyone and the organization stays in control of what bots can do.

(ROADMAP Phase 03.1 goal restated as a user story: "Every member can have their own private bot that lives as a direct chat in their sidebar and answers every message, and every bot — personal or team — has explicit, admin-governed capabilities (internet, memory, reply mode, time context, usage limit, MCP servers and OpenClaw Marketplace plugins) enforced in the OpenClaw cell on every turn".)

**This plan's slice (tracer):** a Developer creates a personal bot in one click, its private chat appears under Bots in the sidebar, and the bot answers a message without an @mention; nobody else can read it. It also lands the whole phase's schema and permissions.

## Decisions (planner, owner-delegated; referenced as D-01 … D-16 in every Phase 3.1 plan)

There is no 03.1-CONTEXT.md; the owner delegated every decision and accepted every recommended default of `03.1-RESEARCH.md` (Addendum A and B8). These are binding for plans 03.1-01 … 03.1-15.

- **D-01 Personal bots.** A personal bot is an `agents` row with `scope = 'personal'` and `owner_user_id` (team bots: `scope = 'team'`, owner null). The resolver gains resource type `agent` with relation `owner` and states `personal` and `disabled`. A personal bot is visible to and usable by its owner only; admins see governance metadata (name, owner, model, capabilities, usage) and may disable or delete it, never read its chat, memory or instructions. In 3.1 a personal bot lives only in its owner's DM: it can never be a member of a channel, is never resolved as a channel @mention and is never offered in channel autocomplete. Default limit: 3 personal bots per user (`bot_policies.max_personal_bots_per_user`).
- **D-02 Permissions (add-only, ADR-0007 rails).** `bot.create_personal` (surface bots, every role, delegable, deniable by rules); `bot.configure` (surface bots; granted by the `owner` relation on an agent and by the admin role on team bots; the personal precondition denies it to non-owners); `bot.internet` and `bot.tool.use` (surface bots, every role, also in `AGENT_PERMISSIONS`, decided as agent ∩ triggering human; `bot.tool.use` carries the tool layer `ResourceFacts.tool = <tool name>`); `plugin.manage` and `mcp.manage` (surface admin, admin role only, non-delegable). `bot.manage` keeps team-bot CRUD and personal-bot governance (list metadata, disable, delete).
- **D-03 Direct conversations.** A DM is `conversations.kind = 'dm'`, `visibility = 'private'`, exactly two members (the human with role `owner`, the bot), unique per pair through `dm_key = 'agent:<botId>|user:<userId>'` (partial unique index on `(organization_id, dm_key) where kind = 'dm'`). DMs reuse the channel resource facts with a new state `dm`: reading is member-only (admins included, existing `private_channel` precondition) and membership is fixed (`channel.members.add`, `channel.members.remove`, `channel.archive` denied with reason `direct_conversation`). Message routes, read markers, the `conv:` topic and the agent reply path accept `channel | dm` through one `getConversation(tx, id, kinds)`; `/channels/*` routes stay channel-only; DMs are listed by `GET /api/v1/dms`. Human↔human DMs and group DMs stay in Phase 4.
- **D-04 DM delivery.** Every human-authored message in a DM produces exactly one `agent.mention.v1` for the DM's bot (no mention needed), inside the message transaction, only while the human still holds `bot.read` on the bot and the bot is not disabled or deleted. `thread.rootMessageId` carries the message id (schema unchanged); `conversation.kind = 'dm'` tells the plugin to reply flat (`threadRootMessageId: null`) and to use one OpenClaw session per DM conversation (no thread suffix). History = the last 50 DM messages, oldest first, current excluded. Bot-authored messages never trigger. Disabling or deleting a bot archives its DMs; re-enabling unarchives them (03.1-02).
- **D-05 One migration.** The tracer generates the only Drizzle migration of the phase (`*_personal_bots_capabilities`). Later plans add code only; a plan that needs a schema change stops and reports it (Pitfall 9). Tables are listed in this plan's Task 1.
- **D-06 Capability model.** Built-in toggles per bot: `internet` (web search + page fetch, read-only), `memory`, `dateTime` (exact local time of the asking human), `replyMode` (`mentions` | `all`, channels only) and `dailyLimit` (turns per day). Defaults: team `{internet: false, memory: false, dateTime: true, replyMode: "mentions", dailyLimit: 100}`, personal `{internet: false, memory: true, dateTime: true, replyMode: "mentions", dailyLimit: 30}`. Org policy (`bot_policies`, one row per org, defaults allow everything): per built-in capability `{orgWide, personal}`, `searchProvider` (`duckduckgo` default, `searxng` when configured), `maxPersonalBotsPerUser` 3, `personalDailyLimitMax` 100, `personalAllowedModels` (empty = every allowed model). Tool sources (MCP servers, installed plugins) carry their own `org_enabled` and `personal_allowed` flags (`personal_allowed` defaults to false). Effective capability = toggle ∧ org-wide policy ∧ (personal ? personal policy : true) ∧ configured ∧ resolver(agent ∩ human) with reason codes `org_policy`, `personal_policy`, `not_configured`, `denied_for_you`, `source_unavailable`, `dangerous`, `dm_only`. 03.1-03 defines the complete contracts once.
- **D-07 Turn policy in the API.** The API computes the effective turn for every delivery (`turnPolicy`) and ships the result inside `agent.mention.v1` as the optional `turn` block `{tools, toolFlags, memory, now, maxToolCalls}`; it records the delivery in `agent_turns`. The cell never recomputes policy; it only intersects with its snapshot. A plugin that receives no `turn` runs with no tools (fail closed). A policy or toggle change bites on the next turn even before the cell reconciles.
- **D-08 Three-layer tool lockdown + gate.** (1) Global `tools.profile: "minimal"` with an explicit dangerous-tool deny list that never contains the wildcard and never contains `web_search`, `web_fetch` or `ocw_memory_save`; (2) per-agent `alsoAllow` = the tools that bot may ever use (from `/cell`); (3) per-run `toolsAllow` = `turn.tools` ∩ snapshot (empty → `disableTools: true`); plus a `before_tool_call` hook registered without a matcher that blocks any tool outside the active turn and asks `POST /agent-channel/v1/tool-calls` for every gated call (fail closed on error or timeout, client timeout under 15 s). Taint rule: after any tool with untrusted output ran in a turn, side-effecting tools (`ocw_memory_save`, MCP tools without `readOnlyHint`, plugin tools) are blocked for the rest of the turn unless their source is marked "trusted for chained calls". Per-turn caps: 8 tool calls, 5 web calls. Shell/exec, filesystem, browser/computer control, gateway admin, messaging, nodes and `x_search` are never offered.
- **D-09 Internet provider.** `web_fetch` is OpenClaw core. `web_search` uses the official `@openclaw/duckduckgo-plugin@2026.9.7` bundled into the cell image (keyless, no container), pinned with integrity, loaded from `/opt/ocw/plugins`. `@openclaw/searxng-plugin@2026.9.7` is bundled too and becomes the provider when `OCW_SEARXNG_URL` is set (optional compose profile `search`). Brave is excluded (paid). Hosted/native search is off (`tools.web.search.openaiCodex.enabled: false`, provider pinned), `x_search` denied. Both plugins are owner-approved official packages: no human checkpoint.
- **D-10 Memory.** Stored in Postgres (`agent_memories`) per (bot, human), read and written only in that human's DM with the bot, saved through our own tool `ocw_memory_save` whose owner comes from the stored delivery (`agent_turns`), never from tool params. Visible to the human it belongs to and clearable (one or all); admins can never read it; audit rows never contain the text. OpenClaw `memory-core` stays off.
- **D-11 Usage limits.** Atomic daily counter per bot (`agent_usage_daily`, UTC day) incremented at delivery with a single conditional upsert. At the limit: no cell event (provably no model call), a clear notice posted as the bot after commit, audit `agent.limit_reached`; in channels the notice goes out once per conversation per day. Owners (personal) and admins see today's usage against the limit and the reset time in their local time.
- **D-12 Reply mode and time.** Reply mode `all` (team bots in channels): only human-authored messages trigger, a bot stays silent when the message @mentions any other bot, replies go to the message's thread, per-(bot, conversation) cap of 6 automatic replies per minute (excess ignored, audited once per window) on top of the daily limit. Date/time: the composer sends the browser's IANA time zone; the turn carries the asking human's exact local time; with the toggle off the turn carries none (OpenClaw's own date line stays, `agents.defaults.userTimezone: "UTC"`).
- **D-13 MCP servers.** Admin registry (`mcp.manage`), remote first (`streamable-http`, `sse`; HTTPS, or http to private/compose hosts only). Credentials are write-only `SecretReference`s (`app.secrets`, kind `mcp_credential`) delivered over `/cell` as `${OCW_MCP_<ID>_<N>}` env refs, never written to config or logs. Immutable safe server names `m` + 8 hex chars. Tools are discovered by a probe run in the cell and stored per server; bot managers enable individual tools per bot (personal bots only from servers with `personal_allowed`). stdio servers run only in the separate `ocw-mcp-sandbox` sidecar (03.1-14, optional: it may slip without blocking SC6). Per-human MCP OAuth is out of scope (needs a public gateway origin).
- **D-14 Marketplace.** The API proxies ClawHub (`OCW_CLAWHUB_URL`, default `https://clawhub.ai`, metadata cached 10 min, no telemetry); the cell never browses. A pure risk scorer classifies each version `refuse | high | medium | low` from channel, verification tier, scan/trust status and the declared capability surface. Official channel only by default; community needs an explicit high-risk acknowledgement and is never available to personal bots unless the admin allows it. Installs are pinned versions approved by an admin (`plugin.manage`), executed by our plugin in the cell after verifying the approved digest, behind OpenClaw's `security.installPolicy` exec gate that allows only approved (package, version, digest); updates are manual and need a fresh review; auto-update stays off; plugin hooks get `allowConversationAccess: false` and `allowPromptInjection: false`; dangerous tool classes stay blocked whatever a plugin declares.
- **D-15 Test and infra rules.** E2E only via `bash scripts/e2e-isolated.sh` (never the demo on :4000/:3000 or `ocw-demo-openclaw`; no `docker compose down/rm/stop/restart`; no `pnpm demo:*`; no migrations against the demo database). No new heavy images in CI-critical paths: fake ClawHub, fake MCP and fake SearXNG are routes of the existing fake-model server; the container smoke bind-mounts working-tree code into existing images (`SMOKE_ONLY=<scenarios>` selects scenarios). The browser e2e simulates the cell with `e2e/support/fake-cell-plugin.ts`; the real cell is proven by `infra/openclaw/test/run-container-smoke.sh` and by the final manual proof (03.1-15) against the isolated stack. ADR-0010 (personal bots, capability model, tool gate) and ADR-0011 (marketplace trust model, MCP remote-first) land in 03.1-15.
- **D-16 UI.** Chat sidebar section "Bots" (personal and team DMs, one-click create), a flat DM view, a bot settings sheet (identity, capabilities, usage, memory), admin pages Settings › Bot policy, Settings › Marketplace and Settings › MCP servers. shadcn tokens only; every UI task captures 1440 and 390 screenshots in light and dark into `.planning/phases/03.1-personal-bots-and-bot-capabilities/screenshots/` and the executor reviews each one with the Read tool before closing the task.
