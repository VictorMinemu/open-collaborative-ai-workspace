# Phase 07.17.1.1.1 Plan 02: The sbx Python lock, its licenses and pre-install evidence Summary

**A 27-pin, sha256-hashed, wheels-only pip-tools lock for the document toolkit resolved on the image's own Python 3.11.2, one SPDX record per pin enforced by `pnpm guard`, and a scripted PyPI/OSV evidence document whose checks (a)-(e) pass after four too-new pins were held back.**

- **Completed:** 2026-11-12T19:48:26Z
- **Tasks:** 3 (Task 1 tracer)

## Accomplishments

- `tools/lock.sh` resolves `requirements.in` in `node:24.22.1-bookworm-slim@sha256:55fb5f5a…d205` (Python 3.11.2,
  `pip-compile 7.6.2 --generate-hashes --only-binary :all:`), downloads the pinned wheels with `--require-hashes
  --no-deps` and reads each `METADATA` with `zipfile`. Nothing is installed and no package code runs. The image was
  already on this machine and was left in place.
- `requirements.lock`: 27 pins, 754 sha256 hashes covering every wheel of each pinned version (amd64 and arm64).
  numpy 2.4.6 and soupsieve 2.10 (the 3.11.2 constraints of Pitfall 5).
- `licenses.json`: 27 records. `pnpm guard --only licenses` now checks 1083 package versions (1056 npm + 27 Python).
- The guard fails on a pin without a record (`<name>@<version> (Unknown) [infra/sandbox/sbx/tools/requirements.lock]`),
  a stale record (`licenses.json entry alpha@0.9.0 has no pin in requirements.lock`), a malformed manifest, a manifest
  without its lock, or a denied license.
- `scripts/sandbox-lock-evidence.mjs` produces the PD-14 document. Final run: `ok: true`, (a)-(e) all true, `holdBack: []`.
