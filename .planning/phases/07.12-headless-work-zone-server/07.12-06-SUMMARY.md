# Phase 07.12 Plan 06: The workspace serves its own Local Runtime — Summary

**The API serves the runtime bundle built in its image, its manifest and checksum, and a POSIX `install.sh` rendered
from `OCW_PUBLIC_API_URL` only. The script verifies the SHA-256 with node, installs for the current user with the Claude
Agent SDK from npm beside the bundle (exact pins, `--omit=optional --ignore-scripts`) and never elevates. The compose
gate checks all four routes on the release images.**

## Intended change (CLAUDE.md plan mode: new public routes)

- Four new **public**, read-only routes in the device module, each limited to 30 requests per minute per client IP
  (per route, per API instance; behind a proxy `OCW_TRUST_PROXY` decides the client IP, as for 02's pairing routes):
  - `GET /api/v1/runtime/version`: the manifest JSON;
  - `GET /api/v1/runtime/bundle`: the file, with `ETag`, `x-content-sha256` and an attachment name (304 on a matching
    `If-None-Match`);
  - `GET /api/v1/runtime/bundle.sha256`: `<sha256>  ocw-runtime.mjs`;
  - `GET /api/v1/runtime/install.sh`: the installer.
- They read no organization data, take no input beyond the path, and need no session (a server has none before it is
  paired). All four were added to the exact public allowlist in `authz.int.test.ts` (an updated expected list, PD-17).
- No migration, no permission, RLS or approval change.

## What was built

- **`distribution.ts`.** `RuntimeDistStore` reads `manifest.json` and `ocw-runtime.mjs` from `OCW_RUNTIME_DIST_DIR`
  (else the checkout's `apps/local-runtime/dist`), parses the manifest with `RuntimeDistManifest` and re-hashes the
  bundle (sha256 and byte count). It caches only a verified load (until the API restarts); concurrent first requests
  share one read. Missing files give 404 `runtime_unavailable`; a mismatch or an unparsable manifest gives 503
  `runtime_corrupt`. Both are re-checked on the next request and logged once per state change, without a path.
- **`install-script.ts` + `install-script.sh`.** `assertScriptSafeUrl` accepts only `http(s)://` followed by
  `[A-Za-z0-9.:/_-]`, with no credentials, query or fragment, and strips trailing slashes. `renderInstallScript`
  re-parses the manifest and fills the template's placeholders with single-quoted values. The script:
  - `set -eu`, `umask 077`, everything inside `main()`, last line `main "$@"`;
  - server = `OCW_SERVER_URL` or the embedded URL, same character rule, `https` or loopback `http` unless
    `OCW_INSTALL_ALLOW_HTTP=1`;
  - checks Linux or macOS, warns as root, needs node ≥ `minNode`, npm, and curl or wget, all before anything is
    written;
  - downloads into `mktemp -d` (removed by an EXIT trap), checks the sha256 with `node -e` and `crypto`;
  - installs into `~/.ocw/runtime/versions/<sha12>` (reused when complete), runs `npm install --prefix <dir>
    --no-audit --no-fund --omit=optional --ignore-scripts <pins>`, checks that `node <dir>/ocw-runtime.mjs version`
    prints the embedded version, `ln -sfn versions/<sha12> current`, writes `install.json` with node (the five
    `RuntimeInstallInfo` fields) and the `~/.local/bin/ocw-runtime` shim (0755, paths single-quoted);
  - keeps the new version and the previous `current`, removes older `versions/<12 hex>` directories;
  - prints the PATH hint, `Next: ocw-runtime setup`, and on an upgrade the `ocw-runtime service restart` hint.
- **Env.** `OCW_RUNTIME_DIST_DIR` (empty = unset).
- **Image.** `runtime-pruner` (`turbo prune @ocw/local-runtime --docker`) and `runtime-bundle` (frozen install of the
  pruned workspace, `build:bundle --out /out`, `OCW_SOURCE_COMMIT` from a build arg). The runner copies only `/out` to
  `/app/runtime-dist` and sets `OCW_RUNTIME_DIST_DIR`.
- **Gate.** `checkRuntimeDist(apiUrl)` after `api-health`. The manifest sha256 must be 64 hex, the checksum line must
  start with it, the bundle must hash to it, and `install.sh` must start with `#!/bin/sh`. Details carry only the
  version and a 12-character sha prefix.

## Deviations from Plan

### Auto-fixed / adjusted

**1. [Rule 3 - Blocking] The script body is a `.sh` template beside `install-script.ts`**
- **Issue:** a TypeScript template literal would need every shell `${…}`, backslash and backtick escaped, which makes the
  security-relevant script hard to read and review.
- **Fix:** `install-script.sh` holds the body with `@NAME@` placeholders. `install-script.ts` reads it once and fills in
  single-quoted values, and throws on an unknown placeholder. The acceptance grep for `checksum mismatch`,
  `OCW_INSTALL_ALLOW_HTTP` and `--ignore-scripts` therefore matches `install-script.sh` (3 lines), not the `.ts` file.
- **Files:** `apps/api/src/modules/device/install-script.sh` (new, not in the plan's file list).

**2. [Rule 2 - Security] No `--chown=node:node` on `/app/runtime-dist`**
- The plan wrote `COPY --from=runtime-bundle --chown=node:node /out /app/runtime-dist`. The copy is root-owned (0644)
  instead, so a compromised API process cannot rewrite the bundle it serves. The API only reads it, which was checked
  in the image.

**3. [Rule 1 - Bug] RESEARCH A1 `--no-optional` rejected**
- The frozen lockfile accepted `--no-optional`. But it also skipped `@esbuild/linux-arm64`, and esbuild's postinstall
  then ran `npm install @esbuild/linux-arm64` from the registry, outside the lockfile. The flag was removed and a
  Dockerfile comment explains why. The SDK's optional platform package stays in the builder layer and never reaches
  the runner.

**4. Plan-text adjustments (no rule):**
- The plan's "OCW_INSTALL_ALLOW_HTTP=1 proceeds via `OCW_SERVER_URL=http://127.0.0.1:<port>`" case cannot show the
  flag doing anything, because 127.0.0.1 is loopback. The test keeps that case and adds `OCW_SERVER_URL=http://0.0.0.0:1`:
  that address counts as non-loopback, so it is refused without the flag. With the flag the script goes on to the
  download, which fails immediately with connection refused and never leaves the machine.
- PATH in the behaviour tests: the plan named "the real node's directory, /usr/bin, /bin". Instead, each case gets a
  bin dir holding a `node` link and the fake npm, plus a tools dir linking only the 11 system commands the script uses.
  The real node directory also contains the real `npm`, so the no-npm case could not be built from it.
- `compose-gate.test.mjs` gained 2 `checkRuntimeDist` cases using a fake fetch. The file was not in the plan's list.
- Not in the plan: a 304 on `If-None-Match`, and 503 `install_script_unavailable` when `OCW_PUBLIC_API_URL` cannot be
  embedded. The env schema already requires a URL, so the 503 only happens for a URL containing a character outside the
  allowed set.

## Notes for Later Waves

- **07 (web):**
  - The install command is `runtimeInstallCommand(apiUrl)` → `curl -fsSL <api>/api/v1/runtime/install.sh | sh`.
  - `GET /api/v1/runtime/version` (public) gives the version and sha to display.
  - A 404 `runtime_unavailable` means the workspace has no bundle, for example a dev checkout that never ran
    `pnpm --filter @ocw/local-runtime build:bundle`.
- **08 (setup) and 05 (doctor):**
  - `install.json` holds exactly `serverUrl`, `version`, `sha256`, `installedAt`, `nodePath`.
  - `nodePath` is the absolute `command -v node`, which can be a symlink such as `/opt/homebrew/bin/node` or an nvm
    path.
  - `serverUrl` is `OCW_SERVER_URL` when it was set.
  - The shim is `exec '<node>' '<OCW_HOME>/runtime/current/ocw-runtime.mjs' "$@"`.
- **09 (e2e):**
  - Point `OCW_RUNTIME_DIST_DIR` at a fresh `build:bundle --out` directory, or rely on the checkout's `dist`.
  - The store caches a verified load until the API restarts, so rebuild the bundle before the stack starts.
  - Use a fake npm, as in `install-script.test.ts`.
- **10 (container):**
  - `node:24.22.1-bookworm-slim` has no curl or wget, and the script needs one of them. Use a non-slim image or
    install curl in the container.
  - Inside the container, use `OCW_SERVER_URL=http://host.docker.internal:<port> OCW_INSTALL_ALLOW_HTTP=1`.
  - The real `npm install` there uses `--omit=optional --ignore-scripts`.
- **11 (gate, docs):**
  - `pnpm gate:compose` now runs `runtime-dist` right after `api-health`.
  - To fill the manifest's `source.commit`, pass `--build-arg OCW_SOURCE_COMMIT=$(git rev-parse HEAD)` to the API build.
    Compose does not pass it yet; without it the commit is `null`.
  - `docs/SERVER.md` should say: the limits are per instance and per route (30 per minute); `OCW_TRUST_PROXY` behind a
    proxy; `OCW_INSTALL_ALLOW_HTTP` only on a trusted network.
