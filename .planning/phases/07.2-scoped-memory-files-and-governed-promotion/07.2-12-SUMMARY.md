# Phase 07.2 Plan 12: Memory editor, history with diffs and file actions Summary

**Writers now edit memory files as Markdown in CodeMirror 6. Each save carries the version it started from, so a
concurrent save opens a conflict view (theirs vs yours: Keep mine / Use theirs) and is never silently overwritten. A
pasted secret is refused with its line and a masked sample. History lists every revision with +N −M and shows a
`@codemirror/merge` diff: side by side from 520 px, unified below. Any older version can be restored as a new one.
Files and folders can be created, renamed or moved and deleted; MEMORY.md can't be renamed or deleted. On phones and
from 1024 to 1279 px the file has View · Edit · History tabs. The owner sees their private memory change live.
Reviewed in 21 screenshots at 1440 and 390, light and dark.**

## What was built

- **Editor (lazy).** It loads through `next/dynamic` only when you enter Edit. The e2e checks that reading never
  downloads a script containing CodeMirror, and that entering Edit does.
  - Uses the app font at 14/22, a primary caret, `bg-primary/20` selection and an active line.
  - Markdown is highlighted from the app palette: semibold headings, muted marks, mono code.
  - Tab is not bound.
  - The accessible name is "Markdown source of {path}".
  - Toolbar: "● Unsaved changes", Cancel and Save. Save is disabled until the text changes. While saving it shows a
    spinner and "Saving…", and the editor is read-only.
  - Cmd/Ctrl+S works inside the editor and on its toolbar.
  - Footnote: "Markdown · ⌘S to save" and "N KB of 256 KB". The size turns red above 90%.
  - A `beforeunload` prompt appears while the draft is dirty.
  - At 1440 the toolbar sits in the header row. Below 1280 it is an h-14 action row under the tabs, with 44 px buttons.
- **Save outcomes.**
  - Success: the toast "Saved version N", then back to View. Focus goes to the Edit tab at 1440, or the View tab on
    tabbed layouts.
  - 409: the conflict view.
    - An amber alert: "{name} saved version N while you were editing."
    - The heading "Choose what to keep" takes focus.
    - The diff compares "Version N (saved)" with "Your changes".
    - Keep mine re-sends with the new version, and another conflict reopens the view. Use theirs discards the draft.
    - On phones both buttons are stacked full width, with their explanations.
  - 422 `secret_detected`: a red alert with the headline ("on line 14"; several lines are listed up to 3, then
    "and N more"), the masked sample in mono and "Go to line N". The lines are tinted with a 3 px bar. Nothing is
    saved.
  - Too large, scope full and network errors: blocking notices in plain words. The draft is kept, and network errors
    offer Try again.
  - A live newer version while editing (the owner's private files): the amber "Version N was saved while you were
    editing. You'll choose what to keep when you save."
- **History.**
  - The 360 px column at ≥ 1280 opens with the `aria-pressed` History toggle. Below 1280 it is the History tab.
  - Rows show `vN`, the operation (Created, Edited, Added to, "Renamed from {old}", Deleted, Restored), +N −M in the
    UI-SPEC text colours, the author (a bot shown "for" its person) and the age.
  - Each row is a `button aria-pressed` with the full accessible name.
  - 30 rows per page, then "Show older versions". With only one version: "No earlier versions."
  - Selecting a row shows the diff bar ("Version N−1 → Version N" or "Empty → Version 1", with counts) and the diff.
    Close it with ✕ or Escape on desktop, or "All versions" on phones.
  - "Restore version N" asks for confirmation (focus on Cancel). The restore toast reads "Restored version N as
    version M".
- **Diff (`MemoryDiff`).**
  - It is read-only. Side by side or unified is chosen by measuring the host (a container query in JS).
  - Unchanged stretches collapse into "⦚ N unchanged lines".
  - Tints are `--success`/`--destructive` at 12/15% (words at 28/32%). Change bars are 3 px emerald and red, 600 in
    light and 400 in dark.
  - `+`/`−` markers sit in their own column, and deleted text in the unified view is struck through.
  - The region is named ("Changes from version a to version b"), with a visually hidden summary. The scroll area is
    focusable.
  - `highlights` draws amber "sensitive span" marks, for 07.2-13.
- **File actions.**
  - The column header has New file and New folder (writers of the open file's scope; they act on its folder).
  - The file header's "File actions" menu has Rename or move…, Delete… and Copy path.
  - Tree row ⋯ menus (writers):
    - File rows get the same items as the header menu.
    - Scope and folder rows get New file… and New folder….
    - On desktop the button shows on hover, on the selected row and while open. On phones it shows on the focused row
      at 44 px.
  - Shortcuts: F2, Delete and Shift+F10.
  - Dialogs:
    - Paths are validated live with `parseMemoryPath`, after blur or 400 ms, plus the scope's listing ("A file with
      this name already exists.").
    - Rename selects the stem, and the button reads Rename or Move depending on whether the folder changes.
    - A new folder creates `{folder}/INDEX.md`. A new file opens in Edit.
    - Delete opens the parent `INDEX.md` or `MEMORY.md` and focuses the parent row.
    - On `MEMORY.md`, Rename and Delete are `aria-disabled` and show the UI-SPEC tooltip.
- **Guard.** Every way out of a dirty Edit opens "Discard unsaved changes?" (focus on Keep editing): the tree, the
  breadcrumb, the tabs, Cancel and "Back to files". Browser Back and Forward are caught after the fact, and Keep
  editing returns to the draft, which survives in `useMemoryDraft`.
- **Live.** `memory.changed` on the user's stream invalidates the scope's tree, its open files and the file's history.
  The open file refreshes in place and announces "Updated to version N by {actor}" politely.
- **Read only.** People without write see the "Read only" badge and no Edit tab, create buttons or row menus. They
  keep History and Copy path.

## Broken-windows candidates (not written to WINDOWS.md, as instructed)

1. **No approver name in revisions.** `MemoryRevisionMeta` lacks the approver, so history shows "Approved proposal ·
   View proposal" instead of "Approved by {person}". It needs a contract field (07.2-13 or later).
2. **Team files are not live.** `memory.changed` goes only to the personal owner's stream (08), so two people editing
   a team file see each other's work only on save (conflict view) or on refetch. This is by design, but worth a
   unit-scoped event later.
3. **History pages on the client.** `GET /revisions` returns every revision; the UI shows 30 at a time.
4. **No undelete** (WINDOWS 138). Deleted files' history is unreachable from the UI.
5. **Trailing newline in diffs.** A file saved without a trailing newline shows an extra "−" empty line in diffs (a
   `diffLines` artifact). It is cosmetic.
6. **Larger editor chunk.** `@codemirror/lang-markdown` pulls in `lang-html`, `lang-css` and `lang-javascript` for
   embedded code. Reading is unaffected (lazy), but the editor chunk is larger than the core needs.
7. **"⌘S" vs "Ctrl+S"** is chosen from `navigator.platform` (deprecated, copy only).
8. **4 pre-existing biome warnings** in `apps/local-runtime`.
