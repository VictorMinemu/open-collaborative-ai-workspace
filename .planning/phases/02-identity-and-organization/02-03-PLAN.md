## Phase Goal

**As an** Organization Admin and every member of the workspace, **I want to** arrange the company into departments, teams and projects with the four PRD roles, have every route decided by one permission resolver, and manage my own password, sessions and profile, **so that** each person and agent can do exactly what their role, units and rules allow and every sensitive change is attributed and audited.

**This plan's slice (tracer for AUTH-06 issuance and AUTH-05 client identity):** a session knows which client created it, short-lived JWTs are issued and verifiable against the JWKS, audit rows inherit session and client automatically, and the contracts for every wave-3 API exist.

<objective>
Enable better-auth's `jwt` plugin with minimal claims and a public JWKS (research §Pattern 5, D-01), tag every session with its client kind and label at creation (§Pattern 6), split cookie authentication out of IdentityService (clientKind in AuthContext, deactivated members rejected), make `tenant(req)` carry session and client so audit rows inherit them, add the Redis revocation fan-out every later plan uses, and publish the wave-3 DTO contracts (units, memberships, rules, member detail, sessions, password reset, profile).

Purpose: wave 3 runs six plans in parallel; this plan gives them the token source (02-08 verifies, 02-11 signs device tokens), the session store and revocation seam (02-07 deactivation, 02-09 sessions/password), and frozen DTOs. It must not add `config.authz` declarations (02-02 introduces that typing in the same wave; 02-09 declares identity routes).
Output: jwt plugin + /api/auth/token + /api/auth/jwks, session client columns populated, authenticate.ts, client-kind.ts, session-store.ts, revocation API, contracts.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser cookie → GET /api/auth/token | A session cookie is exchanged for a bearer credential |
| public → GET /api/auth/jwks | Public keys are world-readable by design |
| request headers → session row | User agent and x-ocw-client are client-controlled strings |
| API instance ↔ Redis | Revocation fan-out between instances |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
