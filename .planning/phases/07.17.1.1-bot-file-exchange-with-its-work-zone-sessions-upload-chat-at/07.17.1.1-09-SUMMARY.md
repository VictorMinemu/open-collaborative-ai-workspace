## Decisions Made

See `key-decisions` in the frontmatter. The non-obvious one: the prefilled MB is clamped to the server's ceiling. Otherwise an organization on a server with `OCW_ATTACHMENT_MAX_BYTES` below 25 MiB would see every policy Save refused, because the default value is above the ceiling.

## Deviations from Plan

**1. [Rule 1 - Bug] Clamp the organization prefill to the server's ceiling**
- **Found during:** Task 1
- **Issue:** The API returns 25 MiB for an organization that never saved, but refuses any `botFileMaxBytes` above `OCW_ATTACHMENT_MAX_BYTES`. On a server with a lower ceiling, any Save of an unrelated field would get a 400.
- **Fix:** `toDraft` uses `min(stored, ceiling)` in whole MB. The effective limit stays the same, because the lower value wins at every call.
- **Files modified:** apps/web/components/settings/work-zone-policy-settings.tsx
- **Committed in:** 8d6acc9d

**2. [Layout] Limits grid has 2 columns in the sheet, not 4**
- **Found during:** Task 2
- **Issue:** The plan suggested `sm:grid-cols-2 lg:grid-cols-4`. The bot sheet is `sm:w-[36rem]` at every desktop width, so four columns would be about 125 px each and clip "Same as the organization (25 MB)".
- **Fix:** `grid-cols-1 sm:grid-cols-2`, which the plan allows ("two or four"). The existing assertion `md:grid-cols-3` in the profile test was updated to the new classes. This is the only existing test line that changed.
- **Committed in:** 80e76b21 / ee744636

**3. [Naming] Profile draft holds `fileMaxBytes` (bytes), not `fileMaxMb`**
- The profile's `ProfileDraft` is the PUT body by design (`= BotWorkZoneProfileInput`), so the value stays in bytes there, and the MB text is separate state. The behaviour matches the plan.

**4. [Older API] The bot field is disabled when the view has no `limits`**
- The plan asks that, without `limits`, the field renders with no hint and no line. It is also disabled, because an editable field whose value is never sent would mislead.

**Total deviations:** 1 auto-fixed bug plus 3 small implementation choices. **Impact:** no scope creep. Existing fields and saves behave as before.
