## Phase Goal

An agent consults or delegates to another agent through the platform, within a permission matrix of who may message
whom, with every hop visible in the thread, audited and bounded (ROADMAP Phase 07.7; A2A-01, A2A-02, A2A-03).

**This plan's slice (tracer, contract level):** one consult round-trips through the contracts: the tool request, the
origin-carrying delivery to the target, the reply event back to the asker, and the thread DTO that renders the hop. Then
the grain, the rule-tool refine, the 07.3 catalog entry and the turn additions.

## Planner decisions (P-01 … P-19)

- **P-01 Split.** 11 plans in 5 waves instead of the research's 5 in 4: the research's API core (decide, deliver,
  return, guard, sweeper, cancel: 12 files and every hard test) and its web plan were each beyond one executor's budget,
  and its split had no owner for the admin rules API before the last wave. ≤ 15 files per plan; no shared file in a wave.
- **P-02 Hardening fix assumed (orchestrator, 2026-10-08; supersedes D-05's placement in 07.5).** Before any 07.x phase
  executes, a standalone fix on `main` makes `/agent-channel/v1/messages` and `/cards` take the human from
  `agent_turns.user_id` through the post's `eventId` and re-check that human's `channel.read`, and makes a trigger
  mandatory (no `inReplyToMessageId` → 403 `no_trigger`). 07.7 never re-plans it. 07.7-06 extends its trigger rule so a
  consult hop's turn is a valid trigger (P-08). 07.7-01 Task 1 asserts the fix is present (execution stops at wave 1
  without it), and plans 04, 05 and 06 check it again before starting.
- **P-03 Org switch** ("Bots may consult each other", Settings › Bot policy, off by default, D-04) = exactly one
  organization-scope rule `{subjectKind: "everyone", permission: "agent.message", tool: null, effect: "allow"}`; off = no
  such row = closed. Written through 07.3's `insertRuleRow` / `deleteRuleRow` / `rulesChanged` (per-row audit).
- **P-04 Per-bot rules (admins only in v1, D-04).** Outbound mode `default` (no row) | `any` (`{agent A, allow, tool null}`)
  | `only` (`{agent A, allow, tool agent:<B>}` per B) | `none` (`{agent A, deny, tool null}`); "Never ask" list =
  `{agent A, deny, tool agent:<B>}`; inbound "Other bots can ask A" off = `{everyone, deny, tool agent:<A>}`. All
  organization scope, permission `agent.message`. Deny always wins, so `only` cannot narrow below the org switch: the UI
  disables it while the switch is on and every view shows a server-computed "Right now" summary. Seen with `rule.read`,
  edited with `rule.manage` (both admin-only). Team and unit bots only (personal bots are out of v1).
- **P-05 One canonical decision (D-02, D-04).** `perms.decide(tx, {kind:"agent", agentId: source, onBehalfOfUserId: H},
  "agent.message", {...agentResource(target, null), tool: agentMessageTool(target.id)}, {...agentResource(target, H), tool:
  agentMessageTool(target.id)})`. Agent pass: rules only (closed by default). Human pass: H's role grant, rules, and the
  `unit_agent` + personal-bot preconditions extended to `agent.message` (target visibility). 07.7-03 tests it, 07.7-04 uses
  it for both the offered targets and the request, 07.7-06 proves it at the route for a hidden unit persona.
- **P-06 07.3 module rows stay truthful.** Adding `agent.message` to the Bots catalog would turn every existing complete
  Bots-off set into "custom"; the 07.7-02 migration inserts the missing `agent.message` deny row next to each complete set.
- **P-07 Consult flow (D-01, D-04).** Asynchronous; same thread as the asking turn; channels (and their threads) only;
  the target must already be a member. The question is a message by the source agent, body `@<handle> <question>`,
  `clientMessageId` `consult:<idempotencyKey>`; the chain upsert, conditional budget, hop insert, target turn and
  `agent.mention.v1{origin}` happen inside that message transaction (delivered iff committed). Pre-post refusals → 409,
  nothing posted, audited `agent.consult.denied`. Agent-typed `@handles` stay inert.
- **P-08 Triggers (orchestrator, 2026-10-08).** A post is triggered when its `eventId` names a turn of the posting agent
  whose `answering_hop_id` or `returning_hop_id` is set and its `inReplyToMessageId` equals that turn's `message_id` (the
  question for the target, the answer or the question for the asker). Human = `agent_turns.user_id` (H), re-checked by the
  hardening path. Anything else keeps the hardening rule (403 `no_trigger`).
- **P-09 Turn done.** The bridge's `finally` calls `POST /turns/:eventId/done` (`replied` | `failed`). A turn that opened a
  pending `consult` hop never closes its own parent; the answer is `agent_turns.reply_message_id` (first message posted
  with that event). Idempotent: conditional `pending →` update.
- **P-10 Ledger.** A chain is created by the first consult of a root turn (`root_event_id` unique). Every hop counts
  against the budget (refused ones too). Deadline 5 min; opening a child bumps the parent to `≥ child deadline + 2 min`.
- **P-11 Taint (D-04).** The consult tool is side-effecting (gate refuses after taint); a tainted turn is never offered
  it; the asker's return turn starts with the target turn's taint (`agent_turns.tainted`, `turn.tainted`).
- **P-12 The root human pays (D-03, D-04, ADR-0019).** Every hop turn records `user_id = H` and decides tools agent ∩ H;
  each turn meters its own bot's `dailyLimit`; cell bots run on organization models; no `ai_usage_records` row.
- **P-13 07.5 approvals break the chain (D-04).** `approvalForCall` returns "no approval" for `ocw_consult_agent` whatever
  policy pattern matches; card-action turns (07.5 re-runs included) never carry chain context.
- **P-14 Stop.** The chain's human or a channel moderator (`message.delete_any`); immediate; chain and pending hops
  `cancelled`; late answers still post (visible) but deliver nothing. No in-flight model abort (the cell has none).
- **P-15 Automatic cancel is lazy (07.7-09):** at request, return and sweep time a chain whose thread root is deleted or
  whose human no longer reads the channel is cancelled `auto`.
- **P-16 ADR-0027** (D-04) is written in 07.7-02 so every executor reads the accepted design. The OpenClaw pins are locked
  by D-04: if the real cell refuses one of them, 07.7-07 stops and reports instead of dropping it.
- **P-17 UI contracts** live in 07.7-08 (settings) and 07.7-10 (thread) as "UI contract" sections in the 07.1-UI-SPEC
  style; the surfaces are small, so no separate UI-SPEC file. Axe through 07.1's `expectNoSeriousA11y`.
- **P-18 Rebase; locate by symbol.** 07.7 executes after 07.1–07.6 and the hardening fix are merged. Every line number in
  these plans is a planning-time hint (taken at `main` 4644fcd); executors locate code by symbol, route path, constant or
  test name, and keep sibling behaviour intact (07.3 module access, 07.5 approvals, 07.1 boards).
- **P-19 Executor rules (all 07.7 plans).** Never disturb the running demo: compose project `t3code-81d72154`, ports
  3000/4000, the `ocw` database, `~/.ocw*`, the `:local` images. Never read `.env` or `.env.demo`. Migrations run only
  through testcontainers and `scripts/e2e-isolated.sh` (one run at a time). No real model, provider or runtime call.
  CLAUDE.md asks for plan mode on permission, policy, audit, tenant-isolation and migration changes: write the intended
  diff as a short plan in the SUMMARY's working notes, then proceed (the owner delegated approval). Failing test first;
  `pnpm verify` green before every commit; Conventional Commits, small and atomic. A failing existing test is a defect to
  fix at its source, never a loosened assertion; a pin that encodes a deliberate catalog change (Task 2) is updated with a
  comment naming ADR-0027.
