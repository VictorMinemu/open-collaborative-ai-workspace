# Phase 07.6 Plan 01: Contracts Summary

One bounded Zod schema set for the whole phase: automations (schedule/webhook/mail triggers, stable-id targets,
runs, preview, digest, webhook endpoint and mailbox DTOs), watched records with `projectFields`, per-viewer Work Zone
session memory, the `agent.automation_run.v1` cell event with outside content in its own block, strict agent-side
propose and record-update bodies, platform card labels, four realtime types, the four D-07 grains and the two
built-in tool names, plus the Bots-off backfill the new module grains need.

## Intended design (P-19: grains, module catalog, migration)

- **Grains (appended, positions 73–76):** `automation.create` (surface `bots`; standard, developer, lead and admin
  roles), `automation.webhook` (surface `bots`; lead and admin roles; delegable, so an allow rule can grant it),
  `automation.manage` (surface `admin`; admin role; non-delegable by the existing admin-surface rule),
  `record.watch` (surface `chat`; every role). None in `AGENT_PERMISSIONS` (agents act only through the run-as
  human), none in `LEAD_PERMISSIONS` (no unit-lead grant).
- **Module catalog (P-05):** the Bots module's patterns gain `automation.create` and `automation.webhook`; no new
  module id. `automation.manage` (admin surface) and `record.watch` (chat surface) belong to no module.
- **Migration:** `20261030071644_bots_off_automation_backfill`, data-only, forward-only, idempotent: for every
  (organization, scope, subject) holding the complete 7-row Bots deny set (deny, no tool, no folder), add the two
  automation deny rows with the same scope and subject; partial (custom) sets untouched; nothing else written,
  changed or deleted; rollback statement in the file. Same pattern as 07.4-14's `20261014042429`.
- **No RLS, function, role, approval or audit change** in this plan.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Time zone validation accepts engine aliases, not only `Intl.supportedValuesOf`**
- **Found during:** Task 1
- **Issue:** the plan said "accept exactly the zones in `Intl.supportedValuesOf("timeZone")` plus `UTC`". Node 24 lists
  `Asia/Calcutta`, `Europe/Kiev`, `Asia/Saigon` but not `Asia/Kolkata`, `Europe/Kyiv`, `Asia/Ho_Chi_Minh`, which
  Firefox and Safari report from `resolvedOptions()`. The digest saves the browser's zone (P-14), so those people
  could never save a digest or schedule.
- **Fix:** `isKnownTimeZone` accepts a listed zone, `UTC`, or a zone the engine resolves into the listed set; `Mars/Olympus`,
  offsets and prompt text are still refused (tested).
- **Files:** `packages/contracts/src/automations.ts` · **Commit:** `2883be67`

**2. [Rule 2 - Missing critical] Bots-off backfill for the two new Bots module grains**
- **Found during:** Task 3 (`upgrade.int.test.ts` turned red)
- **Issue:** P-05 adds `automation.create` and `automation.webhook` to the Bots module, but an organization, unit or
  person that turned Bots off before 07.6 holds only the 7 earlier deny rows: the module reads `custom` and the two
  new grains are not denied (exactly WINDOWS #177 from 07.4). The plan assumed no catalog follow-up was needed.
- **Fix:** data-only migration `20261030071644_bots_off_automation_backfill` (07.4-14 pattern) and the upgrade test
  extended: `HEAD_ONLY` lists it, Bots reads `off` and denies both automation grains for org A's everyone and Max,
  rows 16 → 20, org B's custom set untouched, both backfills idempotent on a second run.
- **Files:** `packages/db/drizzle/20261030071644_bots_off_automation_backfill/*`, `apps/api/src/upgrade.int.test.ts`
- **Commit:** `ebc28565`

**3. [Rule 3 - Blocking] Existing exact assertions extended for the appended grains**
- `apps/api/src/modules/organization/permissions/resolve.test.ts`: the hand-written role matrix
  (`Record<OrgRole, Record<Permission, boolean>>`) needs the four grains or the API stops type-checking; added per D-07.
- `packages/contracts/src/permissions.test.ts`: count 73 → 77; 07.11's `slice(72)` → `slice(72, 73)`.
- `packages/contracts/src/module-access.test.ts`: the two exact Bots pattern lists gain the two grains (the plan said
  this file stays unchanged, but it asserts the exact pattern list); the 07.8 test was renamed "C-05 does not apply to
  07.8" because for 07.6 it does.
- No assertion was loosened; each now pins the new values.

**4. [Plan contradiction] `automation.manage` is non-delegable**
- The plan says none of the four grains is in the non-delegable list, but `NON_DELEGABLE_PERMISSIONS` is derived from the
  admin surface, which the plan assigns to `automation.manage`. Kept the stricter existing rule (no allow rule can confer
  "manage everyone's automations"); the test pins it. `automation.webhook` stays delegable as D-07 requires.
