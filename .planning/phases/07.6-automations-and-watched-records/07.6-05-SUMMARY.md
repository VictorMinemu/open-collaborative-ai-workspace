# Phase 07.6 Plan 05: The automation entity as a REST resource Summary

**Automations are a governed REST resource: created and run as their owner, scheduled with cron-parser in their own
IANA zone (DST pinned for Madrid and Sydney), targets decided for the creator and the bot together, managers who pause
and delete but never edit, resume or run as someone else, Run now enqueuing one ids-only `automation.fire` job in the
same transaction, and typed seams that plans 09, 10, 11, 12 and 21 fill without touching the module index.**

## Intended design (plan mode, P-19): access matrix and audit list

### Access matrix (every cell decided by the resolver; other organizations always 404 through RLS)

| Action | Owner (run-as) | `automation.manage` holder (not owner) | Other member |
|---|---|---|---|
| `GET /automations` (mine) | own rows | own rows | own rows |
| `GET /automations?scope=all` | needs `automation.manage` | everyone's, `runAs` on each row | 403 `not_allowed` |
| `POST /automations` | `automation.create` (403 `not_allowed`); webhook trigger also `automation.webhook` (403 `webhook_not_allowed`) | same, always run as themselves | same |
| `GET /automations/:id`, `GET …/runs` | yes | yes | 404 |
| `PATCH /automations/:id` | `automation.create`; not a digest | 403 `not_allowed` | 404 |
| `POST …/pause` | yes | yes (`pausedBy` = the manager) | 404 |
| `POST …/resume` | `automation.create` (resets the breaker) | 403 `not_allowed` | 404 |
| `POST …/run` | `automation.create`, status active (409 `automation_inactive`) | 403 `not_allowed` | 404 |
| `DELETE /automations/:id` | yes | yes | 404 |
| `GET /automations/options` | `canCreate`, `canWebhook`, caps, usable bots (personal bots of the caller + team bots with `bot.read`, never disabled) | | |
| `GET /automations/target-options?agentId=` | `automation.create` + the bot among the caller's usable bots (404 otherwise) | | |
| `POST /automations/schedule-preview` | `automation.create` | | |

`viewerCan`: owner `edit` (agent_turn, with `automation.create`), `run` (active, with `automation.create`), `pause`,
`delete`; manager `pause`, `delete`.

Target decision (create and every update; 09 repeats it at fire): bot live and not disabled (`agent_unavailable`),
creator holds `bot.read` on it (else `agent_unavailable`, internal `bot_not_readable`); personal bot → owner only and
`{kind:"dm"}` only (`personal_bot_target`); conversation: a non-archived channel the creator reads, then the bot is a
member (`agent_not_member`) and may post, the creator may post, and the bot acting for the creator may read
(`target_not_postable` otherwise); channel ⇒ text layout, board ⇒ board layout + a column of that board, thread ⇒ a
live top-level message of the conversation. Caps: `max_automations_per_user` (non-digest rows, counted under a
per-creator advisory lock, 409 `automation_cap`), `max_runs_per_day_cap` (400), `min_schedule_minutes` (400
`schedule_too_frequent` with `minMinutes`).

### Audit list (ids, kinds and codes only; never the name, instructions or a payload)

| Action | Actor | Metadata |
|---|---|---|
| `automation.created` | creator | automationId, agentId, actionKind, triggerKind, targetKind, conversationId |
| `automation.updated` | owner | automationId, agentId, triggerKind, targetKind, conversationId, changed (field names), version |
| `automation.paused` | owner or manager | automationId, runAsUserId, previousStatus |
| `automation.resumed` | owner | automationId, previousStatus |
| `automation.deleted` | owner or manager | automationId, runAsUserId, agentId, actionKind, triggerKind |
| `automation.run_started` | owner (Run now) | automationId, runId, trigger `manual` |
| `automation.run_skipped` | owner (Run now at the daily budget) | automationId, runId, trigger `manual`, reason `runs_per_day` |

Realtime: `automation.updated {automationId}` on `user:<runAs>` for every mutation; `automation_run.updated
{automationId, runId}` on `user:<runAs>` for Run now. No RLS, schema, function or grant change in this plan.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] 409 `board_column_has_automations` in the 07.1 column delete**
- **Found during:** Task 4 (board targets). 07.6-02 made the automation → board column FK NO ACTION, so deleting a
  targeted column would end in a 500 from the FK.
- **Fix:** `DELETE /boards/:conversationId/columns/:columnId` counts automations on the column first and answers 409
  `board_column_has_automations` (tested in automation.int.test.ts).
- **Files:** apps/api/src/modules/chat/board/columns.ts · **Commit:** 64f7972d

**2. [Rule 3 - Blocking] Strict authz needs a resolver decision on every 2xx**
- The owner's own reads, runs list and delete would answer without a decision (ownership is a data fact), which the
  strict test guard turns into 500. `visible()` always decides `automation.manage` for the actor and every service
  check runs through `perms.can(req, …)` when a request is present (`AutomationActor.req`).

**3. [Interface] Trigger adapters receive their deps and expose a `view`**
- The plan's `TriggerAdapter` had no way for 10/11 to reach `core` (secrets, egress) from a module-level const. Each
  method now takes a trailing `deps: TriggerDeps` (`{ core, perms }`), and `view(tx, a, deps)` gives the DTO's
  `trigger.webhook` / `trigger.mailbox` (null until 10/11). The seam register functions take
  `AutomationSeamDeps = { perms, approvals, modelGateway, service }`.

**4. [Contracts] `RunAutomationResponse` (`{ runId }`)** added to `packages/contracts/src/automations.ts` for `POST
/automations/:id/run` (202), so 15's web client derives it instead of duplicating a DTO.

**5. [Export] `channelFacts`** added to the chat module's public index (the target decision needs the channel facts of
the creator and the bot; no duplicate of chat's membership/unit-path logic).

**6. Minimum-interval window 10 instead of 5** and **Run-now budget as a skipped run** (see key decisions).

## Notes for later waves

- **09 (runner):** `registerRunner(core, seams)` is called once inside `register()` (before `jobs.start`). Reuse
  `decideTarget(tx, perms, { agentId, userId: runAsUserId, target: targetOf(row) })` at fire (its codes map to run
  reasons; `bot_not_readable` exists in both), `missedPolicy`, and compute `next_run_at` with
  `nextRunAfter(schedule, scheduledFor)` (never from now). Run now's runs are `trigger = 'manual'`, `scheduled_for`
  null, already counted against `max_runs_per_day` (non-skipped runs since UTC midnight); its job data is exactly
  `{ organizationId, runId }`. Use `service.announce(tx, row)` and emit `automation_run.updated` like `runNow`.
- **10 (webhooks):** fill `webhookTrigger` (`onCreate` returns `{ webhookSecret }`, which `create`/`update` pass back
  once) and `view` (`{ publicId, url }` for the DTO). Kind changes call `onDelete` (old) then `onCreate` (new);
  same-kind saves with a `trigger` body call `onUpdate`. `automation.webhook` is checked by the service on create and
  on a switch to webhook.
- **11 (mailboxes):** same contract for `mailTrigger` (`view` returns the `Mailbox` DTO).
- **12 (approval kind):** replace the `fromApprovalId` refusal at the top of `service.create` (400
  `approval_not_found`); `registerAutomationApprovalKind(approvals, service)` is already called by `index.ts`.
- **13 (digest):** `service.create(tx, actor, input, { actionKind: "digest", config })` stores empty instructions and
  skips the per-user cap; digests are listed (with `actionKind`) but `PATCH` refuses them (400) and the owner's
  `viewerCan` has no `edit` for them.
- **15 (web):** errors carry `details`: `schedule_too_frequent` → `{ minMinutes }`, `automation_cap` → `{ max }`,
  runs/day → `{ max }`. Target labels are server-composed (`#sales`, `Thread in #sales`, `Your DM with Scout`,
  `{person}'s DM with {bot}` for managers, `orders board · {column}`, `private channel` for a manager who cannot read
  it). `DELETE` answers 204; Run now 202 `{ runId }`.
- **19 / ADR-0028:** record the DST semantics above and the board column 409.
