## Phase Goal

**As an** Organization Admin and every member of the workspace, **I want to** arrange the company into departments, teams and projects with the four PRD roles, have every route decided by one permission resolver, and manage my own password, sessions and profile, **so that** each person and agent can do exactly what their role, units and rules allow and every sensitive change is attributed and audited.

**This plan's slice (tracer for ORG-03):** one real route — channel archive — is decided end to end by the single resolver, with the denial audited; then every layer of the intersection is proven, and the rails that force every other route onto the resolver are installed.

<objective>
Build the one authority for authorization (research §Pattern 1, §Pattern 4): a pure `resolveEffectivePermissions` over loaded facts, a permission service that maps decisions to HTTP (404 hidden / 403 with details) and audits denied mutations in their own transaction, the route-coverage registry (warn mode), the static legacy-check guard, `GET /api/v1/me/permissions`, and web gating through `useCan`. Migrate the channel-archive route as the tracer.

Purpose: wave 3 plans (02-04 … 02-09) migrate their modules against this service in parallel; its interface below is the contract they code against. Deny/allow rules come from `app.permission_rules` (D-02); hierarchy facts from `org_units`/`unit_memberships` (D-07).
Output: organization/permissions/** (resolver, policy, facts, service, errors + tests + guard), authz.ts (+ test), organization/members.ts, /me/permissions, web lib/permissions.ts and gated nav.
</objective>

Algorithm for this task: (1) principal gate: a deactivated principal gets an empty set and `principalDenied` with layer user (users, reason "deactivated"), agent (agents, reason "agent_disabled") or device (devices, reason "device_revoked"); (2) grants = ROLE_PERMISSIONS[orgRole] for users, AGENT_PERMISSIONS / CELL_PERMISSIONS / DEVICE_PERMISSIONS for the other kinds, plus relation grants from policy.ts RELATION_PERMISSIONS[resource.type][relation] kept only when PERMISSION_SURFACE[p] is in ROLE_SURFACES[orgRole] (non-user principals take relation grants inside their own permission set only); (3) for each granted permission evaluate, in this order, the first denial: precondition (policy.ts PRECONDITIONS, layer "resource"), then deny rules whose subject matches and whose permission pattern matches (organization scope only in this task: scopeUnitId null; layer "org", or "user"/"agent" when the rule subject is a user/agent; reason "denied_by_rule", ruleId set); (4) permissions = grants minus denied. `decide()` returns { allowed } or the denial; a permission never granted yields { layer: "role", reason: MISSING_REASON[permission] ??
