## Phase Goal

**As a** controller of a Work Zone session, **I want to** use a real Full access mode where the device owner allows it, **so that** long tasks run without prompts while my organization stays in control (ROADMAP Phase 03.2 goal, ADR-0012; full user story in 03.2-01-PLAN.md).

**This plan's slice:** the device side of ADR-0012 — local opt-in, daemon refusal, the real bypass modes in both adapters through the authorized path only, and the device-local controls to switch it.

<objective>
Implement Full access on the device exactly along ADR-0012's path: opt-in lives on the device, the daemon re-checks it on every start, change and turn, the adapters enter the runtime's bypass mode only for authorized fullAccess and keep failing closed for anything else.

Purpose: D-01, D-02, D-03, D-04, P-11, P-12; WZC-04 (device side).
Output: daemon config/CLI/control-socket opt-in, daemon refusals, fake runtime fullAccess, Claude relaunch with bypass, Codex never + dangerFullAccess per turn, desktop Runtime menu toggle, full-access e2e.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → daemon (start/configure/prompt with fullAccess) | A buggy or compromised server could ask for bypass |
| daemon → runtime CLI (bypass options) | The most privileged runtime configuration |
| web origin (desktop main window) → desktop main process | Remote content with a narrow preload API |
| local user → desktop menu / CLI | The only legitimate place to enable the opt-in |
