# Debug report: 03.1 call-time tool gate bypassed in real cells

## Symptoms

expected: every tool call in a real cell goes through the OCW gate (authorize before the call, report the outcome after, fail closed).
actual: web_search ran and SearXNG results reached the model, but the fake Agent Channel API recorded `tool calls : []`, `outcomes : []` (CI job 111608839253).
reproduction: CI `cell-smoke`, `infra/openclaw/test/run-container-smoke.sh`, scenario `capabilities`.
started: first real-cell run of the 03.1 gate. Unit and contract tests passed because they called `registerFull` directly against a fake runtime.

## Root cause

The gate was registered from `defineChannelPluginEntry({ registerFull })`. OpenClaw 2026.9.7 runs each agent turn
inside a prepared plugin generation, and during the turn the global hook runner reads only that generation's
registry. The boot registry (`full` mode) is reused only while the activation fingerprint (a hash of every
top-level config key) is unchanged. The OCW plugin writes the cell's bots, providers and bindings right after
boot, so every turn's registry is a fresh `loadPluginRegistryHandle({ activate: false })`. In that load plugins
register in `discovery` mode, where `defineChannelPluginEntry` calls `registerCapabilities` but skips
`registerFull`. As a result no ocw `before_tool_call` existed where tools run, `hasHooks("before_tool_call")` was
false, and calls ran with no gate and no audit. Two conditions had to hold together (AND-gate): the hook lived
in a callback that is skipped by mode, and the turn ran in a non-activated registry.

Evidence (shipped dist, extracted with `docker create` + `docker cp`; no cell was started):
- `hook-runner-global-*.mjs` `resolveHookRegistry`: when a generation registry exists it is returned exclusively.
- `get-reply-*.mjs` `runPreparedReply`: every reply runs in `withPluginRuntimeGenerationScope(lease.snapshot)`.
- `prepared-model-runtime.facts-*.mjs`, `load-context-*.mjs`: the active registry is reused only when the config fingerprint matches; otherwise `loadAgentRuntimePluginRegistryHandle`, which uses `activate: false`.
- `loader-runtime-load-*.mjs` `resolvePluginRegistrationPlan`: no runtime side effects → `discovery`, where `api.on` is still available.
- `core-*.mjs` `defineChannelPluginEntry`: `registerFull` runs only in `full` and `tool-discovery`; `registerCapabilities` runs in `full`, `discovery` and `tool-discovery`.
- The bundled `onepassword` plugin registers `api.on("before_tool_call")` unconditionally in `register()`.
- Our built entry loaded with OpenClaw's real `plugin-sdk/channel-core` on the host: before the fix, `discovery` had no hooks; after the fix it has `before_tool_call@10000` and `after_tool_call`.
- Plugin tools resolve from the active registry (`openclaw-tools-*.mjs`), which is why `ocw_memory_save` can be offered while the hooks registered next to it were missing.

Eliminated: (a) the fake API filters records, because it stores the body verbatim and the tool did run; (b) a tool path that skips the hook, because every wrapper calls `runBeforeToolCallHook`; (c) a manifest or config opt-in for `before_tool_call`, because only conversation hooks need `allowConversationAccess`.

## Fix

- `apps/openclaw-channel/src/register-capabilities.ts` (new): registers the gate from `registerCapabilities`, so it exists in every registry that can run a tool, and logs `[ocw] tool gate registered (<mode> registry)` once per mode.
- `register-full.ts` now registers only the memory tool. `index.ts` wires `registerCapabilities`. `openclaw-sdk.d.ts` adds `registrationMode`, `logger` and `registerCapabilities`.
- Gate semantics are unchanged: unscoped, priority 10 000, fail-closed, process-wide state shared across registries.
- Regression test `src/openclaw-registration.test.ts` loads the real entry through `src/testing/openclaw-host.ts`, which models OpenClaw's mode gating, per-mode API, typed-hook registration and turn hook runner, taken from the dist. It covers every registration mode, a turn in the non-activated registry, denial and the 15 s fail-closed budget. Before the fix it had 6 failures, all in `discovery`. Mutation check: unwiring `registerCapabilities` gives 8 failures.
- The smoke prints the gate wiring. Fake-model debug logging is now off by default (`FAKE_MODEL_DEBUG` is passed through from the caller).

## Side finding: DuckDuckGo not loaded at boot (expected)

Both search plugins declare `activation.onStartup: false`. Gateway startup only boot-loads the owner of
`tools.web.search.provider`. The smoke sets `OCW_SEARXNG_URL`, so `render-config` pins `searxng`. DuckDuckGo loads
at boot only in cells without SearXNG, and the smoke already accepts either set. This is not a bug.

## Prevention

- Why it was not caught: contract tests called `registerFull` directly and never modelled registration modes or the per-turn registry. Only the real-cell smoke exercises that path, and it had never run green.
- Recurrence guard: `apps/openclaw-channel/src/openclaw-registration.test.ts` ("a discovery registry carries the gate exactly once…", "has the gate at all…") and the `capabilities` cell-smoke scenario. Re-check `testing/openclaw-host.ts` against the dist on every OpenClaw bump.
