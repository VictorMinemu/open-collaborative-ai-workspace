## Phase Goal

Each member connects their own MCP account once and sessions refresh themselves (plan map and executor rules:
07.4-01-PLAN.md).

**This plan's slice (tracer, protocol level):** a client that does discovery → authorize with PKCE and `resource` →
token → MCP `whoami` with the bearer gets a per-grant subject from the fake; then refresh, revoke, registration,
CIMD, scenarios and the keychain endpoints. This is the Wave 0 test double every connector test uses.

    // fake-mcp-oauth.mjs — base = the request's own origin (Host header), so it works as http://127.0.0.1:<port>
    // in int tests and http://fake-mcp:4291 in e2e
    GET  /.well-known/oauth-protected-resource/mcp-oauth/mcp → { resource: <base>/mcp-oauth/mcp,
           authorization_servers: [<base>/mcp-oauth], scopes_supported: ["records:read","records:write"],
           bearer_methods_supported: ["header"] }
    GET  /.well-known/oauth-authorization-server/mcp-oauth → { issuer: <base>/mcp-oauth, authorization_endpoint,
           token_endpoint, revocation_endpoint, registration_endpoint, code_challenge_methods_supported: ["S256"],
           client_id_metadata_document_supported: true, authorization_response_iss_parameter_supported: true,
           scopes_supported: ["records:read","records:write","offline_access"], response_types_supported: ["code"],
           grant_types_supported: ["authorization_code","refresh_token"],
           token_endpoint_auth_methods_supported: ["none","client_secret_basic","client_secret_post"] }
    GET  /mcp-oauth/authorize   validates client, exact redirect_uri, response_type=code, code_challenge + S256,
                                resource == PRM resource, state; auto-approves; 302 redirect_uri?code&state&iss
    POST /mcp-oauth/token       authorization_code (PKCE verify, resource match, client auth, single-use 5-min code),
                                refresh_token (resource required, rotation; reuse → invalid_grant + family revoked);
                                the response carries an `id_token` (unsigned JWT, alg none) with `email` =
                                `<subject>@fake-mcp.test` unless the scenario says no_id_token (UI-SPEC R1 label)
    POST /mcp-oauth/revoke      RFC 7009 (200 always; revokes access or refresh token and its family)
    POST /mcp-oauth/register    RFC 7591 DCR → { client_id, client_secret?, redirect_uris, … }
    POST /mcp-oauth/mcp         streamable HTTP MCP; no/invalid bearer → 401 + WWW-Authenticate: Bearer
                                resource_metadata="<PRM url>", scope="records:read"; tools:
                                whoami (read-only → { subject, scopes }), create_record (destructive, { title } → { id }),
                                echo_auth (read-only → the Authorization header it received)
    POST /mcp-oauth/__scenario  { deny?, no_pkce_meta?, no_iss?, wrong_iss?, insufficient_scope?, expires_in?,
                                  revoke_all?, slow_mcp_ms?, different_issuer?, fail_token_5xx?, no_id_token? }
                                  (replaces previous)
    GET  /mcp-oauth/__stats     { tokenRequests: { authorization_code, refresh_token }, refreshReuse, revocations,
                                  registrations, lastResource: { authorize, token, refresh }, mcpCalls,
                                  accessTokenHashes: string[] }   // sha256 hex only
    GET|HEAD|POST /kc/whoami    200 { authorized: true, method } when Authorization is "Bearer <kcToken>" or
                                Basic kcuser:kcpass or a client-credentials token; else 401
    ANY  /kc/echo               200 with the received request headers as JSON (redaction tests)
    GET  /kc/redirect           302 Location: http://169.254.169.254/latest/meta-data/
    GET  /kc/big                200, 512 KB text body
    POST /kc/token              client_credentials (client kc-client / kc-secret) → { access_token, expires_in: 60 }

    export function createFakeMcpOAuth(opts?: {

      kcToken?: string;
    }): { handle(req, res, url): boolean; issuedTokens(): { access: string[]; refresh: string[]; codes: string[] };
          setScenario(s): void; reset(): void }          // issuedTokens is in-process only (leak sweeps), never HTTP
