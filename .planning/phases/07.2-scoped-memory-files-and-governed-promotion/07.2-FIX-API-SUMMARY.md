# Phase 07.2 FIX-API: API ledger fixes before the gate Summary

**Nine API-side ledger items fixed in the `wt/07.2-fixapi` worktree, each with a test that failed before its fix,
on a real ephemeral PostgreSQL. Approvals whose action vanished now close as failed. The server never writes for a
deleted or turned-off bot. Presidio runs outside the proposal transaction. Memory search only reads. The read routes
count against the turn cap. Team files update live. The database refuses a file scope change.**

## Broken-windows candidates (not written to WINDOWS.md, as instructed)

1. **#139 remainder.** `GET /memory/scopes` and the agent's scope list still create missing org and unit scopes.
   Removing this needs eager scope creation on unit and org creation plus a backfill.
2. **Already-stranded requests.** Proposals that cascaded before this fix stay `pending` until they expire. No sweep
   closes them.
3. **Member removal.** If removing or deleting a member ever cascades their personal scopes, that path does not call
   `closeGone`. Only unit deletion, bot deletion and forget do.
4. **Rename and live updates.** A rename notifies the readers of the new path. Readers who could see only the old path
   get no event.
5. **Fan-out cost.** A unit-scope write appends one event per reader. This is the unit-persona pattern; a `unit:` topic
   would be the next step at scale.
6. **Snippets past the window.** A file whose only match lies past 16 KiB shows its opening words, unmarked.
7. **No e2e for team live updates.** The proposal-view "Closed without a decision" footer also has no render test.
8. **Lint warnings.** The 4 pre-existing biome warnings in `apps/local-runtime` remain.
