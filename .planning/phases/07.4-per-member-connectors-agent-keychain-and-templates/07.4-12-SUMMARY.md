# Phase 07.4 Plan 12: Connector proxy, connect card and leak sweep Summary

**A shared bot now calls a per-member connector with the account of the person who asked, never anyone else's.
`POST /agent-channel/v1/connectors/call` claims the call against the turn, opens that member's token and calls their
MCP server through the egress guard. A 401 gets exactly one forced refresh and one retry. A member who has not
connected (or must reconnect) gets a platform-owned "Connect your Acme CRM account" card in the same chat, with a way
back. `/connectors/list` shows the turn's connectors and keys. Unit keys now follow the audience rule, DMs get a name
in shares, and a phase-wide sweep proves no secret of 07.4 leaks anywhere.**

## Accomplishments

- **Connector proxy (`connectors.ts`).** It has the same shape as `/http-requests`:
  1. tx0, with no user, reads the turn's human from the ledger;
  2. tx1 runs as that human and checks, in order:
     - the live turn;
     - connector and logical tool;
     - the tool on the turn (`member_account` if the audience rule withholds it now, else `not_in_turn`);
     - the re-decision (`policy_changed`);
     - the connection (`not_connected` / `needs_reconnect`);
     - `claimToolCall` with the logical tool's flags;
  3. outside any transaction: `accessTokenFor`, then `callTool` (30 s, `egress.bound` inside, credential redacted);
  4. tx2: `finishToolCall` and `touchConnection`.

  Audits carry ids, connector and `credential: "member"`, never arguments or results.
- **401 handling.** One `forceRefresh` and one retry. If the refresh is refused, or the retry also gets a 401, the
  connection is marked `needs_reconnect` (code `upstream_unauthorized`) and the reconnect card is posted.
  `insufficient_scope` is an error result naming the scopes the server asked for, with the reason in the audit.
- **Connect card (`connect-card.ts`).** It follows UI-SPEC § 5 and R8: `generic`, `info`, one field (`How it works` /
  `What happened`), and Open → `/settings/connections?connector=<id>&return=<encoded permalink>`.
  - The return route is the DM, AI chat or channel thread permalink; it is dropped if the whole target would not pass
    `AgentCardRoute`.
  - Idempotency key `connect:<eventId>:<serverId>`, `cardPlatformOwned: true`.
  - Posted as the bot through chat's agent path. A card that fails to post never changes the 409.
- **List (`/connectors/list`).** It returns:
  - the per-member connectors whose logical tools are on the turn now, with the asker's status and the tools' names,
    descriptions and input schemas;
  - the turn's usable keys.

  It is claimed with the stricter of the delivered and re-decided `ocw_connector_list` flags, so listing per-member
  connectors taints the turn.
- **Unit keys (#191).** A unit key is usable only when every reader of the judged conversation is in that unit's
  audience:
  - readers are DM, group DM or private-channel members, or an AI chat's audience;
  - a public channel or an unbounded AI chat never qualifies;
  - organization keys serve everyone.

  `keys.unitAudience` is re-decided on every delivery and call, and the keychain proxy refuses a withheld key with
  `unit_audience`.
- **Shares naming (#194).** DMs and group DMs are named for the viewer: "your private chat with Alex Kim", "your group
  chat with Alex Kim and Víctor Ruiz". `null` is left only for conversations the viewer can no longer read.
- **Leak sweep.** One scenario covers every credential path of the phase, using canaries and real fake-provider
  tokens. Every surface is covered and shown to bite by a mutation. No leak was found, so nothing had to be fixed at a
  source.

## Deviations from Plan

### Auto-fixed / added (Rules 1-3)

1. **[Rule 2 - Security] The connect card is platform-owned.** The plan said "when 07.2's marker exists". It does, so
   `cardPlatformOwned: true`, and the bot's PATCH gets 403 `card_platform_owned` (tested).
2. **[Rule 2] Not-connected refusals happen before the claim.** A member who never connected neither spends the turn's
   tool budget nor taints it. The plan's "audit `bot.tool_call.completed` blocked `not_connected`" now applies only to
   the post-claim case (a refresh refused mid-call). The pre-claim case is audited as `bot.tool_call` denied with that
   reason.
3. **[Rule 3] The fake revokes a whole grant for any token.** "Revoke the access token only" cannot happen with it. The
   401-on-a-valid-looking-token case replaces the sealed access token with one the provider never issued (expiry
   unchanged), which is the same upstream 401. The dead-grant case uses `revoke_all`.
4. **[Rule 3] The fake's `/kc` Basic pair and client-credentials client are configurable** (`kcBasic`, `kcClient`,
   with a node test), so the sweep's vault values are canaries. `startConnectorsStack` takes `env`, `logLevel` and
   `fake` options.
5. **[Rule 2] Plugin half of #192.** The list tool and the local gate follow the turn's `ocw_connector_list`
   untrusted flag, so a local write after a list is blocked as read-only instead of being refused by the API.
6. **Brief items outside the plan's file list:**
   - unit-key audience (#191): `keychain/service.ts`, `turn-policy.ts`, `http-requests.ts`, contracts, plugin mirror;
   - DM naming (#194): `shares.ts`, contract comment;
   - e2e spec and screenshots for the card (C-03).

### Plan text vs. what was built

- **403 `no_trigger` instead of 404 `unknown_turn`**, for unknown, foreign and org-B turns, as in 07.4-11.
- **`insufficient_scope` answers 200 with `isError: true`** instead of 502. Only the content reaches the model, and it
  names the scopes. The audit records `status: error, reason: insufficient_scope`.
- **The retry after a forced refresh** uses the 07.4-10 refresh window. A second 401 within 30 s of a forced refresh
  reuses that token and ends in `upstream_unauthorized`, by design against refresh storms.
- **The tool recorded in `agent_tool_calls`** is the logical name `<safe>__<tool>`, so per-tool history stays
  readable.
