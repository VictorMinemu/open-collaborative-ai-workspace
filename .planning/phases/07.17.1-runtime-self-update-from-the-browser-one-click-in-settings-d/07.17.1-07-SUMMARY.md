# Phase 07.17.1 Plan 07: Supervision, boot reconcile and doctor Summary

**A daemon that a self-update restarted now reports that run's real outcome from the marker (succeeded, or failed
"the runtime came back on the previous version"), repairs a stale `install.json` and can prune old versions; only a
bundle installed under `versions/<12 hex>/` and started by systemd or launchd counts as supervised; and the doctor
names an update that left the server down, with the way back. Nothing calls the two new modules yet (08 and 10 do).**

## Performance

- **Duration:** ~12 min
- **Completed:** 2026-11-11
- **Tasks:** 3 (T1 tracer)
- **Files:** 4 created, 2 modified

## Accomplishments

- `reconcileSelfUpdate`: reads the marker, compares the running sha256 with `marker.to.sha256` and builds two
  `runtime.update.run` frames (`started`, `finished`) with the marker's `runId`, `commandId` (omitted when null),
  `trigger`, versions, 12-hex builds and `method: "ocw_bundle"`, plus the `lastRun` for `RuntimeSelfStatus`. It leaves
  the marker for the caller to remove after sending.
- `pruneRuntimeVersions` and `clearStaging` keep `versions/` small without ever touching the running or current
  directory or a non-build name.
- `isSupervised` / `runningBuild` implement PD-11 and PD-05 with explicit inputs; only the answer leaves the device.
- Doctor: `DoctorDeps.selfUpdateMarker`; `daemon` and `service` fail with "The runtime did not come back after
  updating to 0.3.2 (abcdef012345)" and the fix "Re-run the install command from Settings › Devices, or point
  ~/.ocw/runtime/current back to versions/<previous12> and run `ocw-runtime service restart`"; the `runtime` hint on a
  service host is "Update it from Settings › Devices (Runtime › Update), or re-run the install command".
