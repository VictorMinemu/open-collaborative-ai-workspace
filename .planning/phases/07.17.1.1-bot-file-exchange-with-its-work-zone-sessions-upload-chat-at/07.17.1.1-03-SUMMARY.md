# Phase 07.17.1.1 Plan 03: Bot file limits, transfer ledger and hourly load Summary

**One additive migration (`20261111225544_bot_work_session_files`) adds the organization's 25 MiB and the bot's nullable file limit (1 MiB … 1 GiB checks) and the tenant-isolated, path-free transfer ledger `app.bot_work_session_files`. `app.bot_work_session_load` now counts each move as one unit of the bot's hourly prompt budget, whatever its outcome.**

- `workZonePolicies.botFileMaxBytes` (NOT NULL DEFAULT 26214400) and `botWorkZoneProfiles.fileMaxBytes` (null = the organization's), each with its named range check.

## Decisions Made
- `HEAD_ONLY` changes in the Task 1 commit, with the migration. The upgrade test's "behind by exactly HEAD_ONLY" case would fail on any commit that has the migration but not the entry (07.17.1 did the same).
- `failure` is unconstrained text, as the plan says. Its doc limits it to a `SessionFileFailure` code (or `timeout`), and 07 / 11 write it.
- No explicit `REVOKE TRUNCATE` for the ledger. The generic grant never includes TRUNCATE, and the plan did not ask for one.
