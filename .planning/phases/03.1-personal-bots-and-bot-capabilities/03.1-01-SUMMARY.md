# Phase 3.1 Plan 01: Personal bot → private DM → reply without mention (tracer) Summary

A Developer creates a personal bot in one click; a private chat with it appears under **Bots** in the chat sidebar, the bot answers a plain message (no @mention) as one flat reply, and nobody else (admins included) can read the chat or reach the bot. The whole phase's schema and the six new permissions are in place.

## What was built

- **Migration** `packages/db/drizzle/20261005005954_personal_bots_capabilities/` (the only one for Phase 3.1, D-05). SQL highlights:
  - `agents.scope` (default `team`, check `team|personal`), `agents.owner_user_id`, check `agents_owner_scope_check ((scope = 'personal') = (owner_user_id is not null))`, `agents.capabilities jsonb`, partial index `agents_owner_idx … where scope = 'personal' and deleted_at is null`.
  - `conversations.dm_key` + unique partial index `conversations_org_dm_key_uq (organization_id, dm_key) where kind = 'dm'`.
  - New tables, all with `organization_id` (post-migrate applies ENABLE + FORCE RLS + `tenant_isolation`): `bot_policies`, `agent_turns`, `agent_tool_calls`, `agent_usage_daily`, `agent_limit_notices`, `agent_memories` (check `char_length(text) <= 500`), `mcp_servers` (unique `(organization_id, safe_name)`), `mcp_server_tools`, `cell_plugins` (unique `(organization_id, package_name) where status <> 'uninstalled'`), `cell_plugin_tools`, `bot_tool_grants`; FKs with `on delete cascade` to agents / mcp_servers / cell_plugins; `secrets.kind` adds `mcp_credential`.
- **Permissions (D-02)**: the six values with surfaces, role grants, `AGENT_PERMISSIONS` (+ `bot.internet`, `bot.tool.use`), descriptions; `plugin.manage` / `mcp.manage` non-delegable.
- **Resolver**: `agent` resource (`owner` → `bot.read`, `bot.configure`), states `personal`, `disabled`, `dm`; preconditions `personal_bot` (user principals, non-owners, on `bot.read|configure|internet|tool.use`) and `direct_conversation` (`channel.members.add|remove`, `channel.archive` on a DM). A bot acting for its owner keeps `bot.internet`; for anyone else it loses it with `personal_bot`.
- **API**: `POST /api/v1/agents/personal` (resolver-decided, advisory-locked cap `max_personal_bots_per_user` default 3 → 409 `personal_bot_limit`, default model, audit `agent.created {scope, ownerUserId, model}`, `agent.created` on `user:<owner>` only, `cell.config.changed`); `GET /api/v1/dms`; `POST /api/v1/conversations/:id/read`; message routes, `conv:` authorizer and the bot reply path accept `channel|dm`; DM dispatch: one `agent.mention.v1` per human DM message (bot live and `bot.read` for the author), `conversation.kind = 'dm'`, history = earlier DM messages; DM thread replies → 400 `dm_is_flat`; bot replies in DMs are always top-level.
- **Privacy (Task 2)**: personal bots never resolve as text @mentions, are skipped by channel mention dispatch, and `POST /channels/:id/members` refuses them with 409 `personal_bot_dm_only` (owner included).
- **Plugin**: flat DM replies (`threadRootMessageId: null` on reply and typing), `sessionKeyFor` (one OpenClaw session per DM conversation, per thread in channels), DM persona line and "Conversation history" label; no thread fields in the DM context.
- **Container smoke**: `SMOKE_ONLY=<mention,signin,dm>`, scenario `dm` with `mention-dm.json`, per-conversation reply matching, smoke containers as first OOM victims.
- **Web**: Bots group under Channels (bot avatar, unread dot, "+" and the "Create your personal bot" row while the caller has no personal bot), `DmView` (header "Personal bot · only you can see this chat", privacy intro, flat list, no @ button, agent typing, optimistic send/retry, read marker), page `/chat/dm/[conversationId]`.

- Screenshot review showed an `@` button in the DM composer (nobody can be mentioned in a DM) and the "Bots" heading 2 px off the "Channels" heading. Added an optional `mentions` prop to the shared `Composer` (default true, unchanged elsewhere) and aligned the heading padding.
- **Files:** `apps/web/components/chat/composer.tsx`, `chat-sidebar.tsx`. **Commit:** b74ac8a

**4. [Plan wording] `bot.configure` denial reason for a non-owner developer**
- The plan's behavior lists `personal_bot` for Alex on `bot.configure`. The resolver only runs preconditions on granted permissions, and a developer is never granted `bot.configure`, so the denial is `role/missing_permission` (still denied). `personal_bot` is asserted for the admin (role-granted) and for Alex with an explicit `bot.*` allow rule. Resolver semantics unchanged.

**5. [Plan wording] Explicit disallowed model → 400 instead of silent default**
- `createPersonalBot` refuses an explicitly requested model the org does not allow (`model_not_allowed`), consistent with `POST /agents`; an omitted model uses the default allowed model.

**6. [Plan wording] `bridge.ts` unchanged**
- It already posts reply and typing with `threadRootMessageId: mention.threadRootId`; making `threadRootId` nullable in the mapper was enough (covered by the new plugin contract test).

**7. [Rule 2 - Safety] Smoke containers get `--oom-score-adj 1000`**
- See Issues below. Added to `run-container-smoke.sh` so the kernel kills the smoke first on a memory-tight VM.
