# Phase 07.8 Plan 09: sandbox files, the soft quota, idle stop and events in sandboxd Summary

**sandboxd now serves a bot's workspace files to people and bots as uid 10001 through `ocw-files`. Every path is
confined by `realpath`, and symlinks out of `/workspace` are refused. Files of a stopped or killed sandbox come from a
network-none helper container. A soft quota refuses writes that do not fit and stops a full sandbox with `disk_full`.
Idle sandboxes stop and keep their volume. CPU and disk are reported, and the API can long-poll every state and usage
change by a boot-scoped cursor. A 73-check smoke proves all of this on real Docker.**

## What was built

- **`ocw-files`** (POSIX sh, coreutils/findutils, root-owned 0755 next to `ocw-run`). Subcommands: `realpath`,
  `list`, `stat`, `read`, `cat`, `write`, `rm` and `du`.
  - Each path is resolved with `realpath -m` under `/workspace`; a path outside it exits 3 (`invalid_path`).
  - `read` and `cat` accept regular files only, so a FIFO cannot block them.
  - Writes go to an O_EXCL temporary file and are then renamed (`mv -T`), or linked with `ln -T` in `create` mode, so
    a failed write never leaves a partial file.
  - `rm` resolves the parent only, so it removes a symlink itself and never the target.
  - Exit codes map to `invalid_path` 422, `not_found` 404, `exists` 409 and `busy` 409 (folder not empty).
- **`files.ts`**: each op is one helper exec, with the path as one argv item and content only on stdin and stdout.
  - `list` re-sorts (folders first, bytewise) and caps at 500 with `more`.
  - `read` returns utf8 or base64 (valid UTF-8 without NUL), with `truncated` and the whole size.
  - `write` and `upload` decode, check the size limits (413), call `assertRoom` before any byte, then stream the bytes
    into the helper's stdin.
  - `download` checks the kind and size first, then reads up to 50 MiB.
  - `delete` re-measures the disk afterwards.
- **`sandboxes.ts`**:
  - `workspace(target)` picks the running `sbx`, or else creates or starts the `files` helper (labels checked, volume
    must exist).
  - `run()` handles exec with stdin (half-close on EOF), a stdout cap and a 60 s backstop.
  - Policy: stored per organization and used at container creation; `ensure` and `restart` refuse `killed` and
    `disk_full` with 409.
  - Stop reasons, the disk cache, CPU deltas, the `usage` op and the reaping of `files` helpers.
  - A Docker `die` watcher (`watch()`) reports crashes.
- **`quota.ts`** measures with `du -sb` through the helper.
  - Over the quota, it marks `disk_full` and stops a running `sbx` with that reason (one usage and one state event).
  - Back under the quota, it clears `disk_full` (one state event, reason null).
- **`sweeper.ts`** runs every 60 s with an injectable clock and one pass at a time. For each running `sbx` it
  measures, stops a sandbox idle past `idleStopMs` with reason `idle` (unless a process is running), or else samples
  usage. It reaps `files` helpers unused for 60 s with `force=1` and without `v=1`, so the volume stays.
- **`events.ts`**:
  - A ring of 5,000 events with a monotonic `seq`, a `bootId` from `randomUUID` per process, and at most 500 events per
    response.
  - An empty answer keeps the cursor (`min(after, seq)`).
  - Polls wait for the next event or the timeout, capped at 25 s.
  - Route `GET /v1/events` (token first, contract query; `waitMs` over 30,000 gives 400).
- **Server**: the routes `filesList`/`Stat`/`Read`/`Write`/`Delete`/`Upload`/`Download`/`Import`, `usage`, `policy` and
  `events`. Log lines still carry only the op, ids, status and duration.
- **`main.ts`** wires events, quota, files, the sweeper and the watcher. New variable `OCW_SANDBOXD_SWEEP_MS`
  (default 60000, minimum 1000). The `listening` log line carries the `bootId`.
- **`ocw-run`** (WINDOWS #235): it removes the `/tmp/ocw-proc` records of process groups that are gone
  (`kill -0 -<pgid>`) each time it starts.

## Real-Docker proof (smoke sections)

- **files:**
  - A 2 MB upload to `reports/q3.csv` is listed with its size. `docker exec stat` shows it and `reports/` owned
    10001:10001. The download has the same sha256. A text write and read come back as utf8; `create` twice gives 409.
  - Planted symlinks (`leak → /etc/passwd`, `etcdir → /etc`, `deep/up → ../../etc`) get 422 `invalid_path` for read,
    download, list and stat, and the body never contains `root:`. A write through `etcdir` gets 422. Deleting `leak`
    removes only the link.
  - Deleting a non-empty folder without `recursive` gives 409 `busy`; with `recursive` it removes 2 entries.
  - After `stop`, the listing works through the helper (`NetworkMode none`, one network `none`, user 10001) and the

  - After `killOrg`, reads still work and the `sbx` stays stopped.

## Deviations from Plan

### Auto-fixed / added (Rules 1–3)

1. **[Rule 2] `policy` op implemented here.** The plan says the sweeper uses "the `limits.idleStopMs` passed at
   `ensure`", but `ensure`'s contract is `{ target }` only. The org limits therefore arrive through the contract's
   `policy` op.
   - Stored per organization: CPU, memory and pids for new containers (this resolves 04's "DEFAULT_SBX_LIMITS until
     policy" stub), the soft quota, the idle stop and `killed`.
   - With `killed`, `ensure`/`restart` answer 409 `killed` (defence in depth behind the API's own check), while people's
     file ops keep working.
   - Defaults until a push: a 2 GiB quota and 15 minutes idle (research §3).
   - The egress fields are accepted and stored for 13's proxy.
2. **[Rule 2] `ocw-files` hardening beyond the plan text:**
   - regular files only for read/cat (FIFO);
   - temporary file + rename, so a write never leaves a partial file;
   - `rm` never follows the last symlink;
   - `du` gives the owner `u+rx` back on folders that lack it (the bot's own uid), so a `chmod 000` folder cannot hide
     its content from the quota.
3. **[Rule 2] Transfer limits.** At most 2 uploads/imports/downloads at once (409 `busy`). A declared
   `Content-Length` over the route limit gets 413 before reading.
4. **[Rule 1] `usage` disk lagged one write.** The measurement runs before the write, so `afterWrite` now records the
   measured size plus the bytes written; the next measurement corrects it. Found by the quota smoke.
5. **[Rule 3] Files outside `files_modified`:**
   - `docker.ts`: `stream()` for the Engine `/events` feed;
   - `main.ts`: wiring and `OCW_SANDBOXD_SWEEP_MS`;
   - `server.test.ts`: the double gains `stream`, and `createServer` now takes `files`;
   - new test files `sweeper.test.ts` and `testing/fake-docker.ts` (a shared Engine double with scripted exec, stdin
     capture and pushed events).
   No parallel plan touched these files; the merge with 12 was clean.

### Names adapted (P-17: names, never semantics)

- `createFiles({ sandboxes, quota })` (not `{ docker, … }`); the `files.remove` op serves `filesDelete`, and
  `files.upload` serves both `filesUpload` and `filesImport` (the same contract input).
- `createQuota({ sandboxes })`, which measures through the sandboxes' helper runner. It also has `afterWrite` and
  `afterChange`.
- `createSweeper({ sandboxes, quota, clock, intervalMs })`: events come from the sandboxes' `onEvent` hook, so the
  sweeper does not take `events`.
- `SandboxdEventInput` is defined in `sandboxes.ts` and re-exported by `events.ts`.

### Plan text vs. what was built

- **Transfer body limit (coordination with 07.8-11).** The API accepts a raw upload of up to 50 MiB (413 `too_large`
  above) and forwards it as base64 JSON, about 67 MiB. My first limit (base64 of 50 MiB + 64 KiB, ≈ 66.7 MiB) left no
  margin. `d6721e60` sets `TRANSFER_BODY_BYTES` = 72 MiB on `filesUpload`, `filesDownload` and `filesImport`.
  `filesWrite` keeps ≈ 1.4 MiB, and every other route keeps `MAX_BODY_BYTES` (1 MiB). The contract schema still
  refuses decoded content over 50 MiB. The tests assert the per-route limits and a 50 MiB upload end to end (RED on
  the limit test before the fix).
- **Uploads "stream the request body into the helper's stdin".** The contract body is base64 JSON, so sandboxd parses
  it and decodes into memory; then it streams the bytes into the helper's stdin in 64 KiB chunks with backpressure.
  There is still no temporary file on the broker.
  - Decision for WINDOWS #233: raise the limit per route rather than stream. A binary streaming body would need a
    contract change in 01, and in the 05/11 client.
- **"crashed" state.** `SandboxStopReason` has no `crashed`, so a crash is state `stopped` with reason null.
- **The files helper's limits** are fixed (0.5 CPU, 256 MiB, 64 pids), not the organization's. `killOrg` also kills
  a running files helper (it carries the org label); the next file op starts it again.

No permission check, contract, label rule or existing assertion was weakened. 04's 33 smoke checks are unchanged
(moved into `section_core`). No existing unit test changed apart from the shared-helper wiring named above.

## Broken-windows candidates (not written to WINDOWS.md, as instructed)

1. **todo (high), 07.8-11.** The policy, the disk state, `disk_full`, the stop reasons and the event ring live in
   sandboxd's memory. After a restart (new `bootId`), the API's events consumer must re-push every organization's
   `policy`. Until then the defaults apply: a 2 GiB quota, 15 minutes idle and **not killed**. The consumer should also
   reconcile state through `usage`, because events from before the restart are gone.
2. **deviation (medium), 01/11.** File transfers stay base64 JSON. sandboxd holds up to ~67 MiB of JSON plus 50 MiB
   decoded per transfer, two at once. True streaming needs a binary body in the contract and the API client.
3. **deviation (medium), 29.** The quota is soft:
   - it counts apparent size (`du -sb`), so sparse files count in full;
   - exec writes between sweeps can overshoot for up to one interval (60 s);
   - the hard quota (XFS `pquota`) must be documented at the gate.
4. **todo (medium), 07.8-11/20.** A crash is `stopped` with reason null (no `crashed` in `SandboxStopReason`). The UI
   cannot say "stopped unexpectedly" without a contract value.
5. **todo (low), 07.8-24.** `OCW_SANDBOXD_SWEEP_MS` is a new sandboxd variable (default 60000). The compose profile
   should leave it at its default, and the env parity test should know it.
6. **deviation (low).** A Docker `die` during a watcher reconnect (2 s retry) is not reported. The API learns the state
   at the next ensure, exec or usage call.
7. **deviation (low).** `du` restores owner `u+rx` on the bot's own folders before it measures.
8. **deviation (low), WINDOWS #235 remainder.** Process records are still in memory only. After a restart, a running
   background process does not keep its sandbox from idling.
9. **todo (low), 29.** CODEOWNERS still lacks `apps/sandboxd/` (as 04 noted).
10. **Pre-existing:**
    - 4 Biome warnings in `apps/local-runtime`;
