# Phase 06.1 Plan 04: Work Zone composer images, stream and queue Summary

A controller can paste a screenshot (a real Cmd/Ctrl+V of an `image/png` clipboard item), drop images on the session pane or pick them with the paperclip. They upload at once into the session's conversation through the Phase 4 pipeline and go out with the prompt. Every controller sees them on the prompt bubble and in the queue, live. The fake runtime's reply `Images: N (types)` shows they reached the device, on Claude Code and on Codex sessions.

## What was built

- **Composer** (`composer.tsx`)
  - Uses `useAttachmentQueue(session.conversationId, …)`. The tray sits inside the card above the text, as in the AI chat composer.
  - `onPaste` takes clipboard file items and keeps any pasted text.
  - The hidden picker accepts the four image types; the button is labelled "Attach images · PNG, JPEG, GIF or WebP, up to 4".
  - Send waits while an upload runs or a file failed or was refused. It posts `{ body, attachmentIds }` and resets the tray on success. On an API error it shows a toast with `errorMessage` and keeps the text and the tray.
  - Refusals:
    - non-images (before presign)
    - the fifth image
    - a model reporting `imageInput: false`: the paperclip is disabled with the reason, paste and drop toast the reason, and tray items are marked refused when the model changes
    - a `/` command while the tray has images: Send is disabled and its title and the hint say why
- **`imageGate`.** Pure and mirrors the API, which stays authoritative. Reasons, verbatim from the plan:
  - "<model> can't read images"
  - "Only images (PNG, JPEG, GIF, WebP) can be sent to a session"
  - "Images can't be sent with a / command"
- **`useAttachmentQueue`.** Gains an optional `precheck(file, accepted)` and `tooManyText`. A refused file enters the tray as a non-retryable error and is never uploaded. Callers that pass nothing (Phase 4 chat, AI chat) behave exactly as before; their specs pass unchanged.
- **Session pane.** `DropZone` wraps the stream and the dock. Label: the session title. Hint: "Images only · up to 4". It is enabled under the same rule as the paperclip and hands files to `composer.addFiles`.
- **Stream.**
  - The prompt bubble (`PromptBubble`) renders `MessageAttachments` right-aligned above the text and opens `Lightbox`, which shows the large webp rendition.
  - The pending "sending to <device>" bubble uses the same component.
  - Previews come only from the API's `/preview` and `/large` routes (T-04-12-02).
- **Queue panel.** The running prompt and every queued prompt show square 44 px previews (`alt` = filename) under the text. Edit, move and cancel are unchanged.
- **`useQueuePrompt`** takes `CreatePromptRequest`. With no images it sends `{ body }` exactly as before.

## Deviations from Plan

1. **[Rule 2 - UX/correctness] The full refusal reason shows under the card** (`composer-hint`, destructive tone, wraps). The plan's reason strings do not fit the shared chip's two-line clamp. The chip's error text also gained a `title`, with no visual change to Phase 4 or AI chat. Commit `3744291`.
2. **`precheck(file, accepted)` instead of `precheck(file)`.** The count is needed to refuse the fifth image in place rather than with a toast. The tray screen limit is 8 chips, with `tooManyText` "Up to 4 images per prompt" beyond that. Retryable upload failures count toward the four.
3. **`MessageAttachments` gained an optional `className`** (`attachment-grid.tsx`, not in `files_modified`). It right-aligns the images in the Work Zone bubble. Default rendering is unchanged.
4. **The paperclip is hidden, not disabled, without storage or `work_session.prompt`** (the Phase 4 rule). It is disabled when the session is archived or the model refuses images.
5. **`session-view.tsx` was also changed in Task 1** to pass `canPrompt`. The plan listed it for Task 2 only.
6. **The Task 2 e2e was not run RED on its own.** It was written first and run only after the implementation, where it passed on the first run. The unit gate was RED-verified. Task 1's tracer was RED-verified for the right reason.
7. **Extra screenshots beyond the plan:** `wz-images-lightbox-*`, `wz-images-slash-*` and `wz-images-codex-*`.
8. **Intended change of 03.2 behaviour:** `work-zone-controls.spec.ts` now expects an enabled paperclip labelled "Attach images" instead of the disabled "Attachments arrive with file uploads".

No permission check, approval gate or RLS path was touched. The client gate is UX only, and the API refuses the same cases (06.1-01/02 tests). No CLAUDE.md-driven changes.
