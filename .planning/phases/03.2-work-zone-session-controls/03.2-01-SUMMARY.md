# Phase 03.2 Plan 01: Work Zone controls tracer Summary

One model change flows composer chip → `PATCH /settings` (catalog-checked, audited) → Device Link `session.configure` → daemon → FakeRuntime (between turns) → `session.settings` → a second controller's chip, live; plus every phase contract, the single `work_zone_controls` migration, slash commands, the runtime controls inventory and the session diff stat.

## What was built

- **Contracts (P-01):** `PermissionMode` = plan/default/acceptEdits/auto/fullAccess with the rank ladder, `minMode`, `modeWithin`, `RUNTIME_BYPASS_LITERALS` (rejected by every payload), `isFullAccessReport`; `session.settings` event; `session-settings.ts` (settings, catalog, controls); `work-zone-policy.ts` (full access and fast mode off by default); Device Link `session.configure`, `CapabilitiesFrame`, hello `fullAccessOptIn`, prompt `permissionMode`; device grants; `WorkSession.settings/fullAccess/runningSince/diffStat`; permissions `work_session.configure`, `device.full_access` (relation-only), `work_zone.manage` (admin, non-delegable); slash commands; inventory with `isExposed`.
- **Migration (P-02):** `20261005201032_work_zone_controls` — `device_grants` (soft revocation), `work_zone_policies`, device opt-in/share cap/catalog columns, session settings columns + `work_sessions_permission_mode_ck`, `work_prompts.permission_mode`. `drizzle-kit generate --name work_zone_controls_check` reports "No schema changes".
- **API:** capabilities ingestion (`hub.onCapabilities`), hello opt-in persisted, `GET /controls`, `PATCH /settings` (lock, configure check, archived 409, decideSettings, P-08 denials, persist + pending, enqueue configure, audit `work_session.settings_changed`, emit), create-path mode check, `session.settings`/`session.started` effective settings, failed configure audited (`work_session.settings_failed`), prompts carry/record the turn mode, `runningSince`, `diffStat`.
- **Local runtime:** `configure?`/`catalog?`, daemon per-session chain, capability-checked modes, capabilities frame in the handshake, adapters refuse modes outside their capabilities, FakeRuntime catalog/configure/`Model: <id>`.
- **Web:** `useSessionControls`, `useUpdateSessionSettings`, `ModelPicker` in the composer; controls refreshed on `work_session.updated`.
- **e2e:** `startFakeDevice`, `work-zone-controls.spec.ts` (desktop + mobile).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] resolve.test.ts role matrix** — `Record<Permission, boolean>` needed the three new permissions (6aa4e81).
**2. [Rule 2 - Critical] `work_session.configure` is device-gated** — added to `DEVICE_GATED` so a revoked device's sessions cannot be configured (ec4ad56).
**3. [Rule 2 - Critical] Claude adapter maps platform → SDK mode explicitly** — `sdkPermissionMode()` refuses `fullAccess` so the widened enum can never become `bypassPermissions` by type coercion (adcadd6).
**4. [Rule 1 - Bug] Mode check order** — org policy is reported before runtime support, otherwise fullAccess under the default policy answered `runtime` instead of the required `org_policy` (ec4ad56).
**5. [Rule 3] Legacy modes without a catalog** — existing sessions on devices that never sent `capabilities` must keep default/acceptEdits/plan (`LEGACY_PERMISSION_MODES`).
**6. Composer viewer gate** — `work_session.configure` added to the session `viewerCan`; the chip is disabled without it, without a catalog, or when archived.
**7. [Rule 1 - Bug] Offline replay test race (effbffa)** — the test waited for 4 frames while asserting 5 after the capabilities frame was added.
**8. Screenshots** — only `wz-controls-*` captures are committed; the regression spec's captures written into the same folder were removed.
