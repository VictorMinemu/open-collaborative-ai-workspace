# Phase 07.8 Plan 20: Sandbox and browser activity in chat, and the browser approval card Summary

**Every reader of a bot's reply now sees, above its text, what the bot did in its sandbox and browser: a collapsed
"Used its sandbox · 2 steps" group that expands into masked steps (verb, mono target, outcome, and for commands the
masked command, folder, exit code, duration and output tail). While the turn runs they see "Scout is writing
reports/late.csv · step 1". A signed-in browser action's 07.5 card shows exactly what will happen on the member's site:
Action, Element, Page (host chip), Session, what the bot will type, why it asks, and that it runs once while the page is
open.**

## Deviations from Plan

### Auto-fixed / added (Rules 1–3)

1. **[Rule 2] Contract + API: `AgentCardApprovalLink.browser`** (`packages/contracts/src/agent-cards.ts`,
   `tool-approval/{kind,view}.ts`, the three pick lists in `approval/registry.ts`, `approval/service.ts`,
   `lib/chat-agent-bridge.ts`). The card had no scheme for its Page field, so it could not say "Not secure" for an http
   page (T-07.8-20-03), and the web would have had to classify a browser card by its field labels. The link now carries
   `{action, host, secure, signedIn}` for `ocw_browser_act` / D-13 `ocw_browser_open`: no element, no value, no option
   (the summary title already names action and host). Additive and display-only; no permission, policy or approval
   decision changed. Tests: `view.test.ts` (`cardBrowserOf` never carries the element or the value) and
   `browser.int.test.ts` (the card's link as Sam lists the DM).
2. **[Rule 3] Views wired** (`dm-view.tsx`, `channel-view.tsx`, `thread-panel.tsx`, outside the file list): the
   `turn.activity` frame goes to `applyTurnActivity`, and each list passes its running turns to `MessageList`.
3. **[Rule 2] `approval-review.tsx`** (outside the file list): passes `expiresAt` for the browser timer and shows the
   browser "Not used" line on the review too.
4. **[Rule 1] Real spaces between the parts of a step** (verb, target, host, outcome), so copy, find-in-page and screen
   readers do not read "Wrotereports/late.csv".
5. **BotActivity on `MessageRow` too.** The plan names `message-card.tsx`, which only renders pinned and saved messages;
   the conversation list renders `MessageRow` in `message-list.tsx`. Both show it.

### Plan text vs. what was built

- **The typed field is “Email”, not “Address”**: the fake site's form names its fields Email, Password and Sign in
  (`fake-sandboxd.mjs`, owned by 07.8-18 in this wave, not edited). Same as 07.8-14.
- **`python fetch.py` exits 127** in the fake sandboxd ("sh: python: not found"), which is the failed-exec detail the
  UI-SPEC screenshot asks for.
- **"Not used" is produced by time** (`decided_at` moved back 16 minutes on the isolated database, as 07.5 produces
  Expired): the card shows Not used only after the 15-minute use window, so an `element_gone` re-run would still read
  Approved until then. Expired likewise moves `expires_at`.
- **The asked-sign-in step needs the requester**: `ActivityStep` carries no person, so `MessageRow` passes
  `requester: null` and the row reads "Asked for a sign-in to {host}"; "Asked you / Asked Sam" is implemented and
  unit-tested for when a caller knows the requester (candidate 1).
- **Watch** is 07.8-26's (`activity-watch`), not rendered here.
- **Approve dialog body for browser actions**: "{bot} does it once, while the page is open, signed in to {host} as you."
  (07.5's copy names a tool and "exactly these values", which does not fit an element action; the UI-SPEC has no dialog
  copy for this case).

No permission check, RLS policy, approval gate or existing assertion was weakened. The 07.5 approval, memory and
board-agent cards keep their markup (`agent-card.test.tsx` snapshots unchanged; 70 existing cases green).
