# Phase 07.10 Plan 07: Gap closure after code review, security audit and UI audit Summary

The visibility panel no longer names a team project to a reader who can't open it (HI-01, the last D-14 leak), and a
hidden session's labels no longer claim "everyone who can use {device}". Stored `ws:` history is stripped on replay,
the last-turn query is bounded to 24 h, focus survival no longer steals focus, and the sidebar's project names, Needs
you reasons, sizes and colours follow the UI contract.

## Intended change (written before code, CLAUDE.md plan mode: permissions, tenant data paths)

Committed first, in `c6eacdc2`, before any code.

### HI-01 / T-07.10-02-05: `GET /work-sessions/:id/visibility` decides the project per viewer

The panel endpoint takes the same decision as `loadViewerFields` (one helper, shared): the session's team project is
**named** to the caller when the caller created the session (D-12) or when the resolver allows `work_session.read` on
the project's `work_project` resource (built from `app.work_project_access`, the `GET /projects` decision). Anyone
else who may read the session gets the **hidden form** (fail closed). Who may call the endpoint does not change: it
stays `work_session.read` on the session (404 otherwise).

What each viewer receives from `/visibility` after the fix:

| Viewer | `project` | `projectDefault` | `teams` | `people` | `viewers.people[].via` for `team` rows | everything else |
|---|---|---|---|---|---|---|
| Creator (in the project, or who left it, D-12) | `{ kind: "team", id, name }` | the project's default | assigned + stale selected | stored people | the team | unchanged |
| Project lead / member / member through a team | named, as above | as above | as above | as above | the team | unchanged |
| Admin | named, as above | as above | as above | as above | the team | unchanged |
| Device owner outside the project (D-11), anyone else who reads a team-project session without project access | `{ kind: "hidden" }` (no id, no name) | `null` | `[]` | `[]` | `null` (no team named) | `kind`, `owner`, `viewers.count/more`, the viewer rows with their reasons (`lead`, `member`, `team` without `via`), `alwaysVisible`, `viewerCan`, `viewerState` |
| Anyone, personal repository | `{ kind: "personal", deviceName }` | `null` | `[]` | stored people | n/a | unchanged |
| Another organization | 404 (unchanged) | | | | | |

- The `PUT /visibility` answer is built by the same function, so it follows the same rule.
- Contracts: `WorkSessionVisibilityView.project` gains the variant `{ kind: "hidden" }` (additive).
- Web: the chip and the panel read the hidden form as "a project you can't open". The panel shows a read-only note
  ("Linked to a project you can't open.") and the footer; it never offers the choices, the teams or the people.

## Deviations from Plan

1. **[Rule 3 - Tooling]** The harness blocks Edit/Write and complex shell forms in the phase worktree, as for 01-06.
   Files were edited in `/tmp/ocw0710-07` and copied in; git ran as plain single commands.
2. **[Rule 2 - Completeness] The hidden form also withholds the stored people.** Not named in the finding, but their
   `active` flag says who has access to a project the caller can't open; the panel has no use for them read-only.
3. **[Rule 2 - Completeness] The hidden panel is read-only on the web even if `viewerCan.change` were true.** The
   resolver gives the D-11 device owner no `work_session.visibility`; the PUT still decides on the server.
4. **LO-04 "touch" hint.** The hint now reaches screen readers (VoiceOver/TalkBack on touch included) through sr-only
   text, as the review's fix says. A sighted touch user still sees only the repository name; adding visible text to
   the row was not asked and would change the approved layout.
5. **Collapsed count alignment:** `ml-auto` aligns Personal with departments that have no "+"; for a viewer who may
   create in a department, that department's always-present "+" slot sits after its count, so its count ends 24 px
   before Personal's. Accepted (the review's suggested change); the chat header is unchanged.

  worse than 07.9; ADR-0031 now says so instead of "never one query per row". Fix when needed: one decision context
  per batch (`usersAllowedMany`), with a `list-perf`-style measurement with many approvals pending.
- **Team names on the session summary.** `visibility.firstTeamName` (list, detail, `ws:`) may name a team assigned to
  a project the reader can't open; it names a team, never the project, as in 07.9 (unit names are organization data).
  Recorded in ADR-0031.

  not get its approvals in Needs you.
