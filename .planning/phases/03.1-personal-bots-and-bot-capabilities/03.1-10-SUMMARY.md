# Phase 3.1 Plan 10: MCP servers attached to bots inside the OpenClaw cell Summary

Registered MCP servers now work for bots inside the cell: the cell probes a server with the official MCP SDK client and the API records its tools. The cell renders only servers that have an enabled tool, with credentials as `${OCW_MCP_…}` env references and an exact tool filter. Every MCP call goes through the existing fail-closed `before_tool_call` gate. Each call is audited with bot, human, server and tool, and is decided as agent ∩ asking human at delivery and again at call time. MCP output taints the turn, so a side-effecting tool cannot run after it unless the admin trusts the server for chained calls.

## What was built

- **Probe (Task 1).**
  - `mcp-probe.ts` uses `Client` with `StreamableHTTPClientTransport` or `SSEClientTransport` from SDK 1.30.0 (pinned exactly, loaded lazily). It sends the snapshot's headers, refuses redirects and paginates `tools/list`.
  - It always closes the session and treats tool metadata as untrusted and bounded.
  - Errors are classified and never carry a header value.
  - The bridge handles `mcp.probe`: it finds the server in the last snapshot, refreshes once if the server is unknown, probes and reports.
- **API (Task 1).**
  - `POST /agent-channel/v1/mcp/probe-results` runs in the cell scope (`cell.sync`) and calls `recordProbeResult`.
  - `GET /cell` delivers `cellMcpServers`, and `agent_cell.config_read` audits the delivered server ids.
- **Rendering (Task 2).**
  - The reconciler writes `mcp.servers.<safe> = {url, transport, headers: {Name: "${OCW_MCP_<SAFE>_<i>}"}, toolFilter: {include: [exact names]}}`.
  - Header values go to the gateway env only, and are removed from it when the server goes away.
  - Servers without an enabled tool are never rendered, and plugin-owned servers that left the snapshot are removed.
  - Agent `alsoAllow` keeps exact `<safe>__<tool>` names and now refuses `bundle-mcp` / `bundle-lsp`.
  - `render-config` sets `mcp.sessionIdleTtlMs: 600000`.
- **Gate and audit (Task 2).**
  - The guard maps OpenClaw's case-folded hook name back to the turn's exact name. The guard and the API use that name for the decision and the audit.
  - `bot.tool_call` for an MCP tool records `sourceKind: "mcp"`, `sourceId` (server id) and `target` (safe name) in `agent_tool_calls` and in the audit metadata.
  - `bot.tool_call.completed` stores the outcome. Arguments and results are never stored.
- **Taint (Task 3).** The generic 03.1-04 rule already held for MCP, so this task only proves it:
  - Locally: after an MCP read, a side-effecting MCP tool is blocked without asking the API.
  - In the API: a call on the same turn is refused as `tainted`.
  - `trustedChaining` allows the chain on a new turn.
  - Revoking trust also affects a turn delivered while the server was trusted, because the API applies the stricter current flags at call time.
- **Registry model.**
  - `testing/openclaw-host.ts` now builds hook events with `normalizeToolPolicyName`, as the dist does.
  - `openclaw-registration.test.ts` runs MCP calls through the real entry in the `discovery` and `full` registries. A mixed-case read is allowed with its exact name, and a write after it is blocked.
- **Smoke scenario `mcp`** (`infra/openclaw/test/run-container-smoke.sh`, fixture `mention-mcp.json`), described below.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The gate blocked any MCP tool with capital letters.**
- **Found during:** Task 2, while reading `wrapToolWithBeforeToolCallHook` in the dist.
- **Issue:** OpenClaw's hook event carries the lower-cased policy name, while the turn and the API use the model-facing name (`m…__getFile`). The fake's tools are lower-case, so the smoke would not have caught it.
- **Fix:** `canonicalToolName` in `tool-guard.ts`; the host model now case-folds as the dist does; unit and registry-model tests added.
- **Commits:** a727aa9, 67f67c8.

**2. [Rule 1 - Bug] Tool-name collision suffixes followed the server's listing order.**
- **Issue:** OpenClaw sorts a server's tools by name before it assigns suffixes, so the API's grants would point at the wrong tool when a server lists colliding names in another order (Pitfall P-B2).
- **Fix:** `openclawToolNames` sorts the same way and returns names in input order.
- **Commit:** a727aa9.

**3. [Rule 2 - Security] Additions beyond the behaviour list.**
- `alsoAllow` refuses `bundle-mcp` / `bundle-lsp`. OpenClaw treats `bundle-mcp` as "every MCP server".
- The reconciler skips non-http URLs and non-OCW env or header names.
- Credentials of a removed server leave `process.env`.
- The probe refuses redirects, so credentials are never replayed to another endpoint.
- Audits carry `sourceId`.

**4. [Rule 1 - Bug] Credential rotation could be ignored.**
- **Issue:** When the runtime view shows the `${ref}` rather than the resolved value, an unchanged entry was never rewritten, so OpenClaw kept the old token.
- **Fix:** The port passes the gateway env, and a header whose value changed forces the upsert.
- **Commit:** b21418b.

**5. [Rule 3 - Blocking] Files outside the plan's list.**
- `infra/fake-model/fake-mcp.d.mts`: types for the in-process fake MCP in TypeScript tests.
- `apps/openclaw-channel/src/openclaw-registration.test.ts` and `testing/openclaw-host.ts`: the debug lesson requires contract tests through the host model.
- Both READMEs.

**6. [Plan wording] The smoke's taint step landed in the Task 2 commit.**
- The whole `mcp` scenario was written in one pass, so it landed in the Task 2 commit (a727aa9).
- Task 3's commit (b569863) holds the guard and API taint tests.

**7. [Plan wording] `handleMcpProbe` takes extra deps.**
- Besides `{client, snapshot}` it takes `refresh`, `probe`, `signal` and `log`.
- `POST /mcp/probe-results` answers `Ok` and does not expose `applied`.
