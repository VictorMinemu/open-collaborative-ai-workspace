# Phase 07.13.1.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 5 (root projects `unit`, `integration`, `web`), Playwright 1.64.1 (e2e, CI only), `node --test` for `scripts/e2e-env-parity.test.mjs` |
| **Config file** | `vitest.config.ts`, `e2e/playwright.config.ts`, `.woodpecker/e2e.yaml`, `.github/workflows/ci.yml` |
| **Quick run command** | `pnpm exec vitest run --project unit <path>` · `pnpm exec vitest run --project integration <path>` · `pnpm exec vitest run --project web <path>` |
| **Full suite command** | `pnpm verify` |
| **Estimated runtime** | ~900 seconds (full), ~10-60 seconds (quick; integration files start one ephemeral PostgreSQL) |

## Sampling Rate

- **After every task commit:** the task's `<automated>` command
- **After every plan wave:** `pnpm test` (wave 2 and wave 3 merge three plans each)
- **Before `/gsd-verify-work`:** `pnpm verify` green and the Woodpecker e2e (desktop and mobile) green with
  `work-zone-session-owners.spec.ts`; the review screenshots copied into `screenshots/`
- **Max feedback latency:** 60 seconds for task-level checks

## Offline rules (owner)

- No test calls a real Claude or Codex login, GitHub, the npm registry or a remote host. Runtime fixtures are offline:
  the Claude `ocw_session` fixture is synthetic (derived from SDK 0.3.282 types, like `browser-mcp.synthetic`), the
  Codex one is derived from the recorded `codex-0.172.0.browser-mcp.rpc.jsonl`.
- Integration tests run on a real ephemeral PostgreSQL (testcontainers), never a database mock, never a non-ephemeral
  database; the migration is applied only there.
- The e2e runs only in CI. Locally it is typechecked (`pnpm typecheck:e2e`) and listed (`--list`).
- Daemon tests use temp `OCW_HOME` folders, fake links and `OCW_RUNTIME_FAKE`; no test touches the real `~/.ocw`.
