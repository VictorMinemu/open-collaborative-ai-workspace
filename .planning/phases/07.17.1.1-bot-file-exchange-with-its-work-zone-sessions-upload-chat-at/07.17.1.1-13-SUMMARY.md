# Phase 07.17.1.1 Plan 13: The download route and the shared refusal matrix Summary

**`POST /agent-channel/v1/work-sessions/download` brings one file of the bot's own session back as a pending attachment of the turn. The bot's reply for that turn links it, and Ana downloads it through the normal attachment route. It runs through 12's `runFileCall` as a second `FileMove`, not a copy. The integration suite now proves every refusal both file tools share, and that no path or name reaches a record or a log line.**

## Intended change (CLAUDE.md plan mode: permissions, audit, tenant data)

- One new route and no new permission, grain, RLS change or schema change (P4). The four 07.16 routes and the upload are untouched (P5).
- The download composes decisions that already exist:
  - tx0 runs user-less.
  - txA runs as the asker: live turn, tool, storage. A download takes nothing from the chat.
  - txB runs as the session's sponsor: own session, origin conversation, profile and sponsor, scope, deny list, outside content, session output, the claim, then `botFiles.prepareDownload`. That call decides `work_session.read` for the sponsor, the session state (a running session is allowed), the device, the budgets and the pending cap.
  - txC: `finish(from_device)`.
- Audit is additive: `bot.work_session_download` uses the same builder and fields as the upload's success audit.

## Deviations from Plan

### Test-scope notes (no production code changed)

**1. The matrix passed when first written; shown non-vacuous**
- The plan expected this ("most cases follow from 12's order and from 11").
- To show the cases are not vacuous, I made a temporary edit that disabled the route's origin-conversation check and its session-output check. Exactly the two matching cases then failed:
  - The ownership case: the service's own origin check then answers after the claim, so the call counts.
  - The session-output case: the claim answers `outside_content` instead of `session_output`.
- Restored with `git checkout -- apps/api/src/modules/agent-channel/work-session-files.ts`.
- `work-session/bot-files.ts` needed no fix, so it is unchanged although it is listed in `files_modified`.

**2. A sentence expectation, fixed in the test**
- The disabled-bot case first failed on the sentence: `profile_inactive` with a reason appends the reason's sentence (`refusedAnswer`). The test now asserts the composed sentence. The route was right.

**3. "A person's session" is Víctor's**
- `startSession(victor, …)` is used, as in the 07.16 control suite. The service device is Víctor's, and Ana's right to start sessions on it is not part of this suite's setup. The rule under test is the same: the session is not one Atlas started.

**4. The sweep has two sanity checks**
- The captured log stream must contain "bot file move finished".
- `app.attachments` must hold a `README.md` or `spec.pdf` row.
- Without these, the sweep could pass on an empty stream or on names never used.
