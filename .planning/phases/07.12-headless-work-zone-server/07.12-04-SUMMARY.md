# Phase 07.12 Plan 04: The runtime as a service (systemd and launchd) Summary

**`ocw-runtime service install|uninstall|status|logs|restart` keeps the runtime running across logouts, crashes and
reboots. On Linux it uses a systemd user unit, or a system unit that runs as a named non-root account. On macOS it uses a
LaunchAgent. Each definition is generated with escaped absolute paths and holds no secret. Installs refuse to start a
second runtime on the same `~/.ocw`, and re-running install is harmless. Every command goes through an exec that tests
cannot point at the real service managers.**

## Accomplishments

- **systemd user unit** at `${XDG_CONFIG_HOME:-~/.config}/systemd/user/ocw-runtime.service`, mode 0644.
  - `ExecStart="<node>" "<OCW_HOME>/runtime/current/ocw-runtime.mjs" run` goes through the `current` directory link and
    is never resolved to the real path. This follows the note from plan 01.
  - `Environment="PATH=…"` puts the node's directory first, then the installer's PATH entries that exist, each once.
  - `OCW_HOME` appears only when it is not the default.
  - Fixed directives: `Restart=on-failure`, `RestartSec=5`, `StartLimitIntervalSec=300`, `StartLimitBurst=10`,
    `KillMode=mixed`, `TimeoutStopSec=20`, `UMask=0077`, `WantedBy=default.target`.
  - Install runs `daemon-reload`, `enable --now`, `is-active` and `loginctl show-user <user> --property=Linger`. When
    `Linger=no` it prints `sudo loginctl enable-linger <user>`.
- **System unit** with `--system --user-name <account>`, root only.
  - The account is checked against `^[a-z_][a-z0-9_-]*\$?$` before any exec, then looked up with `getent passwd`.
  - Refused: `root`, any account with uid 0, an unknown account, an account without an installed runtime ("install
    the runtime as build first … (sudo -u build -i)"), a non-root caller, macOS and Windows.
  - The unit adds `User=`, `After=`/`Wants=network-online.target` and `WantedBy=multi-user.target`.
  - The final line points at signing in with `sudo -u <account> -i`.
- **LaunchAgent** at `~/Library/LaunchAgents/org.ocw.runtime.plist`, mode 0644.
  - Keys: `KeepAlive { SuccessfulExit: false }`, `ProcessType Standard`, `RunAtLoad`, `WorkingDirectory`,
    `EnvironmentVariables` (`PATH`, plus `OCW_HOME` when not the default). Stdout and stderr go to
    `~/.ocw/logs/runtime.log`; that directory is created with mode 0700.
  - Every value is XML-escaped, and control characters are refused.
  - Commands use `launchctl bootout|bootstrap|print` in `gui/<uid>`. A bootout of an agent that is not loaded is
    tolerated.
  - `restart` runs bootout, rotate, bootstrap. The log moves to `runtime.log.1` when it is above 5 MB. `logs` reads
    the last N lines; `--follow` runs `tail -F`.
- **Status** returns the `ServiceStatus` that 05 and 08 consume. `nodePathExists` and `bundlePathExists` come from
  parsing the paths back out of the installed unit or plist, so doctor can see a node binary that an nvm upgrade
  deleted.
- **One owner (D-14):** `runtimeOwnerConflict` runs before anything is written.
  - The control socket answers within 2 s and this unit is not running → refused with "a runtime already runs on this
    account …".
  - `desktop-daemon.pid` names a live process (EPERM counts as alive) → refused with "the desktop app supervises …".
  - A stale or invalid pidfile is ignored.
- **Idempotent re-install:**
  - Same text and running → no write, no restart, "already installed and running".
  - Changed text and the daemon reports `sessions: []` → write, `daemon-reload`, restart.
  - Changed text with a session running, or no answer from the daemon → write and reload only, then print "restart
    with `ocw-runtime service restart` when no session runs".
  - Installed but stopped → started again.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `$` in Environment= is not doubled**
- **Found during:** Task 1
- **Issue:** PD-11 lists `$`→`$$` for the quoted values. systemd expands `$` only in `ExecStart=`. In `Environment=`,
  `$$` would reach the service as two dollar signs.
- **Fix:** `systemdQuote` (ExecStart words) escapes as PD-11 says. A separate `systemdEnvQuote` escapes `\`, `"` and
  `%` only. `WorkingDirectory=` uses `systemdPathValue`: unquoted, because systemd does not unquote that directive,
  with `%` doubled.
- **Commit:** `ce14073e`

**2. [Rule 2 - Security] No user unit or LaunchAgent as root**
- **Found during:** Task 1
- **Issue:** The plan refuses `--user-name root` for system units, but a plain `service install` run by root would have
  created a root-owned user service (T-07.12-04-01).
- **Fix:** As uid 0, `install` without `--system` is refused. On Linux the message points to
  `--system --user-name <account>`.
- **Commit:** `ce14073e`, extended to macOS in `9772f501`

**3. [Rule 2 - Correctness] Two robustness steps for launchd**
- **Found during:** Task 2
- **Issue:** `launchctl bootstrap` straight after `bootout` can fail with error 5 while the old instance is torn down.
  `print` straight after bootstrap may not show `running` yet.
- **Fix:** One bootstrap retry and one print re-check, each after an injected 1 s sleep. Both are tested.
- **Commit:** `9772f501`
