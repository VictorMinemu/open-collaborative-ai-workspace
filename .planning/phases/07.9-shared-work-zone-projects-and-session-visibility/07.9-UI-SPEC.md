# Phase 07.9 — UI Design Contract

> Visual and interaction contract for the five 07.9 surfaces: (1) the session **visibility chip** in the session header
> and its **popover** (bottom sheet on phones), (2) the **sidebar marker** shown only when a session's audience differs
> from its project's default, (3) the **new-session dialog**: repos grouped under their team project and one line
> "Visible to: … · Change", (4) the **Work Zone project pages** (`/work-zone/projects` and
> `/work-zone/projects/<unitId>`) with project settings: default switch, people, assigned teams, linked repos, and (5)
> the **Settings › Organization** additions on a project unit. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. Every value comes from the existing tokens in `apps/web/app/globals.css` and the existing primitives
> in `apps/web/components/ui/*`. This phase adds **no new primitive, no new CSS variable, no new font and no new web
> dependency**. Where this file and a plan differ, this file wins and the difference goes to **§ Plan reconciliation**.
> UX risks found in D-01…D-12 are in **§ UX risks** (U-1 and U-2 resolved by D-11 and D-12).

**The owner's brief is a hard constraint:** "muy visual, sin mucha contaminación visual, pero que se entienda todo muy
bien". It is applied as five rules, and every element below names the rule that justifies it:

| # | Rule | Consequence |
|---|------|-------------|
| N1 | One chip, one popover | Visibility is read and changed in exactly one place per session. No banner, no second badge, no settings page for a session |
| N2 | Silence on the default | The sidebar and lists show nothing when a session follows its project's default. A marker means "this one is different" |
| N3 | The answer, not the rule | The popover always ends with *who* can see the session now (faces + count), not with a policy description |
| N4 | Plain words | "Only me", "Project", "2 teams", "3 people", "can see". Never "ACL", "grant", "audience", "scope", "visibility rule" in UI copy |
| N5 | No color for status | Visibility never uses accent, amber or red. Icons are `text-muted-foreground`; the label carries the meaning |

## Information Architecture and Navigation

| Entry | Route / place | Shows | Who (the API decides; the web renders what it returns) |
|-------|---------------|-------|----------------------------------------------------------|
| Visibility chip | Session header right cluster, immediately left of the presence stack | Who can see this session (short label) | Everyone who can see the session; `viewerCan.changeVisibility` (creator, project leads, admins) makes it editable |
| Visibility popover / sheet | Opened by the chip | 4 choices + inline pickers + who can see it now | Same |
| Sidebar marker | Session row, after the title | Only when the audience ≠ the project default | Rows the viewer can see |
| New-session line | New-session dialog, right under the Project section | "Visible to: {label} · Change" | Anyone starting a session |
| Projects index | `/work-zone/projects` (new). Sidebar link **Projects** (`FolderKanban`) above the existing **Devices** link | Team projects the viewer can open; their personal repositories | Project access (D-02) |
| Project page | `/work-zone/projects/<unitId>` (new), tabs `Sessions` (default) · `Settings` (`?tab=settings`) | Sessions the viewer can see in this project; access, default, people, teams, repositories | Project access; editing: project leads and admins (D-03, D-10) |
| Breadcrumb link | Session header: the project segment links to the project page for team projects | — | Plain text for personal projects (tooltip "{repo} on {device}") |
| Settings › Organization | `/settings/organization?unit=<id>` (existing) for a unit of kind `project` | Two new sections after People: **Teams** and **Work Zone** (default switch, repositories, "Open in Work Zone") | Existing `viewerCan` on the unit; the API re-decides |

Where a person finds a team project: (a) the sidebar **Projects** link, (b) the session breadcrumb, (c) the new-session
dialog group header, (d) Settings › Organization for admins and leads. No new rail entry, no new settings section
(N1: the project already lives in the org tree; Work Zone gets one link).

Sessions in the sidebar group by **team project** when the repo is linked (two repos of one project sort together),
by repo otherwise. The row's project label and two-letter badge use the team project name when linked.

#### 1.3 Labels, pickers and apply rules

Short label (chip) and long label (new-session line, tooltips, accessible names), computed in
`lib/session-visibility.ts`:

| Audience | Short label | Long label |
|----------|-------------|------------|
| owner, viewer is creator | Only me | Only you |
| owner, viewer is not | Only {owner first name} | Only {owner} |
| project (team) | Project | Everyone in {project} |
| project (personal) | Project | Everyone who can use {device} |
| teams, 1 active | {team} | {team} |
| teams, 2+ active | {n} teams | {A} and {B} · {A}, {B} and {n} more |
| people | {n} people (active people + the owner) | {n} people |

**Team picker** (`team-picker`), under Teams: a checkbox list of the project's assigned teams, no search (a project
has few teams). Row min-h-11 (h-9 visual ≥ 768): native checkbox `size-4 accent-primary`, `KindIcon` sm, name 14/400,
"{n} people" 12/400 muted right. Nothing checked yet → a 12/400 muted hint "Pick at least one team." under the list.

**People picker** (`people-picker`), under People: the owner first as a fixed row ("{name} (you) · Owner" or
"{owner} · Owner"), then the chosen people (avatar 24, name 14/400, remove `X` icon-xs 28, 44 below 768,
`aria-label="Remove {name}"`), then one search field `h-9` (`h-11 text-base` below 768) "Add people in {project}"
with the `SubjectPicker` combobox markup from `share-people.tsx`, **restricted to people with project access** (the
API lists them) and with **no** teams or "Everyone" options. Options render **inline** under the field (`max-h-48`
scroller), not as an overlay, so they never clip inside the popover or the sheet. No match: "No one in {project}
matches “{q}”." Nothing chosen yet → "Pick at least one person."

Apply rules (no Save button; N1):
1. Choosing **Only me** or **Project** applies at once.
2. Choosing **Teams** or **People** opens its picker; nothing is saved until the first team or person is picked;
   then every check, pick or remove applies at once. Closing the panel with nothing picked keeps the previous
   audience (no request was made).
3. While a request is pending, the changed control shows `Spinner` 12 in place of its icon; the rest stays usable;
   requests are serialized (the last state wins).
4. If the change removes anyone who could see the session, a toast says so with **Undo** (restores the previous
   audience in one request, 8 s). Widening never toasts: the footer count changing is the feedback.
5. A polite live region announces "Visible to {long label}. {n} people can see it." after each applied change.
6. On failure: the control returns to the server's state and a toast "Couldn't change who can see this session. Try
   again." No inline error inside the panel (the panel never shows a stale state).

#### 1.4 Read-only panel

Viewers without `changeVisibility` see the same title, subline and footer, and **only the current choice** as a
static row (icon, label, line; no radio). For teams / people the static row lists the names as plain text
("Backend, Design" / avatars of the people). One line under it: `Info` 14 + "Only {owner}, project leads and admins
can change this." (12/400 muted). A creator who left the project (D-12) gets "You left {project}, so you can't change
this." instead. No disabled radios (N1: nothing that looks clickable and is not).

#### 1.5 Entries outside project access (D-04)

A team no longer assigned to the project, or a person who lost project access, stays in the stored audience but
grants nothing. The pickers show it as an inactive row: avatar / `KindIcon` at `opacity-50 grayscale`, name
`text-muted-foreground line-through decoration-muted-foreground/40`, line 12/400 "Left {project}" (person) /
"No longer assigned to {project}" (team), and the remove `X` (editors only). Inactive entries never count in the
chip label or the footer. If every entry is inactive, the chip reads as the owner case ("Only me" / "Only {owner}")
and the panel keeps Teams / People selected with the inactive rows visible, so the editor understands why.

## Interaction Contract

### Chip and panel
- Click / Enter / Space on the chip opens the popover (≥ 640) or sheet (< 640). The panel loads
  `GET /work-sessions/:id/visibility` on open (stale-while-revalidate; the chip label comes from the session DTO, so
  the chip never waits).
- Keyboard: Tab moves chip → radio group (arrow keys move and select, native) → the open picker → See all → close.
  Escape closes and returns focus to the chip. A choice made with arrow keys applies only after focus rests on it for
  400 ms without another arrow press, so passing over Only me on the way to People never saves it. Pointer clicks
  apply at once (rule 1). Teams / People only open their picker (rule 2).
- Live updates: another editor's change updates the open panel and the chip in place (session event); a picker the
  viewer is typing in keeps its query.
- Losing edit rights while the panel is open switches it to read-only in place.

### Narrowing and live removal (D-04, ADR-0009)
- The server re-authorizes `ws:<id>` at once. A removed viewer's session view switches to the access-lost state
  (§ States) and the row disappears from their sidebar, home and project page in real time. No toast for them.
- The editor gets the toast with Undo (rule 4); Undo re-widens in one request and the removed people regain the
  session (they see it again in the list; an open access-lost view offers `Open session` via a live check).

### New-session dialog
- Changing project resets the line to that project's default; the popover in draft mode never calls the save API.
- Start session sends `{ visibility: { kind, teamIds?, userIds? } }` with the create request; a server refusal
  (for example a person who left the project meanwhile) shows inline in the dialog's existing error line.

### Project pages
- Index and project page update live from the unit and session events already used by Settings › Organization and the
  Work Zone list. Losing project access while on the page swaps to the no-access state.
- Default switch, assign, link, remove and unlink each save immediately with a toast; remove and unlink confirm first.
- `?tab=settings` deep-links the Settings tab; an unknown tab falls back to Sessions.

### Focus management
- Opening the popover focuses the selected radio (editable) or the panel title (read-only); the sheet does not move
  focus into the search field (no keyboard pop on phones) and focuses the title.
- After a picker applies, focus stays on the control that changed.
- Dialogs focus Cancel on destructive confirmations and the first field elsewhere; closing returns focus to the trigger.

### Reduced motion
- Popover and sheet keep their existing transitions only when motion is allowed (existing primitives); See all expands
  without height animation under `motion-reduce`.
