# Phase 07.13.1: Desktop app auto-update — Context

**Gathered:** 2026-11-26
**Status:** Ready for planning
**Source:** owner request ("hay que implementar un sistema de auto update para todos los clientes, ya sea windows linux o
mac"), decided under the owner's standing autonomy grant from `07.13.1-RESEARCH.md`.

## Phase boundary

The OCW desktop app (Electron, apps/desktop) finds a newer release on the canonical GitHub releases, downloads it,
verifies it and installs it by itself on Windows (NSIS), Linux (AppImage) and macOS (arm64, ad-hoc signed), never
cutting a Work Zone turn. The bundled Local Runtime is updated with the app. Out of scope: code signing (Phase 9), the
`.deb` self-install, the web app, headless servers (ADR-0040 already updates them).

## Locked decisions

- **D-01 Updaters.** electron-updater 6.8.11 (exact pin; `lodash.isequal` deprecation accepted), constructed per
  platform: `NsisUpdater` (Windows), `AppImageUpdater` (Linux with `APPIMAGE` set), `AdhocMacUpdater extends
  BaseUpdater` (macOS). Never the `autoUpdater` getter, `MacUpdater`, `DebUpdater`, Squirrel.Mac or any listening port.
- **D-02 Source.** GitHub provider of `VictorMinemu/open-collaborative-ai-workspace`, set in code, HTTPS only. Stable
  releases only (`allowPrerelease = false`, `allowDowngrade = false`). Active only in release builds
  (`OCW_RELEASE_BUILD` define); a test feed only when unpackaged (e2e / dev).
- **D-03 Assets.** electron-builder gives every file its release name (`OCW-vX-macos-arm64.dmg|.zip`,
  `-windows-x64-setup.exe`, `-linux-x86_64.AppImage`, `-linux-amd64.deb`) and writes `app-update.yml` and
  `latest.yml`, `latest-mac.yml`, `latest-linux.yml` (`publish: github`, still `--publish never`). release.yml uploads
  them, the mac zip and the blockmaps without renaming; `SHA256SUMS` covers them; a manifest check gates every runner.
- **D-04 Integrity.** sha512 from the release manifest (electron-updater) plus, on macOS, `ditto` extraction,
  `codesign --verify --deep --strict`, bundle id `dev.ocw.desktop` and the expected version. `persist-credentials:
  false` on release jobs with write access. No Ed25519 now. ASVS 10.3.1 recorded as an accepted deviation until Phase 9
  signing. Turning on GitHub immutable releases is an owner action listed in the release notes.
- **D-05 macOS install.** Stage beside the installed bundle. A detached helper (Electron as Node, argv only, no shell
  strings) waits for the app and its daemon to exit, swaps by two renames with rollback, writes a path-free result and
  relaunches with `open`. No elevation. From a dmg, a translocated path or an unwritable folder: the fallback "Update
  available" link plus "Move OCW to Applications" (`app.moveToApplicationsFolder()`).
- **D-06 Linux `.deb`.** No auto-install. Today's notice, adding "or use the AppImage, which updates itself".
- **D-07 Idle gate.** New strict, local-only control commands `appUpdateHold { drain }` and `appUpdateRelease`, reusing
  ADR-0040's all-gates step (extracted, shared), with running 07.11 CLI jobs and a running self-update as blockers.
  Bounded at 30 min; auto-release after 2 min without a stop. The app quits for an update only after the daemon reports
  `held`; prompts held at the gate are re-queued after restart (ADR-0040 PD-27).
- **D-08 Levels.** The org ∩ device 07.11 level (`status.runtimeUpdates.effectiveLevel`; unknown counts as notify).
  `automatic`: background download, install on quit, and by itself when the daemon is idle and the person has been away
  ≥ 30 min (owner wants it automatic). `notify`: download, then "Restart to update" on a click. `off`: no automatic
  check. "Check for updates…" works at every level.
- **D-09 UI.** Tray, Runtime menu and onboarding window only (never the web app): check, progress, "Restart to update",
  "Waiting for N sessions…", the fallback link. electron-updater's logger off; fixed sentences; never a path.
- **D-10 Version.** The app version is the release tag (release.yml's existing `npm pkg set`). The repository keeps
  `0.1.0` as the dev value. The first updating release is installed by hand once (release notes).
- **D-11 ADR.** `docs/adr/0046-desktop-app-self-update.md` per the research outline; completes ADR-0032/0040's deferred
  desktop update without editing them; AGENTS.md gets one stack row.
- **D-12 Tests.** Offline only: a local fake release server fixture (no GitHub calls), unit tests for the controller,
  the mac updater and the swap helper (temp dirs), daemon tests for the hold, a CI manifest check. Real-release updates
  on a Mac, Windows and Ubuntu are owner UAT.
