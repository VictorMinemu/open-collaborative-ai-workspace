# Phase 07.1 Plan 06: Columns, card text edits and card search Summary

**Card authors can now edit a card's title, description and fields. Each edit goes through chat's `editMessage`, so the board, the root message, its history and search stay in step. A typed title is never replaced, even when two edits race. The generic message edit refuses card roots. The channel's owner and admins manage columns: categories, a default waiting state, order, limits, and safe deletion that moves the cards.**

## Plan-mode record (permission, audit and tenant paths; approval delegated per P-15)

| Route | Guard | Decision |
|---|---|---|
| `PATCH /boards/:id/cards/:messageId` (text) | `writableBoard`, then the card author | `channel.post` as before. Title, description or fields also require `authorKind = user` and `authorId = caller`, otherwise 403 `not_author`. That covers members, org admins, and every agent-authored card. Moves and the waiting state are unchanged (any poster). |
| `PATCH /messages/:id` | unchanged, plus one check | After the readable and author checks: if the message is the root of a card (`board_cards.message_id`), the route answers 400 `board_card_use_board`. Replies and other messages behave exactly as before. |
| `POST /boards/:id/columns` | `readableBoard` → `channel.update` → 410 → stream lock | 404 when the board is hidden or in another org; 403 for a plain member; 200 for the owner or an org admin. |
| `PATCH /boards/:id/columns/:columnId` | same | 404 `board_column_not_found` for a column on another board. |
| `DELETE /boards/:id/columns/:columnId` | same | Audited `board.column.deleted` with the count of moved cards. |

Audits:
- `board.card.updated`: `titleChanged`, `titleSource`, `descriptionChanged`, `fieldsChanged`, `waitingOnChanged`, `version`.
- `board.column.created`: column id, category and default waiting state.
- `board.column.updated`: `renamed`, from/to category, from/to default waiting state, `moved`.
- `board.column.deleted`: category, `movedCardsTo`, `movedCards`.

All carry `conversationId` and `boardVersion`. None carries a title, description, field value or column name, and the tests assert it.

## Deviations from Plan

1. **[Rule 3 – blocking] Column request contracts were missing.**
   - **Issue:** 07.1-01's cross-plan contract lists `CreateBoardColumnRequest`, `UpdateBoardColumnRequest` and `DeleteBoardColumnQuery`, but none of them exists in `packages/contracts/src/board.ts`.
   - **Fix:** I added all three with the documented shapes. `defaultWaitingOn` defaults to `null` ("Keep as is"). An update must change at least one thing. They have unit tests in `board.test.ts`.
   - **Conflicts:** no other wave-3 plan touches these files. Commit `271e340`.
2. **[Scope] Files outside `files_modified`.** None of these is touched by a parallel wave-3 plan.
   - `rank.ts` / `rank.test.ts`: new `keysAfter`, which appends cards to the bottom of a column in order.
   - `service.ts`: exports `columnsOf`, `toColumn` and `ColumnRow` for `columns.ts`.
   - `message-actions.ts`: `dtoOf` is exported so the board route can feed chat's edit observers.
3. **[Design] Edit observers via a callback.** `updateBoardCard` still returns `BoardCard`. It now takes an optional `onTextEdited(tx, { row, previousMentions, dir })` hook. The board route uses it to call `core.chatEvents.messageEdited` exactly as the generic edit does: only newly mentioned people are notified, never a bot. The agent path (07.1-10) passes no hook, since agents never edit text (P-03).
4. **[Ordering] Task 2's service logic shipped with Task 1.** The title rules and the 409 recovery are in the same `updateBoardCard` code path as the tracer, so Task 2's RED showed only the generic-edit guard failing. The title-rule and race cases were written test-first, but they passed against the Task 1 code.
5. **[Design] Delete with move, two choices:**
   - Tombstoned card rows are moved too, because `board_cards_column_fk` is RESTRICT. A column that holds only tombstones hands them to the first remaining column without needing `moveCardsTo`.
   - The target column's `defaultWaitingOn` applies to the moved cards (P-09: entering a column). They get `version + 1` and no per-card event; clients refetch on `board.updated` with dropped cards, as 07.1-04's `replaceColumns` already does.
6. **[Spec detail] Error code for a bad `moveCardsTo`.** When it names the column itself or another board's column, the answer is 400 `invalid_column`, the existing code for "column not on this board". The plan only said 400.

## Open items

- **Possible deadlock window (low):** a card text edit takes stream → card → root message. `DELETE /messages/:id` on the same root takes message → stream (through `appendEvent`). If both run at the same instant on the same card, PostgreSQL aborts one of them with a deadlock error, which surfaces as a 500. A fix would be for the delete route to take the stream lock first when the message is a card root. That is `message-actions.ts` DELETE plus the 07.1-05 replay context, so I left it for 07.1-14 or a follow-up.
- **07.1-11 (web):**
  - Column routes answer `BoardUpdatedEvent`.
  - Card `fields` in a PATCH are merged over the current values, so send only the changed keys; `null` clears a field.
  - Text edits by a non-author are 403 `not_author`. Hide the edit affordance unless `authorKind === "user" && authorId === me`.
- **07.1-14:** add the three column routes to the registry-driven cross-tenant guard. They already have an org-B case in `columns.int.test.ts`.
- **Superseded broken window:** 07.1-03's deviation `board_card_text_not_editable` is resolved. That code no longer exists.
