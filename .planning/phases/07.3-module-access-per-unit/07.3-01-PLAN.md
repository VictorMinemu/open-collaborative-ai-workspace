## Phase Goal

Admins and leads turn whole modules (Work Zone, AI chats, bots) on or off for a department, team or person from
Settings, expressed as resolver deny rules, so the UI hides what the API already refuses. No feature-flag system.

**This plan's slice (tracer, API level):** contracts first (two grains, the catalog and the module-access API schemas),
then one module turned off by an ordinary catalog deny rule is refused end to end (AI chats through the single
readable-set choke point), then the resolver proofs (deny beats admin, unit inheritance, agent ∩ human, the Bots
side effect, the lead ceiling), the team-bot dispatch fix, the Work Zone and Bots refusals, ADR-0024 and the PRD
paragraph. The module-access API is 07.3-02; the web hiding is 07.3-03; the Settings panel is 07.3-04.

<objective>
Contracts first: `ai_chat.read`, `unit.modules.manage`, the module catalog and the module-access request/response
schemas. Close the two enforcement gaps the research found (AI chat reads through `channel.read`; channel bot dispatch
ignoring `bot.read` for team bots). Prove with resolver and integration tests that a catalog deny makes the API refuse
every module, beats the admin role and is inherited down the unit tree. Record ADR-0024 and the PRD paragraph.

Purpose: ACCESS-01 (catalog), ACCESS-03 (API refusals, deny-beats-admin, unit inheritance); D-01, D-03, D-04, D-05.
Output: `module-access.ts` contract + tests, grains, resolver precondition + tests, `chat/access.ts` and `chat/index.ts`
fixes, `module-access-enforcement.int.test.ts`, reply-mode cases, ADR-0024, PRD §65 paragraph.
</objective>

    export function modulePatternOf(pattern: string): ModuleId | null;   // which module an exact pattern belongs to

    // API schemas (implemented unchanged by 07.3-02, rendered by 07.3-04)
    export const ModuleState = z.enum(["on", "off", "custom"]);
    export const ModuleScopeRef = z.object({ scopeUnitId: Id.nullable(), name: z.string() });   // null = organization
    export const ModuleInherited = ModuleScopeRef.extend({ state: z.enum(["off", "custom"]) });
    export const ModuleAccessQuery = z.object({ unitId: Id.optional() });                      // omitted = organization
    export const ModuleSubject = z.discriminatedUnion("kind", [
      z.object({ kind: z.literal("everyone") }),
      z.object({ kind: z.literal("user"), userId: Id }),
    ]);
    export const SetModuleAccessRequest = z.object({
      module: ModuleId, scopeUnitId: Id.nullable(), subject: ModuleSubject, enabled: z.boolean() });
    export const ModuleAccessModuleState = z.object({ module: ModuleId, state: ModuleState, inherited: ModuleInherited.nullable() });
    export const ModuleAccessPerson = z.object({
      userId: Id, displayName: z.string(), avatarUrl: z.string().nullable(),
      canEdit: z.boolean(),                                   // the resolver's decision (lead vs admin target), never a role check

    export const ModuleAccessView = z.object({
      scope: ModuleScopeRef,
      modules: z.array(ModuleAccessModuleState),             // everyone rows at this exact scope, catalog order

      overrides: z.array(z.object({ unitId: Id, name: z.string(), modules: z.array(ModuleAccessModuleState) })),

## Planner decisions (bind every 07.3 plan)

- **P-01 Split.** Four plans in three waves: 01 → (02 ‖ 03) → 04. The research's single web plan would touch about 20
  files; it is split into hiding (03, needs only this plan) and the Settings panel (04, needs the API).
- **P-02 Contracts first.** `packages/contracts/src/module-access.ts` holds the catalog and the module-access API schemas;
  07.3-02 implements them and 07.3-04 renders them, unchanged (a needed change is a recorded deviation).
- **P-03 Catalog.** Exactly the research catalog (A1, A2) in the interfaces block. Entry grains: `work_session.read`,
  `ai_chat.read`, `bot.read`.
- **P-04 Lead ceiling.** A resolver precondition on `unit.modules.manage` reading `ResourceFacts.targetRole`; reason
  `role_ceiling`; a lead never targets an admin, an admin targets anyone (D-05 (1)).
- **P-05 API.** `GET /api/v1/module-access?unitId=` and `PUT /api/v1/module-access`; exact-scope catalog deny rows only;
  idempotent; per-row `permission_rule.created/deleted` audit with `metadata.module` and `via: "module_access"`; one
  `permission_rules.updated` per request that changed rows (07.3-02).
- **P-06 State.** `on` (no catalog row at the exact scope and subject), `off` (all), `custom` (some); `inherited` = the
  nearest strict ancestor or the organization whose everyone rows (and, for a person, their user rows) are not `on`.
- **P-07 Panel placement.** A Modules card in its own component (`module-access-card.tsx`), mounted with one line in
  `unit-detail.tsx` (07.1 also adds a card there) for admins and leads via `viewerCan`; Settings › Modules
  (`/settings/modules`, `unit.modules.manage` at organization scope, so admins only) for organization-wide and
  per-person organization rows plus the list of unit overrides (07.3-04).
- **P-08 Web gating.** `useModule` / `ModuleGate` (skeleton while loading, off state when denied, children on a failed
  permissions fetch because the API stays the authority); entries (AI chats section, views row, bot DMs, `/bots` links)
  hide only when `useModule(id) === "off"`, never while loading or after a failed fetch; route gates in section layouts so section sidebars stay;
  bot DMs hidden in lists, a bot DM deep link shows the off state; "Add device" needs `device.pair`; the account
  "AI chat" entry needs `ai_chat.use` (07.3-03, 07.3-04).
- **P-09 Not built (research A5, accepted by D-05).** No grant cleanup, no interrupt of running Work Zone turns, no
  re-decision of queued AI prompts; proactive agent messages to a denied human belong to 07.6/07.7. Recorded in ADR-0024.
- **P-10 Docs.** ADR-0024 (reserved for 07.3 by the orchestrator) and one PRD §65 paragraph; AGENTS.md is trimmed to 190
  lines or fewer ("Built so far" moved to `docs/STATUS.md`, stack rows merged, no rule changed) and gains one Module
  access row at the 07.3-04 gate, so 07.1–07.7 keep room under the 200-line limit (orchestrator, 2026-10-09).
- **P-11 Executor rules.** Never touch the demo (ports 4000/3000, the `ocw` database, `~/.ocw*`), never read `.env` or
  `.env.demo`, no migration, no new dependency; e2e only through `scripts/e2e-isolated.sh`. Plan mode for permission
  changes (CLAUDE.md): write the intended diff as a plan in the SUMMARY notes, then proceed (owner delegated approval).
- **P-12 Siblings.** 07.1–07.7 run in parallel worktrees: the permission count is main's count + 2; the contracts index
