## Phase Goal

See `07.8-01-PLAN.md`. **This plan's slice (tracer):** an admin approves a pinned npm package and a bot's sandbox has it
the next time it starts — then review details and risk, then the native plugin refusal reason.

CLAUDE.md plan mode (P-17): write the approval model, audit metadata and install trigger as the first section of the
SUMMARY, then proceed.

<objective>
Build the API side of sandbox packages on ADR-0011's pinned-approval model: review through sandboxd, approve by review
token, switches, removal, per-bot installs at sandbox start, upstream-change refusal, risk verdicts, and the R12 reason for
native dangerous plugins.

Purpose: SBX-04 (refused capabilities become installable only as sandbox-confined packages; admin tools stay refused);
D-03, D-11 (F-3).
Output: `modules/sandbox/packages.ts` (+ tests), routes, the install trigger, risk additions, fake package ops.
</objective>
