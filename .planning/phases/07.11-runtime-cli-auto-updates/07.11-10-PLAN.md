## Phase Goal

See `07.11-01-PLAN.md`. **This plan's slice:** what people see (PD-15, no UI-SPEC): the owner's and admin's runtime
updates block in Settings › Devices with "Update now" and the history, the members' compatibility flags, the org policy
select, the new-session flag and the session's "Updating…" line, verified at 1440 and 390 in light and dark.

## Layout (PD-15; extends existing patterns, nothing new in kind)

- **Device card › DeviceFacts** (the `border-t` area under the card header, after the Full access fact), only when
  `device.runtimeMaintenance` is present: a fact block in the Full access fact's exact structure — icon tile (size-6,
  `RefreshCw`, muted; amber like Full access's warning tile when any runtime is `unsupported`/`broken` or the last run
  failed), title "Runtime updates" with a muted inline note on the right: "Organization: Automatic · This device:
  Notify only" (a `Lock` icon and "Set on the device" when the device level is lower), one sentence for the effective
  level ("Updates install when the agent is idle; turns are never cut." / "New versions are reported; install them with
  Update now." / "Updates are off."), then the runtime rows (`data-testid="runtime-update-row"`, `data-runtime`,
  `data-state`):
  - line 1: `RuntimeLogo` (size-4) · label (font-medium text-sm) · installed version (`font-mono text-xs
    text-muted-foreground`) · status pill (`Badge`: success "Up to date", brand "{latest} available", outline with
    `Spinner` "Updating…", outline "Waiting for an idle moment" (title attribute "since {relative time}"), destructive
    "Update failed", warning "Unsupported version", destructive "Can't run sessions", outline "Not checked");
  - line 2 (`text-xs text-muted-foreground`): "{Method label} · {location}" (e.g. "Native installer · ~/.local/bin");
    manual: "Installed with {method label}. Update it with the tool that installed it."; needs admin: "Needs admin on
    this machine:" followed by the existing `CopyLine` with the display command; updates disabled: "Updates are
    disabled on this machine (DISABLE_UPDATES).";
  - line 3 (`text-xs text-muted-foreground`): last run ("Updated 2.1.290 → 2.1.300 · automatically · 3 h ago" /
    "Update failed 10 min ago" / "Checked 5 min ago");
  - actions at the row's end on ≥ 768 and full-width under the text below 768: "Update now" (`Button size="sm"`,
    variant outline, `min-h-11 md:min-h-8`, `data-testid="runtime-update-now"`) when `viewerCan` has `device.maintain`
    and the runtime `canUpdate`; disabled with a reason in its `title` when the device is offline, the state is not
    `idle`, or a level is `off`; "History" (`Button size="sm" variant="ghost"`, same heights,
    `data-testid="runtime-update-history"`).
- **History sheet** (`Sheet`, right side ≥ 640, bottom below; title "{Device} · Runtime updates"; `data-testid=
  "runtime-update-history-sheet"`): a list of runs (`data-testid="runtime-update-run"`): `historyDate`, runtime logo
  and label, "2.1.290 → 2.1.300", trigger ("Automatic" / "By {name}" / "On the device"), outcome `Badge` (Succeeded ·
  Unchanged · Failed · Skipped: broken version · Refused · Expired · Requested · Running), the error text when
  refused, and a `<details>` "Output" with a `<pre>` (`max-h-48 overflow-auto font-mono text-xs`). Empty: "No updates
  yet." Loading: skeleton rows. Error: the existing `ServerUnreachable`.
- **Runtime chips (everyone)**: the existing chip gains a suffix after the version: `· older than supported`
  (`text-warning`) or `· can't run sessions` (`text-destructive`), `data-testid="runtime-compat-flag"`.
- **Work Zone policy page**: a new `Section` "Runtime updates" after the existing sections, before Save: a `Select`
  (`data-testid="policy-runtime-updates"`) with three items and one-line descriptions: Automatic — "Devices update
  Claude Code and Codex when the agent is idle. Turns are never cut."; Notify only — "Devices report new versions; the
  device owner or an admin presses Update now."; Off — "Devices don't check for new versions."; then a muted note
  "A device owner can lower this on the device (desktop app › Runtime updates, or `ocw-runtime updates`)."
- **New-session dialog**: on a runtime card, when `device.runtimeCompatibility[id]` is `unsupported`: subtitle "{version}
  is older than supported · ask {owner} to update" in `text-warning`; `broken`: the card is disabled and says
  "{version} can't run sessions · ask {owner} to update".
- **Session timeline**: `runtime.update` events render as the existing `system` item kind: waiting → "Updating {label}…
  your turn starts when it finishes"; done → "{label} updated to {version}"; failed → "{label} update failed · your
  turn runs on the installed version" (`data-testid="runtime-update-line"` on the rendered line).
