# Phase 07.8 Plan 13: the bot's browser and the egress proxy in sandboxd Summary

**sandboxd now runs each bot's browser in its own hardened `brw` container, reaches the outside only through the
namespace's `sandbox-egress` proxy it creates and governs, and streams live frames over HTTP. A 74-check real-Docker
smoke proves it end to end, including a real public-internet navigation through the proxy.**

## What was built

- **brw.** Built only from `brwSpec`: the hardened profile (10001, read-only root, `CapDrop ALL`, no new privileges,
  init, private IPC), `ShmSize` 512 MiB, tmpfs `/tmp`, no volume, no port, stdin kept open. Env: proxy, Chromium
  sandbox on, runtime. The seccomp profile (`OCW_SANDBOX_BRW_SECCOMP`) is sent inline. `brwSpec` refuses Chromium
  without its sandbox under runsc.
- **egress.** sandboxd creates `ocw-egress-<ns>` on `ocw-egress-out-<ns>` (the only non-internal network it makes)
  and attaches it to each bot network with the alias `sandbox-egress`. The policy file carries, per network: org,
  bot, kind, mode, allow hosts and private hosts. `botNetworks` lists every bot subnet of the namespace and
  `ownAddresses` every proxy address. A missing or killed org policy gives mode `off`. The file is written as root
  through exec, then HUP, then the reload line is awaited; with no bot network the file is removed. The proxy has no
  org or agent label, so no kill reaches it.
- **agent link.** Attached stdio, JSON lines in, agent frames out. Type-0 frames lose their context-id tag; stderr is
  dropped and never logged.
- **browser ops.** Every contract op, mapped to the agent's ops (`applied` → `accepted`, `hold` → `held`, resize sends
  `mode`, screenshot drops `maskRects`).
- **Agent events.** These become frame controls (size, navigated, focus, closed) and `browser` events (navigated,
  focus_sensitive, download, closed, crashed).
- **Frames.** One chunked response per viewer, headers flushed at once. The agent screencasts only while someone
  watches.
- **Idle and holds.** Idle 5 min, holds capped at 15 min after the last activity, own 30 s sweep timer (sweeper.ts
  unchanged).
- **Stops.** `killOrg` kills brw with sbx. A link that drops without a broker stop is reported as a crash.
- **D-14.**
  - `info().browserSandbox` reports the posture of a started browser.
  - A posture mismatch is refused.
  - `fatal` (no sandbox under runsc) means the browser did not start: 503, never a fallback.
  - sandboxd refuses to start inside a container carrying `ocw.sandbox` (own id from `/proc/self/mountinfo` or
    `/proc/self/cgroup`).
- **sbx.** `ensure` attaches the proxy to the shell network, and `purge` detaches it before removing the networks.

## Deviations from Plan

1. **[Rule 2 - Security] brw on its own per-bot network (`ocw-bnet-…`), not on the shell's network (P-03 said one
   network for sbx, brw and the proxy).** The proxy selects policy by the address a connection arrives on. With one
   shared network, sandboxEgress and browserEgress could not differ, yet the plan's own smoke needs browser `public`
   and shell `allowlist`. The split also keeps exec off the network of the browser that holds member cookies (smoke:
   A's brw cannot reach A's sbx).
2. **[Rule 1 - Bug] `infra/sandbox/browser/agent.mjs` (07's file).** For a plain-http URL, the proxy's 403 came back as
   a page, so `contextNavigate` reported success for a refused navigation. The agent now maps a 403/502 carrying
   `X-OCW-Egress` to `navigation_refused`. 07's browser smoke was rerun green.
3. **[Rule 3] Contract `SandboxdContextResize.mode` (optional, additive) plus a contract test.** Without it, `phone`
   (mobile emulation and touch) could not be told from a custom size. When it is absent, sandboxd infers `small` or
   `expanded` from their fixed sizes, else `custom`.
4. **[Rule 3] Files outside `files_modified`:**
   - `apps/sandboxd/src/main.ts`: env `OCW_SANDBOX_BRW_IMAGE`, `OCW_SANDBOX_EGRESS_IMAGE` and
     `OCW_SANDBOX_BRW_SECCOMP`, the wiring, and the D-14 self-label check.
   - `infra/sandbox/test/stack-smoke.mjs`: the Node driver for frame decoding and input frames, the same pattern as
     07.
5. **Routes.** The contract paths are used (`/v1/browsers/contexts/frames?orgId=&agentId=&contextId=`, POST
   `/v1/browsers/contexts/input`), not the plan text's `/v1/browser/contexts/:id/...`.
6. **Hold input.** The contract has `hold: boolean`, not `untilMs`, so a hold lasts 15 minutes, capped at 15 minutes
   after the last activity.
7. **Proxy output.** It is followed over the attached stdio, not the Engine logs endpoint (log driver `none`, nothing
   on disk).
8. **Not in the smoke:**
   - Idle and hold timing (5 and 15 minutes) is unit-tested with a fake clock.
   - runsc is not available on Docker Desktop.
9. **Pause recovery.** The weekly rate limit wiped `/tmp`, including the saved full driver. Task 2's steps were
   rebuilt from the version that had passed 74/74, and the full smoke passed 74/74 again before the Task 2 commit.

## Broken-windows candidates (not written to WINDOWS.md)

1. **No proxy env in `sbx`.** `sbx` has no `HTTP(S)_PROXY`, so curl, pip and npm in the shell ignore the proxy unless
   given `-x`. 04's `spec.test` pins `Env`, so this was left for a later plan.
2. **Contexts lost on restart.** A sandboxd restart forgets its context map. The agent's contexts live on, but answer
   `no_context` through sandboxd until the agent's own 5-minute idle closes them. The API must reopen.
3. **Silent proxy loss.** If the proxy container is removed or recreated, bot networks are re-attached only on each
   bot's next `ensure` or `browserEnsure`. Until then, that bot has no way out (fail closed, silent).
4. **Exceptions in `setOrgPolicy`.** A policy write to the proxy that fails makes `POST /v1/policy` answer 503 after
   sandboxd already stored the policy. The API retries, but the proxy can lag until the retry.
5. **Proxy header spoofing.** The proxy forwards an upstream `X-OCW-Egress` header. A site can therefore make its own
   http navigation look refused (self-only, harmless). Consider stripping it in `proxy.ts`.
6. **Unused browser policy fields.** The org `browserLimits.idleStopMs` and `diskQuotaBytes` are unused. Browser idle
   is the fixed D-12 5 minutes.
7. **API wiring still owed.** The API (07.8-14/16) must:
   - send resize `mode`;
   - read `browserSandbox` from `browserEnsure` or `info`;
   - handle the new `navigation_refused` for http refusals;
   - set `OCW_SANDBOX_BRW_IMAGE`, `OCW_SANDBOX_EGRESS_IMAGE` and `OCW_SANDBOX_BRW_SECCOMP` in compose, e2e and
     `.env.example` (plan 24).
8. **Not exercised on real Docker.** The gVisor path (`chromium+gvisor`, refusal under runsc) is unit-tested only,
   as is amd64 runc with `container-only`. Both are for plan 24.
