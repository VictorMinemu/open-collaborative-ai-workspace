## What changed

1. **Header regression (MUST).** `work-zone-title` failed at 390 because the title measured 196 px against a 188 px
   box. The 44 px rule makes a single row impossible: four 44 px controls would leave the title about 150 px. So below
   768 the header has two rows:
   - row 1: the crumb, then the controls;
   - row 2: the status dot and the `h1`.

   The chip keeps 10's rules: 32 × 32, icon-only on the default, icon + label otherwise, and a 44 px hit area. Its label
   truncates first when space runs out (the cluster may shrink, the crumb keeps 6 rem). From 768 up, nothing changed.
   One title element is rendered at a time, so `getByTestId("session-title")` stays strict.
2. **Sidebar and home.**
   - Contrast: the Settled badge (the "ended/failed glyph" in #327 and the dimmed badge in #316) and the active rows'
     branch line now use the full `text-muted-foreground`.
   - Touch: Settled rows, the Settled toggle and Show more are 44 px below 768.
   - The per-row "+" is hidden on coarse pointers (see decisions).
   - Home: in recent sessions the names truncate and the time keeps its words (`recent-session-time`).
   - Failed status chip: a deterministic Failed row in the spec exposed the home Failed chip at 3.83:1. It now uses the
     Badge destructive pill.
3. **44 px controls below 768.**
   - Header Queue / Changes / ⋯.
   - `SheetCloseButton`: the icon stays in place and the box grows to 44 px. Every sheet that keeps the default close
     gets it, and 10's two local closes now render the same component.
   - `MembersSection`: Add people (both), Remove (`size-11 md:size-8`), and the Lead switch's `::after` hit area, as on
     13's default switch.
4. **`not_in_project`.**
   - Contract: the value is appended to `WorkZoneStartBlock`.
   - API: `liveState` checks project access with the same `projectAccessDenial` that `createWorkSession` uses, so the
     card link and the review's `startBlocked` both carry it.
   - Web: `liveStartBlock` keeps it ahead of the live device state. The card and review read "{repo} belongs to a
     project you're not in. Ask one of its leads to add you." A failed Start says "{repo} belongs to a project you're
     not in."
   - Bot: its failed-reason sentence now names the cause instead of "it could not be carried out".
5. **e2e typecheck.** `e2e/tsconfig.json` extends the node config, adds the DOM libs and `allowImportingTsExtensions`
   (a spec imports `module-access.ts`). The root turbo task `//#typecheck:e2e` runs under `pnpm typecheck`, and
   `--force` works. It found 9 errors in 4 files, fixed without loosening any type:
   - `bot-activity`: `replyRow` takes `Page | Locator`, like the support version.
   - `ai-chat-share`: the upload body is a `Uint8Array`.
   - `agent-cards` and `notification-prefs` declared `Window.__notes` twice with different types. There is now one
     declaration in `support/window.d.ts`.
6. **Screenshot hygiene.** The runner reads the spec names from `playwright test`'s command line, and `shot()` writes
   only when `test.info().file` matches one exactly. So `work-zone-visibility` no longer rewrites the 09 marker
   captures, and the setup project writes nothing into a phase folder. Proven: the runs here produced no `setup-*.png`.
