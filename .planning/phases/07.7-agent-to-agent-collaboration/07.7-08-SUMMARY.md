# Phase 07.7 Plan 08: Consult settings in the web app Summary

**Admins turn "Bots may consult each other" on in Settings › Bot policy (off by default) and set each team or unit
bot's consult rules in its sheet: Can ask (organization default, any bot, only these bots, no bot), Never ask, and
"Other bots can ask {Bot}". Every change is one full PUT, and the API's "Right now" line confirms it.**

## Performance

- **Duration:** ~45 min (11:00–11:45)
- **Tasks:** 3 (1 tracer, 2 auto), all TDD
- **Files:** 5 created, 2 modified (plus 12 screenshots)

## Accomplishments

- `agent-messaging-queries.ts`: four hooks on 07.7-03's routes. Responses are parsed with the contract schemas. A switch
  change invalidates every cached bot view (`orgDefault` and Right now follow it). A bot change replaces that bot's view
  and invalidates the others (their Right now depends on this bot's inbound switch). An error refetches the server state.
- `AgentConsultSettings`: a bordered `<label>` row with a top-aligned `Switch`. While pending, a 14 px spinner shows and
  the switch is disabled. It shows the target state while pending and falls back to the server state on error. On/off
  toasts use the copy table. Without `canManage`, the switch is disabled and the helper ends with "Only admins can
  change this." It renders nothing without `rule.read`. It is mounted between `<BotPolicySettings />` and
  `<PersonalBotsTable />`.
- `AgentMessagingSection` (bot sheet, right after "Capabilities", team and unit bots only, viewers with `rule.read`
  only):
  - The Right now line (`aria-live="polite"`, `Waypoints`) and the people note.
  - "Can ask" uses `FormField` + `Select`. "Only these bots" is disabled while the switch is on, and the reason line is
    linked by `aria-describedby`.
  - Two chip lists (`<ul aria-label>`, remove buttons named `Remove @handle`, `max-md:size-11`) with "Add a bot…"
    pickers. The pickers list team and unit bots other than this bot and not already listed.
  - An inbound switch row.
  - Loading shows three `Skeleton` rows. A load error shows "Couldn't load consult settings." with Try again.
    `invalid_agent_messaging` maps to the copy-table toast. Read-only disables every control and hides the Add
    pickers.
- `effectiveSentence` / `modeOptions` are exported pure helpers. The web test pins every copy variant.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The org switch was named by the whole row**
- **Found during:** Task 1 (tracer e2e)
- **Issue:** Base UI's `Switch` inside a wrapping `<label>` sets `aria-labelledby` to the whole label. The accessible
  name therefore included the helper.
- **Fix:** `aria-labelledby` points at the label text span, and the helper stays in `aria-describedby`. The inbound
  switch does the same. The `<label>` stays as the hit area, at least 44 px.
- **Commit:** `a0579d09`, `e564236f`

**2. [Rule 2 - Correctness] "Only these bots" with no bot, and removing the last bot**
- **Issue:** `SetAgentMessagingRequest` refuses mode `only` with an empty allow list.
- **Fix:** Choosing "Only these bots" is a local draft that shows "Pick at least one bot." and saves nothing. The first
  added bot sends the PUT. In mode only, the last chip's remove button is disabled. This adds no copy; the admin changes
  "Can ask" instead. The e2e asserts both.
- **Commit:** `e564236f`

**3. [Test] A third bot in the "only" screenshot**
- The API reports `effective.kind: "any"` when an allow list happens to cover every other bot of the organization (07.7-03:
  any = every candidate is allowed). The screenshot case therefore adds a "Dora" outside the list, so the line names the
  two chips.

**4. [Test] Placement assertion raced the policy form's skeleton**
- The placement check now waits for both neighbours (`bot-policy-settings`, `personal-bots-table`) before reading the
  order. This flaked once in the combined run and was fixed before the final runs.

**5. [Test] Captures cropped the app shell**
- `scrollIntoView` also scrolls overflow-hidden ancestors, which cropped the 1440 settings capture. The spec's
  `frame()` now moves only the nearest scroll area and resets the ancestors.
