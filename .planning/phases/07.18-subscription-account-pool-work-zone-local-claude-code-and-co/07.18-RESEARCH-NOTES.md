# Phase 07.18 research notes (2026-11-24)

Summarised from three research passes. Anything marked "unverified" must be proven by a test or the owner's UAT.

## Claude Code / Agent SDK

- **Auth precedence:** cloud provider > `ANTHROPIC_AUTH_TOKEN` > `ANTHROPIC_API_KEY` > `apiKeyHelper` >
  `CLAUDE_CODE_OAUTH_TOKEN` > profiles > `/login` credential. Strip the first three when passing a pool token.
  https://code.claude.com/docs/en/authentication
- **`claude setup-token`:** a one-year OAuth token, not saved anywhere, model requests only, needs a Pro, Max, Ultra,
  Team or Enterprise plan. No documented refresh. Usage reads need a "profile" scope this token probably lacks.
- **`CLAUDE_CONFIG_DIR`:** each directory has its own login, settings and history.
- **`Options.env`:** replaces the subprocess env for each `query()`.
  https://code.claude.com/docs/en/agent-sdk/typescript
- **Limit signals:**
  - `SDKRateLimitEvent` (`type: 'rate_limit_event'`, `status: 'allowed' | 'allowed_warning' | 'rejected'`,
    `resetsAt?`, `rateLimitType` `five_hour | seven_day | seven_day_opus …`, `utilization`).
  - `SDKAssistantMessage.error` is `'rate_limit' | 'billing_error'`.
  - The text "You've hit your session limit · resets 3:45pm". The SDK exports `USAGE_LIMIT_ERROR_PREFIXES`, marked
    @alpha. https://code.claude.com/docs/en/errors
- **Resume:** transcripts live under `$CLAUDE_CONFIG_DIR/projects/`. Resuming under another token with the same config
  dir is unverified but plausible. Caches are per organization, so a switch is a full cache miss.
- **Tools:**
  - CLIProxyAPI is a proxy that imitates the official client.
  - better-ccflare is a proxy with session-sticky routing. It removed round-robin and weighted routing because they "can
    trigger Claude's anti-abuse systems". https://github.com/tombii/better-ccflare/blob/main/docs/load-balancing.md

## Codex

- **Auth per process:** `CODEX_HOME/auth.json`, refreshed by Codex. Refresh tokens rotate (`refresh_token_reused`).
  "Do not share the same file across concurrent jobs or multiple machines."
  https://learn.chatgpt.com/docs/auth/ci-cd-auth
- **app-server v2 account methods:** `account/login/start` takes `chatgpt`, `chatgptDeviceCode`, `apiKey` or
  `chatgptAuthTokens`; the last one is marked "OPENAI INTERNAL USE ONLY". Also `account/read`, `account/logout`,
  `account/updated`, `account/rateLimits/read` and `account/rateLimits/updated` (`primary` / `secondary`:
  `usedPercent`, `windowDurationMins`, `resetsAt`). The comment says clients "must not infer recovery from
  percentages". https://github.com/openai/codex/blob/main/codex-rs/app-server-protocol/src/protocol/v2/account.rs
- **Limit signals:** HTTP 429 `usage_limit_reached` with `resets_at`; in v2 it is `codexErrorInfo:
  "usageLimitExceeded"`.
- **Resume:** OpenAI's documented approach is to restart app-server with the new token, then call `thread/resume`.
  Rollouts live under each `CODEX_HOME`, so they must be shared between slots. Encrypted reasoning tied to an account is
  unverified.
- **Tools:** codex2api (`round_robin | remaining_quota | fill_first`), codex-lb (sticky threads), CLIProxyAPI
  (`round-robin | weighted-round-robin | fill-first`, session-affinity, cooldown).

## OpenClaw 2026.9.7 (pinned image docs)

- **Profiles:** several per provider, created with `openclaw models auth login --provider openai --profile-id <id>`.
- **Order:** `models auth order set` / gateway `models.authOrderSet` > `auth.order.<provider>` > stored. With no order
  set, OpenClaw goes round-robin by least recently used and puts accounts in cooldown last. There is no weighted mode.
- **Session stickiness:** a session keeps its profile. It changes on cooldown, `/new` or `/reset`.
- **On a rate limit:** OpenClaw tries the provider's other profiles first, then the fallback models. Cooldown is 30 s →
  1 min → 5 min max, following `Retry-After`.
- **Credentials:** SecretRef covers API keys and static tokens only, not ChatGPT OAuth. OpenClaw refreshes OAuth itself,
  so tokens stay in the cell (ADR-0006).
- **Our code today:**
  - One sign-in per provider into the shared `main` agent store.
  - `accountFromStore` reports the first usable profile; `logout` removes all of them.
  - `model_providers` has one row per org and provider.
  - `render-config.mjs` sets no `auth.order`.

## Terms (verbatim, for the record; the owner decided to proceed)

  - "Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route
    requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users."
  - "Advertised usage limits for Pro, Max, and Ultra plans assume ordinary, individual usage of Claude Code and the
    Agent SDK."
- Anthropic consumer terms: "You may not share your Account login information … or Account credentials with anyone
  else."
- OpenAI Terms of Use: "You may not share your account credentials or make your account available to anyone else" and
  "circumvent any rate limits or restrictions".
- OpenAI Services Agreement: "Customer will not share Account access credentials or individual login credentials
  between multiple users" and "(i) violate or circumvent Usage Limits".
