# Phase 07.17.1 Plan 03: Served lockfile, shared dist store and served build Summary

**`GET /api/v1/runtime/npm-shrinkwrap.json` serves the verified lockfile bytes from the device module's single
`RuntimeDistStore`; the lockfile/package.json checks live once in `runtimeExternalFiles` (contracts) with install.sh
pinned byte-identical; `DeviceHub.servedRuntime()` returns `{ version, build }` (12 hex) from the same store.**

## Accomplishments

- New public route `RUNTIME_ROUTES.externalLock` (`/api/v1/runtime/npm-shrinkwrap.json`). It uses the same `route` config
  as the other distribution routes (`authz: "public"`, 30 per minute), returns 404 `runtime_unavailable` / 503
  `runtime_corrupt` through `need()`, sends `content-type: application/json; charset=utf-8`, `cache-control: no-cache`
  and `x-content-sha256 = externalLockSha256`, and its body is `RuntimeDist.externalLockBytes`, the exact bytes `load()`
  hashed. It reads no query or path input.
- `registerRuntimeDistRoutes(app, core, store)` no longer constructs a store. `createDeviceModule` builds the only
  `new RuntimeDistStore(...)` in the API (grep count 1) and passes it to the routes and to `DeviceHub` as `runtimeDist`.
- `runtimeExternalFiles(m, lockText)` in `@ocw/contracts` checks lockfile v3, root `ocw-runtime-deps` and exact pins,
  and returns `{ lock: lockText, packageJson }` with the trailing newline. It does no hashing and imports no Node
  built-in. `install-script.ts` keeps the sha256 and heredoc-marker checks and the newline strip, and calls the helper
  for everything else. The golden sha256 `368c823c…72fd` was captured from the pre-refactor renderer and still matches.
- `RuntimeDistStore.served()` and `DeviceHub.servedRuntime()` return `{ version, build: sha256.slice(0, 12) }`, or null
  when the dist is missing or corrupt or no store was given. After a verified read the result is cached, so nothing is
  read from disk again.
- `writeRuntimeDist(dir, opts)` test helper (defaults: version 0.3.1, a tiny bundle, the two-pin lockfile).
