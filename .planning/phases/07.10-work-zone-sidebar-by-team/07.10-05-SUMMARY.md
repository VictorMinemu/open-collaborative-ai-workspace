# Phase 07.10 Plan 05: The sidebar's "+" actions, onboarding and projects-request states Summary

The Work Zone sidebar's "+" buttons now do what a chat user expects. A department's "+" creates a team project there,
preselected on the unit the viewer may create in. A project's "+" (pointer only) and a repository's "+" start a session
on that project's or repository's repository. A person with no team project reads one quiet line on how to share
sessions with their team, and a failing projects request shows its error with Try again without hiding any session.

## What the sidebar does now

- **Section "+" (D-07, R3, R6, § 2):** `section-create`, "New project in {unit}" (aria-label and tooltip), 24 px in the
  header's action slot; with a pointer it shows on the header's hover or keyboard focus, on touch it is always visible
  and 44 × 44. It shows only where `GET /work-projects/parents` (fetched only when `viewerCan.create`) has a parent whose
  `topId` is the section. It opens the shell's one `NewProjectDialog` with the department itself preselected when the
  viewer may create there, else the first unit inside it in the API's order; a `defaultParentId` the viewer may not use
  is ignored (`chosenParent`). The new project's row appears in the section after the dialog's existing navigation.
- **Project "+" (R5, § 5, U-8):** `project-new-session`, "New session in {project}", a button beside the link (never
  inside it), absolutely placed in the live count's slot with the same right edge. With a pointer it shows on the row's
  hover or keyboard focus and the count turns `invisible` (no width change; a 24 px slot is reserved when there is no
  count, so the "+" never covers the name or the pill). Not rendered on coarse pointers (`pointer-coarse:hidden`). It
  opens the new-session dialog with `{ teamProjectId }`: that project's first online repository the viewer can start
  on, else its first (`preselectedRepo`).
- **Repository "+" (§ 7):** `repo-new-session`, "New session in {repo}", hover-revealed with a pointer, visible and
  44 × 44 on touch; it opens the dialog on that repository. None on a repository linked to a project the viewer can't
  open (D-14: no start is possible there).
- **Where a row "+" shows:** only where the viewer has a repository to start on, read from the new-session dialog's own
  `GET /projects` (the shell's dialog already requests it on every Work Zone page; no new request, D-09). A member who
  can't use the project's devices gets no "+", as the project page gives them no New session (07.9 D-13).
- **Header "+":** unchanged; `openNewSession()` with no target keeps today's default. Every existing caller of
  `openNewSession` passes a repository id or nothing and keeps working.
- **Onboarding (D-08, § 9):** in place of the department sections while the viewer belongs to no team project:
  "Share sessions with your team →" + the link button "Create project" (opens New project) for someone who may create,
  "Team projects you're added to appear here." for anyone else. One line of 12 px muted text, no card, border or icon;
  it goes away once a project exists.
- **Projects request (UI-SPEC States):** while it loads, one header bar (`h-4 w-24`) and three rows (`h-8`, 72/56/64 %);
  when it fails with no data, "Couldn't load projects." with Try again (refetch, disabled while fetching), then the
  active sessions (and the open one) not already under Personal grouped by `rowProject` under a plain label, as
  `SessionSubRow`s. Data already loaded keeps drawing the sections if a later refetch fails.

## Deviations from Plan

1. **[Rule 3 - Blocking] Tooling.** The harness blocks Edit/Write in the dedicated worktree, as for 01-03: files were
   edited in `/tmp/ocw0710-05` and copied in. The content is what an edit would produce.
2. **[Rule 1 - Bug] A project "+" where the viewer cannot start.** Found by the final e2e (`work-zone-projects`: Pia is in
   Customer portal but can't use its devices). The "+" would have opened the dialog on another project's repository.
   The project and repository "+" now show only where the viewer's `GET /projects` lists a usable repository of that
   project (`startableTargets`, fail closed while loading). Commit `b2758c88`.
3. **[Rule 1 - Test id collision] `project-new-session`.** The UI-SPEC gives the sidebar's project "+" the test id the
   07.9 project page's New session already uses. As 03 did for `project-row-<id>`, the four page-level locators in
   `work-zone-projects.spec.ts` are scoped to `project-page` (moved, none deleted); Pia's page-wide "no New session"
   check is kept as well and now also proves the sidebar "+" is absent for her.
4. **Spec races fixed (no product change), each seen once in a run of the final tree:** the hover capture now waits
   for both "+" before pressing Tab (the section "+" arrives with the parents request, after the index); the
   new-session dialog is closed with Cancel instead of an early Escape that the mobile drawer could receive; the live
   session is marked `running` only after the fake device has settled it to `idle` (otherwise the device's own answer
   could overwrite it, the 03 marker spec's pattern).
5. **Extra test ids:** `projects-loading`, `projects-error`, `projects-retry`, `fallback-group` (not in the UI-SPEC list).
6. **Plan files list:** `sidebar/use-creatable-units.test.ts` (new) holds the hook's pure cases;
