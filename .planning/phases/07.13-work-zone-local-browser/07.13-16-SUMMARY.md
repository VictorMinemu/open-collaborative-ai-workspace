# Phase 07.13 Plan 16: Browser tab in the web session view Summary

The session view now has a Browser tab next to Queue and Changes. People who can see the session watch the page its agent drives on the device, live. They get the bots' state chip, host chip and placeholders, in agent-neutral words. The tab shows only while `session.browser.status === "available"`. Closing it closes the socket, so the device stops streaming.

## What was built

- **Task 1 (tracer, TDD): watch the device's page live.**
  - `workLiveSocketUrl` builds `ws(s)://<api>/api/v1/live/work-browser/<id>` from `workLivePath`.
  - `createWorkLive` opens one socket per panel through the bots' `connectLive` (`options.url`). Auth, reconnect, silence checks and final close codes are the bots'. The JWT goes as a subprotocol, never in the URL (T-07.13-16-01).
  - State is kept in the `LiveView` shape: `contextId` and `bot.id` are the session id, `bot.name` is the runtime label.
  - Only the latest frame is held. It is dropped whenever the state stops showing the page (T-07.13-16-02/03).
  - `stop()` closes the socket with 1000. `useWorkLive` wraps the controller with `useSyncExternalStore`. The panel is keyed by session id.
  - `session-view.tsx`: `PanelTab` gained `"browser"` (Globe icon) and the tabs come from `panelTabsOf(session.browser)`.
    - On ≥1280 px it opens as a side panel, below that as the sheet.
    - The side panel and the sheet share one `PanelBody`.
- **Task 2 (TDD): every state, in Work Zone words.**

  | State | What the panel shows |
  |---|---|
  | Connecting | "Connecting…" |
  | Idle | "Nothing to show yet: the agent has not opened a page" |
  | Live | Frame, host chip, "Not secure" for http, activity line ("{agent} is {activity}" or "{agent}'s browser on {device}") |
  | Reconnecting | Last frame dimmed, "Connection lost. Reconnecting…" |
  | Private, takeover | "Private sign-in in progress", with the bots' body |
  | Private, member sign-in | "Private browsing for {member}" and "Only {member} can watch while the agent uses their sign-in." |
  | Ended | One sentence per reason, never naming a bot ("The browser closed after 10 minutes without use.") |
  | No permission (also after access is lost) | "You can't watch this browser" |
  | Error | Try again |

  - The frame is `<figure aria-label="Live view of the session's browser">`. The state chip is `role="status"`.
  - Private, ended and no_permission states render no `<img>` and no host.
- **Task 3: phone, desktop, dark mode, accessibility.**
  - The panel's header row is 44 px below 768, and Try again is 44 px.
  - The frame keeps the 8/5 ratio (960×600) and scales to the panel's width. It uses theme tokens only.
  - Below 768, Browser opens from the session menu.

## Deviations from Plan

1. **[Rule 1 - Bug avoided] The bots' `LiveFrame` and a `WorkLiveContext` adapter are not used.**
   - **Why:** `LiveFrame` reads `useOptionalLiveView()`. `LiveContext` is not exported, and the app shell's `LiveViewProvider` wraps the session view. A `LiveFrame` here would draw whatever bot browser that provider has open, which is a cross-view leak. An adapter cannot provide that context without editing `components/browser/*`, which the acceptance criteria forbid.
   - **What instead:** `work-live-panel.tsx` has a small `WorkLiveFrame` that copies the blob-URL drawing (latest wins, revoked after paint). It reuses only the prop-only pieces: `StateChip`, `HostChip`, `FramePlaceholder`, `placeholderOf` (private takeover and error bodies) and `activityWordsOf` (paused and controlling).
   - The artifact's `contains: "LiveFrame"` is met by `WorkLiveFrame`.
2. **[Rule 2 - Missing feature] The ended → new page reconnect.**
   - **Why:** the server closes the socket with 1000 after `ended`, so without this a later page would never show.
   - **What:** the panel retries when `session.browser.live` goes false → true after an end.
3. **[UX] Below 768, Browser is in the ⋯ menu, not the header.** Explained under Decisions. The sheet's tab row still lists Browser.
4. **[Interpretation] "Reused full sheet" means the session view's own sheet.** It is full width at 390, with 48 px tabs and the 44 px sheet close. The bots' `LiveFullSheet` reads the same bot live context as above.
5. **[Interpretation] Activity line.** The Work Zone server sends `activity: null` today. The live line reads "{agent}'s browser on {device}" rather than the bots' "{bot} isn't doing anything right now.", which would be wrong while the agent works. A masked activity, when one arrives, reads "{agent} is {activity}".
