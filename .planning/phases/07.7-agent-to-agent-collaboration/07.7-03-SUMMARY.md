# Phase 07.7 Plan 03: agent.message decisions and the admin consult rules Summary

**Agent-to-agent consults are closed until an admin turns on one audited `everyone` allow rule; per-bot rules
(`any` / `only` / `none`, never ask, inbound off) are ordinary `agent.message` rows on the `tool` column. The resolver
now also judges target visibility for the human the bot acts for (unit personas, personal bots).**

## Accomplishments

- `GET/PUT /api/v1/agent-messaging`: on means exactly one organization-scope `{everyone, allow, agent.message, tool
  null}` row, and off means none (a hand-written duplicate goes too). Writes go through 07.3's `insertRuleRow` /
  `deleteRuleRow` with `via: agent_messaging`, plus one `permission_rules.updated`. `canManage` is the resolver's
  `rule.manage`.

  bot's own rows: per-row audit with `{via, agentId}` and one event. The view returns mode, lists, inbound,
  `orgDefault`, `canManage` and a "Right now" summary computed by the resolver's agent pass.

## Working notes (P-19, plan mode for permission and audit changes)

Intended diff, applied as written:

- **Resolver:** no change to `resolve.ts`. In `policy.ts`, `agent.message` joins the personal-bot precondition and the
  `unit_agent` precondition. No existing test was loosened.
- **Org switch rows:** on = insert `{scope null, everyone, null, agent.message, tool null, allow}` if no such row
  exists. Off = delete every such row (folder null).
- **Per-bot rows:** a bot's own rows are organization-scope `agent.message` rows without a folder whose subject is the
  bot, plus `everyone` rows with tool `agent:<bot>`. The wanted set:
  - `any` → `{agent, null, allow}`
  - `only` → `{agent, agent:<B>, allow}` per B
  - `none` → `{agent, null, deny}`
  - never ask → `{agent, agent:<B>, deny}` per B
  - inbound off → `{everyone, agent:<bot>, deny}`

  The PUT diffs on (subjectKind, subjectId, tool, effect). It never touches unit-scoped rows, other bots' rows, the
  switch, 07.3 module rows or 07.7-02's authorless backfill rows.
- **Who:** `rule.read` / `rule.manage` preHandlers (admin surface). Leads and standard members get 403 before any lookup.
