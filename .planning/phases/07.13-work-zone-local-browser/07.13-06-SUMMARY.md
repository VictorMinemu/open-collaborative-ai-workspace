# Phase 07.13 Plan 06: Chromium installer, device opt-in, doctor Summary

**The device fetches (or copies from a local zip) exactly the pinned Chrome for Testing 156.0.8078.47 headless shell, verified by sha256 and size while it streams, installs it atomically under `~/.ocw/browsers/156.0.8078.47/` with one install at a time, lets its owner switch the browser on or off locally (default off), and doctor names in one line what keeps it from starting.**

## Performance

- **Tasks:** 3 (1 tracer, 2 auto), all TDD
- **Files:** 4 created, 6 modified (1811 insertions)

## Accomplishments

- `pins.ts`: the five-platform pin table from RESEARCH; a test reads `infra/sandbox/browser/Dockerfile` and asserts the linux64 and linux-arm64 `--checksum` + URL pairs equal the pins, so the brw image and the runtime cannot drift.
- `install.ts` `installBrowser({ root, platform, fromZip?, fetchImpl?, onProgress?, pins? })`: refuses a tampered zip (`checksum_mismatch`), a zip-slip archive with a matching hash (`download_failed`), a 404 or network error (`download_failed`), a short or long body (`checksum_mismatch`); in every refusal no `<root>/<version>`, no `.staging-*` and no lock is left. An existing valid marker short-circuits; two concurrent calls fetch once; a waiting install picks up another process's result; a stale lock is taken over and crashed staging dirs are swept. macOS quarantine is stripped with `xattr -dr` (A-9), failures ignored. Error messages never hold a path.
- `config.ts`: `browser { optIn, sandbox }` with PD-18's `container` as the only other sandbox value (schema refuses anything else); `OCW_ALLOW_BROWSER` and `OCW_BROWSER_SANDBOX` win.
- `cli.ts`: `browser on|off` writes runtime.json (0600, other keys kept) and sends the strict value-less `reloadConfig`; `status` prints `Browser: on|off (<source>) · installed <version>|not installed`; `install [--from-zip <zip>]` shows progress on stderr and prints the home-relative executable path; bad usage exits 2.
- `doctor.ts` `browser` check: off -> ok + `ocw-runtime browser on`; on, not installed -> warn "installs on first use" + `ocw-runtime browser install`; missing libraries -> fail + `sudo apt-get install -y …` built from ldd's sonames; Ubuntu AppArmor userns restriction -> fail + the profile line; `container` outside a container -> fail; inside -> warn "Chromium sandbox off inside this container"; else ok with the version. The output holds no absolute home path (tested); `/etc/apparmor.d/ocw-chrome-headless-shell` is added to the doctor's public paths so `safeLine` keeps it.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] The AppArmor profile path would have been hidden by the doctor's own redaction**
- **Found during:** Task 3
- **Issue:** `safeLine` replaces every absolute path outside the home with `<outside home>`, which would have turned the fix line's `/etc/apparmor.d/...` into something nobody can run.
- **Fix:** `APPARMOR_PROFILE_PATH` joins `PUBLIC_ABSOLUTE_PATHS` (a fixed system path that says nothing about the host); the executable is written as `@{HOME}/…` so no home path is printed.
- **Files modified:** apps/local-runtime/src/doctor.ts
- **Commit:** 1010e6f4

**2. [Rule 2 - Correctness] An installed AppArmor profile would still have failed the doctor**
- **Found during:** Task 3
- **Issue:** the sysctl stays `1` after the owner installs the profile, so a check on the sysctl alone never turns green.
- **Fix:** `appArmorFixLine` also reads the profile file and returns null when it already names this executable.
- **Commit:** 1010e6f4

### Other notes

- `appArmorFixLine(exe, read?, home?)` takes an extra `home` parameter (the plan names `(exe, readFile?)`) so the attach path can be made home-relative and tested.
- `parseOsRelease` is exported besides `readOsRelease` (testable parsing).
- The `doctor` ok line for "off" carries a fix line (the plan asks for it); the `DoctorCheck.fix` doc comment now reads "null when there is nothing to do".
- Task 2's tests were written before the code but not run red before implementing; Tasks 1 and 3 were run red first.
- Debian 13 t64 names are an assumption (A-6 measured bookworm, 22.04 and 24.04 only).
