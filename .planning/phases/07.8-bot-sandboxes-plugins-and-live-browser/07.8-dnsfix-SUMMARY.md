# Phase 07.8 gap: gVisor egress DNS and the red fake test, Summary

**Bots on gVisor installs now reach the internet through the egress proxy. sandboxd writes the proxy's address on
each bot network into every sandbox's `/etc/hosts` (`ExtraHosts sandbox-egress:<ip>`). On the CI dind, the
gvisor-browser smoke passes with 37 checks and 0 failures, and its `failure: ignore` is removed. The red fake-sandboxd
test now pushes a policy first, and the fake's policy gate is unchanged.**

## Root cause (confirmed)

- **Cause:** runsc does not answer Docker's embedded DNS (127.0.0.11) on the internal bot networks.
- **Effect:** `HTTP(S)_PROXY=http://sandbox-egress:3128` and Chromium's `proxy.server` could not resolve the proxy.
  Every gVisor sandbox failed closed with `EAI_AGAIN` (07.8-24 probe).
- **Proof of the fix:** the same nested runsc daemon now passes every navigation and shell request through the proxy
  by name.

## What changed

- **`spec.ts`**
  - `egressHosts(address)` returns `["sandbox-egress:<ip>"]`, or `[]` without a proxy. It accepts only an IPv4
    address, so no host name, second entry or newline can reach `ExtraHosts`.
  - `egressHostsCurrent(extraHosts, address)` compares exactly. Docker's `null` counts as empty.
  - The `shellSpec`, `brwSpec`, `installerSpec` and `reviewSpec` builders take `egressAddress`. The files helper and a
    removal run (network `none`) get no entry.
- **`egress-attach.ts`:** `attach()` returns the proxy's address on that network as Docker reports it, after the
  usual label check and policy write. It reads the address again after a proxy restart (re-sync).
- **`sandboxes.ts`**
  - `ensure` passes the address to the shell it creates. A stopped shell whose entry is stale or missing is removed
    with `DELETE ?force=1` and no `v=1`, then created again. Its workspace and packages volumes stay.
  - `restart` with a stale entry recreates the shell instead of a Docker restart, because a Docker restart would keep
    the old entry.
- **`browser.ts`:** the same rule for a stopped `brw`, which keeps nothing outside its tmpfs.
- **`packages.ts`:** every networked review or installer run gets its run network's proxy address. These are fresh
  containers, so they cannot be stale.
- **Behaviour on proxy restarts (documented in INSTALL.md):**
  - Docker gives a restarted container a new address, and may reuse the old one elsewhere (checked locally).
  - Stopped sandboxes pick up the new address at their next start. A running sandbox keeps its entry until its next
    start or restart.
  - A stale entry points at nothing or at the bot's own container, so it fails closed.
- **Unchanged:**
  - The proxy, its policy refusals (`proxy_self`, `bot_network`, `attached_network`, `platform_host` for the name),
    label ownership checks and the proxy env.
  - sandboxd still acts only on its own labelled objects.
- **CI:** `gvisor-browser` in `.woodpecker/sandbox.yaml` no longer has `failure: ignore`. The GitHub mirror has no
  gVisor job (it runs only the runc smokes), so nothing changed there.
- **Fake test:** `server.test.mjs` asserts `409 policy_missing` before the push. It then pushes the same policy as
  `e2e/support/sandbox.ts` `seedPolicy`, and runs ensure and exec.

## Broken-window candidates (not written to the ledger)

1. **(LOW) A running sandbox keeps a stale entry after a proxy restart.**
   - **Before:** under runc, Docker DNS followed the proxy's new address.
   - **Now:** a running sandbox keeps the old entry until its next start or restart. It fails closed.
   - **Possible follow-up:** when the proxy is restarted, the egress module could ask for stale running sandboxes to
     be recreated.
2. **Unrun verification:** there is no pushed Woodpecker run of `sandbox.yaml` with gvisor-browser required. Record it
   on the first push.
3. `run-packages-smoke.sh` does not print the runtime it ran under. Under the gVisor daemon it is runsc by inference
   (`auto` with runsc registered).
4. Running the gVisor smokes by hand on the dind leaves build cache behind (27 entries this time). `disk-budget.sh`
   bounds it.
