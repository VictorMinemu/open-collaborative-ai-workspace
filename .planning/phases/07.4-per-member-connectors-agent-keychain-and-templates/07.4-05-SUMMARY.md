# Phase 07.4 Plan 05: Connector OAuth client and MCP tool client Summary

**The API now has its own OAuth 2.1 client for MCP servers, written to the spec, and an MCP tool client. Both send
every request through the egress guard.** The OAuth client covers RFC 9728 → RFC 8414 discovery, the S256 presence
check, https-or-same-origin endpoints, client choice keyed by issuer, PKCE with `resource` and `state`, the RFC 9207
`iss` check, the code exchange, refresh and revocation. The tool client hands results back as text that is capped at
32 KB, free of control characters and has every credential redacted. Its errors are bare codes.

## Accomplishments

- **Task 1 (tracer).** Against the in-process fake, the client runs the whole flow:
  1. `discover`;
  2. pre-registered `chooseClient`;
  3. `buildAuthorization`;
  4. a browser hop through the guard;
  5. `checkCallbackIssuer`;
  6. `exchangeCode`, whose `accountLabel` is `<subject>@fake-mcp.test` (null under `no_id_token`);
  7. `callTool whoami` with the bearer, which returns the grant's subject.

  The fake's stats show `resource` on both the authorize and the token request.
- **Task 2.**
  - `chooseClient` follows the spec's order: pre-registered for this exact issuer, then CIMD, then DCR (which reuses
    a stored client only for the same issuer), then `needs_client`.
  - `chooseScope` uses the admin override first, then the challenge scope, then the PRM scopes. It adds
    `offline_access` only when the authorization server lists it.
  - `refreshTokens` resends `resource`. The ChatGPT terminal set makes a failure terminal; 5xx and network errors are
    transient.
  - `revokeToken` never throws.
  - Refusals are covered in both unit and fake tests.
- **Task 3.**
  - Result shaping: text parts concatenated; `structuredContent` used only when there is no text; images, audio and
    resources replaced by notes; control characters other than `\n` and `\t` stripped; every credential string and
    its base64 forms redacted *before* the 32 KB UTF-8 cap.
  - `listTools` drops schemas over 16 KB and reads `readOnly` / `destructive` from the annotations; a tool is
    destructive by default unless it is read-only.
  - `McpUpstreamError` mapping, with a challenge that is kept, cleaned and redacted.

## Ledger items honoured

- **WINDOWS #175 (SDK falls back to global fetch).** Every SDK helper call passes `fetchFn: egress.bound(policy)`:
  `discoverOAuthProtectedResourceMetadata`, `discoverAuthorizationServerMetadata`, `exchangeAuthorization`,
  `refreshAuthorization` and `registerClient`. Both transports pass `fetch: <guarded wrapper>`. `revokeToken` uses
  `egress.fetch`. `startAuthorization` makes no request.
  - **Proof:** `oauth.test.ts` and `oauth.int.test.ts` replace `globalThis.fetch` with a `vi.fn` that records each
    call and throws. `afterEach` asserts it was never called, which still catches the SDK paths that swallow the
    throw.
  - **Mutation checks**, each reverted afterwards:
    - drop `fetchFn` from `discoverOAuthProtectedResourceMetadata` → all 3 tracer tests fail;
    - drop `fetch` from `StreamableHTTPClientTransport` → 2 tests fail with "global fetch called".
- **WINDOWS #173 (the fake shares DCR/CIMD clients across issuers).** Client credentials are keyed by issuer in the
  client itself. `ClientChoice` carries `issuer`. `chooseClient` matches pre-registered and stored clients by exact
  issuer. `buildAuthorization` and `exchangeCode` refuse a client of another issuer with `issuer_mismatch`.
  - **Proof:**
    - unit: a pre-registered client of another issuer is ignored, and a stored DCR client of another issuer is not
      reused;
    - integration, `different_issuer`: under the alt issuer, `chooseClient` ignores both the main issuer's
      pre-registered client and its stored DCR client and registers a new one; the old client cannot be carried into
      the new flow; a full grant works with the new client.
  - **Mutation checks:** removing the issuer filter on stored clients, the filter on pre-registered clients, or
    `assertSameIssuer` each makes a test fail.

## SDK option names actually used (@modelcontextprotocol/sdk 1.30.1)

- `discoverOAuthProtectedResourceMetadata(serverUrl, { resourceMetadataUrl }, fetchFn)`. Here `fetchFn` is the
  **third positional argument**, not an option.
- `discoverAuthorizationServerMetadata(asUrl, { fetchFn })`
- `startAuthorization(issuer, { metadata, clientInformation, redirectUrl, scope, state, resource })`. It makes no
  request.
- `exchangeAuthorization(issuer, { metadata, clientInformation, authorizationCode, codeVerifier, redirectUri, resource, fetchFn })`
- `refreshAuthorization(issuer, { metadata, clientInformation, refreshToken, resource, fetchFn })`. The metadata is
  minimal: token endpoint plus `token_endpoint_auth_methods_supported: [bundle.authMethod]`.
- `registerClient(issuer, { metadata, clientMetadata, fetchFn })`
- `selectClientAuthMethod`, `extractWWWAuthenticateParams` (`client/auth.js`), `checkResourceAllowed` and
  `resourceUrlFromServerUrl` (`shared/auth-utils.js`), `OAuthError.errorCode` (`server/auth/errors.js`).
- `new StreamableHTTPClientTransport(url, { requestInit, fetch })` and `new SSEClientTransport(url, { requestInit, fetch })`.
  SSE's EventSource also uses `fetch`.
- `client.connect(transport, { signal, timeout })`, `client.callTool(params, undefined, { signal, timeout })`,
  `client.listTools(params, { signal, timeout })`.
- `auth()` is not used.

### Interface additions (all additive, Rule 2)

- `ClientChoice` variants carry `issuer`. This keys custody by issuer and lets the flow refuse a cross-issuer client.
- `exchangeCode` accepts an optional `scope`. It is used for `TokenBundle.scopes` when the token response omits
  `scope`.
- `listTools` accepts an optional `timeoutMs`.
- Extra exports:
  - in `oauth.ts`: `parseWwwAuthenticate` (for 07.4-10 to feed `discover` and `chooseScope` from
    `McpUpstreamError.wwwAuthenticate`) and the `AuthServerMetadata` type;
  - in `mcp-client.ts`, for the unit tests: `shapeToolResult`, `shapeTool`, `capSchema`, `redactSecrets`,
    `stripControl`, `McpToolInfo` and `McpUpstreamCode`.

### Behaviour choices beyond the plan text

- The plan named `discoverOAuthServerInfo` and `selectResourceURL`. Two-step SDK discovery is used instead, for the
  reason under key-decisions. `checkResourceAllowed` replaces `selectResourceURL`, which needs an
  `OAuthClientProvider`; it is the same check, and the PRM `resource` is sent verbatim, as the SDK advises.
- Extra refusals:
  - a server without PRM, or whose PRM `resource` is another server → `discovery_failed`;
  - an issuer different from its discovery URL → `discovery_failed`;
  - an untrusted `resource_metadata` URL in a challenge → `discovery_failed`.
- Guard refusals: `egress_refused` only for policy refusals (private, platform, scheme, https…). Timeouts, DNS and
  network errors are `discovery_failed` during discovery and transient `token_exchange_failed` at the token endpoint.
- `refreshTokens`:
  - with no refresh token → `needs_reconnect` (terminal);
  - a confidential client without its secret → `needs_client` (terminal), with no request made;
  - an untrusted token endpoint → `token_exchange_failed`, with no request made.
- An unknown OAuth `error` is a transient `server_error`; this is the SDK's mapping. `oauthError` only ever holds a
  `[a-z0-9_.-]{1,64}` token.
- MCP errors:
  - a 403 without `insufficient_scope` → `upstream_error`;
  - the caller's own abort → `timeout`;
  - on a timeout the session DELETE is skipped (see the candidates below).

## Broken-windows candidates (not appended: WINDOWS.md is off-limits in this run)

1. **unrun-verify (medium):** SSE has no positive round trip; the fake only speaks streamable HTTP. Only the SSE
   refusal through the guard is tested (`mcp-client.ts`).
2. **deviation (medium):** CIMD is chosen whenever the instance URL is https and the AS supports it, but nothing
   checks that the AS can reach the document. On an internal-CA install the AS cannot fetch it. 07.4-10 needs a way to
   prefer DCR or pre-registered clients there, for example a setting or a fallback after a failed authorize
   (`oauth.ts` chooseClient).
3. **deviation (low):** servers without RFC 9728 metadata (2025-03-26 style) cannot be connected per member
   (`discovery_failed`).
4. **deviation (low):** `revokeToken` form-encodes the client id and secret in Basic auth (RFC 6749 §2.3.1), while the
   SDK's token requests do not. The two agree for URL-safe secrets, which covers every DCR secret seen; they could
   differ for secrets with reserved characters.
5. **deviation (low):** on a call timeout the MCP session is not DELETEd (the abort cancels it); the server expires
   it.
6. **deviation (low):** the recorded-refusal fallback could label a later non-guard failure as `egress_refused` if a
   side request in the same call was refused.
7. **Ledger follow-ups for the owner:**
   - #175 is now proven for every 07.4-05 call site; the remaining 07.4-10/11 call sites still need it.
   - #173 is proven at the client-library level; 07.4-10's custody must store clients keyed by issuer and pass the
     confidential client's secret to `refreshTokens` / `revokeToken`.
