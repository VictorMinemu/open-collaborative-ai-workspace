<decisions>
## Implementation Decisions

### Common to phases 07.1–07.7 (orchestrator, 2026-10-08)
- **C-01:** The Control Plane owns the feature. Agents act only through `ocw_*` plugin tools that the Agent Channel API
  decides (resolver, agent ∩ human, taint) and audits; OpenClaw's in-cell equivalents (file memory, cron, webhooks,
  `sessions_send`, exec approvals, per-requester MCP OAuth) stay off (principles 6, 9, 12).
- **C-02:** Contracts first (Zod in `packages/contracts`), RLS on every organization-scoped table with a cross-tenant
  test, an audit event for every sensitive action, `pnpm verify` (incl. `pnpm guard`) green before every commit, TDD.
- **C-03:** UI work is verified at 1440 and 390, light and dark, with reviewed screenshots and e2e through
  `scripts/e2e-isolated.sh`; Woodpecker CI must stay green.
- **C-04:** No new paid or hosted service; any new dependency is pinned, license-checked by `pnpm guard`, and justified.
- **C-05:** Research for this phase: `.planning/research/OPS-FEATURES.md` (the F-numbers below). Code references there
  were taken at `main` 4644fcd; re-check them.

### Phase decisions
- **D-01:** Connector auth modes `org_secret` (today's admin-registered MCP) | `per_member_oauth` | `per_member_secret`;
  members connect in Settings; tokens sealed per member with ADR-0017's sealing and serialized refresh; reconnect state —
  F1.
- **D-02:** An API-side connector proxy (`/agent-channel/v1/connectors/:id/call` or similar) performs MCP calls with the
  requester's credential (agent ∩ human), audited per call; OpenClaw's `per-requester` OAuth is rejected. The OAuth
  callback lands on the API. Follow the current MCP authorization spec (PKCE S256, RFC 8707 `resource`, client ID
  metadata documents with a pre-registered fallback when the instance has no public HTTPS URL).
- **D-03:** Results obtained with a member's account default to DMs (ADR-0019 audience rule); shared contexts need an
  explicit, audited choice.
- **D-04:** Keychain (`vault_items`): personal or unit scope, kinds api_key | basic | oauth, host allowlist; the agent
  sees a handle; the API injects the secret only towards allowed hosts; `secret.used` audit without value; storage via
  `SecretReference` (db/openbao) — F2.
- **D-05:** Agent templates (F3): unit-scoped, versioned; instantiation creates a personal agent with `template_id` and
  version, its own memory (07.2 personal scope) and connections; personal-agent caps apply. Decide fork vs linked
  updates in research (default: fork with "update available" notice).
- **D-06:** Touches secrets, permissions and audit → plan-mode level care; never log or return secret values.

- **D-07 (orchestrator, after research):** research defaults accepted — (1) keychain storage is `db` only in this phase
  (the OpenBao store is load-once/read-only; runtime-created items in OpenBao are backlog); (2) private/LAN hosts are
  reachable only through an admin-managed private-host allowlist, never from personal keys; (3) keychain kind `oauth`
  means client credentials, token in memory only; (4) per-member OAuth is offered only when the instance has HTTPS
  (or localhost), pointing admins to `pnpm ocw enable proxy`. A pinned-IP egress guard (`lib/egress.ts`: undici
  `connect.lookup`, private/platform hosts blocked, no redirects) lands first and every new outbound call uses it.
  Three fixed plugin tools (`ocw_connector_list`, `ocw_connector_call`, `ocw_http_request`); MCP client
  `@modelcontextprotocol/sdk` (already locked) plus our own `code_challenge_methods_supported` and RFC 9207 `iss`
  checks. Templates fork with an "update available" notice. Audience: member-account tools only in DMs / unshared AI
  chats; elsewhere withheld with reason `member_account`. ADR-0025.
