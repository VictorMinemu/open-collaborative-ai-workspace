## Phase Goal

A bot that started a Work Zone session moves files between that session and the conversation it started it from:
it **uploads** an attachment of the thread into the session's working tree and **downloads** a file of the session back
to the conversation as an attachment people open and download, each bounded by a per-file limit the organization and
the bot's profile configure, decided server-side, audited, and never sending an absolute path (owner, 2026-11-11: "el
bot debe poder ver el output de la ia de la workzone y seguir haciendo prompts, descargar archivos", "añade que pueda
subir y descargar archivos para el workzone", "el limite de peso por archivo que sea configurable"; CONTEXT D-01 … D-14;
BWF-01 … BWF-08). Reading output, prompting and stopping already ship (07.16).

**This plan's slice (tracer, contract tier):** the phase's vocabulary in `packages/contracts` and its mirror in the
plugin. Plus this hub: plan map, shared files, cross-plan names, planner decisions PD-01 … PD-26, edge coverage,
prohibitions, flagged assumptions, source coverage. Every later 07.17.1.1 plan cites this hub.

- **PD-05 Transport (D-08, Pitfalls 8, 10).** A command carries the repo-relative path and the bounds, never bytes and
  never a URL; the transfer id is the command id; the daemon builds `toRuntimeFileUrl(config.serverUrl, cmd.id)`
  itself and sends its cached device JWT (`getAccessToken`). The API route accepts only a device JWT whose device is
  the ledger row's device, not revoked, with `device.link` decided (legacy raw device tokens answer 401); the row is
  single-use (`pending` → `streaming`; any later request 410) and expires at `created_at + transferDeadlineMs(bound)`
  (410 after). `PUT` requires `content-length` (411 without) and answers 413 before reading a byte when it exceeds the
  row's `max_bytes`; the body is counted as it streams (more than declared or than `max_bytes` aborts). At most
  `concurrentTransfersPerProcess` (4) transfers stream per API process (503 `busy` beyond). Garage multipart with
  8 MiB `Buffer` parts, one part in memory; a file of one part or less uses `put`. No presigned URL; the API hashes
  (sha256) and sniffs every byte it stores. Fastify's `requestTimeout` stays 0 (app.ts sets none); the ledger deadline
  bounds the time.
- **PD-06 Call order (D-01, D-02, D-10 … D-13; RESEARCH Pattern 1).** tx0 user-less: the turn of this bot (else 404
  `unknown_turn`), its profile, `ownBotSession`, the effective limit (`loadBotFileLimit`). txA as the asker
  (`turn.userId`): `liveTurn` (else 404) → the tool on the turn (`not_in_turn`) → storage configured
  (`storage_unavailable`) → upload only: `attachmentForTurn` (null → `attachment_not_found`, no probing) and its size
  against the limit (`file_too_large` with `limit` and `sizeBytes`). Then the route creates the transfer id and
  subscribes the waiter (`botFiles.waitForAck`, the hub's `waitForFileAck`, abortable). txB as the session's sponsor (`bot_work_sessions
  .sponsor_user_id`): `liveTurn` → the tool on the turn → own session (`not_your_session`) → origin conversation
  (`not_your_session`) → profile present, its sponsor equal to the session's (WR-05) and active (`profile_inactive` +
  reason) → `profileScopeRefusal` → `workSessionFilePathRefusal(path)` (`path_not_allowed`) → `turn.tainted &&
  !profile.actOnOutsideContent` (`outside_content`) → `turn.sessionOutputRead && !readOnly(eventId, workSessionId)`
  (`session_output`) → the claim (one of 8; `outsideContent` when tainted, `sessionOutputExempt` when exempt) →
  `botFiles.prepareUpload|prepareDownload`. Refusals before the claim are `refuseBeforeClaim` (a denied
  `agent_tool_calls` row, not counted); after it `auditRefusal`. The route awaits the waiter outside any transaction,
  then txC as the sponsor: `botFiles.finish` → the answer and its audit.
- **PD-07 Sponsor rights (principle 6).** `prepareUpload` decides `work_session.prompt` for the sponsor on the session
  (writing into its tree is acting on it, like a prompt); `prepareDownload` decides `work_session.read` (what the diff
  route asks). Refused → `not_allowed`. No new permission or grain.
- **PD-08 Session state (D-04, D-13, Open Question 1).** Under the bot's lock then the session row lock (`svc.lock`):
  `archived` → `session_ended`; `completed` or `failed` → `session_not_running`; `host_offline`, or the device not
  `online` or revoked → `device_offline` (before any ledger row); upload only when `status = idle` and the session has
  no prompt `queued`, `dispatched` or `running` → else `session_busy`; download in `idle`, `running` or
  `waiting_approval` (a file being written may be read half-done; documented in ADR-0041). On the device: not in
  `this.sessions` → `not_running`; a write while a turn runs → `busy` (second line).
- **PD-09 Paths and the deny list (D-02, D-03, D-09).** `WorkSessionFilePath` at both ends (the plugin's local check,
  the strict bodies, the device payloads); `workSessionFilePathRefusal` in the API before the claim (a refusal costs no
  transfer) and in the daemon, authoritative, on the requested path **and** on the path relative to the realpath of the
  root, both ways; `.env` uploads are refused on purpose. The Claude adapter's `isSecretPath` keeps its home-directory
  list and uses the shared basename rule.
- **PD-10 Containment on the device (D-03, D-04; RESEARCH Pattern 4).** Root = `realpath(active session cwd)` (the
  worktree when isolated). The parent's realpath must equal the root or start with `root + sep`; missing parents are
  created for a write one segment at a time, each `lstat`-checked and never through a symlink. Read: `lstat` regular
  file (not a symlink, FIFO, socket, device or directory), `open(O_RDONLY | O_NOFOLLOW)`, `fstat` size ≤ `maxBytes`
  (else `too_large: <size>` before any byte moves). Write: free space ≥ size (`statfs`), a temp `.ocw-upload-<id>.part`
  in the parent opened `wx` with mode 0o644, bytes counted and hashed, size and sha256 equal to the payload's (else
  `mismatch`), no overwrite → `link(tmp, target)` (EEXIST → `exists`) then unlink; overwrite → the target must be a
  regular file or absent, then `rename`; the temp file is removed on every failure. Bytes only end to end; nothing is
  decoded or executed; ack errors pass `sanitizeString` with the session roots.
- **PD-11 Limits (D-07).** Organization: `work_zone_policies.bot_file_max_bytes` (default 25 MiB), saved only ≤
  `OCW_ATTACHMENT_MAX_BYTES` (400 with the field). Bot: `bot_work_zone_profiles.file_max_bytes` (null = the

  an organization lowered later wins at once. "MB" in the UI is MiB (the chat's `formatBytes`). The limit is checked

  the API's 413. `file_too_large` carries `limit` and, when known, `sizeBytes`, and its sentence is
  `botFileTooLargeSentence`.
- **PD-12 Budgets (D-06).** One unit of the 07.16 hourly prompt budget per transfer the API enqueued (a ledger row,
