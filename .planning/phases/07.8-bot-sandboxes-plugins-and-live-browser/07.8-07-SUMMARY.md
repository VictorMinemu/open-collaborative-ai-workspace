## What exists now

- **Image** (`infra/sandbox/browser/Dockerfile`):
  - Multi-arch, pinned and checked at build time.
  - Runs as user 10001. Chromium is at `/opt/chromium/chrome-headless-shell`. The agent is the entrypoint, run under
    Docker init. There is no EXPOSE.
  - 251 MB compressed. `node agent.mjs --check` fails the build if Chromium or the pin is missing.
- **Agent** (`agent.mjs`):
  - Launches Chromium over Playwright's pipe: `--remote-debugging-pipe` is confirmed in the container, and there is no
    `--remote-debugging-port`. Also passes `--disable-quic` and the WebRTC non-proxied-UDP policy. `OCW_BROWSER_PROXY`
    is passed through.
  - Contexts are ephemeral, with service workers blocked, so routing cannot be bypassed.
  - Ops are serialized per context, and every op has a 45 s timeout.
  - Errors carry a fixed code and message, never page text.
  - Stderr carries fixed lines only. The one exception is Chromium's own fatal launch lines, at launch, before any page
    exists.
- **Redaction** (`redact.mjs`):
  - A value is replaced with `[redacted]` for any of these: `type=password`; `autocomplete` current-password,
    new-password or one-time-code; `-webkit-text-security` other than none; a name, label, field name, id, placeholder
    or aria-label matching `/pass|pwd|otp|code|pin|secret|token/i`; or a human-typed mark.
  - A text field the agent has no facts for is redacted (redact on doubt).
  - Nothing inside a text field is serialized, because its inner editor repeats the value.
  - Links carry no value, because an href can hold a token.
- **Takeover:**
  - Marks are made only while a takeover is active, by window-capture listeners in the agent's isolated world, so a
    page cannot forge or see them. Marks last for the page's lifetime.
  - While a takeover is active, bot ops answer `paused`.
  - `contextInput` maps key, text, mouse, wheel and touch events to CDP. It validates each event and never writes the
    payload anywhere.
  - `focus { sensitive }` is emitted when the focused field changes between password-like and not.
- **Screenshots:** sensitive and marked fields (judged from the AX tree and the field facts) are painted out on the
  decoded image. After human input, iframes are painted out too.
- **Storage state:**
  - Export keeps only cookies that domain-match (RFC 6265) the sign-in host. That host is the site lock, or the first
    host the context navigated to.
  - It keeps that host's origin storage only. The identity provider's cookie is dropped.
- **Site lock:**
  - Every top-level or pop-up navigation to another host is aborted with `net::ERR_ABORTED`, so the page stays where it
    was, and is reported as `blockedNavigation {host}`.
  - `allowCrossSite` lifts the lock for the one op that carries it.
- **Downloads:** files are saved under `/tmp/downloads/<token>` with a 50 MiB cap, served by `contextDownload`, and
  removed when the context closes.
- **Resize:** small (960×600), expanded (1280×800), or phone (mobile emulation plus touch). The screencast restarts at
  the new size.

1. The context opens `/login` and the email field is not redacted while it is empty and untouched.
2. Takeover on. `contextSnapshot`, `contextScreenshot`, `contextAct` and `contextNavigate` answer `paused`.
3. Input frames enter `ana@example.test` in the email field (key frames), `S3cr3t-Hunter2-OCW` in the password field,

4. Takeover off. A focus event flagged the password field as sensitive.
5. Snapshot: Email, Password and One-time code are each `redacted: true` with value `[redacted]`. The snapshot shows
   **Hide password**, which proves the field was revealed. None of the four strings is in the snapshot JSON.
6. A text wait for each of the four strings returns `ok: false`.
7. Screenshots:
   - PNG: `masked ≥ 3`. Mask rects cover the three field boxes, and every pixel inside them is `0,0,0,255`, decoded in

   - JPEG: `masked ≥ 3`.
8. Takeover on, click **Sign in**, takeover off. The page shows "Welcome", and the fake site counts 1 login and 0
   failures.
9. On every run, the whole transcript is checked: stdout bytes (responses, events, frames) and stderr contain none of

## Deviations from Plan

### Auto-fixed issues

1. **[Rule 1 - Bug] The spike's seccomp delta was incomplete.** On Docker Desktop, the profile from spike (i) (default +
   clone/setns/unshare) made Chromium's zygote die with `Check failed: sys_chroot("/proc/self/fdinfo/")`. The spike
   never reached this point, because its Ubuntu host failed earlier on AppArmor. `chroot` is now allowed too. The kernel
   still requires the capability inside the new user namespace, which an unprivileged process has only there. With this,
   Chromium's own sandbox runs on hardened runc (`browserSandbox: chromium`).
2. **[Rule 1 - Bug] The pop-up escaped the site lock.** The smoke caught `window.open` reaching `evil/collect`.
   Playwright's `request.frame()` throws for a pop-up's first navigation, and the handler had treated that as a
   subframe. A navigation request with no frame is now top level.
3. **[Rule 1 - Bug] Throttled screencast.** The last frame of a page that then stops changing could be dropped. The
   newest frame inside the throttle window is now delivered when the window ends.
4. **[Rule 2 - Security] A text wait as an oracle.** `contextWait {for: "text"}` would have matched page text, including
   a contenteditable's typed content. It now polls the redacted snapshot.
5. **[Rule 2 - Security] Screenshot masks.** The plan's isolated-world DOM overlay could be hidden or moved by a page
   script. The agent paints the boxes on the decoded PNG instead (playwright-core's bundled pngjs and jpeg-js).
6. **[Rule 1] The D-14 fallback condition.** The first version fell back on any zygote error, which would have hidden
   the seccomp bug as `container-only`. Fallback now happens only on Chromium's `No usable sandbox`.

### Other recorded changes

- **`xvfb` dropped** from the install-deps list (headless shell needs no X server). The list is 70 packages instead of
  109. This is within the approved list.
- **`unzip.mjs`**, a file not in the plan's list: it extracts the verified archive with playwright-core's bundled zip
  reader, so no extra apt package is needed. It refuses absolute paths, `..`, links and duplicate entries.
- **Fake sites use port 8080** (`http://panel.fake.test:8080/app`), because the fake container runs unprivileged.
- **The "no listening port" check** reads `/proc/net/tcp{,6}`, because `ss` is not in the image. It excludes only
  Docker's embedded DNS on `127.0.0.11`, a dockerd-owned socket in the container's namespace.
- **Contract additions on the agent side:**
  - The screenshot result carries `maskRects`; 01's non-strict `ScreenshotResult` strips it.
  - `contextResize` also takes `mode` (`small`, `expanded`, `phone`, `custom`).
  - `contextTakeover` takes `active` (01) or `on` (the plan text).
  - New ops: `info`, `contextFrames {on}` and `contextDownload {token}`.
  - New error codes `paused` and `internal`, beyond `SandboxdErrorCode`.
- **E1 field count.** The four strings sit in three fields, because the toggle reveals the same input. Masks cover
  those three.
- **D-14 checks in the smoke** beyond the plan:
  - With Docker's default seccomp on runc, the agent reports `container-only`.
  - When the agent is told it runs under runsc, it refuses to start instead of falling back.
- **Tests and code are committed together,** because AGENTS.md requires `pnpm verify` before every commit. RED was run
  and seen to fail for `redact.test.mjs` and for the E1 check.

## Broken-windows candidates (not written to WINDOWS.md, per instructions)

1. **Iframes.**
   - The snapshot covers the main frame's AX tree only, so a login form inside an iframe gives the bot no refs.
   - After human input, screenshots mask whole frames.
2. **Live frames are not masked.** Screencast frames to other viewers show a plain-text field, such as the username,
   while it is typed. F-5 sends frames only to the controller during a takeover; plan 16 (API) must enforce that.
3. **sandboxd (13) mapping.** sandboxd must:
   - strip the agent's context-id tag from type-0 frames and re-frame them per context;
   - map the agent codes `paused` → `paused`, `internal` → `service_unavailable`, `sandbox_required` (fatal) →
     `service_unavailable`;
   - send `mode` on resize.
4. **CI (24).** Only arm64 on Docker Desktop was run. On the amd64 Woodpecker (Ubuntu 24.04), runc should report
   `container-only`; the gVisor nested job should report `chromium+gvisor`. Both still need a run.
5. **apt packages are not snapshot-pinned.** The origin gate holds, but versions move with bookworm security updates.
6. **Fresh element after typing.** A page that rebuilds an input after the person typed (cloning its value) escapes the
   human-typed mark. The name and autocomplete rules still apply. This is out of scope: the site already holds the
   value.
7. **Build cache.** About 2 GB of build cache from the image builds is left, because there is no prune.
