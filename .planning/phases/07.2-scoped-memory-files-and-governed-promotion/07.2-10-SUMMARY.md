# Phase 07.2 Plan 10: Memory file and folder viewer Summary

**Members now have a Memory section: a file explorer of every scope they may read (department, team, organization,
private and bot memory), an accessible tree on `@headless-tree/react`, files rendered through the shared Markdown
renderer with in-viewer links, and search grouped by scope with a scope selector. It works as two panes from 1024 px
and as a full-screen tree, then file screen, on phones. Reviewed in 16 screenshots at 1440 and 390, light and dark.**

## What was built

- **Navigation and routes.** "Memory" (`NotebookText`, `memory.read`) sits between Bots and Work Zone in the rail
  and in the phone drawer. `/memory` and `/memory/<scopeId>/<…path>` render a `MemoryShell` that lives in the memory
  layout, behind `ModuleGate("memory")`, so the 07.3 module switch hides it live.
- **Tree.** `@headless-tree/react` provides the ARIA tree: roving tab stop, `aria-level`, set sizes, expanded
  state, arrows and Home/End. The component adds:
  - Enter or Space opens a file (focus moves to its `<h1>`) or toggles a folder.
  - Typeahead with a 500 ms buffer, and `*` expands the siblings.
  - → on a file does nothing.
  - The open file is `aria-selected` and `aria-current="page"`.
  - Rows, icons, kind tags, indent guides and the selected bar follow the UI-SPEC: 36/32 px on desktop; 56 px scope
    nodes with a "{n} files" line and 44 px rows on phones.
  - Expanded state lasts for the session, and deep links expand their ancestors.
- **Reading pane.**
  - Breadcrumb `<nav><ol>` with the file name as a focusable `<h1>` (15/600). More than 4 segments on desktop, or
    more than 3 on phones, collapse into a "Show full path" menu.
  - Meta row: scope badge, version, editor avatar, age with the full date, "Read only", and the private-scope note.
  - The document renders through `<Markdown variant="document" resolveHref>` in a 760 px column.
  - A template-only `MEMORY.md` shows "Nothing saved here yet."
- **Links.** A relative `.md` link that stays inside the scope opens in place (client navigation, same tab).
  - Links that leave the scope, or are not `.md`, render as text.
  - External links keep `target="_blank"` and `safeUrl`.
  - The resolver's output still goes through the hardening plugin, so a hostile resolver result
    (`javascript:`) is dropped. A unit test proves it.
- **Search.**
  - The field sits at the top of the column (h-11 on phones). It is debounced 250 ms and starts at 2 characters.
  - While a query is present, results replace the tree. They are grouped by scope under sticky labels, with marked
    snippets and a polite "N results" count.
  - A "Search in" selector lists "All memory" plus the scopes the API listed; the current scope comes first on a
    file screen.
  - With no hits it shows "No results for “…”." and, when narrowed to a scope, "Search all memory".
  - Enter on a result opens it and focuses its `<h1>`. Escape clears the query and returns focus to the tree.
  - The query persists across files (one tap back on phones).
- **States.**
  - Loading: 6 skeleton tree rows plus a skeleton file pane.
  - No readable scope: an EmptyState.
  - Tree error: "Couldn't load memory." with Try again. File error: "Couldn't open this file." with Try again.
  - Not found: missing, denied, malformed and non-id URLs share one state, "This file doesn't exist or you can't open
    it", with a link back to the scope or to Memory.
- **Proposals row.** It is pinned at the bottom of the column (h-12; h-14 on phones) and links to `/memory/proposals`,
  which 07.2-13 builds.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 - Bug] The tree could be unreachable by Tab**
- **Found during:** Task 3 (keyboard e2e design).
- **Issue:** headless-tree's tab stop is its focused item. When that item sat inside a collapsed folder (the open
  file on `/memory`), no row had `tabIndex=0`, and the arrows did nothing.
- **Fix:**
  - The tab stop falls back to the open file's row, then the first row.
  - A row that receives DOM focus becomes the tree's focused item.
  - Desktop `/memory` also expands the scope whose `MEMORY.md` is open.
- **Files:** `memory-tree.tsx`, `memory-shell.tsx`. **Commit:** 59bf5f17.

**2. [Rule 2 - Threat T-07.2-10-02/03] Malformed and non-id URLs**
- **Issue:** `/memory/<not-an-id>/…` (a typo or a crafted link) reached the API, and its 400 showed the generic error
  state. That state differs from not-found, and `/memory/proposals` hits the same path until 07.2-13 lands.
- **Fix:**
  - The scope segment is validated with the contract `Id` before any request.
  - A 400 from the file route is treated as not found.
  - The e2e asserts it.
- **Commit:** a7ddcefb.

**3. [Rule 1] e2e race.** The phone back control was measured while the loading screen's control was being
replaced. The spec now waits for the loaded file first.

### Interpretations and plan adjustments

- **Fixture shape.**
  - The plan said Sam's tree shows "Organization and Ventas (Team) and no other unit". But a team must sit under a
    department (`ALLOWED_PARENT_KINDS`), and team members read their department's memory.
  - The seed is therefore department "Comercial" with teams "Ventas" (Sam) and "Compras" (Alex).
  - The e2e asserts Sam's tree equals the API's listing (Comercial, Ventas, Organization) and that Compras is absent.
- **Layout-owned shell.** The plan listed two pages. I added `app/(app)/memory/layout.tsx`, which renders the shell
  and the module gate; the pages only declare routes. This keeps the tree's instance, focus and scroll across file
  changes. 07.2-13's `/memory/proposals` page will be a sibling route and can switch the column by pathname.
- **No skipped tests.** Per-project flows run inside one test that branches on the project, instead of
  `test.skip`, because the plan fails on any skipped test. The keyboard test runs the desktop keyboard flow at 1440
  and the touch, back-control and breadcrumb checks at 390.
- **Truncated names.** The name is truncated and gets a Tooltip only when actually cut. There is no `title`
  attribute, to avoid a second native tooltip. Rows carry the full name in `aria-label`.
- **Meta tooltips.** The private note, the full date and the "Read only" explanation are pointer Tooltips. Their text
  is also in `sr-only` spans, because focusable non-interactive spans fail lint (`noNoninteractiveTabindex`).
- **"No files yet" row.** It is `aria-hidden`; the scope's accessible name gains ", no files yet".
- **Not built here (07.2-12, per the plan's prohibitions):**
  - View·Edit·History tabs (desktop and phone), the History toggle and the ⋯ file menu.
  - The New file and New folder header buttons, and the row ⋯ menus.
- **Not built here (07.2-13):** the nav badge count and the Proposals row count.
- **TDD shape.**
  - Unit tests ran RED first for both tasks.
  - The Task 2 e2e was written after the components, so its first run was green.
  - The fix commit's e2e step ran RED first.
