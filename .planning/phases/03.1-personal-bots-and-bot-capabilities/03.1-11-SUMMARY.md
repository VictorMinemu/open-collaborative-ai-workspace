# Phase 3.1 Plan 11: OpenClaw Marketplace API (ClawHub proxy, risk scoring, pinned approvals) Summary

Organization Admins can search ClawHub through the API (cached, anonymous, fixed user agent), open any release and see publisher, channel, verification, scan/trust state, compatibility, the declared surface and a deterministic risk with reasons, then approve that exact pinned version: the approval re-reads ClawHub live, must match the reviewed token, writes a `cell_plugins` row with the reviewed digest, sends the cell one `plugin.install.v1` with an artifact URL on the configured ClawHub origin, and is audited. Updates need a fresh review; uninstall removes the plugin's tools from every bot first.

## What was built

- **Contracts** exactly as the plan's interface block, plus `EMPTY_DECLARED_SURFACE`, `CellPluginStatus` and the route query/param schemas. Agent Channel additions are additive: an older `CellSnapshot` without `plugins` parses to `[]`.
- **risk.ts (pure)**: refuses channels, gateway method dispatch / HTTP routes, CLI backends, extension factories, tool-result middleware, trusted tool policies, memory/context slots, external auth, worker providers, code executors, bundled MCP servers, dangerous tool names, ClawHub blocks (blockedFromDownload, malicious/quarantined/revoked/blocked/hidden moderation, malicious scan), incompatible host and missing digests. High: community, unscanned/pending, scan not clean, moderation pending, hooks, unknown compatibility, unknown capability, missing manifest, dangerous config flags. Medium: web search/fetch providers, model providers, media/document providers, skills, CLI commands, unverified source tier, publisher not official on the official channel. Reasons are deduplicated and sorted worst first. `reviewTokenOf` hashes a canonical JSON (lists deduplicated and sorted).
- **clawhub.ts**: search (`/api/v1/packages/search?family=code-plugin`), browse (`/api/v1/plugins`, cursor), release detail (`/detail?version=`), lenient Zod parsing, manifest summary → `DeclaredSurface`, 8 s timeout, 5 MB body cap, `MarketplaceUnavailableError` (`timeout | unavailable | network | malformed`) and `MarketplaceNotFoundError`, Redis cache through the bus.
- **service.ts / routes.ts**: the six routes, `bundled` and `installed` per org, approvals (409 `review_changed`, 422 `plugin_refused` with reasons, 409 `high_risk_ack_required`, `bundled_plugin`, `already_installed` incl. the unique-index race), settings (`plugin.settings_updated`, `cell.config.changed tools.updated`), upgrades (`plugin.install.v1 mode update`, `plugin.update_requested`), uninstall (grants deleted in the same transaction, `plugin.uninstall.v1`, `tools.updated`, `plugin.uninstall_requested`), 503 `marketplace_unavailable`.
- **Fake ClawHub**: five fixture packages with the real response shapes; tarballs in `FAKE_CLAWHUB_ARTIFACT_DIR` (named `artifact.npmTarballName`, npm-pack naming) replace the fixture digests with real sha256 / sha512 integrity / sha1 shasum / size everywhere and are streamed by `/artifact/download` with `X-ClawHub-Artifact-Sha256`, `X-ClawHub-Npm-Integrity`, `X-ClawHub-Npm-Shasum`, `X-ClawHub-Npm-Tarball-Name`. In-process controls: request log with headers, mutable fixtures, outages (`status` or `delayMs`), `reset()`. Mounted in `server.mjs` with the same tolerant dynamic import as the fake MCP (3 small hunks); the Dockerfile copies it and the fixtures.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `/cell` returns `plugins: []`**
- `CellSnapshot.plugins` has a default, so the `/cell` route's response typing required it (same as 03.1-09's `mcpServers`). One line in `apps/api/src/modules/agent-channel/index.ts` with a comment that 03.1-12 wires the approved list.
- **Commit:** c899d6e

**2. [Rule 1 - Bug] Reviews and stale cache**
- Found by the integration test: with reviews served from the 10-minute cache, a release that changed on ClawHub (or changed back) made every approval answer `review_changed` until the cache expired. Reviews now ask ClawHub first (`refresh` mode: cached copy only during an outage), approvals stay strictly live, and the 409 carries the fresh review. Search keeps the 10-minute cache.
- **Commit:** e54605b

**3. [Plan wording] Real ClawHub paths instead of the plan's guesses**
- The client uses `/detail?version=` (see decisions) and the artifact URL is `/versions/{v}/artifact/download` (the plan said `/versions/{v}/artifact` streams the tarball; on the real API that path returns JSON metadata). The fake serves both shapes, so 03.1-12 can rely on `PluginInstallEvent.artifactUrl` as is and 03.1-15's real-ClawHub proof downloads from a real path.

**4. [Rule 2 - Security] Additions beyond the behavior list**
- Refusals for bundled MCP servers, code executors, missing digests and packages without a plugin id; 5 MB body cap; stale fallback on outages; ClawHub never called before the `plugin.manage` check; origin assertion on every artifact URL; `plugin_busy` / `plugin_uninstalling` / `same_version` guards; unique-index race mapped to 409.

**5. [Plan wording] `fake-clawhub.d.mts`**
- Not in the plan's file list: type declarations so the TypeScript tests import the fake in-process without `any`.

**6. [Plan wording] Function names**
- Service exports `updateCellPlugin`, `uninstallCellPlugin`, `listCellPlugins`, `getCellPlugin` (the plan said `updatePlugin`, `uninstallPlugin`, `listPlugins`), and the client exposes `search` / `versionDetail` / `artifactUrl` instead of separate per-endpoint calls. `createClawhubClient` also accepts an injected `cache` and `now` (the plan listed `bus`, `timeoutMs`, `fetchImpl`).
