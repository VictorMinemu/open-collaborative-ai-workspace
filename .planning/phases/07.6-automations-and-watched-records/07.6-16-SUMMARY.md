# Phase 07.6 Plan 16: Settings › Digest Summary

**Each member now sets up their digest in Settings › Digest, right after Notifications. They choose the days, time and
zone (the browser's zone by default), the four sections, skip-empty, the bot that delivers it (their personal bot
preselected) and an optional AI summary, which shows METERED and who pays before it can be turned on. Save shows the
next send time. Preview renders the exact Markdown of the unsaved form, and Send a test now posts the saved digest to
their DM, with an Open link. Members with no bot get the dashed box with Create a personal bot, and Save tells them why
it is off.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Plan 15's `TimeZoneField` and day chips are not on this base**
- **Found during:** Task 1. The base branch has plans 01–09, 13, 20, 21 and 22. `components/automations/` does not
  exist.
- **Fix:** Day chips and the zone field (an `Input` with a `<datalist>` of `Intl.supportedValuesOf("timeZone")`,
  checked on blur with the contract's `AutomationTimeZone`, the same rule the API applies) are built inside
  `digest-settings.tsx`. They follow the spec's classes and copy. No file of plan 15 was created, so there is no merge
  conflict.
- **Files:** `apps/web/components/digest/digest-settings.tsx`, `digest-form.ts` · **Commit:** `92793b71`

**2. [Rule 2 - Module access] The Digest entry carries `permission: "automation.create"`, and the page is behind
`ModuleGate module="bots"`**
- The plan's interface showed the entry without a permission. A digest is the person's own automation:
  `GET /digest` answers 403 without `automation.create`, and Bots off turns that grain off (module-access.ts). The
  entry now leaves with the module, like Connections and Keychain (ADR-0024). An individual deny rule still shows the
  page, with the API's 403 sentence in an `EmptyState`. `account-nav.test.ts` lists Digest after Notifications and
  passes `automation.create` in the Bots-off cases.
- **Commits:** `3c0e412f`, `92793b71`

**3. [Rule 2] Live view on the person's own `user:` stream**
- `automation.updated` and `automation_run.updated` (both `ev` and `eph`, per 22's note) refetch the view, so `Next:`
  and `last sent` follow a pause from the automations list or a run that just went out. A form with unsaved changes is
  never overwritten.

**4. [Structure] One extra file, `digest-form.ts`**
- The web Vitest project renders static markup in Node (no DOM), so the rules, copy and formatting live in pure
  functions there. The page is `DigestSettingsView` (pure) plus `DigestSettings` (state and queries).

**5. [Test infra] No-bot e2e and per-run members**
- Every developer can read the team bots other specs create on a shared stack. Sam's page therefore receives the real
  `GET /digest` response with team bots removed (`page.route`). Create a personal bot is the real call, and the new
  bot is then listed and preselected.
- Members are new to each run (unique emails): a test send counts toward the digest's 5 runs a day, so `--keep-db`
  reruns stay green.
- The regression spec (`notification-prefs`) also wrote its captures into the phase folder. They are not this plan's,
  so they were removed.

### Plan interpretation

- The test-send toast names the saved digest's bot from the view (`POST /digest/test` returns only ids).
