## Deviations from Plan

1. **[Rule 1 - Bug] Every API refusal read as "the workspace could not be reached" in a real cell**
   (`apps/openclaw-channel/src/api-client.ts`, 8cadf6f5).
   - **Found by:** the new smoke scenario, first run. The ended turn's read and propose printed "could not be
     reached" instead of "this conversation turn is no longer active".
   - **Cause:** OpenClaw loads the plugin once per registry. The shared client (on `globalThis`) comes from one module
     instance and the tools that catch its errors from another, so `instanceof AgentChannelHttpError` was false.
     This affects every plugin tool that maps HTTP refusals (memory, memory files, card, board), not only memory.
   - **Fix:** a process-wide brand plus `Symbol.hasInstance`. RED first: two unit tests that import a second module
     instance failed, then passed; the smoke then passed.
2. **[Rule 1 - Bug] Full suite: mobile `admin-org` could not clear units** (`e2e/tests/admin-org.spec.ts`, 8cdf7486).
   - **Cause:** since 07.2-08 a unit with live memory files cannot be deleted (409 `unit_has_memory`). The desktop
     memory specs leave team memory before the mobile admin-org run. The API log showed the single 409 on `DELETE /units`.
   - **Fix:** the spec deletes each unit scope's files and resets `MEMORY.md` to the template first, and its asserts
     now name the unit and the API answer. No assertion was loosened. Proof: 49/49 with the memory specs first.
3. **Full e2e run 2 not completed.** From test 257 (mobile) on, specs timed out because the host ran out of memory:
   47 GB used, 154 MB free, 19 GB in the compressor, load average 136. The machine then rebooted (the containers
   show Exited 137). After the reboot the demo's postgres and redis are stopped, and the harness would start them in
   the demo's compose project, which is prohibited, so the rerun was not done. **Open item:** one clean full-suite run
   once the demo's database is back.
4. **`gate:compose` needed two retries, both root-caused.**
   - Attempt 1: Docker Hub TLS handshake timeout right after the reboot. It passed once the registry answered.
   - Attempt 2: "all predefined address pools have been fully subnetted". The host has 28 user networks against
     Docker Desktop's 31 pools, and every compose project adds the always-created `pii` network (WINDOWS 120).
   - I freed one pool by removing the e2e harness's own exited `ocw-e2e-storage` container and network. That project
     belongs to the harness, not the demo, and is recreated by the next e2e run.
   - **Warning for the owner:** the demo's next `up` also needs a `pii` network and may hit the same error.
5. **Leak sweep audiences.** The plan says the admin finds no canary. That is true only for private canaries: an
   admin legitimately reads Ventas memory. The test encodes the real audience per canary instead.
6. **Extended-scan e2e case** (`OCW_PRESIDIO_URL=http://192.0.2.1:3000 … memory-proposals -g "extended scan"`) not
   rerun, for the same reason as item 3. Its two screenshots are FIX-WEB's, taken on the same UI code.
7. **Commits cut from verified trees.** Commits 2-4 were cut from one tree that passed `pnpm verify`, the way the fix
   rounds did it. Commits 1 and 5 each had their own run.
8. **AGENTS.md** got one line, the Memory and approvals row. "Built so far" lives in STATUS.md now, so the plan's
   separate Conventions bullet was folded into that row.

   Unknown event ids still answer memory calls instead of `no_trigger`.
