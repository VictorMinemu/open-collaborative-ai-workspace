## Phase Goal

**As an** Organization Admin and every member of the workspace, **I want to** arrange the company into departments, teams and projects with the four PRD roles, have every route decided by one permission resolver, and manage my own password, sessions and profile, **so that** each person and agent can do exactly what their role, units and rules allow and every sensitive change is attributed and audited.

**This plan's slice (AUTH-06 verification):** the browser WebSocket and every REST route accept short-lived JWTs verified against the JWKS, and revocation reaches open sockets instantly.

<objective>
Verify the JWTs issued since 02-03 everywhere a user connects (research §Pattern 5, D-01): `jose` + an in-process JWKS cache (never better-auth's per-call verifyJWT), Bearer on REST, the `ocw.auth.<jwt>` subprotocol on `/ws` (cookie-only upgrades rejected), the realtime client fetching a token before each connect and refreshing once on 4401, revocation fan-out closing sockets with 4401, and the device-token signer/verifier 02-11 needs.

Purpose: SC4 — "API and WebSocket connections authenticate with short-lived JWTs verifiable against a JWKS endpoint; the Phase 1 cookie-authenticated WebSocket moves to short-lived JWT/JWKS verification without breaking reconnect and replay".
Output: identity/jwt.ts, Bearer in authenticate.ts, gateway on JWT + revocation, realtime-client getToken, web token manager, tests.
</objective>

## Trust Boundaries

| Boundary | Description |

| browser → GET /ws upgrade | Untrusted Origin and subprotocol header; token must be verified before the upgrade |
| any client → REST with Authorization | Bearer strings of unknown type (user JWT, device JWT, device/cell tokens) |
| Redis pub/sub → gateway | Revocation messages trigger socket closes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-08-01 | Spoofing | forged/tampered JWT | high | mitigate | jose jwtVerify with EdDSA only, issuer + audience pinned, claims Zod-validated (strict); tampered/expired/wrong-aud tests |
| T-02-08-02 | Spoofing | device JWT used as user token (and vice versa) | high | mitigate | Distinct aud (ocw:device-link) and typ claim; strict AccessTokenClaims; cross-use tests |
| T-02-08-03 | Spoofing | revoked session keeps a valid JWT / open socket | high | mitigate | Redis revoked-sid check on every verify (TTL 900 s > 600 s exp); onRevocation closes sockets 4401; sid recheck every 5 min (Pitfall 5) |

| T-02-08-05 | Spoofing | cross-site WebSocket hijacking | high | mitigate | Origin allowlist checked before token verification (unchanged) and cookies no longer authenticate /ws |
| T-02-08-06 | Denial of service | JWKS refetch storms on unknown kids | low | mitigate | One refetch per unknown kid with a 30 s cooldown |
| T-02-08-07 | Elevation of privilege | deactivated member's JWT | high | mitigate | verifyAccessToken rejects deactivated members (org_members lookup); test |
