## Phase Goal

See `07.12-01-PLAN.md`. **This plan's slice:** the Control Plane side of terminal pairing (D-03, D-13): a short code a
server shows, approved by a signed-in owner, ending in today's device token through today's tested transaction.

<objective>
Implement RFC 8628-shaped device-code pairing on top of the existing enrollment path (PD-06): a pre-tenant pending
request in Redis, a `device.pair` approval that writes an ordinary `device_enrollments` row in the approver's tenant
with its audit, and a token poll that runs the existing enroll transaction, factored into `enrollWithCodeHash`. Limits
per IP and per user (PD-07), audit (PD-08), cross-tenant and permission tests. CLAUDE.md plan mode: permissions, audit
and tenant data change here.

Purpose: 03's CLI, 07's web dialog, 08's setup and 09/10's proofs pair through these routes.
Output: `enroll.ts`, `pairing.ts`, unit and integration tests, the allowlist entries.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous server → API | Start and poll are public; their bodies are untrusted |
| signed-in member → API | Lookup and decisions are user routes behind `device.pair` |
| Redis (pre-tenant) → PostgreSQL (tenant) | Approval moves a request into the approver's RLS-protected org |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.12-02-01 | Spoofing | device-code phishing (owner approves an attacker's host) | high | mitigate | Lookup shows name, platform, request IP and age; 07 shows the code to compare and a warning; the device is unshared by default; approval audited (PD-08) |
| T-07.12-02-02 | Elevation of privilege | a member guessing a live code from someone else's server | high | mitigate | 40-bit codes, 10-min TTL, 10/min per user across lookup+approve+deny, per-IP limits; the CLI prints the owner after pairing (03) |
| T-07.12-02-03 | Denial of service | poll and start hammering | medium | mitigate | `slow_down` per device code, 60/min and 10/10 min per IP |
| T-07.12-02-04 | Tampering | double approval / approve-deny race | medium | mitigate | Lua compare-and-set inside the approval transaction; PK on `code_hash`; Task 2 race case |
| T-07.12-02-05 | Information disclosure | codes in logs or URLs | medium | mitigate | Codes only in bodies; Task 3 log capture case; query strings already stripped |
| T-07.12-02-06 | Elevation of privilege | cross-tenant device | high | mitigate | Device created in the approver's tenant transaction (RLS); organization-B case |
| T-07.12-02-07 | Repudiation | unaudited decisions | medium | mitigate | `device.pairing_approved`/`denied` in the same transaction as the decision; `device.enrolled` with `via` |
</threat_model>
