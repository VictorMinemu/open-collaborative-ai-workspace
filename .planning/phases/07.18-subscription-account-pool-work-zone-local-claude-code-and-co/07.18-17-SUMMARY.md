# Phase 07.18 Plan 17: Admin docs, release notes, STATUS/DEMO, owner UAT and the phase gate Summary

The account pool is written down for admins, members and the release. It is the default and needs no member action
(D-15). The owner has a 13-step real-account checklist covering A-01 … A-05 and the security checks. Locally, lint,
guard and typecheck pass, and 10 853 tests pass after one testcontainers port flake was re-run.

## What was built

- **`docs/self-hosting/account-pool.md`** (Task 1, `afad227a`), in the house style of `connectors.md`. It opens with an
  intro naming Settings › Account pool, the default and ADR-0044 / ADR-0006, and a table of who uses what. Its 9
  sections:
  - **Who manages it and what members see:** labels only, the dialog, header and timeline lines.
  - **Add a Claude account:** `claude setup-token`, the token lasts a year, is sealed and never shown again, API keys
    are refused, "Paste a new token" → Replace the token. Also the Used by scope.
  - **Add a ChatGPT account:** For bots (cell device code; the pre-07.18 sign-in is already the first account) and on a
    server device (Settings, or `ocw-runtime account add codex --label …`, which arrives off; `account list` and
    `remove`).
  - **Pick a strategy:** a table with the UI labels ("Use one until its limit, then the next", Round-robin, Weighted),
    sticky per session, the bots note, the fallback switch.
  - **What happens at a limit:** cooldown to the reset (5 min … 7 days), the same turn re-runs, at most 3 switches, the
    sentences, needs sign-in.
  - **Where each credential lives:** a table of the Claude token, the device slot and the bot profile, plus the
    redirect guard and `apiKeyHelper`.
  - **Remove an account:** the per-kind sentences.
  - **Known limits.**
  - **The providers' terms:** quoted from ADR-0044, with "The organization owns the accounts and the risk."
- **`docs/releases/v0.4.0.md`** (Task 2, `92882a62`): the outcome line ("Work goes on when a subscription runs out …
  members do nothing").
  - **What's new:** the pool and the guide link, Claude, ChatGPT for bots and on a device, the three strategies, the
    switch, the member-visible lines.
  - **Fixes for bots on ChatGPT:**
    - from plan 16, a new sign-in after every bot account was removed now reaches the bots;
    - from the parallel gap fixes, turning every ChatGPT bot account off no longer signs them out, and Disconnect on
      Settings › Models also removes the pool's bot accounts.
  - **Upgrade:** server first, one additive migration (`account_pool`), nothing changes until an admin adds accounts,
    the existing bot sign-in becomes the first account, headless servers update with one click, devices that are not
    updated keep their own login, the desktop app needs the new files.
  - **Known limits:** A-01/A-02 not yet checked with real accounts and the fallback sentence, `apiKeyHelper`, weighted
    → round-robin for bots, the default model and no automatic title on a pool-only device, AI chats outside the pool,
    the terms risk.
- **`docs/STATUS.md`:** a "07.18 Subscription account pool (Phase 07.18)" entry after 07.17.1.1.2, in the house style:
  where, credentials, selection, limits, tests, limits.
- **`docs/DEMO.md`:** an "Account pool (Phase 07.18)" scenario before Troubleshooting (victor@ adds accounts, sam@ sees
  the pool line, the switch at a limit), plus the fake-limit note (`OCW_RUNTIME_FAKE_LIMIT_PREFIX`) and a pointer to
  the UAT.
- **`07.18-UAT.md`:** in the 07.10 UAT format (`gsd-verify-work` compatible). It has a setup that forbids writing
  tokens and 13 tests, each with steps, an expected result and a `[pending]` result:
  1. two setup-tokens;
  2. D-15, a member with no setup;
  3. **A-01**, a Claude switch and resume;
  4. the cooldown ends;
  5. two Codex slots (Settings and CLI);
  6. **A-02**, a Codex slot switch and resume;
  7. A-03, bots on ChatGPT in a real cell (adoption, remove one, all off and back on);
  8. A-04, order and the weighted note;
  9. A-05, bots on a setup-token rather than the API key;
  10. no token in the HAR;
  11. audit;
  12. no token on the device or in its journal;

## Deviations from Plan

1. **[Orchestrator instruction] Release notes file is `docs/releases/v0.4.0.md`, not `v0.3.7.md`.** This is a feature
   release after v0.3.6. `release.yml` reads `docs/releases/<tag>.md`, so the file matches the tag `v0.4.0`.
   `apps/local-runtime/package.json` is not bumped (the orchestrator does that at release time).
2. **[Orchestrator instruction] The CI half of Task 3 is not done here.** The worktree must not push, so there is no
   PR, no `gh pr checks` and no CI links. The acceptance check "at least 3 `https://` in the UAT" is therefore not met
   yet. The UAT has a CI table with a row per workflow for the orchestrator to fill after it pushes. No links were
   added only to satisfy the count.
3. **[Orchestrator instruction] The release notes list two fixes that land in parallel** (all ChatGPT bot accounts off
   no longer signs them out; a Disconnect on Models removes the pool's bot rows), from `deferred-items.md` 1 and 2.
   If the gap-fix agent's work does not merge, remove those two bullets before tagging.
4. **[Rule 3] STATUS.md has no Troubleshooting section** (that heading is in DEMO.md). So the STATUS entry follows the
   file's bullet-per-phase style at the end, and the DEMO scenario sits before DEMO's Troubleshooting.
