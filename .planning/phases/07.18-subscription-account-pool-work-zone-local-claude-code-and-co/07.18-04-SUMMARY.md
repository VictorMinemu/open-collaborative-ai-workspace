# Phase 07.18 Plan 04: Account selection and cooldown bounds Summary

Pure account selector for the subscription pool: failover in the admin's order, least-recently-used round-robin and
nginx smooth weighted round-robin (5/1/1 gives A A B A C A A and returns to zero state), plus cooldowns bounded to
5 min … 7 days from `POOL_LIMITS` and the earliest future reset. No database access; the caller (plan 09) filters
usable accounts, locks the policy row and persists `last_used_at` and `wrr`.

## What was built

- `pickAccount(strategy, candidates)` → `{ id, wrr } | null` (null for an empty list under every strategy).
  - Shared tie-break: priority asc, `createdAt` asc, id asc.
  - `failover`: first in that order; `wrr` unchanged.
  - `round_robin`: never used first, then smallest `lastUsedAt`, ties by the order; `wrr` unchanged.
  - `weighted`: add the clamped weight to each current value, pick the largest (ties by the order), subtract the total
    from the winner; returns the new state for every candidate. Ignores `lastUsedAt`.
- `cooldownUntil(resetsAt, now)`: null / now / past → now + `defaultCooldownMs`; beyond now + `maxCooldownMs` → capped;
  else the reset (T-07.18-04-01, T-07.18-04-02 mitigated).
- `isCooling(until, now)`: true only for a strictly future instant.
- `earliestReset(rows, now)`: soonest future `cooldownUntil`, else null.
