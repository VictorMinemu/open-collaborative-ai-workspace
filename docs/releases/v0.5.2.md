The desktop app **updates itself** on Windows, Linux (AppImage) and macOS, its runtime included, and never restarts in
the middle of a Work Zone turn. Install this version by hand once; the next ones arrive by themselves.

## What's new

- **The desktop app updates itself** (ADR-0046). It checks the project's GitHub releases once a day, downloads the new
  version, checks it against the release's SHA-512 and installs it on the next restart. The runtime inside the app is
  updated with it.
  - **Windows** (the per-user installer) and the **AppImage** update themselves.
  - **A Mac** updates itself when OCW runs from Applications in a folder it can write. Before the swap it checks that
    the new app's code seal is intact and that it is OCW at the expected version. If anything fails, the installed app
    stays as it was.
  - **The `.deb`** keeps **Update available** with the download link, now worded "download the .deb, or use the
    AppImage, which updates itself". It never installs packages as root.
- **Never in the middle of a turn.** **Restart to update** waits until no Work Zone turn runs on the computer and
  shows "Waiting for 2 sessions to finish…" meanwhile. New prompts wait at the gate and run right after the restart.
- **Your organization's level decides when** (Settings › Work Zone policy › Runtime updates, lowered per device in the
  app's Runtime menu):
  - *Automatic*: downloads in the background and installs when you quit OCW, or by itself when no turn runs and you
    have been away for 30 minutes.
  - *Notify only*: downloads, then waits for **Restart to update to v…**.
  - *Off*: no automatic check.

  **Check for updates…** in the tray and the Runtime menu works at every level.
- **Move OCW to Applications.** A Mac app opened from the disk image or a folder it cannot write offers **Move OCW to
  Applications to get automatic updates**.
- **Only real releases update.** Only builds made by the release workflow look for updates: an app you package
  yourself, or a fork's build, never replaces itself with this project's release. Stable releases only, never an
  older version.

## Upgrade

In `/opt/ocw` (or wherever the server is installed):

```bash
sudo node scripts/ocw.mjs upgrade --check   # current and newest release; changes nothing
sudo node scripts/ocw.mjs upgrade           # backup, this release, new keys, rebuild; never goes backwards
```

- **No migration.**
- **Install the desktop app v0.5.2 by hand once on each computer.** Older versions cannot update themselves. Quit OCW,
  then install the files below as before:
  - **Mac**: open `OCW-v0.5.2-macos-arm64.dmg` and drag OCW to Applications, replacing the old one. Open it once and
    choose **Open Anyway** in System Settings › Privacy & Security, or run
    `xattr -dr com.apple.quarantine /Applications/OCW.app` (only on the OCW app). Keep it in Applications: that is
    where it can update itself.
  - **Windows**: run `OCW-v0.5.2-windows-x64-setup.exe` (SmartScreen: **More info › Run anyway**).
  - **Linux**: prefer `OCW-v0.5.2-linux-x86_64.AppImage`, which updates itself. Rename it `OCW.AppImage` so later
    updates replace it in place and your shortcuts keep working. On the `.deb`,
    `sudo apt install ./OCW-v0.5.2-linux-amd64.deb`; later versions are a notice with the link.

  From then on, later releases arrive by themselves at the device's level.
- **Headless Work Zone servers** update their runtime to 0.5.2 as before, with one click (Settings › Devices › the
  server › Runtime updates › **Update**) or by themselves at the *Automatic* level.
- **For the repository's owner: turn on immutable releases.** In the GitHub repository, **Settings › General ›
  Releases**, enable **release immutability**. Published files then cannot be replaced or deleted, so no one can swap
  an update under the devices after a release is out. The release workflow already uploads everything to a draft and
  publishes last.

## Known limits

- **The builds are still unsigned** (until Phase 9). Each update is checked against the release's SHA-512, over HTTPS,
  from this repository only, but not against a publisher signature. Whoever can publish this repository's releases can
  ship code to every device, as with manual downloads today (ADR-0046 § 11).
- **On a Mac, each update is a new code identity.** macOS may ask again for Keychain access or for privacy permissions
  after an update, and the computer may need pairing again (**Pair this computer**). Signed builds will end this.
- **macOS may ask before an app changes another app** (Privacy & Security › App Management). If it refuses, OCW stays
  on the installed version and says so once; download the new version from the link.
- **Standard Mac users and the `.deb` get the link**, not an automatic install: a Mac user who cannot write
  `/Applications`, or the `.deb` package.
- **macOS builds are Apple silicon only**, as before.
- **A versioned AppImage name changes with each update** (`OCW-v0.5.3-linux-x86_64.AppImage`); the app says so once.
  Rename it `OCW.AppImage` to keep one name.
