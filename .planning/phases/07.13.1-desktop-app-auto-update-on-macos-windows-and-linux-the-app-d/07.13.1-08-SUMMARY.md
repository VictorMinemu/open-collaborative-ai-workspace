# Phase 07.13.1 Plan 08: ADR-0046, docs and the v0.5.2 runtime Summary

ADR-0046 records the unsigned desktop self-update: one updater per platform, the GitHub feed set in code, the
`appUpdateHold` gate, the 07.11 levels, and the ASVS 10.3.1 accepted deviation. It completes ADR-0032's scope clause
and ADR-0040's "desktop app auto-update (signed builds, MVP 2)" without editing either, and supersedes 07.13 D-18's
"no silent install". AGENTS.md has its row and still has 200 lines. README § 7, the v0.5.2 notes and STATUS tell people
how updates work, what to install by hand once, and what the unsigned builds still cost. The runtime is at 0.5.2, so
v0.5.2 can be tagged.

- **README § 7** has an "Updates" paragraph covering:
  - Windows and the AppImage update themselves; name the AppImage `OCW.AppImage`.
  - A Mac updates itself from Applications. From the disk image or an unwritable folder it shows the link and offers
    "Move OCW to Applications".
  - The `.deb` gets the link or can switch to the AppImage.
  - The level decides when (Settings › Work Zone policy › Runtime updates), and a restart waits for turns.
  - Install by hand once.
- **docs/releases/v0.5.2.md** follows the style of the v0.5.0 notes:
  - What's new.
  - Upgrade, with three points:
    - No migration. The desktop app is installed by hand once on each computer, with the per-OS steps. The Mac step
      keeps only the narrow `xattr` on `/Applications/OCW.app`. On Linux the AppImage is preferred and renamed
      `OCW.AppImage`; `.deb` users get the notice with the link.
    - Headless runtimes update to 0.5.2 as before.
    - The owner action: Settings › General › Releases › enable release immutability.
  - Known limits: the builds are unsigned (§ 11); each update gives a Mac a new code identity (Keychain or privacy
    prompts, maybe pairing again); App Management may ask; standard Mac users and the `.deb` get the link; Apple silicon
    only; versioned AppImage names change.
