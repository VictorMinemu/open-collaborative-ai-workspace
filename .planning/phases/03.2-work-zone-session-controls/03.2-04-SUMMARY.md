# Phase 03.2 Plan 04: Work Zone policy, intersection and per-turn mode Summary

Org Work Zone policy (admin-only, audited) plus one server-side intersection — policy ∩ device opt-in ∩ device cap ∩ `device.full_access` grain ∩ runtime catalog ∩ inventory — enforced on every settings change, every new session and every dispatched turn, with live downgrades/stops when anything tightens and a fail-closed stop when a device reports Full access without authorization.

## What was built

- **Policy (Task 1, D-02, D-11):** `work-session/policy.ts` (tolerant `fromRow`, `loadWorkZonePolicy`, `saveWorkZonePolicy` with changed top-level keys and 400 `empty_modes`, `knownModels` from non-revoked devices' catalogs). `GET/PUT /api/v1/work-zone-policy` behind `work_zone.manage`; `work_zone_policy.updated` audited only when something changed; a changed policy reauthorizes every active session of the org.
- **Grain and caps (Task 2, P-06, P-08):** relation `full_access_grantee`; `RELATION_PERMISSIONS.device` per the plan; `deviceResource({…, cap})` (legacy behaviour when `cap` is omitted). `device/access.ts` pure `deviceModeCap` (owner → fullAccess; else highest of everyone-share and current user/unit grants), `deviceControllerFloor` (min(acceptEdits, shareMaxMode, lowest current grant)), `isRevokedPrincipal`, and `loadDeviceAccess` (one grants read + unit paths). Device list, `/projects`, PATCH/DELETE device, session create and `/work-zone/controls` use it, so listed grantees are users of the device.
- **Controls (Task 2):** `controls.ts` gains the inventory gate (`exposed`, default `isExposed(runtime, uiKey)`), the full reason precedence, `CONTROLLER_FLOOR`, `authorModeCap`, `highestAvailableMode`, `turnMode`, `clampToControls`; `decideSettings` checks context-window availability. `context.ts` `loadControlsContext` is the single loader used by GET controls, PATCH settings, POST create, GET `/work-zone/controls`, dispatch and reauthorization. PATCH audits `work_session.full_access_entered` / `work_session.full_access_left`.
- **Per turn and downgrades (Task 3, P-07, D-03, D-04):** `tryDispatch` computes each prompt author's mode, writes it to the prompt payload and `work_prompts.permission_mode`, audits `work_prompt.dispatched` (`requestedMode`, `effectiveMode`, `capped`, `fullAccess`); a null cap fails the prompt with `work_prompt.refused` (`access_revoked` / `mode_not_allowed`) and moves to the next prompt. `reauthorize` / `reauthorizeOrg` / `onAccessChanged` stop sessions whose creator lost access (`work_session.access_revoked`, "Access to <device> was revoked") or clamp and send `session.configure` (`work_session.settings_downgraded`, `full_access_left`, interrupt of a Full access turn). `hub.onCapabilities` calls `onAccessChanged(…, "device_opt_out")` when the opt-in goes true → false. `apply` refuses unauthorized Full access/bypass reports on `session.settings` and `session.started` (interrupt + stop, `failed`, `work_session.unauthorized_mode`, value not stored).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3] Contract shape of per-runtime policy keys** — `UpdateWorkZonePolicyRequest` is shallow-partial, so `maxEffort` / `allowedModels` must carry both runtimes. Tests send `{ "claude-code": …, codex: … }` instead of changing the P-01 contract.
**2. [Rule 2] Session create never starts above the creator's cap** — the start mode was only checked when it differed from `default`; now an explicit mode is refused with its reason and the implicit default is lowered (7e90d8a).
**3. [Rule 1] Non-contiguous policies** — `min(session, cap)` could yield a mode the policy left out (e.g. `[plan, acceptEdits]` with a `default` session); dispatch uses `highestAvailableMode(ctx, model, sessionMode)` instead (7e90d8a/e19a681).
**4. [Rule 2] Downgrades never raise a mode** — the first `clampToControls` fell back to the lowest available mode, which could raise a plan-mode session; fixed with a unit test (e19a681).
**5. [Rule 2] Interrupt the Full access turn in flight on a downgrade** — otherwise an opted-out device or a Full-access-off policy would let the running turn finish in Full access (e19a681, tested in the opt-out case).
**6. [Rule 2] D-03 check also on `session.started`** (tested).
**7. [Rule 3] Extra files** — `work-session/context.ts` (the DB loader kept out of the pure `controls.ts`), `testing-workzone.ts` (shared fixtures), and `BuiltApp.deviceHub` in `app.ts` (tests call `onAccessChanged` / `reauthorizeOrg` directly).
**8. Test adaptation** — settings.int's "model switch drops effort" seeds the requested effort through SQL, and the `auto` assertion uses `isExposed`, because Claude effort and `auto` are `not_confirmed` until Plans 02/03 confirm them.
