# Phase 07.17 Plan 11: The open tool on fan-out run turns Summary

**Runs of fan-out automations now offer `ocw_conversation_open` with their remaining caps (`automationRun.fanOut`, counted since the automation's local midnight). Every agent-turn run carries its re-validated escalation targets. Every other turn is unchanged byte for byte.**

## Performance

- **Duration:** about 12 min
- **Completed:** 2026-11-10T10:05Z
- **Tasks:** 2 of 2
- **Files modified:** 7

## Accomplishments

- **turnPolicy offer.** `turnPolicy` takes `conversationOpen`, which the caller computes; bot-capabilities never imports automation. The tool is appended last, and only when a slot is free.
- **Delivery wiring.** `AgentMention.conversationOpen` is set only by `deliverAutomationRun`. `buildMentionEvents` forwards it only for `trigger: "automation"`.
- **fanOutOffer.** `fanOutOffer` in the runner gives `remainingDay = max(0, perDay − rows since localDayStart(now, zone))` and `remainingRun = min(perRun, remainingDay)`. A row from yesterday in the automation's zone does not count.
- **Escalation.** Every `agent_turn` delivery calls `escalationFor`, so gone targets drop out. `automationRun.escalation` is present only when the list is not empty.
- **E9 proofs.** The fan-out-off run's turn deep-equals `turnPolicy` without the offer (every key but `now`), and its `automationRun` keys are the 07.16 set. The fan-out turn is that same turn plus one trailing tool and flag. The existing exact `automationRun` `toEqual` in the 07.6 tracer passes unchanged.

## Decisions Made

See `key-decisions`. The most consequential one: `fanOut` goes on the event only when the tool actually made it onto the turn. Without that, a turn already full at 64 tools would carry fan-out caps for a tool the bot cannot call.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Coverage] The ADR-0038 §12 case lives in `work-session-offer.int.test.ts`**
- **Found during:** Task 2
- **Issue:** The behaviour to prove is "no `ocw_work_session_*` on a fan-out run even when the bot's profile is active". It needs a paired device, a consent and an active profile. That fixture exists only in `work-session-offer.int.test.ts`, which is not in `files_modified`.

**2. [Rule 1 - Correctness] `automationRun.fanOut` is gated on the tool being on the turn**
- **Found during:** Task 1
- **Issue:** The plan sets `automationRun.fanOut` whenever the runner's offer is present. A turn already at `MAX_TURN_TOOLS` drops the tool, so it would still have announced the caps.
- **Fix:** `fanOut` is written only when `ev.turn.tools` includes `ocw_conversation_open`. Proven by the 64-tool case.
- **Committed in:** `0e90a208`
