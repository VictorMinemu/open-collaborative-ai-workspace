# Phase 07.4 Plan 14: Phase gate: journey, ledger fixes, ADR-0025 and the full gate Summary

**Phase 07.4 is proven end to end in a real browser and the whole local gate is green. Each member's own account answers
for them through the same shared bot, in a DM, in a shared channel once they allow it, and with a key the bot only sees
by handle. Seven ledger items are fixed at their source, each with a test that failed first. One real bug found by the
gate itself is fixed too. ADR-0025 is Accepted and VALIDATION is signed.**

## What was built

- **The journey (Tasks 1-2), `connectors-journey.spec.ts`, desktop and mobile.**
  - Víctor asks Relay in their DM and gets the "Connect your Pipeline CRM account" card.
  - **Connect** opens Settings › Connections with the row highlighted. He signs in at the fake provider and **Back to
    chat** returns him to the same DM. Asked again, the bot answers with his own subject, which Settings shows as
    `as sub_…@fake-mcp.test · last used just now`.
  - Sam asks the same bot: he gets his own card, never Víctor's data. Once connected he gets a different subject.
  - In a private `#ops` the tool is withheld. The reply links "Allow Pipeline CRM in #ops", and the dialog says
    "2 people can read results here" before Allow. Once allowed, the call returns his subject; after Revoke it is
    refused again.
  - Víctor's personal key is used by handle from his personal bot's DM: the fake answers
    `{"authorized":true,"method":"bearer"}`. No cell event, request, reply, page or API response carries the key.
    Keychain shows `1 bot · last used just now`, and `secret.used` carries host `fake-mcp:4291`, method `GET`, status
    200 and no value.
- **The fake cell (`FakeCellPlugin`)** now calls `/connectors/list|call` and `/http-requests` like the real plugin. It
  takes the persona's decisions (`toolCallsFor`) and writes the `member_account` allow links.

## Deviations from Plan

### Auto-fixed issues

1. **[Rule 1] Unit deletion 500 with 07.4 data.** Found by the gate and fixed in `b0e3fb6a` (above).
2. **[Rule 1] Stale `connectors.spec` expectation (`your DM with Sam Lee`).**
   - 07.4-12 made the API name DMs for the viewer, and 07.4-13's spec, built in parallel, still expected the web
     label.
   - The spec and the web fallback now use the API's wording (`2900a3e8`).
3. **[Rule 3] The persona's allow link opens in a new tab.** Chat Markdown opens every link with `target=_blank`
   (ADR-0016), so the journey follows the new page instead of expecting the same tab. See the new ledger items.
4. **[Rule 2] Nav entry.** Withdrawal needed a way in, so the Connections nav entry stays visible while the member
   still has a connection or a share.
5. **[Rule 3] e2e cleanup.**
   - The journey deletes its connector with `clearConnections` in `afterAll`. The mobile `mcp-servers` cleanup
     otherwise met a member connection and got 409.
   - `admin-org.spec` clears unit keys and templates.

### Plan text vs. what was built

- The plan's Task 3 asked for a separate AGENTS.md security-rule line. The brief allows one line, so the egress rule
  is inside the new stack row.
- The plan listed the regression specs to run. The gate ran the full suite instead, which includes them.
- `connectors-journey` screenshots add `journey-share-dialog-*` beside `journey-share-*`, so the reply and the dialog
  are separate files.
