# Phase 07.17 Plan 18: The owner's fan-out scenario in the browser Summary

**One Playwright spec runs the whole owner scenario on desktop and phone, light and dark: an automation every 10 minutes opens a card per new ERP order, dedupes on the next runs, each card's turn runs its own Work Zone session and its wake moves the card to Done mentioning @logistics, Logistics hears it and Eva doesn't. A person's @log picks the team from the composer. The fake ERP has a new `__add` hook and the fake cell mirrors the plugin's open, item and card-wake turns.**

## Accomplishments

- Fake ERP `__add { id, fields }`: a new order made "elsewhere". It is callable but never listed, and an existing id is `isError "exists: <id>"`.
- Fake cell (PD-22), only when a spec sets the hooks:
  - `fanOutFor`: one `ocw_connector_call` of `list_records`, then exactly the plugin's `{ eventId, agentId, items }` to `/conversations/open`, then `Opened <n>, existing <m>`.
  - `itemCallsFor`: awaited, runs in the card's thread, and remembers the item's escalation.
  - `wakeCallsFor`: on `turn_done` in a remembered thread, the read and the move, then `Done: <last output line> @<handles>`.
  - Tainted and session-read turns move cards the way the plugin does: no board read, version memory, one 409 retry.
- `automation-fan-out.ts` sets up the people and the Logistics team under Supply chain, a fresh `fleet-…` board per attempt, Atlas's 07.16 profile and consent, the orders and the API body for the phone run.
- `automation-fan-out.spec.ts` has 9 serial tests on both projects:
  - creating the automation in the editor (desktop) or through the API with an editor check (phone);
  - orders, then cards in Backlog and the runs thread, then dedupe;
  - sessions, In progress, the held turn, Done and the `@logistics` chip;
  - Cam's mention, and nothing for Eva in the API or the badge;
  - Dan's Teams pick, the unit chip and Cam's count going up by exactly one;
  - Cam's inbox opening the card thread;
  - a third Run now, and the Runs tab chips.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] PD-22's "read, then move" would be refused on a tainted turn**
- **Found during:** Task 1
- **Issue:** Item turns and card wakes are tainted or have read a session. The API refuses `/board/read` for them, and the plugin refuses `read` and `create` locally (07.17-09).
- **Fix:** The fake now moves the card without reading the board. It starts at the version it remembers (1 for a just-opened card) and retries once on a 409 at `details.card.version`. Untainted turns still read first, so `board-agents.spec.ts` keeps its behaviour, and a unit test pins that.
- **Files modified:** `e2e/support/fake-cell-plugin.ts`
- **Commit:** `ba5ba385`

**2. [Rule 3 - Blocking] The fake ERP's `list_records` lists every record**
- **Found during:** Task 1
- **Issue:** It also lists the seed orders and any added by earlier specs or attempts.
- **Fix:** `fanOutFor` returns `select`, and the spec keeps its own order ids. `addOrders` accepts an order that already exists, because the fake keeps records for the whole run.
- **Files modified:** `e2e/support/fake-cell-plugin.ts`, `e2e/support/automation-fan-out.ts`
- **Commit:** `ba5ba385`

**3. [Plan wording] "Doing" is "In progress"**
- The default board columns are Backlog / In progress / Done / Cancelled, so the spec uses the real started column.

**4. [Rule 2 - Correctness] `__add` is not in tools/list**
- **Issue:** Listing it would add a tool row to every connector that records `FAKE_ERP_TOOLS` (4 integration test files) and to the per-member probes in `watched-records.spec.ts`. That is a silent change to other suites.
- **Fix:** `UNLISTED_HOOKS` in the fake ERP. The `.d.mts` documents the hook beside `FAKE_ERP_TOOLS`.
- **Commit:** `ba5ba385`

No component bug was found locally. Any a11y or layout failure CI reports gets fixed at its source with a failing test first.
