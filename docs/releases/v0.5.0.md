Claude Code and Codex sessions get a **browser on the session's own device**, its localhost included, so an agent can
open the app it is building, read the page and click through it. The session's audience watches it live, and the
person who asked can take control to sign in to a site; that sign-in is saved for them only.

## What's new

- **The browser tools** (ADR-0035). In a Work Zone session the agent opens one page at a time on the device that runs
  the session: open, read, click and type, wait, take a screenshot and close. It reads the same redacted page a bot
  reads (passwords, one-time codes and secret fields show as `[redacted]`), and page content is treated as untrusted
  input, never as instructions. Only `http` and `https` pages open. The timeline shows the host and the action, never
  the page's text.
- **Off until both sides turn it on.**
  - **Settings › Work Zone policy › Browser** (admins): **Allow the browser in Work Zone sessions**.
  - **The device's owner**, on each device: **Allow the browser on this computer** in the desktop app's Runtime menu,
    or `ocw-runtime browser on` on a headless server (`ocw-runtime browser status` shows the state).
  The device checks both again before every tool call. A session on a device that has not updated yet says "Update
  this device to use the browser" instead of failing.
- **Approvals for new sites.** The first page of a host in a session asks once (the request shows `host:port`);
  `localhost`, `127.0.0.1` and `[::1]` never ask. Full access skips the prompts, and the per-tool approval rules an
  admin sets for `ocw_browser_*` still win.
- **The Browser tab** of a session shows the page live to everyone who can see the session (in the ⋯ menu on phones).
  The device sends frames only while someone watches.
- **Take control.** The person who asked the current or last turn presses **Take control** and uses the page with
  their own mouse and keyboard, for example to sign in. The agent waits meanwhile, and everyone else sees "Private
  sign-in in progress". The agent can also ask for it ("Claude needs you to sign in to github.com"); **Not now**
  declines.
- **"Done, save my sign-in"** hands the page back and saves that site's sign-in for you: only that site's cookies and
  storage, sealed on the server. Later sessions of yours load it automatically when the agent opens that site, on any
  device that runs your sessions. **Done** hands back without saving anything.
- **Settings › Keychain** lists these sign-ins under **Work Zone**, next to the bots' sign-ins, with their expiry (at
  most 30 days, or less if the organization sets less). **Revoke** one and it stops loading; a page that has it loaded
  closes. Bots' sign-ins and Work Zone sign-ins are never shared.
- **The desktop app says "Update available"** in its tray menu and window when a newer release is out, with the
  download link. It does not install anything by itself.

## Upgrade

In `/opt/ocw` (or wherever the server is installed), upgrade the server first:

```bash
sudo node scripts/ocw.mjs upgrade --check   # current and newest release; changes nothing
sudo node scripts/ocw.mjs upgrade           # backup, this release, new keys, rebuild; never goes backwards
```

- **One migration**, additive (`work_zone_browser`). The browser stays off until an admin turns it on in Settings ›
  Work Zone policy: sessions run exactly as before.
- **Headless Work Zone servers on v0.3.1 or later update their runtime to 0.5.0** with one click (Settings › Devices ›
  the server › Runtime updates › **Update**), or by themselves at the *Automatic* level. The switch waits until no turn
  runs.
- **Runtimes older than v0.3.1 need the install command once**: re-run it from **Settings › Devices › Add a device ›
  Server**, then `ocw-runtime service restart` when no session runs. From then on updates are one click.
- **The browser downloads on first use**: the pinned Chrome for Testing headless shell, about 100 to 126 MB depending
  on the platform, checked against its SHA-256, into `~/.ocw/browsers`. To fetch it ahead of time, run
  `ocw-runtime browser install`. It is not inside the desktop installers, and the device's own Chrome is never used.
- **On Linux**, `ocw-runtime doctor` checks the browser: it prints the one `apt-get install …` line for missing
  libraries and, on Ubuntu 23.10 or later, the AppArmor line that lets the browser use its sandbox. The runtime never
  runs `sudo` itself.
- **Recommended agent versions move** to Claude Code 2.1.332 and Codex 0.172.0. The oldest supported versions do not
  change.

The desktop app does not update itself: install the new files below. Its runtime ships inside it.

## Known limits

- **One page per session.** No downloads, no uploads and no visible browser window on the device.
- **Sign-ins work only in sessions only you can see** (yours, or a project only you and the device's owner can read).
  In a wider session the agent is told so, and nothing loads.
- **The device is the boundary.** The device's owner, and programs running as the device's user, can reach the browser
  while it is open, a loaded sign-in included. The sign-in dialog says so; sign in only on devices you trust.
- **Screenshots need a model that reads images.** Codex sends screenshots to the model as images; with a text-only
  model the screenshot tool says it needs an image-capable model.
