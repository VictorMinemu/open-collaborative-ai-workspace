# Phase 07.17.1.1.2 Plan 07: The task offer Summary

**Each delivered turn now gets the task tools and task facts its situation allows. The decision comes from `taskOfferFor` and is gated by `computeTurn.longTasks`. The new `task` trigger has no browser, still lists the thread's files and gets the Work Zone offer. At the daily limit it stops quietly through `onLimitReached`. A task's own turns list its ended background processes once each.**

## Intended change (CLAUDE.md plan mode: permissions and tenant data)

- `taskOfferFor(tx, …)` reads the bot's single active task in the turn's thread. It runs inside the caller's tenant transaction, with an explicit `organization_id` filter on top of RLS. The thread key is null in `dm` and `group`, otherwise the thread root.
  - `ai_chat` gets nothing.
  - **Control**: the turn's event is the task's `current_event_id`, or the asker is the requester and the task is `waiting`.
  - **View**: every other turn in that thread.
  - **Start**: no active task, on `mention`, `reply_mode`, `work_session` or `automation_item`.
  - Otherwise no offer.
- `turnPolicy` appends the tools only after `computeTurn`, the consult tool, attachment read, the Work Zone block and conversation-open (P3: a task never widens a turn). It does so only while `computed.longTasks` is true.
  - start gets all three tools; control gets continue and finish.
  - The tools use `TASK_TOOL_FLAGS`. On a full turn the last non-platform tools are evicted, all or none.
  - `turn.task` is set for control and view. `agent_turns.task_id` is set for control only.
- No new permission, grain or RLS change. Nothing about a task reaches `message.text` (P4).

## What was built

- `apps/api/src/lib/chat-agent-bridge.ts`: `"task"` added to the trigger union, plus `AgentMention.task { taskId, reason?, process? }`.
- `apps/api/src/modules/agent-channel/task-offer.ts` (new):
  - `taskThreadKey` and `turnTaskOf`. `turnTaskOf` builds `TurnTask` from the row. On control turns it also lists up to `finishedProcessesMax` ended, unreported processes, ordered by `ended_at`.
  - `markProcessesReported`, `taskOfferFor` and `TaskOffer`.
- `apps/api/src/modules/agent-channel/mentions.ts`:
  - The offer is computed per bot.
  - `taskTurn` is part of `unattended`, which only turns the browser off. `listsFiles = !unattended || taskTurn`.
  - `taskTurn` is added to the Work Zone offer condition.
  - At the limit, `taskLimitReached` records the audit with `notified: false` and calls `deps.onLimitReached`. There is no claim and no post.
  - After a delivered control turn, the listed processes are marked reported.
- `apps/api/src/modules/bot-capabilities/turn-policy.ts`: `TurnTaskOffer`, `TASK_OFFER_TOOLS`, the task block, `turn.task` and the ledger `taskId`. `TurnTaskOffer` is exported from `bot-capabilities/index.ts`.
