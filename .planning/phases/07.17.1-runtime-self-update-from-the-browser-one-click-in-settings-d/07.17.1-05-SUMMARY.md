# Phase 07.17.1 Plan 05: Daemon prepare and switch Summary

**The device can now build the runtime its workspace serves in `versions/<sha12>` beside the running one (sha256 and
byte cap against the strict manifest, hash-checked lockfile, `npm ci --ignore-scripts` with a fixed argv and filtered
env, preflight), and switch `current` to it atomically behind a 0600 run marker. Nothing calls it yet (08 decides
when, 10 restarts).**

## Accomplishments

- `prepareVersion` in the PD-07 order: scratch-home guard (tests) → Node major → free space (statfs failure does not
  block) → reuse of a complete build → staging download (streamed, hashed, capped; `redirect: "error"`) → lockfile
  hash then `runtimeExternalFiles` → `package.json` and `npm-shrinkwrap.json` as install.sh writes them → `npm ci` →
  preflight → rename. Staging is removed in a `finally`.
- `serverRuntimeUrl` mirrors install.sh's http rule (https; http only for `localhost` / numeric `127.*` or
  `OCW_INSTALL_ALLOW_HTTP=1`); `127.0.0.1.nip.io` and `127.1..1` are refused.
- `switchToVersion` + `SelfUpdateMarker`: marker → `current.tmp-<pid>` → rename over `current` → `install.json`
  (0600, `config.serverUrl`, new version/sha256, old `nodePath`). The previous version stays.
- `runFixedCommand` exported from the 07.11 runner. `runUpdate` is unchanged.
- The fake npm has a `ci` role, and a harness lets plans 07, 08 and 10 reuse the scratch home, the stub and the fake npm.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Security/PD-19] npm lookup limited to node's directory and the daemon's PATH**
- **Found during:** Task 1
- **Issue:** `findExecutable("npm", env)` also scans `~/.local/bin`, `~/.npm-global/bin`, `/opt/homebrew/bin` and `/usr/local/bin`. With `npmPath: null`, a test could reach the real npm and its registry, and `npm_missing` could not be tested reliably.
- **Fix:** `resolveNpm` tries the explicit `npmPath`, then `<dirname(execPath)>/npm`, then `npm` on `env.PATH` only. Under `requireScratchHome`, an npm whose realpath is outside the OS temp directory throws `outside_scratch_home`. A-07 still holds: npm sits next to the service's node.
- **Files:** self-update.ts. **Commit:** 35e69779

**2. [Rule 2 - PD-25] Unexpected fs errors never leave as raw messages**
- **Issue:** errors from mkdir, write and rename during prepare name absolute paths.
- **Fix:** they map to `disk_full` (ENOSPC/EDQUOT) or `switch_failed`. The original error is kept as `cause`, and a scrubbed `detail` goes to the log.
- **Commit:** 35e69779

**3. [Rule 2] `SelfUpdateError.detail` (scrubbed) and `cause`**
- These keep the underlying text (npm output, HTTP status, zod error) for the caller's local log only. The message is always the sentence. Plans 08 and 10 should log `err.detail` and send only `err.message`.

**4. Harness surface wider than the hub's sketch (additive)**
- `DistStub` also has `bundle`, `lock`, `redirectRequests` and `bundleClosedEarly`.
- Extra exports: `testLock`, `testManifest`, `layOutVersion`, `HOST_PATH_TOKEN_RE`, `SCRATCH_NODE_PATH`, `STUB_SDK_VERSION`, and `ScratchHome.nodePath`.
- `scratchOcwHome()` installs 0.3.1 by default. With `installed: null` nothing is installed and `oldSha12`/`oldSha256` are `""`.
- The "unknown manifest key" case uses an injected `fetch` rather than a seventh stub mode.

**5. Preflight on a reused build.** The hub covers reuse only as "no bundle request, no npm". The preflight still runs on a reused directory, as install.sh does.

**6. A failed `install.json` write after the link moved is not fatal.** See the key decision. A `switch_failed` at that point would report a failure even though `current` already points at the new version.

**7. Task 2 RED passed on first run.** Task 1's action already required the failure enum, the sentences and the stub modes, so the T2 cases passed straight away. To check they test real behaviour, I made three targeted mutations: removed `redirect: "error"`, removed the lock hash check and disabled the disk floor. They made E3, E5 and E9 fail (3 failures), and the file was restored with `git checkout`. T2 therefore has a `test(...)` commit only.

**8. A declared `content-length` that differs from `manifest.bytes` fails `checksum` before reading.** This is extra protection on top of the streamed cap.

**Total deviations:** 3 auto-fixed (Rules 2), 5 documented scope/shape notes. **Impact:** no change to any cross-plan
name in the hub. The harness and the error class are only additive.
