## Phase Goal

See `07.17-01-PLAN.md` (PD-05, PD-06, PD-15, PD-17). **This plan's slice:** an automation can be told to fan out and whom to
mention, and a fan-out automation's runs live in one "<name> · Runs" thread instead of one card per run (Pitfall 3).

<objective>
Accept and validate `fanOut` and `escalation` on create and update, return them in the DTO, post the run log root and
anchor fan-out runs in its thread, add `escalationFor` for delivery, count `opened` per run, audit the settings, and prove
non-fan-out runs unchanged (D-02, D-08, D-10, D-16, PD-05, PD-06, PD-15, PD-17).

Purpose: the open route (16) answers the run; the run log keeps a 10-minute poll from flooding the target.
Output: service and targets changes, one new module, one new integration file, runner suite additions.
</objective>
