# Phase 1 — Deviations log

Deviations from `01-BUILD-SPEC.md` / `01-RESEARCH.md`, with the reason for each. Newest at the bottom.

## Stage A (platform core), 2026-10-02

No stack fallback was needed. TypeScript 7.0.2, pnpm 12.8.1 (via `packageManager` + corepack), Drizzle
1.0.0-rc.4 and turbo 2.11.x all work as the research described.

| # | Deviation | Why | Impact |
|---|-----------|-----|--------|
| A-1 | `minimumReleaseAge: 10080` (7 days) picked slightly older patches than the research table: better-auth 1.7.6, @better-auth/core 1.7.6, turbo 2.11.4, biome 2.5.14, vitest 5.0.2, next 16.3.6, redis 6.2.1, @fastify/swagger 9.9.0, @scalar/fastify-api-reference 1.72.1, pg 8.23.0. `pnpm` and `@pnpm/exe.*` are excluded from the age gate (`minimumReleaseAgeExclude`), because the package manager is pinned separately. | Supply-chain policy from the research. | None functionally. Bump deliberately once versions mature. |
| A-2 | Tenant RLS is applied generically by `packages/db/sql/post-migrate.sql`. It loops over every `app` table with `organization_id` and applies ENABLE + FORCE + the `tenant_isolation` policy with `nullif`. Policies are not declared per table with Drizzle `pgPolicy`. | drizzle-kit never emits FORCE. A generic step also covers new tables automatically, so B1/B2/B3 only add Drizzle tables. | The enumerator test (`packages/db/src/rls-isolation.int.test.ts`) still proves every table. New tables need one fixture row in `seedOrg()`, otherwise the test fails. |
| A-3 | `ocw_migrator` is `BYPASSRLS`. | It owns three narrow `SECURITY DEFINER` lookup functions used before the tenant is known: `app.lookup_device_token`, `app.lookup_agent_credential`, `app.lookup_device_enrollment`. Each returns only the ids needed to open `withTenant()`. | `ocw_app` stays NOSUPERUSER NOBYPASSRLS (asserted by a test). `ocw_migrator` is used only by the one-shot `migrate` service. |
| A-4 | `ocw_auth` has an `auth_plane` policy with full access to `app.audit_events` (SELECT/INSERT only, by grant) and `app.org_members`. | better-auth writes the identity-plane audit rows and the members projection in its own transaction, without tenant context. | `ocw_auth` is the trusted identity-plane role and already reads every user/session. |
| A-5 | `app.org_members` has a surrogate `id` column (uuidv7, unique) next to its (org, user) primary key. `auth.instance_setup` uses a unique `singleton` boolean instead of a text PK. | better-auth's adapter requires a uuid `id` on every model it writes, and it generates or omits ids itself. | None. |
| A-6 | Same-transaction audit for setup, invitation create/revoke and accept/sign-up: the research spike passed. `runWithTransaction` + `getCurrentAdapter`, with an internal better-auth plugin that exposes `auditEvent` / `orgMember` / `instanceSetup` as adapter models, rolls everything back on an injected failure (`apps/api/src/identity.int.test.ts`, test "SPIKE"). | — | No fallback needed (A3 resolved). |
| A-7 | `user.signed_in` is audited in a separate `withTenant` transaction after better-auth answers 200. `member.joined` is appended after acceptance commits, also in a separate transaction. | Sign-in has no domain write to share a transaction with (research Pattern 10). `member.joined` is a realtime hint. | Documented. |
| A-8 | The API runs TypeScript through `tsx` in production (`node --import tsx src/main.ts`). There is no build step and no bundle. | Speed. Workspace packages export raw `.ts`. | Slightly slower cold start. A bundle (tsdown/esbuild) can come later without code changes. |
| A-9 | The browser calls the API directly at `OCW_PUBLIC_API_URL` (`:4000`) with CORS and credentials. There is no reverse proxy. The web reads the URL at request time, so the Docker image is not tied to one host. | Research Alternative A9. Cookies are host-scoped, so `localhost:3000` and `:4000` share the session. | Hosting on two different hostnames needs a proxy (Caddy, Phase 7). For a LAN demo, set both URLs to the LAN host and add it to `OCW_TRUSTED_ORIGINS`. |
| A-10 | `compose.yaml` does not set a fixed project `name`. | Each worktree gets its own Docker project instead of colliding. | Host ports still collide between parallel stacks. Override `OCW_WEB_PORT`, `OCW_API_PORT`, `OCW_POSTGRES_PORT`, `OCW_REDIS_PORT` in `.env`. |
| A-11 | `apps/web` commits the `AGENTS.md` / `CLAUDE.md` that Next 16 regenerates on every `next dev`. | Otherwise they show up as untracked files forever. | None. |
| A-12 | Operational: Docker Desktop ran out of disk during the first image build. Only unused build cache was pruned (`docker builder prune -f`, 14 GB). No images or volumes were touched. | Unblock the build. | None. |

## Desktop (B4, apps/desktop), 2026-10-02

Run: `pnpm --filter @ocw/desktop dev` (build + Electron; first-run default server `OCW_WEB_URL` or
`http://localhost:3000`). Package: `pnpm --filter @ocw/desktop package:mac` → `apps/desktop/release/mac-arm64/OCW.app`
and `release/OCW-0.1.0-arm64.dmg`. Smoke: `pnpm --filter @ocw/desktop test:smoke` (Playwright `_electron`,
isolated profile via `OCW_DESKTOP_USER_DATA` + `OCW_HOME`, fake enrollment API, real web on :3000 if up).

| # | Deviation | Why | Impact |
|---|-----------|-----|--------|
| D-1 | The main window loads the web app URL instead of a bundled renderer (DESK-01). Only onboarding and the offline page are bundled. | One UI codebase for the demo; the web app already works in a hardened window. | Needs a reachable server. Offline page retries every 5 s. |
| D-2 | The preload exposes `window.ocwDesktop = { isDesktop, platform, status(), addProject({name?}), listProjects(), onStatus(cb) }` instead of the spec's `ocw.desktop.{status, addProject, openInEditor}`. `openInEditor` is **not** implemented. | `shell.openPath` on a path chosen by remote content can run `.app`/`.command` files. That needs an editor allowlist first. | The web app feature-detects `window.ocwDesktop` (type in `apps/desktop/src/shared/desktop-api.d.ts`). |
| D-3 | The device token is stored with `safeStorage` (Keychain) in `<userData>/desktop.json` and passed to the daemon as `OCW_DEVICE_TOKEN` at spawn. The daemon deletes it from its env on read. No token file is written. | The daemon already supports the env var. | The token is visible in the daemon's initial environment to the same macOS user (`ps -E`) until the daemon removes it. That is acceptable versus a plaintext file. The desktop app enrolls itself over HTTP and does not use B3's `ocw-runtime enroll` CLI. |
| D-4 | Pairing calls `POST {api}/api/v1/devices/enroll {code, name, platform}` itself. The code is sent trimmed but not case-normalised. | Contract from B3. | The API should normalise code case if codes are shown uppercase. Not yet verified against the real endpoint (missing in this worktree); tested against a fake. |
| D-5 | The daemon runs as `Electron --run-as-node` (`ELECTRON_RUN_AS_NODE=1`, Node 24.21 inside Electron 44.4.5) in its own process group (`detached`). Override with `OCW_DAEMON_NODE` / `OCW_DAEMON_ENTRY`. The pidfile `<OCW_HOME>/desktop-daemon.pid` is reaped on start. A daemon already answering on the socket (started by hand) is adopted, not replaced. | ADR-0005 standalone process with no system-Node requirement. | Quitting the app stops the daemon (SIGTERM to the group, SIGKILL after 5 s), so sessions do not survive quitting the app. Closing windows does not stop it (the app stays in the menu bar). |
| D-6 | The packaged app ships `apps/local-runtime` via `pnpm deploy --prod --legacy` (hoisted) into `Contents/Resources/daemon` through an `afterPack` hook, because electron-builder strips `node_modules` from extraResources. The SDK's bundled Claude Code binaries (~200 MB) are removed. | The daemon drives the user's installed `claude` CLI (subscription login), so the bundled binaries are not needed. | `.app` 386 MB, `.dmg` 144 MB. The daemon still runs TS through tsx (deviation A-8). |
| D-7 | macOS builds are **ad-hoc signed only** (`identity: "-"`). No Developer ID, no notarization, no hardened runtime. | Out of scope tonight. | On another Mac, Gatekeeper blocks the first open (right-click › Open, or `xattr -dr com.apple.quarantine OCW.app`). The local build opens normally. |
| D-8 | `pnpm-workspace.yaml`: added `electron-winstaller: false` to `allowBuilds`, plus exact-version `minimumReleaseAgeExclude` entries for the `apps/local-runtime` deps. Those deps (claude-agent-sdk 0.3.287, anthropic sdk 0.131.0, MCP sdk 1.32.0, vitest 5.0.3, ws 8.22.0) were merged without a lockfile and are younger than 7 days. | Without this, `pnpm install` fails for everyone, including `--frozen-lockfile`. | Remove the entries after 2026-10-09. The lockfile now includes local-runtime and desktop. |
| D-9 | Build uses esbuild directly (main/preload CJS, onboarding IIFE), not electron-vite. | Least friction with pnpm 12 + TS 7; no extra toolchain. | None. |
| D-10 | `pnpm lint` at the root still fails on pre-existing `apps/local-runtime` formatting (single quotes vs biome double quotes). `apps/desktop` is clean. | Not owned by B4. | Run `biome check --write apps/local-runtime` when that package is next touched. |

## Bots on a ChatGPT subscription (Codex), 2026-10-04

Owner requirement: bots can use the customer's own ChatGPT subscription through Codex instead of an API key
(BYO per self-hosted instance). Design: **ADR-0006** (sign-in runs inside the OpenClaw cell; the API only
orchestrates). Contract: `01-AGENT-CHANNEL-API.md` § "Subscription sign-in".

| # | Deviation | Why | Impact |
|---|-----------|-----|--------|
| C-1 | OpenClaw-native sign-in, not the API-side fallback. The plugin drives `runModelsAuthLoginFlow` (provider `openai`, method `device-code`) from `openclaw/plugin-sdk/provider-auth-login-flow-runtime`, a JS-only "production-private" export of OpenClaw 2026.9.7. | The CLI needs a TTY and the Gateway method `models.authLogin` needs `operator.admin`; this export is what OpenClaw's own `/login` and Control UI use. Verified in the real image (device code from auth.openai.com). | Tokens never reach our DB/logs/API and OpenClaw owns refresh. Re-run the container smoke test on every OpenClaw bump. |
| C-2 | OpenClaw 2026.9 folded the `openai-codex` provider into `openai` (`openai:<email>` OAuth profiles, `openai/<model>` refs). OCW keeps `openai-codex/<model>` as its own model ref and the plugin maps it, pinning `agentRuntime.id: "openclaw"` per bot model. | Keeps the API-key OpenAI provider and the subscription distinct in OCW; never selects the native Codex harness (tools). | With both connected, the plugin writes the API-key provider as `ocw-openai` inside OpenClaw. |
| C-3 | The cell allows OpenClaw's bundled `openai` plugin at boot (`plugins.allow: ["ocw", "openai"]`, personality layer off). | It owns the device-code flow, refresh and the Codex catalog; enabling it later swaps plugin instances mid sign-in. | Memory: idle about 0.6–0.8 GB, a ChatGPT turn up to about 1.35 GB RSS. `demo:up` now gives the cell `--memory 2g`. Two gateways side by side OOM this Mac's Docker VM (about 1.3 GB free). |
| C-4 | `entrypoint.mjs` deletes `openclaw.json.bak` / `.last-good` before writing the rendered config. | Found while upgrading the demo cell: OpenClaw flagged the fresh base config as a "size drop" versus last run's provisioned config and auto-restored the backup, so base-config changes (here the plugin allowlist) never applied on an existing volume. Latent since MVP 0. | Bots/providers are re-provisioned by the plugin at boot as designed (about 1 s). |
| C-5 | Flow state (including the one-time code) lives in Redis with a TTL, not in PostgreSQL. | Short-lived, per-org, must expire by itself; never needed after the flow. | Audit rows (start, cancel, connected, failed, credentials lost, disconnected) are in PostgreSQL in the same transaction as each state change. |
| C-6 | A provider 401/403 during a turn is answered with a fixed "reconnect in Settings › Models" reply instead of OpenClaw's own error text, and is not retried. | Retrying cannot fix a rejected credential; OpenClaw's text is internal. | Applies to API-key providers too. |
| C-7 | Local E2E ran against the demo stack with a pg_dump taken before and restored after, and with the demo cell stopped for the run. | The suite creates users, channels, bots and devices; the codex spec needs to be the only cell (the first reporter owns a flow). | The demo workspace is unchanged by the run. CI runs the same specs on a fresh stack. |
