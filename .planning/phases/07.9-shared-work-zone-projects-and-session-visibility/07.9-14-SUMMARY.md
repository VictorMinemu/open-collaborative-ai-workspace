# Phase 07.9 Plan 14: New-session dialog, who will see the session Summary

**Starting a session now shows where it belongs and who will see it, in one line.** Repositories sit under their team
project (with the device and its status in each caption), then Personal by device. "Visible to: {long label} · Change"
follows the chosen repository's default and opens the same panel as the header chip, in draft mode. Start session sends
the choice, and a stale choice is refused in the dialog with the person's name. Repositories of the caller's own device
that are linked to a project they can't open are shown apart, disabled, and never as personal.

## What the e2e proves (both widths)

- **Grouping (D-01, R5).** `project-group-<unitId>` reads "Customer portal … · Team project" and holds both linked
  repositories, each caption naming its device and "Online". The personal repository sits under "Personal" in its
  device group.
- **D-14.** Pia's own repository, linked by an admin to Payroll, shows in `project-group-hidden` ("Linked to a project
  you can't open"), disabled, never as a `project-option`. No `GET /projects…` response her page read contains
  Payroll's name or id (`finishedBodies`).
- **The line (D-03, D-07).**
  - Choosing a team repository shows "Visible to: Everyone in Customer portal … · Change" (`data-kind="project"`), and
    Change is named "Change who can see this session".
  - Change opens the draft panel: a popover at 1440, a nested bottom sheet at 390. Project is checked with "Default".
    The API's preview reads 3 people (Pia, Leo, the admin as lead and device owner).
  - Only me applies at once: the line reads "Only you", the footer "2 people" (the device owner always sees it, D-11).
    No request reaches any `/work-sessions/:id/visibility` and no toast appears.
  - A personal repository resets the line to "Everyone who can use E2E NS Solo …"; back on the team repository it
    reads "Everyone in …" again.
- **Start.** The create request carries `visibility: { kind: "owner" }`, and the new session's chip reads Only me
  ("Visible to Only you. Change who can see this session").
- **Stale choice (D-04, D-13).** People with Leo is chosen ("2 people"), then Leo is removed from the project through
  the API. Start answers 422, and the error line reads "Leo Park isn't in Customer portal … anymore. Choose who can see
  it again." It is in view without scrolling. The URL stays `/work-zone`, and Pia still has one session on that
  repository.
- **Layout and accessibility.**
  - axe is clean (serious/critical) on `new-session-dialog` in both themes at both widths, on `visibility-popover` at
    1440, and on `visibility-sheet` at 390. `unnamedControls()` is empty.
  - At 390: the label and Change share one row (centres within 2 px, line ≤ 48 px), Change and every sheet control are
    ≥ 44 px, sheet rows are ≥ 56 px, and nothing scrolls sideways.

Fixes made after the review:
1. **Refusal out of view.** The error line sits at the end of the scrolling body. After Start it was below the fold, so
   the person saw nothing happen. It now scrolls into view (`block: "nearest"`), and the spec asserts `toBeInViewport()`
   with no manual scroll.
2. **Status dot spacing.** In team-project captions the green dot's halo touched "Online". The dot now has its own
   padding.
3. **1440 capture.** At 900 px high the popover flips above Change (not enough room below) and covers the grouping. So
   the grouping and the popover are captured separately (`new-session-dialog-1440` and `new-session-dialog-draft-1440`).

Accepted as is:
- **Popover above the line at 1440.** This is the primitive's collision flip. The popover stays anchored to Change and
  inside the viewport.
- **Parent not dimmed under the nested sheet (390).** Base UI does not render a nested dialog's backdrop. The sheet's
  rounded top, border and shadow separate it clearly in both themes.
- **Long test names truncate** the line and the Project row, with the full text in `title`.
- **Tight gap between the description and "Project".** This is pre-existing spacing; the plan says nothing else in the
  dialog changes.

## Deviations from Plan

1. **[Process] Tasks 1 and 2 overlap in commit 1.** The dialog, the refusal mapping and the spec were written once, so
   commit 1 already carries the refusal and the D-14 group. TDD:
   - The groups test was RED on the missing module before the code.
   - The line test and the dialog test were written before their code but not run RED separately (the modules did not
     exist).
   - The e2e is RED by construction: no `new-session-visibility` existed at the base.
   - Commit 2 is the review fixes and the screenshots.
2. **[Rule 2] D-14 repositories.** The plan's `groupRepos` signature has no hidden group. It gains `hidden: Project[]`,
   and `isStartable` (online and not hidden) gates Start and the preselection. Without this, such a repository would
   read as personal (07.9-06 broken-window 2).
3. **[Test scope] The D-14 secrecy check.** "No API response names Payroll" was too broad: `GET /members` lists every
   member's unit names, and unit names are organization data shown in Settings › Organization. The check is now what
   D-14 hides: the link. No `GET /projects…` response names Payroll or carries its id.
4. **[Extra test file] `new-session-dialog.test.ts`.** It is not in the plan's file list. It holds the unit cases of
   `audienceRefusal`, which the plan's acceptance grep requires to live in the dialog file.
5. **[Acceptance grep] Refusal string.** The code builds "… anymore. Choose who can see it again." from two parts, so
   the grep matches the helper's doc comment (the verbatim example). The behaviour is proven by 5 unit cases and the e2e
   string assertion.
6. **[Copy] Refusal variants beyond the UI-SPEC's one line.** Two or more people: "{A} and {B} aren't in …" / "{A}, {B}
   and {n} more aren't in …". Personal repository: "{name} can't use {device} anymore. …". Teams: "{team} isn't
   assigned to {project} anymore. …".
7. **[Branch guard] Worktree branch `wt/07.9-14`.** The coordinator named this branch. It is outside the executor's
