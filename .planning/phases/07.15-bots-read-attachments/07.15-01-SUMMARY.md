## Decisions Made

- **The mirror drops invalid fields and keeps the turn** (`.optional().catch(undefined)` on the four fields), as `memoryFiles` and `maxSandboxCalls` already do. An invalid list then means no files are listed. That fails closed, because the API still decides every read. The contract refuses the same inputs, and the parity test proves both behaviours.
- **The mirror keeps a refused `code` as a snake-case string**, not the enum. This follows the plugin's existing convention (`AgentChannelConsultResponse`, `MemoryToolRefused`), so a newer API's code still delivers its sentence. `AttachmentReadRefusal` and `ATTACHMENT_READ_SENTENCES` are still mirrored exactly, for the guard's local refusals in 06.
- **Image dimensions** are positive ints or null. The hub says "int | null"; a 0-pixel side is not a valid image.
- **The mirror's `maxAttachmentReads` / `maxAttachmentChars` are `nonnegative`**, like the mirror's `maxSandboxCalls`. The contract follows the hub's `z.number().int()` exactly.
