## Findings fixed at the source

1. **Doctor's `updates` ignored the running daemon** (`apps/local-runtime/src/doctor.ts`, `ea2ba73f`).
   - Cause: when the daemon answered `status` without a `runtimeUpdates` block (it runs no maintenance: a fake
     runtime, or a runtime older than 07.11), the check fell back to the doctor's own environment. The container proof
     showed `updates: ok (automatic)` for a daemon started with `OCW_RUNTIME_UPDATES=off`.
   - Fix: that case warns "The running runtime does not manage CLI updates" with a restart fix line. A level the
     daemon took from `OCW_RUNTIME_UPDATES` is named as such, with a fix for the environment.
   - Test: `doctor.test.ts` › "updates: reports what the running daemon does, not this shell's environment
     (07.12-11)" (RED: `expected 'ok' to be 'warn'`). The base fixture's daemon now reports `runtimeUpdates`, as every
     07.11+ daemon with real runtimes does; the existing "all thirteen ok" case needs that. The proof now prints
     `updates=warn`.
2. **The served manifest never named its source commit** (`compose.yaml`, `scripts/gate/lib.mjs`,
   `scripts/gate/compose-gate.mjs`, `b991fd55`).
   - Cause: the Dockerfile accepts `OCW_SOURCE_COMMIT`, but compose never passed it (06's note).
   - Fix: compose passes `OCW_SOURCE_COMMIT: ${OCW_SOURCE_COMMIT:-}` to the api build. `gate:compose` writes it from a
     clean HEAD (`gateSourceCommit()`). `checkRuntimeDist` reports `commit` and fails when the manifest's commit is
     not the built one.
   - Tests: `compose-gate.test.mjs` (commit required; compose wiring) and `lib.test.mjs` (`createGateEnv` writes it
     and refuses a non-hex value). The release gate then showed commit `41029ce421c1`.
3. **The isolated e2e runner broke the connector specs on a moved API port** (`scripts/e2e-isolated.sh`,
   `727fece5`).
   - Cause: the fake OAuth client's redirect defaults to `:4290`. CI passes `FAKE_MCP_OAUTH_REDIRECTS`; the runner did
     not. With `OCW_E2E_API_PORT=4690` both connector specs got `redirect_uri is not registered`.
   - Fix: the runner passes `FAKE_MCP_OAUTH_REDIRECTS` for `$API_PORT` (same behaviour on the default port).
   - Test: `e2e-env-parity.test.mjs` › "the runner's fake registers the OAuth redirect on the runner's own API port,
     as CI does (07.12-11)". In run 2 both connector specs passed on both projects.

**Not a code finding.** In run 1 the e2e web process (`next start`) exited with no log line during the mobile Work
Zone specs. Every later page load got `ERR_CONNECTION_REFUSED` while the API kept answering. No test or helper kills
processes by name. Run 2, with only the harness line above changed, ran all 711 tests with the web alive (a watcher on
its pid confirmed it). Recorded as an environmental exit under the machine's load.
