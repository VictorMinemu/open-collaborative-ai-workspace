# Phase 07.6 Plan 10: Signed webhooks as an automation trigger Summary

**A lead's webhook automation gets an unguessable URL and a `whsec_` secret shown once and sealed in the secret store;
`POST /api/v1/hooks/:publicId` accepts only Standard Webhooks requests verified by the `standardwebhooks` library over
the exact bytes within ±5 minutes, is idempotent by `webhook-id`, bounded at 64 KiB and 60 a minute per URL (counted
in Redis across replicas), answers 410 once the automation is gone, and turns each accepted request into an
`automation_events` row plus an `automation.inbound` job in one transaction, which 21 posts as a Received card with a
read-only turn.**

## The public route: checks in order, and the logging rule (plan mode, P-19)

`POST /api/v1/hooks/:publicId`, `config.authz: "public"`, in its own encapsulated Fastify scope:

1. **Rate limit** (`onRequest`, before anything else): 60 a minute per URL, keyed `hook:<publicId>` and counted in
   Redis (`ocw:rl:POST/api/v1/hooks/:publicId:hook:<publicId>`) → 429 `rate_limited`. The rejection is recorded at
   most once per endpoint and minute.
2. **Body size** while the body is read: the scope's only parser keeps the raw Buffer for every content type, with a
   route `bodyLimit` of 65 536 bytes → 413 `payload_too_large`, recorded as `too_large`.
3. **Public id**: malformed (not 26 Crockford base32 characters) or unknown → 404; tombstoned or unlinked → 410
   (`app.lookup_webhook_endpoint`, ids only).
4. **Signature and timestamp**, in the endpoint's organization: the current secret, then the previous one while its
   24-hour grace lasts, each opened with its AAD; `standardwebhooks` checks the ±5-minute window and the HMAC over the
   exact bytes (constant-time, space-separated `v1,` list) → 401 with one fixed body, the reason (`signature` or
   `timestamp`) recorded on the endpoint.
5. **Payload**: a verified body that is not JSON, contains `\u0000` (jsonb refuses it) or has a `webhook-id` over 998
   characters → 400 `invalid_payload`.
6. **Event**: `insert … on conflict (webhook_endpoint_id, external_id) do update duplicate_count + 1`; a repeat → 200
   `{status: "duplicate"}`; a new event is `accepted` with `thread_key` null, and its `automation.inbound` job and its
   `webhook.received` audit row (`{result, endpointId, automationId, eventId}`) commit with it → 202
   `{status: "accepted"}`. Paused, the hourly cap and access are left to the inbound worker (21).

**Logging rule.** No body, header value or secret goes to a log, an audit row, an error or a job. The request log
serializer already drops headers and query strings. The scope's error handler logs only the error `code`, because a
database error's detail can quote the failing row. Audit and job data carry ids only. Secrets appear only in the
create, update and rotate responses. The canary test checks this for an accepted request, a refused one, a too-large
one and a duplicate.

## What was built

- **`webhook-verify.ts`**: `verifyStandardWebhook(raw, headers, secrets)` → `{ok, id, payload}` or `{ok: false,
  reason}`. `newWebhookSecret()` (`whsec_` + base64 of 32 random bytes), `newPublicId()` (128 random bits as 26 Crockford
  base32 characters) and `normalizePublicId()` (upper case, or null).
- **`webhooks.ts`** (the trigger adapter):
  - `onCreate` inserts the endpoint, seals the secret (`webhook_secret`, AAD `<org>:webhook_endpoint:<id>`), audits
    `webhook_endpoint.created` (ids) and returns `{webhookSecret}` once.
  - `onUpdate` keeps the URL and the secret.
  - `onDelete` (delete, or a kind change) tombstones and unlinks the endpoint, removes both secrets and audits
    `webhook_endpoint.deleted`.
  - `view` gives `{publicId, url}` with `url = OCW_PUBLIC_API_URL + /api/v1/hooks/<publicId>`.
- **`webhook-routes.ts`**: the public scope above, then:
  - `GET /automations/:id/webhook`: visibility through `service.get` (owner or `automation.manage`; others and other
    organizations 404). Returns the endpoint DTO (never the secret), the last 10 deliveries with links (thread or board
    card), the last rejection and `previousValidUntil` while the grace is open. `lastPayload` is the latest unpurged body
    and goes to the owner only.
  - `POST /automations/:id/webhook/rotate`: the owner with `automation.webhook` (a manager gets 403 `not_allowed`).
    Issues a new secret once, keeps the old one for 24 hours, audits `webhook_endpoint.secret_rotated` and announces
    `automation.updated`.
- **`lib/rate-limit-store.ts`**: `RedisRateLimitStore` uses one MULTI per hit (`INCR`, `PEXPIRE … NX`, `PTTL`): a fixed
  window that starts at the first hit and is never extended, like the in-memory store. It also has `read`. `child`
  namespaces each route by `METHOD+url`. `app.ts` registers it once as the plugin's `store` over `core.bus.pub`.
- **`secrets/index.ts`**: `putSealed` accepts `webhook_secret`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] 05's seam test and the public-route allowlist.**
- `automation.int.test.ts` expected a lead's webhook trigger to answer 400 `trigger_unavailable`. That case is
  removed; the mail case stays until plan 11.
- `authz.int.test.ts`'s public allowlist gains `POST /api/v1/hooks/:publicId`.
- Commit `145fdeb4`.

**2. [Rule 2 - Security] Flood-proof rejection record.**
- Recording `rate_limited` on every request over the limit would turn a flood into one lookup and one UPDATE per
  request.
- The record is now throttled to once per endpoint and minute with a Redis `SET NX PX 60000` key.
- Commit `145fdeb4`.

**3. [Rule 2 - Security] Error logs carry only the error code.**
- A failed insert's PostgreSQL detail ("Failing row contains …") could quote the payload.
- The public scope's error handler logs `{code}` only.
- The route also refuses bodies that jsonb would reject (`\u0000`) and ids over the column cap before inserting, so
  those become a 400 instead of a 500.
- Commit `145fdeb4`.

**4. [Interface] `MULTI` with `PEXPIRE NX`, plus `read`.**
- As planned, with no Lua and no new dependency.
- The factory returns the plugin's `FastifyRateLimitStoreCtor` through one documented cast. The plugin's types declare
  `child(RouteOptions)`, but at runtime it passes the merged limit options (`timeWindow`, `routeInfo`).

**5. [Design] The signature rejection is written in the request's tenant transaction.**
- The plan asked for the rejection to be recorded in its own small transaction.
- A refused request writes nothing else, so the row commits alone either way.
- 413 and 429 are recorded in their own transaction from the scope's error handler.
