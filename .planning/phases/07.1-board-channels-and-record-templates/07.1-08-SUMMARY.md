# Phase 07.1 Plan 08: Web board view Summary

**Board channels work end to end in the browser. You can create one from the dialog (Layout: Board), add cards, and move them by keyboard, pointer, menu or long-press. Cards open as threads. The board covers its loading, error, empty and paged states, mirrors membership and archive gating, and passes axe in both themes at 1440 and 390. The dnd-kit spike passed on `@dnd-kit/react` 0.5.0, so the fallback was not taken.**

## dnd-kit decision (P-05, for ADR-0022 in 07.1-14)

**Shipped:** `@dnd-kit/react` 0.5.0 and `@dnd-kit/helpers` 0.5.0, as pinned by 07.1-01. `package.json` and `pnpm-lock.yaml` are unchanged.

**Why:** the spike was the keyboard cross-column move: focus the grip, press Space, ArrowRight, Space. It passed on the first e2e run in the real board. The card lands in an empty lane and dnd-kit's live region reads `“Broken pump” dropped in In progress, position 1 of 1.` After a reload the card is still there.

Pointer drags within and across lanes, Escape cancel and the touch long-press at 390 all work on the same 0.5.0 API:
- `DragDropProvider`
- `useSortable` with a `group` per column
- `useDroppable` for empty lanes
- `move()` in `onDragOver`

**Two 0.5.0 caveats, both handled in `board-view.tsx`:**
1. `@dnd-kit/react` does not re-export the `Accessibility` plugin class. Its entry in the default plugin list is replaced by a `{ plugin, options }` descriptor that carries the UI-SPEC instructions and announcements, found by name or else the first entry, as in the preset. The e2e asserts the copy, so an upstream change fails loudly.
2. When a card crosses lanes mid-drag, it remounts and its sortable's `initialGroup` changes. The cancel announcement therefore takes the start column from the board's own drag-start map.

## Deviations from Plan

1. **[Scope / ordering] Task 3's channel-view work landed in Task 1.** The board copy of the join and archived banners, New card hidden for read-only viewers, and the loading, error, empty and Show-more rendering were built with the board view in `afc84f2`. Task 3 proved them in e2e. Behaviour matches the plan.
2. **[Rule 1] Cancel announcement column** (`8f45c40`). dnd-kit's `initialGroup` is lost when a card remounts in another lane mid-drag, so the board now records the drag's start column itself.
3. **[UI-SPEC, visual] Grip faint at rest** (40 % opacity, full on hover or focus) instead of hidden. On boards without a prefix, the reserved grip slot made titles look indented next to nothing.
4. **[UI-SPEC, minor] Mouse drag threshold is 5 px, not 6 px.** This is dnd-kit 0.5.0's own distance constraint: `PointerActivationConstraints` is not re-exported by `@dnd-kit/react`, so it is reused from the defaults, minus the 200 ms hold. Touch keeps the default 250 ms / 5 px, which matches the UI-SPEC exactly.
5. **[Rule 2] One change per card at a time** (07.1-04 open item). While a card's PATCH is in flight, its menu shows only Open thread (`canPost && !pending`), so a second move cannot carry a stale `expectedVersion`. `card-menu.tsx` was not changed.
6. **[Test helper] `expectNoSeriousA11y` waits for `document.getAnimations()`** before analysing. Without the wait, opening dialogs and menus are measured mid-fade, and the blended colours give false contrast failures.
7. **[Scope] Extra e2e helpers in `e2e/support/board.ts`:** `boardSnapshot`, `columnId`, `apiCard`, `boardColumn` and `columnOrder`, next to the four named in the contract. The contract names keep their signatures.
8. **[Spec] The 44 px check covers controls inside `board-view` plus the toolbar's New card.** The segmented Board | Messages triggers are 36 px boxes with a 44 px hit area through an `::after` extension (07.1-04's `tabs.tsx`). `boundingBox` cannot measure that extension, so they are excluded.
