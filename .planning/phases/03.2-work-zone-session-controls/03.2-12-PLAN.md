## Phase Goal

**As a** controller of a Work Zone session, **I want to** see each session under a short title that says what was asked, **so that** I recognise my sessions at a glance in the sidebar, the header and the browser tab without anyone typing a name (ROADMAP Phase 03.2 success criterion 7, WZC-07; the phase user story is in 03.2-01-PLAN.md).

**This plan's slice:** the automatic session title decided by the owner on 2026-10-05 (D-18 … D-20), end to end: contracts, one additive migration, API request/accept path, Device Link command and result frame, daemon, FakeRuntime, the real Claude Code and Codex title calls with recorded fixtures, fallbacks, inventory, ADR and the layout check.

## Planner decisions for this plan (P-14 … P-19)

P-01 (contracts once) and P-02 (one migration) bound Plans 01 … 11. D-19 needs the title source persisted, so this plan adds its own contracts and one additive migration. P-13 (test and infra rules) applies unchanged.

- **P-14 Title source.** `work_sessions.title_source` text, NOT NULL, default `'user'`, check `user | heuristic | auto`. The default is the protected value: rows created before this column, and any insert path that does not say otherwise, are never retitled. `POST /work-sessions` writes `heuristic` when no title was typed and `user` when one was. No backfill statement is needed.
- **P-15 Wire protocol.** The API sends the device command `session.title` with `{ runtime, model, prompt }` (prompt cut to 4000 characters). The device answers with a new device→server frame `title.result` `{ requestId, sessionId, title, model }` and then an ok ack. On failure it sends only a failed ack whose error starts with a stable `TitleFailureCode`. This is the `diff.request` / `diff.result` pattern: the hub accepts a result only for a `session.title` command of the same device. The title is not a `SessionEvent`, so it is never appended to the session stream.
- **P-16 Shape.** `normalizeSessionTitle` (device) and `SessionTitle` (API) live in contracts and share one word counter (`Intl.Segmenter` word-like segments, so scripts without spaces count correctly). Normalization:
  1. Take the first non-empty line.
  2. Drop a leading `Title:` / `Título:` label, markdown marks, wrapping quotes, control characters and trailing punctuation.
  3. Collapse whitespace.
  4. If every word is capitalised (Title Case), convert to sentence case. All-caps and mixed-case words such as API or GitHub keep their case.
  5. Uppercase the first letter.
  6. Keep at most 6 words.
  7. Cut at the last word boundary within 48 characters.
  8. Return null when fewer than 3 words remain, or when a single word is longer than 48 characters.

  `SessionTitle` refuses:
  - an empty title or one over 48 characters;
  - fewer than 3 or more than 6 words;
  - line breaks, control or format characters;
  - backticks, asterisks, angle brackets;
  - leading or trailing whitespace, wrapping quotes, trailing punctuation;
  - absolute host paths (a home directory such as Users/home/root, `~/`, or a Windows drive).
- **P-17 Title calls on the device.** Both run in a fresh empty temp directory (`mkdtemp`, removed afterwards), never the project or the OCW home. Both send the shared `TITLE_INSTRUCTIONS` and the prompt wrapped by `titleUserMessage`.
  - **Claude Code:** a separate `query()` with:
    - `model: "haiku"`, `permissionMode: "default"`. Not plan: 03.2-02 observed plan mode running Haiku as Sonnet.
    - `tools: []` and a `canUseTool` that denies everything.
    - `allowDangerouslySkipPermissions: false`, `settings.permissions` = `secretDenyRules()` + `disableBypassPermissionsMode: "disable"`.
    - `settingSources: []`, `persistSession: false`, `maxTurns: 1`, `systemPrompt: TITLE_INSTRUCTIONS`.
    - `env: childEnv(...)` (API keys stripped), the PATH `claude`.

    The init model must be `haiku` or the catalog row's `resolvedModel`.
  - **Codex:** a short-lived `codex app-server` (the `listCodexModels` pattern):
    - `initialize` with `experimentalApi: false`.
    - `thread/start` with `model: "gpt-6-luna"`, `sandbox: "read-only"`, `approvalPolicy: "untrusted"`, `approvalsReviewer: "user"`, `ephemeral: true`, `baseInstructions: TITLE_INSTRUCTIONS`.
    - `turn/start` with the model's lowest catalog effort (`low`) and `summary: "none"`.
    - The text of the final `agentMessage` is the result.

    It aborts if any of these happens:
    - an approval request arrives (declined);
    - an `item/started` that is not an agent message or reasoning;
    - an unrestricted thread policy (`isUnrestrictedCodexPolicy`);
    - a thread model other than `gpt-6-luna`.
- **P-18 Gate and audit.** The API asks for a title only when all of these hold: the session's `title_source` is `heuristic`; this is the session's first prompt and not a slash command; the device catalog of the session's runtime lists `TITLE_MODEL[runtime]`; the policy's `allowedModels[runtime]` is empty or includes it; the inventory row `session.title` of that runtime is exposed (gate added in Task 2). Audits: `work_session.title_requested` `{ runtime, model, promptLength }`, `work_session.title_generated` `{ model, length }` and `work_session.title_failed` `{ reason, model }`. None of them carries prompt or title text, and none touches `lastError`.
- **P-19 Timeout and concurrency.** The daemon runs `session.title` outside the per-session configure/prompt chain (the same as `diff.request`), with `TITLE_TIMEOUT_MS = 20_000` enforced by the daemon itself (abort signal + race). Tests can lower it with `DaemonOptions.titleTimeoutMs`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → device (`session.title` command) | Carries the first 4000 characters of a member's prompt to the session's device |
| device → runtime vendor (title call) | The prompt goes to the small model of the session's own runtime on the device owner's login |
| runtime → device (model answer) | Untrusted model text, possibly steered by prompt injection in the member's prompt |
| device → API (`title.result`) | A device-supplied string that becomes a session and conversation name shown to every controller |
| API → web (title rendering) | The title in sidebar, header and `document.title` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.2-12-01 | Information disclosure | Title call vendor and billing | high | mitigate | The API sends `runtime = s.runtime` and `model = TITLE_MODEL[s.runtime]`. The daemon runs only that runtime's adapter (`title_runtime_mismatch` when the active session runs another). Adapters use `childEnv` with API keys stripped, so only the owner's own login is used and no pooled key exists. Int test (ii) and daemon test |
| T-03.2-12-02 | Spoofing | `title.result` from another device or tenant | high | mitigate | The hub accepts a result only for a `session.title` command of the same device. The service checks `s.deviceId` and `cmd.workSessionId` under the device's tenant (RLS). Int tests (e), (h) |

Codex: read-only + untrusted + user reviewer; any approval request or non-message item → interrupt + fail, so no output leaves; the unrestricted-policy guard applies. Unit tests per adapter |
| T-03.2-12-04 | Tampering | User-typed title overwritten | medium | mitigate | `title_source` default `user` (protected); create writes `user` for typed titles; a single conditional update `where title_source = 'heuristic'`. Int test (c) and e2e |
