# Phase 07.18 Plan 15: Web, Settings › Account pool for admins Summary

Admins run the whole subscription pool from one Settings page. There is a Claude section and a ChatGPT section, each with its distribution strategy, its fallback switch and its accounts in order. Claude also has a "Used by" scope. Admins can:

- add a Claude account by pasting a `claude setup-token` value;
- add a ChatGPT account for bots or on a server device, using a device code;
- switch accounts on or off, rename them, reorder them, set their weight, replace a token, or remove them.

## What was built

- **Page and nav.** `/settings/account-pool` uses the house Settings layout (PageHeader, a max-w-4xl scroll container). The `account-pool` nav entry (KeySquare icon) sits right after Models and needs `provider.manage`. Members who reach the URL see "Only workspace admins manage the account pool."
- **Sections.** Each section shows a title, its plan line, an "N of M ready" badge and its add button. Below that are the strategy controls:
  - Distribution select, using the contract's labels and descriptions.
  - Claude only: the "Used by" select ("Work Zone and bots" / "Work Zone only" / "Bots only").
  - A note: "A session keeps its account until that account hits its limit." Under weighted it adds `BOTS_WEIGHTED_NOTE`.
  - The switch "Use the device's own login when no account is ready".
  - With no accounts, the section shows an empty state with one line of help and the add button.
- **Rows.** Each row shows:
  - the label, the plan (ChatGPT Pro, …) and a status chip: Ready, Cooling until 15:40 / Tue 15:40, Paste a new token / Needs sign-in, or Off;
  - where the account lives: Sealed on the server, On Build server (· offline), or Bots runtime;
  - when it was last used, and usage bars (as `role="meter"`) when the runtime reported usage.
  - Actions: move up and down (the ends are disabled), rename inline (Enter / Escape), replace the token (token accounts), remove (with a confirm dialog that says what happens), and the on/off switch. Under weighted there is also a weight field (1–100).
  - Every control has an accessible name.
- **Add Claude account.** Fields are Label and Setup-token. The token field is password-type with autocomplete off. Two safeguards:
  - an `sk-ant-api…` value shows the contract's sentence inline and Save stays off;
  - the token lives only in the form state, is cleared after save, and the form unmounts on close.
- **Add ChatGPT account.**
  - The dialog asks "Where will this account be used?": "For bots" or "On a device". On a device, online service devices are listed first; the others are disabled with "Not a server device" or "Offline". Then it asks for a label, and Start sign-in.
  - The code view has:
    - the verification link (new tab, `rel="noopener noreferrer"`) with a copy button;
    - the code, large, with a Copy button, and an "Expires in m:ss" countdown;
    - Cancel, then "Connected" (the dialog closes after 1.2 s), or the error in plain words with Try again.
  - It polls every 2 s while starting or pending.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing functionality] A way to act on "Paste a new token"**
- **Found during:** Task 2
- **Issue:** The status chip asks for a new token, but the plan's row actions had no way to give one.
- **Fix:** Token rows get a "Replace the token of <label>" button. It opens the Claude dialog in replace mode (no label field, PATCH `{ token }`, never echoed back).
- **Files modified:** add-claude-account-dialog.tsx, account-pool-row.tsx, account-pool-settings.tsx
- **Commit:** 613a172b

**2. [Rule 1 - Bug] Phone layout of a row under weighted**
- **Found during:** the visual check after Task 3
- **Issue:** At 390 px the weight, five actions and the switch did not fit on one line. The remove button and the switch wrapped to stray lines.
- **Fix:** Rows reflow with flex order. The switch sits on the label's line, the actions take their own line, and the weight takes a line of its own on a phone. The row test now asserts `flex-wrap` / `sm:flex-nowrap` instead of `flex-col` / `sm:flex-row`.
- **Files modified:** account-pool-row.tsx, account-pool-settings.test.tsx
- **Commit:** 5859bf05

**3. [Rule 2 - Security] The code leaves the cache on close**
- **Found during:** Task 3
- **Issue:** T-07.18-15-02 asks that the code is not kept after the dialog closes. React Query would have kept the last GET (which carries the code) in memory.
- **Fix:** `forgetSignIn` removes both sign-in queries on unmount. Closing mid-flow (Escape, X, backdrop) also calls the cancel route. A test checks that the console is never called and that the cache is emptied.
- **Commit:** 5859bf05

### Test style

The plan says "testing-library, mocked `api`". The web vitest project has no DOM, so the tests follow the house style instead: `renderToStaticMarkup` of exported parts, plus mutation factories driven by `MutationObserver` against `vi.mock("@/lib/api")`. Interactions (open dialog, close after save) are covered through the mutation factories and the rendered states. A real click-through is plan 16's browser journey.
