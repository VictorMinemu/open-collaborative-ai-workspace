# Phase 07.9 Plan 12: RLS audience backstop, cross-tenant matrix and scale Summary

The database now refuses a user request any session row outside that user's audience (RESTRICTIVE `audience_backstop`
on the four session tables, calling the one SQL rule), D-14 keeps assigned teams out of nested projects, every phase
route has an organization-B case derived from the registry, and the rule is measured at 5,000 sessions with explicit
budgets (the list as a member: 332 ms against 3,000 ms).

## Intended change (CLAUDE.md plan mode)

- **Backstop.** Four RESTRICTIVE `audience_backstop` policies in `post-migrate.sql`. `work_sessions`: a user request sees
  or writes a row only when `app.work_session_access` names the user with a seeing relation (or created it); user-less
  transactions pass (D-13). The three child tables use the `EXISTS` form on `work_sessions`. `tenant_isolation` is not
  touched; nothing permissive is added.
- **D-14 (MUST, ledger #307).** The `team` branch of `app.work_project_access`, the `teams` audience of
  `app.work_session_access` and `app.work_project_team_via` ignore memberships of units of kind `project`. Projects are
  leaves (`ALLOWED_PARENT_KINDS`), so this is exactly "never descendants of kind project". `subtreeMemberCounts` follows,
  with the same rule.
- **Whole API under the backstop.** Run the full integration suite and fix each failure at its source; never a
  user-less read of content for the caller.
- **Matrix and scale.** A registry-derived cross-tenant matrix for `/work-projects*`, `/visibility*` and `/audience/*`.
  A 5,000-session perf test with a budget per reader, and the list's `EXPLAIN ANALYZE`.

## Deviations from Plan

### Auto-fixed Issues

1. **[Rule 1] Seeing set instead of `cardinality(...) > 0`.** The plan's interface admitted any fact, so a
   `project_lead`-only row would pass. That contradicts the plan's own behaviour ("afterwards they read 0 rows"), the
   viewers enumerator and the resolver precondition. The policy uses `&& {creator, creator_left, device_owner, viewer,
   admin}`.
2. **[Rule 1] `created_by` shortcut in USING too.** The plan put it only in WITH CHECK, which breaks
   `INSERT … RETURNING` (fix 1).
3. **[Rule 3] Files outside this plan's list.** `facts.ts` (05) and `index.ts` (07) were changed for fixes 2 and 4, and
   `hidden.ts` is new. No W5 plan touches them; the fixes are at the source, as Task 2 requires.
4. **[Rule 1] Two new definer functions** (`work_session_shape`, `work_session_exists`). Both return ids or a boolean,
   are scoped to the caller's tenant and use `REVOKE PUBLIC` / `GRANT ocw_app`.
5. **Exact expectations updated to the new correct values** (P-14: allowed and named here):
   - `rls-isolation.int` now expects 2 policies on `app.work_session_grants` (was 1; its comment anticipated plan 12).
   - `projects.int` follows D-14: Engineering `memberCount` goes from 4 to 3, the project's `access.count` from 4 to 3
     and Web's `memberCount` from 3 to 2. Víctor and Otto reached those counts only through a project nested under the
     assigned unit, which D-14 now forbids.
6. **[Rule 1, perf] `deliverToReaders` rewritten** (Task 3: fix at the source, numbers above). The admins are still
   selected by role in SQL; `guard.test` forbids a TS role literal.

## Decisions for ADR-0030 (plan 15)

- **Shape.** The backstop is RESTRICTIVE on `work_sessions` (the rule) and on `work_prompts`, `work_approvals` and
  `work_session_grants` (the EXISTS form). It is never permissive and `tenant_isolation` is unchanged.
- **Seeing relations.** These are `creator`, `creator_left`, `device_owner`, `viewer`, plus the `admin` fact. A
  `project_lead` fact alone sees nothing. The creator also passes by `created_by` (required by `INSERT … RETURNING`).
- **Writes.** WITH CHECK judges the row as it was before the statement, so a lead may narrow a session past themself;
  USING hides it afterwards.
- **Limits.**
  - User-less transactions pass (D-13). The backstop guards against API code that forgets the resolver, not against a
    compromised `ocw_app` role that sets `app.user_id = ''`. The follow-up is an explicit system actor.
  - `device_commands` and `stream_events` are not covered.
  - FK cascades bypass RLS.
  - GET denials are still not audited (pre-existing design).
- **Hidden means not in the audience.** A row hidden by the backstop is treated as the resolver's `not_in_audience`.
  The route answers the same 404, writes the `authz.denied` audit on non-GET requests and gives the live `ws:` revoke
  `cause: visibility`. A first subscribe never reveals the cause.
- **Facts of others** are read through definer functions (`work_session_shape`, `work_session_access`), never through
  the caller's RLS.
- **D-14.** Project memberships never count for assigned teams: access, `teams` audiences, the via-team reason and
  member counts. Device unit grants keep `deviceModeCap` parity (ADR-0012).
- **Fan-out.** It is awaited after commit and costs one rule pass per member and session. Measured: about 25 ms per
  session at 200 members.

## Broken-window candidates (for the coordinator; the ledger was not touched)

- **#306, #308, #314.** Measured and within budget (numbers above). Candidates to close as fixed.
- **#311 (low).** The after-commit fan-out is still awaited by the request: 6.3 s for a 250-session device sweep, and
  roughly 25 ms per emitted session at 200 members. A Work Zone policy change that clamps thousands of sessions
  (`reauthorizeOrg`) would hold the admin's request for about a minute or more. Follow-up: a per-organization,
  serialized background delivery queue (keeps order, frees the request).
- **#307 (MUST, D-14).** Fixed, with tests (SQL plus `projects.int` expectations). Candidate to close.
- **New (low).** On a live re-decision, a deactivated member's subscription to a session would carry
  `cause: visibility` instead of `role`, because their row is hidden before the resolver runs. Sockets of deactivated
  members are normally closed by session revocation.
- **New (follow-up, ADR-0030).** An explicit system actor, so that a user-less `''` is denied by default.
