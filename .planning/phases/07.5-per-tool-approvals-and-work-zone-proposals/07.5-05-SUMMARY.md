# Phase 07.5 Plan 05: One Work Zone session start path Summary

Session creation now lives in one place. `POST /work-sessions` hands its body to `createWorkSession(tx, deps, actor,
input, opts)` in `work-session/start.ts`. That function runs the same checks in the same order, with no request, for
any member. Every refusal is a result code returned before the first write. The route turns each code back into the
status, code, message and denial payload it returned before. A start for a proposal marks the first prompt with the
bot, and records the bot and the approval in `work_session.created`. Without a mode, a start never goes above
`default`. `WorkPrompt.proposedBy` now reaches REST and `prompt.updated`.

## Intended extraction (plan mode, P-13; written before the code)

What moves from `routes.ts` to `start.ts`:

- The whole `POST /work-sessions` body becomes `createWorkSession(tx, deps, actor, input, opts)`, in the same order:
  `work_session.create` → slash-command prompt → project ⨝ device (RLS, `removedAt`) → `deviceId` cross-check →
  `loadDeviceAccess` + `device.use` (`deviceFacts`) → online → runtime installed → signed in → controls context →
  start mode (absent → `default`, lowered with `highestAvailableMode`, never raised; explicit → refused with its
  reason) → `decideSettings` → conversation, `workSessions` insert, join, `session.start` outbox, audit
  `work_session.created`, first prompt, `emitSession`.
- Request-bound calls become request-free: `perms.assertCan(req, …)` → `perms.decide(tx, { kind: "user", userId },
  …)` with the same resource facts; `authOf(req)` → `actor { userId, organizationId, clientKind }`.
- Every early exit returns `{ ok: false, code, message, … }` before the first write. The denial (`AuthzDenial`) and the
  settings field/reason travel in the result so the route can rebuild today's exact error.
- `queuePrompt` and `joinConversation` move to `start.ts` as exported helpers; the route's prompt endpoint uses them
  (one copy). `settingsDenied` and its message tables move too (the route's settings path imports them). The
  device-unusable messages and the slash-command predicate become one exported helper each, used by both.
- New, only through `opts`: `proposedByAgentId` on the first prompt and `proposedByAgentId` / `approvalId` in the
  `work_session.created` metadata. A human call passes no opts, so its rows and audit are unchanged.

What stays in the route:

- `authOf(req)` → actor, `markDecided(req)` (the resolver decided inside `createWorkSession`), and the mapping
  code → today's `HttpError` / `AuthzDeniedError` (same status, code, message, denial payload; the app's error
  handler still writes `authz.denied` for 403s).
- `controlsFor` and `assertDeviceUsable` remain for the other routes (`/controls`, `/settings`, `/work-zone/controls`).

Built as intended.

## Interface for 07.5-07 / 07.5-08

```ts
// work-session/start.ts (types re-exported from work-session/index.ts)
type WorkSessionStartResult = { ok: true; session: WorkSession } | WorkSessionStartFailure;
type WorkSessionStartFailure =
  | { ok: false; code: "not_allowed" | "device_not_shared"; message: string; denial: AuthzDenial }
  | { ok: false; code: "project_not_found"; message: string; reason?: "other_device" }
  | { ok: false; code: "device_offline" | "runtime_unavailable" | "prompt_not_allowed"; message: string }
  | { ok: false; code: "settings_denied"; message: string; field: string; reason: ControlDenialReason };
interface WorkSessionActor { userId: string; organizationId: string; clientKind: string | null }
// createWorkSessionModule(core, hub, deps) now returns WorkSessionModule = ApiModule & { start(tx, actor, input, opts?) }
// opts: { proposedByAgentId?: string; approvalId?: string }
```

- Call `start` inside the decider's own `withTenant` transaction. It throws if the tx tenant user is not `actor.userId`.
- A proposal passes only `{ projectId, deviceId, runtime, prompt }`, with no mode, model or settings.
- `settings_denied` cannot happen for a proposal in practice. It only fires when an explicit mode or setting is refused, or when no mode at all is available to the member.

## Deviations from Plan

### Names and shapes adapted (P-13: name, never semantics)

1. **`WorkSessionStartResult`'s failure is a discriminated union** (`WorkSessionStartFailure`). It carries
   `denial: AuthzDenial` for `not_allowed` / `device_not_shared`, `reason?: "other_device"` for `project_not_found`,
   and a typed `field` / `reason: ControlDenialReason` for `settings_denied`.
   - The plan's shape (`field?`, `reason?: string`) could not rebuild the 403 denial payload the route has always
     sent.
2. **`deps.core` is `Pick<Core, "audit">`**, and the input type is `WorkSessionStartInput` (=
   `CreateWorkSessionRequest`, the Zod input type).
   - The new types are `WorkSessionStartOptions`, `WorkSessionStartDeps` and `WorkSessionModule`.
   - `queuePrompt` is now the exported `queueWorkPrompt`.
3. **`settingsDenied`, `DENIAL_LAYER`, `DENIAL_MESSAGE` and `FIELD_LABEL` moved to `start.ts`.** The route's settings
   path imports `settingsDenied`. This was a pure move with identical text.
   - `deviceUnusableMessage`, `isSessionCommand` and `SLASH_COMMAND_MESSAGE` are the single copies that both files use.

### Auto-fixed / added

1. **[Rule 3] `markDecided(req)` in `POST /work-sessions`.** The resolver decision now runs through `perms.decide`
   without the request. Without the mark, the authz registry would record the 200 as undecided (strict mode in tests:
   500).
   - The "every Work Zone answer went through the resolver" assertion in `settings.int.test.ts` stays green.
2. **[Rule 2] Tenant-context guard.** `createWorkSession` throws if `tenantOf(tx)` is not the actor's organization and
   user. Audit rows and RLS take the actor from the transaction, so a mismatched tx would attribute a session to the
   wrong person.
3. **[Rule 2] An empty prompt after trimming is `prompt_not_allowed`.** This only applies to direct calls: the
   route's Zod `min(1)` after `trim` makes it unreachable over HTTP.
4. **A deleted bot shows `proposedBy: null`.** Bot deletion is a soft delete (`deleted_at`), so `proposerNames`
   ignores deleted agents. A hard delete is covered by the FK `SET NULL`, and both are tested. Agent names are read
   only when a prompt has a proposer, so there is no extra query for people's prompts.

### Findings (no code change)

1. **The HTTP route's "lowered default" branch is dead code.** `CreateWorkSessionRequest.permissionMode` has a Zod
   `.default("default")`, so over HTTP `permissionMode` is never `undefined`.
   - A member capped at `plan` who posts without a mode gets 403 `device_grant`. They do not get a `plan` session,
     even though the route comment says the implicit default is lowered.
   - Only direct calls without a mode (07.5-08 proposals) take the lowered path, which the plan wants (P-08).
   - I kept the behaviour exactly as it was, because the brief required the human route to stay byte-identical. See
     broken-windows candidate 1.
2. **The plan's "trimmed prompt" requirement already held.** `parseSlashCommand` does `trimStart()` before matching.
   `isSessionCommand` also trims explicitly, so this no longer depends on the parser. Results are identical for every
   input.
