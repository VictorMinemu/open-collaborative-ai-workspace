# Phase 07.8 Plan 30: Contracts 01b (browser, live view, modules, approvals, cards) Summary

The contracts now cover the live view with takeover: strict Agent Channel browser bodies, live-view frames, the
sign-in card link and browser sessions. None of these schemas has a field for page script, DOM, cookies, storage or HAR
output. `sandbox` and `browser` are ordinary 07.3 modules with five grains, the 07.5 approval hooks cover the confined
tools and D-13's cross-site `open`, and the web module maps typecheck.

## What was built

**Task 1 (tracer), commit `5ec575ab`.**
- `browser.ts` (imports only `common` and the leaf `agent-card-route`) contains:
  - `BROWSER_LIMITS`, exactly as the plan lists them.
  - `BrowserRefusal` (28 codes) and `BROWSER_REFUSAL_STATUS`.
  - Seven strict Agent Channel bodies and their responses.
  - `BrowserUrl`: WHATWG parse, `http:` or `https:` only, no user info, no control characters, at most 2,000 characters.
  - `BrowserHost` and `BrowserRef`. A ref is an opaque `[A-Za-z0-9_-]{1,64}`, so a CSS or XPath selector cannot parse.
  - Per-action required fields on `act` and `wait`.
  - `BrowserDownload`: workspace downloads carry a relative path, conversation downloads an attachment.
  - Live-view frames: `LiveStateFrame` (`endReason` is required when ended, `privateReason` when private), `viewerCan`, `lease` and `focus`. The client side is a closed `LiveClientFrame` union over take, release, keep, resize (phone mode needs a size) and `LiveInputFrame`.
  - `BrowserSignInStatus`, `BrowserSessionItem`, `BrowserSessionList`, `BrowserContextRow`, `BrowserActivityItem` and `BrowserTabView`.
- `agent-cards.ts` gains:
  - `export * from "./browser"`, with the reason in a comment.
  - Kind `browser`.
  - `AgentCardBrowserSignInLink` and `AgentCard.browserSignIn`.
  - `viewerCan` value `sign_in`.
  - `AgentCardInput` no longer accepts kind `browser`.

**Task 2, commit `4ec6a104`.**
- `ModuleId` gains `sandbox` and `browser`, with the UI-SPEC labels and descriptions and patterns `sandbox.*` and `browser.*`. No seeded rows. No grain went into an existing module, so C-05 does not apply (a test proves it).
- Five grains were appended at the end of the enum:
  - Surface `bots`, delegable.
  - Added to STANDARD next to `bot.tool.use`, so every role holds them.
  - `AGENT_PERMISSIONS` gains only `sandbox.use` and `browser.use`.
- `isApprovableTool` accepts `/^ocw_(sandbox|browser)_[a-z0-9_]+$/`, except `ocw_browser_signin` and `ocw_browser_close`. Matching is exact lower case.
- `TOOL_APPROVAL_LIMITS.browserPendingTtlMs` is 900,000.
- `ToolCallApprovalView.browser` (`ToolCallBrowserAction`):
  - `action` includes `open`.
  - `host` and `sessionSite` are host-validated.
  - `value` is limited to 500 characters (the same limit as preview values).
- Web maps:
  - `MODULE_ICONS`: `Container` and `MonitorPlay`.
  - `OFF_COPY`: the UI-SPEC §4.1 extras.

## Deviations from Plan

1. **[Rule 3, blocking] Files outside the plan's list.** Adding kind `browser` and the new modules broke exhaustive maps and exact tests in:
   - `apps/web/components/chat/agent-card.tsx` (`KIND: Record<AgentCardKind>`, now `browser: { label: "Sign-in", icon: LogIn }`).
   - The plugin's card mirror parity test.
   - The API exact tests listed above.
   - The e2e copy.

   No W1 plan touches these files.
2. **[Rule 2, spoofing] Agents cannot post `browser` cards.**
   - Contracts: `AgentCardInput.kind` is `AgentCardKind.exclude(["browser"])`.
   - Plugin: `AGENT_CARD_KINDS` = `AGENT_POSTABLE_CARD_KINDS` + `"browser"`. Parity with the contracts is kept, while the `ocw_agent_card` tool enum and the plugin's `AgentCardInput` use the postable kinds only.

   Before this change, `AgentCardInput` was the type of the API's `insertCard`, and the API failed to typecheck against the DB column's 8-kind enum.
3. **[Name adaptation, P-17] `viewerCan.signIn` became the array value `"sign_in"`.** `AgentCard.viewerCan` is `Array<"follow" | "decide">` in the code.
4. **[Convention] `BROWSER_REFUSAL_STATUS.no_trigger` is 403, not 404.** This matches the existing Agent Channel and plan 28. `no_context` and `screenshot_unavailable` are 404 (plans 14 and 28), `timeout` is 503 and `element_gone` is 409.
5. **[Rule 2] Two privacy and validation changes.**
   - `LiveStateFrame.host` and `secure` are nullable, so the `no_permission` state does not reveal the page.
   - `LiveStateFrame.approvalRoute` and `BrowserContextRow.conversation.route` use `AgentCardRoute` (internal routes only). That needs one import of the 07.5 leaf `agent-card-route.ts`, beyond the planned "imports only common.ts". It is not a 07.8-01 file.
6. **[D-14] `BrowserSandboxMode` and an optional `BrowserTabView.browserSandbox`.** The Browser tab footer must not claim gVisor isolation on a `container-only` host.
7. **[Flake, WINDOWS #119] One rerun.** The third `pnpm verify` run failed only on `apps/api/src/modules/ai-chat/multiplayer.int.test.ts`: "Timed out after 10000ms while waiting for container ports to be bound" (Redis testcontainer). The one rerun was fully green.
