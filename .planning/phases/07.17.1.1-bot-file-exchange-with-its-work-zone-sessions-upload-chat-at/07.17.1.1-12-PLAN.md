<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cell → API | Ids and a repo-relative path from a less-trusted cell, possibly steered by outside content |
| asker ↔ sponsor | The attachment is decided with the asker's rights; the session and the transfer with the sponsor's |
| API → device | One command per call, after every decision |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.17.1.1-12-01 | Information disclosure | another thread's or conversation's file into a session | high | mitigate | `attachmentForTurn` as the asker (five refusal cases) |
| T-07.17.1.1-12-02 | Elevation of privilege | planted runtime config or secrets | high | mitigate | `workSessionFilePathRefusal` before the claim; the device re-checks (04) |
| T-07.17.1.1-12-03 | Denial of service | oversized uploads | medium | mitigate | The attachment's size against the applied limit before the claim and before any byte moves |
| T-07.17.1.1-12-04 | Spoofing | cross-tenant cell tokens or extra body keys | high | mitigate | tx0 under the cell's organization (404); strict body (400) |
| T-07.17.1.1-12-05 | Repudiation | unrecorded outcomes | medium | mitigate | One record per outcome (denied row + refusal audit, or the success audit) |
</threat_model>
