# Phase 07.14 Plan 02: Organization connector auth migration Summary

**One additive migration (`20261106163356_org_connector_auth`) adds two organization auth modes to `mcp_servers.auth_mode`, adds a closed-code `auth_failure` column, and creates `app.connector_org_connections`, which has tenant RLS and a composite FK to the organization's own server. It is tested on ephemeral PostgreSQL, as `ocw_app` across tenants, and through the N-1 → N upgrade.**

## Intended schema change (plan mode, CLAUDE.md)

Written before the migration was generated:

- `app.mcp_servers.auth_mode`: the check `mcp_servers_auth_mode_check` is dropped and re-added in one `ALTER TABLE` with `org_oauth` and `org_client_credentials` added. Existing rows keep their mode. `mcp_servers_auth_mode_transport_check` (`auth_mode = 'org_secret' or transport <> 'sandboxed-stdio'`) does not change, and it already refuses both new modes on the stdio sandbox.
- `app.mcp_servers.auth_failure text` is a new nullable column. Every existing row gets null. The new check `mcp_servers_auth_failure_check` allows null or one of the eight D-10 codes.
- `app.connector_org_connections` is a new table with these columns: `id`, `organization_id` (FK organization, cascade), `server_id`, `method` (`oauth` | `client_credentials`), `status` (`connected` | `needs_reconnect`), `secret_id` (FK secrets, set null), `issuer`, `client_id` ≤ 256, `token_endpoint` ≤ 2000, `scopes text[] default '{}'`, `account_label` ≤ 200, `access_expires_at`, `last_error` ≤ 64, `connected_by uuid` (no FK), `connected_at`, `updated_at`, `last_used_at`.
  - Unique `(organization_id, server_id)`.
  - Composite FK `(organization_id, server_id)` → `mcp_servers (organization_id, id)` on delete cascade.
  - The existing post-migrate loop gives it ENABLE + FORCE RLS and `tenant_isolation`. There is no owner-only policy and no SECURITY DEFINER function.
- What the migration does not do: drop a table, change a column type, or update data. Rolling back needs a follow-up migration; the SQL header gives the rollback statements.

## Accomplishments

- The two organization modes and the failure code can be stored, and PostgreSQL refuses anything outside the closed sets.
- The organization's account per server is stored in `connector_org_connections` with tenant RLS. The composite FK stops a row from naming another organization's server, even though FKs bypass RLS.
- The `ocw_app` tests show that one organization cannot see, update or delete another's connection, or forge one.
- The upgrade test shows `ocw upgrade` applies the migration with every existing server unchanged and no new rows.

## Decisions Made

- The new table has only the composite FK to `mcp_servers`, with no extra single-column FK, so the key always carries the organization (07.6 precedent). `secret_id` keeps the plain set-null FK, as `connector_connections` does.
- The schema's literal lists are local `const` tuples, because the db schema imports nothing from contracts. Drift is caught by the test, which iterates `ConnectorAuthFailure.options` from `@ocw/contracts` against the column.
- The tenant case asserts the table's policy set is exactly `["tenant_isolation"]` with FORCE RLS, which proves the PD-05 prohibition (no owner-only policy).
