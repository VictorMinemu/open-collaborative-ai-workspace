# Phase 07.13 Plan 03: The Work Zone browser migration Summary

One additive migration (`20261125164903_work_zone_browser`) adds the organization's browser switch, the device's own
opt-in and capability version, an owner-only `app.work_browser_signins` table (sealed `browser_session` secret, clean-up
and member-gone triggers), an audience-bound `app.work_browsers` row per session, and per-organization purge and sweep
functions. All of it is proven on ephemeral PostgreSQL only.

## What was built

- **Schema (`packages/db/src/schema/app.ts`)**
  - `workZonePolicies.allowBrowser`: default false.
  - `devices.browserOptIn`: default false.
  - `devices.browserVersion`: nullable, `devices_browser_version_ck` allows 1 to 100.
  - `workBrowserSignins`: composite secret FK (cascade), `work_browser_signins_owner_site_uq`, `work_browser_signins_org_id_uq`, secret index and host check.
  - `workBrowsers`: PK `work_session_id` with a composite session FK (cascade) and a composite sign-in FK (`SET NULL ("signin_id")`). Checks: state, origin, upload origin, lease and upload.
- **Migration**: the house header with the rollback recipe. It also adds two SECURITY DEFINER trigger functions, `work_browser_signin_secret_cleanup` and `work_browser_signins_member_gone`. They fire on `org_members` deactivation, on `org_members` delete and on `auth.member` delete. Both have a fixed search_path and `REVOKE ALL … FROM PUBLIC`.
- **post-migrate.sql**
  - `personal_owner_only` RESTRICTIVE on `work_browser_signins`.
  - `audience_backstop` RESTRICTIVE on `work_browsers`.
  - `REVOKE TRUNCATE` on both tables.
  - `app.work_browser_sweep_organizations`: returns ids only, keyset by id, limit clamped to 1 to 1000.
  - `app.purge_work_browser_signins`: works in the caller's organization only and returns `id, user_id, site_key`.
  - Both functions are SECURITY DEFINER, revoked from PUBLIC and granted to ocw_app.
- **Tests**
  - `work-browser-schema.int.test.ts` (14 tests): defaults and checks; owner-only reads and writes for another member, an admin and a user-less session; cross-tenant isolation; the unique key and host check; secret clean-up; member-gone triggers; policies and TRUNCATE; one row per session, cascade and SET NULL; lease, upload and origin checks; audience (a member outside the audience reads 0 rows and cannot write); purge isolation; sweep listing and keyset; function privileges.
  - `upgrade.int.test.ts`: the migration is now listed last. After the upgrade from 07.18, devices read `browser_opt_in = false, browser_version = null` and the policy reads `allow_browser = false`. The new tables are empty and accept a row.

## Notes for later waves

- After a sign-in is deleted, `signin_user_id` is not cleared: only `signin_id` becomes null. Plans 16 and 17 must clear `signin_user_id` themselves when they unlink.
- `work_browsers.lease_id`, `controller_user_id` and `lease_expires_at` must be set or cleared together. The lease check refuses a partial lease. The upload columns work the same way.
- A user-less tenant transaction (Device Link, sweeps) passes `audience_backstop`, but `personal_owner_only` hides every sign-in from it. Device paths that need a sign-in must run as the member, or go through a SECURITY DEFINER function.
- The sweep returns only organization ids. Per-organization work runs in `withTenant()` and calls `purge_work_browser_signins(now())`. That call returns `id, user_id, site_key` for the audit, never a secret id.
