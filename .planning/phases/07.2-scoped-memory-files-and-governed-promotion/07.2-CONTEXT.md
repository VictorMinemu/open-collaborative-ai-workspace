# Phase 07.2: Scoped memory files and governed promotion - Context

**Gathered:** 2026-10-08 (owner: "ponte a planificar cada mejora…"; decisions from `.planning/research/OPS-FEATURES.md`)
**Status:** Ready for research

<domain>
## Phase Boundary

Owner requirement: **a viewer of files, folders and subfolders where bots keep their memory as `.md` files**. Memory
becomes platform-owned Markdown files per scope with a viewer, and shared writes are governed by detection + human
approval applied by the server. Work Zone → memory ingestion is Phase 07.6; semantic search is out of scope.

</domain>

<decisions>
## Implementation Decisions

### Common to phases 07.1–07.7 (orchestrator, 2026-10-08)
- **C-01:** The Control Plane owns the feature. Agents act only through `ocw_*` plugin tools that the Agent Channel API
  decides (resolver, agent ∩ human, taint) and audits; OpenClaw's in-cell equivalents (file memory, cron, webhooks,
  `sessions_send`, exec approvals, per-requester MCP OAuth) stay off (principles 6, 9, 12).
- **C-02:** Contracts first (Zod in `packages/contracts`), RLS on every organization-scoped table with a cross-tenant
  test, an audit event for every sensitive action, `pnpm verify` (incl. `pnpm guard`) green before every commit, TDD.
- **C-03:** UI work is verified at 1440 and 390, light and dark, with reviewed screenshots and e2e through
  `scripts/e2e-isolated.sh`; Woodpecker CI must stay green.
- **C-04:** No new paid or hosted service; any new dependency is pinned, license-checked by `pnpm guard`, and justified.
- **C-05:** Research for this phase: `.planning/research/OPS-FEATURES.md` (the F-numbers below). Code references there
  were taken at `main` 4644fcd; re-check them.

### Phase decisions
- **D-01:** OCW owns memory as virtual `.md` files in Postgres (`memory_files` + append-only `memory_file_revisions`),
  scopes personal | agent | project | team | org, relative paths, folders from paths, a `MEMORY.md` per scope — F4. The
  OpenClaw memory slot stays `none`; the cell's files are not used.
- **D-02:** Agent tools `ocw_memory_list`, `ocw_memory_read`, `ocw_memory_write` (own scopes) and `ocw_memory_propose`
  (shared scopes) through the Agent Channel API; the existing `ocw_memory_save` notes are migrated into each
  (bot, human) personal scope and keep "admins never read personal memory" (ADR-0010).
- **D-03:** Viewer: react-arborist tree (verify maintenance and a11y; alternative acceptable), the shared `<Markdown>`
  renderer for reading (no raw HTML), CodeMirror 6 for editing Markdown source, `@codemirror/merge` for diffs; desktop
  tree | file | history, 390 px full-screen tree → file with View/Edit/History tabs + breadcrumb. An agent's page shows
  its memory and its capabilities/skills read-only. FTS search over memory like chat.
- **D-04:** Permissions `memory.read|write|promote` decided by the resolver on the scope's unit; per-folder rules via a
  path prefix on permission rules (deny wins) — F5.
- **D-05:** **Approve-and-apply primitive** (reused by 07.5, 07.6): an approval card whose decision the server applies,
  with a one-use grant bound to a hash of the exact action; designed generically in contracts and the API.
- **D-06:** Detector layers: (1) TypeScript regex/checksums (secrets via the existing redact patterns, IBAN, cards with
  Luhn, NIF/NIE, email, phone) — always on, secrets blocked; (2) Presidio as an optional compose profile; (3) a model
  classifier is **not** in this phase (metered; backlog). Findings and reader count appear in the approval card; no
  auto-approval.
- **D-07:** Requires plan mode-level care: new permissions, RLS and audit (CLAUDE.md).

- **D-08 (orchestrator, after research):** research design accepted — a dedicated `approval` module
  (`approval_requests` + a type registry with `hashInput/canDecide/apply/view`, modes `server_apply` for 07.2 and
  `grant` for 07.5) with its own decision route and a `/memory/proposals` inbox, because approvers may not read the DM
  where a proposal starts; proposal cards are `platform_owned` (server-composed, agent PATCH → 403); agent reads of
  shared memory are decided as agent ∩ requesting human ∩ every reader of the conversation (audience rule); personal
  memory is owner-only in the resolver **and** a restrictive RLS policy on `app.user_id`, audit without paths or
  content; secrets are blocked on every write (human edits too), with `redact()` patterns moved to contracts keeping
  `redact()` output identical; tree library `@headless-tree/react` instead of react-arborist; Presidio `pii` profile with
  a derived Spanish image (spaCy model in its own container) and a 2 s fail-open-with-visible-warning call (never
  auto-approve). Defaults confirmed: tainted turns may propose (flagged) but not write; scope `unit` covers department,
  team and project; admins read unit memory, never personal; self-approval only in personal scopes. `ocw_memory_save`
  keeps working by appending to the personal `MEMORY.md`. ADR-0023.
- **D-09 (orchestrator):** phases 07.1–07.4 each add a migration, permission grains and an ADR. They execute one phase
  at a time (07.3 → 07.1 → 07.2 → 07.4), each rebased on main, so drizzle snapshots, the upgrade test's `HEAD_ONLY`
  list and the permission enums never conflict.
