# Phase 07.6 Plan 04: Test fakes (GreenMail + fake ERP MCP) Summary

**Disposable GreenMail for IMAP integration tests, a "changed elsewhere" ERP MCP with compare-and-set writes at
`/erp-mcp`, and opt-in GreenMail on 127.0.0.1:4294/4295 in the isolated e2e stack.**

## Performance

- **Duration:** about 15 min

## Accomplishments

- `startGreenMail({ users })` in `apps/api/src/testing-mail.ts`: GreenMail 2.1.14 pinned by digest, SMTP 3025 / IMAP
  3143 / IMAPS 3993 mapped on 127.0.0.1, random passwords per run, waits for the IMAP `* OK` greeting, `sendMail()` over
  nodemailer with `messageId` and arbitrary headers, `stop()` removes the container.
- `createFakeErpMcp({ token })` in `infra/fake-model/fake-erp-mcp.mjs`: SO-10442 / SO-10443 seed, `update_record`
  refuses a stale `expectedUpdatedAt` with `isError` + `{ error: "conflict", updated_at }` and changes nothing,
  `__mutate` bumps `updated_at`, `add_note` does not; `state.records / notes / calls` and `reset()` for in-process tests.
- The fake server mounts it at `/erp-mcp` (`OCW_FAKE_ERP_TOKEN`, default `e2e-erp-token`; `opts.erpToken` in tests).
- `OCW_E2E_MAIL=1 bash scripts/e2e-isolated.sh` starts GreenMail through `scripts/e2e-greenmail.sh`, exports
  `OCW_E2E_IMAP_PORT` / `OCW_E2E_SMTP_PORT`, adds `greenmail=127.0.0.1` to `OCW_EGRESS_TEST_HOSTS` and removes the
  container in the existing trap. Without the flag every mail line is skipped.
