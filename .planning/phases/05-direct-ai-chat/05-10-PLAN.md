## Phase Goal

**As a** member of an organization that uses the workspace, **I want to** hold a private, streaming AI conversation on my own ChatGPT plan by default or on a model my organization pays for — choosing the model per message, stopping and regenerating answers, with titles, instructions, web search, files, a usage record for every answer and a read-only share link for colleagues — **so that** I get a ChatGPT/Claude.ai-quality assistant inside the workspace where every generation is metered, private by default and attributable.

**This plan's slice (tracer):** the owner clicks Share in the chat header, the API freezes a snapshot and returns `/share/ai/<id>`, and a colleague signed in to the same organization opens that link and reads the transcript. Then revoke, the privacy edges and share-scoped images. Planner decisions P-01 … P-14 are in `05-01-PLAN.md` (P-08 executor rules, P-09 UI); multiplayer sharing in place is Phase 6 (P-14).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| any browser → `/share/ai/<id>` and `/api/v1/ai-shares/*` | Link holders; only signed-in members of the org may read |
| owner → create/revoke | Owner-only actions on their chat |
| share routes → object storage | Presigned GETs for snapshot files only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-10-01 | Information disclosure | public or anonymous access to a share | high | mitigate | Every route `requireUser` + `ai_chat.share.read`; tenant RLS on `ai_chat_shares`; no token in URLs; int tests for anonymous, other org and deny rule |
| T-05-10-02 | Information disclosure | share revealing later or other content | high | mitigate | Immutable snapshot jsonb written once; attachment allow-list per share; int tests after new messages/regenerate and for a foreign attachment id |
| T-05-10-03 | Elevation of privilege | non-owner creating or revoking shares | medium | mitigate | Create: readable + `ai_chat.share` (owner-only precondition); revoke: `created_by`; hidden = 404 |
| T-05-10-04 | Information disclosure | share ids enumerated to probe existence | low | mitigate | uuidv7 ids, signed-in members only, revoked/missing/other-org identical 404 |
| T-05-10-05 | Repudiation | untracked sharing | low | mitigate | Audits `ai_chat.share_created`, `ai_chat.share_revoked`, share downloads |
</threat_model>
