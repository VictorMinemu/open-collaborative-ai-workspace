# Phase 07.13.1.1 Plan 07: Sessions by person view, row actions, sidebar link and naming-rule fields Summary

`/work-zone/people` groups every Work Zone session the viewer can see by its owner ("You" first, then by name, former members last). Each group shows an avatar, the name and a count. Rows have the runtime logo, the title, project · online dot · device with a "Server" marker, the last activity and the status. Person, Project and Device filters live in the URL. Each row has a 44 px "Session actions" menu that reuses plan 06's Rename and Assign dialogs. The sidebar foot links the view. Settings › Work Zone policy and the project Settings tab each have a "Session names" naming-rule field.

## Accomplishments

- **Task 1 (tracer): the view.**
  - `peopleModel(sessions, viewerId, filters)` is pure. Its only input is `useWorkSessions()`.
  - Route `app/(app)/work-zone/people/page.tsx`: a static segment matched before `[id]`, wrapped in Suspense for `useSearchParams`.
  - `PeopleView` reads the filters with `useSearchParams` and writes them with `router.replace(…, { scroll: false })`.
  - States: loading skeleton, `ServerUnreachable` "Couldn't load sessions.", "No sessions you can see yet.", and "No sessions match these filters." with Clear filters.
- **Task 2: row actions, filters and sidebar.**
  - `rowActions` decides what each row's menu offers. `RowMenu` shows Open, Rename… and either Assign to me… or the muted reason line. The testids match plan 06's: `session-rename`, `session-assign`, `session-assign-reason`.
  - The menu button sits outside the row link: `size-9 max-md:size-11`, aria-label "Session actions for <title>".
  - Filter bar below 640 px: Person full width, then Project and Device side by side, then the count line with Clear filters. From 640 px everything is on one row. Every select is `max-md:h-11`. Each select has a leading icon and is tinted while it filters.
  - `SidebarFooterLinks` (testid `sidebar-people`, `aria-current` on the view). `PEOPLE_PATH`, and `isSessionPath` excludes `/work-zone/people`.
- **Task 3: naming rules.**
  - The shared `NamingRuleField` has the label "Naming rule", an n/600 counter, the helper sentence and "Use at most 600 characters.". It normalises CRLF to LF, trims, and treats a blank rule as null.
  - Policy: the new section saves with the existing PUT. Save is disabled while the field is invalid. A 400 naming `sessionNamingRule` shows inline.
  - Project: managers (`viewerCan.manage`) get the field and Save rule; everyone else gets plain read-only text (`whitespace-pre-wrap`) or "No naming rule.". The new section sits after New sessions.
