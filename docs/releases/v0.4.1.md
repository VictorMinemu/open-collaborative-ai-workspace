Attach any file to a Work Zone prompt, and the one-click runtime update reaches servers installed by an older runtime.

## What's new

- **Any file on a Work Zone prompt** (ADR-0045). The paperclip takes PDFs, Markdown, Word files, spreadsheets, archives
  and anything else, up to 10 per prompt. Images the model can read still go straight to the model. Every other file,
  and an image the model cannot read, is copied into the session's working tree at `.ocw/uploads/` before the turn
  starts, and the agent is told where it is.
  - An existing file is never overwritten (`name-1.ext`).
  - If a copy fails, the prompt does not run and the composer says which file failed and why.
  - In a git project, `.ocw/uploads/` is added to the repository's local exclude list (never to `.gitignore`), so the
    agent does not commit uploads by accident.
  - Files share the organization's per-file limit for bots (Settings › Work Zone policy, "Largest file a bot moves").
  - A device whose runtime is too old to receive files shows "Update this device to attach files".

## What's fixed

- **No "Update" button for the OCW runtime on servers installed by v0.2.x.** Their systemd or launchd unit was written
  before the runtime marked itself as a service, so Settings › Devices said "Run as a service to update from the
  browser" although it ran as one. The runtime now accepts such a unit when the unit itself proves it restarts the new
  build (our header, the install's `current`, a restart on exit 75, no drop-in overrides). `ocw-runtime doctor` and
  `ocw-runtime service status` flag an outdated unit with one fix line: `ocw-runtime service install`.

## Upgrade

In `/opt/ocw` (or wherever the server is installed):

```bash
sudo node scripts/ocw.mjs upgrade --check   # current and newest release; changes nothing
sudo node scripts/ocw.mjs upgrade           # backup, this release, new keys, rebuild; never goes backwards
```

- **One migration**, additive (`work_prompt_files`).
- **Headless Work Zone servers** update their runtime with one click (Settings › Devices › the server › Runtime updates
  › **Update**), or by themselves at the *Automatic* level. A server installed by v0.2.x shows the button only from this
  runtime on: once, run `ocw-runtime service install` on it (it rewrites the unit and restarts when no session runs).
- Attaching files needs the updated runtime on the device that runs the session.

The desktop app does not update itself: install the new files below. Its runtime ships inside it.
