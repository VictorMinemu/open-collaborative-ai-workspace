# Phase 07.13 Plan 10: Work Zone live view in the API Summary

A session's audience can now watch the page the session drives on its device, live, over a dedicated binary WebSocket. The device is asked for frames only while someone allowed watches. A per-frame gate keeps a member's loaded sign-in or a takeover private. Viewers on another API instance get the frames through Redis, only while they watch.

## What was built

- **Task 1 (tracer, TDD): the live socket.**
  - `GET /api/v1/live/work-browser/:sessionId` is registered like the bots' route: `authenticateUpgrade` in `onRequest`, `authz: "user"`, a malformed id gets 404.
  - Each viewer is decided with `work_session.read` on `sessionFacts`, in the viewer's tenant. Unknown, foreign-tenant and out-of-audience sessions are closed with 4403.
  - `viewerCan` is sent first, then `state`. JPEGs go out through the bots' `FrameSlot`, imported only from `../browser`.
  - The device gets `browser.frames { on: true }` when the first allowed viewer arrives and again every `watchPingMs`. It gets `on: false` when the last viewer leaves.
  - `index.ts` registers the view and assigns `onBinary`: decode the frame, check that the session runs on the sending device (cached 5 s, one read at a time), then pass it to `live.onFrame`.
- **Task 2 (TDD): privacy gate and re-authorization.**
  - The `work_browsers` row is polled every second while someone watches.
  - `lease_id` set: only the socket registered with `registerLeaseSocket` gets frames (`controlling`). Everyone else gets `private` with reason `takeover` (`other_device` or `other`) and the controller's name.
  - `signin_user_id = M`: only M's sockets get frames. The others get `private` with reason `member_session`, M's display name and no host.
  - Closed row: every viewer gets `ended { endReason }`, the socket closes with 1000, and the device gets `on: false`.
  - Invalidations from the gateway's bus and revocations re-decide each viewer, and so does the per-socket session recheck. A 10 s heartbeat (`heartbeat()`) resends each viewer's state.
- **Task 3 (TDD): cross-instance relay.**
  - `live-relay.ts` uses `hold`, `touch`, `announceWatch`, `remoteWatching`, `publishFrame` and `subscribeFrames`.
  - A frame is published only while another instance announced within `watchLapseMs`.
  - Bus messages are parsed, bounded and dropped when malformed.
  - Log lines carry only ids and error names.

## Deviations from Plan

1. **[Rule 3 - Blocking] Files outside `files_modified`.**
   - `app.ts`: one line passes the gateway's `allowedOrigins` to `createWorkBrowserModule`. Without it the route refuses every Origin.
   - `live-testing.ts`: a new test helper both test files share. It cannot reuse the bots' `live-testing.ts`, because the acceptance grep forbids `../browser/` imports.
   - `browser/live-view.int.test.ts`: its registry pin "the one live route" now lists both live routes, each still `user`. No check was weakened.
2. **[Interpretation] Access removal is tested on Mia, a device-shared viewer, not the creator.**
   - The plan's behavior says "removing the creator from the session's audience".
   - A personal session's creator is always in its audience, so the test removes Mia's device grant instead.
   - That triggers the org invalidation: `no_permission`, then 4403.
3. **[Design] Relay surface.**
   - `onRemoteWatch(cb)` became `remoteWatching(sessionId)`, plus `hold`/`touch` to follow the watch channel. Nothing needed a callback.
   - Frame messages carry `i` besides `{ w, h, b64 }`, so an instance ignores its own frames.
   - Every instance with viewers announces and follows, which keeps the device on while another instance watches.
   - Fast pings (1 s, at most 10) bridge the first-frame gap.
4. **[Design] `endReason` comes from the last `work_browser.closed` audit row of the session.**
   - The row has no end-reason column.
   - `closed_by_bot` is never used. A plain close maps to `idle`.
5. **[Additive] Extra tests.**
   - A tenant-isolation test: organization B's admin gets 4403 and no stream. It was added after GREEN and passed as written, because the behavior already held.
   - A malformed-bus-message test for the relay.
