## Phase Goal

A controller pastes, drops or attaches images in the Work Zone composer and the session's runtime (Claude Code or
Codex) receives them with the prompt; everyone in the session sees the sent images in the stream.

**This plan's slice (tracer, device level):** a `prompt` command with `images` (as 06.1-02 sends it; built by the tests here, since the two plans run in parallel) goes through
the real daemon into the runtime and comes back as a visible result — then the two real adapters are pinned against
their installed input types with tests. Planner decisions: `06.1-RESEARCH.md` (P-01 … P-12); executor rules P-13 in
`06.1-01-PLAN.md`.

<objective>
Make the device side honest about images: bounded parsing and frame size, refusal where a runtime cannot take them,
clear failures, no image data in anything the daemon reports, and adapter tests for Claude Code (Agent SDK 0.3.282)
and Codex (app-server 0.160.0) including steer and model capability.

Purpose: WZ-IMG-03 (device half); D-05, D-07, P-07, P-08, P-10, P-11.
Output: pinned `maxPayload`, daemon image refusal and redaction, fake runtime images, adapter and catalog tests, one
synthetic Codex fixture.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → daemon (command frames) | Server-authored but untrusted size and content at the device edge |
| daemon → runtime (stdin / JSON-RPC) | Image bytes leave the daemon only into the session's runtime process |
| runtime → daemon → API (events, acks, logs) | Untrusted text that may echo input |
| image content → model | Untrusted user content (text in a screenshot may try to instruct the agent) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.1-03-01 | Denial of service | oversized or numerous images in a frame | medium | mitigate | `maxPayload` pinned to the shared constant; `PromptPayload` bounds (count, base64 length, media types) before any adapter call; tests (Task 1) |
| T-06.1-03-02 | Information disclosure | base64 echoed in ack errors, logs or `session.error` | medium | mitigate | `stripImageData` on all three; Codex `userMessage` items never mapped; tests incl. the synthetic replay (Tasks 1, 2) |
| T-06.1-03-03 | Tampering / Information disclosure | images written by the daemon to disk, a worktree (and the diff) or tmp | medium | mitigate | In-memory only; Claude base64 blocks, Codex data URLs; no path-based input item (acceptance grep). The runtimes' own transcript persistence (Claude `~/.claude/projects/*.jsonl`, Codex rollouts) is out of scope (owner's device, same as prompt text) |
| T-06.1-03-04 | Tampering | images silently dropped by a runtime that cannot take them | medium | mitigate | Daemon refusal on `supportsImages: false`; Claude `image_error` and Codex turn errors surface as failed prompts (Tasks 1, 2) |
| T-06.1-03-05 | Elevation of privilege | instructions embedded in an image steering the agent | medium | accept | Images are user content of that turn only; they never change the permission mode, settings, slash handling or approvals, which stay enforced by the platform (P-07 per-turn mode) and the runtime's own permission flow; same trust as the prompt text its author typed |
| T-06.1-03-06 | Information disclosure | host paths or filenames reaching the runtime/provider | low | mitigate | The payload carries media type and bytes only; no filename or path field exists in `PromptImage` |
</threat_model>
