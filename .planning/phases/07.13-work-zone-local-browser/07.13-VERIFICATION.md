# Phase 07.13: Work Zone local browser Verification Report

**Phase Goal:** A Work Zone session can use a browser on its own device. Claude Code and Codex open pages (the device's
`localhost` included), read them, click, type and take screenshots, while the session's audience watches live. It is
governed like the bots' browser and delivered by the upgrade. Widened scope (owner, 2026-11-25): a person signs in to a
page from the live view, and that sign-in is saved for that user and reused in their later turns.

### Gaps Summary

No blocking gaps. The phase's code delivers every success criterion and requirement, and every HIGH review finding
(HI-01…HI-06) is fixed in the code with tests. Those tests pass when run here: 2618 unit, 146 integration, 401 web and
144 desktop tests. What remains is evidence that cannot be produced here: the CI run on HEAD (pending), the full
headless container proof (never run end to end), the real Claude Code and Codex CLIs, the real upgrade of an installed
device, the visual review, and the real-account UAT.

One residual is flagged for the owner, not as a blocker. The HI-06 fallback stops the shim token from reaching a
**loaded** sign-in and refuses `ocw_browser_signin` on a shared device. It does not cover a page the member signed in to
by hand through a **spontaneous** takeover that ends with "Done" without saving. On a device where another member's
Codex session runs, that page stays drivable via the shim token during the member's turns.

## Update 2026-11-25: HI-06 residual closed

The hand-signed-page residual above is closed by `46ff42d5` (merged in `e876e71e`): in a Codex session, a page a member
signed into by hand closes on "Done" (or as soon as another person's session starts or resumes) whenever another
person's session is live on the device; the agent's next call is told why. Claude sessions are unchanged.
