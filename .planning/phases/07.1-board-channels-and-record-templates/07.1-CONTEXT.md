# Phase 07.1: Board channels and record templates - Context

**Gathered:** 2026-10-08 (owner: "ponte a planificar cada mejora…"; decisions from `.planning/research/OPS-FEATURES.md`)

<domain>
## Phase Boundary

Teams run any workflow (case files, orders, tickets, candidates) as a board channel whose cards are threads with their
agent, plus record templates that name cards. External-system column sync is **out of scope** (backlog OPS-BL-04);
watched records are Phase 07.6.

</domain>

<decisions>
## Implementation Decisions

### Common to phases 07.1–07.7 (orchestrator, 2026-10-08)
- **C-01:** The Control Plane owns the feature. Agents act only through `ocw_*` plugin tools that the Agent Channel API
  decides (resolver, agent ∩ human, taint) and audits; OpenClaw's in-cell equivalents (file memory, cron, webhooks,
  `sessions_send`, exec approvals, per-requester MCP OAuth) stay off (principles 6, 9, 12).
- **C-02:** Contracts first (Zod in `packages/contracts`), RLS on every organization-scoped table with a cross-tenant
  test, an audit event for every sensitive action, `pnpm verify` (incl. `pnpm guard`) green before every commit, TDD.
- **C-03:** UI work is verified at 1440 and 390, light and dark, with reviewed screenshots and e2e through
  `scripts/e2e-isolated.sh`; Woodpecker CI must stay green.
- **C-04:** No new paid or hosted service; any new dependency is pinned, license-checked by `pnpm guard`, and justified.
- **C-05:** Research for this phase: `.planning/research/OPS-FEATURES.md` (the F-numbers below). Code references there
  were taken at `main` 4644fcd; re-check them.

### Phase decisions
- **D-01:** Keep `conversations.kind='channel'` and add `layout: 'text'|'board'` (a new kind touches ~35 sites) — F12.
- **D-02:** Tables `board_columns` (name, rank, category backlog|started|done|cancelled, optional `external_state_id`
  reserved for later sync) and `board_cards` (PK = root `message_id`, column_id, fractional `rank`, `waiting_on`
  none|us|customer|both, optional `external_ref`, `version`). A card is the root message of a normal thread; its body is
  a plain-text summary so search works unchanged.
- **D-03:** Realtime: durable `board.*` events on the `conv:` stream with seq/cursor replay.
- **D-04:** Web: `@dnd-kit` (verify the current stable package and a11y), a "Move to…" menu on every card, column tabs at
  390 px; clicking a card opens the existing thread panel; the create-channel dialog offers text or board (no voice).
- **D-05:** Ordering with fractional indexing and a server re-rank on collision; optimistic `version` on card updates.
- **D-06:** Record templates (F14) per unit: typed fields (Zod), default columns with category and initial
  `waiting_on`, naming rule `{prefix}-{seq} · {field} · {summary}` with a per-board counter; reuse `TitleSource`
  user|heuristic|auto; a user-typed title is never replaced. A model-generated `{summary}` is optional and paid by the
  card creator's AI chat backend rules — confirm in research or leave summary deterministic (first line) by default.
- **D-07:** Who may create boards, columns and templates: reuse channel management grains; agents may create and move
  cards only through Agent Channel endpoints (principle 9).

### Claude's Discretion

</decisions>
