## Phase Goal

**As a** member of a team that works in the workspace, **I want to** hold my whole daily conversation there — channels grouped by department and team, DMs and group DMs with people and bots, messages I can edit, delete, react to, pin, save and link to, @channel/@here and notifications I control, search and files — **so that** I do not need a second chat tool and every message stays attributed, editable under audit and delivered in realtime.

**This plan's slice (tracer):** Sam's sidebar shows "3" on #random and a mention badge on #general as messages arrive, and opening them clears both on every device (snapshot counts → live deltas → read route → `conversation.read` → other tab). Planner decisions P-01 … P-12 are in `04-01-PLAN.md` (P-04, P-07, P-08, P-09).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → read/unread routes | Untrusted seq values and message ids |
| API → `user:<id>` | Read-state events to the member's own devices |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-10-01 | Information disclosure | counts leaking activity of unreadable conversations | medium | mitigate | Counts only on resolver-filtered list rows; unjoined/hidden conversations report nothing or 404 |
| T-04-10-02 | Tampering | forged read markers for other users | low | mitigate | Updates scoped to the caller's membership row; events only on `user:<me>` |
| T-04-10-03 | Information disclosure | message existence through `unread` with foreign ids | low | mitigate | Message must belong to the readable conversation; otherwise 404 |
| T-04-10-04 | Denial of service | expensive count queries | low | mitigate | LATERAL count capped at 100 on existing indexes (`messages_conv_seq_idx`, `notifications_unread_idx`) |
</threat_model>
