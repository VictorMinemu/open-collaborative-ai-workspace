# Phase 07.2 Plan 11: Agent Channel memory routes and memory files in the turn Summary

**Bots now use memory through the real Agent Channel API. Each call must belong to a live turn whose human still reads
the conversation. It is decided as the bot ∩ that human, and every reader of the conversation must be allowed to see
what the bot reads. Writes go only to the bot's own scopes, and shared changes become proposals. The legacy
`ocw_memory_save` notes and the DM memory panel now live in the person's private `MEMORY.md` with the same contract.**

## Intended change (plan mode, written before editing)

**Routes** (`apps/api/src/modules/agent-channel/memory-files.ts`, cell scope, `authz: "cell"`, `cell.sync` preHandler like
every Agent Channel route): `POST /agent-channel/v1/memory/{list,read,write,propose}` with the contract's strict bodies
(`AgentChannelMemoryList|Read|Write|Propose`; an extra `userId`/`ownerUserId` or a bad path is 400). `write` accepts a
scope id too (the plugin never sends one; the fake API answers it `own_scope_only`), so a model that names a shared
scope id gets `own_scope_only`, not a 400.

**Turn gate, in order, on every route** (one transaction, committed before any 403):
1. The turn (`agent_turns` by `eventId`, RLS = the cell's organization) must be this agent's, and its human
   (`agent_turns.user_id`, never a parameter) must still read the turn's conversation (`isReadable`, a thread judged by
   its channel). Otherwise **403 `no_trigger`** (the PR #25 rule), audited `memory.agent_refused {route, reason,
   eventId}`. This replaces the plan's in-band `unknown_turn` (orchestrator instruction); the plugin's error mapping
   gains `no_trigger` → "this conversation turn is no longer active".
2. The tool is in the delivered turn (`not_in_turn`), and still offered now (`currentTurnTools`, `memory_off`).
   Refusals are 200 `{refused}` like the contract, audited with ids only.

**Decisions:** every read is agent ∩ the turn's human (`MemoryActor` agent with the human), then the audience rule
(`decideAgentRead`) with `conversationAudience(tx, turn)`:
- `dm` / `group` / private channel → its human members (listed); public channel → unbounded; `ai_chat` → `audienceOf`
  (listed, or unbounded with a unit/org grant); a `thread` → its parent; anything else → unbounded (fail closed).
- **Personal-like memory** (the person's private scope with this bot, a personal bot's notebook) is used **only in a
  one-person DM** with its owner (ADR-0023 decision 4): read/list elsewhere → `audience_too_wide`; **propose into it
  elsewhere → `dm_only`** (the card would show its excerpt to the conversation). This is the decision on "is
  `personal` DM-only": yes, for every tool.
- A scope or file the human may not read reads as `not_found` (never revealed); `denied` stays for proposals (09).

**No scope is created for a refused read:** aliases (`personal`, `agent`) resolve to the existing row or to facts
built from the bot and the human (`resolveToolScope`); the decision runs on those facts; the scope is ensured only after
an allow. `proposals.ts` (09) gets the same order (09's broken-window candidate 4).

**Writes:** only own scopes: the turn's personal scope (1-human DM) or the notebook of a **personal** bot; a team
bot's notebook or any shared scope id → `own_scope_only`. Then ONE conditional update counts the call unless tainted or
at the cap (`tainted`, `cap_reached`), then `appendToFile` / `writeFile` in a savepoint as the agent for the human;
domain errors map to refusals (`version_conflict`, `secret_detected`, `too_large`, `scope_full`, `not_found`;
`agent_shared_write` → `own_scope_only`, other resolver denials → `denied`). `replace` needs `expectedVersion` for an
existing file. **Propose** calls `MemoryService.propose` (09 counts the call; a tainted turn proposes, flagged).

**Turn** (`turn-policy.ts`): `ocw_memory_list`, `ocw_memory_read`, `ocw_memory_propose` wherever memory is effective
(every conversation kind, and the cell-wide view); `ocw_memory_write` next to `ocw_memory_save` only in one-person DMs.
Fixed order: `web_search, web_fetch, ocw_memory_save, ocw_memory_list, ocw_memory_read, ocw_memory_write,
ocw_memory_propose, ocw_agent_card, ocw_board_card, catalog…`. Flags: list/read/propose `{false,false}`, write
`{false,true}`. `TurnContext.memoryFiles`: the private `MEMORY.md` (one-person DM, ensured on that turn after the
decision) and this bot's notebook `MEMORY.md` when it exists and `decideAgentRead` allows it for the conversation; never
in AI chats (ADR-0019: no memory once shared); each cut to 8 KiB UTF-8 with `truncated`.

**Legacy (`bot-capabilities/memory.ts`), same contract and refusal set:** `saveMemory` keeps `unknown_turn → dm_only →
not_in_turn → memory_off → (tainted | cap_reached)`, then under the `(bot, human)` advisory lock dedupes on an identical
bullet and appends `- <text>` (newlines flattened) to the private `MEMORY.md` as the agent for the human; `memoryId` =
the file id; a full file (256 KiB) → `cap_reached`; a secret → 400 `secret_detected` (a new rejection, not a refusal:
ADR-0023 blocks secrets on every write; the plugin reads 400 as "the note was not accepted"). `listMemories` /
`clearMemories` / `loadTurnMemory` read the bullets of that file through the memory service as the caller (owner-only
resolver + RLS); item ids are deterministic UUIDs of (file id, the bullet's occurrence among equal bullets, text);
deleting one bullet writes a new revision (stale id → 404); clear all = `forgetScope` (files, revisions, proposals) and
a fresh `MEMORY.md`. `app.agent_memories` is no longer read or written (not dropped).

**Wiring:** `createAgentChannelModule(core, { modelLabel, memory })`, `createBotCapabilitiesModule(core, { memory })`;
mentions and card-action turns pass the memory service and a lazy conversation audience to `turnPolicy`.

**Tests:** `memory-files.int.test.ts` (tracer, schema, turn gate incl. `no_trigger` and the human who left, audience
matrix, own-scope writes, taint, caps, secrets, proposals, cross-tenant, authz registry, plugin parity: the plugin's own
client and mirror schemas against the real routes), updated exact tool lists in `capabilities.int.test.ts`,
`tool-calls.int.test.ts` (read/propose stay allowed after a taint, write refused), `ai-chat-delivery.int.test.ts`,
`memory.int.test.ts` (storage checks read the file).

The implementation followed this plan. See the deviations for what goes beyond the plan's file list.

## Deviations from Plan

### Orchestrator instructions applied

1. **403 `no_trigger` instead of the in-band `unknown_turn`.** The four routes answer 403 `no_trigger` when:
   - the turn is unknown;
   - the turn belongs to another agent or another tenant;
   - the turn's human no longer reads its conversation.

   The refusal is audited `memory.agent_refused` and committed before the throw. `not_in_turn` and `memory_off` stay
   in-band refusals.
   - The plugin's `errorResult` maps 403 `no_trigger` to the `unknown_turn` sentence. That is two lines plus a test in
     `apps/openclaw-channel`, outside the plan's file list.
   - The legacy `POST /memories` keeps its 404 `unknown_turn` (the prohibition says its refusal set is unchanged).
2. **`personal` is DM-only for every tool.** This applies to personal-like memory generally:
   - read and list outside the owner's one-person DM: `audience_too_wide`;
   - propose outside it: `dm_only`, added in 09's `proposals.ts`, because the card would show the excerpt to the
     conversation.
3. **No scope for a refused read.** `resolveToolScope` and `ensureToolScope` in `memory/scopes.ts` and
   `memory/index.ts` decide on the alias's facts before anything is inserted. 09's `proposals.ts` now uses them too,
   which closes 09's candidate 4.

### Auto-fixed / interpretations

4. **[Rule 3] `mentions.ts` and `cards.ts` (outside the file list).** These wire the memory service and a lazy
   `conversationAudience` into `turnPolicy` for mentions and card-action turns. `bot-capabilities` imports the
   service as a type only, because a value import would create the cycle memory → agent → chat → bot-capabilities.
5. **[Rule 1] `e2e/tests/bot-capabilities.spec.ts`.** Two exact `[turn tools: …]` strings are updated to the new
   lists; this spec is not run in `pnpm verify`. `mcp-servers` and `marketplace` use team bots with memory off, and
   `board-agents` only checks containment, so they are unchanged.
6. **`write` takes a scope id.** The route body is the contract's strict object with `scope: MemoryToolScope`. A shared
   id gets `own_scope_only`, as the plan's behaviour and the fake API expect, instead of a 400. The plugin never sends
   an id.
7. **AI chats carry no memory files at all**, not even a solo chat, under ADR-0019 and the existing "no memory in any
   AI chat delivery". Their tools are list, read and propose, decided per call.
8. **Legacy secrets: 400 `secret_detected`.** It is audited `{reason: "secret_detected", chars}`. ADR-0023 blocks
   secrets on every write; this is a rejection outside the unchanged six-code refusal set, and the old plugin reads 400
   as "the note was not accepted".
9. **Legacy resolver denial → `memory_off`.** A rule that denies the private scope to the bot or the human is answered
   `memory_off`, so the refusal set stays unchanged.
10. **Item ids and times.** A legacy item id is a UUIDv8 of (file id, occurrence among equal bullets, text). Each
    item's `createdAt` is the file's `updatedAt`, because bullets carry no time.
11. **Prune test replaced** (named above). A file has no pruning; its cap is 256 KiB, which gives `cap_reached`.

## Broken-windows candidates (not written to WINDOWS.md, as instructed)
