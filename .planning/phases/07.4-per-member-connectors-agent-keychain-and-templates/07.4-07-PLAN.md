## Phase Goal

Keychain items (personal or unit scope, host allowlist) are used by handle: the API injects the secret only towards
allowed hosts, the model never receives it, and every use is audited without the value (plan map and executor rules:
07.4-01-PLAN.md).

**This plan's slice (tracer, keychain level):** a member stores a personal API key, the value is sealed to that item,
a granted bot acting for that member resolves its handle, and the API can build the injection header — with no
outbound call yet; then unit items, permissions, private hosts and grants; then the injection details and client
credentials. The agent-facing route `POST /agent-channel/v1/http-requests` is 07.4-11. Plan mode first (CLAUDE.md:
permissions and audit, D-06).

<objective>
Build the keychain module: storage of agent-usable secrets by reference, the rules that decide when an agent may use

</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| member/admin browser → API | Secret material in request bodies; host allowlists chosen by people |
| keychain → secret store | Sealed values bound to their item |
| API → token endpoint | Client-credentials exchange to a configured URL |
