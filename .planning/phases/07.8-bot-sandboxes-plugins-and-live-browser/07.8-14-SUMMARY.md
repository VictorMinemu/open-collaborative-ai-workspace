# Phase 07.8 Plan 14: API browser routes Summary

## Intended change (plan mode, P-17; written before the code)

### Decision order of every `POST /agent-channel/v1/browser/*` call

1. **tx0, no user.** The turn's human from `agent_turns` (`turnHumanOf`); no such turn of this agent in the cell's
   organization → 403 `no_trigger`, audited.
2. **txA, AS that human (read and precheck).** `liveTurn` (the human still reads the conversation, else 403
   `no_trigger`). The context of (bot, conversation, member) is read inside the tenant, with its session's site. Every
   route but `open` needs one (404 `no_context`). A context whose takeover lease is held answers 409 `paused` before any
   decision, so no budget is used. For `act` with a ref only, and only when `sandboxAvailable(…, "browser")` allows the
   call: one internal snapshot outside any transaction reads the element's role and name. If the ref is gone → 409
   `element_gone`, recorded and not counted. A grant waiting for it stays unused ("Not used").
3. **tx1, AS that human: `decideSandboxCall` (kind `browser`, shared with the sandbox).**
   - resolver `browser.use` for agent ∩ human → organization switch → kill → the bot's `capabilities.browser`;
   - the tool on the delivered turn (`policy_changed`);
   - sandboxd configured;
   - the shared 40-call budget under the turn row lock;
   - the organization's browser cap (`maxBrowsers`, `brw`) under its advisory lock, dry run;
   - 07.5 `approvalForCall` with the canonical arguments, plus the floor and TTL below;
   - the slot reserved;
   - the claim: one conditional UPDATE counts `sandbox_calls`, and taints the turn for open, snapshot, screenshot, wait
     and act.

   A refusal is recorded in `agent_tool_calls` and audited `bot.tool_call`. On `approval_required` or
   `approval_pending`, the context is held: `state paused`, `paused_for approval`, `held_until` = now + 15 min. After the
   commit, sandboxd `contextHold`. The context row is created here for a first `open`, under a per-(bot, conversation,
   member) advisory lock, so one context exists per triple. It holds the target's host only.
4. **Outside any transaction: sandboxd.**
   - `browserEnsure` when the bot's `brw` is not running. The organization policy is pushed first, so a restarted
     broker never runs on defaults.
   - The op itself. `open` re-creates a context sandboxd lost (`no_context`) with `siteLock` = the session's site when a
     session is loaded.
5. **tx2, AS the human: the outcome.**
   - the context's host, secure flag, hold released, or ended;
   - the ledger row's status and duration;
   - the host-only outcome audit;
   - the activity step.

   A `paused` answer from sandboxd (takeover) gives the budget back.

## Outcome

A bot now opens, reads and acts on web pages only through the Control Plane.

- Each call is decided like a sandbox call. It counts against the same 40-call budget and the organization's browser
  cap, and it stops on the kill switch.
- Every place records the host only: the context row, audit, the ledger and the activity.
- The model never sees a password, even when the broker or agent has a bug: the API's second pass replaces any leaked
  value and records an incident.
- On an anonymous page the bot browses freely.
- Once a member's session is loaded for the page, every click or keystroke waits for that member's yes. The page is
  held 15 minutes and the approval expires with it.
- Once signed-in data is in the turn, reaching another host needs an approval too, through `open` or through a click
  the site lock stopped (D-13).

2. **[Rule 2] The element check before the decision.** `act` with a ref reads one snapshot first, outside any
   transaction and only when the browser is available. That gives the element's role and name for the approval
   (R8) and the step. A ref that is gone is refused `element_gone` before the claim, so an approved grant stays
   unused ("Not used", R9). This costs one extra sandboxd call per act.
3. **[Rule 2] `member_data` is set by the API.** Any turn that operates a context with a session gets `member_data`
   set to true, so D-13 holds on re-run turns too. 21 also sets it when it loads a session.
4. **[Rule 2] The site lock as a second line.** An `open` redirected cross-site, or an act the lock stopped, becomes
   the requester's approval when the turn has member data, and `navigation_refused` otherwise.
5. **[Rule 1] A page closed between the precheck and the decision** is refused `no_context` before the claim, so it
   costs no budget.
6. **[Rule 2] `pushPolicy` before every `browserEnsure`.** After the merge, the module client's `policy_missing`
   recovery covers the browser ops as well (regression test `8f6518bc`).

### Plan text vs. what was built

- **`cap_reached` answers 403** (contract `BROWSER_REFUSAL_STATUS`), not 409.
- **The typed step uses the fake's "Email" field** (`“Email” on panel.fake.test`); the plan's example said
  `“Search”`.
- **The snapshot is read raw** (`client.stream`) and parsed without the contract's redaction refinement. A leaked
  value is then the API's incident, not a parse failure. The text the model reads is composed from the passed nodes
  in the agent's own line format; sandboxd's text is never forwarded.
- **The act's new host after a navigation** comes from a `contextWait {for: time, ms: 0}`, because
  `SandboxdActResult` has no host.
- **The kill switch** closes contexts through sandboxd's `closed` events (`kill_switch` while the organization is
  killed, otherwise `idle`). The next refused (`killed`) browser call also closes them. `killSandboxes` itself was
  not touched, because the sandbox module was in flight elsewhere.
- **Downloads** from `act` answer `download: null`. Plan 25 owns F-8.
- **Incident audit action**: `browser.redaction_incident` (ids and a count).
