# Phase 07.10: Work Zone sidebar by team - Context

**Gathered:** 2026-10-27.
- **Owner's request:** after phase 07.9 shipped, the owner did not see projects in the Work Zone sidebar and asked:
  "quiero que sea como por canales según el equipo… piénsalo bien para que sea usable para mucha gente".
- **Owner's approval:** the coordinator proposed the layout below. The owner answered "perfecto, ponte a ello de forma
  autónoma".

**Status:** Ready for UI design and planning

<domain>
## Phase Boundary

The phase only reorganises the Work Zone sessions sidebar (desktop column and mobile drawer). It also adds the small
amount of data the client needs to group by team. It reuses 07.9's projects, visibility, access rule and pages
unchanged: no new access rules, and no change to who can see what.

Out of scope:
- Changes to the session view.
- The project page's layout, beyond the entry points it gains.
- New permissions.
</domain>

<decisions>
## Implementation Decisions

### Common (orchestrator)
- **C-01:** No new access decisions. The sidebar shows only what the existing `/work-sessions` and `/work-projects`
  responses already allow (ADR-0030). Any new field goes through contracts first (Zod) and never widens what a viewer
  learns. In particular, a project the viewer cannot open is never named (D-14 of 07.9).
- **C-02:** UI work is verified at 1440 and 390, light and dark. Screenshots are reviewed, axe must be clean, targets
  are 44 px on touch, and e2e runs through `scripts/e2e-isolated.sh`. Never remove existing behaviour (search, the
  Settled list, live markers, the 07.9 visibility marker) as a side effect.
- **C-03:** Low visual noise is a hard constraint (07.9 UI-SPEC N-rules). Every visible element must earn its place.

### Phase decisions (approved by the owner)
- **D-01, sections by department, like chat:**
  - One collapsible section per top-level unit (department), keyed like `groupChannelsByUnit`.
  - A team project sitting under a team shows its team as a small pill, as chat does for team channels.
  - Order: the viewer's own units first, then the rest alphabetically.
  - Collapse state is persisted per user (localStorage, a Work Zone key).
  - A collapsed section still shows the rows that need the viewer, plus a hidden count.
- **D-02, projects you belong to:**
  - The sidebar lists only the team projects the viewer belongs to: direct member, member of an assigned team, or
    project lead.
  - Other projects they can open or manage (admins, parent leads) are reached through "Browse projects" (the 07.9
    `/work-zone/projects` index), like unjoined channels.
  - An admin never sees every project in the sidebar.
- **D-03, project rows behave like channel rows:**
  - The row shows the project icon, the name, the team pill when the project sits under a team, and a live count
    ("●2" running sessions the viewer can see).
  - Clicking the row opens the project page (`/work-zone/projects/<id>`).
- **D-04, only active sessions under each project:**
  - Active sessions are listed under their project, at most 3, then "+N more", which opens the project page.
  - "Active" means the existing `isActiveSession` rule.
  - Settled sessions live on the project page. A global "Settled" list is kept only if the UI-SPEC finds it necessary
    for discoverability (decide in the UI-SPEC; never lose access to history).
- **D-05, "Needs you" on top:**
  - The top section gathers the sessions waiting on the viewer: a pending approval the viewer can decide, or the
    viewer's turn or queued prompt waiting, from any project or personal repo.
  - It plays the role of mentions in chat.
  - It is hidden when empty.
- **D-06, Personal at the end:** the viewer's repos not linked to any team project, with their active sessions. This
  section replaces today's flat list for unlinked repos.
- **D-07, "+" actions:**
  - The section "+" appears on hover and is always visible on touch where space allows. It creates a team project in
    that unit, only when the viewer may create there (07.9 `viewerCan.create` and parents).
  - The project "+" starts a new session in that project (07.9 new-session dialog, preselected).
  - The header "+" keeps starting a new session.
- **D-08, empty and onboarding states:**
  - With no team projects yet, one discreet line reads "Share sessions with your team → Create project".
  - Search keeps working across projects, sessions and personal repos.
- **D-09, scale:**
  - Must stay usable with hundreds of members, dozens of departments and hundreds of projects.
  - Use collapsed sections, membership-only listing, at most 3 sessions per project, and virtualised or lazy rendering
    if needed. One request each for projects and sessions; no N+1 per project.
  - Live updates use the existing per-user delivery (07.9-07), with no new org-wide broadcast.
- **D-10, data:**
  - The client needs each project's parent unit and top-level unit (id, name, kind) and whether the viewer belongs to
    it.
  - Add these to the existing responses (session `teamProject` ref and/or `WorkProjectSummary`), additively and only
    for projects the viewer may open.
  - Prefer one projects response with `membership: "member" | "team" | "lead" | "manager"`, so the sidebar can split
    "mine" from "browse". No new endpoint unless the research shows it is needed.

### Claude's Discretion
- Exact component split, storage key name, the icon for project rows, the live-count style, animation.
- Whether the "Settled" list survives in the sidebar (D-04), provided history stays one click away.
</decisions>
