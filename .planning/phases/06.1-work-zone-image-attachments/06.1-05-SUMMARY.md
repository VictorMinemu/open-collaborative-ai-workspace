## Deviations from Plan

1. **The full e2e ran with no spec filter, not just `work-zone attachments ai-chat-attachments`.** The orchestrator
   asked for the full run on both projects. It includes every spec the plan named.
2. **[Rule 1 - Bug, found in full e2e run 1] Search palette keystrokes lost after "Back to results"** (`search.spec`,
   mobile).
   - Symptom: after `fill("")` + `pressSequentially("sammy")`, the input held only "s".
   - Cause: Base UI's `DialogPopup` uses `restoreFocus: "popup"`. When the focused Back button unmounts, it focuses
     the popup in a microtask and again on the next animation frame. Under load, that frame landed after the first
     keystroke, and the rest went to the popup.
   - It is also a UX defect: after Back, the keyboard was not in the search field.
   - Fix: Back focuses the input before it unmounts.
   - Test: the spec asserts `toBeFocused()` after Back. It was RED on both projects before the fix and GREEN after.
   - Commit `921a7af` (Phase 4 code; `search-palette.tsx`, `search.spec.ts` were outside `files_modified`).
3. **[Rule 1 - Bug, found in full e2e run 2] A realtime listener could silently stop receiving a topic**
   (`agent-cards`, desktop).
   - Symptom: Victor's page never saw Alex's presence, while Alex's page saw Victor. So Alex's presence was joined,
     but Victor's socket received no deltas.
   - Cause, in `RedisBus`:
     - The bus unsubscribed with a bare `unsubscribe(channel)`.
     - In node-redis 6.2.1 that call does not mark the channel `unsubscribing`. It removes all of the channel's
       listeners only when the UNSUBSCRIBE reply arrives.
     - A new subscribe that comes before the reply joins the leaving channel without sending SUBSCRIBE, and its
       listener is wiped when the reply lands.
   - When it happens: the last listener of a topic on an instance leaves while a new one joins, as in a page reload
     on a conversation. In the e2e, Victor lands on the fresh channel after sign-in, then `goto` reloads it.
   - Impact: that socket got **no live frames for the topic** (messages, cards, presence) until it reconnected.
   - Fix:
     - unsubscribe passes the channel's dispatcher, so node-redis marks it unsubscribing and a racing subscribe sends
       its own SUBSCRIBE
     - the listener joins before the SUBSCRIBE round trip
     - a stale stop is a no-op
     - a failed SUBSCRIBE leaves no entry
   - Test: `apps/api/src/lib/redis.int.test.ts` against Redis 8 reproduces it deterministically. It was RED before
     the fix.
   - Commit `5c31c02` (`apps/api/src/lib/redis.ts`, Phase 1 code, outside `files_modified`). Blast radius: every
     pub/sub topic. The realtime, Work Zone and chat integration suites and the full e2e are green on it.
4. **06.1-VALIDATION.md was created.** The plan said not to create it when the orchestrator had not seeded it. The
   orchestrator's instruction for this run was to write it, so it was written from the plans and SUMMARYs at the gate.
5. **The audit query in DEMO.md orders by `occurred_at`, not `created_at`.** The plan's SQL used `created_at`, which
   does not exist on `app.audit_events` and would fail.
6. **Task 3 was not run.** The owner checkpoint is recorded as deferred under the orchestrator's delegated autonomy
   (see below).
