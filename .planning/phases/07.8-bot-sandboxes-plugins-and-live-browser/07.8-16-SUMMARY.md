# Phase 07.8 Plan 16: Live view and takeover (API) Summary

**People who read the conversation now watch a bot's browser live through the API's own authorization. Only the member
the bot works for can take control. While they hold it, or while their signed-in session is loaded, nobody else
receives a single frame. What they type reaches the page and nothing else.**

## Intended change (plan mode, P-17; written before Tasks 2 and 3)

### Resolver preconditions (`organization/permissions/policy.ts`)

A new resource type `browser_context`, built by `browserContextResource({ reader, botOwner, requester, memberSession })`.
The live view loads only facts; every decision is the resolver's:

| Fact | Source (data only) |
|---|---|
| `reader` (relation) | the person's own `channel.read` of the context's conversation, through the chat module's readable set (`access.isReadable`, every kind including AI chats) |
| `owner` (relation) | `agents.owner_user_id` = the person |
| `requester` (relation) | `browser_contexts.requested_for_user_id` = the person |
| `member_session` (state) | `browser_contexts.session_id` is set |

| Grain | Rule on a `browser_context` |
|---|---|
| `browser.watch` | people only; `reader` or `owner`, else `not_conversation_reader`; with `member_session`, only the `requester`, else `member_session` |
| `browser.control` | people only; the `requester`, else `not_browser_requester`; plus the prerequisite `browser.watch` on the same page (`not_browser_watcher`) |

Both grains come from the role (every role holds them), and the 07.3 module rule `browser.*` removes them, so the Browser
module turned off for a person wins over every relation. At organization scope only the role and the module rules
decide; the live view reads that answer as "module off for this person".

### The lease model (`browser/takeover.ts`)

- The lease lives on the context row: `controller_user_id` plus `lease_expires_at`. No migration is needed.
- `take` is one conditional UPDATE. It wins only when nobody holds a live lease. So two people, or two devices of one
  person on two API instances, never both control a page. The losing device is told `someone_else`.
- The expiry is 10 minutes after the latest input. The holder's instance writes `keep` at most every 30 s while input
  flows.
- The local sweeper warns at 9 minutes with a `lease` frame and releases at 10 minutes (`idle`).
- The lease also ends on:
  - hand back (`released`);
  - the controller's socket closing (`closed`);
  - loss of `browser.control` or of the session (`access_lost`);
  - the kill switch, or the page ending.
- A lease whose instance died is cleared as `idle` by whichever live view reads the row after its expiry.
- `browser.takeover_started` and `browser.takeover_ended` are audited with the context id, the host and the reason only.
- Each change is announced on Redis `ocw:browser:lease` with the organization and context ids only.
- The bot's routes already answer `paused` from the row (`takeoverActive`, 07.8-14) without spending budget.
- sandboxd gets `contextTakeover` on and off.

### The privacy filter (`browser/live-view.ts`)

One hub per API instance:
- one upstream `contextFrames` stream per page, open only while at least one viewer may receive frames;
- a one-frame slot per viewer (latest wins).

Per viewer, per decision:

| Situation | That viewer gets |
|---|---|
| Browser module off for the person | `ended` / `module_off`, closed |
| Not allowed to watch (`not_conversation_reader`, another organization, unknown id) | `viewerCan {false,false}`, `no_permission` with no host, closed 4403, zero frames |
| `member_session` denial (U-2) | `private` / `member_session` with the member's name, zero frames |
| A live lease, this socket took it | `controlling` (`controller: self`), frames |
| A live lease held by someone else, or by the same person on another socket (F-5) | `private` / `takeover` (`controller: other` or `other_device`), zero frames |
| The page ended | `ended` with the row's `endReason`, closed |
| An approval hold | `paused` (`pausedFor`, approval route), frames |
| Otherwise | `live` or `idle` with the host and the masked activity phrase, frames |

- Input frames are accepted only from the socket that holds the lease. They are forwarded to sandboxd as
  `LiveInputFrame` batches and never logged, audited, published or stored.
- Re-decisions come from:
  - the gateway's invalidation bus;
  - `cell.config.changed` (the bot's switch, the organization's settings);
  - the lease channel;
  - a 1 s poll of the row;
  - the per-socket session recheck.

### Auto-fixed and added (Rules 1–3)

   - `organization/permissions/resolve.ts`: the type unions;
   - `organization/index.ts`, `realtime/index.ts` and `agent-channel/index.ts`: exports (`currentPhrase` for the
     activity line);
   - `app.ts`: the browser module gets the sandboxd client, the gateway's origins and the phrase;
   - `infra/fake-model/fake-sandboxd.{mjs,d.mts}`: restart can forget contexts, viewport and mode in stats, a refused
     host;
   - `scripts/guard/run.mjs`: rule tests pick up every `.ts`/`.sql` fixture, so `live-input-logging.ts` runs;
   - `packages/contracts/src/browser.ts` and `sandboxd-protocol.ts`.
2. **[Rule 2] Contract `LiveServerFrame` gains `{type:"refused", op:"take", reason}`.** Without it a refused take had
   no answer. Additive; plans 22 and 26 read it.
3. **[Rule 1] The first takeover test run revealed a fixture bug.** Every test reused one open page, so leases and a
   loaded session leaked between tests. `live-testing.ts` `open()` now closes the previous page through the bot's own
   close route. That change landed in commit `4ed997db`, after the Task 2 commit that already relies on it.
4. **[Rule 2] Semgrep and typed metavariables.** The rule avoids typed metavariables (`($F: LiveInputFrame)`). In
   Semgrep 1.178 they make the existing `rules.sql` fixture fail with a PartialParsing error. The rule binds the type
   from parameter and `const`/`let` annotations instead.
5. **[Rule 2] A watched page whose browser may no longer run is closed by the live view.** This covers the bot's switch
   off, the organization switch off (`module_off`) and the kill switch (`kill_switch`), with `browser.closed` and, when
   a lease was held, `browser.takeover_ended`. Ending it for viewers while leaving the row open would be inconsistent.
6. **[Rule 1] Expected-shape update (P-17).** `apps/api/src/modules/sandbox/fake-browser.test.ts` sent
   `{type:"key", key:"a"}`, which the tightened contract refuses. It now sends a full key frame.

### Plan text vs. what was built

- **`take(tx, ctxId, user, connId)`** takes no connection id. The connection is local to the hub that took the lease;
  other instances see "the same person, another socket" as `other_device`. `not_allowed` is the resolver's answer,
  decided by the live view before `take`.
- **Idle with a test clock**: `BrowserModule.live().sweep(nowMs)` drives it; the background sweeper runs every 15 s.
- **Paused**: built from the row's hold (`paused_for`) and the latest step's approval permalink. The test uses a 07.5
  `always` policy on `ocw_browser_act` rather than a signed-in act.
- **Drop-on-slow**: on loopback the kernel buffers absorb a 2 s pause, so the integration test can only bound the
  socket's buffered amount (under one frame plus framing) and check the catch-up. The "only the latest frame" property
  is proven deterministically by the `FrameSlot` unit tests.
- **OpenTelemetry**: the takeover test starts a NodeSDK in process, with the API's http, pg and Fastify
  instrumentations and an in-memory exporter, before importing the app. It recorded 1,947 spans in one run (http, pg,
  @fastify/otel, better-auth); none carries the sentinel.

No permission check, RLS policy, approval gate or existing assertion was weakened.

## Broken-windows candidates (not written to WINDOWS.md, as instructed)

1. **flake (medium), `sandbox/files.int.test.ts` "51 MB → 413".** Intermittent `fetch failed: write EPIPE`: the server
   answers 413 and closes while the client is still writing. Under load it failed in the full gate and once alone, then
   passed 2/2 alone. The test should accept EPIPE or read the response before finishing the body.
2. **flake (low), testcontainers.** A Redis port-bind timeout (`lib/redis.int.test.ts`), and `artifact/attachments.int`
   reporting storage disabled under host load (WINDOWS #119).
3. **deviation (medium), `live-view.ts`.** A lease held by an instance that died stays in the row until its expiry
   (≤ 10 min after the last keep). Until then sandboxd keeps `takeover` on, and the bot answers `paused`. It is cleared
   (`idle`) by the next live view that reads the row. Without a watcher nothing clears it before the bot's next call; a
   cross-organization sweeper needs a SECURITY DEFINER lister (same gap as #244).
4. **deviation (low), `live-view.ts`.** A page that is watched resizes from the bot's 1280×800 to 960×600 (R10 small by
   default), so the bot's layout changes while someone watches. Decide in 22/28 whether the default should stay
   `expanded`.
5. **todo (low), contracts.** `LiveStateFrame` has no `browserSandbox`. The live-view footer cannot show the isolation
   per page; Settings and the Browser tab (27) can.
6. **deviation (low), Semgrep.** `ocw.live-input-logging` matches only declared types and field names in the listed
   paths. A frame renamed through an untyped variable outside those paths is not caught (the sentinel tests are the
   backstop).
7. **todo (low), fake sandboxd.** A `crashed` control event does not end the frame stream (the real broker's does). The
   API learns about it from the event feed instead, as the test does.
8. **Pre-existing:** the 4 Biome warnings in `apps/local-runtime`; the `pg` "client.query() when the client is already
   executing" deprecation.
