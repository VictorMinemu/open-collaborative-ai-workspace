**Refinements inside the ADR's wording (no superseding ADR needed):**

- §11 idempotency: the woken state is recorded as `waiting_approval:<newest pending approval id>` while approvals are
  pending (`wakeStateKey`, plan 20 follow-up `a2ee5c5b` / `01845866`). The ADR's rule ("wakes only when the pair
  (status, last completed prompt) differs from the last wake") still holds; the status part is finer for approvals, so
  a second approval inside one prompt wakes the bot once more and the same approval never twice.
- §12 offer: the four tools are also withheld when fewer than four tool slots are free on the turn (plan 11). This only
  narrows where they are offered.
