# Phase 07.14 Plan 13: The browser end to end, the organization leak sweep and ocw.raw-auth-mode Summary

**The whole feature now runs end to end in the browser. An admin connects Company CRM from its row and saves Billing API's client credentials in the dialog. Sam, a member, asks the team bot Relay in a channel, and Relay answers with the organization's account on both servers. After the admin disconnects, Relay's next call gets the admin sentence. The 07.4 leak sweep now covers every organization credential, and a Semgrep rule blocks raw mode comparisons in apps/.**

## Decisions Made

- **Where the e2e reads the PD-10 sentence.** The fake cell shows refusals as `refused (<code>)`, so the e2e asserts the sentence on the proxy's 409 body, which is what `apps/openclaw-channel` hands the model.
- **How the rule names the literal.** It sits behind `"$MODE"` with a metavariable-regex, plus a `pattern-regex: org_secret` conjunct. The conjunct only gives Semgrep a prefilter (see deviation 1).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The new TypeScript rule broke the SQL fixture's rule test**
- **Found during:** Task 3 (`--rule-tests`).
- **Issue:** with the literal behind a metavariable-regex, and also when spelled out in every pattern, Semgrep 1.178 had no prefilter. It parsed `.semgrep/tests/rules.sql` as TypeScript (`PartialParsing`), so `ocw.rls-bypass`'s fixture test failed. With the HEAD rules, `rules.sql` passed and only the new `rules.ts` fixtures failed, which was the expected RED.
- **Fix:** a `pattern-regex: org_secret` conjunct, with a comment explaining it.
- **Files modified:** `.semgrep/rules.yml`
- **Verification:**
  - `--rule-tests`: `live-input-logging.ts` 1/1, `rules.sql` 1/1, `rules.ts` 6/6.
  - Mutation on the tree: temporary `apps/api/…probe.ts` (`===`) and `apps/web/…probe.tsx` (`!==`) were both flagged, and a `.probe.test.ts` was not. The probe files are deleted.
- **Committed in:** `c6a3d08a`

**2. [Rule 3 - Blocking] The e2e harness needs a `.env`**

- I left the harness's own `ocw-e2e-storage-garage-1` running: it is shared by e2e runs and the harness manages it. The demo stack was never touched.
