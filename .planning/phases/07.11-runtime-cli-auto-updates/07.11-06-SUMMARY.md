# Phase 07.11 Plan 06: Control Plane runtime maintenance Summary

**The API stores what each device reports about its coding CLIs, keeps an audited per-run history, lets only the
owner and admins see it and press "Update now" (payload `{ runtime }` only), and tells every device the org's level
and the manifest at connect and on change, with organization B fully isolated.**

## Intended change (CLAUDE.md plan mode: permissions, audit, tenant data)

- **Permissions:** `device.maintain` (01: owner relation + ADMIN role, non-delegable) decides `GET
  /devices/:id/runtime-updates`, `POST /devices/:id/runtimes/:runtime/update` and whether `GET /devices` carries
  `runtimeMaintenance`. It joins `DEVICE_VIEWER_CAN`; the grants `managed` list is unchanged. No check is weakened.
- **Audit (same transaction, never output or a path):** `device.runtime_update_requested` (user),
  `…_available` / `…_stale` / `device.runtime_updates_level_changed` (device, on transitions), `…_started` /
  `…_finished` (requester, system or device; finished `result: "error"` for failed/refused), `…_skipped` (system).
- **Tenant data:** every read and write runs in `withTenant` (frames: `{ organizationId, userId: null }`; routes: the
  caller's tenant) on RLS tables; the push lists devices inside the target org's tenant. Organization-B cases cover
  both routes, the list and the push.

## Notes for later waves

- **07 (daemon):** the API sends `runtime.config` right after `welcome` and on every org change; ack `runtime.update`
  with `ok: false, error: "<reason>"` to refuse (stored as `refused`, ≤ 500 chars, scrubbed). A `started` frame must
  carry `commandId` to adopt an "Update now" request; without it the run gets its own row. A `finished` frame without a
  prior `started` is accepted (own row; `skipped_broken` deduped per candidate). Snapshots rewrite `runtime_info`.
- **09 (e2e):** `GET /devices/:id/runtime-updates` shows the run newest first; audits are queryable by
  `action like 'device.runtime_update%'`.
- **10 (web):** `Device.runtimeMaintenance` is present only when the viewer has `device.maintain` *and* the device has
  reported; `viewerCan` includes `device.maintain` for the owner and admins. 409 codes: `update_pending`,
  `device_offline`, `runtime_updates_off`, `manual_update` (message carries the display command). History `requestedBy`
  has `{ id, name }`.
- A level change is pushed only to devices `online` at PUT time; one connecting later gets it at `welcome`.
