# Phase 07.11 Plan 04: Device maintenance core (install method, registry, runner) Summary

**The device can now say how each CLI was installed and which one command updates it, from one fixed on-device table.
It can ask the npm registry for the latest version on that install's channel, then run the command safely and check
the result. A native Claude Code install on a fake home goes from 2.1.290 to 2.1.300 end to end, with no shell, no
escalation, no credential in the child and no host path in anything that may leave the device.**

## The install table as built (PD-09)

| Method | Recognised by (realpath unless noted) | Device runs | Display |
|---|---|---|---|
| native (Claude) | `…/.local/share/claude/versions/<v>` | `<bin> update` | `claude update` |
| codex_standalone | `<CODEX_HOME>/packages/standalone/releases/<v>-…/` | `<bin> update`, `CODEX_HOME` = detected | `codex update` |
| volta | realpath `…/volta-shim` or `/.volta/tools/image/packages/` | never (manual) | `volta install <pkg>@latest` |
| pnpm | `/pnpm/global/<n>/`, or the bin directory = `PNPM_HOME` | never (manual) | `pnpm add -g <pkg>@latest` |
| bun | `/.bun/install/global/node_modules/` | never (manual) | `bun add -g <pkg>@latest` |
| yarn | `/yarn/global/node_modules/` | never (manual) | `yarn global add <pkg>@latest` |
| mise / asdf | `/mise/installs/`, `/mise/shims/` / `/.asdf/` (bin or realpath) | never | none, "Update it with the tool that installed it" |
| npm | `<prefix>/lib/node_modules/<pkg>/` and `<prefix>/bin/npm` executable | `<prefix>/bin/npm install -g --prefix <prefix> <pkg>@<candidate>`, `<prefix>/bin` first on PATH | `npm install -g <pkg>@latest` |
| homebrew_cask / _formula | `<brew>/Caskroom/<name>/` or `<brew>/Cellar/<name>/` and `<brew>/bin/brew` executable | `<brew>/bin/brew upgrade [--cask] <name>`, `<brew>/bin` first on PATH | `brew upgrade --cask claude-code[@latest]` / `brew upgrade codex` |
| system_package | under `/usr`, `/bin`, `/sbin`, `/opt`, `/snap` (not `/usr/local`, `/opt/homebrew`) | never | `sudo apt update && sudo apt upgrade claude-code` / `sudo dnf …` / `sudo apk …` |
| project_local | a `node_modules` outside the rows above | never | none |
| sdk_bundled (Claude not found) | none | never | none, "Updates with the OCW runtime" |
| not_installed (Codex not found) | none | never | none |
| windows | any binary when `platform === "win32"` | never | none |
| unknown | anything else (e.g. a Caskroom without brew) | never | none |

Writability (`access(W_OK)`) is checked on what each method writes. When it fails the install is `needs_admin` with
`sudo <template>` (Homebrew: the plain command) and `updateCommandFor` returns null. `DISABLE_UPDATES` (env, or `env` in
`~/.claude/settings.json`) makes Claude `updates_disabled`.

## Deviations from Plan

### Auto-fixed / additions

**1. [Rule 2 - Correctness] Re-resolve under the lock before running, not only after**
- PD-11 says to re-resolve after the command. The runner also re-resolves once the lock is held, and probes the
  from-version there. If the method or install root changed, it ends `failed` "install method changed since the check"
  without running anything, which is what the plan's symlink-swap test asks for. A queued second updater then measures
  from the version the first one installed and ends `unchanged`.
- Commit: `01243bd3`

**2. [Rule 2 - Security] Every `*_API_KEY` variable is dropped from the child, not only the listed ones**
- The child env drops `OCW_*`, `CLAUDE_API_KEY_VARS` (`ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`), `OPENAI_API_KEY` and
  `CODEX_API_KEY`, and also any name ending in `_API_KEY`, which is what the fake reports on.
- Commit: `01243bd3`

**3. [Design] Extra public fields and options beyond the cross-plan names**
- `InstallResolution` adds `note` (a path-free sentence for manual, admin, disabled and SDK-bundled cases),
  `managerPath`, `prefix` and `brewName` (device-only). `publicInstallFields(r)` is the view 07 maps into
  `RuntimeMaintenanceStatus`.
- `ResolveOptions` adds `systemDirs` and `systemPackageManager`, so the system-package rows are testable without
  touching `/usr`.
- `RunUpdateOptions` adds `killGraceMs`, `lockRetryMs`, `lockGiveUpMs`, `exec`, `reResolve`, `now` and `sleep`.
- `updateCommandFor(resolution, candidate, baseEnv = process.env)` takes the base env so the npm and brew `PATH` can
  start with the prefix's `bin`.
- `fake-update.json` also accepts `noise` (lines of filler output, used by the 10 KB cap test).
- `fake-update-env.json` also records `pathHead`, `noColor` and `codexHome`. These are names and paths of the fake
  tree, never secret values.

**4. [Decision, RESEARCH A3] pnpm, bun, yarn and Volta are manual.** Detection is proven on fake trees (Volta through its
`volta-shim` symlink). Their update commands (`pnpm --allow-build`, bun trust, Volta) are not, so the device shows the
command and never runs it. Users of those installs get "notify" behaviour only. Promoting one to updatable later means
adding a row to `updateCommandFor` and a fake-tree run test.

**5. [Decision] Homebrew `needs_admin` displays the brew command without `sudo`**, because Homebrew refuses to run as
root. The other methods display `sudo <template>` as planned.

**Not done (orchestrator instruction):** no rebase on `main` (PD-17); the worktree base is `1400d1a5` as instructed.
