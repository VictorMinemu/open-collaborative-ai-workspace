## Resolution

root_cause: |
  F1 (desktop memory-files:853): environment. The Mac entered Clamshell Sleep (lid closed, on battery) at 10:30:55
  and stayed asleep 38 s while the test waited on its Save click; browser, API and Playwright froze together and on
  wake the 30 s test timer fired at once. The runner held no sleep assertion (the run had also idle-slept 17 s at
  10:28) and never reported sleeps. No product or test defect: after wake the 409 and the conflict view were correct.
  F2 (mobile smoke:4): product race. AppShell closed the mobile drawer on every pathname change; /chat shows the
  shell, then router.replace()s to the default channel once the channel list loads. A tap on the menu in that window
  opened the drawer and the redirect closed it. smoke hits it because it clicks right after /chat (openAs waits for
  /chat/<uuid>).
  F3 (exposed by the gate's --repeat-each): memory-proposals leaves clients/acme-<w>.md (and siblings) in the Ventas
  tree that memory-files' keyboard case walks and snapshots exactly; a fresh run orders them safely, a repeat does not.
fix: |
  F2: AppShell closes the drawer after a pathname change only when the person acted inside the drawer
  ([data-mobile-nav], click/keydown capture) since it opened; back/forward closes it directly on popstate (React
  renders popstate transitions synchronously, so a flag set there would be too late). Regression spec
  e2e/tests/mobile-drawer.spec.ts holds /api/v1/channels so the tap always lands before the redirect.
  F1: scripts/e2e-isolated.sh runs `caffeinate -i -w $$` (no idle sleep during a run) and, on exit, lists every
  "Entering Sleep state" from pmset -g log since the run started, so a sleep-caused failure is named as such.
  F3: memory-files' beforeAll prunes the Ventas scope to its seed (e2e/support/memory.ts pruneVentasToSeed).
