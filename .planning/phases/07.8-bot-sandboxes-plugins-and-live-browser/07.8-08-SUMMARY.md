# Phase 07.8 Plan 08: Phase tracer on the real stack and the e2e sandbox harness Summary

**A bot runs `ocw_sandbox_exec` from a real OpenClaw cell, through the real API, into a real hardened `sbx`
container run by the real sandboxd. Another bot cannot see its file. The admin's kill switch stopped the running
command in 262 ms. The audit rows carry ids only, and the sandbox environment holds no token. The e2e harness now has
a fake sandboxd by default and the real one behind `--sandbox`, and CI cannot drift from it silently.**

What each step showed:

1. **alsoAllow in the real cell.** The cell's live `openclaw.json` listed 15 confined tools for Scout (Sandbox and
   Browser on) and 8 for Echo (Sandbox only). Scout's reply was
   `Tool ocw_sandbox_exec said: exit 0 … stdout: proof-361066e2f0 … [tools: 15 | …ocw_sandbox_exec…]`. The turn
   carried no `ocw_browser_*` tool: the API does not offer browser tools until 07.8-14, so the turn narrowed the agent
   entry.
2. **Isolation.** Echo's reply: `exit 1 … stderr: cat: note.txt: No such file or directory`. Scout's container is on
   `ocw-net-ocw-e2e-3a3824d79072` with volume `ocw-ws-ocw-e2e-3a3824d79072`; Echo's is on `…-5e8267b20f95` with its
   own volume. Both carry `ocw.namespace=ocw-e2e`, `ocw.org=<org>` and their own `ocw.agent`.
3. **Kill switch.**
   - `["sleep","120"]` → `still running as process HIuToazfRIxf6uru after 25.0 s`.
   - A turn delivered before the kill, with `[[pause:8]]`, answered
     `Tool ocw_sandbox_exec said: An admin stopped all sandboxes. Files are kept, but I can't run anything until it is resumed.`
   - A turn delivered after the kill answered `Tool ocw_sandbox_exec not offered [tools: 8 | …]`.
   - No running container of the organization was left 262 ms after `POST /api/v1/sandbox/kill` (364 ms in run 1).
4. **Audit.** `sandbox.exec` metadata is exactly `{status, eventId, exitCode, durationMs}` for both bots, and
   `sandbox.killed` is `{browsers: 0, sandboxes: 2}` with Ana as the actor. Zero `audit_events` and zero
   `agent_tool_calls` rows contain the nonce, `note.txt` or `after-kill`.
5. **No token in the environment.** The whole `env` tool result was read from the fake model's request capture, not
   only the 200-character preview. It contained neither the cell token nor the sandbox token nor `OCW_`; the `sbx`
   container's `Config.Env` passed the same check. The visible env is `NODE_VERSION`, `HOSTNAME`, `YARN_VERSION`,
   `HOME=/workspace`, `PATH` and `PWD`.

**All five proof runs:**

- **Run 1:** 5/5 PASS. The first ask got "not offered" while the switch change reached the cell; the second ask
  answered in 1588 ms.
- **Run 2:** FAIL at step 1. Echo stayed `provisioning`.
  - Root cause, from the read-only stream rows and the API log: `cell.config.changed` seq 1 at 18:35:52.602, the cell's
    `GET /cell` at 52.637, seq 2 (Echo) at 52.654.
  - The plugin's `refreshCell()` coalesced the second event into the in-flight refresh, whose snapshot was already
    taken, so Echo was never provisioned.
  - First mitigation: one cell change at a time in the proof.
- **Run 3:** 5/5 PASS (above).
- **Run 4:** after the merge, FAIL at step 1 again. The proof created Echo only once Scout was `ready`, but the flight
  was still running afterwards: the status report goes out before the boot-cache write that ends the refresh.
  - Event 1 at 21:24:41.978, `GET /cell` at 42.071, Scout `ready` at 42.990, Echo's event at 43.215, and no further
    `GET /cell`.
  - Sequencing could not hide the race, so it was fixed in the plugin (Rule 1, deviation 15).
- **Run 5:** on the merged HEAD with the fix (cell image rebuilt from the tree), 5/5 PASS, 15/8 confined tools in the
  cell's `alsoAllow`, cold first exec 5776 ms, kill 240 ms, nothing left.

## Deviations from Plan

1. **[Rule 3] Per-bot switch route.** `PATCH /agents/:id/capabilities` dropped `sandbox`/`browser`, so the plan's "through
   the existing capabilities route" could not work. I added both to `TOGGLES` in `bot-capabilities/routes.ts`, outside
   the files list. Plan 15 relies on it.
2. **[Ledger #240, Rule 3] `confinedCellTools()` in `turn-policy.ts`.** This is outside the files list; no W3 plan
   touches the file. The snapshot follows only the bot's switches and whether sandboxd is configured. The organization
   switch and the kill are not cell-wide facts.
3. **Killed sentence.** 05 asserts that a killed organization is offered no sandbox tool, so a fresh mention after the
   kill reads "not offered". The killed sentence is proven for a turn delivered before the kill whose exec lands after
   it: the new fake model directive `[[pause:N]]` delays a turn's first tool call. Both behaviours are in the proof.
4. **Proof shape.** The steps are a Playwright API-only spec (`e2e/proof/sandbox.sandbox-proof.ts`), with its own
   project `sandbox-proof` in `e2e/playwright.proof.config.ts` so neither proof runs the other. Both files are outside
   the list. The shell owns the containers and prints the PASS lines from the spec's state file.
5. **Images `:e2e`, not `:local`.** `cell-proof.sh` builds `ocw-openclaw:local`; the proof builds
   `ocw-openclaw:e2e`/`ocw-fake-model:e2e` and removes them.
6. **`--sandbox` image set.** An image is built only when its Dockerfile exists and the broker reads its variable.
   Today that is `sbx` only. `infra/sandbox/browser/Dockerfile` and, after the merge, `infra/sandbox/egress/Dockerfile`
   exist, but `apps/sandboxd/src/main.ts` reads neither `OCW_SANDBOX_BRW_IMAGE` nor `OCW_SANDBOX_EGRESS_IMAGE` yet.
   They join automatically with 13.
7. **Contract, additive.** `SandboxdErrorCode` gains `paused`. Without it, a takeover refusal from the fake (and from the
   real `brw` via 13) parses as a service failure in the API client.
8. **Plan 01's file `packages/contracts/src/sandboxd-protocol.ts` and its test.** Changed here; no W3 plan touches
   them.
9. **Added `apps/api/src/modules/sandbox/fake-browser.test.ts`.** The API client parses every fake browser answer with
   the contract, and the leak control's snapshot must fail that parse.
10. **`FakeCellPlugin` signature.** It is `sandbox(m, tool, args)` / `browser(m, tool, args)`, with the mention first like
    `connectorCall`, instead of `sandbox(tool, body)`. A refusal code outside the contract enum renders
    `failed (<status>)`. Names and codes are imported from the contracts source by relative path, because Playwright
    cannot resolve `@ocw/contracts`.
11. **Commit shape.**
    - Task 1's commit also carries the fake server's `/__sandboxd` mount and the runner's default-mode exports, which
      are Task 2 behaviour in shared files.
    - `e2e/support/sandbox.ts` landed whole in Task 1.
    - Task 3 was committed before Task 2.
12. **Ana is the e2e admin** (`ADMIN`, displayed as "Víctor Ruiz").
13. **`e2e-isolated.sh` trap.** The EXIT trap now fails the run when `ocw.namespace=ocw-e2e` objects remain;
    INT/TERM exit 130 through it.
14. **Read-only diagnosis.** To find the root cause of runs 2 and 4, I read `app.stream_events` of `ocw_e2e` with `psql` in the
    compose postgres container the harness itself uses. These were read-only queries on the e2e database only.
15. **[Rule 1] Plugin fix, outside the plan's files.** `apps/openclaw-channel/src/bridge.ts` `refreshCell()` now
    queues one follow-up refresh for every caller that arrives during a flight, instead of handing back the flight whose
    `GET /cell` may predate their change. It is unit-tested in `bridge-refresh.test.ts`.
    - It blocked the tracer twice (runs 2 and 4), and sequencing the proof could not hide it.
    - No W3 plan touches the plugin; the ownership map gave `apps/openclaw-channel/src/*` to 06, which is done.
    - Proven by the cell smoke and proof run 5.
