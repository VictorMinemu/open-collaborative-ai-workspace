# Phase 03.2 Plan 02: Claude adapter settings, catalog and backstop Summary

The Claude Code adapter now applies model, effort, fast mode, context window and permission mode between turns, reports the effective values on every init, publishes the runtime catalog of the logged-in subscription without a turn, lowers the mode per turn to the prompt's cap, and refuses raw settings slash commands. All of it is backed by fixtures recorded at CLI 2.1.289 / SDK 0.3.282.

## What was built

- **configure() (D-07, D-14):** applied immediately while idle. During a turn, changes are held and merged (last value wins), then applied before the next user message is pushed. If a change made while idle fails, the adapter emits `session.error` and rejects with `settings_rejected`. If a held change fails at dispatch, it is reported and dropped, and the turn still runs. Afterwards the adapter emits `session.settings` with the applied values.
- **applyFlagSettings** only ever carries `effortLevel` / `fastMode`. The `QueryHandle` type rejects any other key, and an `afterAll` assertion checks every recorded call across the suite (T-03.2-02-01).
- **Context window (D-10):** the model is re-selected with or without `[1m]`, and only where the catalog lists both windows. Choosing a model's fixed window is a no-op; any other window is `settings_rejected`. After a model change the adapter reports that model's base window.
- **Per-turn cap (P-07):** each turn runs at `minMode(configured, prompt.permissionMode)`, set before the turn and restored before the next uncapped one. If the mode cannot be set, the turn fails (`session.error` + `prompt.completed isError`) and nothing is pushed.
- **Slash backstop (D-13, P-10):** `refuseSlashCommand` in `prompt()` uses `slashDisposition`. `/model`, `/effort`, `/fast`, `/permissions`, `/config`, `/mcp` etc. get `slash_command_refused` before anything is queued; `/compact` passes through.
- **Mapper (D-15):** every init yields `session.settings` (model, permissionMode, fastModeState, fastModeReason, effort when present). `session.started` is still emitted once.
- **Catalog (D-08 … D-11):** `buildClaudeCatalog` is pure and produces:
  - no `default` row; the alias resolving to the same model is marked as the default
  - alias rows current, `claude-*` rows legacy, no badge
  - efforts minus `DEFERRED_EFFORTS`, `defaultEffort` null
  - the 200k/1M pair only where the probe accepted both
  - fast/auto flags and `CLAUDE_FAST_MODE_COST`

  `collectClaudeCatalog` / `probeClaudeModels` use one throw-away query that is always closed and has a 90 s timeout. `ClaudeCodeRuntime.catalog()` caches the result for 10 min and returns null when the CLI is missing or signed out.
- **Recorder:** `scripts/record-fixture.ts --scenario plan-read | settings | catalog`. Every scenario refuses an API key and aborts on `apiKeySource ≠ none` or bypass. `settings` and `catalog` also require `claude --version` to be 2.1.289.

## Subscription use and what the fixtures confirmed

- **One subscription turn in total**, for the `settings` fixture. It ran in a throw-away temp git repo with `hello.txt`, started in `plan` with `haiku`, then received `configure({model:"sonnet", effort:"low", permissionMode:"auto"})` and the prompt "Reply with exactly the word OK. Do not use any tools." Cost reported by the CLI: $0.056 (subscription, `apiKeySource: none`). It never ran in bypass mode, and no re-recording was done.
- **Auto: confirmed.** After `setPermissionMode("auto")` the CLI emitted a `system/status` frame with `permissionMode: "auto"`, and then the init reported `permissionMode: "auto"`.
- **Model: confirmed.** After `setModel("sonnet")` the init and the response both report `claude-sonnet-5-5`.
- **Effort: accepted, but not echoed.** `applyFlagSettings({effortLevel:"low"})` returned no error and the turn ran. The SDK init carries no `effort` field (sdk.d.ts says it is published only on Remote Control bridge frames), so the effort readback is the applied value.
- **Fast mode reason:** the init reports `fast_mode_state: "off"` / `fast_mode_disabled_reason: "sdk_opt_in_required"`, because fast mode was not requested in the recording. `extra_usage_disabled` (research) stays covered by a synthetic init derived from the recorded one.
- **Catalog (no turn):** 12 rows; the default alias is `claude-opus-5-5`. Only `claude-opus-4-6` offers both 200k and 1M. All 5.x models and Opus 4.7/4.8 run a fixed 1M. Haiku 4.5 and Sonnet 4.6 run a fixed 200k (Haiku `[1m]` is refused with "Haiku 4.5 doesn't have a 1M context window"). This matches the research.
- **Observed: plan mode swaps Haiku for Sonnet.** In `plan` mode, `setModel("haiku")` + `getContextUsage` report `claude-sonnet-5-5` / 1M. The 2.1.287 plan-read fixture shows the same thing: init says haiku, the responses come from sonnet. The first catalog probe ran in `plan` mode and recorded 1M for haiku. I moved the probe to `default` mode and re-ran it (no turn). This fixed a bug in my probe; it was not a re-recording of a turn.
