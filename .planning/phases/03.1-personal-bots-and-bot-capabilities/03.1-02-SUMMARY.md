# Phase 3.1 Plan 02: Team-bot DMs, personal-bot privacy and governance Summary

Any member opens a private chat with a team bot from its card or detail sheet ("Message"); two members get two separate chats and never see each other's history. Personal bots now exist only for their owner in `/agents`, `/agents/:id`, realtime events and the mention autocomplete; admins can disable, re-enable or delete one (audited with `governance: true`) but get 403 `personal_bot` on any edit. Disabling or deleting any bot archives its chats; re-enabling restores them.

## What was built

- **API**
  - `POST /api/v1/agents/:id/dm`: load bot (404 missing/deleted) → `bot.read` on `agentResource` hidden as 404 → 409 `bot_disabled` → `ensureDm` → audit `dm.opened {agentId}` only when created.
  - `GET /agents`: per-bot `perms.filter(bot.read)` plus a `scope === team || owner` guard; each item gets `viewerCan`. `GET /agents/:id`: `bot.read` hidden as 404, `viewerCan`.
  - `PATCH /agents/:id`: team bots `bot.manage` for every field (unchanged behaviour); personal bots: owner `bot.configure` for everything, admin `bot.manage` for `{enabled}` only (fields → `bot.configure` → 403 `personal_bot`), anyone else 404. Owner model changes use `personalModels` (400 `model_not_allowed`). Disable/enable call `setAgentDmsArchived` in the same transaction; audits carry `scope`, `ownerUserId` and `governance: true` when the actor is not the owner (never instructions or chat content).
  - `DELETE /agents/:id`: owner `bot.configure` or admin `bot.manage` (governance) on personal bots, `bot.manage` on team bots; archives DMs, removes channel memberships, `agent.deleted` on `user:<owner>` for personal bots.
  - `setAgentDmsArchived` sets/clears `archivedAt` on every DM with the bot and notifies each human member on `user:<id>`; posting in an archived DM answers 410 `channel_archived` (existing path).
  - Limit `bot_policies.max_personal_bots_per_user` (default 3, 409 `personal_bot_limit`) was already enforced by 03.1-01; now covered with a policy row of 1.
- **Contracts**: `Agent.viewerCan?: Permission[]`, `OpenDmResponse`.
- **Web**: primary **Message** button (`data-testid="bot-message"`) on the card footer and in the sheet header for ready/provisioning bots with `bot.read`; `useOpenDm` resolves after `/dms` refetched (no "chat missing" flash); **Personal** badge (`bot-personal-badge`) on card and sheet; no Add to channel for personal bots; edit/enable/delete controls from `botAbilities(agent)` (viewerCan); owner sees why an admin-disabled bot cannot be switched on; gallery copy "Message them privately or mention them in any channel"; bots list also follows `user:<me>`; personal bots never offered as @mentions.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `personal-bots.spec.ts` cleanup as the owner**
- The spec listed Sam's personal bots through the admin's `GET /agents` to delete them between projects; admins no longer see personal bots, so the mobile run would start with Sam's bot already present. It now lists and deletes as Sam. **Commit:** 7f9dd7f

**2. [Rule 2 - Security] Owner cannot undo an admin's disable**
- Without it, governance disable was meaningless (the owner could PATCH `{enabled:true}`). An admin (non-owner) disable sets `statusMessage = "Disabled by a workspace admin"`; the owner's re-enable answers 403 `disabled_by_admin` and the sheet disables the switch with that message. Schema-free (D-05). **Commit:** 7f9dd7f (API), 5d136bf (UI + tests)

**3. [Rule 2 - Correctness] Realtime keeps `viewerCan`; owners follow `user:<me>`**
- Realtime agent payloads have no `viewerCan`, so a status flip would have hidden the Message button; `upsertAgent` keeps the last decided value and refetches for bots first seen over realtime. Personal-bot events no longer reach `org:`, so `useBotsRealtime` also listens on `user:<me>`. **Files:** `apps/web/lib/bots-queries.ts`

**4. [Rule 2 - Correctness] Delete keeps DM memberships**
- `DELETE /agents/:id` used to drop every membership; it now archives the bot's DMs first and removes only channel memberships, so an archived DM keeps its counterpart. **Commit:** 7f9dd7f

**5. [Scope] Files outside the plan list**
- `apps/api/src/modules/chat/index.ts` (one export line), `apps/web/components/bots/bot-bits.tsx` (`botAbilities`; `PersonalBadge` lives in `bot-card.tsx`), `e2e/tests/personal-bots.spec.ts` (deviation 1).

**6. [UX] Card Add to channel as an icon button**
- To keep the primary Message button on one row at 390, the card's Add to channel is an icon button with tooltip (same `add-to-channel` test id, `aria-label`); the sheet keeps the labelled button.
