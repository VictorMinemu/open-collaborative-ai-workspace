## UI contract (thread hops)

Existing tokens and primitives only. Verified widths 1440 (`desktop`) and 390 (`mobile`, touch). Icons (lucide-react
1.48.0, verified present): `Waypoints` (question), `Forward` (handoff), `CornerDownRight` (answer), `LoaderCircle`
(waiting), `CircleCheck` (answered), `CircleAlert` (couldn't answer), `TimerOff` (no answer in time), `CircleStop`
(stopped), `Gauge` (daily limit), `Square` (Stop button).

### Placement
- In each message row, when `message.consult` is set and the message is not deleted: one `ConsultChip` directly under the
  author line and above 07.8's `BotActivity` block (when the message has one) and the body (or the Agent Card), also on
  continuation rows (whose author line is hidden). The same row component renders in the channel view and the thread
  panel, so the chip shows in both. Nothing else in the row changes (pinned/saved labels, activity, card, attachments,
  reactions and the thread summary keep their order).

### Chip (`data-testid="consult-chip"`, `data-role`, `data-status`)
- Container: `mb-1 inline-flex max-w-full flex-wrap items-center gap-x-1.5 gap-y-0.5 rounded-md border bg-muted/40
  px-2 py-0.5 text-xs text-muted-foreground dark:bg-white/[0.04]`.
- Content, in order: role icon (size-3.5, `aria-hidden`) · provenance text · (question role only) ` · ` + status (icon
  size-3 `aria-hidden` + `font-medium` label) · (waiting and allowed) the Stop button.
- Status colours (text and icon together; the label always carries the meaning): answered `text-emerald-700
  dark:text-emerald-400`; couldn't answer, no answer in time, daily limit `text-amber-700 dark:text-amber-400`; waiting
  and stopped stay `text-muted-foreground`. `LoaderCircle` spins with `animate-spin motion-reduce:animate-none`.
- Stop (`data-testid="consult-stop"`): `Button variant="ghost"` sized `h-6 px-1.5 text-xs` with `Square` (size-3) and the
  label; at < 768 `max-md:h-11 max-md:px-3` so the target is ≥ 44×44. Pending: disabled with a 12 px `Spinner`. Success:
  `toast.success`; error: `toast.error(errorMessage(err))`.
- Shown to: the chain's human (`me.id === consult.onBehalfOfUserId`) or a viewer who may moderate the channel (the
  conversation's existing `viewerCan` for `message.delete_any`); only while `status === "pending"` and role `question`.
- Names come from the chat directory (bots by id → `@handle`, people by id → display name); unknown → `a bot` / `a
  teammate`.
- 390: the chip wraps inside the message column (`max-w-full`); no horizontal scroll; the status may move to its own line.

### Copy (English, sentence case)

| Element | Copy |
|---------|------|
| Question (consult) | `Asked @{target} for {human}` |
| Question (handoff) | `Handed over to @{target} for {human}` |
| Second-level prefix | `Step 2 · ` before the question text |
| Answer | `Answer to @{source}` |
| Status: pending / answered | `Waiting…` / `Answered` (handoff: `Working…` / `Handed over`) |
| Status: failed / timed_out | `Couldn't answer` / `No answer in time` |
| Status: cancelled / refused | `Stopped` / `Daily limit reached` |
| Stop | label `Stop`, `aria-label="Stop asking @{target}"` |
| Stop success toast | `Stopped. @{source} won't get more answers for this request.` |
| Stop errors | 403 `Only the person who asked can stop this.` · 404 `This request is no longer available.` |

### Accessibility

| Element | Markup |
|---------|--------|
| Chip | A `<p>` read before the body; icons `aria-hidden`; the status is text (no `role="status"`: many chips per thread would be noisy) |
| Stop | Native `<button>` with the aria-label above; keyboard-reachable in the row's tab order |
| Contrast | Text ≥ 4.5:1 on `bg-muted/40` and its dark variant; icons ≥ 3:1 |
| Axe | `expectNoSeriousA11y(page, '[data-testid="thread-panel"]')` (or the thread panel's existing test id) with chips present, light and dark |

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server → browser (`message.consult`) | Viewer-agnostic side data on messages the viewer already reads |
| browser → `/api/v1/agent-chains/:id/cancel` | User action; the API decides |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.7-10-01 | Elevation of privilege | Stop shown to the wrong people | low | mitigate | Visibility is a hint; the API enforces (07.7-06); spec checks Alex has no Stop |
| T-07.7-10-02 | Information disclosure | chips revealing hidden ids or names | low | mitigate | Ids only travel on messages the viewer already reads; names resolved from the viewer's own directory with fallbacks |
