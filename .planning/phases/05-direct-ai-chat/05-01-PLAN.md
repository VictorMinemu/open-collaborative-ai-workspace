## Phase Goal

**As a** member of an organization that uses the workspace, **I want to** hold a private, streaming AI conversation on my own ChatGPT plan by default or on a model my organization pays for — choosing the model per message, stopping and regenerating answers, with titles, instructions, web search, files, a usage record for every answer and a read-only share link for colleagues — **so that** I get a ChatGPT/Claude.ai-quality assistant inside the workspace where every generation is metered, private by default and attributable.

(ROADMAP Phase 5 goal restated as a user story, same intent: "A user holds a private, streaming AI conversation with organization-configured models and every generation metered — a new AI chat run loop (AI SDK 7) next to the bots' OpenClaw path, with the Phase 1 Settings › Models providers moved to `SecretReference`s that govern AI chats as well as bots"; owner decisions D-01 … D-08 in `05-CONTEXT.md` add the per-member ChatGPT plan backend.)

**This plan's slice (tracer):** one ChatGPT-plan chat turn flows browser → `POST /ai-chats` (owner-only, one generation gate, audit) → model gateway (the member's own token) → AI SDK `streamText` → fake `POST /v1/responses` → coalesced `ai.delta` frames on `conv:<id>` → the browser, then a durable final message with a usage record that survives a reload. It also lands every Phase 5 contract and both Phase 5 migrations.

Task 1 is the package-legitimacy pre-flight gate that the protocol requires before any install (no code); the tracer (Task 2) is the first implementation task.

## Planner decisions (binding for Plans 05-01 … 05-12; referenced as P-01 … P-14)

Owner decisions are D-01 … D-08 in `05-CONTEXT.md`. These planner decisions fill Claude's discretion and never override a D-xx.

- **P-01 Contracts once.** Every Phase 5 contract is defined in this plan (interfaces block). Later plans import these names verbatim and never rename or remove one. A later plan may add an optional field or a new export only in a contract file it lists in `files_modified` (add-only), then runs `pnpm typecheck --force`. `ai-generation.ts` imports only `common.ts` and `agent.ts`; `chat.ts` imports `ai-generation.ts`; `ai-chat.ts` imports `chat.ts`, `attachments.ts`, `session-title.ts`, `permissions.ts`, `agent.ts` and `ai-generation.ts` (no import cycles: a cycle between contract modules crashes at load).
- **P-02 Two migrations, both here.** `*_ai_chat` (schema, generated) and `*_provider_secret_refs` (data backfill, custom, sorted after it). Later plans add no drizzle migration; a plan that needs a schema change stops and reports. `packages/db/sql/post-migrate.sql` (grants, SECURITY DEFINER helpers) may be extended by a plan that lists it.
- **P-03 Readable set.** `ai_chat` joins `ReadableKind` in `chat/access.ts` but is NOT in the default kinds: only callers that pass `kinds` including `ai_chat` (ai-chat module, conv topic authorizer, search from 05-07, attachments from 05-09) see AI chats, so sidebars, unread counts, inbox, threads and saves never change. An AI chat is a `private` conversation with exactly one `conversation_members` row (`role: owner`); the resolver's existing private-channel precondition hides it from everyone else, admins included (hidden = 404). The new resource state `ai_chat` denies membership, moderation, broadcast and generic posting (`ai_chat_private`).
- **P-04 ModelRef and gateway.** Every turn names `ModelRef = {backend: chatgpt_plan | org_key | mock, provider, modelId}`. `model-gateway` is the only module that imports `@ai-sdk/*` and the only place a `LanguageModel` is built — always a provider instance (`createOpenAI(...).responses(id)`, `createAnthropic(...)(id)`, `createOpenAICompatible(...)(id)`), never a string id (string ids route to the metered Vercel AI Gateway). `apiKey` is always passed explicitly (the providers otherwise read `OPENAI_API_KEY` / `ANTHROPIC_API_KEY`). `chatgpt_plan` uses only the requester's own `user_model_credentials` row (D-01: never pooled); `mock` exists only with `OCW_MODEL_PROVIDER=mock`.
- **P-05 Prompts.** `buildModelMessages` (pure, `ai-chat/build-model-messages.ts`) is the only prompt builder: persisted rows in seq order (deleted rows skipped) → `{instructions, messages}`; purposes `chat` and (05-07) `title`. `streamText` / `generateText` are imported from `ai` only in `ai-chat/run-loop.ts` and `ai-chat/titles.ts`; `guard.test.ts` enforces it.
- **P-06 Streaming protocol.** Durable `message.created` for the user message and the assistant placeholder (`status: streaming`, `body: ""`, `generation` projection). Ephemeral `ai.delta {conversationId, messageId, generationId, offset, text}` on `conv:<id>`, coalesced every `AI_DELTA_COALESCE_MS` (50 ms); `offset` = UTF-16 length already emitted. Partial text flushes to `ai_generations.partial_text` every `AI_PARTIAL_FLUSH_MS` (1 s), never to `messages.body` (its STORED `search_tsv` would re-index three configurations each time). One durable `message.updated` at the end with the final body, status and generation (usage included). The snapshot returns `running.partialText`; the client subscribes first, buffers deltas, then stitches (`stitchAiSnapshot`) and refetches once per ~1.2 s while a gap remains (max 3 tries; the final `message.updated` always repairs it).
- **P-07 One generation per conversation.** `ai_generations` partial unique index on `(conversation_id) where status = 'running'`, inserted in the send transaction → 409 `generation_in_progress`. Per-user concurrency cap `concurrentGenerationsPerUser` (default 3) under `pg_advisory_xact_lock(hashtext('ai:' || user_id))` → 429 `concurrent_generations`. Idempotent send: the existing `(organization_id, author_kind, author_id, client_message_id)` unique index; a retried POST returns the existing message and generation. Heartbeat every `AI_HEARTBEAT_MS` (10 s); `instance_id` names the API process holding the `AbortController`. Stop (05-04) fans out on Redis `ocw:ai:abort`; the sweeper (05-04) marks stale (> 60 s) generations `interrupted` and keeps their partial text.
- **P-08 Executor rules.** E2E only via `bash scripts/e2e-isolated.sh` (API :4290, web :3290, fake :4291, Garage :4292 in compose project `ocw-e2e-storage`). Never touch the running demo: ports 4000/3000, `ocw-demo-*` containers, the `ocw` database, `~/.ocw-demo`, `~/.ocw`; never `pnpm demo:*`; no compose lifecycle on the demo project; never `docker exec` into `t3code-81d72154-postgres-1`; never start OpenClaw containers. Migrations only through testcontainers and the harness. Memory-constrained machine: run integration files one at a time and never two e2e runs at once. Contract changes → `pnpm typecheck --force` (turbo can give a stale pass). No real provider, ChatGPT or SearXNG call from any test or command: the fakes in `infra/fake-model` only. Work in the isolated worktree the orchestrator provides.
- **P-09 UI.** ChatGPT/Claude.ai-quality screen in the Work Zone / T3 Code layout language (D-08): centered column (max ~760 px), user turns as right-aligned bubbles, assistant turns full-width through the Phase 4 `<Markdown streaming>` with a quiet footer, sticky composer, `components/ui` (Base UI) primitives, `useStickToBottom`, `useSheetSurface` for bottom sheets at 390. - **P-10 Secrets.** Provider keys are read only through `core.secrets.resolve(tx, ref)` (05-02). Member OAuth tokens live in `app.secrets` kind `user_model_credential`, sealed with AAD `<orgId>:<userId>:chatgpt_plan`, referenced by `user_model_credentials.secret_id`; they never appear in a response, WS frame, audit row or log line. Errors from providers are logged as `{code, status, provider}` only — never the error object (AI SDK errors carry request bodies, i.e. prompts).
- **P-11 Labels.** Every org-key model, in the picker, the composer chip, Settings › Models and the message footer, carries the `METERED` label ("billed to your organization"); plan models show "Using ChatGPT plan · Manage usage" (`CHATGPT_MANAGE_USAGE_URL`) near the composer (OpenAI UI rule); the mock model shows "Mock (E2E) · not metered".
- **P-12 Test-only overrides.** `OCW_CHATGPT_API_BASE_URL`, `OCW_CHATGPT_AUTH_BASE_URL` and `OCW_AI_MOCK_BASE_URL` point the API at the fakes; `loadEnv` refuses the two ChatGPT overrides when `NODE_ENV=production`. - **P-13 Assistant author.** Assistant messages are `author_kind = 'agent'` with `author_id = null` and a `generation` projection; the ai-chat DTO sets `author = {kind: "agent", id: null, displayName: <model label>}` (the model in a direct chat is not an agent principal; Phase 6 personas will set `author_id`). AI chat messages never go through `chat.postMessage`, so they never notify, wake a bot or count as unread.
