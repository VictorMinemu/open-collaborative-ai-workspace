# Phase 07.4 Plan 06: Connector auth modes on the MCP registry Summary

**Admins now register MCP connectors in one of three auth modes from Settings › MCP servers. Organization-secret
servers behave as before. Per-member sign-in and per-member key connectors store their mode, a sealed pre-registered
OAuth client and the member header, and they never reach the OpenClaw cell. A mode switch or a delete that would
orphan member credentials needs explicit confirmation, which shows the member count, and is audited.**

## Accomplishments

- **API (`mcp/service.ts`)**
  - Create, update and delete persist `authMode`, `memberHeaderName` / `memberHeaderPrefix`, `oauthScopes` and the
    pre-registered client. The client secret goes through `SecretsService.put` (`mcp_credential`); responses only
    show `hasSecret`.
  - Ledger 178 is honoured. `memberHeaderName` is checked server-side with `isAllowedInjectionHeader()` and against
    the transport's reserved headers (`member_header_forbidden`). Six headers are tested, including `Cookie`,
    `Proxy-Authorization` and `Mcp-Session-Id`.
  - PATCH re-checks the rules of the resulting mode against the stored server:
    - stdio → `per_member_needs_remote`;
    - headers on a member mode → `headers_not_allowed`;
    - a header or OAuth fields on the wrong mode → `member_header_not_allowed` / `oauth_not_allowed`.
  - Leaving a member mode, or a DELETE, with members connected answers 409 `connections_exist` with
    `details.count`. With `clearConnections` (body) or `?clearConnections=true` (DELETE), every connection row and
    its secret is deleted in the same transaction. The audit is `connector.connections_cleared
    {serverId, count, reason}`.
  - `cellMcpServers` filters `auth_mode = 'org_secret'`. A cell probe is never requested for a member connector:
    the admin probe answers 409 `member_connector`, and a late cell report is ignored.
  - `replaceServerTools` was extracted from `recordProbeResult` without changing behaviour. It stores
    `input_schema`, capped at 16 KB (larger schemas are dropped). It is exported for 07.4-10, together with
    `setOAuthStatus`, `oauthClientsOf` and `DiscoveredTool`.
  - The DTO reads the real columns, which replaces 07.4-01's `org_secret` stub. `memberConnections` comes from one
    grouped count under RLS.
  - `GET /mcp-servers` adds `oauth: connectorOAuthUrls(OCW_PUBLIC_API_URL)`.
- **Catalog:** `CatalogSource.authMode` is filled in `loadCatalog`. The capability rules are unchanged.
- **Web**
  - An "Authentication" fieldset with three radio cards, in the same markup as Transport, and the mode explanation.
  - Sign-in mode: a read-only redirect URI with a copy button (plus the client metadata URL when it exists), and a
    collapsible "Pre-registered client (optional)" with Issuer URL, Client ID, a write-only Client secret, and
    Scopes (R11). A stored client shows as "Issuer … · Client ID … · Secret set", with Replace and Remove.
  - Member key mode: Header name (default `Authorization`) and Prefix.
  - Choosing stdio disables both member modes, with the reason shown.
  - When `oauthAvailable` is false, "Each member signs in" reads "Needs HTTPS" and an inline `role="note"` points
    to `pnpm ocw enable proxy`.
  - Server cards show:
    - the mode badge and the OAuth status badge (AA amber/red);
    - the member count and "Client: pre-registered (host)";
    - the needs-client warning and the member key chip;
    - "Waiting for a member to connect" and "Tools appear after the first member connects." (R6). Re-probe is
      hidden for member connectors.
  - Member connectors no longer make the list poll.
  - Mode-switch confirmation ("Disconnect {n} members?", focus on Cancel) and delete-with-members ("Delete and
    disconnect {n}"). Both take the count from the DTO before any request (R4). A 409 opens or updates the same
    dialog.
  - Touch targets are 44 px below `md`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The list polled forever with a member connector present**
- **Found during:** Task 1.
- **Issue:** `useMcpServers` refetched every 1.5 s while any server was `pending`. A member connector stays
  `pending` until 07.4-10's probe.
- **Fix:** Poll only for organization-secret servers that are pending or probing.
- **Files:** `apps/web/lib/mcp-queries.ts`.
- **Commit:** ccb1635d

**2. [Rule 2 - Correctness] A late or stale cell probe report could rewrite a member connector's tools**
- **Fix:** `recordProbeResult` ignores reports for non-`org_secret` servers, and `probeMcpServer` refuses with 409
  `member_connector`. Enabling a member connector does not request a cell probe.
- **Commit:** ccb1635d

**3. [Rule 2 - Correctness] Switching to a member mode left the organization headers and their secrets behind**
- **Fix:** They are deleted with the switch, and the cell is notified (tested in `mcp-cell.int`).
- **Commit:** ccb1635d

**4. [Rule 1 - Bug, a11y] Badge `warning` contrast 1.91:1**
- **Found by:** axe in the Task 3 e2e.
- **Fix:** Explicit amber/red classes on the OAuth status badges only. The shared Badge variant is left unchanged
  (see candidates).
- **Commit:** 37338661

## Broken-windows candidates

1. **Owner-only policy vs admin clearing (medium).** Ledger 170 plans a restrictive owner-only policy on
   `connector_connections`. If one lands, the admin count (`memberConnections`) and the clearing on switch or delete
   will see only the admin's own rows, and the clearing would silently leave other members' credentials behind. The
   policy needs an admin or `mcp.manage` path, for example a `SECURITY DEFINER` count-and-clear, and these tests
   must stay green.
2. **The shared Badge `warning` variant fails AA in light mode (medium).** It is 1.91:1 on its own tint.
   "Probing" on the MCP cards and other screens still use it.
3. **PanelDialog close button is 32 px at 390 (low).** This is `components/ui/panel-dialog.tsx`. The plain Dialog
   already goes to 44 px below `lg`.
4. **Cross-org FK rows (low, ledger 169).** A `connector_connections` or `connector_oauth_clients` row of org B
   may reference org A's server, because database FKs bypass RLS. Org A's code never sees or touches it (tested).
   It is still an orphan that `ON DELETE CASCADE` removes, but its `secret_id` is not removed by A's deletes.
   07.4-10's inserts must resolve the server id inside `withTenant`.
5. **Pre-existing:** 4 biome warnings in `apps/local-runtime`. Integration timing flake in
   `realtime-presence.int.test.ts` (rate-limit window, 3 s budget).
