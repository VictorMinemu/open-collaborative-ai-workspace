# Phase 07.13 Plan 09: Browser child process with real Chromium Summary

**The device now drives the pinned Chrome for Testing headless shell over Playwright's pipe in a supervised `ocw-runtime browser-agent` child. The page is read only through the bots' redaction and masked JPEG screenshots. Only http(s) pages are ever shown, even through links, 302s and pop-ups. Metadata hosts are refused at three layers, and each session's throwaway profile lives in a 0700 run dir that is removed on close, after a crash, and by the sweep.**

## Performance

- **Tasks:** 3 (1 tracer, 2 auto), all TDD
- **Files:** 8 created, 4 modified (2290 insertions)

## Accomplishments

- `createBrowserAgent`: one in-memory context (`serviceWorkers: "block"`, downloads refused, 960×600) and one page. `open` on an open page navigates it. `snapshot` goes through `serializeSnapshot` with the isolated-world facts and marks. `act` (click/type/select/press/scroll) and `wait` (load/text/time) keep brw's semantics, and a text wait is matched against the redacted snapshot. `screenshot` returns a JPEG (q80) through `maskedScreenshot`, kept to one control frame. Launch failures map to `no_usable_sandbox` / `missing_library` / `launch_failed` and are never retried without the sandbox.
- Refusals: `file:`, `chrome:`, `devtools:`, `view-source:`, `data:` and `javascript:` give `navigation_refused`, through `open`, a link click and a 302. A metadata host (any spelling) gives `metadata_refused`, directly, by link and by redirect. Each case is checked by a test against the real browser.
- `BrowserChild`: spawns `process.execPath [...entry, "browser-agent"]` with `childEnv` (PATH, HOME, TMPDIR/TMP/TEMP, OCW_BROWSER_EXECUTABLE, OCW_BROWSER_SANDBOX, plus ELECTRON_RUN_AS_NODE when set). It reads frames with `decodeFrameHeader`, and a bad header kills the child. Per-op timeouts come from WORK_BROWSER_TIMEOUTS_MS. `close()` ends stdin, sends SIGTERM after 3 s and SIGKILL after 6 s, then removes the run dir. After a SIGKILL, pending calls reject with `browser_unavailable`, `{ event: "crashed", scope: "process" }` fires, the run dir is removed, and no process on that profile keeps running (Chromium follows its pipe).
- `runBrowserAgent`: JSON lines in, `encodeFrame` control frames out (`ready`, responses, agent events with origins only). It dispatches only `AGENT_OPS` through `runOp`, runs each op under a deadline, writes fixed stderr names, and exits 3 when Chromium disconnects. Later plans add ops in `ops.ts` (the list plus a `runOp` arm). `main.ts` does not change.
- CI: Woodpecker `OCW_TEST_BROWSERS_DIR=/home/ocw-ci/cache/ocw-test-browsers`. GitHub's verify job caches `~/.cache/ocw-test-browsers` keyed on `pins.ts` and runs `sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0` before `pnpm verify`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Security] Redirects to a metadata host bypassed Playwright routing**
- **Found during:** Task 1 (A-8 probe)
- **Issue:** The route handler is called only for the first URL of a redirect chain. A 302 to `169.254.169.254` was sent to the network (on macOS it timed out; on a cloud VM it would have loaded).
- **Fix:** `--host-resolver-rules` maps every metadata host and its IPv6 spellings to `~NOTFOUND`. A `request` listener marks the redirected hop `metadata_refused`, and the route now aborts every request to a metadata host, not only navigations.
- **Files:** apps/local-runtime/src/browser/agent/ops.ts
- **Commit:** 77b6832e

**2. [Rule 1 - Bug] An unsafe 302 left Chromium's error page committed**
- **Found during:** Task 1
- **Issue:** `ERR_UNSAFE_REDIRECT` commits `chrome-error://chromewebdata/` after `goto` rejects, so the page left http(s).
- **Fix:** `restore()` settles, then goes back (or re-opens the last http(s) URL, else `about:blank`). It runs after a failed `open` and after every `act`, and a stray non-http(s) commit queues it before the next op.
- **Commit:** 77b6832e

**3. [Rule 3 - Blocking] A static playwright-core import broke the bundle's start contract**
- **Found during:** Task 2 (bundle.test.ts)
- **Issue:** esbuild hoists the external import, so a bundle with nothing installed beside it failed on `playwright-core` before naming the Claude Agent SDK.
- **Fix:** `ops.ts` imports only Playwright types and loads `playwright-core` with `await import` on first launch. `cli.ts` imports `main.js` lazily.
- **Commit:** 29ee5610

**4. [Rule 1 - Test robustness] Temp-dir check raced the in-process agent test**
- **Issue:** When ops.test.ts ran in parallel, its in-process Chromium put a profile in the OS temp dir, which broke a before/after diff in child.test.ts.
- **Fix:** The check now reads this child's own Chromium command line: its only profile is under the run dir, and that profile is not in the OS temp dir.
- **Commit:** ddfe6f0f

### Other notes

- `testBrowser` downloads only when `CI` is set. The plan says "else installBrowser". The orchestrator rule says tests never download locally, so locally the real-Chromium suites skip with a hint when the cache is empty.
- `AgentError` has an extra `invalid_request` code. WorkBrowserRefusal has no code for a malformed body or an unfit action, and the contracts belong to plan 01. Plan 12 maps it to its tool result.
- Task 3's pop-up, `info` and download behaviours came with Task 1's port of brw, so its tests passed on first run. A mutation check confirmed the pop-up test catches a pop-up that is not closed.

- `cli.test.ts`'s browser-agent test was written after the `cli.ts` arm (in the same task, before its commit).
- On Windows `childEnv` also passes `SystemRoot`, because Node and Chromium need it. That is untested here.
