# Phase 07.8 Plan 03: The three blocking spikes Summary

**Chromium's own sandbox runs under gVisor systrap (not on runc on Ubuntu 24.04). A plugin tool's image reaches the
model once the model declares image input. The whole sandboxd lifecycle works inside the Woodpecker dind on hardened
runc.**

`requirements-completed` is empty on purpose. SBX-01, BRW-01 and BRW-03 are informed by these spikes, not delivered
by them, so they stay open for the plans that build them.

## Deviations from Plan

1. **[Gate deviation, approved] gVisor source.** Google's bucket has no `release/20261005.0/x86_64/runsc`, so the
   official GitHub release asset was used, SHA512-verified. This is recorded in VALIDATION and in OUTCOME (i).
2. **[Rule 3 - Blocking] gVisor sidecars.** `runsc` alone fails in `release-20261005.0`: `sidecar "gvisor_sentry" not
   usable … --sidecar-usage-policy is set to STRICT`. The spike now extracts `gvisor-bin/` too. Plan 24 must install
   the whole tarball.
3. **[Rule 1 - Bug, spike code] Self-kill in spike (iii).** The first run killed its own runner (exit 137), because the
   runner carried `ocw.spike=07.8`. The runner now carries `ocw.spike-runner=07.8`. Lesson for 13: `sandboxd` must
   never carry the sandbox label it kills.
4. **[Rule 3 - Blocking, spike code] Manifest declaration in spike (ii).** The first run failed with `No callable tools
   remain … no registered tools matched`, because a plugin tool must be listed in `openclaw.plugin.json`
   `contracts.tools`. The scratch copy adds it. Plan 06 must list every new `ocw_*` tool there.
5. **[Rule 2 - Evidence] Extra diagnostic modes.** Spike (i) adds mode (c-aa) (AppArmor unconfined) and `unshare`
   probes, including a no-hardening case. They show that the runc failure comes from the host and not from our flags.
   Spike (ii) adds a second variant (`input` declared). It shows exactly why the image was dropped.
6. **Spike (ii) image size.** The tool returns a 1×1 PNG, as planned. OpenClaw passed it through intact (118-char data
   URL). Downscaling of large screenshots (`imageMaxDimensionPx`) was documented, not exercised.

## What changes the plan

- **07 / 13:** `browserSandbox` is a new reported property (`chromium+gvisor` | `chromium` | `container-only`). Never
  fall back to `--no-sandbox` silently on runsc.
- **06 / 14:** the cell snapshot needs a per-model image capability, and the reconciler must render `input`. Without
  it, the screenshot tool is useless to the model. The image reaches Chat Completions models as a **user-role**
  message, so the screenshot tool's `untrustedOutput` taint is the protection.
- **24:** install gVisor from the GitHub release with its sidecars. The Woodpecker dind needs no reconfiguration. The
  gVisor job uses a nested dind step.
- **29:** ADR-0029 records Chromium-sandbox-on under gVisor (better than the research's `--no-sandbox` assumption),
  the Ubuntu ≥ 23.10 userns restriction on runc, and A2's `input` condition.
