# Phase 07.5 Plan 01: Contracts for per-tool approvals and Work Zone proposals Summary

The phase's contracts are in place. `canonicalJson` implements RFC 8785 with no new dependency and passes the
Appendix B number vectors and the §3.2.3 sort sample. It throws on lone surrogates, NaN, ±Infinity, `undefined`,
non-plain values and nesting deeper than 32. There are typed approval policies with the `tool_approval.manage` grain
(team surface, admins and leads, never agents). The tool-call request, decision, card link, card-action grant and the
`tool_call` view are all additive. The Work Zone proposal contracts cannot express a permission mode.

## Deviations from Plan

### Names adapted (P-13: name, never semantics)

1. **`AGENT_CARD_ROUTE_PREFIXES`, `isAgentCardRoute` and `AgentCardRoute` moved to the new leaf module
   `agent-card-route.ts`.** `agent-cards.ts` re-exports all three unchanged.
   - Why: the planned imports form a cycle. `agent-cards.ts` imports `approvals.ts`, which imports
     `tool-approvals.ts`, which needs `AgentCardRoute`. That would throw a TDZ `ReferenceError` at module load.
   - Effect: the `"/approvals"` prefix sits in the leaf file.
2. **`ApprovalHeadline` already existed from 07.2-13** with `{title, context, requester, tags}`. It is kept unchanged.
   - The plan's `agent`, `origin`, `chips` (≤ 3) and `useBy` were added as optional fields.
   - `ApprovalSummary.headline` is now `.nullable().optional()`.
   - Plans 06, 07 and 08 must also fill `context` (nullable), `requester` and `tags` (may be `[]`).
3. **The view's source-kind enum is named `ApprovalToolSourceKind`.** `ToolSourceKind` already exists in
   `bot-capabilities.ts` as `mcp | plugin`, and the two collided in `index.ts`.
4. **New helper names the plan left open:**
   - `ApprovalOrigin`, `ApprovalOriginKind` and `ToolCallPreviewField` in `tool-approvals.ts`
   - `AgentChannelToolCallApproval` (the decision `approval` shape, reused by `AgentChannelApprovalRefusalDetails`)
   - `ApprovalKindsParam` and `ToolApprovalScope`
   - `hasInvisible(text)`, which backs `notices.hiddenCharacters`
5. **`work-zone-proposals.ts` imports `ApprovalOrigin` from `tool-approvals.ts`** instead of duplicating the origin
   DTO. There is no cycle: `tool-approvals.ts` imports only `common.ts` and the leaf route module.
6. **`WorkZoneStartBlock` was created in Task 1 instead of Task 3**, because Task 1's card-link field `blocked`
   needs it.

## Module catalog / backfill

`tool_approval.manage` has surface `team`. The 07.3 module catalog (`module-access.ts`) only classifies Work Zone,
Bots and `ai_chat.` grains, and none of its patterns match `tool_approval.*`. No module catalog entry changed, so
existing "off" rule sets need **no backfill** for this grain (unlike #177 in 07.4). The two new built-in tools
(`ocw_work_zone_projects`, `ocw_start_work_zone`) are not grains. 07.3's Work Zone module removes them through
`work_session.create` at turn assembly (07.5-08).
