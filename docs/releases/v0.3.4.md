Fixes for two problems found in v0.3.3 testing. Long bot conversations no longer get stuck on "Context is too large",
and bots run Work Zone sessions in projects without git. Conversation summaries are now an organization setting.

## What's fixed

- **Long conversations no longer get stuck.** When a bot conversation outgrew the model's context, OpenClaw tried to
  summarize it, then threw the summary away when it could not keep every required fact. The conversation stayed
  stuck: every message answered "⚠️ Context is too large and auto-compaction could not recover this turn". Summaries
  now keep what fits. If one still fails, the bot starts that conversation over with only its recent messages and
  answers, once per message. The old transcript is archived, not deleted.
- **Conversation settings for admins.** **Settings › Bot policy › Conversations**:
  - **Strict summaries** (off): refuses a summary that drops required facts. A long conversation can then get stuck.
  - **Keep exact identifiers in summaries** (off): ids, codes and order numbers stay word for word, at the cost of
    longer summaries.
  - **Recent history kept** (20,000 tokens): the latest messages kept word for word.
  - **Start a fresh session when a summary fails** (on): the bot keeps the recent messages of the chat.

  See [docs/self-hosting/bot-conversations.md](https://github.com/VictorMinemu/open-collaborative-ai-workspace/blob/main/docs/self-hosting/bot-conversations.md).
- **Work Zone sessions in projects without git.** A bot whose profile has **Isolated worktree** on now works directly
  in a project folder that is not a git repository, instead of failing with "isolated worktrees need git". It never
  runs a second session at once on that folder. Projects in git keep their isolated worktree. In **New session**, the
  **Isolated worktree** switch is off and disabled for a project without git ("This project has no git repository").

## Upgrade

In `/opt/ocw` (or wherever the server is installed):

```bash
sudo node scripts/ocw.mjs upgrade --check   # current and newest release; changes nothing
sudo node scripts/ocw.mjs upgrade           # backup, this release, new keys, rebuild; never goes backwards
```

- **Two new migrations, additive:** whether a Work Zone project is in git (filled in when each device next connects)
  and the four Conversations settings (with the defaults above).
- **Bots pick up the new summary settings by themselves.** A conversation that is stuck recovers on its next message.
- **Headless Work Zone servers** on v0.3.1 or later update their runtime with one click (Settings › Devices › the
  server › Runtime updates › **Update**), or by themselves at the *Automatic* level. Nothing in the runtime changed
  besides its version.

The desktop app does not update itself: install the new files below. Its runtime ships inside it.

## Install the server

On Ubuntu 24.04 or Debian 12, with a DNS name pointing at the server:

```bash
curl -fsSL https://raw.githubusercontent.com/VictorMinemu/open-collaborative-ai-workspace/main/scripts/install.sh \
  | sudo bash -s -- --domain ocw.your-company.com
```

The installer installs this release (`v0.3.4`). The [README tutorial](https://github.com/VictorMinemu/open-collaborative-ai-workspace#install-it-on-a-server)
walks through the first admin, model providers, invites and what to try first.

## Desktop app

None of the builds is signed yet, so the first launch needs one extra step:

- **macOS** (Apple silicon): open `OCW-v0.3.4-macos-arm64.dmg` and drag OCW to Applications. Open it once, then go to
  **System Settings › Privacy & Security** and choose **Open Anyway** (or run
  `xattr -dr com.apple.quarantine /Applications/OCW.app`).
- **Windows** (x64): run `OCW-v0.3.4-windows-x64-setup.exe`. If SmartScreen stops it, choose **More info › Run
  anyway**. It installs for the current user, without admin rights.
- **Linux** (x64): on Ubuntu or Debian, `sudo apt install ./OCW-v0.3.4-linux-amd64.deb`. Elsewhere,
  `chmod +x OCW-v0.3.4-linux-x86_64.AppImage` and run it. The app keeps the device token in the desktop keyring
  (GNOME Keyring or KWallet), which must be available.

Then enter your workspace URL and pair the computer under **Settings › Devices › Add device › Desktop app**. On a
server without a screen, use the headless runtime instead (**Settings › Devices › Add a device › Server**). Signed
builds are planned for MVP 2.

## Known limitations

- Long tasks run in channels, threads and DMs, not in AI chats. A task stays in its own thread: it cannot span several
  conversations or bots, and there is no list of a bot's tasks yet (the card in the thread is the place to look).
- A turn carries at most 101 tools from MCP servers and plugins (128 in all). The bot sheet's **Tools** section says
  how many of the ones you turned on do not fit.
- A very large job may need more than the 40 turns of the default. The card then says the task used its turns; an
  admin raises **Turns per task** and the person asks again.
- After **Stop**, a turn already running finishes before the task ends (OpenClaw cannot abort a turn).
- Bots read documents in Spanish and English OCR only, and do not transcribe audio or video.
- The desktop app does not update itself, and its builds are not signed yet.

The full list is in the [README](https://github.com/VictorMinemu/open-collaborative-ai-workspace#known-limitations).
