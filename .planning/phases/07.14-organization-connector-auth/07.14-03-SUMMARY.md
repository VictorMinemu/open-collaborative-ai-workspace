# Phase 07.14 Plan 03: Fake OAuth MCP Server Client Credentials Summary

**The 07.4 fake OAuth MCP server now issues, refuses and expires RFC 6749 §4.4 client-credentials tokens for pre-registered confidential clients, has one scenario knob per D-10 diagnosis trigger, and the API test stack and e2e fake each pre-register a client-credentials client.**

## Accomplishments

- `client_credentials` branch on `POST /mcp-oauth/token`. It accepts Basic (form-urlencoded parts, decoded per RFC 6749 §2.3.1) or `client_secret_post`. `resource` must equal the MCP resource. Scopes are checked. There is no refresh token and no id_token, and the subject is `sub_cc_<client_id>`. `expires_in` comes from the scenario (default 3600).
- Strict refusals: `invalid_target`, `invalid_scope`, `invalid_client` (401) and `unauthorized_client` for public clients. Every attempt is counted in `tokenRequests.client_credentials`, `lastResource.cc` and `lastClientAuth`.
- Four diagnosis scenarios: `cc_post_only`, `no_authorization_endpoint`, `issuer_mismatch_meta` and `invalid_scope_at_authorize`. All four are typed and documented in the `.d.mts`.
- AS metadata advertises `client_credentials`.
- `PRE_REGISTERED_CC` / `CC_SECRET` exist in `startConnectorsStack`, and `ocw-e2e-cc` / `e2e-cc-secret-canary` exist in the e2e fake.
