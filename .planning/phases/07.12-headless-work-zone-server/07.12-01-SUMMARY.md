## Decisions Made

- **Banner, footer and hash in the script.** The script writes the banner and footer itself and hashes the exact
  bytes it writes, so `sha256` and `bytes` always describe the file on disk.
- **SPDX `OR` licenses.** An `A OR B` license is accepted with its first allowlisted alternative; an `AND`
  expression fails the build. Today only MIT packages are bundled, so this has no effect yet.
- **Installed SDK must match the pin.** The build also fails when the installed SDK version differs from the pin.
  This prevents a manifest that pins one version while the tests ran against another.
- **One more export.** `runtime-dist.ts` also exports `CLAUDE_AGENT_SDK_PACKAGE` and `BundleLicense` (the zod enum of
  the allowlist). These add to the listed names; nothing is renamed.

## Issues Encountered

- **Symlinked bundle could not find the SDK.** In the first test run the bundle in the scratch directory was a
  symlink. Node resolved `node_modules` from the file's real path (the build directory) and did not find the SDK. The
  test now copies the file, which is how `install.sh` will lay it out.
- **Desktop shell commands refused.** The worktree sandbox refused `env -i` shell compositions, so the manual
  smoke run was folded into `bundle.test.ts`, which covers it.

## Notes for Later Waves

- **06 (serving and image):**
  - Run `pnpm --filter @ocw/local-runtime build:bundle --out <dir>`; `--commit <sha>` or `OCW_SOURCE_COMMIT` sets
    `source.commit`.
  - In the image stage, `git` is probably unavailable and `commit` will be null unless one of those two is passed.
  - The script reads the SDK's `package.json` from `apps/local-runtime/node_modules`, so that stage needs a
    `pnpm install` that includes the SDK. The SDK's optional platform binary may be skipped.
- **03 (CLI pairing) and 08 (setup):**
  - Use `PAIRING_INTERVAL_SECONDS` and `PAIRING_SLOW_DOWN_STEP_SECONDS` for the poll interval.
  - Write `deviceId`, `webUrl` and `pairedWith` (`{ organization, owner, at }`) into runtime.json from the optional
    `EnrollDeviceResponse` fields.
  - `readInstallInfo(home)` returns null in a development checkout.
- **02 (API pairing):**
  - Normalize the typed code with `normalizeUserCode` before hashing.
  - `StartPairingResponse.userCode` must be the formatted `XXXX-XXXX` (the schema enforces it).
- **09 and 10 (end-to-end and container proof):** the bundle needs the SDK and its peers to resolve beside it, and
  Node resolves them from the bundle's real path, so a symlinked `ocw-runtime.mjs` must sit next to its own
  `node_modules`. The `current` symlink layout in PD-04 works because `current/` is a directory link that holds both.
- **Codex `clientInfo.version`.** The Codex client still reports `version: "0.0.0"` in `clientInfo` (`codex/*.ts`,
  recorded fixtures). It was left unchanged on purpose: it is unrelated to the daemon version and the fixtures depend
  on it.
