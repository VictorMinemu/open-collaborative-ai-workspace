# Phase 07.16 Plan 19: Outside content: the admin's flag, bypass only on isolated servers, a proposal otherwise Summary

**After a bot's turn reads outside content, a Work Zone start without the admin's flag becomes a proposal the asker reviews. The card warns "Proposed after reading outside content", and Start marks the first prompt tainted. With the flag the bot acts, but it gets Full access only on an isolated server, and the session stays tainted. 15/15 new integration cases pass locally on real PostgreSQL and Redis.**

## Intended change (CLAUDE.md plan mode: permissions, audit, tenant data)

- **Start route, tainted turn, flag off.** The sponsor's transaction (tx1) runs the usual checks and then writes nothing. The route then opens tx2 as the asker. In tx2 it checks the live turn, claims the call with `outsideContent` (metadata `fallback: "proposal"`) and calls today's `proposeWorkZone`. The proposal uses the profile's device and runtime and is stored with `tainted = true`. The answer is `proposed`. If the proposal is refused for the asker, the answer is `outside_content`, and the audit records the proposal's own code.
- **Start route, flag on.** The call is claimed with `outsideContent`, and the layer carries the turn's taint. An explicit `fullAccess` off an isolated server answers `outside_content_bypass` before anything is written.
- **Prompt route.** The same flag rule. A prompt from a tainted turn is queued with `tainted = true`, and `work_sessions.tainted_at` is set if it is still NULL.
- **Proposals.** The card gets the warning notice and `apply` passes `firstPromptTainted`. The `ocw_start_work_zone` route is unchanged, so it still refuses tainted turns at its claim.
- **D-20 gap (flagged by 15 and 17).** The board, memory-file and sandbox routes use their own conditional UPDATEs. Each now also requires `session_output_read = false`.
- No permission check, RLS policy, approval gate or existing taint check is weakened. The admin flag is never set by this plan. Human routes are unchanged.

## Decisions Made

- **The fallback runs as the asker in its own transaction.** The proposal belongs to the asker, and its human checks (`work_session.create`, `device.use`, D-13) must see their RLS. The sponsor's transaction only decides.
- **The fallback proposes only a project in the profile's live set.** Otherwise it answers `project_not_allowed`. Outside content never widens what the profile allows.
- **`outside_content_bypass` is refused before the claim.** It is a denied call that does not count, like `session_output`.
- **`outsideContent` is decided once, in the audit builder, from the turn's taint.** Every outcome of a tainted turn (stop and pre-claim refusals included) says so.
- **A profile default above the context steps down to the highest allowed mode.** Before, it fell straight to `default`. This applies to untainted starts too, and it never refuses an implicit default. See deviation 2.

## Deviations from Plan

**1. [Rule 2 - Missing critical] D-20 on the board, memory-file and sandbox routes**
- **Found during:** flagged by 07.16-15 and 07.16-17; the orchestrator assigned it to this plan.
- **Issue:** these routes use their own conditional UPDATEs, which ignored `agent_turns.session_output_read`. A cell calling them directly after a session read was not refused.

- **Files modified:** board.ts, memory-files.ts, sandbox.ts and one test case in each route's suite.

- **Commit:** `5a996d0e`

**2. [Rule 1 - Bug] The implicit mode fell straight to `default`**
- **Found during:** Task 2
- **Issue:** a profile default above what the context allows fell back to `default` (Supervised). After outside content on a desktop, that is not "the highest mode below Full access" that the plan's behaviour requires.
- **Fix:** when an implicit (profile) default is refused on the mode, `bots.start` tries each mode below it, highest first, down to `default`. Then it tries the implicit start as before. No refused attempt writes anything, because `createWorkSession` decides the settings before any insert. An explicit mode is still never lowered.
- **Files modified:** apps/api/src/modules/work-session/bot-sessions.ts
- **Verification:** "desktop: without a mode…" gives `BELOW_FULL`. bot-start 17/17, work-sessions 25/25 and bot-dispatch 18/18 are unchanged.
