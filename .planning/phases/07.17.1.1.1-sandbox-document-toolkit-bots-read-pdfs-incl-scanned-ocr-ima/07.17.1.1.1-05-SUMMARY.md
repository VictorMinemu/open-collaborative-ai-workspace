# Phase 07.17.1.1.1 Plan 05: Real-Docker smokes for the document toolkit, the macro rule and drift Summary

**The sandbox smoke now proves the toolkit the way a bot uses it: fixtures generated in the bot's own shell and read
with `ocw-extract` through sandboxd as 10001, on runc and (in CI) gVisor, under a 900 s cap. It also proves the macro
rule with a positive control that really fires, and image drift on real Docker. Locally on runc: `docs` 25 ok lines,
`drift` 7 ok lines, the full smoke green, nothing labelled left behind.**

## Intended change (CLAUDE.md plan mode: smoke of the isolation boundary)

- `infra/sandbox/test/run-sandbox-smoke.sh` gains two sections after `restart`: `docs` and `drift` (in `SECTIONS`,
  the usage text, the header and the runner; `drift` runs last because it moves the `$IMAGE` tag). `--only docs` and
  `--only drift` run alone.
- `docs` acts only through sandboxd's HTTP API: people's file write (base64), `exec` as 10001 with background
  polling. There is no `docker exec`, and no egress proxy, so it is offline. Only the macro control uses plain
  `docker run` of throwaway, labelled containers with the image tests' hardening flags and `--network none`.
- `.woodpecker/sandbox.yaml` `gvisor-smoke`: `--only core,docs`, its wall time, and greps for `runtime gvisor` and
  the docs OCR line. `sandbox-smoke` (runc) still runs every section.
- `infra/ci/disk-budget.sh`: the comment only (about 2.3 GB, the `sbx` share about 1.1 GB). No value or command.
- Not changed: sandboxd, the image, any hardening flag, cap or existing check.

## What was built

- **Task 1 (tracer), `docs`.** A fresh org and bot X. `make_fixtures.py` is written to `fxgen/` through
  `/v1/files/write` and run in the shell with `--only scan.pdf,text.pdf,sign.png,plan.docx,ventas.xlsx,slides.pptx,
  plan.odt,pedido.eml,pack.zip,blob.bin,macro.fodt`. Then one `ok docs:` line per type: the scanned PDF (`(ocr)` and
  "politica de devoluciones", matched without accents), text PDF, Spanish PNG, docx, xlsx (`### sheet: Ventas`,
  `Norte,1200`), pptx, odt, `.eml` (`Pedido 42`, `### attachment: factura.pdf`), the zip listing line for `a.txt`,
  and `blob.bin` → exit 3. The section also checks the PATH (five tools), the python3 imports and `id -u` 10001. The
  batch exits 75 with `--budget 1` and reaches 0 within five default-budget runs. `_index.tsv` is read through
  sandboxd (scan.pdf `done`), `fx/text.pdf` keeps its sha256, every answer's stdout is at most 16 384 bytes, and the
  section prints `docs: section took <N> s` (fails over 900 s).
- **Task 2.** The macro block is inside `docs`. `ocw-extract fx/macro.fodt` and the bot's own `soffice --headless
  --norestore --convert-to pdf` (default profile under `/workspace/.config`) produce `fx/out/macro.pdf`, and
  `fx/MACRO-RAN` never exists. On runc, `macro_control` builds `${IMAGE}-macro-control` (FROM the smoke image,
  `ocw.xcd` removed, labelled). In it and in the real image it generates `macro.fodt`, seeds `MacroSecurityLevel` 0
  and opens the file headless. The control must fire (or the smoke prints `macro positive control not achieved
  (configuration-only proof)`), and the real image must not (FAIL otherwise). Under gVisor it prints one `skip docs:
  macro control …` line.
  `drift` uses org D with bots P and Q. P is stopped, the tag is rebuilt (I2), and the next ensure gives a new
  container on I2 with `drift/kept.txt` intact. Q keeps running across another rebuild (I3): the same container on
  I2. After stop and ensure, Q is a new container on I3. `restart` of P (running on I2) re-creates it on I3, file
  intact. `on_exit` removes `$IMAGE`, `$MACRO_IMAGE` and every recorded ID (I1, I2, I3, the control) after the
  containers are gone, and counts labelled images in the leftover check.

`docker system df` fails on this machine before and after (a pre-existing container with a missing layer snapshot,
as in 03). The build cache was measured with `docker buildx du` instead: 3.995 GB before, 5.216 GB after the first
smoke build. The default builder keeps the smoke image's layers, and they were not pruned (no prune is allowed). Later
builds reused them.

**Durations.** runc local (arm64, M-series): `docs` 13 s without the macro block, 74-75 s with it. CI amd64 runc and gVisor:
**proven on CI**. The orchestrator pushes, and the `sandbox-smoke` and `gvisor-smoke` run links, both `docs: section
took` lines and the `gvisor-smoke took` line are to be recorded from that run. gVisor (A-01, PD-18) was not run
locally: Docker Desktop has no runsc.

**Macro control result (for ADR-0043).** Positive control **achieved** locally: without `ocw.xcd`, a profile with
`MacroSecurityLevel` 0 and an ordinary headless open run the document's `dom:load` Basic macro (MACRO-RAN written).
With the real image's finalized `ocw.xcd`, the same open never runs it. So A-02 holds: `share/registry/ocw.xcd`'s
finalized keys win over a user profile. That is a behavioural proof, not configuration-only.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] YAML parsed the new grep line as a mapping**
- **Found during:** Task 1 (parsing `.woodpecker/sandbox.yaml` after the edit)
- **Issue:** `- grep -q "ok   docs: scanned PDF OCR" …` contains `: `, so YAML read it as an object. Woodpecker
  would have rejected the step or run something else.
- **Fix:** the whole command is single-quoted. The parse now shows it as a string.
- **Commit:** b84b7b5c

**2. [Rule 2 - Missing critical] Images counted in the leftover check**
- The plan wanted every built image removed and "zero labelled objects left". The old count covered only
  containers, volumes and networks. Labelled images now count too, after removal by tag and by recorded ID.
- **Commit:** f64cbe83

**3. [Plan text] Extra restart check in `drift`; `--only macro.fodt`**
- 04 also changed `restart`, so `drift` re-creates P with `restart` after Q's sequence (a new container on I3, file
  kept). The plan's `make_fixtures.py --only macro` names the fixture `macro.fodt`, and that name is used.
- The gvisor-smoke step captures the smoke's exit (`rc`) so that `gvisor-smoke took` prints even on failure, then
  fails with `test "$rc" = 0`. This mirrors `gvisor-browser`.

**Total deviations:** 3. **Impact:** none on scope. No cap, flag or check was weakened, and the 900 s cap was not
raised.
