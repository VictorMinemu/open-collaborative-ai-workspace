level and manifest, stores what devices report, keeps the history, audits every step, lets owners and admins press
"Update now", and shows the details only to them (ROADMAP success criterion 4; RTU-06).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device → API | Snapshot and run frames are untrusted; schema-parsed, scrubbed again, bounded |
| browser → API | "Update now" and history are decided by the resolver (`device.maintain`) |
| API → device | Only `runtime.config` (level + manifest) and `runtime.update` `{ runtime }` |
| tenant A ↔ tenant B | Devices, history, audit and frames are organization data |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.11-06-01 | Elevation of privilege | `POST …/update` by a grantee or member | high | mitigate | `assertCan(device.maintain)` via the resolver; Task 2 403 cases |
| T-07.11-06-02 | Tampering | server-injected command | high | mitigate | Payload `{ runtime }` only, asserted deep-equal (Task 2); no other server→device field (D-05) |
| T-07.11-06-03 | Information disclosure | maintenance details to grantees / on `org:` | high | mitigate | DTO field only for `device.maintain` holders; `org:` id-only ping; Task 1 cases |
| T-07.11-06-04 | Information disclosure | host paths in stored output / snapshot | high | mitigate | Schemas refuse paths; `scrubHostPaths` again before storing; audit never carries output (Task 1) |
| T-07.11-06-05 | Repudiation | lost audit when the device was offline | medium | mitigate | Run frames come from the device's offline log; idempotent by run id; audit only on first transition (Task 1 replay case) |
| T-07.11-06-06 | Denial of service | "Update now" spam | medium | mitigate | One `requested` per device and runtime (DB partial unique → 409), stale expiry after 1 h, offline refused (Task 2) |
| T-07.11-06-07 | Information disclosure | cross-tenant request, history or config push | high | mitigate | `withTenant` + RLS on every read; push lists devices inside the org's tenant; Task 3 org-B cases |
| T-07.11-06-08 | Spoofing | a device reporting another device's runs | medium | mitigate | Handlers use the authenticated `DeviceRef` id only; rows are keyed by it |
</threat_model>
