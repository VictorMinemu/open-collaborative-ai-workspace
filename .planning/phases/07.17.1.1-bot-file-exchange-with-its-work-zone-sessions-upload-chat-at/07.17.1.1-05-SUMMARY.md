# Phase 07.17.1.1 Plan 05: Bot Work Zone file tools in the cell Summary

**The OpenClaw plugin now has `ocw_work_session_upload` and `ocw_work_session_download`. Their closed schemas accept only ids and a repo-relative path, both are checked locally against the mirror's `WorkSessionFilePath`, and each call gets one attempt within a 615 s budget. The gate treats both as self-validated and leaves taint and session-output decisions to the routes. The Work Zone block shows the per-file limit. The real-cell smoke now covers both calls; it runs on CI.**

## Accomplishments

- **Upload (T1, tracer).** The upload posts `{eventId, agentId, workSessionId, attachmentId, path}`, plus `overwrite` only when the model passes it. The tool refuses locally, without sending anything:
  - a `deviceId`, `userId`, `conversationId`, `url` or `absolutePath` key;
  - a non-uuid id;
  - a path such as `../x`, `/etc/hosts`, `~/x`, `C:\x`, `a\b`, `a//b` or `./a`;
  - a NUL or bidi character, or a path over 1 024 characters;
  - a non-boolean `overwrite`.
- **Upload answer.** A success renders "Put docs/spec.pdf (1.5 KB) into session <id>."
- **Download (T2).** The download posts `{eventId, agentId, workSessionId, path}`. An `attachmentId` or `overwrite` parameter is refused as an extra key. A success renders "Downloaded <name> (<size>) from session <id>. It is attached to your reply; read it with ocw_attachment_read on a later turn if you need its content."
- **Refusals.** Both tools show the API's sentence first. A `file_too_large` refusal keeps the API's composed size sentence word for word. An older API's base sentence stays as it is.
- **Ended turns and failures.** A 404 `unknown_turn` and a timeout render the same fixed sentences the 07.16 tools use. Logs never carry a path or a file name.
- **Gate.** Both tools are self-validated and counted against the cap of 8; the ninth call is refused locally. They are never approvable, and no arguments leave the cell. On a tainted turn and after a session read they still reach their routes, which decide (`ROUTE_DECIDES_TAINT`, `SESSION_OUTPUT_EXEMPT`). Memory writes keep their local block.
- **Client.** `workSessionUpload` and `workSessionDownload` make one attempt each with `WORK_SESSION_FILE_REQUEST_TIMEOUT_MS` (615 000). A 5xx is not retried. `workSessionPrompt` still uses 30 000.
- **Work Zone block.** When `turn.workZone.files` is present, the block adds a `files` line: "Move files with ocw_work_session_upload and ocw_work_session_download: up to 25 MB each (the organization's limit), 5 each way per turn, only in this conversation; uploads only while the session is idle." The tools text also names both new tools. Without `files`, the block is deep-equal to the 07.16 one, and an unknown limit source counts as absent.
- **Fake API and smoke (T3).** The fake API now has strict `/work-sessions/upload|download` routes and records their bodies.
  - In the smoke's `bot_work_sessions` scenario, the `alsoAllow` check now expects the six names, sorted.
  - A new case injects `mention-work-session-files.json`. It asserts:
    - one upload body with keys `agentId,attachmentId,eventId,path,workSessionId`;
    - one download body with keys `agentId,eventId,path,workSessionId`;
    - no `/tool-calls` row for the event;
    - "Put docs/spec.pdf" and "Downloaded README.md" in the reply;
    - the files line in a model request.
  - The existing assertions are unchanged.

## Decisions Made

- The names joined the plugin's list one task at a time: upload in T1, download in T2. The manifest and registry tests iterate that list, so adding both names in T1 would have left T1's commit with a listed but unregistered tool.
- When the API sends `file_too_large` with a `limit` but no usable sentence, the plugin composes the size sentence with the mirror's `botFileTooLargeSentence`. In every other case the API's sentence wins.
- Logs carry ids, codes and byte counts, never a path or a file name.
