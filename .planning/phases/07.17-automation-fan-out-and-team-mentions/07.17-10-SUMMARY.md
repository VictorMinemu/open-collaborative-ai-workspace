# Phase 07.17 Plan 10: Plugin item turns, fan-out instruction, escalation sentence Summary

**The cell turns each `agent.automation_item.v1` into the bot's own tainted turn in the opened root's thread, with the item in an `external` block labelled untrusted, and tells run turns how to call `ocw_conversation_open` once and both run and item turns whom to mention.**

## Accomplishments

- `mapAutomationItem` follows `mapAutomationRun`. It maps the event as a mention on the root, so the run-as person is the sender, the server sentence is the body and the reply goes in the root's thread with `inReplyToMessageId` = the root. It adds an `automation` block (source `ocw`: automation id and name, run, item, standing order) and an `automation_item` block (source `external`, labelled untrusted, payload exactly `{ title, text, openedAt }`). The turn always starts tainted and browser tools are dropped.
- The bridge handles `agent.automation_item.v1` the way it handles the 07.16 wake. The type is in `TURN_EVENT_TYPES` and the event switch. The frame is validated with `safeParse`, a bad one logs only the seq and field path and is skipped, and a good one runs through `runTurn` with idempotency `evt:<eventId>`.
- `fanOutInstruction` (the must-haves sentence word for word) is added to the automation block of fan-out runs. `escalationSentence` is added to run and item blocks when targets exist; handles go through `blockHandle` and each appears once.
- Run events without `fanOut` / `escalation`, or with `null` / `[]`, map deep-equal to before (PD-18).
