# Phase 07.17.1 Plan 06: Settings › Devices Runtime row Summary

The Runtime updates section of a device card now opens with an "OCW runtime" row. It shows the installed `version · build` next to what the workspace serves, with one Update button that the API decides. The row follows its run every 2 s and toasts the outcome or the API's refusal sentence. It covers every busy, blocked, desktop, older-daemon and checkout state. A turn held by the restart says the runtime is restarting.

## What was built

- `runtimeSelfView(device)` is a pure function that decides the row's view from `hostKind`, `runtimeMaintenance.self` and `runtimeMaintenance.served` only. The web decides nothing about permissions: it shows Update only with `device.maintain` in `viewerCan`, and the API re-decides every request.
- `RuntimeSelfRow` reuses the 07.11 row's layout (`flex flex-col gap-2.5 px-3 py-2.5 md:flex-row md:items-start md:gap-3`, `flex-wrap` header, buttons `min-h-11 md:min-h-8`, full-width buttons on mobile). It has a `Server` icon tile, a mono version and a Badge pill:
  - "{v} available" (brand)
  - "Up to date" (success)
  - "Update failed" (warning)
  - the busy label with a spinner: Downloading…, Installing…, Waiting for sessions to finish, Restarting… (with "since …" on hover)
- Under the header:
  - the line "Your workspace serves {v} · {build}"
  - the level line: automatic "Updates by itself when no session runs", off "Automatic checks are off. Update still works.", nothing at notify
  - the last-run line (`lastRunText`, type widened to `Pick<…, "lastRun" | "checkedAt">`)
  - notes: the block sentences, the not-served sentence, "Updates with the desktop app", and "Re-run the install command once to turn on one-click updates." followed by a wrapping `CopyLine` of `runtimeInstallCommand(apiUrl)`
- Toasts: "OCW runtime updated to {version} · {build}"; "OCW runtime update failed" with the run's error; the refused/expired error; `errorMessage(err)` for a 409.
- The list is now labelled "Runtimes on this device". The history state, the `RuntimeUpdateHistorySheet` and both device query hooks take `RuntimeUpdateTarget`.
- `event-stream.tsx`: `runtime.update` with `subject: "ocw-runtime"` renders the restart line with test id `runtime-update-line`. Without `subject`, the 07.11 copy is unchanged (its tests still pass).
