## Phase Goal

A controller pastes, drops or attaches images in the Work Zone composer and the session's runtime (Claude Code or
Codex) receives them with the prompt; everyone in the session sees the sent images in the stream. Reuses the Phase 4
attachment pipeline; the API is the only ACL and forwards bytes to the device as `PromptPayload.images`.

**This plan's slice (tracer, API level):** contracts first, then one image goes end to end on the server: Phase 4
presign/PUT/complete into the session's conversation → prompt with `attachmentIds` → link → dispatch persists ids only →
the hub hydrates base64 at send time → a FakeDevice receives it. Then the access rules and the byte rules.

Planner decisions P-01 … P-12 are in `06.1-RESEARCH.md` ("Planner decisions"). Executor rules (P-13): never touch the
running demo (ports 4000/3000, the `ocw` database, `~/.ocw*`), never read `.env` or `.env.demo`, apply migrations only
through testcontainers or `scripts/e2e-isolated.sh`, make no real provider or runtime call. CLAUDE.md asks for plan mode
on tenant-isolation changes and schema migrations: present the schema diff and the scope delegate as a plan before
editing, then proceed (the owner delegated approval).
