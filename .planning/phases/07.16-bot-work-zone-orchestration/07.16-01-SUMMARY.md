# Phase 07.16 Plan 01: Bot Work Zone contracts Summary

**One leaf contract file (`bot-work-zone.ts`) fixes the phase's bot-facing vocabulary: the turn's Work Zone offer, four strict `ocw_work_session_*` tool bodies and their answers with 19 fixed refusal sentences, a bounded repo-relative read model, the `agent.work_session.v1` wake event, the profile/consent views and pure live-card helpers. The OpenClaw plugin mirrors all of it, with parity tests.**

## Accomplishments

- `TurnContext.workZone` (optional) and `BUILTIN_TOOLS.workSession*` / `WORK_SESSION_TOOL_NAMES` / `WORK_SESSION_TOOL_FLAGS`.
  All four names are never approvable and never dangerous on either host.
- Strict start, prompt, read and stop bodies. None of them can express `deviceId`, `userId`, `visibility`, `worktree` or
  `audience` (P6). Prompts are trimmed and 1..50 000 characters. The answers are discriminated unions on `kind`.
- `BotWorkSessionReadModel`: output limited to 6 000 characters in total (refined), `RelativePath` on every file and
  approval path, at most 10 tools, 50 files, 10 approvals and 3 deciders. A key-name walk over every answer variant
  proves no key matches `/absolute|abs_path|hostPath|url/i` (P2).
- `AgentWorkSessionEvent` follows the `AgentConsultReplyEvent` pattern, with the event type constant in both copies.
- `BotWorkZoneProfileInput` (strict, distinct project ids), `BotWorkZoneProfile`, `BotWorkZoneProfileView`, the consent
  schemas, `BOT_PROFILE_STATUS_SENTENCES`, `OUTSIDE_CONTENT_WARNING` and the local `HostKind` enum (equal to 02's
  `DeviceHostKind`).
- Card helpers: `WORK_SESSION_CARD_LABELS`, `workSessionCardStatus`, `workSessionStepLabel`, `workSessionCardOf`.
- 07.15-shaped turns, `EMPTY_TURN` and every existing payload still parse (additive only).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Guard `ocw.permission-bypass-token` refused the new tests' bypass literals**
- **Found during:** the end-of-plan `pnpm guard` run (PD-24 protocol).
- **Issue:** the new tests wrote `"bypassPermissions"` and `"danger-full-access"` to prove they are refused. Semgrep only
  allows those literals in the ADR-0012 path files.
- **Fix:** the tests now take every literal from `RUNTIME_BYPASS_LITERALS`. In the plugin, they load it from the
  contracts' `session-events.ts`. This is a stronger test: every literal is refused in both copies. The guard rules were
  not changed.
- **Files modified:** `packages/contracts/src/bot-work-zone.test.ts`, `apps/openclaw-channel/src/plugin-contract.test.ts`
- **Commit:** `6f8f4024`

### Notes against the hub's wording (same names and bounds, nothing renamed)

- `RelativePath` is exported from `common.ts`, not `device-link.ts`. File status uses `DiffFileStatus`, which is the
  same enum as `DiffFile.shape.status`.
- The contracts' `agent-channel.ts` has no event union. Like `consultReply`, the wake event is registered through
  `AgentChannelEventTypes`. The plugin bridge's `TURN_EVENT_TYPES` set is plan 09's file and was not touched.
- `BotWorkZoneProfile` is built from a shared field shape rather than `BotWorkZoneProfileInput.omit().extend()`. The
  keys and bounds are the same; the view stays non-strict.

**Total deviations:** 1 auto-fixed (Rule 3) and 3 wording notes. **Impact:** none on the names other plans rely on.
