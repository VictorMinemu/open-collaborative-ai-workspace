# Phase 07.14 Plan 10: Watched records on organization-account connectors Summary

**Watched records and their compare-and-set write-backs now run on `org_oauth` / `org_client_credentials` servers with the organization's sealed token. On the watched wire they are workspace access (`org_secret`), so no member connection or share is needed. A refused organization credential fails `connector_unavailable` and never sends a member a Reconnect DM.**

## Intended change (plan mode, CLAUDE.md)

`watched/` is a module that decides which credential reaches a shared board, so here is the intended change before the detail:
- Every literal `authMode === "org_secret"` in `watched/{options,check,service,write}.ts` becomes a D-16 predicate.
- `rendersInCell` → organization headers (unchanged path).
- `isOrgCredentialMode` → the organization's key from `credentialKeyOf`.
- `isPerMemberMode` → the caller's own credential plus the share rule (unchanged).
- No RLS, permission or approval check was relaxed. The share rule still applies to every member mode. An org mode never falls back to the linker's account, and a member mode never uses the organization's.

## Accomplishments

- **`check.ts` `callWith`:**
  - Org modes use `credentialKeyOf` → `accessTokenFor`, with one `forceRefresh` and one retry on a 401, then `markNeedsReconnect` on the organization key.
  - Every refused organization credential, and a switched-off org server, returns `fail("error", "connector_unavailable")`.
  - `touchCredential` stamps whichever credential was used.
  - `readRecord` runs the share check only for member modes. `tellLinker` only fires for member modes.
- **`options.ts`:** `usable = isPerMemberMode || orgEnabled`. A `workspace` flag sets the wire value `org_secret`, `connection: null` and `shared: true`.
- **`service.ts`:** `connector_disabled` and `assertShared` treat every non-member mode like organization headers. The DTO maps with `isPerMemberMode`.
- **`write.ts` `preflight`:**
  - Switched off → `connector_error` for every non-member mode.
  - Org modes need a connected organization connection (else `connector_error`) and no member connection or share.
  - Member checks are unchanged.
- **Web:** both watched files decide with `isWorkspaceAccess`. The wire shape did not change.

## Decisions Made

- **orgEnabled:** org modes respect it everywhere in watched (options, link, check, write), as organization headers already did. Member modes keep ignoring it, as before.
- **A refused organization credential:** on a check it is status `error` / code `connector_unavailable`, not `not_connected`. The watch strip then shows an error, not "paused, reconnect", and `tellLinker` is gated a second time on `isPerMemberMode`.
- **`preflight` code for org modes:** it answers `connector_error` for an unusable organization connection. The route's `not_connected` sentence says the connector "uses <person>'s own account", which is wrong for the organization's.

**1. [Rule 2 - Correctness] `preflight` checks the organization connection for org modes**
- **Found during:** Task 2

- **Fix:** `credentialStatusFor(tx, credentialKeyOf(server, …))` must be `connected`, else `connector_error`. It refuses before any token is read or request is sent.
- **Files modified:** `apps/api/src/modules/watched/write.ts`
- **Verification:** the `rules()` assertions in the write-back describe (RED returned `not_connected`, GREEN returns `connector_error`)
- **Committed in:** `a790cb93`

**2. [Rule 2 - Correctness] `callWith` refuses a switched-off org-mode server**
- **Found during:** Task 1
- **Issue:** `accessTokenFor` does not look at `orgEnabled`, so a check on a switched-off org server would still have called upstream.
