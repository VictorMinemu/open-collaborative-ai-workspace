# Phase 07.18 Plan 16: the account pool in the browser Summary

The owner's scenario now has a browser journey on the real daemon in fake mode, on desktop 1440 and mobile 390, in
light and dark. An admin adds two Claude accounts in Settings › Account pool. Sam, a member, starts a session and only
sees "Account: pool (failover)" (D-15: no choice, nothing to set up). The first account hits its limit on the first
turn, and the same turn finishes on the second: the timeline says why, the header says "Account: b", Settings shows the
first one cooling. For bots, the organization's existing ChatGPT sign-in is the pool's first account, an admin adds a
second one with the device code, and removing it signs out only that profile in the cell.

**The e2e has not run yet.** Project rule: e2e runs only in CI. Typecheck, lint, guard and every unit test the plan
touches pass locally (below).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] A Models page ChatGPT sign-in never served bots once the pool had removed every bot account**
- **Found during:** Task 2, while planning the spec's interplay with `codex-subscription.spec.ts`, which runs after
  it on the same CI stack.
- **Issue:** `cellAccountPool` counts removed rows, so once a ChatGPT bot account has existed and none is left enabled,
  the snapshot leaves `openai-codex` out of `subscriptions` (plan 14, on purpose). A new Settings › Models sign-in then
  fails like this:
  1. the plugin reported `connected` without a profile id, so no pool row was made;
  2. the snapshot kept withholding the subscription;
  3. no credential state report ever named the new profile, because the plugin only reports listed subscriptions;
  4. the plugin's next sync logged the fresh credential out.

  On CI this would also have failed `codex-subscription.spec.ts` (`subscriptions` would be `[]`), and the journey's own
  second run on one stack.
- **Fix:** `subscription-auth.ts` reports `signedIn.profileId ?? ev.profileId` on every `connected`. The API already
  adopts a Models page sign-in that carries a profile id (plan 14). Adoption that the next profile list would have done
  now happens at connect, and it works while the subscription is withheld. Plan 14's decision that bots stay off ChatGPT
  when every bot account is removed or off is unchanged.
- **Files modified:** `apps/openclaw-channel/src/subscription-auth.ts`, `subscription-auth.test.ts` (two expectations
  now include `profileId: "openai:owner@example.test"`).
- **Commits:** `e3c4f68b` (RED), `2a2710c8` (GREEN).
- **Release note for 17:** the cell plugin changed: a Models page sign-in joins the pool at once.

**2. [Rule 3 - Blocking] `codex-subscription.spec.ts` uses a 07.18 fake cell**
- **Issue:** after this journey removes its ChatGPT accounts, a pre-07.18 fake cell (no profile id) would hit item 1 on
  the same stack.
- **Fix:** its fake gets `deviceAuth.profiles: true`, with a comment. Its assertions are unchanged (`credentials`,
  `revoked` and `subscriptions` keep their meaning).
- **Commit:** `80d41545`.

**3. E14 path.** The plan says "the fake cell already holds one profile (reported at start)". Removed pool rows count
forever, so a pre-07.18 plugin's sign-in followed by an upgrade could only be adopted on a never-used stack. That would
make the spec fail its second run on one stack. The spec instead:
- makes the existing sign-in through the Models page route with a 07.18 fake (adopted at connect);
- restarts the cell holding that profile, which reports its list at start;
- checks there is still exactly one account.

The pure old-plugin adoption stays covered by plan 14's `cell-pool.int.test.ts`.

**Other choices:**
- axe runs in light and dark on every screen, which is stricter than the plan's single run.
- The session screen gets axe on `session-header` and `event-stream`, not `session-view`, which also contains the
  composer that other specs cover.
- Touch targets are checked on the sections and dialogs, which cover row actions, selects and dialog buttons. The
  shared `expectTouchTargets` does not measure `role="switch"` spans (Base UI renders the switch as a span with a
  hidden input). The row puts each switch in a `max-md:min-h-11` wrapper.

### Not done here (logged in `deferred-items.md`)

- `DELETE /model-providers/openai-codex` leaves the pool's live `cell_profile` rows showing "Ready" while the cell holds
