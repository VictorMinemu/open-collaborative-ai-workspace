# Phase 07.15 Plan 03: The one row rule for bot file access Summary

**`attachmentForTurn` (live message, the turn's conversation, its thread in a channel, never an unsent or Work Zone
upload) now decides `ocw_sandbox_import`, which also writes `bot.attachment_imported` on every outcome; the bot
history window and the rule share `messageScopeFilter`.**

## Intended change (CLAUDE.md plan mode: permissions, audit, tenant data)

- New `agent-channel/attachment-access.ts` with the D-16 row rule. Its semantics match PR #55's `importableAttachment`
  exactly: the row is present under RLS, of the turn's conversation, `ready`, has a `messageId`, no `workPromptId`;
  the conversation is a channel, thread, DM, group or AI chat; the carrier message is live and in the turn's
  conversation; in a channel it is the turn's thread root or a reply in that thread (root = the turn message's
  `threadId ?? id`); every other kind is read whole.
- `/sandbox/import`: the precheck's three-term check is replaced by `attachmentForTurn` (null → `not_found`).
  `service_unavailable`, `too_large` and the F-8 `audienceCovers` check stay where they were. `sandbox.file_imported`
  and `bot.tool_call` are unchanged.
- An additional audit row `bot.attachment_imported` (actor and agent the bot, user the asker, resource the
  attachment). It holds ids, the media type, the size and the outcome, never a name or a path. It is written in the
  transaction that records each outcome.
- `buildMentionEvents`: the inline thread filter is moved as-is into `messageScopeFilter`.
- No permission check, RLS policy or approval gate was weakened. The import is now stricter.

## Decisions Made

- The thread root is looked up only for channel turns, as in #55. DMs, groups, AI chats and thread conversations are
  read whole, so they never need the trigger message.
- The audit's `conversationId` is the resolved row's conversation, or the turn's when no row was resolved.
  `mediaType` is `contentType ?? declaredType`.
