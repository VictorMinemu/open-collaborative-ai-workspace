# Proxied connector tools never take a turn's tool slots; connector arguments are never closed

## Problem (owner UAT, v0.3.4 on ocw.autofy.ing, Histolab BOT, an organization-account ERP MCP server with many tools)

1. **Tools past the cap are refused although enabled.** `ocw_connector_call` → `listar_expedientes` with `{}`:
   `Tool ocw_connector_call blocked: that connector tool is not allowed on this turn.`
   (`apps/openclaw-channel/src/tool-guard.ts:416`). Root cause: `assemble()` in
   `apps/api/src/modules/bot-capabilities/turn-policy.ts` adds a proxied source's tools (per-member connectors and
   organization-account servers, `proxiedSource()`) to `turn.tools` under their logical names `m<8 hex>__<tool>`
   (`CONNECTOR_LOGICAL_TOOL`, `apps/openclaw-channel/src/agent-channel-protocol.ts:2316`) in the final catalog loop,
   which stops at `TURN_CATALOG_TOOLS_MAX` (101, quick 261113-e6s). Those logical names are **not OpenClaw tools**: the
   plugin passes OpenClaw only `turn.tools ∩ the bot's configured tools` (`mention-mapper.ts` ~798, `allowedTools`), and
   reaches every logical tool through the one `ocw_connector_call`. So they never count against the provider's 128
   function-tool limit, yet today they consume it, and a big server's tools past the cap are dropped from the turn, so
   the gate (plugin `tool-guard.ts`, `connector-tools.ts` ~258, API `agent-channel/connectors.ts` ~382/392) refuses them.
2. **Every connector call with arguments fails validation.** `catalogo_operaciones` with `{buscar: …}`:
   `arguments.buscar: schema is false`. OpenClaw 2026.9.7 validates tool calls with TypeBox
   (`validateToolArguments`, image `dist/package-update-activation-recovery.mjs` ~286938) against the normalized tool
   schema; the `arguments` property of `ocw_connector_call` (`apps/openclaw-channel/src/connector-tools.ts` ~244,
   `{ type: "object" }` with no `additionalProperties`) ends up closed (`additionalProperties: false`). Reproduced in the
   image: TypeBox `Value.Errors` on `{arguments:{type:object,properties:{},additionalProperties:false}}` with
   `{arguments:{buscar:"x"}}` → `/arguments/buscar boolean` ("schema is false"); with `additionalProperties: true` → no
   error. OpenClaw's normalizers only default `additionalProperties` when the key is absent.

## Fix

### A. Proxied logical tools do not count against the provider tool limit (API, contracts, plugin)

- `packages/contracts/src/bot-capabilities.ts`:
  - export `TURN_CONNECTOR_TOOLS_MAX = 1000` (doc: proxied connector tools are reached through `ocw_connector_call` and are
    never OpenClaw function tools, so they have their own bound, not the provider's 128).
  - `TurnContext.tools`: `.max(TURN_TOOLS_MAX + TURN_CONNECTOR_TOOLS_MAX)` (the provider limit is enforced by the API on
    the non-logical names, see below).
  - export a pure helper `isConnectorLogicalTool(name)` matching `/^m[0-9a-f]{8}__\S/u` (same shape as the plugin's
    `CONNECTOR_LOGICAL_TOOL`; reuse it in the plugin if the plugin already imports from contracts, else keep the plugin's
    regex) and `openClawToolCount(tools)` = count of names that are not logical connector tools.
- `apps/api/src/modules/bot-capabilities/turn-policy.ts`:
  - In `assemble()`: proxied sources' logical tools are added **without** the `TURN_CATALOG_TOOLS_MAX` / `MAX_TURN_TOOLS`
    checks (bounded by `TURN_CONNECTOR_TOOLS_MAX` instead); in-cell catalog tools keep the `TURN_CATALOG_TOOLS_MAX` stop,
    counted on `openClawToolCount(tools)`; the `add()` cap for platform tools counts `openClawToolCount` too.
  - Every later `tools.length` vs `MAX_TURN_TOOLS` check in `computeTurn` (Work Zone session tools, sandbox/browser
    families, task tools and their eviction, attachment read, consult, conversation open, withheld bookkeeping: grep
    `MAX_TURN_TOOLS`) uses `openClawToolCount(...)`. Eviction never evicts a logical connector tool to make room (they
    take no room).
  - `toolsOverLimit` counts only in-cell catalog tools (proxied tools are never over the limit); update its doc.
- Plugin (`apps/openclaw-channel`): `agent-channel-protocol.ts` mirrors the contract (`TurnContext.tools` max) if it has
  its own copy; nothing else should need to change (it already separates logical names). Verify `mention-mapper.ts`
  never passes a logical name to OpenClaw (`allowedTools`), and that a turn with 300 logical tools + 120 OpenClaw tools
  maps correctly.
- `ocw_connector_list` (API `connectors.ts`) lists every logical tool of the turn: verify it is not truncated elsewhere
  (a listing cap per connector is fine if it exists and is documented; if the listing has a size bound smaller than a big
  server, keep it but make sure a tool past the listing bound is still callable when named).
- Web bot sheet copy (`apps/web/components/bots/tools-section.tsx`): the "at most N tools" warning counts in-cell tools
  only; tools of organization-account / per-member connectors are not limited. Adjust copy only if it states otherwise.

### B. `ocw_connector_call`'s `arguments` is explicitly open

- `apps/openclaw-channel/src/connector-tools.ts` ~244: `arguments: { type: "object", additionalProperties: true,
  description: … }`. Check the plugin's other free-form object parameters (grep `type: "object"` without
  `additionalProperties` among tool `parameters` in `apps/openclaw-channel/src/*-tool*.ts`) and make the ones meant to be
  free-form explicitly open; never open a schema that is closed on purpose.
