## Phase Goal

The Claude Code and Codex CLIs that the Local Runtime drives stay up to date on every device without anyone touching
it, above all on server-type shared devices (a headless daemon, often Linux, where several members run shared sessions
on the owner's login), and on members' own computers too. The daemon finds how each CLI was installed and the one
command that updates it; the latest version comes from the npm registry; a compatibility manifest bundled in
`packages/contracts` and served by our Control Plane decides what may be installed (broken never); an update runs only
when that runtime is idle on the device and never cuts a turn; an org policy (automatic · notify · off) intersected with
a device-local level decides whether it happens; owners and admins see versions, status and history and can press
"Update now"; everything is audited and works headless (ROADMAP Phase 07.11; RTU-01…RTU-07).

**This plan's slice (tracer, contract level):** the whole vocabulary of the phase in `packages/contracts`, proven by
one update's frames round-tripping through the Device Link unions; plus the new permission. Plus this hub: plan map,
shared files, cross-plan names, planner decisions PD-01…PD-19.

There is no UI-SPEC for this phase: the layout is specified concretely in 07.11-10 (PD-15), reusing the existing
Settings › Devices card, the Work Zone policy page sections and the policy history sheet.

## Planner decisions (PD-01 … PD-19)

- **PD-01 Split.** 11 plans in 6 waves (above). W2 runs four plans on disjoint files; W3 two; W4 two.
- **PD-02 Where the end-to-end proof lands.** The orchestrator asked the first wave to prove one update end to end.
  That needs the contracts (contracts first, AGENTS), the migration, the daemon and the hub at once: more than one plan
  can carry at the 50 % context target. So each plan leads with a vertical tracer of its own tier proven against the 01
  contracts, and the phase's real end to end (real daemon, fake CLI, fake registry, real API, owner's view, audit)
  is 09 Task 1, in W4, the first wave in which both halves exist. 06 Task 1 (FakeDevice → API) and 07 Task 1 (daemon →
  protocol-faithful fake server) already prove each side against the same frames in W3.
- **PD-03 Device Link (CONTEXT: discretion).** Server → device `runtime.config` is ephemeral (never queued): sent right
  after `welcome` and again when the org's `runtimeUpdates` changes (Redis control op `{ op: "config" }` on the
  device channel, so every API instance reaches its own sockets). Device → server `runtime.maintenance` is a snapshot
  sent in the handshake and on change only while connected (like `projects.sync`); `runtime.update.run` goes through
  the offline log so no audit is lost. Command `runtime.update` carries only `RuntimeUpdatePayload` (D-05). Older
  daemons ignore `runtime.config` and ack `runtime.update` as an invalid frame (harmless); older APIs never send
  `runtime.config`, so the daemon stays at `notify` (D-10).
- **PD-04 Storage (CONTEXT: discretion).** Current state = `devices.runtime_maintenance` jsonb (the last snapshot,
  written only from the device socket, like `runtime_catalog`). History = table `device_runtime_updates`: `id` uuid pk,
  `organization_id`, `device_id` (composite FK to `devices (organization_id, id)`, cascade), `runtime`, `run_id` uuid
  null (device-generated), `command_id` uuid null, `trigger`, `requested_by` uuid null, `state`, `from_version`,
  `to_version`, `candidate`, `method`, `output` (≤ 4096), `error` (≤ 500), `requested_at`, `started_at`,
  `finished_at`, `created_at`; unique `(organization_id, device_id, run_id)`; partial unique `(organization_id,
  device_id, runtime) where state = 'requested'` (one pending "Update now" per device and runtime); index
  `(organization_id, device_id, created_at)`. "Update now" inserts a `requested` row with `command_id` and
  `requested_by`; the device's `started` frame carrying that `commandId` adopts it (sets `run_id`); runs without a
  `commandId` insert their own row; replays are idempotent by `run_id`; a `requested` row older than 1 h becomes
  `expired` before a new request is accepted.
- **PD-05 Who sees what (D-06, D-11).** `device.maintain` decides the two routes and whether `GET /devices` carries
  `runtimeMaintenance` for a device (its `viewerCan`); `runtimeCompatibility` goes to everyone who already sees the
  device (it is computed from versions they already see). The `org:` stream only ever gets the existing id-only
  `device.updated` ping. Members and grantees never see install method, location, update command, state or history.
- **PD-06 Audit catalogue (D-06, principle 12).** Written in the same transaction as the state change, never with
  output or a path. `device.runtime_update_requested` (user, route; metadata `{ runtime }`);
  `device.runtime_update_available` (device; once per (runtime, latest version) when a snapshot first says `behind`;
  `{ runtime, installed, candidate, candidateCompatibility }`); `device.runtime_update_started` and
  `device.runtime_update_finished` (actor: the requester `user` for manual, `system` for automatic, `device` for a
  local trigger; `{ runtime, from, to, candidate, outcome, trigger, method }`; finished has `result: "error"` for
  failed/refused); `device.runtime_update_skipped` (system; a broken candidate, once per candidate);
  `device.runtime_update_stale` (device; when a snapshot first reports `stale`); `device.runtime_updates_level_changed`
  (device; when the reported local level differs from the stored one; `{ from, to, source }`);
  `work_zone_policy.updated` with `changed: ["runtimeUpdates"]` (existing route).
- **PD-07 The gate (D-03, D-03a, D-03b).** A turn of runtime R is in flight when the adapter's `activeTurns()` > 0
  (running or queued in the adapter, approvals included) or the gate's `admitted` > 0 (a command between admission and
  the adapter call). Held while the gate is closed: `session.start`, `prompt` (and steer), `session.configure`,
  `session.title` and catalog collection for R; never held: `interrupt`, `approval.resolve`, `session.stop`,
  `diff.request`, and anything for the other runtime. Admission re-checks the gate and increments `admitted` in the
  same synchronous step, so nothing slips in between the idle check and the update. Automatic updates wait up to
  `DRAIN_AFTER_MS` (1 h) with the gate open and take the first idle moment (closing the gate in the same tick); after
  that they drain (gate closed; in-flight turns finish). "Update now" (manual or local) drains at once. A held command
  makes its session emit `runtime.update` `waiting` once; when the update ends, those sessions get `done` (with the new
  version) or `failed`. A pending update older than `STALE_AFTER_MS` (24 h) is reported `stale`. Nothing ever calls
  `interrupt` for an update.
- **PD-08 Levels (D-02, D-10).** Effective = lower of org (or `notify` until a `runtime.config` arrives) and the device
  level. `off`: no registry request at all; the snapshot still reports the installed version and method. `notify`:
  checks and reports; installs only on "Update now". `automatic`: installs when behind, the candidate is not broken
  and `canUpdate`. "Update now" needs effective ≥ `notify` (API: org `off` → 409 `runtime_updates_off`; device: local
  `off` → refused "updates are off on this device"). A manual request makes a fresh registry check; not behind →
  refused "already up to date". After an `unchanged` run, automatic retries for the same (runtime, candidate) back off
  24 h.
- **PD-09 Install methods (D-01, D-05, D-08).** One fixed table on the device (RESEARCH § Install methods): native
  Claude (`~/.local/bin/claude` → `~/.local/share/claude/versions/…`) → `<bin> update`; Codex standalone (realpath
  under `${CODEX_HOME:-~/.codex}/packages/standalone/`) → `<bin> update` with that `CODEX_HOME`; npm global (realpath
  under `<prefix>/lib/node_modules/<pkg>`) → `<prefix>/bin/npm install -g --prefix <prefix> <pkg>@<candidate>`;
  Homebrew cask/formula (realpath under `<brew>/Caskroom/<name>/` or `<brew>/Cellar/<name>/`, confirmed by
  `<brew>/bin/brew` existing) → `<brew>/bin/brew upgrade [--cask] <name>`; pnpm / bun / yarn / Volta globals →
