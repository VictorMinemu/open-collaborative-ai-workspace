<objective>
Per D-07 (and D-12 for its tests). The daemon can hold every runtime gate for the desktop app's restart and tell it,
synchronously and without a race, when no Work Zone turn runs, so the app never cuts a turn to install an update. The
hold reuses ADR-0040's all-gates step (extracted from `self-update-job.ts` into a shared helper), is bounded, releases
itself if the app died between the hold and the quit, and excludes the 07.11 CLI updates and the runtime self-update in
both directions.

Purpose: DAU-06, the daemon half of "never cut a turn". Output: `all-gates.ts`, `app-restart-hold.ts`, two strict
control commands, `status.appUpdate`, daemon wiring and tests.

Interface this plan publishes (plans 03 and 05 copy it into the desktop package, which does not depend on
`@ocw/contracts`):

- request `{ cmd: "appUpdateHold", drain: boolean }` (strict) → `{ held: boolean, state: "idle" | "draining" | "held", running: number, blocked?: "runtime_update" }`
- request `{ cmd: "appUpdateRelease" }` (strict) → `{ released: boolean }`
- `status().appUpdate` → `{ state: "idle" | "draining" | "held", running: number, lastEnd?: "released" | "timed_out" | "auto_released" }`
- `running` = for every runtime, `activeTurns(id) + gate.admitted`, summed.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| desktop app → daemon control socket | Local same-user requests (0600 Unix socket / named pipe), never the server |
| server → daemon (Device Link) | Prompts that the hold must not let start mid-restart |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.13.1-01-01 | Denial of service | a hold that never ends | high | mitigate | 30-min max with gates closed, 2-min auto-release after `held`, `appUpdateRelease`; every exit clears timers (Task 2 tests) |
| T-07.13.1-01-02 | Tampering | a turn cut by the restart | high | mitigate | `closeAllIfIdle` checks and closes in one synchronous step; held prompts never start in a stopping daemon (sealed gates, PD-27 re-queue) |
| T-07.13.1-01-03 | Elevation of privilege | the server or a forged field asking for a hold | medium | mitigate | Commands exist only in `ControlRequestSchema`, never in Device Link frames; strict schemas refuse extra keys |
| T-07.13.1-01-04 | Tampering | overlapping CLI update, self-update and app hold | medium | mitigate | `runtimeUpdateBusy` blocks the hold; `exclusive` and `cliBusy` block the others while the hold is active |
| T-07.13.1-01-05 | Information disclosure | host paths in answers or logs | low | mitigate | Answers carry states and counts only; requests are never logged |
</threat_model>
