## Phase Goal

**As an** Organization Admin and every member of the workspace, **I want to** arrange the company into departments, teams and projects with the four PRD roles, have every route decided by one permission resolver, and manage my own password, sessions and profile, **so that** each person and agent can do exactly what their role, units and rules allow and every sensitive change is attributed and audited.

**This plan's slice:** the people half of the admin console (ORG-04 users, roles, memberships view) extending Settings › Members, plus member profiles (ORG-06).

<objective>
Extend Settings › Members (research §Admin console UX item 1, D-09) on the 02-07 and 02-09 APIs: role select for admins, unit chips linking to the Organization page, status pill and "Show deactivated" filter, row menu (View profile, Create password reset link, Deactivate/Reactivate), invite form limited by the inviter's ceiling, Revoke only where `viewerCan` allows, the "What can each role do?" matrix (read-only roles view — custom roles are out of scope per research), and a member profile sheet reused by the chat members dialog. Remove the last web role check from this page.

Purpose: SC2's "users, roles … and memberships are managed from CRUD pages in the admin console (extending Settings › Members)" and SC5's "see other members' profiles".
Output: updated Members page, new row/sheet/dialog components, member-queries.ts, admin-members e2e spec, reviewed screenshots.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-12-01 | Elevation of privilege | hidden controls bypassed by crafting requests | medium | mitigate | No authorization in the browser — controls follow /me/permissions and viewerCan; the API decides (02-07 tests) |
| T-02-12-02 | Information disclosure | reset link persisted or leaked | high | mitigate | Link kept only in component state, never in query cache, URL or logs; warning copy; server marks the response no-store |
| T-02-12-03 | Information disclosure | avatar URL tracking | low | mitigate | referrerPolicy no-referrer on URL avatars; server accepts only https |
| T-02-12-04 | Tampering | stale UI after a role change | low | accept | Server re-decides; the UI refreshes on member.updated within one realtime round trip |
</threat_model>
