## Phase Goal

See `07.11-01-PLAN.md`. **This plan's slice:** the device owner's half of the level (D-02: a device-local opt-out that
can only lower the org policy, through the same three paths as ADR-0012's Full access opt-in) and the desktop app's
status lines and toggle (D-09: the desktop only shows and toggles).

<objective>
Let the device owner set the device level from the CLI, the desktop menu or the environment, applied without a
restart through the existing value-less `reloadConfig`, and show each runtime's update status in the desktop menu.

Purpose: RTU-05's device side; RTU-07's desktop half.
Output: config setter, CLI subcommands, daemon reload, desktop runtime-config helpers, a pure menu model with tests,
the menu wiring.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| device owner → daemon | The level is local configuration; only the device's user can write runtime.json or set the env |
| desktop renderer → main | The web origin and the preload API cannot reach the level (main process only) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.11-08-01 | Elevation of privilege | server or web raising a device's level | high | mitigate | The level is only in runtime.json/env; `reloadConfig` is value-less and strict; no frame or IPC channel carries it |
| T-07.11-08-02 | Tampering | malformed runtime.json | low | mitigate | Refused with the existing message; the daemon keeps its current level |
| T-07.11-08-03 | Repudiation | a device turning updates off silently | medium | mitigate | The snapshot reports `localLevel` and source; 06 audits `device.runtime_updates_level_changed` |
| T-07.11-08-04 | Denial of service | lowering the level mid-update | low | mitigate | A running update finishes; only pending ones are cancelled (Task 1) |
</threat_model>
