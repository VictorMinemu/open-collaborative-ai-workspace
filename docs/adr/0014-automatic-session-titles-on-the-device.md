# ADR-0014: Automatic session titles on the device

## Status

Accepted (owner decision 2026-10-05, D-18 … D-20 in `.planning/phases/03.2-work-zone-session-controls/03.2-CONTEXT.md`).
**Date:** 2026-10-05. Builds on [ADR-0013](0013-work-zone-session-settings-protocol.md) (Work Zone session settings
protocol) and [ADR-0005](0005-local-runtime-daemon-process-model.md) (daemon process model); supersedes neither.

**Amended in place 2026-10-05** (same phase, before this ADR was relied on anywhere else): the shape was tightened
from 3–6 words / 48 characters to 2–5 words / 32 characters so a title fits a sidebar row in full (decision 4).

## Context

A Work Zone session without a typed title used to show the first line of its first prompt, cut at 80 characters.
Long first lines were hard to tell apart in the sidebar, the breadcrumb and the browser tab. The owner asked for a
short, recognisable title made from the first prompt, generated by the session's own runtime. These principles
constrain the design:

- Principle 3: run locally when necessary. The prompt is already on the device, and so is the runtime login.
- Principles 7 and 8: no host paths or secrets may leave the device inside a title.
- Principle 10: open source first. There is no pooled or metered key: each device owner's own Claude or ChatGPT
  subscription pays.

The two runtimes differ:

- Claude Code (Agent SDK) can run a separate one-shot query.
- Codex (`codex app-server`) can run an ephemeral thread on a short-lived app-server.
- In plan mode, Claude runs Haiku as Sonnet (finding in 03.2-02).

## Decision

1. **Where the title is generated.** On the session's device, by the session runtime's own small model, on the
   device owner's login:
   - Claude Code uses `haiku`.
   - Codex uses `gpt-6-luna`.

   The vendor is always the session runtime's vendor. `TITLE_MODEL` lives in `packages/contracts/src/session-title.ts`.
2. **Protocol (P-15).** The API sends the device command `session.title` with `{ runtime, model, prompt }` (the
   prompt is cut to 4000 characters). The device answers in one of two ways:
   - Success: a `title.result` frame `{ requestId, sessionId, title, model }`, then an ok ack.
   - Failure: only a failed ack whose error starts with a stable `TitleFailureCode`.

   The hub accepts a result only for a `session.title` command of that same device (the `diff.request` /
   `diff.result` pattern). A title is not a `SessionEvent`, so it is never added to the session stream.
3. **Title source (P-14).** `work_sessions.title_source` takes one of three values:
   - `user`: typed by a user, never replaced. This is the default, so older rows are protected.
   - `heuristic`: the first line of the prompt.
   - `auto`: generated.

   The migration only adds this column (additive). The API stores an automatic title with one conditional update,
   `where title_source = 'heuristic'`, so a typed title or an earlier automatic title is never overwritten.
4. **Shape (P-16).** 2–5 words in the prompt's language, sentence case, no quotes, markdown or trailing
   punctuation, at most 32 characters, cut on a word boundary. 32 characters is what fits one Work Zone sidebar
   row in full: the row has 219 px at 1440 (267 px in the 390 drawer); the longest recorded title, "Fix settings
   page login redirect" (32 characters), measures 196 px. Words are counted with `Intl.Segmenter`, so languages
   written without spaces count correctly. Each side checks the title:
   - The device runs `normalizeSessionTitle`. It refuses any answer, and then any title, that `contain()` /
     `redact()` would change (`title_sanitized`: host paths and credential-like tokens are refused, never
     rewritten). The raw answer is checked first so the word-boundary cut cannot keep the head of a credential.
   - The API checks `SessionTitle` again: length, word count, no control characters, markup or home-directory
     paths, the session's own device, the same tenant (RLS) and the requested model.
5. **When the API asks (P-18).** Only when all of these are true:
   - the title source is `heuristic`;
   - this is the session's first prompt;
   - the prompt is not a slash command;
   - the device catalog lists `TITLE_MODEL[runtime]`;
   - the org Work Zone policy `allowedModels[runtime]` is empty or includes that model;
   - the runtime's `session.title` inventory row is exposed (backed by a recorded fixture).

   A session created without a prompt first takes its prompt's first line, then asks.
6. **Fallbacks (D-19).** In each of these cases the session keeps its first line:
   - a skip by the rules above;
   - a refusal by the API;
   - a failed ack;
   - the daemon's own 20 s timeout.

   A title runs outside the session's configure/prompt chain. A title failure never sets `lastError`, never emits a
   `session.error` and never changes the status.
7. **Isolation per runtime (P-17).** Each call runs in an empty temporary directory, which is then removed. Each
   uses the shared `TITLE_INSTRUCTIONS` and the prompt wrapped in `<request>` delimiters.
   - **Claude Code** runs a separate `query()` with these options:
     - `model: "haiku"`, `permissionMode: "default"`;
     - `tools: []` plus a deny-all `canUseTool`;
     - bypass disabled, secret deny rules, `settingSources: []`, `strictMcpConfig`;
     - `persistSession: false`, `maxTurns: 1`, `thinking: disabled`;
     - API keys stripped from the environment.

     The init must report `haiku` or its resolved model.
   - **Codex** runs its own short-lived `codex app-server` (`experimentalApi: false`) with one thread and one turn:
     - `thread/start`: `ephemeral: true`, `sandbox: read-only`, `approvalPolicy: untrusted`, reviewer `user`,
       `baseInstructions`;
     - `turn/start`: the lowest catalog effort (`low`), `summary: "none"`.

     The title fails, and the turn is interrupted, on any of these:
     - an approval request (declined);
     - a non-message item;
     - an unrestricted policy;
     - another model.
8. **Audits.** The API records three events:
   - `work_session.title_requested` `{ runtime, model, promptLength }`
   - `work_session.title_generated` `{ model, length }`
   - `work_session.title_failed` `{ reason, model }`

   None of them carries prompt or title text.

## Consequences

- Each new untitled session spends one small-model turn of the device owner's subscription. With thinking
  disabled, that is about 550 input tokens and a few output tokens (estimate: the 2.1.289 recording, made before
  thinking was turned off, also spent 3.7k thinking tokens in 31 s). A Codex turn took about 7 s at 0.160.0.
- One fixture per runtime is recorded at the pinned versions (`claude-code-2.1.289.title.sdk.jsonl`,
  `codex-0.160.0.title.rpc.jsonl`). A runtime upgrade re-records them before its inventory row stays exposed.
  Both were recorded under the earlier 3–6 word / 48-character instructions and were not re-recorded for the
  amendment: their raw answers now normalize to "Redirección de login al expirar" (31 characters, from
  "Redirección de login al expirar sesión") and "Fix settings page login redirect" (32, from "Fix settings page
  login redirect bug"). The cut can leave a trailing function word ("al expirar"); the instructions ask the model
  for 2–5 words, so a fresh answer should rarely need the cut.
- The API refuses a title it cannot validate. A title out of shape costs a turn and is shown nowhere (audited as
  `invalid_title`).
- On Codex, the owner's local hooks still run on the title thread. Their `hookPrompt` items are ignored, never
  treated as tools.
- ADR-0013 is unchanged: titles are not settings and do not use `session.configure`.
