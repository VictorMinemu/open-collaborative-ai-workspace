## Phase Goal

Admins and leads turn whole modules on or off for a department, team or person from Settings, as resolver deny rules,
so the UI hides what the API already refuses.

**This plan's slice (tracer, browser level):** the Settings panel. An admin turns Bots off for a team from that team's
Modules card and a team member's open tab loses the Bots entry live; then exceptions per person, inherited and
read-only states, the lead's view, Settings › Modules for the organization, the account entry, the phase gate.
API from 07.3-02, hiding from 07.3-03; planner decisions P-01 … P-12 in `07.3-01-PLAN.md` (P-06, P-07 here).

**UI contract (no UI-SPEC for this phase; this is the layout):**
- **Modules card** (`data-testid="module-access"`), placed after People and before Access rules in the unit detail, with
  the unit detail's section header style: title "Modules", description "Turn Work Zone, AI chats and bots on or off for
  everyone in {unit} and everything inside it. Off hides the module and the API refuses it." Body: one bordered list
  (`rounded-xl border bg-card shadow-xs`, `divide-y`), one row per catalog module in catalog order: the module's rail
  icon in a muted tile, label and the catalog description, and on the right a `Switch`
  (`data-testid="module-switch-<id>"`, `aria-label="<Label> for everyone in <scope>"`, checked = `on`).
  - `custom`: switch unchecked plus a "Custom" outline badge and the line "Part of this module is off by a manual rule.
    Turn it on to clear it."
  - `inherited`: switch disabled and unchecked, the line "Off for everyone in <name>" (or "Off for the whole
    organization"), and for viewers who can open that scope a "Change" link to it (unit: `/settings/organization?unit=<id>`;
    organization: `/settings/modules`).
  - Bots row when `unitBotCount > 0` and the switch is on: "<unit> has N bot(s). Turning Bots off also stops them for
    everyone, admins included." (amber text, `TriangleAlert` icon); the same sentence in the confirmation.
  - Pending PUT: the switch shows a spinner and stays disabled; errors through `toast.error(errorMessage(err))`; the
    view comes back from the PUT response.
- **Exceptions for people** (inside the same card, below the list): heading "Exceptions for people", description "Turn a
  module off for one person in {scope}." and an "Add person" button opening a dialog with a searchable list of the view's
  `people` whose modules are all on (pattern of `add-people-dialog.tsx`). Rows: avatar, name, chips "<Label> off" /
  "<Label> custom" / "<Label> off in <scope>" (inherited), and "Edit" opening a dialog "Modules for <name>" with the three
  switches. A person with `canEdit: false` shows the switches disabled and "Only an organization admin can change modules
  for an admin." Rows with every module on and no inherited state are not listed.
- **Overrides** (only when the view has any): "Turned off inside {scope}", rows "<unit> · AI chats off, Bots custom", each
  a link to that unit.
- **Settings › Modules** (`/settings/modules`, icon `Blocks`, page header "Modules", description "Turn modules on or off
  for the whole organization or for one person. Departments and teams: Settings › Organization."): the same panel at
  organization scope. Turning a module off for everyone asks first: dialog "Turn <Label> off for everyone?", "Everyone in
  the organization loses <Label> right away, admins included. Turning it back on restores it.", buttons "Turn off"
  (destructive) and "Cancel".
- **390:** each module row keeps the label and description on the left (description wraps) and the switch right-aligned
  with a 44 px hit area; chips wrap; dialogs use the existing full-width mobile dialog; no horizontal scroll.
