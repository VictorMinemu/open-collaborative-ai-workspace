# Phase 07.6 Plan 15: The automations UI tracer Summary

**Bots › Automations works in the browser at 1440 and 390, light and dark: a person creates a scheduled automation
(presets, IANA zone, the next three runs from the API across DST, channel, board column or DM targets with their
reasons), sees it in the list, runs it now and reads Done in its run history with an Open link to the run card; a
manager reads someone else's automation read-only and may only pause or delete it; and every server-composed card of
the phase now shows its own pill word and notices, including the automation proposal card's Proposed · Created ·
Created with changes · Discarded · Expired · Failed.**

## What was built

- **Route and nav.** `/bots/automations` (static, gated by the Bots module) with `PageHeader` + "New automation" and a
  `<nav aria-label="Bots sections">` of two links with `aria-current="page"` (ui/tabs underline look, `min-h-11`); one
  import and one mount line in `bots-gallery.tsx` (2 insertions).
- **List.** One bordered list; rows are a stretched open button (accessible name: name, status, schedule, last run) and
  a separate `⋯`; 5-column grid at ≥ 768 (fixed status column so rows align), stacked blocks at 390. Active = dot +
  word, Paused = muted pill, Needs attention = amber pill + "Paused after 3 failed runs.". Digest rows carry the Digest
  badge and open `/settings/digest`. Mine · Everyone (`?scope=all`) for `canManage`, Everyone sorted needs attention →
  person → name; usage line and the cap state. Loading skeletons, empty states (with and without create rights),
  `ServerUnreachable` "Couldn't load automations.". A just-created row is highlighted 2 s and takes focus once.
- **Editor sheet.** Settings · Runs; Basics (name, bot with `· your personal bot` / `· {unit}` / `· not ready`,
  instructions with the counter from 3200), When (`TriggerStep`: Schedule · Webhook · Mail radio cards, Webhook
  disabled with its reason without `automation.webhook`; `ScheduleBuilder`), Deliver to (`TargetPicker`), Runs as,
  Limits (runs per day ≤ the org cap, bot daily limit, breaker, workspace limits). Footer per mode (new / own / read-
  only), status banner (paused by / needs attention with the last reason; Resume for the owner only), the discard
  guard, form-level refusals with the UI-SPEC sentences, 409 `version` → "This automation changed while you were
  editing." + Reload, `?draft=` prefill with the brand-soft banner and `fromApprovalId` on save. Full screen at 390,
  footer stacked with the primary action first, 44 px controls.
- **Run history.** Newest first, 30 a page with "Show older runs", time in the automation's zone (browser time in the
  title), trigger word, Outside content badge (webhook, mail, tainted), result dot + word, reason sentence or "Answered
  in {duration}", Open to the anchor (`/chat/<conv>?thread=…&m=…` or the DM); `?run=` scrolls, focuses and rings the
  run until the first interaction.
- **Agent cards (R1, 8d, Surface 5).** Platform-owned: pill = `statusLabel` in the status's tone (`aria-label="Status:
  {label}"`), notices between title and fields (warning amber, neutral muted, `role="note"`), long values as block
  values, 44 px full-width actions at 390, the workspace badge. Non-platform cards ignore both fields (byte-for-byte test
  and the unchanged snapshots). `automation.create` cards: the six pills, the "{bot} proposed this. Nothing runs until
  {person} confirms." line while pending, Edit → · Create automation · Discard for the run-as person with the UI-SPEC
  confirmation copy, "Only {person} can confirm this automation." for everyone else, Created by / Discarded by lines,
  Open automation to `resultRoute`, failed reasons in words and "Ask {bot} again when it's fixed.".

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The contract refused the "Last day" preset.** `CronExpression` allowed letters only in
three-letter names, so `45 23 L * *` (UI-SPEC: Every month · Last day) could not be saved. A lone `L` field is now
accepted; cron-parser already read it; the API schedule test pins it. Commit `33dafe21`.

**2. [Rule 1 - Bug] A digest read "Mondays, Tuesdays, Wednesdays, Thursdays and Fridays at 8:00 AM".** `digestCron`
writes a day list; `scheduleSummary` now reads Monday-to-Friday as "Weekdays" and all seven days as "Every day" (the
run card and the list share it). Commit `4c145467`.

**3. [Rule 1 - Bug] A live refetch would have overwritten a concurrent change.** `useAutomationLive` refetches the open
automation; taking `expectedVersion` from it would have saved over someone else's edit. The editor keeps the version it
loaded (`baseVersion`), so the save answers 409 and shows the banner (e2e proves it).

**4. [Rule 1 - Bug] The new row took focus 400 ms after creation, closing a row menu opened meanwhile** (found by the
tracer). The row now focuses itself once, on its first render.

**5. [Rule 2 - a11y] Read-only editor body.** Every control is disabled for a manager, so axe flagged the scroll area
(`scrollable-region-focusable`); it becomes a named, focusable region only in read-only mode.

**6. [Rule 2] Every platform-owned card gets the workspace badge** (UI-SPEC 8 says all four server cards carry it; the
renderer showed it only with an approval or sign-in link).
