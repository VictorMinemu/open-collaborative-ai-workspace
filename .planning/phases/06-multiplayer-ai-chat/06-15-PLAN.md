## Phase Goal

**As a** member who holds a private AI chat, **I want to** share it in place with a colleague, a team, a department or the whole organization so that several of us and the model write in the same conversation — the model knowing who said what and answering one request at a time on the asker's own plan or model, nobody's private context leaking, and agents joining as full personas that post live cards — **so that** AI work in the workspace becomes multiplayer, attributable and safe.

**This plan's slice:** people see and use Agent Cards — one renderer everywhere, live in-place updates, follow and approve. P-decisions: `06-01-PLAN.md` (P-11, P-13).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent-authored card content → browser | Untrusted model output rendered to people |
| browser → follow/decision routes | Server decides; UI reflects `viewerCan` and `decision` |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-15-01 | Spoofing | phishing link from a card | high | mitigate | Open renders only `AgentCardRoute`-valid internal routes; unit test with an external target (Task 1) |
| T-06-15-02 | Tampering | markup/link injection through card text | medium | mitigate | Plain-text rendering of title, fields and summary; unit test (Task 1) |
| T-06-15-03 | Repudiation | accidental approvals | medium | mitigate | Confirmation dialog naming the card; decisions audited server-side (06-13) |
| T-06-15-04 | Elevation of privilege | UI offering actions the server would refuse | low | mitigate | Buttons from `viewerCan`/`decision`; the API enforces (06-13) |
