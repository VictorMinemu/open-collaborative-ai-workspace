# Phase 06.1: Work Zone image attachments - Context

**Gathered:** 2026-10-07 (owner request in conversation; no discuss-phase run)
**Status:** Ready for planning

<domain>
## Phase Boundary

Images only (PNG, JPEG, GIF, WebP) into a Work Zone prompt: paste (Ctrl/Cmd+V), drag-and-drop and the composer's
paperclip. The API forwards them to the session's device as `PromptPayload.images`; the Claude Code and Codex
adapters hand them to the runtime; the session stream shows them. Non-image files (PDF, text, archives) for Work
Zone prompts are **out of scope** (the runtime reads the repo itself).

Diagnosis that led here (2026-10-07): web composer has no paste handler and a deliberately disabled paperclip
(`apps/web/components/work-zone/composer.tsx` ~162); `CreatePromptRequest = { body }` only
(`packages/contracts/src/work-session.ts:112`); the device side already supports it (`PromptImage` /
`PromptPayload.images` in `packages/contracts/src/device-link.ts:205-213`, `claude-runtime.ts:191`,
`codex-runtime.ts:167`); inventory row "Composer: attachments | deferred"
(`packages/contracts/src/runtime-controls/workzone-ui.ts:128`, `docs/workzone/runtime-controls-inventory.md:143`).

</domain>

<decisions>
## Implementation Decisions

- **D-01: Reuse the Phase 4 attachment pipeline.** Same upload flow (presigned PUT to Garage, server-side sniffing,
  renditions), same `attachment.upload` permission, same limits where they apply. No second storage path. The API
  stays the only ACL (ADR-0015).
- **D-02: Contract.** `CreatePromptRequest` gains optional `attachmentIds` (small max, e.g. 4–8; planner sets it
  from the device-link budget). `body` may stay required (text + images), unless research shows an image-only
  prompt is natural for both runtimes — planner decides and records it. The stored `WorkPrompt` carries the
  attachment refs so the queue, the stream and history show them (contracts first, Zod).
- **D-03: Server checks.** Only attachments uploaded by the sender, in the same organization, unused or reusable per
  Phase 4 rules, sniffed as an allowed image type, within the per-image and per-prompt byte budget. Cross-tenant and
  other-user ids fail exactly like missing ones (no oracle). Tenant-isolation integration test required. The
  prompt's audit event records attachment ids and counts, never bytes.
- **D-04: Bytes to the device.** At dispatch the API reads the bytes from object storage (prefer the large rendition
  when it exists and the original is large; keep the original type when small) and sends base64 in
  `PromptPayload.images`. The planner must find the device-link max frame/message size and set the budget so a
  prompt with the max number of images always fits, with margin. Never log image bytes or base64.
- **D-05: Adapters.** Verify the existing Claude (`claude-runtime.ts:191`) and Codex (`codex-runtime.ts:167`) image
  mappings against the pinned runtime versions' input shapes (Claude Agent SDK image content blocks; codex
  app-server image input). Add adapter tests. If a runtime rejects images, the turn fails visibly with a clear
  reason — never silently dropped. Treat image content as untrusted input like any prompt.
- **D-06: UI.** Composer: paste, drop zone and enabled paperclip; removable thumbnails with upload progress and
  errors; send disabled while uploading. Stream: the prompt bubble shows its images (thumbnails, open full size)
  for every controller, including queued prompts in the queue panel. Matches the T3 Code layout (03.2 D-17) and the
  AI chat composer's attachment look. 1440 and 390, light and dark, screenshots reviewed.
- **D-07: Steer.** A steered (`delivery: "steer"`) prompt with images: allowed only if the Codex steer input accepts
  images; otherwise images force queue delivery — planner decides from research and records it.
- **D-08: Inventory.** Update the "Composer: attachments" row in `workzone-ui.ts` and
  `docs/workzone/runtime-controls-inventory.md` from deferred to shipped (images only) with evidence.

### Claude's Discretion
- Exact limits (count, bytes), whether renditions or originals go to the device, plan/wave split.

</decisions>
