# Phase 3.1 Plan 03: Capability model, org bot policy, governance and per-turn policy Summary

One capability model (contracts first) decides, for every bot, which built-ins (internet, memory, date/time, reply-all) and which MCP / plugin tools are effective and why not; owners and admins manage it through three routes; every delivered `agent.mention.v1` now carries the effective `turn` for that bot and that human, recorded in `agent_turns`, so a policy change bites on the next message before the cell reconciles.

## What was built

- **Contracts** (`packages/contracts/src/bot-capabilities.ts`, exported from the index): every name of the plan's interface block, unchanged. D-06 defaults (team `{internet:false, memory:false, dateTime:true, replyMode:"mentions", dailyLimit:100}`, personal same with `memory:true, dailyLimit:30`), default policy (allow everything, DuckDuckGo, 3, 100, `[]`). `DANGEROUS_TOOL_NAMES` (the 29 exact core names / groups) and `isDangerousToolName` (exact list, every `group:*`, `session(s)_*`, word patterns for shell/exec/spawn/process/terminal, browser/computer/canvas/screen, gateway/node/openclaw, outbound messaging, filesystem objects × mutating verbs, config × mutating verbs; never a `BUILTIN_TOOLS` name; `write_note` on a notes server is not dangerous). Header documents the mirrors in render-config and the plugin (parity test in 03.1-04).
- **Agent Channel (additive)**: `turn: TurnContext.optional()` on `AgentMentionEvent`, `CellAgent.capabilities` (default `{tools: []}`), `CellSnapshot.webSearch` (default DuckDuckGo), three new `cell.config.changed` reasons, `AgentChannelToolCallRequest/Decision/Result`, `AgentChannelMemorySave/Response`; header lists `POST /tool-calls`, `/tool-calls/:callId/result`, `/memories`.
- **Pure decision** (`capabilities.ts`): `readCapabilities` (stored jsonb over scope defaults, invalid values ignored), `effectiveCapabilities` (reasons `org_policy` → `personal_policy` → `not_configured` → `denied_for_you`; reply-all on a personal bot → `dm_only`), `effectiveTools` (`dangerous` → `source_unavailable` → `org_policy` → `personal_policy` → `denied_for_you`).
- **Routes** (module `bot-capabilities`, all `authz: user`):
  - `GET/PATCH /api/v1/agents/:id/capabilities`: `bot.read` hidden as 404 (personal bot of someone else, admins included), then `bot.configure` (403). The human side is the caller: `bot.internet` and `bot.tool.use` (tool layer per granted tool) decided as the bot acting for the caller. PATCH validates `limit_above_policy`, `dm_only`, `dangerous_tool`, `unknown_tool`; `tools` replaces the grant set; audit `agent.capabilities_updated` with `{scope, changed, granted?, revoked?}` (keys and tool names only); `cell.config.changed` reason `agent.capabilities_updated`.
  - `GET/PUT /api/v1/bot-policy` (`bot.manage`): defaults when no row; `searxng` refused with 400 `not_configured` unless bundled and `OCW_SEARXNG_URL` set; audit `bot_policy.updated` with dotted changed keys; `cell.config.changed` reason `policy.updated`.
  - `GET /api/v1/bot-governance` (`bot.manage`): personal bots only — name, username, avatar, owner, model, status, capabilities, today's usage; DTO built field by field, no instructions / DMs / memory.
- **Turn policy** (`turn-policy.ts`): `currentTurnTools` (web tools when internet is effective, `ocw_memory_save` only in a DM, then effective catalog tools; flags web `{untrusted, not side-effecting}`, memory `{trusted, side-effecting}`, MCP/plugins untrusted with side effects per the decision above), `turnPolicy` (adds `now` with the asking human's zone or UTC via `Intl.DateTimeFormat("en-GB", {dateStyle:"full", timeStyle:"short"})`, caps 8/5, inserts `agent_turns`, returns `{deliver:true, turn}`; named extension points for 03.1-05 metering and 03.1-07 memory), `cellAgentCapabilities` (per-agent `alsoAllow`, ignoring per-human rules).
- **Delivery**: `buildMentionEvents(tx, mention, {core, perms})` assigns the event id first, calls `turnPolicy` per target with the triggering human, attaches `turn`, skips the event when `deliver` is false. `GET /agent-channel/v1/cell` merges `capabilities.tools` per agent and `webSearch.provider` from the org policy.
