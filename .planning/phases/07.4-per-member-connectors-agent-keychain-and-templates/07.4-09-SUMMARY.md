# Phase 07.4 Plan 09: Connector and keychain tools in the OpenClaw cell Summary

**The real OpenClaw 2026.9.7 cell now runs three fixed plugin tools: `ocw_connector_list`, `ocw_connector_call` and
`ocw_http_request`. Each one posts only the turn's event and agent ids to the Agent Channel API and answers with the
API's content or one fixed sentence. The local gate checks each call with the logical tool's flags or the HTTP
method's. A 20 s connector call completes inside a real turn, and no member credential or per-member MCP server ever
reaches the cell.**

## Performance

- **Duration:** about 70 min (18:05 to 19:15 local). About 40 min of that was three `pnpm verify` runs and four
  real-cell smoke runs.
- **Tasks:** 3 of 3.
- **Files:** 3 created, 14 modified.

## Accomplishments

- **Tracer (Task 1).** `ocw_connector_call` works end to end: manifest `contracts.tools` → `registerFull` → gate
  pre-check → `POST /connectors/call` → result to the model. This was proven in the real image (research A1). The body
  is exactly `{eventId, agentId, connector, tool, arguments}`. The tool is self-validated, so it never goes through
  `/tool-calls`. The logical tool `m1a2b3c4d__whoami` is never offered to the model as a tool.
- **Task 2.**
  - `ocw_connector_list` renders connectors, their tools with argument schemas, and key handles as compact text.
  - `ocw_http_request` posts exactly `{eventId, agentId, handle, method, url, headers?, body?}`. Its output names a
    redirect by host and never follows it.
  - Every `AgentChannelToolRefusal` code maps to one fixed sentence. `not_connected` and `needs_reconnect` map to
    NOT_CONNECTED, and `member_account` maps to MEMBER_ACCOUNT. A canary in the API error body never reaches the model.
  - Gate flags:
    - `ocw_connector_call` takes the logical tool's flags (unknown flags count as the most dangerous case).
    - `ocw_http_request` treats GET and HEAD as reads and every other method as side-effecting.
    - `ocw_connector_list` is always allowed when offered.
  - A `member_account` withheld entry renders the UI contract's sentence with the R7 share link.
- **Task 3.** The fake API gained knobs (`slowMs`, `refusal`, `result`). The `connectors` smoke scenario now proves:
  - the slow call completes;
  - both refusal sentences arrive intact;
  - the share link reaches the model request for `#ops`;
  - list plus a GET by handle go through their own routes;
  - the cell holds no per-member MCP server and no member token.

  The full smoke stays green.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The gate's turn dropped the logical connector tools**
- **Found during:** Task 1, on the first real-cell run. The reply was "That connector tool is not available on this
  turn".
- **Issue:** `openclaw-port.ts` begins the gate's turn with `tools: turn.tools ∩ alsoAllow`. Per-member logical tools
  are never in alsoAllow (Pattern 4), so `m1a2b3c4d__whoami` was gone before the tool or the gate could check it.
- **Fix:** `mapMention` computes `connectorTools`: the turn's `<m+8hex>__<tool>` names that are not configured
  OpenClaw tools, and only when the run may use `ocw_connector_call`. The port passes them to `beginTurn`, and the gate
  and the tool check `ActiveTurn.connectorTools`. OpenClaw's `toolsAllow` is unchanged.
- **Files:** `mention-mapper.ts`, `openclaw-port.ts` (not in the plan's list), `tool-guard.ts`, `connector-tools.ts`.
- **Commit:** 5d07be26

**2. [Rule 3 - Blocking] Exact tool-list test outside the plan's file list**
- `openclaw-registration.test.ts` pins the exact tools that `registerFull` registers. It was updated to the new list
  (precedent: 07.4-01 deviation 2).
- **Commits:** 5d07be26, 1fa5ee7c

### Other deviations

- **Manifest per task.** Task 1 declared only `ocw_connector_call`; Task 2 added `ocw_connector_list` and
  `ocw_http_request`. This keeps manifest/registration parity (`plugin-contract.test.ts`) green at every commit. The
  plan put all three names in Task 1.
- **`logicalToolOf()` lives in `tool-guard.ts`,** not `connector-tools.ts`. The gate and the tool share it, and
  `connector-tools.ts` already imports `tool-guard.ts`, so this avoids an import cycle.
- **`testing/openclaw-host.ts` is unchanged.** Its `registerTool({name})` already supports the new declared names.
- **`ocw_connector_list` uses fixed local flags** `{untrustedOutput: false, sideEffecting: false}`, whatever the turn
  delivers. This matches the plan's "always allowed when offered" and research Pattern 4.
- **Fake API calls record `receivedAt` / `answeredAt`** beside the body, to measure the slow path. The smoke and the
  contract test exclude these two keys from the exact-keys check.
- **Smoke images use unique tags** (`ocw-openclaw:smoke-07409`, `ocw-fake-model:smoke-07409`,
  `ocw-mcp-sandbox:smoke-07409`), so the run never touched the demo's `:local` images.
- **The full smoke ran with `SMOKE_BUILD=1`.** The overlay mode (no rebuild) fails the marketplace scenario on this
  Docker Desktop host (see broken-windows candidate 1). The connectors scenario passed in both modes.
- **TDD commit shape:** there are no separate RED `test(...)` commits, because the brief requires `pnpm verify` green
  before every commit. RED was run and observed:
  - Task 1: the test file failed on the missing module, and the guard test failed (1 test);
  - Task 2: 16 failing tests across `connector-tools`, `tool-guard` and `mention-mapper`.

  Task 3 is `tdd="false"`.

## Broken-windows candidates

1. **The smoke's overlay mode fails the marketplace scenario on macOS Docker Desktop (low, pre-existing).** `docker cp`
   of `install-policy.mjs` keeps the host uid (501), so OpenClaw's install gate fails closed with "must be owned by
   the current user (uid=1000) or root". CI is not affected (`SMOKE_BUILD=1`). A fix would be a
   `docker exec -u 0 chown root:root` after the copy.
2. **07.4-11 must put the static names in the cell snapshot (medium).** `ocw_connector_list`, `ocw_connector_call` and
   `ocw_http_request` must be in `cellAgentCapabilities` (alsoAllow), and never the logical names. Otherwise OpenClaw
   cannot run them. The smoke supplies them through `FAKE_AGENT_TOOLS`.
3. **OpenClaw's tool-execution ceiling is unmeasured above 20 s (low).** The client budget is 35 s and the proxy plan is
   30 s. Only 20 s was proven, so a 30 s case could join the ADR-0025 upgrade checklist (07.4-14).
4. **Tool descriptions in `ocw_connector_list` do not taint the turn (low, by design).** They come from admin-registered
   servers and are capped at 300 characters per line by the plugin and 1024 by the contract. If 07.4-11 decides that
   descriptions are untrusted, it should flag the list as `untrustedOutput` server-side. The local gate would then need
   to read it from the turn rather than use fixed flags.
