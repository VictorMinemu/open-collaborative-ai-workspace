## Context

Hub: `07.17.1.1.1-01-PLAN.md` (plan map, PD-03 executor rules, PD-14, PD-15, A-06). This plan is the Python supply
chain: the lock the image installs (03), its license records, the license guard that keeps them honest, and the
package-legitimacy gate. It owns no Dockerfile line, so it runs beside 01.

<objective>
Resolve the toolkit's Python environment into a hash-pinned, wheels-only lock on the image's own interpreter, record
one SPDX license per pin, extend `pnpm guard` to check Python locks like the npm lockfiles, and stop for the owner's
approval of every pin before anything is installed (D-01, D-03, D-09).

Purpose: the same supply-chain bar as the browser image's package-lock (D-01), and the gate the legitimacy seam
requires for `SUS` packages.
Output: `requirements.in`, `requirements.lock`, `licenses.json`, `lock.sh`, the guard extension and its tests, the
approval checkpoint.
</objective>
