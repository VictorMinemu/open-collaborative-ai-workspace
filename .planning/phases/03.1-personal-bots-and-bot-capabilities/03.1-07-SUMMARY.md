# Phase 3.1 Plan 07: Persistent bot memory Summary

A bot now remembers what its human asks it to. The note is saved through the bot's own gated tool `ocw_memory_save`, and the API binds it to the human of the delivered turn. It comes back only in that human's DM turns. The human sees and clears it under "What <bot> remembers about you" in the DM header. Admins, other members, channel turns and other tenants never see it. Once web or tool output has entered a turn, the cell and the API both refuse to save.

## What was built

- **`memory.ts`**:
  - `saveMemory` loads the `agent_turns` row and refuses in this order:
    - `unknown_turn`: missing, another bot's, or another org's (hidden by RLS).
    - `dm_only`
    - `not_in_turn`
    - `memory_off`: re-decided with `currentTurnTools`.
    - `tainted` / `cap_reached`: one conditional UPDATE that also counts the call.
  - The owner is always `turn.user_id`. Saves for one owner are serialised with an advisory lock. Exact duplicates return `created:false`. Anything beyond 200 notes is pruned, oldest first.
  - `loadTurnMemory` returns the newest 50, oldest first. `listMemories` returns newest first. `clearMemories` deletes one note or all of them, scoped to the owner.
- **Turn injection**: `turnPolicy` sets `turn.memory` only when `conversationKind === "dm"` and memory is effective. This closes WINDOWS.md id 2, now marked `fixed`.
- **User routes**: GET and DELETE `/agents/:id/memories`, and DELETE `/agents/:id/memories/:memoryId`.
  - They always use `userId = caller`.
  - `bot.read` is checked with `hideAs404`, so an admin gets 404 on someone else's personal bot.
  - Audit `agent.memory_cleared {count, scope}`.
- **Cell route**: `POST /agent-channel/v1/memories` in the cell scope (`cell.sync`, `authz: cell`).
  - The body schema strips unknown fields, so `userId` / `ownerUserId` in the body are ignored.
  - Refusals map to 404 (`unknown_turn`) or 409 with the code. The refusal audit is committed before the error is thrown.
- **Plugin**:
  - `ocw_memory_save` is declared in the manifest under `contracts.tools` and registered from `registerFull` as a factory tool.
  - Its schema is `{text, maxLength 500}`, with a description that tells the model to save short, durable facts the user asked it to remember and never web or tool content.
  - It refuses locally when there is no turn, the tool is not offered, the turn is tainted, or the text is empty or over 500 characters.
  - It posts `{eventId, agentId, text}` and returns `Saved.` / `Already saved.` / a fixed `Not saved: …` line, never the API's error body.
  - Logs carry ids and status codes only.
  - The port passes `conversationId` to `beginTurn`.
  - The guard treats `ocw_memory_save` as side-effecting whatever flags the turn carries.
- **Smoke**: scenario `memory` (`FAKE_AGENT_TOOLS` now includes `ocw_memory_save`).
  - A DM turn offers only that tool and carries `memory: [likes green tea]`.
  - It asserts one `/memories` POST with the event id, the bot and `lives in Madrid`, with no `/tool-calls` request.
  - It asserts the reply contains `Tool ocw_memory_save said:` and the offered tool list includes it.
  - It asserts the captured model requests of that DM contain `likes green tea` and no request of another conversation does.
- **Web**:
  - `MemoryPanel` is a right sheet, full width on mobile. Each note shows its date and an always-visible delete button.
  - The panel has a short line on how notes are used, the empty state "Nothing yet. Ask <bot> to remember something.", the line "Only you can see this. Admins can't.", a note count and Clear all behind a confirmation dialog.
  - The DM header gets a Memory button (icon + label at ≥ 640 px, icon only below). It shows while memory is effective or any note exists. Agent replies refresh the list.
- **E2E**:
  - `FakeCellPlugin.simulateToolCalls`: `ocw_memory_save` posts to `/memories`; any other tool goes to `/tool-calls` and then reports a result.
  - Reply lines are `Tool X: allowed | saved | denied (<code>) | not offered`, and every reply ends with `[memory: N] [now: zone]`.
  - `bot-memory.spec.ts` covers saving, the panel, `[memory: 1]`, deleting one note, `[memory: 0]`, Clear all with confirmation, and admin GET → 404.
  - `bot-capabilities.spec.ts` now gets "Tool web_search: allowed" through the real gate, "Tool web_search: not offered" after the admin's denial, and asserts the literal "2 of 30" usage. That closes 03.1-06's open "tighten the usage assertion" note.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] Saves count against the turn's tool cap; new refusal `cap_reached`**
- **Issue:** Checking `row.tainted` with a plain read races a concurrent `/tool-calls` authorization on the same turn.
- **Fix:** One conditional UPDATE does the counting and the taint check, as `/tool-calls` does.
- **Files:** memory.ts, memories.ts. **Commit:** ba74c4c

**2. [Interface] `saveMemory(tx, core, perms, p)`**
- `perms` was added to re-decide `memory_off` through `currentTurnTools`.

**3. [Rule 2 - Security] `ocw_memory_save` always side-effecting in the guard**
- **Issue:** The guard trusted the delivered flags. A turn carrying `sideEffecting:false` for the memory tool would have let it run after untrusted output in the cell. The API would still refuse it.
- **Fix:** Forced in `tool-guard.ts`, with a test. **Commit:** c43becf

**4. [Rule 3 - Blocking] Files outside the plan's list**
- `openclaw-port.ts` (one field: `conversationId` for the guard's fallback lookup).
- `openclaw-sdk.d.ts` (the `registerTool` / tool-context types).
- `register-full.ts` (new, so `registerFull` is testable without the OpenClaw runtime; `index.ts` imports it).
- `testing/run-fake-api.ts` (doc line).
- `agent-channel.int.test.ts`: its exact fake-cell reply now carries the new suffix.

**5. [UX] DM privacy line ellipsizes instead of clipping** (dm-view.tsx, see Screenshots). **Commit:** 4a0c863
