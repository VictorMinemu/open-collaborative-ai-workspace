# Phase 07.13.1.1 Plan 08: Session owners end to end on a server and a desktop device Summary

One serial spec proves the phase on the real API, web, daemon and fake runtime, at 1440 and 390: Ana takes over Pia's session on a server, live for both; a session shared only with Ana warns and then leaves Pia's page and sidebar; a desktop device's session offers no Assign to me; people and the agent rename sessions; both naming rules are saved; the people view groups and filters. CI now keeps the `0713111-*` review screenshots. Nothing ran end to end locally (owner rule): typecheck and `--list` only.

## Accomplishments

- **Support (`e2e/support/work-zone-owners.ts`):** `startOwnerDevices(admin, run, { shareWith })` starts two fake daemons, one with `OCW_RUNTIME_HOST=service` and one with `desktop`. It waits until `GET /devices` reports each `hostKind` and shares both with each person (a device grant). `startSessionAs`, `sessionAs` (null on 404) and `waitIdle` cover the sessions.
- **Test 1 (tracer), "Ana takes over Pia's session on the shared server":**
  - Pia's `project` session; both pages first show Pia as owner (the chip's `aria-label` from 768 px, "Owner · …" below).
  - The dialog names the session, says Pia stays in its history and shows no warning. Confirm sends the POST (200).
  - Both headers move to Ana; Pia's without a reload. Both timelines carry "Ana Ferrer took over this session from Pia Romero". The API tells Pia `createdBy = Ana`.
  - A second session shared only with Ana: the dialog has exactly one warning, "Pia Romero will lose access to this session.". After Confirm, Pia's page shows `session-access-lost`, her sidebar row is gone and her `GET` answers 404.
- **Test 2, desktop refusal:** Ana's menu shows "Only sessions on a server can be assigned." and no Assign to me item. The API answers `GET …/assign` with `{ allowed: false, reason: "not_on_server" }` and the POST with 409. The owner stays Pia.
- **Test 3, renames:**
  - Ana types "Login redirect fix" (the counter reads 18/200) and saves. Pia's title follows live, and the API confirms it.
  - On an untitled session, Pia sends `session rename {"title":"Fix login redirect"}`. Both headers show the new title, the timeline has the `ocw_session_rename` tool card, and the answer says it was renamed.
  - On Ana's titled session, the same line answers "A person named this session, so their title stays." and the title stays (checked on the page and in the API).
- **Test 4, naming rules:** the admin saves "Start with the area, then the change" in Settings › Work Zone policy, and Ana, as lead, saves "Prefix with the module" in the project's Settings tab. Each is polled from the API, then read back after a reload. `afterAll` clears both (T-08-03).
- **Test 5, people view:**
  - Ana opens it from `sidebar-people` (from the drawer on phones). Groups: "You" first with 2 sessions, then Pia with 2. The three server rows carry the Server marker; the desktop row has none. The count reads "4 sessions".
  - Person = Pia gives "2 of 4". Adding Device = the laptop gives "1 of 4", with only the desktop session. Clear filters is pressed, then Project = the server's repository gives "3 of 4". Each filter is checked in the URL.
- **Per surface (header, assign dialog, rename dialog, both naming-rule sections, people view plain and filtered):** axe in light and dark (serious and critical fail), `unnamedControls` empty, no sideways scroll. On phones, `expectTouchTargets` runs on each surface, plus the header exceptions below.
- **Captures:** `0713111-{header-owner, assign-dialog, owner-changed, assign-warning, assign-reason, rename-dialog, policy-naming-rule, project-naming-rule, people, people-filtered}-{1440|390}` and each one's `-dark`.

## Deviations from Plan

1. **[Rule 2 - Correctness] `e2e/support/layout.ts` changed (not in files_modified).** `captureReview` was gated only by `OCW_E2E_SCREENSHOT_DIR`. `shot()` already checks the spec list. With the folder now set in CI for the whole run, every other spec's `captureReview` would have waited for toasts to clear (failing after 10 s), moved the pointer and switched themes. It now returns early unless `writesScreenshots(test.info().file, OCW_E2E_SCREENSHOT_SPECS)` is true. Local runs are unchanged: a run without spec filters still writes every spec's screenshots. The 7 tests in `screenshots.test.ts` still pass.
2. **One commit for the spec across Tasks 1 to 3.** It is one file whose tests share one `beforeAll` fixture, so the three tasks' test parts landed together, then the CI change and a format fix. The tracer gate (typecheck plus `--list`) was run on the full file before the CI task.
3. **Header touch targets:** see the key decision above (the chip's `::before` hit area; the actions button and the menu items are measured instead).
4. **Woodpecker retention:** the plan asks for 14 days. The dind host prunes `/home/ocw-ci/artifacts` after 7 days (`infra/ci/disk-budget.sh`, `-mtime +7`), which this plan does not own. The GitHub artifact keeps 14 days. On Woodpecker, copy the files into the phase's `screenshots/` folder within 7 days, or raise the prune in a CI plan.
5. **Extra captures** (owner-changed, assign-warning, assign-reason) beyond the seven listed; all match `0713111-*`.
