# Phase 07.17.1.1 Plan 10: Six Work Zone tools on the turn, the file limit, shared route helpers Summary

**Bots with an active Work Zone profile are now offered `ocw_work_session_upload` and `ocw_work_session_download` with the four session tools, all six or none, and their turn tells them the per-file limit (`workZone.files`, from `loadBotFileLimit`). The routes' claim, refusal and audit helpers moved unchanged to `agent-channel/work-session-calls.ts`.**

## Intended change (CLAUDE.md plan mode: permissions, audit)

- Who gets the Work Zone tools does not change (P5). The set grows from four to six behind the same all-or-none rule in `turn-policy.ts`, which already reserves `WORK_SESSION_TOOL_NAMES.length` slots. PR #71's behaviour stays: when the session tools are offered, `ocw_start_work_zone` and `ocw_work_zone_projects` are removed from that turn and room is counted without them; with no room the proposal tools stay.
- The offer gets one read-only field, `files`, computed the way the file routes compute it at call time.
- The helper extraction is a move. The three closures are byte-identical (checked with `diff` against `HEAD`'s bodies), and `readOnly` and `judgedConversationId` only gained `export`. No condition, order, audit field or answer of start, prompt, read or stop changed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in plan arithmetic] Slot case total length**
- **Found during:** Task 1
- **Issue:** The plan says that with `TURN_TOOLS_MAX - 5` tools besides the proposal tools the turn has `TURN_TOOLS_MAX - 1` tools. It actually has `(MAX - 5) + 2 = MAX - 3`. `MAX - 1` was carried over from the four-tool case, and it contradicts the plan's own "one fewer → all six" boundary.
- **Fix:** The test asserts `TURN_TOOLS_MAX - 3` for the full turn and `TURN_TOOLS_MAX` for the room turn. The boundary (`kept + 6 <= MAX`) is the one the plan describes.
- **Files modified:** `apps/api/src/modules/agent-channel/work-session-offer.int.test.ts`
- **Committed in:** `fc0872f4`

**2. [Rule 3 - Blocking] Tracer's "organization" source needs a server ceiling above 25 MiB**
- **Found during:** Task 1
- **Issue:** The test stack's default `OCW_ATTACHMENT_MAX_BYTES` is 25 MiB, which ties with the organization's default. `effectiveBotFileMaxBytes` names the server on a tie, but the plan expects `source: "organization"`.
- **Fix:** The offer suite starts its stack with `OCW_ATTACHMENT_MAX_BYTES = 100 MiB`. No product code changed.
- **Committed in:** `fc0872f4`

**3. [Rule 2 - Test coverage] Fake cell key test**
- **Found during:** Task 1
- **Issue:** The plan's verify runs `fake-cell-plugin.test.ts`, but no case covered the new keys.
- **Fix:** I added one case to `e2e/support/fake-cell-plugin.test.ts` (not in `files_modified`). It checks that upload and download post only their own keys, with strings trimmed.
- **Committed in:** `fc0872f4`, formatted in `7b99eb45`

The tracer test also resets the bot's `fileMaxBytes` to null in a `finally`, so later cases see the organization's limit again.
