The Work Zone shows whose session is whose, lets you take over a session on a shared server, and lets people and
the session's own agent rename sessions, following your organization's and your project's naming rules.

## What's new

- **Sessions by person.** A new Work Zone view (**Sessions by person**, at the foot of the Work Zone sidebar) lists
  every session you can see, grouped by its owner: you first, then everyone else by name. Each row shows the project,
  the device (with a **Server** marker), the last activity and the status. Filter by person, project and device.
  It shows only sessions you could already see; nothing new becomes visible.
- **The owner is on every session.** The session's header shows its owner (a line under the title on phones).
- **Assign to me on servers.** In a session's menu, **Assign to me…** makes a session yours when it runs on a shared
  server that you may use.
  - Before you confirm, the dialog says exactly what changes: who loses access, and which of their waiting prompts
    are cancelled.
  - A running turn is never cut. It finishes, and the next turns follow the new owner's limits.
  - The timeline records it ("Ana took over this session from Luis"), and the change is audited.
  - Sessions on someone's own computer, sessions a bot started and archived sessions cannot be assigned. The menu
    says why in one line, for example "Only sessions on a server can be assigned."
- **Rename a session.** **Rename…** in the session's menu, or in a row's menu in Sessions by person, sets the title.
  Everyone who has the session open sees the new title at once. A title you typed is never replaced by an automatic
  one.
- **The agent can rename its session.** Claude Code and Codex sessions get a rename tool. The agent can rename the
  session once per turn, when its purpose is clear or changes. It never asks you to approve the rename, and it never
  replaces a title a person typed. The timeline shows each rename.
- **Naming rules.** Admins write the organization's rule in **Settings › Work Zone policy › Session names**. Project
  leads write the project's rule in the project's **Settings** tab, under **Session names**. The project's rule is added
  after the organization's. Automatic titles follow them, and the agent sees them with its rename tool, so titles
  follow your company's and your project's conventions. Each rule can be up to 600 characters. Changes are audited,
  but the audit never contains the rule's text.

## Upgrade

In `/opt/ocw` (or wherever the server is installed), upgrade the server first:

```bash
sudo node scripts/ocw.mjs upgrade --check   # current and newest release; changes nothing
sudo node scripts/ocw.mjs upgrade           # backup, this release, new keys, rebuild; never goes backwards
```

- **One migration**, additive (`session_owners_rename`: the two naming-rule settings and a per-turn rename mark).
  Nothing changes until someone assigns, renames or writes a rule. Sessions run exactly as before.
- **Headless Work Zone servers update their runtime to 0.5.3** with one click (Settings › Devices › the server ›
  Runtime updates › **Update**), or by themselves at the *Automatic* level. The switch waits until no turn runs. The
  agent's rename tool comes with this runtime.
- **The desktop app updates itself from v0.5.2**, its runtime included, at your organization's level (Automatic,
  Notify only or Off), and never in the middle of a turn. A computer still on v0.5.1 or older installs v0.5.3 by hand
  once, as described in the [v0.5.2 notes](v0.5.2.md#upgrade).

## Known limits

- **Assign to me works only on devices that report themselves as a server** (`service`: a headless runtime installed
  as a service). The desktop app always reports a computer. The device's owner sets this label, so it is a product
  rule, not a security boundary; every takeover is audited with the device's label and its owner.
- **You can take a session only for yourself.** Assigning a session to someone else, and bulk reassignment by an
  admin, are not available yet.
- **The previous owner is not added back.** If the session is visible only to its owner, or to listed people who do
  not include them, the previous owner loses access, unless the server is theirs. The dialog warns about this first.
- **Titles stay 2 to 5 words and 32 characters.** A naming rule can shape the wording, but not that shape. A rule like
  "Title Case, prefix #TICKET" cannot be followed in full.
- **A Codex session sees a new rule at its next start.** Claude Code sessions pick it up at their next turn, and
  automatic titles in the next new session.
- **A runtime older than 0.5.3 has no rename tool.** Its sessions start and get automatic titles as before, without
  the naming rules.
- **Naming rules are per organization and per project**, not per team yet.
