# Phase 07.18 Plan 18: Account pool gap closure Summary

Turning every ChatGPT bot account off no longer signs the cell out (the API names the withheld subscription in `accountPool.withheldByPool` and the plugin keeps its profiles), and a Disconnect on Settings › Models now removes the pool's ChatGPT bot rows in the same transaction, audited with reason `provider_disconnected`.

## Gap 1: every ChatGPT bot account off logged every profile out

- **What broke:** with the pool managing ChatGPT and no bot account enabled, `GET /agent-channel/v1/cell` leaves `openai-codex` out of `subscriptions` (07.18-07, on purpose). The plugin's `sync` read "not listed, credential stored" as "disconnected while offline" and logged out every profile, so turning one account back on needed a new sign-in.
- **Fix:** the cell route names a connected subscription the pool withholds in `accountPool.withheldByPool` (contract in `packages/contracts/src/agent-channel.ts` and the plugin's mirror). `sync` skips the offline-disconnect logout for a withheld provider. A provider that is neither listed nor withheld (provider row deleted, no pool rows) is still signed out, as before. Bots still never use ChatGPT while every account is off: the provider stays out of `subscriptions` and out of the ready set.
- **Tests:**
  - `subscription-auth.test.ts`: all accounts off (withheld) twice → no logout, both profiles kept, not ready; one back on → ready at once, no login, no logout; then a real disconnect with a pool → every profile signed out.
  - `plugin-contract.test.ts`: `withheldByPool` parses to equal values in both copies; absent stays absent; an unknown provider or too many entries are refused by both.
  - `cell-pool.int.test.ts`: the snapshot carries `withheldByPool: ["openai-codex"]` when the only bot account is disabled or removed, none when enabled, none after `DELETE /api/v1/model-providers/openai-codex`.
- **Commit:** `38de9162`

## Gap 2: Disconnect on Settings › Models left the pool's ChatGPT bot rows "Ready"

- **What broke:** `DELETE /api/v1/model-providers/:provider` deleted the provider row and revoked every profile in the cell but left the live `cell_profile` rows. With the provider gone no credential state report could reconcile them, so Settings › Account pool kept showing them as Ready.
- **Fix:** the route, in the same transaction, calls the new `removeCellProfiles(tx, core.audit, POOL_OF_SUBSCRIPTION[provider])` (account-pool module): every live `cell_profile` row of that pool gets `removed_at`, one `account_pool.account_removed` each with `{ provider, kind, origin, label, reason: "provider_disconnected" }` (no token, no profile id). The `openai-codex → chatgpt` mapping now lives once in the agent module (`POOL_OF_SUBSCRIPTION`), used by the cell pool and the route.
- **Tests (`cell-pool.int.test.ts`, real PostgreSQL + Redis):** an enabled and a disabled bot account are removed and audited once each; an already removed row keeps its old `removed_at` and gets no second audit; a Claude token and a ChatGPT device slot stay live; Settings › Account pool lists only the slot; the cell gets an empty ChatGPT pool with nothing withheld; another organization's bot account stays live and has no audit row (tenant isolation). A provider that is not connected is a 404 and removes nothing.
- **Commit:** `30b6db1f`
