<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model (possibly prompt-injected) → `ocw_memory_save` | The model decides when to save |
| cell → `/agent-channel/v1/memories` | Cell token holder writes memory |
| browser → memory routes | Humans read and clear their notes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.1-07-01 | Information disclosure | memory read by others (admins, other members, other tenants) | high | mitigate | Routes always scoped to the caller; `bot.read` with `personal_bot` precondition; cross-tenant RLS; tests |
| T-03.1-07-02 | Tampering | memory poisoning via web/tool content | high | mitigate | Taint rule in the plugin and the API (`tainted`), DM-only, user-visible list with delete |
| T-03.1-07-03 | Spoofing | model choosing whose memory to write | high | mitigate | Owner derived from `agent_turns.user_id` of the stored delivery; extra fields ignored; test |
| T-03.1-07-04 | Information disclosure | memory leaking into channel turns | high | mitigate | Injected only when `conversation_kind = dm`; save refused outside DMs; tests |
| T-03.1-07-05 | Information disclosure | memory text in audit/logs | medium | mitigate | Audits carry counts and lengths only; plugin logs no text |
| T-03.1-07-06 | Denial of service | unbounded memory growth | low | mitigate | 500-char check constraint, 200 per (bot, human) with pruning, 50 per turn |
</threat_model>
