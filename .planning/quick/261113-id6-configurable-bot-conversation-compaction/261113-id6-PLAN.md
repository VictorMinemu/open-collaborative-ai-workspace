# Configurable bot conversation compaction, and recovery when it fails

## Problem (owner UAT, production logs, OpenClaw 2026.9.7)

A bot's long DM (gpt-6-astra, ~128 tools per turn, ERP MCP results) answers every message with "⚠️ Context is too
large and auto-compaction could not recover this turn…". Gateway log, every attempt:

```
[context-pressure-diagnostic] … route=compact_only estimatedPromptTokens=257712 promptBudgetBeforeReserve=252000
[compaction-safeguard] Compaction safeguard: required quality facts exceed finalized artifact budget; requiredChars>16000 identifierCount=12
[compaction-diag] end … trigger=budget provider=openai/gpt-6-astra attempt=1 maxAttempts=1 outcome=failed reason=guard_blocked
```

Research in the image (`ocw-openclaw:local`):
- `applyCompactionDefaults` sets `mode: "safeguard"` when unset (`validation-core-*.mjs:542-559`).
- The safeguard **quality guard defaults ON in code**: `qualityGuardCfg?.enabled ?? true` (`builtin-openclaw-*.mjs:17249`),
  although the schema comment says "Default: false". With `identifierPolicy: "strict"` (default), the required facts
  (headings, latest ask, identifiers) exceed the summary budget, `qualityRetentionInfeasible` → `guard_blocked`, never
  retried, so the session is stuck forever.
- `mode: "default"` would also skip the guard but summarizes the whole transcript in one call (can overflow itself);
  keep safeguard (chunked) and turn the guard off.
- The failure reaches the plugin only as reply text (no structured error): prefix `⚠️ Context is too large and
  auto-compaction` (also `⚠️ Auto-compaction could not recover this turn`). It happens before the model runs.
- A fresh session can be made by deleting the session entry: `deleteSessionEntry({ sessionKey, agentId?, storePath?,
  env?, archiveTranscript?, expectedSessionId?, expectedUpdatedAt? }): Promise<boolean>` from
  `openclaw/plugin-sdk/session-store-runtime` (`session-store-runtime-*.mjs:342`), or by rotating our session key.

The owner asked: "que sea todo configurable" (admin-configurable).

## Fix

### A. Organization setting (Settings › Bots, the bot policy), contracts first
Add `conversations` to `BotPolicy` (`packages/contracts/src/bot-capabilities.ts`, like `tasks` with
`BotTaskPolicyLimits`), merged per field by `UpdateBotPolicyRequest`, defaults in `DEFAULT_BOT_POLICY`:

| field | type / bounds | default | maps to OpenClaw |
| --- | --- | --- | --- |
| `strictSummaries` | boolean | `false` | `agents.defaults.compaction.qualityGuard.enabled` |
| `keepIdentifiers` | boolean | `false` | `compaction.identifierPolicy` `"strict"` / `"off"` |
| `keepRecentTokens` | int 2 000 – 100 000 | 20 000 | `compaction.keepRecentTokens` |
| `freshSessionOnFailure` | boolean | `true` | our bridge's recovery (B) |

Verify each OpenClaw key name and accepted values in the image's zod schema (`/app/dist/zod-schema-*.mjs`) with a
throwaway `docker run --rm --entrypoint sh ocw-openclaw:local -c '…'` before using it; drop a field whose key does not
exist and say so in the summary.

- DB: columns on `bot_policies` (`packages/db/src/schema/app.ts:676`) with defaults and CHECK bounds, additive
  migration via the repo's drizzle workflow; add its name to `HEAD_ONLY` in `apps/api/src/upgrade.int.test.ts`.
- API: GET/PUT `/api/v1/bot-policy` read/write it (same authz as the rest of the bot policy; audit as the existing
  policy update does). The cell snapshot (`apps/api/src/modules/agent-channel/index.ts` ~439, where `webSearch` is
  set) gains `conversations: { strictSummaries, keepIdentifiers, keepRecentTokens, freshSessionOnFailure }`, additive
  and optional in `CellSnapshot` (`apps/openclaw-channel/src/agent-channel-protocol.ts:1831`).
- Web: a "Conversations" section in `apps/web/components/settings/bot-policy-settings.tsx`, in the Long tasks
  section's style: "Strict summaries" switch (hint: "Refuses a summary that drops required facts. A long conversation
  can then get stuck."), "Keep exact identifiers in summaries" switch, "Recent history kept" number (tokens), "Start a
  fresh session when a summary fails" switch (hint: "The bot keeps the recent messages of the chat."). Mobile verified
  layout like the Long tasks fields. Tests in `bot-policy-settings.test.tsx`.

### B. Plugin: apply the setting and recover
- `infra/openclaw/render-config.mjs` boot defaults: `compaction: { mode: "safeguard", qualityGuard: { enabled: false },
  identifierPolicy: "off", memoryFlush: { enabled: false } }` (pin, so a cell without a snapshot yet is safe).
- `apps/openclaw-channel/src/reconciler.ts`: from `cell.conversations` (absent = the defaults above), own and write
  `agents.defaults.compaction.{qualityGuard.enabled, identifierPolicy, keepRecentTokens}` (keep `mode: "safeguard"`
  and `memoryFlush.enabled: false`), with the same change detection as the other owned keys (no rewrite when equal).
- `apps/openclaw-channel/src/openclaw-port.ts` / `bridge.ts`: when a turn's reply text starts with the compaction
  failure prefix(es) and `freshSessionOnFailure` is on: do not deliver that text; delete that session's entry
  (`deleteSessionEntry`, `archiveTranscript: true`, scoped to the turn's agent and session key) and dispatch the same
  turn once more (the chat window is already in the turn's structured context). Only once per turn; if the retry
  fails again, deliver one clear text: "This conversation got too long for me to summarize, so I started over with
  only its recent messages, and that failed too. Try again in a new thread." Log at info with the session key (no
  content). Off → deliver OpenClaw's text unchanged. The retry must keep the inbound dedupe id rules (`inboundMessageId`
  = eventId or `eventId:attempt`, see bridge.ts retry loop) so the second dispatch is not dropped as a duplicate.
- Plugin tests with fakes (no real OpenClaw): recovery once, no double recovery, off = text passthrough, reconciler
  writes/doesn't rewrite.
