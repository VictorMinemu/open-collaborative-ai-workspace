# Phase 07.7 Plan 02: Agent chain ledger, loop guards and ADR-0027 Summary

**Agent-to-agent ledger in PostgreSQL: `agent_chains` / `agent_chain_hops` under FORCE RLS with every loop guard (target
once, not root, not self, depth 1..2, one pending per source, idempotency, budget) as a named constraint that holds
under racing writers, chain columns on `agent_turns`, the ids-only `app.expired_agent_chain_hops`, the `consult.tick`
queue, the Bots-off `agent.message` backfill, ADR-0027 (Proposed) and the PRD §80 v1 paragraph.**

## Working notes: intended DDL (plan mode, P-19)

Written before the migration was generated; executed as written plus the two additive guards marked (+).

- `app.agent_chains`: id, organization_id, conversation_id, thread_root_id, root_event_id (unique
  `agent_chains_root_event_uq`), root_agent_id, human_user_id, status (active|completed|cancelled), hop_budget 3,
  hops_used 0, cancel_reason (user|auto), cancelled_by_user_id, closed_at, created_at, updated_at.
  FKs `agent_chains_conversation_fk` (org, conversation) and `agent_chains_root_agent_fk` (org, root agent), cascade;
  unique `agent_chains_org_id_root_uq` (org, id, root_agent_id); checks status, cancel_reason, `agent_chains_budget_check`;
  index (org, conversation, thread_root).
- `app.agent_chain_hops`: id, organization_id, chain_id, root_agent_id, parent_hop_id, source/target agent, depth, mode
  (consult|handoff), status (pending|answered|failed|timed_out|cancelled|refused), refusal_reason (≤ 64),
  source_event_id, target_event_id, question_message_id (FK messages cascade, unique), answer_message_id,
  idempotency_key (1..200), deadline_at, closed_at, timestamps. `agent_chain_hops_chain_fk` (org, chain, root) →
  agent_chains; source/target FKs (org, agent) → agents; `_target_once`, `_not_self`, `_not_root`, `_depth_check`,
  `_parent_depth_check`, `_one_pending` (partial unique where pending), `_idempotency`; index (deadline_at) where
  pending; index (answer_message_id) where not null. (+) `agent_chain_hops_parent_fk` made composite with
  `agent_chain_hops_parent_key_uq`; (+) `agent_chain_hops_source_depth_check`.
- `app.agent_turns` += chain_id, chain_depth smallint not null default 0 (`agent_turns_chain_depth_check` 0..2),
  answering_hop_id, returning_hop_id, reply_message_id (plain uuids, no FK).
- post-migrate: `app.expired_agent_chain_hops(integer, timestamptz)` in the `stale_automation_runs` shape.
- Data-only: authorless `agent.message` deny row next to every complete 9-pattern Bots-off set.

## Accomplishments

- The two ledger tables exist under the generic FORCE RLS + `tenant_isolation`; the RLS enumerator seeds one chain and
  one hop per organization, and a 07.7 section proves cross-tenant select/update/delete/insert/move fail and that the
  composite keys refuse another organization's conversation, agent and chain from inside a tenant.
- Every guard is enforced by PostgreSQL and asserted by constraint name; two clients racing the last budget slot get
  exactly one row (final `hops_used` = 3); racing same-target and second-pending inserts give exactly one row and one
  23505 on the named index.
- `app.expired_agent_chain_hops` returns `(id, organization_id)` of pending hops past their deadline across
  organizations, deadline order, limit clamped 1..1000, executable by `ocw_app` only.
- `consult.tick` is in the migrator's catalog and the API's `JOB_QUEUES` / `TickQueue` (compile-time equality kept);
  an upgraded N-1 database gets the queue. No worker or schedule (07.7-09).
- The Bots-off backfill completes 9 → 10 for Max and org A's everyone (rows 20 → 22), leaves Bea's custom set
  untouched, is idempotent with the two earlier backfills, and writes no allow or authored row.
- ADR-0027 (Status: Proposed) records D-01 … D-04 and D-06 … D-16 with defaults and v1 limits; PRD §80 gains the
  "v1 (Phase 07.7, ADR-0027)" paragraph mapping `can_message` / `cannot_message` to `agent.message` rules.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing guard] Parent hop must be in the same chain and targeted the child's source**
- **Found during:** Task 1
- **Issue:** the planned `parent_hop_id → agent_chain_hops (id)` let a depth-2 hop name a parent in another chain or one
  whose target is not the asking bot, so depth could be forged around the constraint set.
- **Fix:** `agent_chain_hops_parent_fk` is composite (organization_id, chain_id, parent_hop_id, source_agent_id) →
  (organization_id, chain_id, id, target_agent_id) via `agent_chain_hops_parent_key_uq`; plus
  `agent_chain_hops_source_depth_check` (depth 1 ⇔ source is the root). Same constraint name; both pinned by tests.
- **Files modified:** packages/db/src/schema/app.ts, the agent_chains migration
- **Commit:** see Task 1

**2. [Rule 3 - Blocking] drizzle-kit snapshot branch conflict**
- **Found during:** Task 1
- **Issue:** 07.6 left two snapshot leaves (`watched_write_lease` and `automation_events_full_message`); drizzle-kit
  refused to generate ("non-commutative migrations") and, with `--ignore-conflicts`, its merge re-emitted
  `ALTER TABLE watched_records ADD COLUMN write_lease_until`.
- **Fix:** generated with `--ignore-conflicts` (the new snapshot's prevIds are both leaves, so later generates are
  clean, as the backfill's was), removed the duplicate statement by hand and documented it in the migration header.
- **Commit:** see Task 1

**3. [Rule 3 - Blocking] Typed literal of an agent_turns row**
- **Found during:** Task 1 (`pnpm typecheck`)
- **Issue:** `connectors-turn.int.test.ts` builds a full `agent_turns` row literal; the new columns made it incomplete.
- **Fix:** added the five chain fields from the selected row.
- **Commit:** see Task 1

**4. [Plan scope] `agent.message` denial asserted on rows, not through the resolver**
- **Found during:** Task 2
- **Issue:** the grain `agent.message` is added by 07.7-01 (contracts, parallel branch); on this branch it is not a
  `Permission`, so `decide(..., "agent.message")` does not typecheck and the Bots catalog still has 9 patterns.
- **Fix:** the upgrade case asserts the exact `agent.message` deny rows (org A everyone and Max, authorless, no tool,
  no folder; none for Bea), the 22-row count and idempotency; `moduleStateOf` keeps asserting `off` / `custom`, which
  becomes the 10-pattern check once 07.7-01 merges. No contracts file was touched.
