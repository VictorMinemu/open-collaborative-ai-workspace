# Phase 07.17.1.1 Plan 04: The daemon's file commands and the bounded diff frame Summary

**The daemon moves one realpath-contained, O_NOFOLLOW-checked regular file per command over HTTP with its own device JWT (PUT on read, lazily GET-then-verify-then-link on write, idle sessions only), and no diff.result frame can exceed the API's 256 KiB inbound limit any more.**

## Accomplishments

- `session-files.ts`: the only place a moved file's absolute path exists. `resolveSessionPath` parses `WorkSessionFilePath`,
  refuses the shared deny list on the requested path and again on the path relative to the realpath of the session's
  cwd, requires the parent's realpath to be the root or under it, and creates missing folders one `lstat`-checked
  segment at a time (never below a link). `openSessionFileForRead` takes regular files only (`lstat`, then `open` with
  `O_RDONLY | O_NOFOLLOW | O_NONBLOCK`, then `fstat`), `too_large: <size>` before any byte moves. `writeSessionFile`
  checks the target (`not_a_file`, `exists`) and free space (`no_space`) before reading the body, writes a `wx` 0o644 temp
  file, counts and hashes (`mismatch`), lands with `link` (atomic `exists`) or `rename` (overwrite), and always removes the
  temp file.
- `daemon.ts`: `toRuntimeFileUrl(serverUrl, commandId)` (path prefix kept, ids checked, never a payload value);
  `session.file.read` outside session order and the runtime gate; `session.file.write` in session order and refused
  `busy` while a turn runs (tracked from forwarded events, forgotten when the session leaves); one `transfer()` helper
  with the device JWT, `transferDeadlineMs`, redirects refused, 401 refresh once, 503 retried after 1 s and 3 s, 410
  `expired`, 413 `too_large`, else `transfer_failed`. Acks are `sessionFileAckError` codes (sanitised with the roots);
  the log line carries the command id and the code only.
- `diff-frame.ts` `boundDiffFrame`: the patch is cut at the last newline that fits (escapes and UTF-8 counted), then the
  file list's longest fitting prefix, `truncated: true`; applied in `sendDiff` after sanitising. `app.ts` takes its
  websocket `maxPayload` from `DEVICE_LINK_MAX_DEVICE_FRAME_BYTES`.
- `tool-policy.ts` `isSecretPath` uses `isSecretBasename` from `@ocw/contracts`; its home-folder list, its template early
  return and `commandTouchesSecrets` are unchanged.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing critical] Transfer ids validated; redirects refused**
- **Found during:** Task 1
- **Issue:** The command id comes from the server. Put raw into a URL path (`..` is normalised away by `URL`) or a temp
  file name, it could move either one. And a `fetch` that follows redirects would let a response send the daemon's JWT
  and bytes to a URL the daemon never built (P3).
- **Fix:** `toRuntimeFileUrl` and `writeSessionFile` accept only `[A-Za-z0-9_-]{1,128}`; the fetch uses `redirect: "error"`.
- **Files modified:** apps/local-runtime/src/daemon.ts, apps/local-runtime/src/session-files.ts
- **Verification:** the `toRuntimeFileUrl` unit case (`../devices/token` throws), the `writeSessionFile` "transfer id that is not an id" case
- **Committed in:** 655c846d, 019e0ec3

**2. [Rule 2 - Missing critical] O_NONBLOCK on the read open; ENOSPC → no_space; exclusive-copy fallback**
- **Found during:** Tasks 1 and 2
- **Issue:** A FIFO swapped in between the `lstat` and the `open` would block the daemon. A disk filling during the write
  needs `no_space`, not `transfer_failed`. File systems without hard links would always fail the no-overwrite landing.
- **Fix:** `O_NONBLOCK` (no effect on regular files) plus an `fstat` re-check; ENOSPC mapped to `no_space`;
  `copyFile(COPYFILE_EXCL)` when `link` is unsupported, still `exists` on EEXIST.
- **Files modified:** apps/local-runtime/src/session-files.ts
- **Verification:** the FIFO case; the rest of the write suite is unchanged
- **Committed in:** 655c846d, 019e0ec3

**3. [Rule 1 - Bug] `isSecretPath` kept its exact order**
- **Found during:** Task 3
- **Issue:** Removing `ENV_TEMPLATE_ALLOW` broke `secretDenyReason`'s Glob/Grep pattern check (ReferenceError). Dropping
  the template early return would also have changed `isSecretPath` (a template inside a secret home folder went from
  allowed to refused).
- **Fix:** A local `ENV_TEMPLATE_ALLOW` stays, for the pattern check and the early return. The secret base-name list
  itself comes only from `isSecretBasename`. Behaviour is exactly as before.
- **Files modified:** apps/local-runtime/src/claude/tool-policy.ts
- **Verification:** claude-runtime.test.ts: all existing tool-policy cases pass, plus the new parity case
- **Committed in:** 9cdb10bf

**4. [Rule 2 - Missing critical] A running / waiting_approval state also counts as a running turn**
- **Found during:** Task 2
- **Issue:** The plan only named `prompt.started` as a turn's start. A session reported `waiting_approval` (or `running`)
  is mid-turn too, and a write then would be a second writer (principle 4).
- **Fix:** `trackTurn` adds on those two states and removes on any other state or on `prompt.completed`.
- **Files modified:** apps/local-runtime/src/daemon.ts
- **Verification:** daemon.test.ts "a session.state that is not running or waiting_approval also ends the turn"
- **Committed in:** 019e0ec3
