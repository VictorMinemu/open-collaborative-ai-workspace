## The real cell (OpenClaw 2026.9.7)

Scenario `approval` (new):

- An unruled `echo` and a `write_note` with an "Always ask" rule in one DM turn. The `echo` body has no `arguments` key
  and not its sentinel; `write_note`'s `arguments` equal the directive's object; the reply says it needs approval; the
  fake MCP executed only `echo` (`*-mcp-call.json` capture added to the fake).
- A card action carrying the grant: the model's re-run posts the same arguments (key order differs from the canonical),
  the fake MCP receives exactly them, the reply is `noted: Globex invoice`, and the captured model request carries
  "Approved by Sam Lee. Call m5e0c0de1__write_note once with exactly these arguments".
- **#219, connector grant:** a flagged `m1a2b3c4d__whoami` waits for approval through `ocw_connector_call`; the grant's
  re-run calls `ocw_connector_call` once with exactly the approved arguments and gets the result. With the fake model the
  call follows the directive, so this proves the plumbing, not a real model's reading of the block.
- **#209, the pin:** the cell logs `tool gate registered (… gate priority 10000, params pin priority -10000)` in the
  full, discovery and tool-discovery registries. A probe runs OpenClaw's own `createHookRunner` with our real gate and
  pin plus rewriting plugins at 5000, 0 and −9999: `PIN_HOLDS`. Recorded residuals: `BELOW_PIN_WINS=true` (a plugin
  below −10000) and `NATIVE_APPROVAL_FREEZES_PARAMS=true` (a plugin answering `requireApproval` first). Source read:
  handlers run highest priority first, each gets its own copy of the event, the last returned `params` win and are
  merged shallowly over the original params. ADR-0026 records it; the OpenClaw upgrade checklist re-runs the probe.

Scenario `work_zone` (new, #214): both tools are in the bot's `alsoAllow`; the model lists projects and proposes; the
bodies are `agentId,eventId` and `agentId,deviceId,eventId,projectId,prompt` (no mode, model, full access or user); the
success sentence comes back; after `web_search` in the same turn the proposal is refused in the cell ("after reading
outside content") and nothing is posted.

## Deviations from Plan

### Full-gate failures fixed at their source (P-13)

1. **[Rule 1] Permalink centring undone (search.spec, desktop).** The new size observer followed the bottom before the
   scroll event of a programmatic scroll-up arrived. `following()` now treats a list higher than where it was last seen
   (and not just clamped by shrinking content) as having left the bottom. `7b6a9f49`.
2. **[Rule 1] Fixture name collision.** 07.5's e2e support registered its org MCP server as "Acme CRM", the name 07.4's
   `connect-card`, `connectors` and `mcp-servers` specs use for a per-member connector. In a full run connect-card found
   the wrong server (grant 400) and approval-policies matched "Acme CRM 1440" (strict mode). Renamed to "Northwind CRM".
   `7e3879da`. Screenshots regenerated.
3. **[Rule 2, a11y] Blocked tool rows on the bot page (agent-memory, 390).** The whole row was dimmed to 75 %, putting
   the effect badge and description at 3.25:1. It only showed once an org MCP server existed when the mobile project
   ran — 07.5's fixture server made it visible. The name alone reads muted now. RED confirmed by reverting. `2f380170`.
4. **[Rule 3] Keychain journey hang (connectors-journey, desktop).** A response body still arriving when `page.goto`
   tore the chat document down never finished, so the final `Promise.all(bodies)` waited 180 s (trace: all actions done,
   then nothing). The chat bodies are now read before navigating; every body is still checked. 3/3 repeats green.
   `c6e9826c`.
