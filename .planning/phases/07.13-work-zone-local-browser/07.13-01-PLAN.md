## Phase Goal

A Work Zone session (Claude Code through the Agent SDK, Codex through `codex app-server`) drives a browser the Local
Runtime runs on the session's own device, so it reaches the device's `localhost`; the session's audience watches it live;
the asker can take control to sign in, and that sign-in is sealed per member × site and reused only in that member's
own turns. Teams get it by upgrading (ROADMAP Phase 07.13; WZB-01 … WZB-11; CONTEXT D-01 … D-35).

**This plan's slice (tracer, contract tier) and the phase hub.** The vocabulary every later plan uses, in
`packages/contracts`, and the requirement rows. Below: requirement ids, plan map, shared files, cross-plan names,
planner decisions PD-01 … PD-29, prohibitions, flagged assumptions and source coverage. Every later 07.13 plan cites this
hub by section name.

## Phase requirements (written into REQUIREMENTS.md by Task 3)

- **WZB-01** Claude Code and Codex sessions on a desktop or headless device open pages (the device's `localhost`
  included), read a redacted snapshot, act (click, type, select, press, scroll), wait, close and screenshot when the
  model accepts images, through one tool set (`ocw_browser_*`) normalized at the adapter edge.
- **WZB-02** Off unless org `allowBrowser` ∩ the device's local opt-in ∩ the device's `browser` capability; intersected
  per session by the server, re-checked by the device per call; only `http(s)`; cloud metadata hosts refused; a
  non-loopback host asks once per session (Full access skips it); admin per-tool rules on `ocw_browser_*` apply (mode).
- **WZB-03** A fresh 0700 profile directory per session browser, deleted on close and swept at daemon start; pages in an
  in-memory context; never the user's browser profile or the system Chrome; downloads refused.
- **WZB-04** Every open, navigation, action, close and refusal audited `work_browser.*` with ids and `scheme://host:port`
  only; page text, typed text, cookies and absolute paths never reach audit, events, logs, `device_commands` or the
  timeline; snapshots reach the model as untrusted page content.
- **WZB-05** The session's audience (`work_session.read`) watches live in the session view; frames only while someone
  watches (≤ 4 fps, 960×600), Device Link binary frames under 256 KiB, latest wins, with takeover and member-session
  privacy states; 1440 and 390, light and dark.
- **WZB-06** Delivered by the upgrade: `ocw upgrade` on the server; runtimes ≥ v0.3.1 update themselves (version 0.5.0);
  the pinned Chrome for Testing headless shell (sha256 per platform) is fetched on first use; missing Linux libraries
  reported with one `apt-get` line (never sudo); the desktop app reports its version and shows "Update available"; an
  older device shows "Update this device to use the browser".
- **WZB-07** Proven by an e2e spec (fake runtime + real local browser + local page) and a headless container proof;
  documented in `docs/SERVER.md`, the README and ADR-0035.
- **WZB-08** Only a person who can prompt the session and asked its current or last turn takes control of the page
  (lease: one holder, 10 min after the latest input, warning at 9); while held the agent's browser tools answer
  `paused` and only the holder's socket gets frames; an abandoned lease after input closes the page.
- **WZB-09** `ocw_browser_signin { host, reason }` asks the turn's asker only and waits up to 15 minutes ("Not now"
  denies); "Done, save my sign-in" exports only the host's cookies (RFC 6265 domain-match) and origin storage, filtered
  again at the API, sealed only when changed, per member × site in the Work Zone scope (AAD
  `${org}:${user}:browser:workzone:${siteKey}`), expiry = min(cookie expiry, org maximum), owner-only (restrictive
  RLS), revocable in Settings › Keychain.
- **WZB-10** A sealed sign-in loads only into a new site-locked in-memory page of that member's own turn in a human
  session whose audience is the member plus at most the device owner, on the device running it, with the browser still
  allowed; another host needs the member's approval; frames go only to that member; it is re-sealed and closed before
  anyone else's browser call, at the end of each of the member's turns, at session end and on close.
- **WZB-11** Leak sweep: cookie and typed-text canaries never appear in any column, event, audit row, log line, Redis
  payload or device command across the D-31 journey.
