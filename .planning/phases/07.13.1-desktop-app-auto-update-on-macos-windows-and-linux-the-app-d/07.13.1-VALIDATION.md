# Phase 07.13.1 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 5.0.2 (root projects `unit`; `apps/desktop/vitest.config.ts`), Playwright 1.64.1 `_electron` (desktop e2e, CI only), Semgrep rule tests (`node scripts/guard/run.mjs --rule-tests`) |
| **Config file** | `vitest.config.ts`, `apps/desktop/vitest.config.ts`, `apps/desktop/e2e/playwright.config.ts`, `.semgrep/rules.yml` |
| **Quick run command** | `pnpm --filter @ocw/desktop test` and `pnpm exec vitest run --project unit apps/local-runtime/src/maintenance/` |
| **Full suite command** | `pnpm verify` |
| **Estimated runtime** | ~900 seconds (full), ~20 seconds (quick) |

## Sampling Rate

- **After every task commit:** the quick command for the touched package
- **After every plan wave:** `pnpm verify`
- **Before `/gsd-verify-work`:** `pnpm verify` green, and a pull-request run of `.github/workflows/release.yml` green on
  the three runners (macOS arm64, Windows x64, Linux x64), which includes the manifest check and the update e2e
- **Max feedback latency:** 60 seconds for task-level checks (the macOS `package:mac` proof in plan 02 Task 1 takes
  up to 15 minutes, runs once, and only with populated electron / electron-builder caches; otherwise the release.yml
  pull-request run covers it)

## Offline rules (owner)

- No test calls GitHub, the npm registry or any remote host; the only network is a loopback server inside the test
  process (the fake release, plan 07).
- No test uses the real `~/.ocw`, installs a service, runs a real installer or replaces an app: temp folders,
  `OCW_HOME` under `/tmp`, `OCW_RUNTIME_FAKE=1`, `installAllowed: false` in the unpackaged test mode.
- The Electron e2e runs only in CI (release.yml); locally it is typechecked and listed (`--list`).
- The local macOS `package:mac` proof (plan 02 Task 1) is a build, not a test; it runs only when the electron and
  electron-builder caches are already populated, because electron-builder would otherwise download from GitHub.
- macOS tools (`ditto`, `codesign`, `plutil`, `xattr`) run only on files in temp folders (plan 04's darwin cases).

## Manual-Only Verifications (owner UAT)

Real updates need two published releases (the first one with the updater is installed by hand once). Run them on the
owner's machines after tagging two consecutive releases (vN with this phase, then vN+1).

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| macOS: vN → vN+1 from `/Applications` | DAU-03, DAU-04, DAU-07 | Real signed-by-CI bundles, real Gatekeeper, App Management, Keychain and TCC | Install vN in /Applications, pair; publish vN+1; "Check for updates…" → "Restart to update"; the app relaunches on vN+1 (About shows it), the runtime reconnects, Settings › Devices shows the new app version; note any Keychain / "modify apps" / privacy prompt and whether re-pairing was needed (A3, A4) |
| macOS: from the disk image and translocated | DAU-04 | Real dmg mount and App Translocation | Run vN straight from the mounted dmg: the menu shows "Update available" and "Move OCW to Applications to get automatic updates"; the move relaunches from /Applications |
| macOS: "Move OCW to Applications" stops the daemon first | DAU-04, DAU-06 | Electron's mover terminates and relaunches the app outside the normal quit path | From the mounted dmg, note the daemon's pid (`pgrep -f ocw-runtime`), click "Move OCW to Applications to get automatic updates": before the app relaunches from /Applications that pid is gone (no orphaned daemon), exactly one daemon runs afterwards, and a Work Zone prompt sent during the move runs after the relaunch; cancelling the move brings the daemon back |
| macOS: standard (non-admin) user | DAU-04 | Real permissions on /Applications | As a standard user the menu shows the link, never a password prompt |
| Windows: vN → vN+1, per-user NSIS | DAU-01, DAU-07 | Real installer, SmartScreen, Defender | No SmartScreen dialog during the silent update (A1), the app relaunches on vN+1, shortcuts still work |
| Ubuntu: AppImage vN → vN+1 | DAU-01, DAU-07 | Real AppImage runtime | The new versioned file replaces the old one beside it, the app relaunches, the one-time "now runs from …" notice appears; renamed to `OCW.AppImage` it is overwritten in place |
| Ubuntu: `.deb` | DAU-05 | Real package install | The menu shows "Update available (v…): download the .deb, or use the AppImage, which updates itself"; nothing installs by itself, no password prompt |
| A running Work Zone turn holds the restart | DAU-06 | Real runtime turn across a real app restart | Start a long turn, click "Restart to update": "Waiting for 1 session to finish…"; a prompt sent meanwhile shows "Restarting the OCW runtime on this device…" and runs after the restart; "Cancel the restart" reopens at once |
| Automatic level unattended restart | DAU-07 | Real idle time | At Automatic with an update ready and no turn running, leave the computer 30 min: the app restarts into vN+1 by itself; at Notify only it waits for the click |
| Visual check of the onboarding window states | DAU-08 | The e2e runs only in CI and its screenshots are not kept | Open "Server and pairing…" with an update downloading, ready and waiting: layout, focus ring and contrast match the window's existing update link |
