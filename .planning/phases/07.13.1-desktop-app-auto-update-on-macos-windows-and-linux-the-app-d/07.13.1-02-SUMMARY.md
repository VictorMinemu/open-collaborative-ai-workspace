# Phase 07.13.1 Plan 02: Release names, update manifests and the release-build flag Summary

electron-builder now names every desktop file with its release name and writes `latest-mac.yml` / `latest.yml` /
`latest-linux.yml` plus `app-update.yml` (GitHub, `VictorMinemu/open-collaborative-ai-workspace`, no `publisherName`);
`check-update-manifest.mjs` recomputes sha512 and size on the runner that built them (and on macOS checks the zip's
seal, bundle id, version and daemon); release.yml uploads them unrenamed, checksums them and never persists git
credentials; `RELEASE_BUILD` is true only in a tag build of the release workflow.

## Deviations from Plan

None in behaviour. Two additions inside the planned files, both stricter checks:

1. **[Rule 2] Release-name and install-file checks.** `check-update-manifest.mjs` also fails when a `files[].url` does
   not start with `OCW-v<version>-` or when the platform's install file (mac zip, Windows setup, Linux AppImage) is not
   listed, so a rename or a missing zip target is caught on the runner, not as a device-side 404.
2. **[Rule 2] Extracted zip's `app-update.yml`.** On darwin the seal step also checks the `app-update.yml` inside the
   extracted zip (the bytes devices install), not only the one in `mac-arm64/`.
