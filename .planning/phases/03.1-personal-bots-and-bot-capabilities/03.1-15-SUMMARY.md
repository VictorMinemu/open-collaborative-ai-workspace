## Real-cell proof (CI, mandated adaptation)

**Trigger.** `.github/workflows/cell-proof.yml`, on `pull_request: labeled` when the label is `cell-proof` (or `workflow_dispatch` once the file is on `main`). `gh workflow run cell-proof.yml --ref feat/phase-3.1-personal-bots` answered `HTTP 404: workflow cell-proof.yml not found on the default branch`, so the label is the trigger (`gh pr edit 10 --add-label cell-proof`; remove and re-add it to run again).

**What the job does.**
1. Sets up as the `e2e` job does: `pnpm setup:env`, compose postgres + redis, `pnpm db:migrate`, Chromium.
2. Checks that ClawHub answers, with one retry after 60 s.
3. Runs, with `PROOF_BUILD=1` (builds `ocw-openclaw:local` and `ocw-fake-model:local` from the tree, as `cell-smoke` does):
   ```
   OCW_BUNDLED_PLUGINS=none OCW_E2E_API_HOST=0.0.0.0 OCW_E2E_CLAWHUB_URL=https://clawhub.ai \
   OCW_MOCK_MODEL_BASE_URL=http://fake-model:18999/v1 PROOF_BUILD=1 \
     bash scripts/e2e-isolated.sh --cmd "bash scripts/cell-proof.sh"
   ```
4. Uploads `proof-out/` (screenshots, `audit.tsv`, cell and fake-model logs) and the Playwright report as artifact `cell-proof`.

**5b. [Rule 1 - Bug] The cell smoke could report "never connected" for a cell that had connected.**
- **Found during:** CI run 37329185804, job 111827607716, on the docs-only head a66c80e.
- **Issue:** the wait loop broke 0.5 s after `agent channel connected` (15:04:08.64), 40 s into a 120 s wait. The post-loop check `docker logs … | grep -q` then failed: under `pipefail`, `grep -q` exits on the first match and `docker logs` dies of SIGPIPE, so a long log (the doctor output) turns a match into a failure. The same trap is documented in `scripts/demo-up.sh`.
- **Fix:** the four `docker logs | grep -q` checks in the smoke now read the whole log (`grep … >/dev/null`).
- **Commit:** the fix commit after a66c80e. That push's CI run is in the orchestrator return.

### Mandated adaptation and plan wording

- **Why:** this was the user's mandated adaptation.
- **Images:** the images are built from the tree (`PROOF_BUILD=1`, as `cell-smoke` does with `SMOKE_BUILD=1`), not reused with bind mounts. In CI a fresh build is root-owned and current.

## Open items

- **Stale provider after uninstall (log noise).**
  - After DuckDuckGo is uninstalled at runtime, `tools.web.search.provider` stays `duckduckgo`. OpenClaw logs `WEB_SEARCH_PROVIDER_INVALID_AUTODETECT` and `Config warnings: … configured plugin "duckduckgo" is unavailable; Gateway will ignore this optional provider`.
  - Behaviour is correct: the API stops offering `web_search` and the next boot render omits it.
  - **Proposed fix:** the reconciler clears the provider when its plugin leaves `plugins.allow`.
- **Hung `POST /agent-channel/v1/plugins/report` in one local e2e run** (req-4mn, simulated cell, mobile marketplace spec). It did not reproduce in 2 later runs or in CI. Worth an integration test of concurrent reports or of the `notifyCellConfig` lock order if it recurs.
- **UX: provider plugins.**
  - In Settings › Marketplace, an installed provider plugin such as DuckDuckGo shows "No tools" and a "Personal bots" switch that does not govern web search. The Internet capability in Bot policy does.
  - Bot policy says "DuckDuckGo — Built in" even when it came from the marketplace.
  - Showing "Provides web search (duckduckgo) · governed by Bot policy › Internet" needs the declared surface in the `CellPlugin` DTO (contract + API).
- **Demo cell restart loop** (Deviation 7). `RestartCount=10` by 15:36 UTC, exit 0, not OOM, in step with other containers of the Docker VM restarting. It reconnects each time. The owner should check the Docker VM's load and memory and the demo bots.
- **`workflow_dispatch` for `cell-proof.yml`** works only after the file reaches `main`. Until then, use the PR label.
- **The proof screenshots `proof-after-uninstall[-dark]`** show the "Bot settings" tooltip, because focus returns to the trigger after the sheet closes. This is cosmetic.
