# Phase 07.11 Plan 05: Retire idle CLIs, resume lazily, self-updaters off, per-runtime gate Summary

**Both adapters now report their turns in flight and retire idle CLI processes without ending sessions (Claude resumes
the runtime session, Codex `thread/resume`s on a new app-server at the next turn), every daemon-launched CLI runs with
its own updater off, and `RuntimeGate` holds one runtime's new turns with no admission race.**

## Baseline (regression rule)

Before any change, `pnpm --filter @ocw/local-runtime test`: **19 files, 362 tests passed**. Every existing case still
passes unchanged after the plan (final: 20 files, 394 tests).

## What changed

- `runtime.ts`: `activeTurns(): number`, `retireIdle(): Promise<number>`, `refreshInstall?(): void` with doc comments.
- Claude (`claude-runtime.ts`): `Session.dormant`; `retireIdle()` closes the query exactly as `relaunch()` does
  (shared `closeQuery`), serialized with settings changes, re-checking idleness inside the step; `wake(s, mode)` shares
  `launch()` with `relaunch()` (new input, abort controller, `done`, `bypass`, flag settings re-applied);
  `dispatch` wakes inside its serialized step in the turn's mode, `configure` wakes in the mode being set; `stop()` on
  a dormant session finishes with one `completed`. `childEnv` always adds `DISABLE_AUTOUPDATER=1` (session, relaunch,
  wake, catalog and title launches; a parent `DISABLE_AUTOUPDATER=0` cannot switch it back on). `refreshInstall()`
  re-resolves `claudePath` (keeps `opts.claudePath`) and drops the catalog cache.
- Codex (`codex-runtime.ts`): `Session.dormant` and a `retired` peer set; `spawnSessionServer`, `attach`
  (retired peers' notifications, requests and close are ignored), `initialize` and `codexThreadParams` factored out of
  `start`; `retireIdle()` marks idle sessions dormant in the same step as the idle check, then stdin end, SIGTERM and
  SIGKILL after `STOP_GRACE_MS` without `finish()`; `wake(s)` respawns with the same env and args, `initialize`,
  `thread/resume`, unrestricted-policy guard; called from `dispatch` (after the turn overrides, so a refused
  fullAccess turn never spawns) and `compact`. `CODEX_APP_SERVER_ARGS = ["app-server", "-c",
  "check_for_update_on_startup=false"]` used by `spawnReal` (sessions, catalog, titles). `refreshInstall()`.
- `fake-runtime.ts`: `activeTurns`, `retireIdle`, `wakeUps`; with `OCW_RUNTIME_FAKE_CLI=1` `detect()` and `catalog()`
  run `<claude|codex> --version` (found with `findExecutable`, `execFile`, 10 s, no shell) through
  `parseRuntimeVersion`; any failure keeps `fake`. Test seam `FakeRuntimeOptions.findExecutable`.
- `maintenance/gate.ts`: `RuntimeGate` per PD-07 (`isOpen`, `admitted`, `heldCount`, `admit`, `closeIfIdle`,
  `close`, `waitIdle`, `open`).
- Test doubles: `daemon.test.ts` (`activeTurnsCount`, `retireIdleCalls`), `title.test.ts` (see deviations).

## Notes for later waves

- 07 wires it: per runtime one `RuntimeGate`; hold `session.start`, `prompt`/`steer`, `session.configure`,
  `session.title` and catalog collection through `gate.admit(fn, onHeld)`; `closeIfIdle(() => adapter.activeTurns())`
  (opportunistic) or `close()` + `waitIdle(...)` (drain); then `retireIdle()`, run the update, `refreshInstall?.()`,
  `open()`. Nothing calls `interrupt`.
- Codex "approve for this session" decisions live in the app-server and are asked again once after a recycle
  (Pitfall 10, T-07.11-05-05, accept); Claude's `sessionAllowedTools` lives in the adapter and survives.
- A Codex `configure()` on a dormant session does not wake it; the change rides on the wake-up `turn/start`.
- The fake-CLI version is read on every `detect()`/`catalog()` call (no cache), so an e2e "update" of the fake CLI is
  visible at the next handshake/catalog collection. `session.started.runtimeVersion` of the fake stays `fake`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `title.test.ts` test double implements the two new methods**
- **Found during:** Task 1 (typecheck)
- **Issue:** `apps/local-runtime/src/title.test.ts` casts an object literal to `AgentRuntime`; with two new required
  members TS2352 broke `tsc`.
- **Fix:** added `activeTurns: () => 0, retireIdle: async () => 0` to that literal (outside `files_modified`, no
  behaviour change).
- **Commit:** e4dd7204

**2. [Rule 3 - Blocking] Codex `activeTurns()` / placeholder `retireIdle()` in Task 1's commit**
- **Found during:** Task 1
- **Issue:** `CodexRuntime implements AgentRuntime`; without the members Task 1's commit would not typecheck.
- **Fix:** Task 1 added the real `activeTurns()` and a `retireIdle()` returning 0; Task 2 replaced it.
- **Commits:** e4dd7204, 5f73d1a2

**3. [Design within the plan] Claude `configure()` wakes; Codex `configure()` does not**
- The plan's action says dispatch and configure wake; its behaviour says "applies it on the wake-up launch (no extra
  query)". Claude: `configure()` on a dormant session wakes once, directly in the mode being set, and applies the rest
  on that launch (one query, strict `settings_rejected`, immediate `session.settings`). Codex sends nothing on
  `configure()`, so waking there would only spawn a process early; the held change rides on the wake-up `turn/start`
  as the behaviour states.

**4. [Design within the plan] Codex resume params from the configured settings**
- `thread/resume` uses `codexThreadParams` for the session's configured mode/model/fast tier (equal to the start
  params when nothing changed, which the test asserts). Resuming with a stale start mode could re-request a
  full-access sandbox after the opt-in was turned off; full access is never requested without the device opt-in.

**Total deviations:** 2 auto-fixed (blocking), 2 documented design choices. **Impact:** none on scope.
