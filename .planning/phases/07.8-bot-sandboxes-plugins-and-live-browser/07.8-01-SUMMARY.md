# Phase 07.8 Plan 01: Contracts 01a (sandbox, sandboxd protocol, bot capabilities, activity) Summary

**One sandbox exec is now expressible end to end in Zod: `ocw_sandbox_exec` and its flags → strict argv body →
`SandboxdExec` → result → tool response, or a `SandboxRefusal` with its HTTP status. The broker contract carries
redacted snapshots, masked screenshots, a site lock with blocked-navigation results and fully pinned package trees.
Replies can carry the turn's activity.**

are delivered by the broker, API, plugin and UI plans.

## What exists now

- **Agent Channel bodies** (strict): exec (argv 1..64, each ≤ 8192 chars, argv[0] non-empty, `cwd` relative, timeout
  1..600 s, `background`), process (poll/kill), read, write (≤ 1 MiB UTF-8), list, delete (never the root), share and
  import. Paths go through `SandboxRelativePath`: no leading `/`, no `.`/`..` or empty segment, no `\`, no NUL, ≤ 1024.
- **Confined tools:** 15 `BUILTIN_TOOLS` entries, so `isDangerousToolName` never refuses them. `CONFINED_TOOL_FLAGS`
  encodes the D-13 rule: `egress_exec` for exec, `cross_site` for open and act, `none` for the other 12. Only share is
  side-effecting. `MAX_SANDBOX_CALLS_PER_TURN = 40`.
- **Host-aware dangerous names:** with no host argument, the cell behaves exactly as before, and `DANGEROUS_TOOL_NAMES`
  is untouched. With host `sandbox`, `exec`, `bash_run`, `write_file`, `puppeteer_click` and `playwright_open` are
  allowed. `gateway`, `nodes`, `openclaw`, `session(s)_*`, `group:*`, `tool_call`, `message`, `send_sms`,
  `update_config`, `code_execution` and `canvas` stay refused.
- **Broker:** `SANDBOXD_ROUTES` covers all 38 ops of the interfaces block, each with its method, a `/v1` path and
  input and output schemas. `contextFrames` is marked `stream: true`, and its `output` is the JSON control message.
  A schema walk proves two things: `StorageStateBlob` appears only in `contextOpen.input` and
  `contextExportState.output`, and no broker key is named `script`, `evaluate`, `expression`, `html`, `dom`, `har`,
  `selector` or `cookies`.
- **Packages:** `PackageTreeEntry` takes sha512/sha256 integrity. The review result carries `entries` (≤ 5000), the
  `lockfile` (≤ 2 MiB) and `treeSha256`. An install names the recorded tree, and each result carries
  `digest_mismatch` or `tree_changed`.
- **Activity:** `ActivityStep` caps the target at 200 chars and the output tail at 4096 bytes. `BotTurnActivity` holds
  ≤ 50 steps plus `more`. There is a `turn.activity` event, and `Message.activity` is optional.

**2. [Rule 2 - Correctness] A capability PATCH would have reset the new switches**
- **Found during:** Task 1
- **Issue:** in Zod 4, `BotCapabilities.partial()` still applies the inner `.default(false)`, which I confirmed with a
  probe. So `UpdateBotCapabilitiesRequest.parse({internet: true})` would have returned `sandbox: false`.
- **Fix:** the patch schema re-declares `sandbox` and `browser` as plain optionals. A test now asserts that a patch
  without them has no such keys. The existing PATCH route only applies its fixed `TOGGLES`, so it ignores both keys
  until plan 15 adds them.
- **Commit:** `d72a03a0`

**3. [D-14] Browser sandbox posture**
- D-14 and 07.8-03 require `browserSandbox` (`chromium+gvisor` | `chromium` | `container-only`) to be reported in
  Settings. `BrowserSandboxMode` was added. It is nullable with default `null` on `SandboxIsolationInfo` and
  `SandboxdInfo`, and nullable on `SandboxdBrowserStatus`.

## Broken-windows candidates (not written to WINDOWS.md, per instructions)

1. `turn.activity` is not registered in `realtime.ts` `EventTypes` or `EphemeralTypes`. Plan 10 publishes it and must
   add it there; the realtime exact-list tests change in that commit.
2. `SandboxdContextInput.events` is loose (`record<string, unknown>`). Once 01 and 30 are merged, tighten it to
   `LiveInputFrame` (plan 16).
3. The file transfer ops (`filesUpload`, `filesDownload`, `filesImport`, `contextDownload`) are base64 JSON up to
   50 MiB, about 67 MiB on the wire. Plans 09 and 11 should check the Fastify body limit or move to streaming.
4. Plans 05, 10 and 14 must map the statuses consistently. `SANDBOX_REFUSAL_STATUS` returns 403 for
   `cap_reached` and `tainted`, which follows the plan's "403 for decisions" and matches `board.ts`. The 07.4
   connector routes return 409 for those codes.
5. npm packages whose lockfile integrity is sha1-only fail `PackageTreeEntry`. Plans 17 and 18 must score them as
   `refuse` with a reason instead of letting the parse fail.
6. `PATCH /api/v1/agents/:id/capabilities` ignores `sandbox` and `browser` (its fixed `TOGGLES`). Plan 15 adds them,
   with the resolver-checked switch.
