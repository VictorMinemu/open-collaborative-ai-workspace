# Phase 07.13 Plan 12: Device tracer (manager, approvals, daemon wiring, fake runtime) Summary

The daemon now has a single `BrowserManager` that checks every Work Zone browser call: the device opt-in, the turn's grant, the lease, the body, the admin rule modes and host approvals. It drives a session's lazily started `BrowserChild`, gives the model page text only inside an untrusted block, and reports summaries and origins only. The fake runtime drives it from `browser <tool> <json>` prompt lines against a real Chromium.

## What was built

- **tools.ts**: the tool table (descriptions say page text is untrusted; `signin` key optional for 19), `WorkBrowserToolResult`, `browserToolSummary` ("Opened h:p", "Clicked on h:p", "Refused: <sentence>"), `pageContent` (lead line plus begin/end markers with a random tag), `pageContentOf` and `resultSignedIn` (used by the fake), result builders.
- **manager.ts**: `BrowserManager` / `SessionBrowserTools` (`available`, `call`, `markUnavailable`, `onAvailableChange`, `setImageInput`, `shimTokenFile`); `onPrompt`, `onTurnStarted`, `onTurnEnded`, `onOptInChanged`, `onServerFrame`, `shimCall`, `endSession`, `stopAll`, `resolveApproval`, `pendingApprovals`, `runDir`, `openPages`. Calls are serialised per session. On a cold start it installs the browser with the D-05 status line (`ocw_browser_install`), and the download goes on even if the turn is cancelled. It maps child errors to refusals (`invalid_request` becomes an isError result with the message), closes an idle page after 10 minutes, and on a crash drops the child so the next `open` starts a new one.
- **approvals.ts**: `BrowserApprovalBroker`. It emits `approval.requested` with `browser { kind, origin, tool }`, then `waiting_approval`, then `approval.resolved`. Host and admin_rule asks wait 10 minutes, `signed_in_host` and `signin` asks wait 15. A deny comes from turn end, session end or the call's abort signal.
- **shim-token.ts**: a 32-byte hex token in a 0600 `shim-token` file (`wx`) inside the 0700 run dir. The check reads the file and compares in constant time; a link, a directory or a malformed file counts as missing.
- **daemon.ts**:
  - Creates one manager. Session starts and prompts pass their grants (with the turn's effective Full access), and `forwardEvent` reports when turns start and end.
  - Sessions get `StartSessionOptions.browser`. A session's end and `stop()` close its page.
  - `approval.resolve` goes to the broker first.
  - `hello` and `capabilities` carry `browser { version: 1, optIn }`. `device.appVersion` comes from `OCW_APP_VERSION`, and only if it is a semver.
  - `reloadConfig` re-reads the browser opt-in. If it changed, it re-sends `capabilities`; if it went off, it closes every open page. The result now includes `browserOptIn` and `browserOptInSource`.
  - At start it runs `sweepRunDirs`. `browser.*` server frames go to the manager. The `browserCall` control command goes to `shimCall`.
  - `status.browser` reports `optIn`, `source`, `sandbox` and `openPages`.
  - The manager's `api.put` only reaches `WORK_BROWSER_SIGNIN_ROUTES` with uuid ids (`toBrowserApiUrl`), under the device JWT, with redirects refused and a 401 retried once.
- **control-socket.ts**: a strict `browserCall { session: uuid, token: 64 hex, tool, args }` arm.
- **device-link.ts**: `sendBinary(bytes)` returns false when the socket is not open or the payload is over 256 KiB, and never queues.
- **fake-runtime.ts**: the PD-28 directive. Each line emits `tool.started`/`tool.completed` with the summary and no `output`. The answer lists each summary, `Signed in: yes|no` and `Contains "<expect>": yes|no`. The fake calls `setImageInput(true)`.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 3 - Blocking] `BrowserChild` removed the shim token with its run dir**
- **Found during:** Task 3
- **Issue:** PD-08 puts the token at `<root>/run/<sid>/shim-token`, but `BrowserChild` deletes the whole run dir when it exits (close, idle close, crash, plus a second delete 2 s later). A Codex shim that read its token at spawn would then be refused after the first idle close.
- **Fix:** I added `BrowserChildOptions.keepFiles` to `child.ts`, which is outside `files_modified`. When it is set, only the other entries are removed; when it is absent, behaviour is unchanged. The manager passes `["shim-token"]` and removes the run dir itself at session end. I added a real-Chromium test in `child.test.ts`.
- **Commit:** b2048e2c

**2. [Rule 2 - Missing critical] Approvals for origins reached by a redirect or an action**
- **Issue:** The child has no site lock yet, so a click or a redirect can land on an origin nobody approved.
- **Fix:** `open` asks for the final origin when it differs from the approved target; if denied, the page is closed and the call answers `approval_denied`. Any later call on a page whose origin was not approved asks first.
- **Commit:** 0e56a688

**3. Small API additions beyond the plan's signatures**
- `onPrompt` takes a 4th argument `{ fullAccess }`, and `promptId: null` stands for the session.start grant.
- `BrowserManagerOptions` gained `fullAccessAllowed`, `browsers`, `createChild`, `childEntry` and `idleMs`. `DaemonOptions.browser` exposes these as test seams only.
- The manager handles a minimal `browser.lease` (held, released, abandoned). This was needed for the plan's "paused" truth; 07.13-15 adds the takeover ops.
- `toBrowserApiUrl` and `appVersionOf` are exported from daemon.ts.

## Threat surface

There is no new network surface: `browserCall` is local only, on the 0600 Unix socket. `api.put` reaches only the two sign-in routes on the daemon's own server URL. The threat register's mitigations are covered:

- T-01: opt-in, grant and capability are checked on every call (tested).
- T-02: approvals sit in the manager, and `alwaysAsk` also applies under Full access.
- T-03: summaries only, and the fake prints only yes/no.
- T-04: the untrusted page block and the tool descriptions.
- T-05: the 0600 per-session token with a constant-time check. The residual risk from other processes of the same OS user is documented in the control-socket doc.
- T-06: events carry origins only and pass through `sanitizeEvent`.
