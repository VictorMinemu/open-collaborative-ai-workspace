# Phase 07.18 Plan 07: OpenClaw cell account pool Summary

The cell now holds several ChatGPT accounts as named OpenClaw profiles (`openai:pool-<accountId>`), signs one out alone,
reports every profile it holds, and applies the API's pool: Claude setup-tokens as `anthropic` token profiles that
reference `OCW_POOL_TOKEN_<n>` (never the literal), the org API key as the last profile, and the strategy's order per
provider. A snapshot without `accountPool` leaves the cell as it was.

## What was built

- **Task 1 (tracer), `openclaw-auth.ts`, `subscription-auth.ts`.** `login({ profileId? })` passes the id to
  `runModelsAuthLoginFlow` and returns the account it actually signed in, with its stored `profileId`.
  `profilesFromStore(store, provider)` lists every OAuth profile in store order with `usable`. `accountFromStore` and
  `status` behave as before. The flow forwards the event's `profileId`. A `connected` report carries `profileId` only
  when the start asked for one, so a start without it sends today's report fields. Credential state reports
  (flowId null) carry `profiles`, sent when the list differs from the last one this instance reported.
- **Task 2, per-profile sign-out.** `logout(provider, profileIds?)` removes only this provider's listed ids (OpenClaw
  removes exact ids whatever their provider, so `anthropic:*` ids are filtered out, and an empty filter is a no-op, never
  "remove all"). It throws the busy error when any of them is still present afterwards. A per-profile revoke stops
  only a running sign-in of those profiles, then reports what is left (`connected` + `profiles`, or `disconnected` +
  `profiles: []`). A revoke without `profileIds` works as before (no extra report).
- **Task 3, `cell-account-pool.ts` (new).** `planCellAccountPool(pool, { anthropicKeyEnv })` is pure. It returns the
  env (token values), the profiles (env names only), the order per provider and `keyInProfiles`. Ids outside
  `anthropic:pool-*` / `openai:*` are never planned. `applyCellAccountPool(plan, driver, { envChanged })` reads the
  store and writes only the differences: missing or changed profiles, removal of the `anthropic:pool-*` and org-key
  profiles no longer wanted, and an order set or cleared (managed plans only). It then refreshes the gateway's auth
  state, logs failures without secrets, and never throws. `createOpenClawPoolDriver` is the real driver over the
  pinned SDK. `openclaw-port.ts` puts the pool env into the gateway env next to the provider keys (stale
  `OCW_POOL_TOKEN_*` are removed) and applies the pool after every reconcile, whether or not the config changed.
  `reconciler.ts` drops the `anthropic` entry's `apiKey` while pool tokens exist (`applyPlanToDraft` deletes an owned
  key set to `undefined`). Every other provider is unchanged.

## OpenClaw 2026.9.7 probes (A-03, A-04, A-05)

These come from reading the pinned image's `dist/` and `docs/`
(`ghcr.io/openclaw/openclaw@sha256:0da12cd4…`, `package.json` version 2026.9.7, extracted with a `docker run --rm`
into the scratchpad). Nothing was installed and no account was signed in. The same notes are in the
`openclaw-sdk.d.ts` comments.

- **A-03 holds.** `runModelsAuthLoginFlow` (`dist/auth-BShLso3q.mjs`) spreads its options into
  `runProviderAuthMethod`, whose `resolveReloginProfileIdentity` stores the method's one returned profile under the
  requested `profileId`. This is the CLI's `models auth login --profile-id`, and the docs show two `openai` logins
  side by side. A requested id with a method that returns several profiles throws, but the openai device code returns
  one. After a login, `promoteAuthProfileInOrder` puts the new profile first in an existing store order. The next
  reconcile restores the API's order because the apply is state-based. PD-12's fallback (store the returned id) stays
  in place: the report carries `signedIn.profileId ?? ev.profileId`.
- **A-04, partly as planned.** The gateway method is `models.authOrderSet` `{ provider, profileIds | null, agentId? }`
  (null clears). It **refuses** a list that leaves out any stored profile of the provider ("profileIds must include
  every available profile"). It also refuses when `auth.order` in the config owns the order. So it cannot keep a
  disabled profile out, and the cell does not use it. The cell writes `store.order[provider]` itself under the same
  lock (`updateAuthProfileStoreWithLock`, exported by `plugin-sdk/provider-auth`), which is exactly what
  `setAuthProfileOrder` (`models auth order set|clear`) does. At selection (`dist/order-OIctrKHp.mjs`) an explicit
  order is the only candidate list. Unlisted profiles are **excluded** (`excluded_by_auth_order`), listed ones keep
  their order, and cooling ones go last. There is one exception: when **every** listed profile is missing from the
  store, OpenClaw falls back to all stored profiles. With no order, OpenClaw sorts OAuth before token before api_key,
  then least recently used. A stored order beats `auth.order` in the config.
- **A-05 holds (by code reading).** `resolveApiKeyForProviderCore` (`dist/model-auth-provider-CakpoXjY.mjs`) tries,
  in this order:
  1. a session pin;
  2. an entry `apiKey` that names a stored profile;
  3. an entry with `auth: "api-key"` (the reconciler never sets it);
  4. non-secret markers;
  5. **the auth profiles in order**;
  6. only then the entry's own key.

  A `token` profile may carry `tokenRef` (an env SecretRef `{ source: "env", provider: "default", id }`).
  `resolveApiKeyForProfile` reads it from the runtime snapshot, which `refreshProviderLoginAuthState` →
  `refreshActiveProviderAuthRuntimeSnapshot` re-publishes from the gateway env. `paste-token` uses
  `upsertAuthProfileWithLock`, which is exported. **`CELL_CLAUDE_TOKENS` stays true** (plan 14: no change). The
  end-to-end check with a real setup-token against Anthropic was not run here (no real account): owner UAT.

## Deviations from Plan

### Auto-fixed / adjusted

**1. [Rule 1 - Correctness] The order is not set through `models.authOrderSet`.**
- **Found during:** Task 3, probe A-04.
- **Issue:** The gateway method refuses partial lists, so a disabled profile could never be left out (T-07.18-07-04).
- **Fix:** The real driver writes the store order directly with `updateAuthProfileStoreWithLock`. This is the same
  write as `setAuthProfileOrder`, under the same lock and with the same `preserveOrderProfileIds`. The driver then
  refreshes the gateway's auth state.
- **Commit:** 6e6a1977

**2. [Rule 2 - Missing critical] Profile ids are filtered by provider on sign-out.**
- **Found during:** Task 2.
- **Issue:** OpenClaw removes exact ids whatever their provider, and an empty `profileIds` must never become a full
  sign-out (T-07.18-07-03).
- **Fix:** The driver removes only `openai:*` ids through an openai revoke. A filter with nothing left does nothing.
- **Commit:** fe472ca6

**3. [Design] `profiles` is a separate optional driver method instead of a widened `status` return.**
- The plan's wording was "`status` gains `profiles`". A separate method keeps `status` callers and test fakes as they
  are, and it can report unusable profiles even when no account is usable.
- **Commit:** 62759fda

**4. [Design] The org API key's profile id.**
- The hub did not name it. It is `anthropic:ocw-org-key`, an `api_key` profile whose `keyRef` points at
  `OCW_PROVIDER_KEY_ANTHROPIC` (the env var the key already lives in). The cell appends it to an explicit Claude order
  when `apiKeyLast` is set. The API's `claude.order` therefore lists token profiles only. This matches plan 14:
  "order [A, B] and apiKeyLast true".

**5. [Design] When the profile list is reported.**
- The plan said the list is reported after two sign-ins. A credential state report now goes out whenever the profile
  list differs from the last one this instance reported, including on the first sync after a plugin start. That
  happens once per process. Plan 14 adopts the pre-07.18 sign-in from it (E14) even when the API sends no
  `accountPool` because it has no pool rows. With a driver that cannot list profiles, the reports are exactly as
  before.

## Notes for plan 14 (API)

- **Every ChatGPT profile disabled.** An empty explicit order cannot be held by OpenClaw: writing one clears the order,
  and every stored profile becomes usable. The cell plans "no order" in that case. The API must keep bots off the
  subscription itself, for example by not listing `openai-codex` in `subscriptions`. The same applies when every
  listed profile is missing from the store, because OpenClaw then falls back to all stored profiles.
- `claude.order` should list only the `anthropic:pool-<id>` token profiles. The cell adds the org key last itself.
- A per-profile revoke is answered by a credential state report (`profiles`) right away.
