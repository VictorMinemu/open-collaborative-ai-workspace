## Phase Goal

Each member connects their own MCP account once and sessions refresh themselves; agent calls use the asker's
credential (plan map and executor rules: 07.4-01-PLAN.md).

**This plan's slice (tracer, protocol client):** against the fake (07.4-04), the API-side library discovers, builds an
authorization URL, follows the fake's auto-approval, checks `iss`, exchanges the code and calls `whoami` with the
bearer — all through the egress guard; then the spec refusals and the MCP result shaping. No routes or storage here.
Plan mode first (CLAUDE.md, D-06).

<objective>
Give the API a spec-correct OAuth 2.1 client for MCP servers and an MCP tool client, both bound to the egress guard,
with the two checks the SDK lacks (PKCE presence, RFC 9207 `iss`).

Purpose: CONN-01/02 (member OAuth), CONN-03 (calls with the member's bearer); D-02, D-07.
Output: `connectors/oauth.ts`, `client-metadata.ts`, `mcp-client.ts` + unit and integration tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → MCP server / authorization server | Remote, partly attacker-influenced documents (PRM, AS metadata, WWW-Authenticate) and responses |
| MCP result → model | Untrusted content that may contain prompt injection or echoed credentials |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.4-05-01 | Spoofing | authorization code injection / downgrade without PKCE | high | mitigate | Refuse when S256 is not advertised; PKCE on every flow (Tasks 1, 2) |
| T-07.4-05-02 | Spoofing | mix-up attack (code from another AS) | high | mitigate | RFC 9207 `iss` check; issuer recorded per flow (Tasks 1, 2) |
| T-07.4-05-03 | Information disclosure | SSRF through PRM / AS metadata URLs | high | mitigate | Egress guard on every request; AS endpoints https or same origin as the admin URL (Tasks 1, 2) |
| T-07.4-05-04 | Elevation of privilege | token usable against another resource | medium | mitigate | RFC 8707 `resource` on authorize, token and refresh, asserted via fake stats (Tasks 1, 2) |
| T-07.4-05-05 | Information disclosure | bearer echoed in results or error text | high | mitigate | Redaction of known credential strings; coded errors without cause text (Task 3) |
| T-07.4-05-06 | Denial of service | huge results or slow servers | medium | mitigate | 4 MiB transport cap, 32 KB result cap, timeouts (Task 3) |
| T-07.4-05-07 | Spoofing | client credentials reused across authorization servers | medium | mitigate | Clients keyed by issuer; pre-registered for another issuer ignored (Task 2) |
</threat_model>
