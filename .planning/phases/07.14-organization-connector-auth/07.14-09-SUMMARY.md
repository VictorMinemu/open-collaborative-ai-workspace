# Phase 07.14 Plan 09: Organization client credentials and the Test sign-in route Summary

**An admin now turns a client-credentials-only MCP server into a working organization connector with a client ID and secret. The API keeps the token fresh by itself: one re-grant across instances, with the issuer re-checked before every token request. `POST /connectors/oauth-test` tells the dialog which sign-in step fails, without registering a client or writing anything. A stored secret is only ever sent to the target it was saved for.**

## Accomplishments

- **`credentials.ts`**
  - New `client_credentials` kind in `StoredBundle`: client ID, secret, token endpoint, issuer (or null), resource, revocation endpoint, auth method, requested scopes, token and expiry. Only organization rows accept it; the member store refuses it.
  - `headerFor` adds the client secret to `secretParts`, so a server that echoes the secret back is redacted.
  - `fresh()` treats a client-credentials token expiring within 60 s (exactly 60 s included) as stale.

    - grants with the stored endpoint and auth method and the server's current scopes;

  - `disconnectOrg` revokes the access token at the published revocation endpoint, authenticating with the client secret.
  - `storeOrgConnection` writes `method`, `client_id`, `token_endpoint` and the granted scopes for this kind.

## Security

**Coordinator finding (MEDIUM), fixed in `2b888453`.**

- **The flaw:** the Test route took `url` and `clientCredentials.tokenEndpoint` from the request, but filled in the organization's stored client secret, and the stored or pre-registered clients, when the form omitted them. An admin could point the test at their own server and receive the stored secret in the token request. The save route had the same flaw through `body.tokenEndpoint` (any https URL passes `trusted()`) and through a changed issuer. That broke the write-only-secret rule (ADR-0025/0017).
- **Test route fix:**
  - Stored clients and the stored secret are used only when the target is the saved one: `url` absent or equal to the saved URL, the same client ID, and the Token URL absent or equal to the saved one. Otherwise only form values are used, and no stored clients are passed.
  - A stored secret also goes to `diagnose` with a `pin` (the saved issuer and endpoint). If discovery now names another issuer (`issuer_mismatch`) or another endpoint (`token_endpoint_untrusted`), the run fails before any token request.
- **Save route fix:** a kept secret is used only if the issuer and endpoint the save would use equal the saved ones. Otherwise it answers 400 `secret_required` and sends nothing; typing the secret again saves.
- **Admin-entered Token URLs** meet `checkMcpUrl` before any request (Test: 400 `invalid_url`; save: 409 `token_endpoint_untrusted`, recorded). Then `trusted()` and the egress guard apply as before.
- **Member Test path:** it shares the route, so the same rule covers it.
- **Tests:**
  - Changed URL: no token request; the saved server's clients are not used.
  - Changed Token URL: no token request.
  - Changed issuer: `issuer_mismatch`, no token request.
  - The saved URL given explicitly: the stored secret is used as before.
  - Refused Token URLs (cloud metadata, loopback): refused before any request.
  - Save: a changed issuer or another Token URL without the secret → `secret_required` with no request.
- **Leak sweep:** the existing one (`security.int.test.ts`) is the 07.4 member sweep and has no client-credentials flow. Adding `CC_SECRET` to it would pass trivially, so it is left for plan 13's 07.14 sweep (T-07.14-09-03 "13 sweep"). This plan's suites already scan responses, audit rows and API logs for `CC_SECRET` and the token.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The rate-limit hook landed on every organization route**
- **Found during:** Task 3. The connector suites ran together and answered 429 on PUT, DELETE and connect.
- **Issue:** `@fastify/rate-limit` appends its hook to the route's `preHandler` array, and the Test route had reused the shared `admin.preHandler` array.
- **Fix:** `preHandler: [...admin.preHandler]`.
- **Regression guard:** the 429 test now makes 12 PUT calls after the limit trips. I confirmed it fails with the shared array.
- **Commit:** `e1e71361`

**2. [Rule 3 - Blocking] Two additive fake scenarios**
- **Issue:** the fake always sent `expires_in` and always published PRM, so "no `expires_in`" and "no metadata + admin Token URL" could not be shown end to end.
- **Fix:** `omit_expires_in` and `no_prm`, in `infra/fake-model/fake-mcp-oauth.mjs` and `.d.mts`. Both are off by default, so nothing changes for existing users.
- **Commit:** `eda106d7`

**3. [Rule 3 - Blocking] `shares.int.test.ts` route coverage**
- **Issue:** its org-B test requires a case for every connector route.
- **Fix:** two cases for the new routes, both 404 for org B.
- **Commit:** `e1e71361`

**4. [Rule 2 - Refactor for correctness] `serverClientsOf` extracted from `startOAuthFlow`**
- **Why:** the Test route must decide from exactly the clients the sign-in uses.
- **Effect:** the member and organization sign-in suites are unchanged and green.
- **Commit:** `e1e71361`

**5. [Plan ordering] Keep-secret / `secret_required` landed in Task 1**
- **Why:** the save route needed it from its first version.
- **Effect:** Task 2's keep-secret cases were already green at RED.

**6. [Rule 3] `diagnose` accepts a client-credentials input without client or secret**
- **Why:** the route can always pass the Token URL to discovery. A missing secret then fails at the token step with nothing sent, instead of a misleading `discovery_failed`.
- **Commit:** `2b888453`

**7. Coordinator security fix** (see Security).

**Total deviations:** 6 auto-fixed, plus 1 coordinator-requested fix. None is architectural.
