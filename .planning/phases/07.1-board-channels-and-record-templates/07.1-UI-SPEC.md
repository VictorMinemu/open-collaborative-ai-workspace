> Visual and interaction contract for board channels, card threads, column settings, card editing and record
> templates. Generated by gsd-ui-researcher, verified by gsd-ui-checker. Every value comes from the existing tokens in
> `apps/web/app/globals.css` and the existing primitives in `apps/web/components/ui/*`. This phase adds no new design
> system, no new CSS variables and no new font.

## Layout Contract

### Shell geometry at 1440 (measured on the Phase 4 screenshots)

App sidebar 240 px + chat sidebar 256 px leave a **944 px content column**. The thread panel is `w-[440px]` at `lg`
(existing). Board geometry is chosen to fit that column:

| Element | Value |
|---------|-------|
| Column (lane) width | **272 px** (`w-68`), fixed, `shrink-0` |
| Gap between lanes | 12 px (`gap-3`) |
| Board horizontal padding | 24 px (`px-6`, matches `PageHeader sm:px-6`); 16 px at <640 |
| Board top / bottom padding | 16 px / 24 px |
| Result at 1440, thread closed | 3 full lanes (24 + 3×272 + 2×12 = 864) + a **56 px peek** of the 4th lane, which signals horizontal scroll |
| Result at 1440, thread open | 504 px board: 1 full lane + peek; opening a card scrolls its lane into view (`scrollIntoView({ inline: "nearest", block: "nearest" })`, `behavior: "smooth"` only with `prefers-reduced-motion: no-preference`) |
| Lane | `rounded-xl bg-muted/50 dark:bg-white/[0.03]`, inner padding 8 px, tiles stacked with 8 px gap; lane body scrolls vertically on its own (`overflow-y-auto scrollbar-thin`), page never scrolls vertically |
| Lane header | 40 px tall, sticky at the top of the lane, `px-2`, same lane background |
| Board scroller | `overflow-x-auto scrollbar-thin snap-x snap-proximity`; lanes `snap-start`; a 24 px right fade (`mask-image` linear gradient) only when more lanes exist to the right |

### Card tile

```
┌─────────────────────────────────────┐  bg-card, border, rounded-lg, shadow-xs (dark: shadow-none), p-3 (12)
│ ⠿ EXP-0007                       ⋯ │  row 1 (h-5): grip (hover/focus only on desktop) · number (mono 12/400 muted) · menu (icon-xs 28)

└─────────────────────────────────────┘
row gap 8 px. Minimum tile height 76 px (no chip, one-line title).
```

| Part | Rule |
|------|------|
| Number | `{prefix}-{number}` in `font-mono text-xs tabular-nums text-muted-foreground`, zero-padded to the rule's `{seq:0…}` width when the board rule has one, else unpadded. Absent when the board has no prefix |
| Duplicate number | When the title starts with the number text followed by ` · `, ` - ` or ` — `, the tile shows the remainder after that separator; the full title stays the accessible name, the tooltip and the text in the thread. Example: badge `EXP-0001`, title shown `Acme · Broken pump` |
| Title | Plain text React node, never Markdown. 2-line clamp; full title in a `Tooltip` on pointer devices when clamped |
| Waiting chip | See Color › Waiting state. Text is always written out; never colour alone |
| Author | `PrincipalAvatar` 20 px (`compact`), `kind` user or agent (agent avatars carry the existing bot styling). Name resolved from the channel member directory already loaded by `channel-view`; unknown → initials of "Former member" |
| Reply count | `MessageSquare` 14 px + number; hidden when 0. Accessible text "3 replies" |
| Last activity | `shortAgo(max(lastReplyAt, movedAt, createdAt))` from `work-zone/session-sidebar.tsx` ("now", "5m", "3h", "2d", "6w"); tooltip/`title` with the full date. Separated from the reply count by ` · ` |
| States | rest: `border-border`; hover (pointer): `border-foreground/15 bg-card`; focus-visible on the open button: existing ring `ring-[3px] ring-ring/40` on the tile; selected (thread open): `ring-2 ring-primary/60`; pending move: `aria-busy="true"`, no visual change (optimistic); being dragged: source becomes a placeholder (dashed `border-primary/40 bg-primary/5`, same height, content invisible) and a drag overlay tile with `shadow-lg` follows the pointer, `rotate-1` only with `motion-safe:` |
| Read-only viewers | Non-members, archived boards: no grip, menu shows only "Open thread" |

Structure (no nested buttons): `<li>` → `<div class="relative">` containing, in DOM and focus order, **grip button**
(z-10), **open button** (stretched over the whole tile with `after:absolute after:inset-0`, carries the title text),
**menu trigger** (z-10). Footer content is inside the open button.

### Column settings dialog

`Dialog` (`sm:max-w-md`), `data-testid="column-settings"`:
Name (Input, 1–60) → Category (four radio rows: icon, name, one-line meaning) → "When a card enters" (Select, five

disabled with the reason shown as its description line.

## Interaction Contract

### Opening a card
- Click / tap the tile body, or Enter / Space on the focused open button → `openThread(card.messageId)` (`?thread=<id>`).
- Pointer drag starts only after 6 px of movement (desktop) or a 250 ms press (touch), so a click or tap always opens.
- A permalink to a card root opens `?thread=<id>` over the board; a permalink to a reply inside a card thread keeps today's highlight behaviour (07.1-07 Task 3).

### Drag and drop (desktop pointer)
1. Hover a tile → grip fades in (`opacity-0 group-hover:opacity-100 group-focus-within:opacity-100`), cursor `grab` on the tile.
2. Drag → source becomes the placeholder, overlay tile follows the pointer (`shadow-lg`, `motion-safe:rotate-1`), lanes auto-scroll near edges, the board scrolls horizontally near its edges.
3. Over a lane → 2 px primary drop line where the card would land; empty lane → its dashed box highlights with "Drop here".
4. Drop → optimistic placement, `PATCH { move: { columnId, afterCardId }, expectedVersion }`. The browser never mints a rank.
5. Escape or dropping outside any lane → cancel, card returns to where it was, no request.

### Keyboard move
Focus order per card: grip (`aria-label="Move card {title}"`) → open button → card menu.
- On the grip: Space or Enter picks up; ↑/↓ move within the lane; ←/→ move to the neighbouring lane (lands at the same index, clamped); Space or Enter drops; Escape cancels.
- While carrying, the overlay tile shows a 2 px primary outline; the board scrolls the target into view.
- The KeyboardSensor and Accessibility plugin of `@dnd-kit/react` provide the live region; the board passes custom screen-reader instructions and announcements (Copy › Screen-reader announcements).

### "Move to…" (every tile, both breakpoints)
Card menu (`data-testid="card-menu"`): `Open thread` · separator · `Move to…` (submenu: radio group of columns with
category icons, current checked) · `Move to top` · `Move to bottom` (each disabled when already there) · `Waiting on…`
(submenu: radio group Nobody / Us / Customer / Both) · separator · `Edit card…` (human author only) · `Delete card…`
(author or `message.delete_any`, destructive). Viewers who cannot post see only `Open thread`.
At 390 the submenus open as nested menus inside the same popup; items are `min-h-11`.
"Move to…" lands the card at the **bottom** of the target column.

### Optimistic moves, rollback and conflicts
- Every move (drag, keyboard, menu) applies `placeCard()` instantly and sends one PATCH.
- **Failure (network, 4xx/5xx other than 409):** restore the pre-move snapshot (instant under reduced motion, else a 150 ms position transition), `toast.error` with the rollback copy, announce it in the live region.
- **409 `board_card_version_conflict`:** restore, apply the server's current card (it may now be elsewhere), `toast` with the conflict copy (neutral, not error), announce it.
- **410 `channel_archived`:** restore, toast the archived copy, the view switches to read-only on the next channel refetch.
- Waiting-state changes follow the same optimistic path.
- Live changes from other people are applied silently (no toast, no announcement); a card moved by someone else while you carry it keeps your drag; on drop the server decides and the 409 path applies.

### Offline and reconnecting
- When `useConnectionMeta().status` is `reconnecting`, `closed` or `idle` for more than 3 s after the board has loaded, a 32 px banner sits under the toolbar: `WifiOff` 14 px + copy, `bg-muted/60 text-muted-foreground text-xs px-6 (px-4 at 390)`, `role="status"`. It disappears when the status returns to `open` (the replay catches up without reload, D-03).
- Moves stay enabled while offline; a failed request takes the rollback path.

### Membership and archive gating (UI mirrors the server; the API decides)
| Viewer | Board |
|--------|-------|
| Member, active channel | Everything (`channel.post`) |
| Non-member previewing a public board | Read and open threads; no grip, no `+`, menu = Open thread; join banner at the bottom (existing markup, board copy) |
| Archived channel | Read and open threads; no grip, no `+`, no New card; archived banner at the bottom |
| Owner or admin (`channel.update`) | Adds column actions, Add column |
| Card's human author | Adds Edit card… (menu and thread strip) |

### Column settings
- Add: `Add column` tile (desktop) / `+` tab (390) → dialog → new column is appended at the end and appears live for everyone (`board.updated`).
- Rename / recategorise / default waiting: column menu `Edit column…`.
- Reorder: `Move left` / `Move right` (disabled at the ends). No drag-to-reorder of columns in this phase.
- Delete: confirmation; non-empty columns require a target; the last column cannot be deleted; at 390, deleting the active column selects the next tab (or the previous one when it was last).

### Card editing (P-02: author only)
- Author: `Edit card…` from the card menu and the thread strip; the root message's own "Edit message" opens the card editor instead.
- Others: no text edit anywhere; they read the card in the thread strip (fields) and the root message (title, description).
- Saving sends only changed parts with `expectedVersion`; a typed title sets `titleSource = user` and is kept through later description or field edits.

### Record templates
- Every member sees the unit's own and inherited templates; managers (`canManage`) see New / Edit / Delete on own rows only. Inherited rows are never editable from a descendant unit.
- The editor validates in place with `validateDraft()` before any request; API refusals render as the form-level error at the top of the body.
- Token chips insert at the caret and refocus the rule input. Removing a field that the rule uses marks the rule invalid immediately.

### Focus management
- Board (desktop) Tab order: header actions → Board/Messages tabs (arrow keys move between them) → New card → for each lane left to right: `+`, column `⋯`, then for each card top to bottom: grip, open, menu; then `Show more cards` → Add column.
- 390: header → toggle → New card → column tabs (arrow keys, Home/End) → active-column `+`, `⋯` → cards (open, menu) → Show more cards.
- Dialogs: focus the first input on open (Name, Title, or Description when the board has a naming rule); on close return focus to the trigger. Delete confirmations focus Cancel.
- After a menu move the focus stays on the moved card's menu trigger in its new place (desktop) or on the tab list (390, card left the visible tab).
- Thread: opening moves focus into the panel (existing composer autofocus); closing returns it to the card's open button.

### Reduced motion (`prefers-reduced-motion: reduce`)
- No tilt or scale on the drag overlay; sortable shift transitions and the drop animation are 0 ms.
- Rollback snaps back without transition; `scrollIntoView` uses `behavior: "auto"`.
- Skeletons `motion-reduce:animate-none`; the tab indicator does not slide.
- Existing dialog and sheet transitions are untouched (global behaviour, out of scope).
