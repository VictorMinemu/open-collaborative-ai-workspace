# Phase 07.18 Plan 19 R3: Everything from the admin panel Summary

An admin now adds a Claude account from Settings with no terminal: the API runs `claude setup-token`'s own OAuth flow
(PKCE verifier in Redis, the exchange through the egress guard, the token sealed like a pasted one). The ChatGPT
device-code sign-in also runs on a laptop the admin owns or that is shared with them; any other laptop shows the
exact `ocw-runtime account add codex --label …` command with a Copy button.

## R3.1 ground truth: the `claude setup-token` OAuth parameters

Read only, no request sent. Sources:
- **A:** the installed Claude Code CLI 2.1.331 (`/Users/victor/.local/share/claude/versions/2.1.331`, a Bun binary;
  bundled JS read with `strings`).
- **B:** the Agent SDK 0.3.282 native binary (`@anthropic-ai/claude-agent-sdk-darwin-arm64@0.3.282/claude`).
- **C:** CLIProxyAPI `internal/auth/claude/anthropic_auth.go` and `pkce.go` (commit `85225381`).

Not reproduced (on purpose):
- `setup-token` then runs `EKo`, an organization managed-settings check that revokes a "withheld mint". That check is
  enterprise policy inside the CLI and has no server equivalent here.
- The CLI's success page redirect and profile fetch are not needed: only the access token is kept.
- CLIProxyAPI's disguise (axios User-Agent, TLS fingerprint) is not copied.

## What was built

### R3.1: Connect a Claude account (commit 82d8b85b)
- **Routes** (`provider.manage`, `no-store`). `POST /api/v1/account-pool/claude/sign-ins` with body
  `{ accountId? }` answers `{ flowId, authorizeUrl, expiresAt }`. `POST …/sign-ins/complete` with body
  `{ flowId, code, label? }` answers the `PoolAccount`.
- **Flow record.** `ocw:account-pool:claude-sign-in:<flowId>` holds `{ organizationId, userId, verifier, state,
  accountId }`, with a 600 s expiry.
  - Another admin's flow, or another organization's, reads as `sign_in_expired` and stays intact.
  - A paste that is not a code (`invalid_code`) or a missing label (`label_required`) keeps the flow.
  - After that point the record is read once with GETDEL. A wrong state answers `state_mismatch`, and the flow is used up.
- **Exchange.** `egressFor(env).fetch` (64 KiB, 30 s). A 400/401/403 answers 400 `code_refused`: "Anthropic didn't
  accept this code. It may have expired or been used already. Start again." Anything else, or a non-`sk-ant-oat`
  token, answers 502 `claude_unavailable`, with an invitation to paste a setup-token instead.
- **Storage.** The token goes through `addClaudeToken` (new account) or `updatePoolAccount({ token })` (Connect
  again), the same path as a pasted token. Audit: `account_pool.sign_in_started` (`{ provider, replacing }`) and
  `account_pool.signed_in` (`{ provider, label, replaced }`). They never carry the token, code, verifier or state.
- **Test-only override.** `OCW_CLAUDE_OAUTH_TOKEN_URL`, refused in production like the ChatGPT overrides.
- **Web.** "Connect a Claude account" is the primary action.
  - It opens a tab inside the click and sends it to the authorize URL once the API answers. The link stays in the
    dialog in case the tab was blocked.
  - Step 2 is "Paste the code", with a client-side shape hint.
  - A code that can no longer be used resets the dialog to Connect, with the API's sentence.
  - "Paste a setup-token instead" is the secondary link. The old form is unchanged behind it, with a link back.
  - Replacing a token ("Replace the token") offers the same two ways.

### R3.2: ChatGPT on a desktop device (commits 7c2936f3, 11010022)
- **API.** `refuseDevice` still accepts any service device. A desktop device (or one without a reported host kind)
  needs the caller's `device.use`, decided by the resolver from the device facts (owner, shared, grant). Otherwise it
  answers 409 `device_not_allowed`: 'This device is not shared with you. Run "ocw-runtime account add codex" on it
  instead.' The decision is made on every start.
- **Web.** `deviceChoices` lists, in order:
  1. devices the admin may sign in on;
  2. laptops not shared with the admin ("Not shared with you"), which can be chosen;
  3. offline devices, disabled.

  Picking an unshared laptop replaces Start with a panel: "Run this on X." It holds the shell-quoted command
  (`codexAddCommand`), a Copy button and "It arrives off. Turn it on here once it's listed.", with a **Done** button.

## Known limits
- If the database write fails after a successful exchange (the pool fills up in the same moment, or the account is
  removed during a replace), the minted token is not revoked at Anthropic. The pool cap is checked when the sign-in
  starts to make this unlikely.
- R3.2 shows no warning that the laptop's owner can read the slot's `auth.json` when the admin signs in on a laptop
  shared with them but owned by someone else. The docs say the account lives on that device.
- Whether a token minted this way behaves like a CLI-minted one has only been checked against the fakes, not real
  accounts. The parameters are identical to the CLI's. This needs the owner's UAT.
