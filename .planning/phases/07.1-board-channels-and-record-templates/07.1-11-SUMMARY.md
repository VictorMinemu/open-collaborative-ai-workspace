# Phase 07.1 Plan 11: Column settings, card strip, card editing and Delete card Summary

**Owners and admins now shape a board's columns from the board itself: add, rename, recategorise, set the default waiting state, reorder and delete with a move target. Every viewer sees the change live. A card's thread opens with a card strip: number, typed title, column and waiting state as menus, Edit card for the author, field values. The thread no longer repeats the card's text. Authors edit their cards from the card menu, the strip and the root's own Edit. Typed titles stay typed and search follows the new title. The author or a moderator deletes a card.**

## Duplicate text in the card thread (07.1-08 open item)

- **Cause.** The root message body is `title + description + field lines`. That is right for search and the Messages view, but under a card strip it repeats everything.
- **Fix, presentation only:**
  - The strip shows the structured data. The title appears there only when it was typed.
  - An automatic title is not shown in the strip. It is built from the number (in the strip), the fields (in the strip) and the description's first line (in the root).
  - The thread root renders only the description (`cardRootView`).
- **Unchanged:** the stored plain-text body, chat search, the Messages view, text-channel threads and replies.
- **Proof:**
  - The 390 e2e asserts that the description's first line appears exactly once in the whole thread panel.
  - The 1440 e2e asserts that the root contains neither the typed title nor `Customer: Acme`.

## Deviations from Plan

1. **[Scope] `message-list.tsx` was not in `files_modified`.**
   - **Why:** routing the root's own "Edit message" to the card editor needs a hook in the list.
   - **What changed:** `MessageList` takes `onEdit`. A function opens another editor; `null` means not offered. When absent, the behaviour is unchanged.
   - **Conflicts:** no wave-4 plan touches the file. The `chat-edit` e2e passes in both projects.
2. **[Test] `board-primitives.test.tsx` (07.1-04).**
   - `cardMenuModel` now also returns `editCard` and `deleteCard`.
   - The "cannot post" `toEqual` gained `editCard: false, deleteCard: false`. The assertion is extended, not loosened.
3. **[Design] Duplicate text fix.** See the section above. The strip shows the title only when it was typed, and the root renders only the description. The plain-text body is unchanged.
4. **[UI-SPEC, layout] Strip rows.**
   - Row 1 is the number, the typed title and Edit card on the right.
   - Row 2 is the column and waiting buttons. Then come the fields.
   - The UI-SPEC sketch puts the number, both buttons and Edit card on one row. At 440 px Edit card wrapped alone, which the screenshot review rejected.
5. **[Copy] Three strings not in the UI-SPEC:**
   - `A typed title can't be left empty`: a typed title cannot go back to automatic through the API.
   - `Waiting on nobody` on the strip's waiting button when the state is `none`: the chip renders nothing for `none`. Same wording as the column dialog.
   - Screen-reader-only dialog descriptions for Add/Edit column and Edit card.
6. **[Ordering] Task 2's code shipped in Task 1.**
   - The column menu, the delete-with-move dialog and the 390 `+` / `⋯` live in the same files as the tracer.
   - Task 2 is the e2e proof and its screenshots, so its commit type is `test(web)`.
   - The card-edit and card-delete mutations also landed with the Task 1 lib file.
7. **[Plan arithmetic] "Move left three times".** From the end of five columns, two moves place the new column right after In progress. The tracer does two and asserts the order.
8. **[Scope] Search → card thread.**
   - The e2e proves that the new title word finds the card, that the old word gives `search-empty`, and that Enter lands on `/chat/<board>?m=<card>`.
   - Opening that permalink as the card's thread over the board is 07.1-09's work (it owns `channel-view.tsx`), so the spec asserts the URL only.
9. **[Rule 2] No spurious 409 from moves.** While the editor is open, a newer live card with the same text (someone moved it or changed its waiting state) becomes the edit's base. A text change by someone else still gives the 409 and Reload card (e2e).
10. **[Rule 2] Archived boards.** `channel-view` passes `canManage` from `channel.update` even for an archived channel. BoardView reads the archive state from the channel cache (`useBoardChannelAccess`) and hides column settings and Delete card, which the API would refuse with 410.
11. **[Design] Column route answers are applied to the cache at once** (guarded by `board.version`). The `board.updated` frame is then a no-op. A delete that moved cards refetches the snapshot, because no per-card event announces the moved cards (P-09).
