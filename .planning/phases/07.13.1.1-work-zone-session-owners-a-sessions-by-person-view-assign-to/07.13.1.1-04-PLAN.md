<objective>
Per D-07, D-08, D-09. The session's agent gets one tool to rename its own session. The daemon owns the decision it can
make locally (turn, grant, once per turn, sanitize) and forwards the rest to the API over the Device Link; Claude Code
reaches it through an in-process SDK MCP server beside `ocw_browser`. The fake runtime drives it for the e2e.

Purpose: WZO-06 on the device (Claude half; Codex is plan 05). Output: `session-tools/` (relay, tools, Claude server),
daemon and adapter wiring, an offline synthetic fixture, tests.

Interface this plan publishes (plan 05 builds on it):

- `runtime.ts`: `StartSessionOptions.sessionTools?: SessionToolsHandle` with `readonly offered: boolean`,
  `description(tool: WorkSessionTool): string`, `call(tool, args, signal?): Promise<SessionToolResult>` (never throws;
  `{ content: [{ type: "text", text }], isError }`), `markUnavailable(reason: "shadowed" | "runtime"): void`,
  `onChange(cb): () => void` (offered or description changed), `shimTokenFile(): Promise<string>`.
- `SessionToolRelay` (relay.ts): `forSession(id)`, `onPrompt(id, promptId | null, grant | undefined, { steer })`,
  `onTurnStarted(id, promptId)`, `onTurnEnded(id, promptId)`, `endSession(id)`, `onServerFrame(frame)`, `sweep()`,
  `shimList({ session, token })` and `shimCall({ session, token, tool, args })` (token checked with `verifyShimToken`
  against `<ocwHome>/run/sessions/<session>/shim-token`; plan 05's control-socket entries call these two).
</objective>
