## Phase Goal

A controller pastes, drops or attaches images in the Work Zone composer and the session's runtime (Claude Code or
Codex) receives them with the prompt; everyone in the session sees the sent images in the stream.

**This plan's slice (tracer, Device Link level):** the linked images of 06.1-01 go to the device: the prompt command
stores ids only, the hub prepares it inside its transaction and hydrates it after commit, and a FakeDevice receives
the base64. Then the byte rules and the frame guard for every frame. Runs in parallel with 06.1-03 (device side; no
shared files). Planner decisions: `06.1-RESEARCH.md` (P-01 … P-12); executor rules P-13 in `06.1-01-PLAN.md`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → device (Device Link) | Image bytes leave the server only inside a bounded command frame to the session's device |
| object storage → API | Bytes read at send time; objects may be missing or larger than expected |
| device → API (ack errors) | Untrusted text that may echo input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06.1-02-01 | Denial of service | an oversized frame closes the device link (1009) and redelivery loops, taking the device offline for every session | high | mitigate | Budget at submit (4 × 2 MiB), read cap at hydration, `frameFits` in `send()` for every frame; a too-large command is failed, never resent; int tests for prompt and non-prompt commands (Tasks 2, 3) |
| T-06.1-02-02 | Information disclosure | image bytes/base64 in Postgres, logs, audit, stream events, ack errors | high | mitigate | Ids-only payload, hydration after commit, audits with counts, `stripImageData` on acks, leak scan over logs and five columns (Tasks 1, 3) |
| T-06.1-02-03 | Denial of service | slow storage or sharp work holding database locks | medium | mitigate | Flush transaction only selects and chooses parts; hydration outside; submit budget from recorded sizes with no storage call (Tasks 1, 2) |
| T-06.1-02-04 | Information disclosure | camera EXIF/GPS reaching the device owner's runtime and provider | medium | mitigate | Everything except small PNGs goes as the EXIF-free rendition (P-02, Task 2) |
| T-06.1-02-05 | Tampering | decompression bombs in the resize step | medium | mitigate | `fitImageWithin` keeps `limitInputPixels`; input is already a ≤ 2048 px rendition |
| T-06.1-02-06 | Repudiation | silent loss of images at dispatch | medium | mitigate | `image_unavailable` / `frame_too_large` refusals audited and shown as `lastError` (Tasks 2, 3) |
</threat_model>
