## Phase Goal

Members connect and disconnect their own account; tokens are sealed per member, refresh is serialized, and a revoked or
expired grant asks to reconnect (plan map and executor rules: 07.4-01-PLAN.md).

**This plan's slice (tracer, member connection):** a member connects through OAuth end to end over the real HTTP
routes — start → the fake's authorize → callback with the member's session → sealed connection → API-side probe fills
the tools; then custody (refresh race, terminal/transient, issuer change, disconnect, secret mode, isolation); then
the callback hardening and member-account shares. Plan mode first (CLAUDE.md: secrets, permissions, audit, D-06).

<objective>
Implement the connectors module's member side: connect (OAuth and secret), callback, CIMD document, credential
custody with serialized refresh and reconnect state, disconnect with revocation, the API-side probe, and the
member-account shares that let a member allow their account in one conversation.

Purpose: CONN-01 (member side), CONN-02, CONN-03 (shares feed the audience rule); D-01, D-02, D-03, D-07 item 4.
Output: `connectors/{index,routes,credentials,probe,shares}.ts` + three integration test files; module registration.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| authorization server → API callback | Untrusted query parameters on a public route |
| browser session → callback | Session must match the member who started the flow |
| API instances ↔ Redis/PostgreSQL | Concurrent refreshes of rotating tokens |
