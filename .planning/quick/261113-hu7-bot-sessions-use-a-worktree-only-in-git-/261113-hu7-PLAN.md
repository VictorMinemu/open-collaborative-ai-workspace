# Bot sessions use an isolated worktree only in git projects

## Problem (owner UAT, v0.3.3)

A bot whose Work Zone profile has **Isolated worktree** on started a session in `preinpección`, a project folder with
no git repository. The daemon refused (`apps/local-runtime/src/git.ts` `NO_GIT_WORKTREE_MESSAGE`: "this project has no
git repository; isolated worktrees need git"), so the session failed and the bot's task blocked. The bot cannot change
the worktree (its start body is strict, the profile decides: `apps/api/src/modules/work-session/bot-sessions.ts` ~491
`worktree: profile.worktree`), and a profile lists several projects, git and non-git.

The device already tells the API whether each project is in a git repository (`DeviceProjectAnnouncement.git`,
`packages/contracts/src/device-link.ts:42`, optional: absent on older devices), but the API does not store it
(`projects` in `packages/db/src/schema/app.ts:1544` has no such column; `apps/api/src/modules/device/link.ts` ~200-220
upserts projects without it).

## Fix

1. **Schema (additive migration):** `projects.git boolean` nullable (null = the device did not say; older devices).
   Generate the migration with the repo's drizzle workflow (see how recent migrations such as
   `20261113035112_bot_task_process_ends` were made) and add its name to `HEAD_ONLY` in
   `apps/api/src/upgrade.int.test.ts` (CI p278-p300 lesson: the upgrade test lists every migration newer than the last
   release). RLS/grants unchanged (column on an existing table).
2. **Device link** (`apps/api/src/modules/device/link.ts`): insert and update set `git: p.git ?? null`.
3. **Bot start** (`bot-sessions.ts`): the session's worktree = `profile.worktree && project.git !== false`. Use that
   effective value everywhere the start uses it, including the D-15 one-executor-per-tree check (`!worktree &&
   load.treeBusy` → `tree_busy`), so a non-git project never gets two active sessions on its tree (principle 4). Read
   the project's `git` in the same transaction (the start already loads the project or can select it by
   `input.projectId`). Restart/redispatch paths keep using the session's stored `worktree` (unchanged).
4. **Bot turn context** (optional, only if trivial): `workZoneOfferFor` projects could carry `worktree: false` for
   non-git projects; skip if it needs a contract change beyond one optional field.
5. **Human new-session dialog** (`apps/web/components/work-zone/new-session-dialog.tsx` ~800-820): if the projects
   API already exposes the project row to the web, expose `git` (optional) and disable the Isolated worktree switch for
   `git === false` with hint "This project has no git repository". If that requires more than an optional field on the
   existing project DTO, skip it and note it in the summary. Never remove existing behaviour.

## Tests (failing first)

- Integration (`apps/api/src/modules/agent-channel/work-session*.int.test.ts` or the bot-sessions suite): a profile
  with `worktree: true`, a project announced `git: false` → the started session has `worktree: false` and the
  dispatched start carries `worktree: false`; a second bot start on the same project while the first is active →
  `tree_busy`. A project announced `git: true` or without `git` → worktree true (unchanged).
- Device link test: the announcement's `git` is stored (true, false, absent → null).
- Upgrade int test passes with the new migration in HEAD_ONLY.
