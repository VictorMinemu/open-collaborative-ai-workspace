Bots start Work Zone sessions in projects without git. Before, a bot whose Work Zone profile uses an isolated worktree
could fail there with "this project has no git repository; isolated worktrees need git".

## What's fixed

- **Bot sessions in a folder without git run in that folder.** v0.3.4 already did this, but only when the device
  had said that the project has no git. Projects added on an older runtime, and folders whose git changed after they were
  added, were never marked. Two changes close the gap:
  - The runtime now checks every project's git each time it connects or syncs its projects, and tells the server.
  - The server also learns it from the first refused start, whatever runtime version the device has. The bot reads
    that a new session will work, and its next start runs in the project folder.
- Unchanged: a session that runs in the project folder still never shares it with another active session (a second start
  there waits until the first one ends).

## Upgrade

In `/opt/ocw` (or wherever the server is installed):

```bash
sudo node scripts/ocw.mjs upgrade --check   # current and newest release; changes nothing
sudo node scripts/ocw.mjs upgrade           # backup, this release, new keys, rebuild; never goes backwards
```

- **No migrations.**
- **Headless Work Zone servers** on v0.3.1 or later update their runtime with one click (Settings › Devices › the
  server › Runtime updates › **Update**), or by themselves at the *Automatic* level. Update them so they report each
  project's git as it is now. Without that update, the server fix alone covers it after one failed start.

The desktop app does not update itself: install the new files below. Its runtime ships inside it.
