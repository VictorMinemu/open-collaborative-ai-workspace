# Phase 03.2 Plan 03: Codex adapter session controls Summary

The Codex adapter now takes the model, effort, fast tier and permission mode as per-turn `turn/start` overrides and reports the effective values back. Supervised means a read-only sandbox with `untrusted` approvals, and a fixture recorded at codex-cli 0.160.0 shows it asks before writing. The catalog comes from `model/list` on the ChatGPT account without opening a thread. `/compact` uses the native RPC. Raw settings slash commands never reach Codex.

## What was built

- **Types:** `generate-codex-types.mjs` gained 6 roots (`ModelListParams/Response`, `Model`, `ThreadSettings(UpdatedNotification)`, `ThreadCompactStartParams`). It was regenerated with the pinned 0.160.0 binary (145 files, pure additions). `experimentalApi` stays false.
- **mode-policy.ts:** one pure table maps each mode to sandbox / approval policy / reviewer. plan = read-only + on-request + user. default = read-only + untrusted + user. acceptEdits = workspace-write(cwd) + on-request + user. auto = workspace-write(cwd) + on-request + auto_review. The file also has the inverse (`fullAccess` for any unrestricted report, null when nothing matches) and `isUnrestrictedCodexPolicy`.
- **CodexRuntime:**
  - `thread/start` and `thread/resume`, plus every `turn/start`, use `codexModePolicy(...)`.
  - `configure()` merges authorized settings and sends nothing until the next turn (D-14). It validates against the cached catalog: unknown models, unknown efforts, `ultra` and unsupported fast mode are refused with `settings_rejected`. `null` resolves to the catalog default. On a model switch, an effort or fast mode the new model lacks drops to that model's default.
  - The turn mode is min(configured, prompt cap) (P-07). Capped input is never steered into a more permissive running turn.
  - `session.settings` comes from the start response, from `thread/settings/updated`, or is synthesized after `turn/start`, and is deduplicated.
  - `/compact` calls `thread/compact/start`. Settings, unknown and refused commands throw `slash_command_refused` before any request.
  - A `thread/settings/updated` reporting dangerFullAccess or `never` emits `session.error` and interrupts the turn.
  - `catalog()` caches for 10 minutes and returns null when Codex is not signed in with ChatGPT or on error.
- **catalog.ts:**
  - `buildCodexCatalog`: hidden models are excluded and `legacy = upgrade !== null`. The NEW badge comes only from `availabilityNux`. Efforts exclude `ultra` and keep their descriptions. Context windows are empty. Fast mode is offered only with the `priority` tier and carries the 2.5x cost note.
  - `listCodexModels` / `collectCodexCatalog`: a short-lived app-server runs `initialize` plus paginated `model/list`, and is killed in `finally`.
- **Mapper:** `thread/settings/updated` maps to `session.settings` (model, effort, serviceTier, fastMode, mode from the inverse table, never the cwd). `modelContextWindow` maps to a display-only `contextWindow`, once per value.
- **Recorder:** `--scenario plan-read|supervised-write|model-list` and `--codex <path>`, with a temp git repo.
- **Inventory:** the Codex rows now say what the 0.160.0 fixtures confirmed: Supervised evidence, Auto exposed, context window display-only, a new readback row, and fast mode with 2.5x.

## Deviations from Plan

### Auto-fixed Issues

1. **[Rule 3 - Blocking] Pinned binary.** The plan said to stop if `codex --version` is not 0.160.0. PATH has 0.160.1 (auto-update), but 0.160.0 is still installed, so I used it explicitly (`--codex` on both scripts). Nothing was installed and the user's config was not changed. (3756db3, 53671a8)
2. **[Rule 2 - Critical] Explicit reviewer.** `approvalsReviewer: "user"` is now sent for plan, default and acceptEdits. The plan-read fixture showed the owner's config defaults the reviewer to `auto_review`, which would have made Supervised auto-reviewed. (53671a8)
3. **[Rule 1 - Contract] Unmatched mode.** `session.settings.permissionMode` is optional but not nullable in contracts, so an unmatched mode is omitted rather than sent as `null` (the plan said `null`). Unrestricted reports map to `fullAccess`, so the server's `isFullAccessReport` can fail closed. (53671a8)
4. **[Rule 1 - Bug] `/compact` completion.** It completes on `turn/completed`, not when the RPC resolves. At 0.160.0, `ThreadCompactStartResponse` is `{}` and `NonSteerableTurnKind` includes `compact`, so completing at RPC resolve would have advanced the queue while the compaction turn ran. RPC errors still complete with `isError`. This behaviour was not fixtured (recording it would cost a turn). (da97f30)
5. **[Rule 2 - Critical] Steer cap (P-07).** Input whose cap is below the running turn's mode, or any steer during a compaction, is queued as its own turn instead of being steered into it (`turn/steer` carries no overrides). (da97f30)
6. **[Rule 2] Defaults resolved from the catalog.** `null` model or effort resolves to the catalog default, because Codex overrides are sticky and sending nothing would not revert. An effort or fast mode the new model lacks drops on a model switch (RESEARCH mapping). (da97f30)
7. **Session start readback.** `session.started` is now followed by a `session.settings` built from `ThreadStartResponse` (model, effort, tier, mode), like the FakeRuntime. One existing test expectation was updated for this. (53671a8)
8. **Plan-read fixture.** It now also yields one display-only `contextWindow` (258400). The existing order test was updated and a dedicated test added. (53671a8)
9. **Turn-response guard.** The `turn/start` response unrestricted-guard from the plan is not applicable: `TurnStartResponse` carries only `turn` at 0.160.0. The guard covers `thread/start`/`thread/resume` responses and `thread/settings/updated`.
