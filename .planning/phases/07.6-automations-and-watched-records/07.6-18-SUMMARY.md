# Phase 07.6 Plan 18: Webhook and mail trigger UI Summary

**A lead or admin now sets up a signed webhook from the automation editor: they pick Webhook, map the payload with JSON
pointers, choose What happens (a card in a board column or a thread, Ask {bot} to read it), create it, and copy the
signing secret from a dialog that cannot be closed until they tick "I've stored the secret". The secret is never shown
again. The panel then shows the URL, the locked secret line, rotation with the 24 h grace, a curl example, live mapping
values, the last deliveries and the latest rejection. A member can set up a mailbox that signs in with a Keychain
Username & password item: they test it without saving and later see its status. Inbound items arrive as Received
cards. Everything was checked in the browser at 1440 and 390, in light and dark, with axe.**

## What was built

- **TriggerStep** (`trigger-step.tsx`). The branches added to plan 15's step:
  - **Webhook before the save:** the line "The URL and signing secret appear after you create the automation." and
    the mapping.
  - **Webhook after the save:** the `WebhookEndpointPanel`.
  - **Mail:** the `MailboxPanel`.
  - **Webhook and mail:** What happens. Its options follow the delivery target. "Ask {bot} to read it" is on by
    default and has its hint.
  - **The secret:** `lastSave.webhookSecret` opens the `SecretRevealDialog`. Done calls `form.dropSecret()`, so the
    sheet's state loses the secret.
  - **Compatibility:** the new `TriggerForm` fields are optional, so plan 15's tests and callers still type-check.
- **WebhookEndpointPanel.**
  - **Endpoint URL:** a read-only mono Input with an icon copy button. The copy is announced through a polite live
    region.
  - **Secret line:** `Lock` + `Set {date} · shown once`. Rotate secret appears only for the owner with the right.
  - **Rotation:** Rotate opens a confirmation with focus on Cancel. Confirming rotates, resets the mutation at once and
    opens the reveal dialog with the new secret.
  - **Grace line:** shown while the previous secret is still valid.
  - **How to send events:** a toggle with `aria-expanded`, the Standard Webhooks sentence and a wrapped curl example
    with its own copy button. The example uses placeholders, never the secret.
  - **Recent deliveries:** a Refresh button and up to 10 rows, keyed by `id + result` (10's note).
    - Accepted: `Created card EXP-0001 in orders`, or `Posted in #sales`.
    - Duplicate: `Already received; nothing new`, with a ring dot.
    - Not run: `Received while paused; not run`, or the run reason sentence.
    - A `→` link opens the card thread or the post.
    - With no deliveries, a dashed empty box.
  - **Rejection notice:** amber, shown only when the rejection is newer than every delivery.
  - **Card number:** built from the board's prefix and naming rule, read with `useBoard`.
  - **Manager view:** a manager (no `lastPayload`) sees no preview and is not asked to send a test event.
- **SecretRevealDialog.**
  - **Closing:** Escape, ✕ and the backdrop do nothing until the box is ticked. They then show "Tick the box to close."
    (`role="alert"`). ✕ appears only once the box is ticked.
  - **Controls:** focus starts on Copy, and Copy shows `Copied` and the toast `Secret copied`. Done is `aria-disabled`
    until the box is ticked. At 390 it is a bottom sheet with full-width 44 px controls.
- **InboundMapping.**
  - **Fields:** Title, Body and Same item, validated as RFC 6901 pointers ("Use a JSON pointer like /order/name").
  - **Live values:** each pointer's value in the last payload, as plain text in curly quotes, `no value` when it names
    nothing, at most 80 characters.
  - **Hints:** "Send a test event to preview values." before any delivery, otherwise the "Values come from the last
    delivery…" hint.
- **MailboxPanel.**
  - **Sign in with:** the viewer's Keychain items of kind `basic`. With none, "You have no username and password keys."
    and a link, "Add one in Keychain", to `/settings/keychain`.
  - **Fields:** Server (mono), Port (993 by default, `w-24` under Server at 390), Folder, and Check every (5 · 10 · 15
    · 30 minutes · 1 hour).
  - **Host check:** a server outside the key's hosts shows the inline error "Add {host} to the allowed hosts of
    “{key}” in Keychain." with the Keychain link.
  - **Test connection:** shows `Testing…` with a spinner, and every fixed result sentence in a `role="status"` line. It
    never saves.
  - **Notes:** the read-only note, and the saved Status line (Checked · n new messages / no new mail, Sign-in failed,
    Couldn't reach, Paused with the automation).
- **The editor sheet** (contained edits; see deviation 1).
  - The form holds `inbound` and `mailbox`.
  - Validation covers pointers and mailbox fields.
  - The create and update bodies send the inbound rule (`null` when switching back to a schedule) and the mailbox.
  - A webhook create resets the save mutation, pins the form to the new automation and calls
    `onCreated(a, { keepOpen: true })`. The list then routes to `?edit=<id>` and does not highlight or focus the row
    behind the dialog.
- **automation-queries.ts.**
  - `useSaveAutomation` runs with `gcTime: 0`.
  - `automationErrorText` words `mailbox_host_not_allowed` (with the host and key from `details`) and
    `mailbox_key_not_usable`.

**1. [Rule 3 - Blocking] `automation-editor-sheet.tsx` is edited, despite the plan's prohibition.**
- **Why:** the sheet owns the form values, the create and update bodies, and the post-create close.
  - Mail could not be saved: `triggerOf` returned `null` and the hard-coded inbound rule was `post`.
  - What happens and the mapping need to be part of the saved body.
  - A webhook create closed the sheet, which would have unmounted the reveal before it was shown (15's own note).
- **What changed:** two `Values` fields; defaults in `blank`, `valuesOf` and `valuesOfDraft`; `triggerOf` for mail;
  validation; the create and update bodies; the kept-open path; and the props passed to `TriggerStep`. That is 75 lines
  in total.
- **Also changed:** `automations-list.tsx`, where `onCreated` routes a kept-open create to `?edit=<id>` without the row
  highlight (+3 lines), and `automation-queries.ts` (`gcTime: 0`, two error sentences).
- **Not met:** the acceptance check `git diff --name-only -- automation-editor-sheet.tsx` prints the file.
- **Merge note for 23:** 23 also edits `?draft=` mode, so expect small conflicts in `valuesOfDraft` and `submit`.
- **Commits:** `49e1708c`, `79f655f9`.

**2. [Rule 1 - Bug] Focus stolen from the reveal dialog** (found by the tracer). The list highlights a new row and the

## Known Stubs

None. An accepted delivery whose item is not posted yet reads `Received` (no link) until the next Refresh; the inbound
worker posts it within seconds.

## Threat Flags

None beyond the register. The plan's three threats are mitigated as follows:

- **T-07.6-18-01 (the secret in the client):** the secret is only in component state and is dropped on Done. The save
  and rotate mutations run with `gcTime: 0` and are `reset()`. Nothing is written to storage or the query cache. The
  e2e canaries check that the secret appears neither in the page HTML after the reveal nor in the list, the run
  history or any toast.
- **T-07.6-18-02 (passwords):** the mailbox panel only selects Keychain items; there is no credential field. The
  password canary never appears.
- **T-07.6-18-03 (payload HTML):** live values are React text nodes (a test renders `<img onerror>` as text), and the
  payload's other fields are never rendered (the payload canary never appears).
