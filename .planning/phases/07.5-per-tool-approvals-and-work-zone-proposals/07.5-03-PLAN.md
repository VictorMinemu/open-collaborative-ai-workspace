## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → policy routes | An authenticated member asks to change who must approve bot actions |
| upper scope → lower scope | A lead's rules sit under organization rules |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.5-03-01 | Elevation of privilege | a lead relaxing an organization rule | high | mitigate | Strictest wins in the resolver; weaker unit rules refused with 409 (Tasks 2, 3) |
| T-07.5-03-02 | Elevation of privilege | non-managers or agents changing policies | high | mitigate | `tool_approval.manage` decided per scope; never an agent grain; cell tokens refused (Tasks 1, 3) |
| T-07.5-03-03 | Information disclosure | history exposing other audit metadata or other tenants | medium | mitigate | History reads only the three actions for the scope and returns only fixed fields; RLS; cross-tenant test (Task 3) |
| T-07.5-03-04 | Repudiation | unrecorded rule changes | medium | mitigate | Audit in the same transaction for create, update, delete (Tasks 1, 3) |
| T-07.5-03-05 | Tampering | lost updates between two editors | low | mitigate | `expectedVersion` with 409 and the current rule (Task 3) |
| T-07.5-03-06 | Spoofing | approver list naming bots or outsiders | medium | mitigate | `users` approvers must be organization members, never agents (Task 3) |
</threat_model>
