## Phase Goal

See 07.7-01 (Phase Goal, plan map, cross-plan contracts, P-01 … P-19).

**This plan's slice (phase tracer, API level):** a bot's consult request becomes a visible, attributed question in the
thread and a turn for the target bot on behalf of the same human, with every guard and refusal. The return half (turn
done, answer back to the asker, Stop) is 07.7-06; the cell half is 07.7-05; the permission rules API is 07.7-03 (same
wave, no shared file).

Module layout without import cycles (revised 2026-11-02, D-07): `agent-message.ts` (decision + offered targets) is
imported by both `mentions.ts` and `consult.ts`; `consult.ts` imports `buildMentionEvents` from `mentions.ts` (exactly as
`automation-runs.ts` and `cards.ts` do); `mentions.ts` never imports `consult.ts` and `registerMentionHandler` is not
changed. Agent-channel imports `announceConsults` from `../chat` (as it imports `patchCard` / `updatePlatformCard`);
chat never imports agent-channel.

<objective>
Build `POST /agent-channel/v1/consultations` end to end on 07.6's primitives: the self-validated route and the claim,
the canonical decision, guards, the question posted with `postAgentMessageIn`, the chain and hop rows, the target's
turn built like a proactive delivery with its `origin`, the hop DTO and its live updates.

Purpose: A2A-01 (question as a visible attributed hop with a chain id), A2A-02 (one decision per hop, deny wins),
A2A-03 (depth, no repeat, budget, one pending, daily limit, asker = H); D-01, D-02, D-03, D-04, D-07, D-08, D-09, D-10,
D-12, D-13, D-15; P-05, P-07, P-11, P-12, P-13.
Output: `consult.ts`, `agent-message.ts`, `chat/consults.ts`, additive seams in the bridge type, mentions and turn policy,
two integration test files.

  1. tx0 (no user): `agent_turns` by `eventId` with `agent_id = agentId` → H; none → `auditUnknownTurn` + 404
     `unknown_turn`.
  2. tx1 as H (`withTenant({organizationId, userId: H})`): `liveTurn` (null → 404 `unknown_turn`). Pre-checks, first
     failure wins: `ocw_consult_agent` in `turn.tools` (`not_in_turn`); `turn.tainted` (`tainted`); conversation kind
     `channel` or a channel's thread (`not_channel`); chain = `turn.chain_id` or the chain whose `root_event_id` is this
     event; chain not `active` → `chain_closed`; `turn.chain_depth + 1 > A2A_MAX_DEPTH` → `depth_exceeded`; target under
     RLS, not deleted (else 404 `target_not_found`); disabled → `target_unavailable`; personal → `target_personal`; =
     source → `target_is_self`; = root or already a target in the chain → `target_in_chain`; not a member of the
     conversation or its parent → `target_not_member`; `decideAgentMessage` denied → `not_allowed`; budget used →
     `budget_exhausted`; a pending hop by this agent in the chain → `consult_pending`. Then `claimToolCall` (flags
     `{untrustedOutput: false, sideEffecting: true}`, `sourceKind: "builtin"`, `reason` = the first refusal code or
     null, metadata `{targetAgentId, chainId?, mode}`); a refused claim (incl. `cap_reached`) answers `{ok: false, code,
     sentence}` and commits (the denied row and audit stay).
  3. Same transaction: `core.chatAgent.postAgentMessageIn(tx, { agentId, conversationId: turn.conversationId,
     threadRootId: the turn's thread root, body: "@<handle> <question>", idempotencyKey: "consult:<key>",
     inReplyToMessageId: turn.messageId, onBehalfOfUserId: H, onInserted })`; `onInserted(tx, questionId)`: chain upsert
     (`root_event_id` unique) → conditional `hops_used` UPDATE → hop insert (pending, deadline now + 5 min) → parent
     deadline bump. `created: false` (a retry of the key) → read the hop by (source, key) and answer its stored state;
     nothing is emitted again. Otherwise `deliverConsultQuestion` → the event → `hop.target_event_id` → audit
     `agent.consult.requested` (actor agent, user H, ids: chainId, hopId, questionMessageId, targetAgentId, depth, mode).
     No event (the target is at its daily limit; `buildMentionEvents` already scheduled the notice) → hop `refused` /
     `limit_reached`, `announceConsults([question])`, audit `agent.consult.refused`, 200 `{ok: false, code:
     "limit_reached", hopId, questionMessageId, sentence}`.
  4. A constraint violation while posting (a race) rolls the whole transaction back; the route maps the constraint name
     to its code (`agent_chain_hops_target_once` / `_not_root` → `target_in_chain`, `_one_pending` → `consult_pending`,
     the budget UPDATE with no row → `budget_exhausted` or `chain_closed`, depth checks → `depth_exceeded`; an unknown
     constraint is rethrown as 500), records it with a second short claim transaction (`reason` = that code) and
     answers it. Statuses per 07.7-01's answer table.
