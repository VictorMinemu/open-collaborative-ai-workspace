# Phase 07.13.1.1 Plan 03: Agent rename, naming rules and their delivery on the API Summary

The session's own agent can now rename it. The API decides each `session.rename` from the device that runs the session, during one of that session's turns, once per turn, and never over a title a person typed. Admins and project leads set naming rules. They are stored, audited by key or length only (never the text), and delivered to the device in the title call (`namingRules`) and in each turn's `sessionTools` grant.

## Accomplishments

- **Device Link:** `link.ts` now has `case "session.rename"`, which calls `hub.sessionToolHandler?.onSessionRename?.(device, frame, reply)`. `hub.ts` gains `DeviceSessionToolHandler`, `setSessionToolHandler` and a `sessionToolHandler` getter. `replyOn` now also sends `SessionRenameResultFrame`, checked against its own schema, on the requesting socket only (never queued, published or logged).
- **The decision:** `createSessionToolHandler(core, svc)` in `rename.ts`, registered in `index.ts` next to `setSessionHandler`.
  - It runs in a device-tenant transaction, under the session lock.
  - It claims the turn's single rename with `UPDATE work_prompts SET title_renamed_at = now() WHERE … IS NULL`.
  - It then calls `applyTitle(…, "auto", { by: "agent", userId: author, agentId, promptId, actorKind: "device" })`.
  - Errors answer `not_available` and are logged with the error name and the ids only.
- **Organization rule:**
  - `fromRow` and the upsert handle `sessionNamingRule` (blank is stored as null), and `changedKeys` lists it.
  - In `PUT /work-zone-policy`, `reauthorizeOrg` runs only when some other key also changed.
- **Project rule:**
  - `PATCH /work-projects/:unitId` accepts the partial body. `defaultVisibility` keeps its own path and audit.
  - `namingRule` upserts `work_project_settings.naming_rule` and writes the `work_project.naming_rule_changed { length }` audit (length 0 when cleared).
  - `projectChanged` runs once per request.
  - The detail returns `namingRule` (`projectNamingRuleOf`).
- **Delivery:**
  - `namingRulesFor(tx, s)` joins the organization rule with the rule of the session's linked team project (`joinNamingRules`). A personal repository gets the organization rule only.
  - `requestTitle` adds `namingRules` to the title payload when there are any.
  - `prepareCommand` builds `sessionTools { rename: titleSource !== "user", namingRules }` for `session.start` and `prompt` only. `hydrateCommand` adds it to the sent copy only.
