## Phase Goal

The bot sandbox image `sbx` (built and run only by `sandboxd`, ADR-0029) ships a document toolkit so a bot reads,
converts and searches common files inside its sandbox without installing anything: PDFs with a text layer, scanned
PDFs and images (OCR in Spanish and English), Word, Excel, PowerPoint and OpenDocument files, CSV/JSON/XML/HTML,
e-mails and archives, plus one helper, `ocw-extract`, that turns any supported file into bounded UTF-8 text, and the bot
is told the toolkit exists. Existing bots get it on their sandbox's next start. Owner, verbatim: "los bots deben poder
leer pdfs, imagenes, archivos, etc." and "Tienes que dejar en el sandbox varias herramientas para leer pdf y todo tipo
de archivos." (CONTEXT D-01 … D-12; DOC-01 … DOC-09; ships in v0.3.2; ADR-0043.)

**This plan's slice (tracer, image tier):** the Debian toolkit baked into `sbx` with its hardening files, the image
test runner wired into CI, and the container environment. Plus this hub: plan map, shared files, cross-plan names,
planner decisions PD-01 … PD-20, edge coverage, flagged assumptions, source coverage. Every later 07.17.1.1.1 plan
cites this hub.

  Until 03 creates the venv, the interpreter falls back to `/usr/bin/python3 -I` (the script picks the venv's when
  `/opt/ocw-tools/venv/bin/python3` exists in the image, checked with one `docker run … test -x`). A second, root,

- **`SHELL_ENV` (01; PD-05)** and `shellEnvCurrent(env)` (04, `spec.ts`).
- **`ocw-extract` CLI (03; D-04, D-11), the contract 05 and 06 rely on:**
  - `ocw-extract <file> [--ocr auto|always|never] [--pages A-B] [--max-chars N] [-o FILE] [--lang spa+eng]`;
    `ocw-extract --batch <dir|archive> [--out DIR] [--budget SECONDS] [--ocr …] [--lang …]`; `ocw-extract --types`;
    `ocw-extract --help`.
  - Exit codes: 0 ok · 2 usage · 3 unsupported type · 4 not found or outside /workspace · 5 encrypted (password
    needed) · 6 too large or a cap hit · 7 conversion failed or timed out · 75 batch budget reached, more to do.
    Every non-zero exit prints one line to stderr starting `ocw-extract: ` with a plain reason and, where useful,
    what to do next.
  - Stdout of single-file mode: a header `=== <name> · <type> · pages <a>-<b> of <n> · text <t> · ocr <o> ===`
    (pages and counts only for paged types), then `--- page <N> ---` or `--- page <N> (ocr) ---` blocks (PDFs),
    `### sheet: <name>` blocks (spreadsheets, CSV), `### slide <N>` blocks (presentations), `### attachment: <name>`
    lines (mail), one `<path> · <size> bytes` line per entry (archives, listing only). Text is UTF-8 NFC with no BOM.
    `--max-chars` default 12 000, ceiling 15 000 on stdout (under `SANDBOX_LIMITS.outputTailBytes` = 16 384 with the
    header and footer); beyond it the output stops and ends with `[truncated: <N> more characters; use -o FILE or
    --pages]`. With `-o FILE` the whole text goes to FILE (under /workspace, at most 64 MiB) and stdout is one line
    `wrote <FILE> · <chars> characters · pages … · ocr …`.
  - Batch: output root default `/workspace/extracted/<basename of the input>`; `<rel>.txt` per file (e.g.
    `docs/a.pdf.txt`), `<rel>.d/<member>.txt` per archive member, `_index.tsv` with the header
    `path	size	mtime_ns	type	method	pages	next_page	chars	status	note` (tabs; status one of `done`, `partial`,
    `failed`, `unsupported`, `skipped`); originals are never copied, moved or modified; `--budget` default 540, at most
    590; stdout is one summary line `batch: <done>/<total> done · <partial> partial · <failed> failed · ocr pages <n> ·
    <out>/_index.tsv`, plus `more to do: run the same command again` when it exits 75.
  - Constants (`ocw_extract/bounds.py`): `DEFAULT_MAX_CHARS = 12_000`, `STDOUT_MAX_CHARS = 15_000`,
    `OUTPUT_FILE_MAX_BYTES = 64 * 1024 * 1024`, `OCR_MIN_PAGE_CHARS = 25`, `OCR_PAGES_PER_CALL = 50`, `RASTER_DPI = 300`,
    `RASTER_SCALE_TO = 3500`, `IMAGE_OCR_MIN_SIDE = 200`, `ARCHIVE_MAX_TOTAL_BYTES = 1024 ** 3`,
    `ARCHIVE_MAX_ENTRIES = 10_000`, `ARCHIVE_MAX_RATIO = 100` (applies to entries over 10 MiB),
    `ARCHIVE_MAX_DEPTH = 1`, `BATCH_DEFAULT_BUDGET_S = 540`, `BATCH_MAX_BUDGET_S = 590`, per-step timeouts
    (seconds): pdfinfo/pdftotext 60, pdftoppm per page 60, tesseract per page 120, soffice 180, exiftool 30,
    msgconvert 60, 7zz list 60, 7zz extract 300.

- **PD-05 Environment (D-03; RESEARCH Pattern 1).** `SHELL_ENV` = `HOME=/workspace`,

  the toolkit (installer and review runs never see it). An approved Python package with a toolkit package's name is
  shadowed by the toolkit's (D-03's order); 07 documents it.
- **PD-06 `ocw-extract` runs isolated (03; RESEARCH Pattern 2, Pitfall 3).** Launcher shebang
  `#!/opt/ocw-tools/venv/bin/python3 -I`, then `sys.path.insert(0, "/opt/ocw-tools/lib")`: PYTHONPATH and the cwd never
  reach it. Every child is an argv list (never a shell), started with `start_new_session=True` and killed with
  `os.killpg` on its step timeout. Children get a **fresh minimal environment**: `PATH` (system paths only),
  `LC_ALL=C.UTF-8`, `HOME` and `TMPDIR` set to a private scratch directory, `OMP_THREAD_LIMIT=1`,
  `OPENBLAS_NUM_THREADS=1`, and **no** proxy variables (LibreOffice and ImageMagick have no way out at all, which
  closes the LO external-link SSRF class for every conversion `ocw-extract` runs; D-05, D-08). Scratch: one private
  directory per run under `/workspace/.ocw-extract-tmp/` (mode 0700; disk, not the memory-backed `/tmp`), removed in a
  `finally`, including after a timeout; a leftover older than one hour is removed at start. LibreOffice always gets a
  throwaway profile (`-env:UserInstallation=file:///tmp/ocw-lo-<random>`, removed after) and `--headless --norestore
  --nolockcheck --nologo --nodefault`.
- **PD-07 Output bounds (D-11; RESEARCH Pitfall 2, Anti-Patterns).** sandboxd keeps the **tail** of stdout, so
  `ocw-extract` caps the **head** (Cross-plan contracts); a bot reads large results with `-o FILE` and
  `ocw_sandbox_read`. PDFs are processed one page at a time (pdftotext per page; OCR rasterizes one page with
  `pdftoppm -r 300 -scale-to 3500 -gray -png -f N -l N`, OCRs it and deletes the PNG before the next).
- **PD-08 Batch (D-04 as refined by D-11; RESEARCH Open Question 2 → RESOLVED).** "Writes `.txt` next to a copy" is
  read as D-11 states: a `.txt` mirror tree plus `_index.tsv` under `/workspace/extracted/…`; originals are never
  copied (no `--copy` flag), moved or modified. Resume: an entry whose `size` and `mtime_ns` match a `done` row is
  skipped; a PDF is resumable per page (`partial` with `next_page`, text appended to `<rel>.txt.partial`, renamed to
  `<rel>.txt` when done); the budget is checked before each file and each OCR page; exit 75 while work remains, 0 when
  every entry is `done`, `failed` or `unsupported` (failures are counted in the summary and the index, not in the exit
  code). Symlinks are never followed; the output root is skipped when it lies inside the input. A top-level archive
  given to `--batch` is one entry whose members are extracted (PD-09) and mirrored under `<archive>.d/`. Cross-turn
  continuation is phase 07.17.1.1.2's.
- **PD-09 Archives (D-05; RESEARCH Security, A5).** Single-file mode lists only. Batch first lists with `7zz l -slt`
  and refuses the archive (status `failed`, note `caps: …`; exit 6 when it is the top-level argument) when the listed
  total exceeds `ARCHIVE_MAX_TOTAL_BYTES` or the free space of `/workspace`, the entries exceed
  `ARCHIVE_MAX_ENTRIES`, an entry over 10 MiB has a size / packed ratio above `ARCHIVE_MAX_RATIO`, any path is absolute
  or contains `..`, or any entry is a link; then extracts with `7zz x` (never with the switch that stores symbolic links) into a scratch directory, mirrors
