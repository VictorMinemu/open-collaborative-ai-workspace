# Phase 07.6 — UI Design Contract

> Visual and interaction contract for automations (list, editor, run history, webhook and mailbox triggers), the
> natural-language confirmation card, the personal digest, watched records on board cards, the three server-composed
> cards (automation run, inbound item, watched-record change) and the Work Zone → memory surfaces. Generated by
> gsd-ui-researcher, verified by gsd-ui-checker. Every value comes from the existing tokens in
> `apps/web/app/globals.css` and the existing primitives in `apps/web/components/ui/*`, plus the `ui/tabs` wrapper
> from 07.1-04. This phase adds **no new primitive, no new CSS variable, no new font and no new web dependency**.
> Where this file and a plan differ, this file wins and the difference is listed in **§ Plan reconciliation**.

Sources: `07.6-CONTEXT.md` (C-01…C-05, D-01…D-08; D-07 holds the accepted design and owner-facing defaults),
`07.6-RESEARCH.md` (Patterns 2-10, Pitfalls 1-9, "UI Surfaces Needing a UI-SPEC", Proposed Plan Split 07.6-15…18),
`07.1-UI-SPEC.md` (card tile, card strip, card menu, `ui/tabs`), `07.2-UI-SPEC.md` (platform-owned card mirror,
"Created by the workspace" badge, status and notice tones, memory proposal statuses), `07.4-UI-SPEC.md` (settings list
pattern, status pills, Keychain `Username & password` items, shared-use dialog and `?share=` links, write-only fields),
`07.5-UI-SPEC.md` (block values in cards, label overrides for linked cards, Work Zone card language), `AGENTS.md`
(principles 2, 4, 6, 8, 9, 11, 12; Developer Profile: responsive first, mobile verified, clear CTAs, no filler copy,
never remove existing UI). Code read on `feat/ops-features-plan`: `globals.css`, `components.json`,
`ui/{badge,button,dialog,panel-dialog,sheet,select,switch,form-field,input,textarea,skeleton,spinner,tooltip,
dropdown-menu,separator}.tsx`, `chat/agent-card.tsx` (`KIND`, `STATUS`, `StatusPill`, `DecisionLine`,

summary, never rendered), `bots/{bots-gallery,provider-bits}.tsx` (`MeteredBadge`, bots `Grid`),
`work-zone/{session-view,meta}.tsx` (session header, `STATUS` labels: `completed` = "Ended"),

## Information Architecture and Navigation

| Entry | Route | Shows |
|-------|-------|-------|
| Bots page, section nav "Automations" (`Zap`) | `/bots/automations` | Own automations (and everyone's for `automation.manage` holders) |
| Automation editor | `/bots/automations?edit=<id>` · `?new=1` · `?draft=<approvalId>` | Sheet over the list; back button closes it |
| Run history | `/bots/automations?edit=<id>&tab=runs` | Same sheet, Runs tab |
| Card Open action | `/bots/automations?edit=<id>&tab=runs&run=<runId>` | Opens the run highlighted (a valid `AgentCardRoute`, `/bots` prefix) |
| Settings › Digest (`Newspaper`), account group, after Notifications | `/settings/digest` | The member's digest |
| Board card menu "Watch external record…" and card strip "Watch record" | Dialog over the board / thread | Link a card to an external record |
| Work Zone session (status Ended or Archived) | `/work-zone/<id>` (existing) | Memory strip above the composer |
| Organization › unit detail, card "Linked repositories" | `/settings/organization?unit=<id>` (existing) | Repository → unit mapping |

- **Bots section nav.** `/bots` and `/bots/automations` share a 48 px row under the `PageHeader`: `Bots` · `Automations`.
  Because each item changes the URL, it is a `<nav aria-label="Bots sections">` of two Next `Link`s with
  `aria-current="page"`, styled with the underline variant classes of `ui/tabs` (2 px primary indicator, `min-h-11`
  hit area below 768). It is not an ARIA tablist (links between pages are not tabs).
- `/bots/automations` is a static segment; it coexists with 07.2's dynamic `/bots/<agentId>` (static wins in Next.js;
  agent ids are UUIDs).
- No new main-nav entry. Automations live with their bots.
- `ACCOUNT_SECTIONS` order after this phase and 07.4: Profile, Security, Notifications, **Digest**, AI chat,
  Connections, Keychain.

## Interaction Contract

### Automations list and editor
- Opening a row, `New automation`, `?edit=`, `?new=1` and `?draft=` all open the same sheet; closing removes the param
  (`router.replace`), Back closes it.
- Unsaved changes + close → `Discard changes?` (`Keep editing` / `Discard`), the 07.4 template-editor rule.
- Validation in place before any request; API refusals render as a form-level blocking notice at the top of the body
  with the fixed sentence for the code (§ Copy › API errors); 409 `version` → `This automation changed while you were
  editing.` + `Reload`.
- `Run now`: immediate (no confirmation, it obeys the same limits), toast `Running “{name}” now.` + action `Open runs`.
- Pause / Resume from the menu or banner: immediate, toast `Paused “{name}”.` / `Resumed “{name}”. Next run {when}.`
- Delete: confirmation (§ Copy), toast `Deleted “{name}”.`; a webhook automation's endpoint stops accepting (410).
- Live: `automation.updated` / `automation_run.updated` on the viewer's `user:` stream (ids only) invalidate the list
  and the open sheet.

### Natural-language card
- `Create automation` / `Discard` confirm first (existing `DecisionButtons`), sending `{outcome, actionHash}` of the card
  on screen; 409 `approval_action_changed` → toast `This proposal changed. Open it to review again.` + `refreshCard`.
- `Edit →` opens the editor with the draft; saving closes the proposal as `Created with changes`; cancelling leaves the
  card Proposed.

### Webhook and mailbox
- Copy buttons: icon → `Check` for 2 s, polite live region `Copied`.
- The reveal dialog cannot be dismissed before the checkbox is ticked; the secret is never refetchable.
- `Test connection` and `Find` never save anything.

### Digest
- Chips and switches change local state only; `Save digest` sends everything; `Preview` uses the unsaved form;
  `Send a test now` uses the saved settings (button disabled with `Save first.` when the form has unsaved changes).

### Watched records
- `Start watching` saves and closes; the strip row appears live (`watched_record.updated` on the `conv:` stream, ids
  only); the first check runs immediately and sets the baseline silently (no change card for the first snapshot).
- `Check now` is rate-limited to once a minute per record (button disabled with `Checked just now`).
- A bot update refused by compare-and-set never changes the external record; the conflict card is posted and the
  watch's snapshot moves to the new values.

### Work Zone
- `Propose to memory` → confirmation → strip shows `Writing a summary…` → `Pending` when the proposal exists
  (`approval_request.updated` and `work_session.updated` refresh it). Double clicks are ignored (button pending).

### Focus management
- Sheet and dialogs focus their first input (confirmations: Cancel; secret reveal: the Copy button); closing returns
  focus to the trigger (row, `⋯`, `New automation`, strip button).
- After saving a new automation focus moves to its row in the list (highlighted 2 s, no motion under reduced motion).
- `?run=` focuses the highlighted run row (`tabIndex=-1`).
- Desktop tab order on `/bots/automations`: rail → header action → section nav → Mine · Everyone → rows (open, `⋯`).

### Reduced motion
- No smooth scroll; skeletons `motion-reduce:animate-none`; the running pill's ping is already hidden; highlight rings
  do not pulse; the Advanced and How-to-send toggles open without height animation.
