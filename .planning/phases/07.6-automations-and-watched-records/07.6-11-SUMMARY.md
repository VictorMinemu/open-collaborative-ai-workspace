# Phase 07.6 Plan 11: IMAP mail trigger Summary

**A mail automation signs in to IMAP with a Keychain `Username & password` item, connects to the address the egress
guard pinned over verified TLS, reads only new mail read-only (EXAMINE + PEEK), stores each mail once and hands it to
21's inbound worker; loop mail is skipped and every failure is a fixed code on the mailbox.**

## Credential path and egress rule (plan mode, P-19)

**Credentials (R8).** A mailbox stores only `vault_item_id`; there is no username, password or token field anywhere in
its request, row or DTO (`MailboxConfigInput` is strict). At save, at every poll and in the test route the API calls
`basicCredentialsFor(core, tx, perms, { vaultItemId, userId })`:

1. The item must exist for that person: a personal item only of its owner (RLS and an explicit owner check; anyone
   else, admins included, gets `not_found`), a unit or organization item only when its unit row is readable.
2. It must be of kind `basic`.
3. The resolver must allow the person `vault.use` on the item's unit (or the organization): on the request when there
   is one (the strict authz check sees it), request-less for the poller (`perms.decide`, the mailbox owner).
4. The value opens through the existing sealed path with the item's own AAD (`openVaultSecret`); a value that does not
   open is `not_usable`.
5. The configured `host:port` must match one of the item's allowed hosts (`mailHostAllowed`: exact host or a strict
   subdomain of a `*.` pattern; the pattern's port, else 993).

The poller opens the key in a transaction that ends before any connection. The username and password only go into the
ImapFlow `auth` option; no log, audit row, error or DTO carries them (ImapFlow's logger is always off, errors become
fixed codes, no server text is stored). A save refuses a key that fails (1)–(4) with 400 `mailbox_key_not_usable` and a
host outside (5) with 400 `mailbox_host_not_allowed`; the test route answers 403 `mailbox_key_not_usable` for a key that
is not the caller's to use and `{ ok: false, code: "host_not_allowed" }` without connecting for (5).

**Egress (P-17).** `resolveEgressAddress(egress, host, { port, privateAllow })` applies exactly the checks
`egress.fetch` applies, sharing its code: platform names and `host:port`, refused names (`localhost`, metadata),
every resolved address classified (loopback, link-local, metadata, reserved, documentation refused; RFC 1918 / CGNAT /
ULA refused unless the exact `host:port` is in `privateAllow`), platform addresses refused even when allowed, test
hosts only for their mapped loopback address. It returns the first checked address and the client connects to it only
(no second resolution). `privateAllow` comes from 07.4's `privateAllowFor`: empty for personal items, the item's own
hosts that the admin's private-host list also names for unit items.

**TLS.** Real hosts: `secure: true` (implicit TLS), `host` = the pinned IP, `servername` = the configured host (an IP
literal is verified as itself), `tls.rejectUnauthorized: true`, TLS 1.2+. `OCW_EGRESS_TEST_HOSTS` names (test-only,
refused in production by env validation): plain IMAP without STARTTLS. The `certificate` case is proven through the
production path: the alias `mail-tls.ocw.test` (not a test host) resolves to a private address of the machine where
GreenMail's IMAPS port is published, is admitted only by an admin private-host entry and a unit key, connects, and
fails on GreenMail's self-signed certificate; without the entry it is refused before connecting.

## What was built

- **`lib/egress.ts`**: `resolveEgressAddress` and `EgressResolver` (`createEgress` / `egressFor` return
  `Egress & EgressResolver`); `precheck` and the connector lookup now share `targetOf` and `resolveChecked` with it. No

- **`keychain`**: `basicCredentialsFor` and its `BasicCredentials` type, exported from the module index.
- **`imap.ts`** (no database): `imapOptionsFor`, `withMailbox` (resolve → connect → `getMailboxLock(folder,
  { readOnly: true })` → work → release → `logout()` in `finally`), `readNewMail` (UID search above the cursor, filtered
  because `n:*` also returns the newest old message, oldest first, 50 per poll, `fetch(uids, { uid, source: {
  maxLength: 256 KiB } }, { uid: true })` = BODY.PEEK), `mailErrorCode` (`auth_failed`, `folder_missing`,
  `certificate`, `unreachable`, `unknown`), `tryMailbox`, `uidKey`, `mailHostAllowed`.
- **`mail-parse.ts`**: `parseMail` with postal-mime: Message-ID only when it is one `<id>`; thread key = first
  References id → In-Reply-To → Message-ID; `Name <address>` sender; HTML-only mail converted by `htmlToText` (comments,
  `head`/`script`/`style`/`template` dropped, block tags as line breaks, entities decoded; hand-written scanners, linear on
  hostile input); text capped at 32 768 characters; loop filters `own_header` (X-OCW-Automation-Run), `self` (From =
  the mailbox's sign-in address), `auto_submitted` (RFC 3834, any value but `no`), `bulk` (Precedence bulk/junk/list).
- **`mailboxes.ts`**:
  - `mailTrigger`: `onCreate` (key and host checks, row, `mailbox.created`, baseline after commit), `onUpdate` (a new
    key, host, port or folder resets the cursor and baselines; any save clears a failure and retries at once;
    `mailbox.updated` with the changed field names), `onDelete` (row removed, events cascade, `mailbox.deleted`), `view`
    (the `Mailbox` DTO; `paused` while the automation is not active; the key's name only).
  - `pollMailbox`: reads the mailbox, opens the key as the owner, connects outside any transaction, then in one
    transaction re-checks the mailbox is unchanged, inserts each kept mail as an `accepted` event (on conflict:
    `duplicate_count + 1`) with its `automation.inbound` job in the same transaction, advances the cursor and counters,
    and audits `mail.received { mailboxId, automationId, count, skipped, duplicates }`. Paused and the hourly cap are
    21's. Failures set `auth_failed` (sign-in, key gone or not usable, host no longer allowed; 30-minute back-off) or
    `unreachable` (everything else; the interval), audited `mailbox.poll_failed` on a change of status or code.
  - `mailboxTick` (every minute): `app.due_mailboxes`, claim (next poll one interval ahead), queue `mailbox.poll`.
  - `testMailbox` and the routes `POST /api/v1/mailboxes/test` (needs `automation.create`; audited `mailbox.tested`
    with the code) and `GET /api/v1/automations/:id/mailbox` (through `service.get`, so the same visibility).
- **`app.due_mailboxes`** (post-migrate.sql): `auth_failed` mailboxes are due after their back-off, or at once when
  their Keychain item's `updated_at` is newer than the mailbox's (the failure). Paused automations stay off the list.
- **Contracts**: `Mailbox.vaultItemId` is nullable (the item can be deleted; the FK sets it null).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Correctness] `app.due_mailboxes` polls `auth_failed` mailboxes again.** The plan requires a back-off of
at least 30 minutes and a resume once the item's password changes, but 02's function never returned `auth_failed`
mailboxes, so nothing could resume them. The function now returns them after `next_poll_at` (30 minutes) or at once
when their Keychain item changed after the failure; 02's schema test was extended for both cases and for a paused
automation. No migration: post-migrate.sql re-creates the function on every migrate. Commit `100bb084`.

**2. [Rule 1 - Bug] 05's seam test expected `trigger_unavailable` for mail.** With the adapter filled, an unknown key is
refused by it with 400 `mailbox_key_not_usable` (still leaving nothing). One line changed in
`automation.int.test.ts`; the webhook half belongs to 10. Commit `100bb084`.

**3. [Rule 2 - Correctness] `Mailbox.vaultItemId` nullable.** The mailbox's key FK is `SET NULL`, so a deleted key left
a row the DTO could not describe. The poll then records `auth_failed` / `key_not_usable`.

### Interface notes

- `resolveEgressAddress` takes the guard as its first argument (`resolveEgressAddress(egress, host, policy)`): the
  platform hosts, the test hosts and an injected resolver live on the guard instance.
- `basicCredentialsFor` takes `perms` and an optional `req` (the strict authz check needs a request decision on the
  test route) and also returns `privateAllow`.
- `pollMailbox` and `testMailbox` live in `mailboxes.ts` (they read and write the database); `imap.ts` stays
  database-free (`withMailbox`, `readNewMail`, `tryMailbox`).
- The baseline after a save runs in the after-commit hook of the save's transaction (awaited before the response), so
  no IMAP connection is held inside a database transaction. If it fails, the first poll baselines instead.
- `envelope` is not fetched: postal-mime parses the capped source, which carries every header used.
