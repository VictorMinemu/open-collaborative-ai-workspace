## The helpers (exports kept stable for 07.9-10)

- **`createTeamProject(admin, { name, parentName?, members })`** returns `TeamProject { unitId, parentId, ownParent }`.
  - It calls `GET /units`, then `POST /units` for the department `"<name> department"` unless a unit called
    `parentName` already exists.
  - It then calls `POST /work-projects { name, parentId }` (the creator becomes the lead automatically), and
    `POST /units/:id/members` once per member.
  - It is retry-safe: it reuses a project of the same name under the parent, and treats `409 already_member` as
    success.
- **`linkRepo(lead, unitId, projectId)`** calls `POST /work-projects/:unitId/repos`.
- **`shareDevice(owner, deviceId, userId, maxMode = "default")`** calls
  `PUT /devices/:id/grants/user/:userId`.
- **`removeTeamProject(admin, project)`** (added in Task 2) does the following:
  - unlinks every repository with `DELETE …/repos/:projectId`, which needs only `work_project.manage`, so a revoked
    device's repository unlinks too;
  - deletes the project unit;
  - deletes the helper-named department, keeping it on `409 unit_has_children`;
  - does nothing if the project is already gone (404).

Every response is parsed with its contract schema (`OrgUnitList`, `OrgUnit`, `WorkProjectDetail`, `UnitMember`,
`DeviceGrant`, `Ok`). A refusal throws `"<METHOD> <route>: HTTP <status> <code>"`. The helpers never touch the
database: the acceptance grep for `pg.` and `@ocw/db` prints nothing. Unit tests: 13/13.

## Deviations from Plan

1. **[Rule 3 - Blocking] `removeTeamProject` added to the helper module (Task 2).** admin-org's `clearUnits` deletes
   every unit and expects success. A team project with linked repositories answers `409 unit_has_repositories`, so
   projects left by the desktop Work Zone specs would have failed admin-org on mobile. Each touched spec now removes
   its project in `finally`. The export is additive and `createTeamProject` keeps its plan shape: `TeamProject` adds
   `ownParent` to `{ unitId, parentId }`. Unit-tested (3 cases).
2. **[Rule 2] Retry safety in `createTeamProject`.** CI runs with `retries: 1`, and a retried test would otherwise hit
   `unit_name_taken`. The helper reuses the parent and the project by name. It also tolerates `409 already_member`,
   which happens because the creator joins as lead automatically.
3. **No separate RED commits.** Both tasks wrote the failing tests first (missing module, then 7 failing cases).
   RED and GREEN were committed together because `pnpm verify` must be green before every commit.
4. **Wider e2e set than the plan's verify command.** It adds approval-cards, tool-approvals, codex-subscription,
   agent-cards, module-access, smoke, admin-org and admin-members, which together cover every spec that touches Work
   Zone and the unit cleanup.
5. **No product defect found.** No product code changed.
