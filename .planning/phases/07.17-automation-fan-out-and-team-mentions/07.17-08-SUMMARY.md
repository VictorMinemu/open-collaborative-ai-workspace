# Phase 07.17 Plan 08: Bots move the cards their automation opened Summary

**`openedCardExemption` lets a tainted or session-read bot turn move and set waiting on its own thread's card, only when this bot's automation opened that card and an admin set the profile's `actOnOutsideContent`; the tool cap stays in the same UPDATE and the move's audit carries `outsideContent` / `sessionOutputExempt`.**

## Intended change (plan mode, PD-03)

Permissions/audit/tenant data in `apps/api`: in `agent-channel/board.ts` `gateTurn`, for `route === "update"` only and only
when the turn row is tainted or `session_output_read`, compute `openedCardExemption` (turn message root = card, in the
turn's conversation; an `automation_conversations` row for that card whose automation's `agent_id` is the turn's bot,
under tenant RLS; `loadBotProfile(...).actOnOutsideContent === true`). If true, the counting UPDATE keeps only the turn
id and the tool cap; otherwise today's statement. The flags reach `updateBoardCard` through a new optional
`auditFlags` arg, merged into `board.card.moved` / `board.card.updated` metadata (no new action name). Create and
read paths and the `not_author` text check unchanged.
