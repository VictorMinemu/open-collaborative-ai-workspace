# Phase 07.7 Plan 07: OpenClaw agent-to-agent off and a two-bot consult in a real cell Summary

**The cell config pins OpenClaw's own agent-to-agent off (`tools.agentToAgent.enabled: false`,
`tools.sessions.visibility: "self"`), and the pinned 2026.9.7 image boots with both pins. In a real cell, Archie consults
Bea only through `ocw_consult_agent` and `POST /consultations`. Bea answers the question, which carries its origin, and
Archie replies to her answer. A tainted return turn cannot consult again.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Security, threat T-07.7-07-01] `reconciler.ts` filters session and agent-to-agent tools (outside the plan's file list)**
- **Found during:** Task 2 (RED).
- **Issue:** The plan expected no production change, on the grounds that `isDangerousToolName` already filters these
  names. That predicate lives in contracts and runs in the API. The cell's `allowedAgentTools` checked only the exact
  `DANGEROUS_TOOLS` list, groups, families and wildcards. A snapshot listing `sessions_send`, `subagents`,
  `conversations_turn` or `agents_wait` put them in the bot's `alsoAllow`.
  - Today OpenClaw's per-agent `group:sessions` and `group:messaging` denies still cover its core tools.
  - The API never lists these names.
  - The cell layer named in the threat register was still missing.
- **Fix:** add a single regex mirror in `allowedAgentTools` (`/^(?:sessions?_|conversations_|agents_)|^subagents$/u`).
  It only tightens the filter: no permission, gate or deny is weakened, and the three dangerous lists are untouched.
- **Why not stop:** the plan says to stop and report when a production change is needed. Here the missing piece is a
  mitigation the plan's own threat register lists (Rule 2). It is a one-line tightening covered by a test tied to the
  contracts' predicate, and the orchestrator runs with full autonomy for non-critical decisions. **Flag for review:**
  whether it should live in 07.7-01's scope instead.
- **Files:** `apps/openclaw-channel/src/reconciler.ts`, `apps/openclaw-channel/src/reconciler.test.ts`.

**2. [Rule 1 - Test bug] Bots are rendered under `agents.entries`, not `agents.list`**
- The first smoke run failed in step 2 because it read `agents.list`. The plugin writes `agents.entries["ocw-<id>"]`
  (`applyPlanToDraft`). The scenario now reads `entries`.
- **Pre-existing, out of scope (deferred):** the 07.6 `automation` scenario's config check uses `c.agents?.list ?? []`.
  Its `agents.every(... group:sessions)` assertion is therefore vacuous: it passes on an empty list. The cell-wide
  `tools.deny` check in the same block still holds, and the `consult` scenario now checks the per-bot entries for real.
  Suggested fix for 07.7-11 or a quick task: read `Object.values(c.agents?.entries ?? {})`.

**3. Smaller choices**
- The plan named the scenario `consult` and the task title calls it `mention-consult`. The script uses `consult`
  (`SMOKE_ONLY=consult`, `want consult`), as the acceptance grep requires.
- The question, the consult reply and the tainted return are generated inline from the fixture, as in the `card`
  scenario. The question's message id (`…d102`) and the chain and hop ids are fixed test ids. The fake API's own hop ids
  are random and do not appear in `/__test/state`.
- The step that checks "the gateway is listening" uses the gateway's `http server listening` log line.

**Total deviations:** 1 security tightening outside the file list and 1 test bug. A pre-existing vacuous check is
deferred. **Impact:** no scope change; no pin dropped.
