# Phase 07.7 Plan 04: Consult route end to end Summary

**`POST /agent-channel/v1/consultations`: a bot's consult becomes its visible `@target question` in the turn's thread,
a chain and a hop opened under the DB guards, and a turn for the target bot on behalf of the same human with a
server-built `origin`; every refusal is a precise, audited `{ok: false, code, sentence}` that leaves nothing behind.**

## Working notes (plan mode, P-19: permissions, audit, tenant isolation)

Intended seams, applied as written:

- Bridge: additive `trigger: "consult"` and `chain?: ChainDelivery`; `PostAgentMessageInput` and the mention handler
  unchanged; `if (mention.author.kind !== "user") return [];` untouched.
- Route: tx0 `agent_turns` (RLS) → human; tx1 as H: `liveTurn` → retry read by (source, key) → pre-checks (tainted,
  not_in_turn, not_channel, chain_closed, depth_exceeded, target_not_found, target_unavailable, target_personal,
  target_is_self, target_in_chain, target_not_member, not_allowed, budget_exhausted, consult_pending) →
  `claimToolCall` (reason = first refusal) → `postAgentMessageIn` (as Archie, in reply to the turn's message, on behalf
  of H) whose `onInserted` upserts the chain, spends the budget with the conditional UPDATE, inserts the hop and bumps
  the parent deadline → `deliverConsultQuestion` → `target_event_id` → `agent.consult.requested`. No event → hop
  `refused/limit_reached`, `announceConsults`, `agent.consult.refused`, 200 `limit_reached`.
- Decision: one call, `organization.messagingDecision` (07.7-03), no policy logic duplicated.
- Audits: `bot.tool_call` (claim) and `agent.consult.*` carry ids, depth, mode and codes only; the question text is
  never logged or audited (asserted).
