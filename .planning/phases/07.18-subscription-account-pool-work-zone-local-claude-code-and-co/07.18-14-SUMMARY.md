# Phase 07.18 Plan 14: bots draw from the pool Summary

The cell now gets the account pool in its snapshot. Claude setup-tokens arrive as `OCW_POOL_TOKEN_<n>` with
`anthropic:pool-<id>` profiles and the strategy's order, with the org Anthropic key last. ChatGPT accounts arrive as
cell profiles with their enabled flags and order. Each "ChatGPT for bots" sign-in is stored as its own cell profile
(`openai:pool-<id>`). The pre-07.18 sign-in is adopted as the first pool account. Every pool change the bots see tells
the cell to re-read its config, and removing one bot account signs out only that profile. Tokens travel only over the
authenticated `GET /cell`; the audit lists account ids only.

## What was built

- **Task 1 (tracer): `cell-pool.ts` `cellAccountPool`, `GET /cell`.**
  - Claude: the live token rows that serve bots (scope `all` or `bots`, enabled, credential ok; PD-18). They are opened
    with `openPoolToken`; a token that does not open is skipped and logged by account id. Cooling tokens are still sent
    (OpenClaw cools them itself).
  - ChatGPT: the live `cell_profile` rows with `enabled`.
  - Order: failover gives the explicit order. Round-robin and weighted give `null` while every bot account is sent,
    else the explicit order of those sent. `apiKeyLast` is true when the cell has the Anthropic provider key.
  - `withheldSubscriptions` drops `openai-codex` from `subscriptions` when the pool manages ChatGPT and has no enabled
    account. `agent_cell.config_read` gains `poolAccounts` (ids).
  - `CELL_CLAUDE_TOKENS` stays true (A-05 held in 07). `claudeTokens: false` is the tested fallback.
- **Task 2: sign-in per pool account and adoption.**
  - `providerAuth.start` takes `poolAccount { label }`. It picks the account id, audits
    `account_pool.sign_in_started` and sends `profileId` on `provider.auth.start`. The flow record keeps
    `{ accountId, label, profileId }`.
  - `report` applies `applyCellProfileReport` in the same transaction as the provider row:
    - a `connected` flow report adds an enabled `cell_profile` row. It uses the reported profile id, else the requested
      one (A-03). The origin is `admin` for a pool sign-in and `adopted` for a Models page sign-in. It is audited
      `account_pool.account_added` and `account_pool.signed_in`.
    - a credential state report with `profiles` adopts unknown profiles (label = e-mail or "ChatGPT account"). It marks
      missing ones removed (`account_removed`, reason `not_in_cell`) and moves each credential to `ok` or
      `needs_sign_in`.
  - The provider row needs a reconnect only when no reported profile is usable. The admin route body accepts
    `poolAccount: BotPoolSignIn`.
- **Task 3: `onChange` → the cell.**
  - `notifyCellOfPoolChange` (agent/subscription.ts) appends one `cell.config.changed` (`providers.updated`) for
    either policy, for a cell profile, and for a Claude token or reorder outside scope `work_zone`. A device slot change
    appends none.
  - A removed cell profile also gets `provider.auth.revoke` with `profileIds: [its id]`.
  - `revokeSubscriptionInCell` takes `{ profileIds }`; without it, every profile is revoked as before.
  - `app.ts` wires it into `createAccountPoolModule`.

## Deviations from Plan

### Owner-directed (D-15 and the orchestrator's note)

**1. Bots stay off ChatGPT when every pool account is disabled or removed**
- **Issue:** OpenClaw cannot hold an empty explicit order: writing one clears it, and every stored profile becomes
  usable (07's SUMMARY). The plan did not cover this case.
- **Fix:** `cellAccountPool` returns `withheldSubscriptions`. `GET /cell` leaves `openai-codex` out of `subscriptions`
  when the pool has ever held a ChatGPT bot account and none is enabled now. With no ChatGPT pool rows at all (the
  pre-07.18 sign-in before adoption), the subscription is listed as before.
- **Test:** "every ChatGPT pool account disabled or removed keeps bots off the subscription".
- **Commit:** 30e7545c

### Auto-fixed / adjusted

**2. [Rule 2 - Correctness] A second, different sign-in while one runs is 409 `sign_in_in_progress`**
- Before this plan, a start during an active flow silently returned that flow. With pool sign-ins, that would attach
  the admin's new label to another account's sign-in. The same request stays idempotent (a double click).
- **Commit:** a7d2802c

**3. [Design] `cellAccountPool` signature**
- The plan wrote `cellAccountPool(tx, secrets)`. It is `cellAccountPool(tx, core: { secrets, log }, { anthropicKey,
  claudeTokens? })`: the log is needed for "logged by id", `anthropicKey` decides `apiKeyLast`, and `claudeTokens`
  makes the A-05 fallback testable. It returns `{ accountPool, withheldSubscriptions, accountIds }`.
- **Commit:** 30e7545c

**4. [Design] `agent/index.ts` also exports `notifyCell` (Task 2)**
- `cell-pool.ts` tells the cell after a report changes the pool. Modules import each other only through `index.ts`.
- **Commit:** a7d2802c
