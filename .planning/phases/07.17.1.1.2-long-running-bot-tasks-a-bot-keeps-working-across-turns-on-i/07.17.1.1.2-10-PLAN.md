## Phase Goal

See `07.17.1.1.2-01-PLAN.md` (PD-11, PD-12, PD-20). **This plan's slice:** the live task card people see: the server's
task link on every read, `viewerCan.stop`, and the web card with its Stop button wired to 08's route.

<objective>
Add a `TaskCards` provider to the chat-agent bridge (`linkOf`, `canStop`), implement it in `task-card.ts` and register
it from `registerTaskUserRoutes`; compose `card.task` and `viewerCan.stop` in `chat/card-actions.ts`; render the task card
in the web with `TaskCard` and `useStopTask` (D-05, D-07).

Purpose: the owner's "visible and stoppable": the card updates in place every turn and the right people can stop it.
Output: one provider, the card composition, one web component with its mutation, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → every reader | Card content and the task link go to everyone who reads the thread |
| browser → Stop route | A person's click; the server re-decides (08) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.17.1.1.2-10-01 | Elevation of privilege | Stop shown to the wrong people | medium | mitigate | `viewerCan.stop` from `mayStopTask`; the server re-decides on the route; role matrix |
| T-07.17.1.1.2-10-02 | Spoofing | the bot faking budgets or status on the card | high | mitigate | `card.task` composed from the row by the server; platform-owned card (08) |
| T-07.17.1.1.2-10-03 | Information disclosure | viewer fields on realtime events | medium | mitigate | `viewerCan` only on REST snapshots; the realtime case |
| T-07.17.1.1.2-10-04 | Information disclosure | another organization's task link | high | mitigate | Tenant transaction + RLS in `linkOf`; organization-B case |
| T-07.17.1.1.2-10-05 | Tampering | goal text rendering as markup | low | mitigate | Plain text rendering (React escaping), one-line sanitized by the server |
