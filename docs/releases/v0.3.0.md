Bots now work in the **Work Zone** themselves, automations open **one conversation per new item**, and anyone can
mention a whole **team**. Also new: organization sign-in for MCP servers, bots that read attachments, a redesigned New
session panel and Work Zone projects without git.

## What's new

- **Bots run Work Zone sessions** (ADR-0038). A bot's sheet › **Work Zone** sets its profile: the device or server,
  the projects, the runtime, the model and its options, the highest permission mode and limits. The device's owner
  allows each bot under Settings › Devices. The bot starts sessions, sends them prompts, reads their output and stops
  them. A live card in the conversation opens the session, and the session links back to the conversation. Full access
  needs the organization policy, the device's opt-in for that bot and the profile. After the bot reads outside content,
  Full access also needs an admin's **Act on outside content** and a server marked as isolated
  (`ocw-runtime isolated-server on`). Otherwise the bot proposes the session for a person to start.
- **Automation fan-out** (ADR-0039). Schedules run as often as every 5 minutes. On a schedule delivered to a channel or
  a board, **Open a conversation for each new item** opens a thread or a card per new item. It never opens the same
  item twice, and it is capped per run and per day. Each item gets its own bot turn, with the Work Zone profile. The
  bot may move the card its automation opened, and mentions the people or teams you choose when it finishes or needs
  help.
- **`@team` mentions.** Mention a team or department in channels, threads and board cards. Its members who can read
  the conversation get a notification. Team mentions never wake bots.
- **Organization sign-in for MCP servers** (ADR-0036). A server can use one shared account for the whole organization,
  by OAuth sign-in or client credentials.
- **Bots read attachments** (ADR-0037): text, code, CSV, JSON, PDFs with a text layer and images (on image-capable
  models).
- **Work Zone:** a redesigned New session panel, and projects in folders without git.
- **Fixes:** faster inbox previews and attached-file handling on hostile input, Work Zone delivery batched by user, a
  cold bot sandbox no longer reads as "could not be reached", and bots' Internet no longer shows "not set up" when
  `OCW_BUNDLED_PLUGINS` is empty.

## Upgrade

In `/opt/ocw` (or wherever the server is installed):

```bash
sudo node scripts/ocw.mjs upgrade --check   # current and newest release; changes nothing
sudo node scripts/ocw.mjs upgrade           # backup, this release, new keys, rebuild; never goes backwards
```

The new migrations are additive. Existing automations, boards and mentions keep working as before. Schedules still on
the old defaults (15-minute minimum, 96 runs a day) move to the new ones (5 minutes, 288).

**Headless Work Zone servers:** to get `ocw-runtime isolated-server`, run the install command from **Settings ›
Devices › Add a device › Server** again on each server ([docs/SERVER.md](https://github.com/VictorMinemu/open-collaborative-ai-workspace/blob/main/docs/SERVER.md#install)).
The desktop app updates from the files below.

## Install the server

On Ubuntu 24.04 or Debian 12, with a DNS name pointing at the server:

```bash
curl -fsSL https://raw.githubusercontent.com/VictorMinemu/open-collaborative-ai-workspace/main/scripts/install.sh \
  | sudo bash -s -- --domain ocw.your-company.com
```

The installer installs this release (`v0.3.0`). The [README tutorial](https://github.com/VictorMinemu/open-collaborative-ai-workspace#install-it-on-a-server)
walks through the first admin, model providers, invites and what to try first.

## Desktop app

None of the builds is signed yet, so the first launch needs one extra step:

- **macOS** (Apple silicon): open `OCW-v0.3.0-macos-arm64.dmg` and drag OCW to Applications. Open it once, then go to
  **System Settings › Privacy & Security** and choose **Open Anyway** (or run
  `xattr -dr com.apple.quarantine /Applications/OCW.app`).
- **Windows** (x64): run `OCW-v0.3.0-windows-x64-setup.exe`. If SmartScreen stops it, choose **More info › Run
  anyway**. It installs for the current user, without admin rights.
- **Linux** (x64): on Ubuntu or Debian, `sudo apt install ./OCW-v0.3.0-linux-amd64.deb`. Elsewhere,
  `chmod +x OCW-v0.3.0-linux-x86_64.AppImage` and run it. The app keeps the device token in the desktop keyring
  (GNOME Keyring or KWallet), which must be available.

Then enter your workspace URL and pair the computer under **Settings › Devices › Add device › Desktop app**. On a
server without a screen, use the headless runtime instead (**Settings › Devices › Add a device › Server**). Signed
builds are planned for MVP 2.

## Known limitations

- Bots read no scanned PDFs (no OCR), audio or video. Office files only through a bot's sandbox. Bots on a ChatGPT plan
  cannot see images yet.
- Claude works only through an org API key.
- A bot's Full access after outside content needs a server dedicated to it (isolated): it must hold nothing else that
  matters.

The full list is in the [README](https://github.com/VictorMinemu/open-collaborative-ai-workspace#known-limitations).
Report problems as [issues](https://github.com/VictorMinemu/open-collaborative-ai-workspace/issues), and security
problems privately ([SECURITY.md](https://github.com/VictorMinemu/open-collaborative-ai-workspace/blob/main/SECURITY.md)).
