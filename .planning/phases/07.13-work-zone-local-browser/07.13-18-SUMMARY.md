# Phase 07.13 Plan 18: Takeover lease and hand back in the API Summary

The person who asked a Work Zone session's turn takes control of the device's page from the live socket, types into it
(input forwarded only from their socket, `lease_input` recorded first), and hands it back; one holder by conditional
UPDATE on `work_browsers`, the bots' 10-minute / 9-minute-warning rules, abandonment after input closes the page, dead
instances' leases swept, and a saving hand back mints the one-use upload 17's route seals.

## What was built

- **`lease.ts` (new):** `askerOf`, `leaseRights`, `takeWorkLease` (asker rule + conditional UPDATE: no lease, or a lapsed
  one without input; audit `takeover_started { origin }`), `keepWorkLease`, `markWorkLeaseInput` (sets `lease_input`,
  pushes expiry), `endWorkLease` / `releaseWorkLease` (lock, clear the three lease columns together, mint the four
  `upload_*` columns together on `save`, close the row when abandoned, audit `takeover_ended`), `sweepLapsedLeases`,
  `tellDeviceEnded`, `announceLease` (`ocw:wb:lease`, `{o,s}` only). `TAKEOVER_MS` / `TAKEOVER_WARN_MS` re-exported from
  the bots' module index.
- **`live.ts`:** client frames parsed with `WorkLiveClientFrame` on an ordered per-socket chain that waits for the first
  decision; `take` (re-decides, refuses `not_allowed` / `someone_else` / `expired`, tells the device `browser.lease
  { held }`, an unreachable device ends it again), `keep`, `release { save }`, holder-only input queued (≤ 256), batched
  ≤ 64 events per `browser.input` within 20 ms; the local sweep (every 15 s; `sweep(nowMs)` for tests) ends idle leases and
  re-sends `lease` at 9 minutes; access loss, socket close, session recheck failure and page end all end or drop the
  lease; a local lease is reconciled with the row on every read (`seen`: dropped once the row no longer shows it).
  `viewerCan.control` is now the take right. `registerLeaseSocket` / `clearLeaseSocket` kept (plan 10's tests use them).
- **Focus hint:** `deviceHandler.onFocus` (index.ts) checks the session runs on the sending device, then `live.onFocus`
  sends `focus { sensitive }` to the holder's socket only; when the holder is on another instance it goes over
  `ocw:wb:focus` (`{o,s,l,f}`, ids and the flag) and that instance delivers locally. A stale lease id reaches nobody.
- **`sweep.ts`:** the lapsed-lease step inside each organization's user-less transaction; devices told and instances
  announced after the commit; `runOnce` returns `{ expired, leases }`.
- **`events.ts`:** a page that closes under a lease audits `takeover_ended { origin, reason: page_ended }`; the
  device's `takeover_abandoned` echo for a row the API already closed audits nothing.
- **Semgrep:** `ocw.live-input-logging` includes `/apps/api/src/modules/work-browser/` and `/apps/local-runtime/src/browser/`,
  the typed-binding regex adds `WorkLiveClientFrame|BrowserInputFrame`, and the message names the Work Zone browser.
  Fixture: positive cases for both types (value, `events`), negative cases for the session id and an error name. The
  guard found nothing in the existing code of the two new paths.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing audit] The page's own end under a lease audits `takeover_ended`, and no audit twice**
- **Found during:** Task 2
- **Issue:** 08's `events.ts` cleared the lease columns on `closed` / `crashed` silently, so a takeover could start
  without an end in the audit (T-07.13-18-05). Once the API itself closes an abandoned page (below), the device's
  `takeover_abandoned` echo would have audited `work_browser.closed` a second time.
- **Fix:** `events.ts` reads the row before closing; under a lease it audits `takeover_ended { origin, reason:
  page_ended, saved: false, abandoned: false }`; a `takeover_abandoned` for a row already closed returns without audit.
- **Files modified:** `apps/api/src/modules/work-browser/events.ts` (not in `files_modified`)
- **Commit:** b6f1faf7

**2. [Rule 2 - Privacy] The API closes an abandoned page on the row in the ending transaction**
- **Found during:** Task 1 design
- **Issue:** clearing only the lease would let the page go public to the other viewers until the device's close arrives,
  showing what the person left in it (T-07.13-18-03; the bots close it in the same transaction, ADR-0029).
- **Fix:** `endWorkLease` sets `state = closed` and audits `work_browser.closed { endReason: takeover_abandoned }` when it
  abandons; viewers get `ended takeover_abandoned` at once; the device still gets `browser.lease { abandoned }`.
- **Commit:** 283f9df9

**3. [Rule 2 - Missing functionality] The focus hint crosses instances**
- **Issue:** `browser.focus` arrives on the instance holding the device link; the holder's socket may be elsewhere.
- **Fix:** undelivered hints go over `ocw:wb:focus` with ids and the boolean only. Not in the plan; plan 23 may mention it
  next to the D-33 exception in ADR-0035 (it carries no input).
- **Commit:** 283f9df9

**4. [Rule 1 - Test gates that the new metadata tripped] Plan 08 / 17 tests updated**
- `audit.int.test.ts`: the closed metadata allow-list now also admits `"reason":"[a-z_]+"`, `"saved":(true|false)` and
  `"abandoned":(true|false)` (codes and booleans, never text); `signins.int.test.ts`: the sweeper's result is
  `{ expired, leases }`. Neither weakens a check. Commit b6f1faf7.

**5. TDD order for Task 3:** `lease.ts` was written whole in Task 1, so the save branch and the focus relay landed in
the Task 1 feat commit (283f9df9) and Task 3's integration tests passed on their first run. Task 3's Semgrep fixture was
RED first (3 missed lines) before the rule change (36465c05).

**6. Semgrep negative case:** the plan's "logging the session id is not flagged" is the negative. Logging a field of a
typed `BrowserInputFrame` binding (even `leaseId`) IS flagged by the existing typed-binding pattern; that is intended
(fail closed), so code must log the session id, not the frame's fields.

## Notes for the next waves

- **Device (15, 19):** frames from the API: `browser.lease { held }` at take; `browser.input { events ≤ 64 }` from the
  holder only; on `release { save: false }`, socket close or idle without input, lost access, or an unreachable take:
  `browser.lease { released }`; after input without hand back: `browser.lease { abandoned }` (the API already closed the
  row; the device closes the page and its `takeover_abandoned` echo is accepted silently); on `release { save: true }`
  ONLY `browser.handback { save: true, uploadId }` (no `released` after it), so the hand back must end the pause.
  `uploadId` is bound to session, member and the page's origin at release time, 5 minutes.
- **Web (21):** `viewerCan.control` is now real (prompt right ∧ asker, re-decided on take, rechecks and invalidations).
  `lease { expiresAt }` arrives at take, at the first entering input, at most every 30 s of input (keep), and again at
  9 minutes (warning); `refused { op: take, reason }`; `focus { sensitive }`. Input sent before the `lease` frame is
  dropped.
- **Sweeper:** `runOnce()` returns `{ expired, leases }`; leases are swept 60 s past expiry.
- **ADR-0035 (23):** record that takeover input crosses instances only through `hub.sendBrowserFrame`'s device control
  channel (D-33 transit), lease announcements are ids only, and the focus channel carries ids and one boolean.
