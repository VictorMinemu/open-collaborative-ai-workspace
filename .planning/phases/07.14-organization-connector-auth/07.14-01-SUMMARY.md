### Auto-fixed Issues

**1. [Rule 3 - Blocking] The API stopped compiling once the contract enum was widened**
- **Found during:** Task 1
- **Issue:** The plan expected the API to keep compiling because "the narrower DB enum assigns into the wider type". The reverse direction fails: `createMcpServer` and `updateMcpServer` write the wider contract value into the narrower Drizzle `auth_mode` column (TS2769 and TS2322 in `mcp/service.ts`). Task 2's new `McpServer` fields also broke `toDto` (TS2739). AGENTS.md requires `pnpm verify` to pass before any commit.
- **Fix:** Added `storableAuthMode()` to `apps/api/src/modules/mcp/service.ts`. It refuses `org_oauth` and `org_client_credentials` with `400 auth_mode_unavailable` and narrows the type to the stored column. Without it, the DB check constraint would reject those modes with a 500, so the guard fails closed and fails cleanly. `toDto` now returns `orgConnection: null, authFailure: null`. Plan 05, which owns `mcp/service.ts` in W2, replaces both once plan 02 has widened the column.
- **Files modified:** apps/api/src/modules/mcp/service.ts
