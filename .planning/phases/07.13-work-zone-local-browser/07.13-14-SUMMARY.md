# Phase 07.13 Plan 14: Codex stdio shim, app-server overrides and mapper Summary

Codex sessions now get the same governed browser as Claude sessions. A session whose browser is available starts its
app-server with `-c mcp_servers.ocw_browser.*` overrides. Those make Codex launch `ocw-runtime browser-mcp`, a stdio MCP
server that relays every call to the daemon's `BrowserManager` over the local control socket. The timeline shows only
the action and the origin.

## What was built

- **`browser/mcp-shim.ts`** + hidden **`ocw-runtime browser-mcp`**:
  - An `McpServer` named `ocw_browser` with the `WORK_BROWSER_TOOL_TABLE` tools (short names, the table's Zod bodies
    and descriptions) over `StdioServerTransport`.
  - Each call sends one `browserCall { session, token, tool, args }` on `controlSocketPath(OCW_HOME)`, with the tool's
    budget plus 30 s, and the MCP cancel ends the connection. The answer is validated (text/JPEG image content,
    `isError`) and returned as is.
  - Daemon errors map to summary-grammar results: "not allowed" becomes `Refused: <not_allowed sentence>`, while an
    unreachable daemon or an odd answer becomes `browser_unavailable`.
  - The env names the session and the token file, never the token. The file must be exactly
    `<browsersRoot>/run/<session>/shim-token`; otherwise the shim exits 1 with a fixed-word message on stderr and
    nothing on stdout.
  - There is no `listen`/`createServer`. The CLI points `console.log`/`info` at stderr.
- **`codex-runtime.ts`**:
  - `codexBrowserArgs(shim, { sessionId, tokenFile })` builds TOML-quoted `command`, `args`
    (`[entry…, "browser-mcp"]`), `env`, `default_tools_approval_mode="approve"` and `tool_timeout_sec=960`.
  - These are appended to `CODEX_APP_SERVER_ARGS` or `CODEX_SLOT_APP_SERVER_ARGS`. With no available browser the
    arguments are unchanged (`args` stays absent).
  - `prepareTurn()` covers the pending account, a browser availability change (restart, then wake with
    `thread/resume`), the dormant wake and `setImageInput`.
  - `onServerRequest` gained the two PD-08 cases. Unknown methods still answer -32601.
  - `CodexRuntimeOptions.browserShim` defaults to `process.execPath`, `[process.argv[1]]` and
    `ocwHome(process.env)`.
- **`mapper.ts`**:
  - `tool.started` is `ocw_browser_<tool>` with an origin-only summary; nothing from the arguments except `open`'s
    origin.
  - `tool.completed` has no `output`. A `Refused: …` line is `ok: false`, and failed items read
    `ocw_browser_<tool> failed`.
  - `browserSummaryLine` checks the manager's grammar. Other MCP servers are unchanged.
- **`record-codex-fixture.ts --scenario browser-mcp --shim [--check]`**:
  - Runs the real codex 0.172 offline (`openOffline` → `offlineRecorderEnv`, temp HOME/CODEX_HOME, the loopback
    fake). CodexRuntime starts it with `codexBrowserArgs` pointing at the real shim, against a local `BrowserManager`
    and control socket in the temp OCW home, the cached pinned shell and the loopback fixture site.
  - `--check` writes nothing and prints `check: Tool open said: <summary>`. It fails if any tool event carries an
    output.

## Deviations from Plan

1. **[Rule 3 - Blocking] `OCW_HOME` (and `OCW_BROWSERS_DIR` when set) in the shim's env.** The plan's env is only the
   session id and the token file. But Codex gives an MCP server only a short list of the app-server's variables, and
   `codexChildEnv` strips every `OCW_*` from the app-server. Without these variables a daemon with a non-default home
   would be unreachable, and its token file would fail the run-dir check. Both are paths, not secrets. Commit 0a9171c2.
2. **Existing test updated.** `answers unsupported server requests with a JSON-RPC error` used
   `item/tool/requestUserInput` as its unsupported example. PD-08 deliberately answers that method now, so the test
   uses `item/tool/call` for -32601 and also asserts the new empty answer. This is a behaviour change the plan asked
   for, not a weakened check. Commit 0a9171c2.
3. **Withdrawal restarts too.** The plan names only late availability. The same comparison also restarts the
   app-server without the overrides when the browser becomes unavailable, so Codex stops offering tools the manager
   would refuse. It never restarts inside a turn: a steer keeps the running process.
4. **The `--check` line is normalized.** The fake's raw reply is
   `Tool open said: Wall time: … Output: Opened 127.0.0.1:<port> Signed in: no …`. Codex adds the prefix (A-3), and the
   manager's answer continues after the summary. `--check` strips the prefix and cuts at ` Signed in:`, so the printed
   line is exactly `Tool open said: Opened 127.0.0.1:<port>` and no page text is printed.
5. **The recorder reads the test browser cache.** `--shim` uses `testBrowser()` (`~/.cache/ocw-test-browsers`, or
   `OCW_TEST_BROWSERS_DIR`) to find the pinned shell, the same cache the unit tests use. It is never a runtime home,
   and Codex and the shim still get only temp homes.
6. **TDD commits:** for each task, a `test(...)` RED commit (failures observed) comes before its `feat(...)` GREEN
   commit.
