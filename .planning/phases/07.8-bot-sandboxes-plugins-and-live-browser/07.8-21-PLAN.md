<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| member's session → bot | The bot acts with it but never reads it |
| member ↔ member, member ↔ admin | A sealed session is its owner's alone |
| sealed state ↔ storage | Plaintext exists only in transit to the browser container |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.8-21-01 | Spoofing | another member or bot using a sealed session | critical | mitigate | AAD per member × bot × site, owner-only RLS, audience rule, tests per case (Tasks 1–2) |
| T-07.8-21-02 | Information disclosure | session plaintext at rest or in logs | critical | mitigate | Sealed secret only; sentinel sweep over every table, log, event, response (Task 1) |
| T-07.8-21-03 | Information disclosure | sign-in in shared channels | high | mitigate | `memberAccountAllowed` for offering and acceptance (Task 2) |
| T-07.8-21-04 | Repudiation | unclear sign-in history | low | mitigate | Audit per request, decision, seal, use, revoke (Tasks 1–3) |
| T-07.8-21-05 | Elevation of privilege | admin reading members' sessions | high | mitigate | 404 for admins; RLS (Task 2) |
| T-07.8-21-06 | Tampering | identity-provider cookies sealed with a site | high | mitigate | P-09 filter at export (07) and site key = card host (Task 1) |
</threat_model>
