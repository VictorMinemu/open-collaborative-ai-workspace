## Phase Goal

See 07.7-01 (Phase Goal, plan map, cross-plan contracts, P-01 … P-19).

**This plan's slice (phase tracer, API level):** a bot's consult request becomes a visible, attributed question in the
thread and a turn for the target bot on behalf of the same human, with every guard and refusal. The return half (turn
done, answer back to the asker, Stop) is 07.7-06; the cell half is 07.7-05; the permission rules API is 07.7-03 (same
wave, no shared file).

Module layout without import cycles: `agent-message.ts` (decision + offered targets) is imported by both `mentions.ts`
and `consult.ts`; `consult.ts` imports `buildMentionEvents` from `mentions.ts`; `mentions.ts` never imports `consult.ts`
(`registerMentionHandler` takes an optional `consult` delegate that `index.ts` wires to `deliverConsult`).

<objective>
Build `POST /agent-channel/v1/consultations` end to end: offering, decision, guards, the question message, the chain and
hop rows, the target's turn and its origin delivery, the hop DTO and its live updates.

Purpose: A2A-01 (question as a visible attributed hop with a chain id), A2A-02 (one decision per hop, deny wins),
A2A-03 (depth, no repeat, budget, one pending, daily limit, asker = H); D-01, D-02, D-03, D-04; P-05, P-07, P-11, P-12, P-13.
Output: `consult.ts`, `agent-message.ts`, `chat/consults.ts`, seams in the bridge, chat, mentions and turn policy, the
07.5 exemption, two integration test files.
</objective>

Consult route (P-07), in order:
  1. Short read-only transaction: `agent_turns` by `eventId` with `agent_id = agentId` (else 404 `unknown_turn`);
     `ocw_consult_agent` in `turn.tools` (else `not_offered`); conversation kind `channel` or a channel thread (else
     `not_channel`); `turn.tainted` (→ `tainted`); chain = `turn.chain_id` or the chain whose `root_event_id` is this event;
     chain not `active` → `chain_closed`; `turn.chain_depth + 1 > A2A_MAX_DEPTH` → `depth_exceeded`; target under RLS, not
     deleted (else 404 `target_not_found`); disabled → `target_unavailable`; personal → `target_personal`; = source →
     `target_is_self`; = root or already a target in the chain → `target_in_chain`; not a member of the conversation or its
     parent → `target_not_member`; H no longer reads the conversation → `human_cannot_read`; `decideAgentMessage` denied →
     `not_allowed`; budget used → `budget_exhausted`; a pending hop by this agent in the chain → `consult_pending`.
  2. `core.chatAgent.postAgentMessage(ctx, { agentId, conversationId, threadRootId: turn thread root, inReplyToMessageId:
     turn.message_id, eventId, body: "@<handle> <question>", idempotencyKey: "consult:<key>" namespace, consult, chain })`.
     Inside that transaction, when the message is new, chat emits the agent-authored mention with `consult`; the handler
     runs `deliverConsult`: chain upsert (`root_event_id` unique) → conditional `hops_used` UPDATE → hop insert (constraint
     violations → ConsultRefusedError with the matching code) → parent deadline bump → `buildMentionEvents` with
     `chain {humanUserId: H, chainId, depth, answeringHopId: hop, returningHopId: null, initialTaint: false, origin}` →
     `turnPolicy(target, H)` → `hop.target_event_id` → append `agent.mention.v1{origin}` → `consultUpdated([question])` →
     audit `agent.consult.requested`. A refusal thrown here rolls the message back.
  3. Response: 200 `sent`; 200 `refused/limit_reached` (question posted, hop `refused`, notice once, audit
     `agent.consult.refused`); 409 `{code}` for every refusal before or during posting (nothing posted; audit
     `agent.consult.denied` in its own short transaction, ids and code only). A retry with the same key returns the stored
     hop's state (the message already exists, nothing is emitted again).
