## Deviations from Plan

### Auto-fixed and added (Rules 1–3)

1. **[Rule 2] The API names the conversation for the viewer, and a private row says why** (`routes.ts`,
   `BrowserContextRow.privateReason`). Without this, the web would have to guess whether a DM is the viewer's own: the
   bot owner can see a row of someone else's DM. It also could not choose between the two private sentences in the
   UI-SPEC. Both changes are additive. 30's contract fixture already assumed composed names ("DM with you").
2. **[Rule 3] `e2e/support/browser-signin.ts`** (new) and `fakeSandboxd().signedIn` in `e2e/support/sandbox.ts`. Both
   specs need a sealed sign-in made the real way. `live-header.tsx` now exports `DOT` and `TONE`, so the tab's row
   chips use the same tones without the live view's `role="status"` (rows are plain text, UI-SPEC Accessibility).
3. **[Rule 1] The meta line read "just now·expires"** in the DOM. The flex gap was the only separator. It is now real
   text, and the unit test reads `textContent` the same way.
4. **#286 fix (migration) in a UI plan**, as the coordinator asked: act on open entries naming 07.8-27.
5. **Test file split:** `browser-sessions.test.tsx` for Task 1, besides the planned `browser-tab.test.tsx`.

### Plan or contract text vs what was built

- **"Stopped" copy:** the activity row reads "Stopped on {host} · {conversation}". The UI-SPEC lists "Stopped" alone,
  which drops the host this list is about.
- **Open live view stays outline on every row.** The UI-SPEC wants it primary on the row of the viewer's own pending
  sign-in card. `BrowserContextRow` carries no "sign-in pending for you" flag; see the candidates below.
- **`browserSandbox` (D-14)** is still not reported by the API (21), so the isolation line names only the runtime.
- **On phones,** Open live view opens the live view 22 ships, the small window. The dock and full sheet are 07.8-26's.
  The spec asserts `live-view` and its `data-context`, so it holds once 26 lands.
- **The plan's "Ana (same org, admin)"** is the e2e admin, Víctor.

No permission check, RLS policy or approval gate was weakened. Sessions stay owner-only: the web only ever calls the
owner-only list, and the e2e proves an admin sees none.

   trigger fires only on a hard delete. A deleted bot's browser sessions stay sealed until expiry or the 7-day purge.

   because the bot is disabled.

   primary variant (UI-SPEC § 3.6).

4. **deviation (low), `browser-queries.ts`.** The Browser tab polls every 10 s; no realtime event announces context
   changes to it. A page opened or closed shows up within 10 s.

   `HEAD_ONLY` order in `upgrade.int.test.ts`.
6. **deviation (low), `routes.ts`.** Rows written before the migration (NULL `opened_host`) still show the current
   host for "Opened".
