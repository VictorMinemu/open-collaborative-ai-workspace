## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `DeviceHostKind` defined in `device.ts`, not `device-link.ts`**
- **Found during:** Task 2
- **Issue:** `device-link.ts` imports `RuntimeInfo` from `device.ts`. If `device.ts` (`Device.hostKind`) also imported `DeviceHostKind` from `device-link.ts`, the two would form an ESM import cycle, and both modules build Zod schemas at load time, so whichever loads second would hit a TDZ `ReferenceError`.
- **Fix:** `export const DeviceHostKind` lives in `packages/contracts/src/device.ts`, and `device-link.ts` imports it there for `DeviceInfo.host`. It is a single definition, exported once from `@ocw/contracts`. The hub's names and shapes are unchanged.
- **Impact:** one acceptance grep is not met as written: `grep -n "export const DeviceHostKind" packages/contracts/src/device-link.ts` prints nothing. The same line is at `packages/contracts/src/device.ts:15`. Plan 22's gate (01's local `HostKind` lists the same values as `DeviceHostKind`) should grep `packages/contracts/src/device.ts`.
- **Commit:** `c892e588`

**2. [Formatting] Biome format and import order in the new tests**
- Pure formatting in `settings-denied.test.ts`, `meta.test.ts` (folded into `1cbe804c`) and `session-settings.test.ts` (import order folded into `c892e588`).
