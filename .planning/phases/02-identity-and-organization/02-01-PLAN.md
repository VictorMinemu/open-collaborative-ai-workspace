## Phase Goal

**As an** Organization Admin and every member of the workspace, **I want to** arrange the company into departments, teams and projects with the four PRD roles, have every route decided by one permission resolver, and manage my own password, sessions and profile, **so that** each person and agent can do exactly what their role, units and rules allow and every sensitive change is attributed and audited.

(Derived verbatim from the ROADMAP Phase 2 goal; the ROADMAP `**Goal:**` line is not in user-story form. Run `/gsd mvp-phase 2` to canonicalise it.)

**This plan's slice:** the demo database is backed up first; the one-way role migration, the Phase 2 schema and the permission vocabulary land in one isolated commit; then every reader of roles follows so existing teammates keep every capability; finally the approved packages and an isolated e2e stack that never touches the owner's demo.

## Locked decisions (orchestrator, owner-delegated) — referenced as D-01 … D-10 in every plan

- **D-01** Web REST keeps the cookie; the API accepts cookie OR Bearer JWT; the browser WebSocket uses a short-lived JWT offered as a `Sec-WebSocket-Protocol` entry and verified against the JWKS before the upgrade.
- **D-02** `permission_rules` table + admin API for explicit deny/allow; UI limited to a read-only listing.
- **D-03** Device Link keeps accepting legacy device tokens behind a flag until Phase 8; the daemon exchanges its device token for a 10-minute device JWT before connecting.
- **D-04** Change password while signed in.
- **D-05** Invitations target the organization only; joining a unit happens afterwards.
- **D-06** Role migration owner/admin → Organization Admin (`admin`), member → Developer (`developer`); unit memberships are `member | lead`.
- **D-07** Hierarchy in `app.org_units` with `parent_id` + `uuid[]` ancestor path (no ltree); hierarchy projects are `org_units.kind = 'project'`; `app.projects` keeps meaning device repositories.
- **D-08** `jose`, `nodemailer`, `@types/nodemailer`, `fast-check` are approved (no human checkpoint).
- **D-09** No UI-SPEC; admin console pages reuse the shadcn components and Settings layout, responsive at 390/1440, dark/light, empty states with CTAs; each UI plan ends with screenshots in `.planning/phases/02-identity-and-organization/screenshots/` that the executor reviews and polishes.
- **D-10** Every task keeps `pnpm verify`, the e2e suite (setup, smoke, chat, bots, codex-subscription, work-zone) and the desktop/local-runtime suites green; `scripts/demo-seed.mjs` and `docs/DEMO.md` follow the new roles.
