# Phase 07.10 Plan 03: Work Zone sidebar by department Summary

The Work Zone sidebar now reads like the chat sidebar: one collapsible section per department holding the team
projects the viewer belongs to (own departments first), each project row opening its page with its team pill, a
"● n" live count and at most three active sessions under it, then "+N more" to the project page. The viewer's own
repositories, and any session from a project they may not see named, sit under Personal. Collapse is remembered per
browser, large departments stay at 15 rows, and the chat sidebar renders the same section header, byte for byte.

## What the sidebar does now

- **Sections (D-01, D-02):** projects of membership `member`, `team` or `lead` grouped under `top`; `manager` rows are
  never rows (Browse projects and today's search reach them). Own departments first, then by name (accent-blind,
  numeric). Projects by name. Team pill when `parent` is not `top`.
- **Project row (D-03):** `FolderKanban`, name (full text in `title`), pill (`max-w-[40%]`), `● n` for provisioning,
  running or waiting-approval sessions; accessible name "{project}, {team}, {n} running"; `aria-current` on the project
  page (any tab). Browse projects (`Compass`) is current only on `/work-zone/projects`.
- **Sub-rows (D-04):** active sessions, approval → live → recent, at most 3, then `+N more` (link, named "{n} more
  active sessions in {project}"); the open session always shows, settled or beyond the cap. One line: glyph (no
  spinner), title, the 07.9 marker and suffix, status text with its old tone; `title` = "{title} · {runtime} · {branch
  or device}[ · +a −d]" (X4).
- **Personal (D-06, PD-07 (b)):** the index's personal repositories plus the repositories of sessions with
  `teamProjectHidden`, a personal repository, or created by the viewer (X1). 5 repositories then "{n} more
  repositories", 3 sessions each then an inline "+N more". A hidden project's repository carries only "Linked to a
  project you can't open".
- **Collapse (D-01, D-09):** `ocw.workzone.sidebar.v1`, `{ [key]: boolean }`, Settled collapsed by default (used by 04),
  corrupt JSON = defaults, failing storage = memory only. A collapsed section keeps the open project, the open session
  and (from 04) the sessions in `needs`; its header shows the hidden count, with ", {n} hidden" for screen readers and
  `aria-controls` on the list.
- **Kept as they were:** the search field and its flat results, the Settled block (open by default), "No sessions
  yet.", the header New session, Devices. 04 replaces search and Settled; 05 adds the "+" actions, the onboarding line
  and the projects-request states.

## Deviations from Plan

1. **[Rule 3 - Blocking] Tooling.** The harness's worktree guard blocks Edit/Write on the dedicated worktree, as for
   01 and 02: files were written in `/tmp/ocw0710-03` and copied in. The content is what an edit would produce.
2. **[Rule 1 - Structure] Legacy rows in `sidebar/session-rows.tsx`.** `ActiveRow`, `SettledRow` and `ProjectBadge`
   (with their private `RowStatus` and `RowDiffStat`) moved unchanged into a new file and stay exported from
   `session-sidebar.tsx`; otherwise `session-sidebar.tsx` and `work-zone-sidebar.tsx` would import each other. 04 retires
   `ActiveRow` from that file.
3. **Accessible name of a sub-row.** An `aria-label` ("{title}, {status}{suffix}") instead of an sr-only comma, so a
   default-audience row has no sr-only node (N2, and the marker spec's `.sr-only` count 0); the 07.9 suffix stays in
   the DOM for `toContainText`.
4. **Extra test ids.** `project-pill`, `repo-live-count`, `section-more`, `personal-more`, `repo-more` (the UI-SPEC
   lists only `project-more` among the more rows).
5. **Spec fixes during Task 3 (no product change):** the mobile tracer raced the drawer's closing animation (fixed with
   `drawerClosed`); the layout spec's first run read the repository row with `toHaveText`, which includes the sr-only
   ", 1 running" (now `toContainText`).
6. **Testcontainers flakes (WINDOWS #119), re-run once, green:** `memory/memory-access.int.test.ts` in the Task 1
   verify; `browser/contexts.int.test.ts`, `work-session/access.int.test.ts`, `work-session/controls-exposed.int.test.ts`
   in the Task 2 verify (an e2e web build ran at the same time).
