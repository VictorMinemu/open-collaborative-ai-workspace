# Phase 07.17 Plan 16: The open route (`POST /agent-channel/v1/conversations/open`) Summary

**A fan-out run's bot opens one board card or channel message for each new item. Items are deduplicated on the sha256 of their key and capped per run and per day under the run and automation locks. Bot-written text is defused. Each opened item gets its own ids-only `automation.item` job. The call is audited with ids and counts only.**

## Performance

- **Duration:** about 20 min (2026-11-10T11:08Z to 11:28Z)
- **Tasks:** 3 of 3
- **Files:** 3 created, 8 modified

## Accomplishments

- `conversations-open.ts` follows the 07.16 two-transaction order. tx0 runs with no user and finds the turn and its run. tx1 runs as the run-as person: live turn, tool on the turn, run, then (under the locks) `active` and fan-out on, then the claim (`outsideContent` on a tainted turn), then `fanOut.open`. If the target refuses a post, everything rolls back and `target_not_postable` is recorded through the claim in a fresh transaction.
- `fan-out.ts` does the work inside `open`:
  - Counts the caps and checks each key: a known key answers `opened: false`; otherwise it checks the caps, then inserts with `ON CONFLICT DO NOTHING`.
  - Posts a board card (typed, defused title, fenced description, the automation's column) or a top-level channel message (bold inert title, fenced body).
  - Sets the root and sends the ids-only `automation.item` job.
  - Marks the run answered, labels the run card with `fanOutLabel` and writes the `automation.conversation_opened` audit.
- Wiring: `createAutomationModule` returns `fanOut`, the agent-channel option `fanOut` mounts the route, and `app.ts` passes it.
- `inboundRooted` now treats opened roots as outside content; the run log root is not included.
- `security.int.test.ts` lists the route with an organization-B case.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug, P2] A defused mention in a board card title resolved again**
- **Found during:** Task 2 (E6)
- **Issue:** `cardMessageBody`'s `oneLine` (`packages/contracts/src/board.ts`) replaced every `\p{Cf}` character with a space. That included U+2060, the joiner `defuseMentions` puts before `@`, so a title "⁠@sam urgent" became "@sam urgent" in the card's message body and `@sam` resolved as a mention. The 07.6 inbound board titles (`automation/inbound.ts`) had the same hole.
- **Fix:** `CONTROL_RE` now keeps U+2060 and still removes every other control or format character (a bidi override is still removed; there is a unit test).
- **Files modified:** `packages/contracts/src/board.ts`, `packages/contracts/src/board.test.ts` (outside `files_modified`)
- **Commit:** `fb78e346`

**2. [Rule 3 - Blocking] Two 07.17-08 board cases assumed a clean turn in an opened card's thread**
- **Found during:** Task 3 (I ran `board.int.test.ts` locally after the `inboundRooted` change)
- **Issue:** Those cases seed an `automation_conversations` row for the card, then expect a person's turn in its thread to be untainted. PD-10 says such turns now start tainted.
- **Fix:** The D-12 case now expects the turn tainted and the move audited with both `sessionOutputExempt` and `outsideContent`. The "untainted turn" case now uses a card no automation opened and asserts that the turn is clean. No check was loosened.
