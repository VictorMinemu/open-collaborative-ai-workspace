## Accomplishments

- `board.ts` defines all the cross-plan contract names, plus these helpers:
  - `BoardFieldDefs`, `TemplateColumns`, `BoardFieldValues`, `BoardCardMove`, `BoardColumnPageQuery`;
  - `recordTemplateProblems` and `namingRuleTokens`, for 07.1-07.

  Limits are as fixed in the plan. Two were added: description 8,000, and 10,000 ranks per re-rank event.
- `renderCardTitle(RULE, {EXP, 7, "Broken pump\nsecond line", {customer: "Acme"}})` gives `EXP-0007 · Acme · Broken pump`. Empty tokens are dropped together with their joining separator. The title is capped at 200 characters and falls back to the summary, then to "Untitled".
- `cardMessageBody` returns `title\n\ndescription\n\nLabel: value` lines. It is clipped to 20,000 characters, and a test ties that to `PostMessageRequest`.
- `CreateChannelRequest`:
  - without `layout`, it parses to `text`;
  - `templateId` is refused unless the layout is `board`.

  `ChannelSummary` without `layout` still parses.
- Agent schemas carry only `eventId` and `agentId`. A patch can only move a card or set its waiting state (P-03).
- `ocw_board_card` is a built-in name, so plugins cannot declare it. `isDangerousToolName` returns false for it. No turn offers it yet; `turn-policy.ts` is untouched.

## Decisions Made

See `key-decisions` in the frontmatter. In short:
- `{prefix}` and `{seq}` require a template prefix.
- Descriptions are capped at 8,000 characters so the body always fits.
- A template created without columns gets the four default columns.
- Agent schemas strip unknown keys, the repo convention.

## Deviations from Plan

**1. [Rule 2 - Correctness] Template rule/prefix coherence**
- **Found during:** Task 3.
- **Issue:** a rule using `{prefix}` or `{seq}` on a template without a prefix would render a title with no number on every card.
- **Fix:** `recordTemplateProblems` refuses it. An update with only `namingRule` checks the grammar alone (`fieldKeys: null`); 07.1-07 must re-check the merged template.
- **Files:** `board.ts`. **Commit:** `83aae7e`.

- Task 3 was committed in two atomic commits: contracts, then dependencies. `pnpm verify` ran on the final tree. The contracts-only commit is a strict subset with no dependency on the new packages.
