## Context

Hub: `07.17.1.1.1-01-PLAN.md` (plan map, PD-03 executor rules, PD-14, PD-15, A-06). This plan is the Python supply
chain: the lock the image installs (03), its license records, the license guard that keeps them honest, and the
scripted supply-chain evidence that must pass before 03 installs anything (the approval itself is 07 T3, before
merge, because it also needs the image CI with the installed versions). It owns no Dockerfile line, so it runs beside
01.

<objective>
Resolve the toolkit's Python environment into a hash-pinned, wheels-only lock on the image's own interpreter, record
one SPDX license per pin, extend `pnpm guard` to check Python locks like the npm lockfiles, and produce objective,
scripted evidence for every pin (age of the exact hashed files, yanked, OSV advisories, legitimacy and repository,
closure) that must pass before anything is installed (D-01, D-03, D-09).

Purpose: the same supply-chain bar as the browser image's package-lock (D-01); the legitimacy seam returns `SUS` for
every PyPI package, so the decision rests on evidence a script produces, not on a reading.
Output: `requirements.in`, `requirements.lock`, `licenses.json`, `lock.sh`, the guard extension and its tests, the
evidence script and its tests, the evidence JSON in the SUMMARY.
</objective>
