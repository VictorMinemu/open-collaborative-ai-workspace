## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `sandbox-packages.spec` failed on desktop (toast over the review sheet's Approve)**
- **Found during:** Task 1 (full e2e run 1)
- **Issue:** at 1440, "This version changed upstream" (Sonner, bottom right) sits over the sheet's footer. The
  re-approval click landed on the toast while it slid in. That is an outside press: the sheet closed and no POST was
  sent (the trace shows the click done and no request). Or the click waited 30 s on the toast, because Sonner pauses
  it under the pointer. The test failed twice in a row, so it was not load.
- **Fix:** before each re-approval the test moves the pointer off and waits for the toast to close. The spec already
  uses this pattern before its second review. No assertion removed, no product change. The UX point is logged in
  `deferred-items.md`.
- **Files modified:** `e2e/tests/sandbox-packages.spec.ts`
- **Verification:** the spec passed twice (14 passed, 3 skipped), and passed in full e2e run 2
- **Committed in:** `c0517a9a`

**2. [Rule 1 - Docs accuracy] The DEMO owner check uses SQL, not a Settings page**
- **Found during:** Task 2
- **Issue:** the plan's step 5 says "open Settings › Audit", but the web has no audit page.
- **Fix:** step 5 gives the `app.audit_events` query, the same way other DEMO owner checks do.
- **Files modified:** `docs/DEMO.md`
- **Committed in:** `826f8cf6`

**3. [Rule 2 - Correctness] ADR refusal list includes `unavailable`**

  the claim). The ADR lists all 12 codes.
