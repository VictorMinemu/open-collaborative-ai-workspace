# Phase 03.2: Work Zone session controls - Context

**Gathered:** 2026-10-05 (owner decisions in conversation; no discuss-phase run)
**Status:** Ready for planning

<domain>
## Phase Boundary

Inside one Work Zone session, controllers change the model (same runtime), the reasoning effort (plus context
window and fast mode where real), and the permission mode — including a real Full access mode — from a composer
that matches the owner's reference screenshots. A device owner can share a device with chosen people so they run
sessions on it without per-session acceptance. Switching runtime (Claude Code ↔ Codex) inside a session and
several agents per session are **out of scope** (researched in `.planning/research/WORKZONE-PROVIDER-SWITCH.md`
and `.planning/research/WORKZONE-MULTI-AGENT.md` for later phases).

</domain>

<decisions>
## Implementation Decisions

### Full access (owner, ADR-0012 — overrides research option 2)
- **D-01:** Full access is the **real runtime bypass mode**: Claude `permissionMode: "bypassPermissions"` (+ `allowDangerouslySkipPermissions: true`), Codex `approvalPolicy: "never"` + `sandboxPolicy: dangerFullAccess`. Research option 3, chosen by the owner.
- **D-02:** It is reachable only when **all three** hold, re-checked on every turn: org policy `allowFullAccess` (default off), the **device's local opt-in** (default off), and the asker's grain to use full access on that device. The device opt-in lives on the device itself (daemon config set from the desktop app, or a flag/config for a headless server daemon) and is reported to the server in the device hello/capabilities; the daemon refuses a full-access request when its local opt-in is off, so a compromised or buggy server alone cannot turn it on.
- **D-03:** The existing fail-closed checks (contracts `PermissionMode` rejecting bypass, `claude-runtime.ts` init check, `codex-runtime.ts` dangerFullAccess/never check, Phase 7 Semgrep idea) are **replaced, not deleted**: they still fail closed for any bypass that did not come through the authorized `fullAccess` path (e.g. init reports bypass while the session's effective mode is not fullAccess → abort).
- **D-04:** Full access shows a persistent badge in the session header and composer to every controller; entering/leaving it and every turn's effective mode are audited (actor, device, session, org). Claude deny rules/hooks and our `redact()/contain()` stay active.

### Shared devices (owner, ADR-0012)
- **D-05:** A device owner marks a device as shared with members or org units, each with a maximum permission mode (up to fullAccess only if the device opt-in allows it). Listed people start and control sessions on it without per-session acceptance. Revocation stops their running sessions. Unlisted members keep today's flow. Builds on the existing `device.shared` flag and `device.use` permission (`packages/contracts/src/device.ts`, `permissions.ts`) — extend, don't replace.
- **D-06:** Device settings (web + desktop) show whose runtime subscription the device uses ("Runs on <owner>'s Claude / ChatGPT login") so sharers understand the cost.

### Controls (research recommendations accepted)
- **D-07:** New device command `session.configure` and device event `session.settings` sharing one `SessionSettings` Zod contract in `packages/contracts`; the API intersects every request with org policy ∩ device opt-in ∩ grain ∩ runtime-reported catalog; the adapter applies pending settings **between turns** and reports the effective values; `work_session.updated` propagates them live.
- **D-08:** Model picker lists only the current session runtime's models from the runtime catalog (Claude `initializationResult().models`/`supportedModels()`, Codex `model/list`). The provider rail shows both runtimes; the other runtime's group is shown disabled with "Switching provider inside a chat is not available yet" (it stays selectable in the New session dialog). No "NEW" badge unless the runtime provides the data (Codex `availabilityNux`); none invented for Claude.
- **D-09:** Effort levels from `supportedEffortLevels` / `supportedReasoningEfforts`; labels Low/Medium/High/Extra High/Max. **Ultracode and Codex `ultra` are deferred** to the multi-agent phase. **Ultrathink** is shown only if a recorded fixture proves the keyword works through the SDK; otherwise it is listed as deferred in the inventory.
- **D-10:** Context window 200k/1M appears only where the runtime offers both (Opus 4.6 today); other models show the fixed value (e.g. "1M"). Codex context window is display-only.
- **D-11:** Fast mode is offered but **org policy default off**; when the runtime reports it unavailable (`extra_usage_disabled`, `model_not_allowed`…) it is shown disabled with that reason. The UI states the cost (Claude: paid usage credits; Codex: ~2.5x subscription limits).
- **D-12:** Permission menu: Supervised / Auto-accept edits / Auto (only where `supportsAutoMode`) / Full access (D-01..D-04), plus **Plan** kept as an option (not in the reference). Fix Codex Supervised to `readOnly` sandbox + `approvalPolicy: "untrusted"` so it really asks before edits (today identical to acceptEdits).
- **D-13:** Slash commands typed in a prompt that change settings (`/model`, `/effort`, `/fast`, `/permissions`, `/config`, …) are intercepted by the adapter and routed through `session.configure` (policy-checked, audited) or refused with a visible notice; they never reach the runtime raw.
- **D-14:** Settings changes during a running turn are held as *pending* and applied before the next queued prompt; the UI shows "applies to the next turn".
- **D-15:** Fix the Claude mapper so every `system/init` (not only the first) forwards the effective model/mode.

### Visual (owner reference)
- **D-16:** The composer bottom bar follows `reference/ref-1..3.png`: model chip with provider icon + name + chevron; "Reasoning · Context" chip (e.g. "High · 1M"); permission chip with lock icon; menus as in the screenshots (sectioned Reasoning / Context Window / Fast Mode menu with a Default tag; permission options with one-line descriptions; model picker with search, favorites star, provider rail, ⌘1–⌘5 shortcuts, "Legacy models" group). Verified side by side at 1440 and 390, light and dark; mobile uses bottom sheets for the menus.

- **D-17 (owner, 2026-10-05 "recuerda la UI"):** the whole Work Zone session screen follows the T3 Code layout in `reference/ref-4-layout.png`, not only the composer: left sidebar of sessions grouped by project with status ("Working 5m"), branch and diff stat; header with breadcrumb (project / session title) and actions; centered message stream with collapsible "Worked for Xm Ys" turn summaries, sub-agent/tool groups and a "N changed files +a −b · Open diff" card; a floating "N agent working · View · Stop" bar above the composer; the composer with model / reasoning / permission chips and attach + send; a footer strip under the composer with worktree, diff stat and branch. Elements whose data exists today are built in this phase; elements that need new data (e.g. sub-agents) are listed in the inventory as deferred, never faked.

### Automatic session titles (owner, 2026-10-05 — added before closing the phase)
- **D-18:** Every Work Zone session gets a short, recognizable title generated automatically from its first prompt (what was asked). It is generated **on the device by the session's own runtime with a small model**: Claude Code → `haiku`; Codex → `gpt-6-luna` (owner: "GPT6-Luna para los chats de GPT"). Same vendor and same BYO subscription as the session (no cross-vendor transfer, no pooled API key, principle 3/10), one-shot, no tools, read-only/plan, isolated from the session's own thread/history, short timeout.
- **D-19:** Fallbacks never block the session: if the small model is not in the device catalog, is not allowed by the org Work Zone policy, or the call fails/times out, the current heuristic title (first line of the prompt) stays. A title the user typed is never overwritten (track the title's source).
- **D-20:** Title shape: 3–6 words, same language as the prompt, sentence case, no quotes/markdown/trailing punctuation, hard cap 48 characters cut on a word boundary; sanitized on the device (`contain()`/`redact()`, no absolute host paths, no secrets) and validated again by the API (only the session's own device, same tenant). It updates the session and its conversation name and propagates live through `work_session.updated`; it must fit the sidebar row, breadcrumb and browser tab at 1440 and 390 without breaking layout.

### Claude's Discretion
- Exact DB shape for shared-device grants and org policy flags (new table vs JSON on device), as long as tenant isolation tests cover it and grains resolve through `resolveEffectivePermissions`.
- Plan/wave split, fixture recording approach (each fixture costs at most one subscription turn per runtime; record once at the pinned versions).

</decisions>
