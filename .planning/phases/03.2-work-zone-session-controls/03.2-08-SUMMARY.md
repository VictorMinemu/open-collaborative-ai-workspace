# Phase 03.2 Plan 08: Settings › Work Zone policy Summary

An org admin now governs every Work Zone session from Settings › Work Zone policy: Full access (off by default, with the device-owner and member conditions stated), the allowed permission modes, the models per runtime picked only from what devices reported, a maximum effort per runtime and fast mode (off by default, cost stated). One Save goes to the API from Plan 04, which stores, audits and enforces it.

## What was built

- **Queries** (`apps/web/lib/workzone-policy-queries.ts`): GET/PUT `/api/v1/work-zone-policy` parsed with `WorkZonePolicyView`. A save writes the cache and invalidates session controls (`["wz","controls"]`) so open sessions refetch what the API re-decided.
- **Nav + page:** a `work-zone-policy` entry after Bot policy (LockKeyhole icon, `work_zone.manage`), and a page shell matching Bot policy.
- **Form** (`WorkZonePolicySettings`):
  - Permission modes: checkbox cards for Plan, Supervised, Auto-accept edits and Auto, each with a one-line description. With none checked, Save is disabled and the page says "Keep at least one permission mode allowed."
  - Full access: the "Allow Full access" switch with the bypass-risk text and a three-step strip (Organization policy / Device owner / Member). The card turns amber when it is on.
  - Models: per runtime, either "Any model the device reports" or "Chosen models" built from `knownModels`. Ids that no device reports stay listed as "Not reported by any device" until removed.
  - Maximum effort: a select per runtime (No limit, Low, Medium, High, Extra High, Max). An unknown saved level stays shown as itself.
  - Fast mode: the switch shows "Claude: billed from paid usage credits. Codex: uses ChatGPT plan limits at about 2.5x."
  - Members without `work_zone.manage` get "Only workspace admins can change the Work Zone policy."
