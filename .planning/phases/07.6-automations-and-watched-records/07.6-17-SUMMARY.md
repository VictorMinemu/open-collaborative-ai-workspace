# Phase 07.6 Plan 17: Watched records in the browser Summary

**From a board card's menu or its thread strip, a person links the card to an ERP record: pick a connector (the API
offers only what the link would accept), Find the record, tick the fields with their current values, choose how often
and which bot reports, and start; the tile then shows Watching / Changed / Paused / Last check failed, the strip shows
the watch line with Check now and Edit / Stop, and the change and Not saved cards land in the card's thread. A
member-account connector without the viewer's share on the board shows the amber notice with the Allow link and keeps
Start watching aria-disabled; the API's 409 `member_account` stays the authority.**

## What was built

- **Options route (API, Rule 3).** `GET /api/v1/watched-records/options?conversationId=`: the board for posting
  (`writableBoard`, archived 410, `channel.post` 403, hidden 404) plus `record.watch`; bots = agent members that pass
  07.6-05's `decideConversation` for the viewer; connectors = remote ones (org-secret only while switched on) with
  every tool that passes `isDangerousToolName`, each with the board bots granted it and its first required argument
  (`idArg`); a connector is offered only when one of those bots may use a read-only, non-destructive tool. Per-member
  connectors carry only the viewer's own `connection` and whether the viewer shares it on this board; the board's
  `readers` count feeds the notice. No secret, header or URL in the answer (tested).
- **Card menu (R11).** `cardMenuModel` gains `watchRecord?: true` only when offered (`record.watch`, post rights, card
  not watched yet), so 07.1's model assertions are unchanged; the item sits after "Waiting on…" and before the
  separator; the dialog is rendered inside the menu's root (no new wrapper, 43 changed lines against the base).
- **Tile.** One `WatchedIndicator` before the reply count (Eye; Eye + amber "Changed" for 24 h; EyeOff; CircleAlert),
  icon `aria-hidden`, and the sentence (`Watching ERP record SO-10442.` / `Changed in ERP 2 hours ago.` / `Paused: …`)
  in the tile's description. Only board tiles (with a menu) show it; the template preview does not.
- **Strip row 3.** `Watch record` (ghost, Eye) for an unwatched card when the viewer may watch; else the line
  (`Watching ERP · SO-10442 · checked just now`, amber `Changed in ERP …`, `Paused: Víctor Ruiz needs to reconnect
  Field ERP.`, `Last check failed …`), `Checking…` with a spinner until the frame arrives, Check now (`Checked just
  now` for a minute) and ⋯ (Edit watch…, Stop watching…) per `viewerCan`; non-posters see the line only. Stop watching
  confirmation with focus on Cancel and the toast.
- **Dialog.** PanelDialog `sm:max-w-lg`, full screen at 390. Connector labels (`· workspace access`, `· your account`,
  `· your account · connect it first` disabled + `Connect in Settings` rows), the org-secret info line, the share
  notice (`role="note"`, `{n} people`) with `Allow {Connector} in #{channel}` → `/settings/connections?share=…&connector=…`
  (the 07.4 return route remembered), Record ID (mono) + Find (spinner), `Found: …` with native checkboxes, values as
  truncated plain text with a Tooltip, the number hint on JSON numbers, `Pick at least one field` / `Up to 20 fields`,
  Check every (15 min … 1 day, default 1 hour), Report with (bots that cannot use the read tool disabled with the
  reason), Advanced (Read with, Record ID argument, Update with, Add notes with, the hint). Refusals in the UI-SPEC
  sentences (`No record SO-99999 in ERP.`, `Connect ERP first.`, `ERP didn't answer. Try again later.`, …), never the
  connector's text. Edit mode: title `Edit watch`, Connector and Record ID read-only, the record re-read once to show
  values, `Save changes` sends only what changed with `expectedVersion`, `Stop watching…` on the left.

## Deviations from Plan

### Auto-fixed / added

**1. [Rule 3 - Blocking] No member-visible source for the dialog's connectors and tools.** `GET /mcp-servers` needs
`mcp.manage` and `GET /connectors` lists only per-member connections without tools, so a member could not be offered
connectors, read tools or grants. Added `GET /watched-records/options` (contract `WatchOptions`) in the watched module,
decided with the link's rules, with an integration test (Víctor's view, a per-member connector's own connection and
share, Sam's not-connected view, Alex 403, Eve 404 across organizations, a text channel 400, a switched-off connector).
Files outside the plan's list: `apps/api/src/modules/watched/{options.ts,options.int.test.ts,routes.ts,index.ts}`,
`packages/contracts/src/watched-records{,.test}.ts`. Commit `c6be157f`.

**2. [Rule 1 - Bug avoided] Check now would have been blocked for a minute after every link.** The UI-SPEC says
"disabled for 60 s after a check"; the link's silent baseline is a check, so the first Check now (the tracer's step)
could never run within a minute. The cooldown starts at the viewer's own check (202) or a 429, which matches the API's
one-minute route singleton; the thread-open check runs only when the last check is over a minute old.

**3. [Rule 2 - Compatibility] 07.1 tiles and menus render outside a QueryClientProvider** (07.1 static unit tests, the
template preview). The watched list and `record.watch` reads go through `useQuery` with an idle client when no
provider exists (no fetch, no data), and `watchRecord` is added to the menu model only when offered, so every 07.1
test passes unchanged.

### Plan details changed

- **Template-watched fields.** 07.1 templates have no watched-field flag; fields are preselected when a found value's
  key or label names one of the board's (template-snapshotted) fields. The e2e board has no fields, so the tracer ticks
  Status, Delivery date and Total itself.
- **Record label.** The fake ERP's record has no label field, so the box reads `Found: SO-10442` (the id).
- **Linker name.** The paused line uses the linker's display name (`Víctor Ruiz`).
- **Number hint.** The fake ERP's total is a decimal string, so the hint is covered by the web test only.
- **`expectNoSeriousA11y`** is called once in the spec, inside `invariants()`, which every review step uses (dialog,
  share dialog, board with a watched card, strip row, change card, conflict card, paused strip; light and dark). The
  acceptance grep (`≥ 3 lines`) counts call sites, not checks; the checks run 7 containers x 2 themes x 2 widths.
- **Bot call in the conflict test.** The spec drives the one `ocw_record_update` call itself through the fake cell's
  `request()` on the mention's `eventId` (`autoReply` off), so the ERP can be changed between the person's check and
  the bot's write; `fake-cell-plugin.ts` is unchanged.
- **`watch-tile-390`** is an extra capture: at 390 the board and the thread are separate screens, so the tile and the
  strip are captured apart.
