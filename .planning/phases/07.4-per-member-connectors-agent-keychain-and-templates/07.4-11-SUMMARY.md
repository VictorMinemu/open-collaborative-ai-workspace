# Phase 07.4 Plan 11: Member-account audience rule and keychain proxy Summary

**Bots can now call an outside API with a key named by its handle and never see the key. The new route
`POST /agent-channel/v1/http-requests` resolves the key for the turn's own human, sends it only to the key's allowed
hosts through the egress guard, removes it from the answer and records every use without the value, the path or the
query. Tools that act with a member's own account (per-member connectors and personal keys) are offered only where
that member alone reads the result, or where they shared it. Elsewhere they are withheld with the reason
`member_account` and a share link target, and the rule is checked again at call time.**

## Accomplishments

- **Shared claim (`claim.ts`).** The caps-and-taint conditional UPDATE, the `agent_tool_calls` row and the
  `bot.tool_call` audit moved out of the tool gate unchanged. The gate calls `claimToolCall`.
  `tool-calls.int.test.ts` is untouched and green. `finishToolCall` records the outcome of a call the API makes
  itself. `liveTurn` is the rule of every agent call: this agent's turn, whose human still reads the conversation.
- **Keychain proxy (`http-requests.ts`).**
  1. tx0, no user: reads the turn's human from `agent_turns`. If there is no turn of this agent, the answer is
     403 `no_trigger`, audited without a human.
  2. tx1 is opened **as that human**, so personal keys resolve under owner-only RLS for the right owner only. It checks
     in this order:
     - the live turn (`no_trigger`);
     - the tool is on the turn (`not_in_turn`);
     - `currentTurn` re-decides the turn, audience rule included (`policy_changed`);
     - the key is a member-account key withheld here (`member_account`) or not usable (`handle_not_allowed`);
     - host and path (`host_not_allowed`);
     - the claim, where GET and HEAD are reads and other methods are side-effecting (`tainted`, `cap_reached`).

     It then opens the sealed value with its own AAD. Refusals before the claim are recorded and audited through
     `claimToolCall`.
  3. Outside any transaction: the header is built (an `oauth` token comes through the guard). Model headers that
     could carry credentials are dropped, and the request goes through `egressFor(env).fetch` with
     `privateAllowFor(item)`, `requireHttps`, 256 KB and 15 s.
  4. tx2: `bot.tool_call.completed` and `secret.used`, both ids, host, method, status, size and duration only. Guard
     refusals are recorded as `blocked` / `denied`.

  The answer keeps `content-type` only, gives a 3xx `Location` as its host only, and returns a textual body with every
  secret part replaced by `[redacted]`, cut at 256 KB.
- **Audience rule (`turn-policy.ts`).** `memberAccountAllowed({scopeKind, aiChatShared, hasShare})` allows:
  - a one-human DM;
  - an AI chat nobody else reads;
  - an active `member_account_shares` row of the asker for that conversation and resource.

  Per-member connector tools travel under their logical `<safe>__<tool>` names, plus `ocw_connector_list` and
  `ocw_connector_call` (call takes the strictest flags of the offered per-member tools). Personal keys follow the
  same rule; unit keys do not. Withheld resources appear on **any** delivery as
  `{tool, reason: "member_account", resource: {kind, id, name}}`, one entry per connector or key. The gate and the
  proxy re-decide with the conversation id, so revoking a share bites mid-turn.
- **Cell snapshot.** `cellAgentCapabilities` lists `ocw_connector_list` and `ocw_connector_call` when the bot has an
  effective per-member tool grant, and `ocw_connector_list` and `ocw_http_request` when it holds a key grant. It
  never lists a logical per-member name.

## Deviations from Plan

### Auto-fixed / added (Rules 1-3)

1. **[Rule 2 - Security] No outbound call inside a transaction: `prepareInjection` split** (`keychain/service.ts`,
   `keychain/index.ts`, outside the plan's files). `prepareInjection` revealed the value and, for `oauth` keys, fetched
   the client-credentials token inside the caller's tx. That breaks the plan's prohibition. `openVaultSecret` (tx) and
   `injectionFor` (no tx) now exist, and `prepareInjection` composes them unchanged for its 07.4-07 callers; the
   keychain suite is green. An `oauth` key is tested end to end through the proxy.
2. **[Rule 3] `currentTurnTools` keeps its shape; `currentTurn` is new.** `capabilities.int.test.ts` pins
   `currentTurnTools(...)` to `{tools, toolFlags}` exactly, so the keychain decision is returned by a new
   `currentTurn`.
3. **[Rule 2] Global-fetch spy and an `oauth` proxy case** were added to the tests (ledger #175, the split above).
4. **[Rule 2] Threads** are judged through their channel or DM, for the live-turn check, the member-account scope and
   the share lookup. Without this, a DM thread would read as a non-DM and a channel share would not cover its threads.

### Plan text vs. what was built

- **403 `no_trigger` instead of 404 `unknown_turn`.** The brief's rule for every agent call ("a live turn whose human
  still reads the conversation; otherwise 403 `no_trigger`"), the same as memory-files, board and cards. The plugin
  (07.4-09) already maps 403 `no_trigger` and 404 to the same sentence.
- **The "unshared AI chat" definition** excludes the turn's own persona (see key-decisions); ADR-0019's `isShared`
  is unchanged for everything else.
- **The member-account refusal in the proxy landed with Task 2**, because it needs Task 2's `keys.memberAccount`. Task 3
  is therefore test-only: the refusal order, response shaping and egress recording were already complete in the
  Task 1 route. Task 3 proves them, and found one gap in the tests (GET after taint).
- **Platform case** uses both the compose service name `postgres:5432` and the test DATABASE_URL `host:port`, each
  listed on the key and on the admin's private-host list (written directly, because the API refuses to list them).
- **Private unit-key case** binds a second fake to this host's own private IPv4 and maps `erp.test` to it through a
  `node:dns/promises` mock. The admin list is then proven by a full round trip, not only up to "gets to connect". The
  test throws if the host has no private IPv4.

## Broken-windows candidates (not appended: WINDOWS.md is off-limits in this run)

1. **deviation (medium), `apps/openclaw-channel/src/tool-guard.ts`.** The plugin's local gate keeps fixed flags
   `{false, false}` for `ocw_connector_list`, while the API now taints server-side once per-member connectors are
   listed. After a list, a local side-effecting `ocw_connector_call` passes the plugin gate and the API refuses it
   `tainted`. That is safe but gives a less precise sentence. The plugin should read the list's flags from
   `turn.toolFlags`.
2. **todo (medium), 07.4-12.** `/connectors/list` must claim with the turn's `ocw_connector_list` flags (`currentTurn`),
   or the taint decision above never applies. `/connectors/call` should reuse `claimToolCall` / `finishToolCall` /
   `liveTurn` and `memberAccountAllowed` (exported).
3. **deviation (medium), `apps/api/src/modules/bot-capabilities/turn-policy.ts`.** Unit keys are offered wherever the
   asker may use them, also in public channels and shared AI chats. Results fetched with a unit's key can then reach
   readers outside that unit. The ADR-0019 every-reader check or a unit-audience check could apply to unit keys too.
4. **deviation (low), `apps/api/src/modules/agent-channel/tool-calls.ts`.** The gate still opens its tx with
   `userId: null`, so its re-decision never sees personal keys. This is harmless today, because the three `ocw_*`
   tools are self-validated and never ask `/tool-calls`.
5. **deviation (low), ADR-0025.** "Unshared AI chat" for member-account tools excludes the turn's own persona, unlike
   ADR-0019's `isShared`. This should be written into ADR-0025 (07.4-14).
6. **todo (low), 07.4-10.** Shares are looked up on the judged conversation (a thread's channel), so the share REST
   route must store the channel or DM id, never a thread id.
7. **deviation (low), `apps/api/src/modules/agent-channel/http-requests.int.test.ts`.** The private-host case needs a
   private IPv4 interface on the test host. It is present on macOS and on GitHub-hosted runners; the test throws
   otherwise.
8. **Test-environment flake (low, pre-existing).** A testcontainers "ports to be bound" timeout, this time in
   `memory/memory-search.int.test.ts`.
