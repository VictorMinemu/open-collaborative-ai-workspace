# Phase 07.2 Plan 07: OpenClaw memory file tools Summary

OpenClaw bots now have `ocw_memory_list`, `ocw_memory_read`, `ocw_memory_write` and `ocw_memory_propose`. Each one forwards to `POST /agent-channel/v1/memory/*` with the turn's `{eventId, agentId, …}` and nothing else. Before sending, each tool checks the request against a mirror of the 07.2-01 contracts and refuses bad input with the same reasons the API uses. Separately, the model now sees the turn's memory files, and the legacy notes block appears only when the API sent no files.

## What was built

- **Protocol mirror (D-02).** The contract pieces are copied into the plugin, which cannot import contracts at runtime:
  - the path and folder parsers, the limits and the scope kinds
  - strict request bodies (`strictObject`) for the four routes
  - 17 refusal codes
  - `TurnMemoryFile`, and `TurnContext.memoryFiles` declared `.max(2).optional().catch(undefined)`

  Parity tests in `plugin-contract.test.ts` run the 07.2-01 accept/reject path table (39 inputs) through both the mirror and the contract and require the same answer. They do the same for the four request DTOs, including a payload with an extra `userId` or `ownerUserId`. Every response the contract accepts reads identically in the mirror.
- **Client.** Four methods. `list` and `read` make two attempts. `write` and `propose` make one, because a retried append would write twice and a retried proposal would open a second approval.
- **Tools (`memory-files-tool.ts`).**
  - The turn comes from the trusted tool context, as in `ocw_memory_save`.
  - Local refusals cover: no turn, tool not offered, unknown scope, parser rejections (with their reason), folder without a trailing `/`, content over 256 KiB counted in UTF-8 bytes, an invalid op, mode or version, and a reason over 280 characters.
  - `write` accepts only the `personal` and `agent` scopes. A shared scope gets the own-scope refusal: "Shared memory needs ocw_memory_propose". `replace` needs `expectedVersion`, and a tainted turn is refused.
  - `propose` still works on a tainted turn. Its result says a person must approve the change and gives the finding kinds with counts and the reader count. It never shows samples.
  - API errors map to fixed sentences. Logs carry ids and codes only.
- **Gate.** `ocw_memory_write` and `ocw_memory_propose` are self-validated: no `/tool-calls` round trip, but still counted locally. `ocw_memory_write` is always treated as side-effecting. `ocw_memory_list` and `ocw_memory_read` go through `/tool-calls` without argument values. `ocw_memory_save` is unchanged.
- **Mapper.** It adds two kinds of block:
  - "Your private memory with <asker>", rendered only in a DM
  - "<bot> notebook"

  Each block carries the scope alias, path, version and content, plus the sentence "Truncated: use ocw_memory_read for the rest" when the file was cut.
- **Manifest and fake API.** `contracts.tools` lists the seven tools. The fake API serves `/memory/list|read|write|propose` from an in-memory store and records every call. Bodies are strict: an unknown key gets a 400.

## Broken-windows candidates (not written to WINDOWS.md, as instructed)

1. **No real API behind the routes until 07.2-11.** The plugin calls `/memory/*`, which only the fake implements. On today's API a call gets a 404, shown to the model as "Not …: this conversation turn is no longer active." The model never sees these tools until 11 offers them in `turn.tools`, so nothing reaches a bot before then.
2. **No container smoke yet.** The real-cell smoke (`infra/openclaw/test/run-container-smoke.sh`, `run-fake-api.ts`) does not run a memory-file scenario. The fake routes are ready for one; 07.2-15 (phase gate) should add a scenario.
3. **Unknown scope kinds are dropped.** The `memoryFiles` mirror uses the exact `scopeKind` enum. If the API adds a kind, the plugin drops the whole list and falls back to the legacy notes. That is safe, but the notebook would silently disappear until the mirror is updated.
