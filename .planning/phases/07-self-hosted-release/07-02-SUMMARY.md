## What was built

- **`schema-check.ts`**
  - The local list comes from `readMigrationFiles`; the applied list is one `select name, hash … order by id` on a short-lived `pg.Client`.
  - Undefined table/schema and permission-denied errors map to `missing`.
  - Exported from `@ocw/db`, which only `apps/api` imports.
- **`post-migrate.sql`** gains two idempotent lines: `GRANT USAGE ON SCHEMA drizzle TO ocw_app` and `GRANT SELECT ON drizzle.__drizzle_migrations TO ocw_app`.
  - The int test proves `ocw_app` cannot INSERT, UPDATE, DELETE or TRUNCATE the table.
  - CLAUDE.md asks for plan mode on DB permission changes. The grant was scoped up front to exactly these two lines, and approval was delegated by the plan.
- **`main.ts`:** `await checkSchema(env.DATABASE_URL)` runs right after the `loadEnv` block and before `buildApp`. On any status other than `ok`, it calls `console.error(describeSchemaMismatch(...))` and `process.exit(1)`, the same shape as `EnvError`. 07-06 can swap `loadEnv()` for an async loader in place.
- **Upgrade baseline**
  - Regenerate with `pnpm --filter @ocw/db upgrade:baseline 3bbcbd9`, optionally with `[--out FILE] [--seed FILE]`.
  - It runs that ref's migrations and SQL from `git archive` in a throwaway `postgres:18` testcontainer, which is stopped and removed at the end.
  - Dump size: 175161 bytes, 5200 lines, 60 tables, 17 migration rows.
- **Seed** (`seed-phase-5.sql`, all synthetic)
  - Two organizations (`acme.test`, `beta.test`), three users with accounts, members and org_members.
  - A channel with a root message, a thread reply and an edited message with its version.
  - A human DM, and an AI chat with a user turn, an assistant reply, a generation and a usage record.
  - A team bot, an `app.secrets` row sealed with the fixed test key, an `openai` model provider with `secret_id` + `secret_ref`, an attachment row, streams with stream events, and audit events.

## Deviations from Plan

1. **[Rule 2 - Clarity] Extra hint in the mismatch messages.** The `behind`/`missing` messages also say `(from a source checkout: pnpm db:migrate)`, and the `diverged` message adds the fix. `pnpm dev` does not migrate, so a developer on a stale DB now gets the exact command. The plan wording is kept verbatim as the prefix.
2. **[Rule 1 - Test design] Two adjustments to the upgrade test.**
   - The pre-upgrade `behind` check runs as `ocw_migrator`. An N-1 database has no read grant for `ocw_app`, so as the app role it reads `missing`; the test asserts both.
   - The upgrade test file also holds the append-only and dump-content checks (no container needed), so all of SELF-03's upgrade evidence is in one file.
3. **[Rule 3 - Test infra] PORT for the spawned API.** The env schema requires `PORT > 0`, so the schema-guard test reserves a free loopback port first instead of passing `0`.
4. **[Process] First `pnpm verify` had one flaky failure.** It ran on the Task 1 tree, concurrently with my baseline generator, and finished 2734/2735. The failure was the `realtime-presence.int.test.ts` rate-limit test ("condition not met within 3000 ms"), a load-sensitive timing test that doesn't touch my code. Rerun alone it passed 9/9. The final `pnpm verify` on the complete tree, run with nothing else in parallel, passed 2746/2746 before any commit was made. So the Task 1 commits rest on that final green run, not on a separate green run of the Task 1 tree alone.
