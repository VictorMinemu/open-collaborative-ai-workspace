<decisions>
## Implementation Decisions

### Common to phases 07.1–07.7 (orchestrator, 2026-10-08)
- **C-01:** The Control Plane owns the feature. Agents act only through `ocw_*` plugin tools that the Agent Channel API
  decides (resolver, agent ∩ human, taint) and audits; OpenClaw's in-cell equivalents (file memory, cron, webhooks,
  `sessions_send`, exec approvals, per-requester MCP OAuth) stay off (principles 6, 9, 12).
- **C-02:** Contracts first (Zod in `packages/contracts`), RLS on every organization-scoped table with a cross-tenant
  test, an audit event for every sensitive action, `pnpm verify` (incl. `pnpm guard`) green before every commit, TDD.
- **C-03:** UI work is verified at 1440 and 390, light and dark, with reviewed screenshots and e2e through
  `scripts/e2e-isolated.sh`; Woodpecker CI must stay green.
- **C-04:** No new paid or hosted service; any new dependency is pinned, license-checked by `pnpm guard`, and justified.
- **C-05:** Research for this phase: `.planning/research/OPS-FEATURES.md` (the F-numbers below). Code references there
  were taken at `main` 4644fcd; re-check them.

### Phase decisions
- **D-01:** Per-tool approval policy (`never | always | when_tainted`, approvers) decided in `POST /tool-calls`; the gate
  sends full arguments only for tools with a policy (today only `query`/`url` travel) — F10.
- **D-02:** Approval card shows the exact action; approval grants one call bound to a hash of tool + canonical params
  (07.2 primitive); the call re-runs as a new turn; the 10 s gate timeout is not used to wait for humans. OpenClaw
  `requireApproval` is not used (not in our typings, resolves outside our cards).
- **D-03:** `ocw_start_work_zone(projectId, deviceId, prompt)` posts a `work_zone` card in "proposed" state; the
  triggering human with `work_session.create` + `device.use` starts it in their name; never from tainted turns; never
  `fullAccess` chosen by an agent; fits Phase 12's live card later — F11.

- **D-04 (orchestrator, after research):** research design and defaults accepted — one `approvalForCall()` decided in all
  three routes (`/tool-calls`, `/connectors/call`, `/http-requests`); the API flags policy tools per turn
  (`turn.toolFlags[tool].approval`) and only those send `arguments` (≤ 32 KB); a mid-turn policy change denies with
  `policy_changed`; a lowest-priority hook pins the checked params (OpenClaw "last returned params wins"); RFC 8785
  canonicalization in contracts with the RFC vectors (reject lone surrogates and NaN); grant hash over (agent,
  requester, conversation, tool, sha256 of canonical args), consumed at dispatch inside the claim transaction, lifting
  taint for that one call; pending 24 h, approved grant valid 15 min; **the re-run turn is delivered for the requester,
  not the approver** (additive `CardAction.turnUserId` for grant kinds; extends ADR-0020); exact action shown in the
  card only in a DM whose single human is the requester, elsewhere a summary with review at `/approvals/<id>`; a new
  `/approvals` inbox with its own badge (07.2's Memory badge filtered to memory kinds); Work Zone proposals are kind
  `work_zone.start` (`server_apply`) over an extracted `createWorkSession`, always `default` mode, new
  `work_prompts.proposed_by_agent_id`, tainted proposals always refused; arguments retained with org data (no purge in
  07.5). ADR-0026.

- **D-05 (orchestrator; superseded by 07.6 D-08 — fixed in a standalone hardening fix before phase execution, 07.5 only relies on it):** fix the existing delegated-reply gap found by 07.7 research: Agent Channel `/messages` only
  re-checks that the turn's human still reads the conversation when the replied-to message is human-authored
  (`agent-channel/cards.ts:78-85`); card-decision and future agent replies skip it. Send the `eventId` and take the
  human from `agent_turns` so every agent post is re-checked, with a regression test.
