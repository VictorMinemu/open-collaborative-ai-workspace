# Phase 07.13 Plan 25: Pins at Codex 0.172.0 / Claude Code 2.1.332, recorded offline Summary

I regenerated the Codex app-server types from 0.172.0 and added `--offline` to both recorders. With it I recorded the
new pins' fixtures: the real binaries ran against `infra/fake-model` on loopback with temp homes and no login. Every
adapter test now replays the floor and the pin. `PINNED_RUNTIME_VERSIONS`, the inventory evidence, the manifest date
and the inventory page all moved together.

## What was built

- **Codex types.** I ran `generate-codex-types.mjs --codex <0.172.0>` with `HOME`/`CODEX_HOME` in a temp dir. The
  output has 154 files (it was 145): 17 changed and 9 new. The adapter compiles unchanged.
  - New fields: `ThreadItem` start and complete timestamps (`ThreadItem` is now an intersection type),
    `MessagePhase.partial_answer`, `CommandExecutionApprovalKind.humanCommand` (behind `requiredHumanApproval` +
    `experimentalApi`, so not reachable from this adapter), `Turn.rootTurnId`, `TurnStartParams.parentTurnId` and
    `rootTurnId`, `ModelListParams.modelProvider`, `mcpToolCall.environmentId`, and new `CodexErrorInfo` values
    (spend limits, `modelNotFound`, …).
  - None of these changes a field the adapter reads.
- **`record-codex-fixture.ts --offline`** works for every scenario. It reuses 04's flow through one `openOffline()`
  (fake, `offlineRecorderEnv`, the version guard, `--print-env`, the loopback check) and `offlineCodexOverrides()`
  (provider, `model="fake-model"`, plugins / remote_plugin / apps off). browser-mcp now uses the same helpers.
  - `offlineSpawn` hands the adapter the offline env and arguments instead of the caller's env.
  - The turn prompts carry `[[call exec_command {"cmd":…}]]`. 0.172 offers `exec_command` (unified exec), not
    `shell`; the recorder prints the offered tools and the `exec_command` parameter names.
  - The repo maps to `/tmp/ocw-fixture-repo`, the rest of the temp dir to `<tmp>`, and the caller's HOME to
    `/Users/fixture-user`.
- **`record-fixture.ts --offline`** covers `catalog`, `settings` and `title`. `plan-read` is refused offline (the fake
  has no Anthropic tool use).
  - The SDK child gets the offline env (`recorderQuery`), and the temp repos live inside the run's temp dir.
  - The cost guard accepts `apiKeySource: "ANTHROPIC_API_KEY"` only when `offlineAnthropicKey(env)` holds (the fake
    key and a loopback `ANTHROPIC_BASE_URL`). It has its own unit test.
- **Fixtures.** No fixture contains `$HOME`, `/Users/<owner>` or an e-mail.

## Deviations from Plan

1. **[Rule 3 - Blocking] The offered shell tool is `exec_command`, with `{ cmd }`.** The plan said "the offered shell
   tool" with `{"command":["cat","hello.txt"]}`. A first offline run answered "Tool shell not offered". That run was
   overwritten, never committed. Commit 835c8328.
2. **The supervised-write approval differs at 0.172.0.** The fake writes through the shell, so Codex asks
   `item/commandExecution/requestApproval` (0.160.0 asked `item/fileChange/requestApproval`). The test takes the
   expected request per version. The `mode.default` evidence keeps 0.160.0's file-change line and adds 0.172.0's
   command line.
3. **The catalog evidence stays on 2.1.289 / 0.160.0.**
   - The offline Claude catalog is the API-key list (no explicit `claude-*` rows, every base 1M). It cannot show the
     `context.window` claim ("only claude-opus-4-6 offers both").
   - The offline Codex list is the bundled one, not an account's.
   - Both new catalogs are replay-tested and named in the evidence where they show the same thing.
4. **Commit grouping.** Task 1's commit also carries the 0.172.0 supervised-write fixture and the full recorder: the
   recorder and the runtime test file are shared by Tasks 1 and 2, and every commit stays green. The Biome format
   fix of `record-codex-fixture.ts` (one long line from Task 1) went into the Task 3 commit.
5. **TDD order.**
   - RED was observed for the `--offline` `--print-env` canary cases: 14 failures before the flag existed.
   - The replay tests were written after recording, because the fixtures are the implementation. Each new replay
     case passed against its fixture on the first run, and the old cases kept passing.
6. **Titles are the fake's.** The offline title prompts carry `[[title:…]]`, so the answer is the forced text. The
   tests check the protocol and the normalization, not model quality.
