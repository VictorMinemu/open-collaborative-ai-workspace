# Phase 07.1 Plan 07: Record templates API Summary

**Record templates are now unit-scoped and reuse the existing unit grains. A board channel created from a template snapshots its prefix, naming rule and fields and copies its columns. Dana's "Case file" template in Ops makes `#cases` name its first card `EXP-0001 · Acme · Broken pump`.**

## Plan-mode record (permission paths)

The owner delegated approval. The decision table was applied as planned.

| Route | Decision | Not found / other tenant |
|---|---|---|
| `GET /record-templates?unitId=U` | `unit.read` on `unitResource(U)`; `canManage` = `unit.members.manage` on U | 404 `unit_not_found` |
| `GET /record-templates` | `unit.read` (org); `canManage` = `unit.manage` | — (RLS: only own org's rows) |
| `POST /record-templates` | `unitId: null` → `unit.manage`; otherwise `unit.members.manage` on the unit | 404 `unit_not_found` |
| `PATCH /record-templates/:id` | same decision on the template's unit; row locked `FOR UPDATE`; stale `expectedVersion` → 409 `template_version_conflict` with `details.template` | 404 `template_not_found` |
| `DELETE /record-templates/:id` | same decision | 404 `template_not_found` |
| `POST /channels` + `templateId` | existing `channel.create` + `placeableUnit`; then `templateForChannel`: org-wide, or the template's unit is on the channel unit's path | 400 `template_not_available` (same for unknown, foreign or out of scope) |

No new permission and no RLS change. Every write is audited (`record_template.created|updated|deleted`) with only `templateId`, `unitId`, `version`, `fieldCount` and `columnCount`. `channel.created` now records `templateId`.

## Deviations from Plan

1. **[Rule 1 - Bug] Timestamp mapping.** This caused the 500 described above. It was fixed before commit 1 in `templates.ts`.
2. **[Scope] Error codes not in the cross-plan list:**
   - `template_exists` (409): duplicate name in the same unit or organization-wide, case-insensitive;
   - `template_not_found` (404): PATCH/DELETE of an unknown or foreign id;
   - `unit_not_found` (404): reused from units.

   A PATCH whose merged template does not fit together is answered with the listed `invalid_naming_rule` code and the contract's message. Examples: dropping a field the rule uses, nulling the prefix of a numbered rule, or a numbered rule on a template without a prefix.
3. **[Order] `POST /channels`.** The template is resolved after `placeableUnit`, because the scope depends on the channel's unit. Before, the temporary refusal ran before placement. Placement errors (404/403) still take precedence, as before. Phase 07.3's code in `chat/index.ts` is untouched.
4. **[Test extras] Cases beyond the behaviour list.** These cover the same truths:
   - a plain member uses an ancestor's template;
   - an Ops template is refused on an organization-level channel;
   - `canManage` is false for Dana on Operations;
   - a deleted template cannot be used for a new channel;
   - a PATCH with no change is refused.
