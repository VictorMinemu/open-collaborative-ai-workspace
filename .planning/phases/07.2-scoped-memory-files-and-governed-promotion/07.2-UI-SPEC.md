## Information Architecture and Navigation

### Where Memory lives

| Entry | Route | Shows |
|-------|-------|-------|
| Main nav "Memory" (`NotebookText`), between Bots and Work Zone, `permission: "memory.read"`, `badge: "pendingApprovals"` | `/memory` | The viewer: all scopes the viewer may read |
| File deep link | `/memory/<scopeId>/<…path>` (segments URL-encoded per segment) | The tree with that file selected and its folders expanded |
| Scope deep link | `/memory/<scopeId>` | Desktop: that scope's `MEMORY.md`. Phone: the tree with that scope expanded and scrolled into view |
| View state | `?tab=edit` · `?tab=history` · `&v=<version>` | Edit mode, History open, a selected revision (back button restores the previous state) |
| Proposals inbox | `/memory/proposals?box=review|requested|decided` | Approvals the viewer may decide or requested |
| Proposal review | `/memory/proposals/<id>` | One proposal |
| Agent page | `/bots/<agentId>?tab=memory|capabilities` | A bot's memory (scopes the viewer may read) and capabilities, read-only |
| DM memory panel | existing "Memory" button in the DM header | Existing notes list + "Open in Memory" |
| Proposal card | in the conversation where the bot proposed | Platform-owned card mirroring the approval |

### Scopes in the tree

Scopes are the top-level nodes of one tree. Order (fixed): private scopes (by bot name) → bot notebooks (by bot name)
→ units in organization-chart order (department, then its teams and projects, depth-first by name) → organization.
`/memory` on desktop opens the first scope's `MEMORY.md` in that order.

| Scope kind | Row label | Icon | Kind tag (`Badge outline`) | Accessible name | Who sees it (API decides; the UI only renders what `GET /memory/scopes` returns) |
|-----------|-----------|------|-----------------------------|-----------------|-----------------------------------------------------------------------------------|
| personal | `You & {bot}` | `Lock` | `Private` | "You and {bot}, private memory" | The human owner only. Never admins (ADR-0010) |
| agent | `{bot} notebook` | `Bot` | `Bot` | "{bot} notebook, bot memory" | Personal bot: its owner. Shared bot: read by everyone who can see the bot (`bot.read`), so it can use its notebook in its own team channel; editing and promoting need `bot.configure` (owner, unit leads, admins) — orchestrator decision 2026-10-08, matches plan 03 |
| unit | `{unit name}` | `UNIT_KIND_ICON[kind]` | `Department` / `Team` / `Project` | "{unit}, {kind} memory" | Members of the unit subtree, leads on its path, admins |
| org | `Organization` | `Globe` | `Everyone` | "Organization, memory for everyone" | Everyone with `memory.read` |

Inside a scope: `MEMORY.md` pinned first, then folders, then files, each group case-insensitive alphabetical
(`localeCompare` with `sensitivity: "base"`, `numeric: true`). Folders exist only when they hold at least one file the
viewer may read (a `deny` path rule hides the folder entirely). Folder names show without a trailing slash; file names
show the stem in the row colour and `.md` in `text-muted-foreground`.

## Interaction Contract

### Tree (ARIA tree via headless-tree)

| Key | Action |
|-----|--------|
| Tab / Shift+Tab | Into the tree on the focused item (roving tabindex: one tab stop), then out |
| ↓ / ↑ | Next / previous visible item |
| → | Closed scope or folder: expand. Open: move to first child. File: nothing |
| ← | Open scope or folder: collapse. Otherwise: move to parent |
| Home / End | First / last visible item |
| Enter | File: open it and move focus to its `<h1>` (desktop and phone). Scope or folder: toggle |
| Space | Same as Enter |
| Type characters | Typeahead to the next visible item starting with them (500 ms buffer) |
| `*` | Expand all siblings of the focused item |
| F2 | Rename or move the focused file (writers) |
| Delete | Delete the focused file, with confirmation (writers; not `MEMORY.md`) |
| Shift+F10 / ContextMenu | Open the focused row's ⋯ menu |
| `/` (focus not in a text field) | Focus the search field |

- Pointer: click on a scope or folder row toggles it; click on a file opens it and keeps focus on the row (browsing
  continues with arrows). Right-click opens the same menu as ⋯ (Base UI context menu).
- Expanded state per scope persists for the session; opening a deep link expands its ancestors and scrolls the row
  into view (`block: "nearest"`, `behavior: "auto"` under reduced motion).

### Edit, save and guard

- Desktop: the Edit tab enters Edit (no single-key shortcut, so screen-reader browse keys stay free); Cmd/Ctrl+S saves; Cancel
  leaves without saving (asks when dirty). Phone: Edit tab.
- Save sends `{content, expectedVersion}`. Success: toast "Saved version {n}", back to View, focus on the Edit tab
  trigger (desktop) or the View tab (phone).
- Dirty guard: leaving Edit with changes (tree click, breadcrumb, tab change, back button, route change) opens the
  Discard dialog; `beforeunload` covers closing or reloading the tab.
- 409 → conflict view; 422 `secret_detected` → secret banner; 413 / `memory_file_too_large` and `memory_scope_full`
  → blocking notice with the copy below; network failure → blocking notice "Couldn't save. Your changes are still
  here." + Try again. The draft is never lost on an error.

### History and restore

- History toggle (desktop ≥ 1280) opens the column and selects nothing; selecting a row shows its diff against the
  previous version (version 1 against empty). URL keeps `?tab=history&v={n}`.
- Restore: confirmation → `POST restore {version, expectedVersion}` → new version with op "Restored", the diff closes,
  the document shows the restored content, toast "Restored version {old} as version {new}".

### Proposals

- Approve or Deny opens a confirmation dialog that names the file, the scope and the reader count, with an optional
  note (Textarea, 280 characters, counter shown from 200). Confirm sends `{outcome, actionHash, note?}` with the hash
  of the view on screen. Cancel has initial focus.
- After a decision: the status pill and footer update in place, toast "Applied to {path}" (approve) or "Proposal
  denied" (deny), focus moves to the `<h1>`; the inbox row moves to Decided; the nav count drops.
- 409 `approval_action_changed`: dialog closes, notice "This proposal changed while you were reviewing it." + "Reload"
  (reloads the view and its hash; never auto-decides). 409 `approval_already_decided` / `approval_expired`: the view
  refetches and shows the current state with its copy.
- Clicking a finding row scrolls the diff to its first line and outlines its spans for 2 s (`ring-2 ring-amber-500`
  only with `motion-safe`, else static until the next click).
- Realtime: `approval_request.updated` refreshes the count, the inbox and an open review without reload; a review
  that becomes decided by someone else shows the decision line and announces it politely.

### Focus management

- Desktop tab order: rail → tree column (header buttons → search → scope filter when shown → tree → Proposals row) →
  file header (breadcrumb links, h1 is not a tab stop, View·Edit, History, ⋯) → document links → history column.
- Opening a file by keyboard (tree Enter, search result Enter, breadcrumb, in-viewer link) focuses the file `<h1>`
  (`tabIndex=-1`, visible focus ring). Opening by pointer leaves focus where it was.
- Phone: entering the file screen focuses the `<h1>`; Back restores focus to that file's row in the tree.
- Entering Edit focuses the editor at the start of the document. Leaving returns focus to the control that triggered
  it.
- Conflict and secret banners: `role="alert"`; focus moves to the conflict heading ("Choose what to keep",
  `tabIndex=-1`) and stays in the editor for the secret banner (the alert is announced).
- Dialogs: first field focused (path dialogs select the stem); confirmations focus Cancel; closing returns focus to the
  trigger (for tree shortcuts, the tree row).
- After Delete: focus the parent folder row (tree) and open the parent's `INDEX.md` or the scope `MEMORY.md`.

### Reduced motion (`prefers-reduced-motion: reduce`)

- Chevrons switch without rotation transition; skeletons `motion-reduce:animate-none`; no smooth scrolling anywhere
  (tree reveal, diff jumps, finding jumps); status pill fade disabled (existing `motion-reduce:animate-none`).
- Existing dialog and sheet transitions are untouched (global behaviour).
