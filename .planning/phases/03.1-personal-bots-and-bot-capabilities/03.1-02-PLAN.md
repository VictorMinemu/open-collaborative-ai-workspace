## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `/api/v1/agents*` | Lists, details, edits and DM opening; identity from the session |
| API → `org:` and `user:` topics | Realtime fan-out of agent changes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.1-02-01 | Information disclosure | `/agents` list/detail | high | mitigate | `perms.filter(bot.read, agentResource)` + `personal_bot` precondition; detail hidden as 404; integration tests as Alex and admin |
| T-03.1-02-02 | Information disclosure | `agent.*` realtime events | high | mitigate | Personal bot events only on `user:<owner>`; test asserts nothing appended to `org:` |
| T-03.1-02-03 | Elevation of privilege | admin editing a personal bot | high | mitigate | Field edits require `bot.configure` (owner); admins limited to `{enabled}` and DELETE via `bot.manage`; 403 test |
| T-03.1-02-04 | Information disclosure | team-bot DM cross-human leakage (API side) | high | mitigate | One DM per (bot, human) via `dm_key`; history and roster scoped to the DM; Alex 404 on Sam's DM; cell-side session isolation proven in 03.1-04 smoke `dm-isolation` |
| T-03.1-02-05 | Repudiation | governance actions | medium | mitigate | `agent.disabled` / `agent.deleted` audits with actor and `governance: true` |
| T-03.1-02-06 | Denial of service | personal-bot sprawl | low | mitigate | `max_personal_bots_per_user` enforced in the create transaction |
| T-03.1-02-07 | Tampering | messages to a disabled bot's DM | medium | mitigate | DM archived in the disable transaction; existing `archived` precondition refuses posts |
</threat_model>
