## Phase Goal

**As a** member of a team that works in the workspace, **I want to** hold my whole daily conversation there — channels grouped by department and team, DMs and group DMs with people and bots, messages I can edit, delete, react to, pin, save and link to, @channel/@here and notifications I control, search and files — **so that** I do not need a second chat tool and every message stays attributed, editable under audit and delivered in realtime.

**This plan's slice (tracer):** presign → browser PUT straight to Garage → API verifies → authorized download, through a real Garage container. Plan 12 wires it into the composer and message list. Planner decisions P-01 … P-12 are in `04-01-PLAN.md` (P-03 readable set, P-08 executor rules, P-10 storage, P-11 rate limits).

Per P-05, P-10, P-11. Tests first (RED).

1. sniff.ts: read the first 4100 bytes with `rangeGet` and detect with `file-type`; when the declared type is in `INLINE_IMAGE_TYPES` the sniffed type must equal it (else rejected, 409 `type_mismatch`); for other declared types store the sniffed type when detected, otherwise `application/octet-stream`; never treat SVG or HTML as an image.
2. renditions.ts: for sniffed raster images, stream the original into sharp with `limitInputPixels` (default 268 M px) and `.rotate()` first, produce `thumb.webp` (fit inside 720) and `large.webp` (fit inside 2048) with metadata stripped, `put` both, store width/height and `has_renditions = true`; failures leave the attachment ready without previews (logged, no crash).
3. complete computes SHA-256 by streaming the original, then sniff, then renditions, then marks ready and audits `attachment.uploaded`.
4. disposition.ts `contentDisposition(filename, kind)` per RFC 6266 (ASCII fallback + `filename*`), used by download (attachment, sniffed type or octet-stream) and preview/large (inline, image/webp). download audits `attachment.downloaded` `{attachmentId, conversationId}`; previews are not audited (ADR-0015 records why). 302 responses carry `Cache-Control: private, no-store`.
5. app.ts: the pino `redact` list gains the response `location` header; storage code never logs URLs; presign route gets `config.rateLimit` 60/min keyed by user (P-11).
6. Boot: if storage is configured, `ensureBucketCors([OCW_PUBLIC_WEB_URL, ...OCW_TRUSTED_ORIGINS])` (methods PUT, GET; header content-type; expose ETag; max age 3600) runs in the background with retries and never blocks or fails the API start; `GET /attachments/config` reports `reason:"unavailable"` with `enabled:false` while Garage is unreachable.
7. sweeper.ts: every 10 minutes (`setInterval`, unref'd, stopped on close) take `pg_try_advisory_lock`, call the new SECURITY DEFINER function `app.due_attachment_sweeps(p_limit integer)` added to post-migrate.sql (owned by the migrator like the existing lookup functions; returns `id, organization_id, conversation_id` for rows with `purged_at is null` and status pending/rejected older than 24 h or deleted older than 30 days; `REVOKE ALL … FROM PUBLIC; GRANT EXECUTE … TO ocw_app`), then per row open `withTenant` for its org, `remove` its three keys and set `purged_at`. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /conversations/:id/attachments`, `/complete`, `/download` | Untrusted filenames, types, sizes and ids |
| browser → Garage (presigned PUT/GET) | Direct object access limited to what the signature allows |
| API → Garage (server operations) | Internal credentials from SecretReference |
| uploaded bytes → sharp / browser | Untrusted file contents |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-04-04-01 | Information disclosure | download/preview of another conversation's or org's file (IDOR) | high | mitigate | Every route resolves the attachment's conversation through `access.readable` (404 when hidden); RLS on `app.attachments`; tests with ids from another conversation and another org |
