# Phase 07.14 Plan 06: Approvals, templates and shares on the member-mode predicate Summary

**Per-tool approvals, agent templates and member-account shares now answer "is this a member's account?" with `isPerMemberMode` / `PER_MEMBER_MODES`, so an `org_oauth` or `org_client_credentials` server is the organization's MCP server everywhere outside the proxy: its approval card never says "your account", a template cannot require it, and nobody can share it as their own.**

## Performance

- **Duration:** about 25 min
- **Completed:** 2026-11-06
- **Tasks:** 2 of 2 (Task 1 tracer, Task 2 auto; both TDD)
- **Files modified:** 8

## Accomplishments

- `tool-approval/kind.ts` `sourceOf`: `connector = !!s?.authMode && isPerMemberMode(s.authMode)`. Org modes get `kind: "mcp"`, `account: "org"`, so `card.ts` renders `Notes · MCP server`.
- `tool-approval/policies.ts` `approvableCatalog`: `kind: s.authMode && isPerMemberMode(s.authMode) ? "connector" : "mcp"`. `CatalogSourceLike.authMode` is now `ConnectorAuthMode`.
- `agent/templates.ts`: both the required-connector check and the editor's `connectors` list filter on `inArray(mcpServers.authMode, [...PER_MEMBER_MODES])`. The error copy stays the same.
- `connectors/shares.ts` `ownResource`: `row && isPerMemberMode(row.authMode)`. Create refuses the share, and list skips a forged one, through the same function.
- None of the four files compares against `"org_secret"` any more.
