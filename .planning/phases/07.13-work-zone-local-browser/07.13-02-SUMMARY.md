## Decisions Made

See `key-decisions`. In short: `extractZip` is archive-agnostic (the Chromium presence check lives in the CLI), it
closes the file descriptor on refusal (it now runs inside a long-lived daemon, not a one-shot build step), and every
refusal names entry and reason.

## Deviations from Plan

1. **[Rule 2 - Correctness] `extractZip` closes the zip and reports reasons per refusal.** The infra script exited the
   process on error; as a library in the daemon it must not leak the fd. Messages went from `refused zip entry #N` to
   `refused zip entry #N: <reason>`. The CLI prints the same success line and usage text. Commit `e8504016`.
2. **[Rule 3 - Blocking] `playwright-core` added as a devDependency of `@ocw/browser-engine`** next to the planned
   peer dependency, so the package's own tests resolve the bundled zip/PNG readers. Same locked version, no new tarball.
3. **[Additive] `filterStateForSite` drops every origin when the site host is empty** (a `file:` origin has an empty
   host name and would otherwise match ""). Identical to brw's rules for every non-empty host.
4. **[Additive] `bundle.test.ts` scratch install now links playwright-core beside the SDK**, so "only the externals
   beside it" holds once later plans import it.
5. **Task 1 had no meaningful RED**: the files are verbatim copies, so the ported tests passed on first run (the tracer
   gate re-ran them green). Tasks 2 and 3 had real RED commits.

No capture test was added (not in this plan's files); `maskedScreenshot` stays covered only by brw's stack smoke until a
later plan tests it.
