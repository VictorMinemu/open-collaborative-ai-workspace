## Phase Goal

**As a** member who holds a private AI chat, **I want to** share it in place with a colleague, a team, a department or the whole organization so that several of us and the model write in the same conversation — the model knowing who said what and answering one request at a time on the asker's own plan or model, nobody's private context leaking, and agents joining as full personas that post live cards — **so that** AI work in the workspace becomes multiplayer, attributable and safe.

**This plan's slice:** agents join AI chats as full personas (they already join channels, DMs and group DMs), answering through OpenClaw with the audience-aware tool intersection. The UI to add them lands in 06-12. P-decisions: `06-01-PLAN.md` (P-10).

<objective>
Let owners add personas to AI chats and let participants @mention them: flat Agent Channel deliveries with attributed history, posting rights for member agents, the audience check that withholds scoped tools, and the plugin mapping for the `ai_chat` kind.

Purpose: AGENT-02 (AI chats), MULTI-05 (persona side), MULTI-06 (memory) — D-06, D-07; P-10.
Output: `members.ts`, AI chat agent dispatch, agent posting into AI chats, `TurnContext.withheld`, audience check, plugin mapping, `ai-chat-delivery.int.test.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| owner client → members routes | Agent ids untrusted; only the owner adds/removes |
| AI chat send → Agent Channel event → OpenClaw cell | Identity, history and tools decided by the API; the cell enforces fail-closed |
| cell → `POST /agent-channel/v1/messages` | Agent posts into an AI chat only as a member, and only while the answered human can still read it |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-10-01 | Elevation of privilege | persona using a scoped tool on behalf of someone who may not, or exposing its results to participants who may not | high | mitigate | Agent ∩ asker via `OnBehalfOf`; audience check (every joined human, never with unit/org grants); withheld list; tool gate refuses withheld calls (Task 2) |
| T-06-10-02 | Information disclosure | memory or personal context leaking into a shared chat | high | mitigate | No memory in any `ai_chat` delivery (test); personal instructions never reach the cell |
| T-06-10-03 | Spoofing | persona history attributing the model's words to a human or vice versa | medium | mitigate | Server-resolved authors; model rows as a distinct system principal; roster from participants (Task 1) |
| T-06-10-04 | Elevation of privilege | non-owner adding agents, personal bots joining, agents posting into chats they left | medium | mitigate | `ai_chat.manage` owner-only; personal bots refused; `channel.post` needs the member relation (Task 1) |
| T-06-10-05 | Tampering | regressions in channel/DM delivery | medium | mitigate | Existing agent-channel, group-dm, tool-calls and memory suites run unchanged |
