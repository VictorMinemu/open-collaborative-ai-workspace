## Phase Goal

the MVP 1 acceptance scenario runs against that exact stack (user story and plan map: 07-01-PLAN.md).

`SecretStore` interface at boot, then the `vault` profile and the one command that moves an existing install onto it.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → OpenBao (compose network) | Credentials (AppRole) in `.env`; secrets in transit on the internal network |
| operator host → `secrets/` | Seal key and recovery material at rest |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-06-01 | Information disclosure | secret values in errors, logs, argv or CLI output | high | mitigate | Errors name references only; canary tests; values via stdin/HTTP; names-only output (Tasks 1, 2) |
| T-07-06-02 | Elevation of privilege | OpenBao reachable from outside | high | mitigate | No published port; asserted by config test and gate check (Task 2) |
| T-07-06-03 | Elevation of privilege | long-lived root token | high | mitigate | Revoked after setup; recovery material only in a 0600 file under 0700 `secrets/`, ignored by git and docker (Task 2; 07-03, 07-04) |
| T-07-06-04 | Denial of service | sealed OpenBao after a restart blocks the API | medium | mitigate | Static auto-unseal; restart case in the gate check (Task 2) |
| T-07-06-05 | Spoofing | API reading another app's paths | low | mitigate | Policy limited to `secret/data/ocw/*`, read only; 403 tested (Task 1) |
| T-07-06-06 | Tampering | references in variables other containers need | medium | mitigate | `loadConfig` refuses references outside the four API-only names (Task 1, D-16) |
</threat_model>
