# Phase 3.1 Plan 12: OpenClaw Marketplace executor in the cell + API-authoritative install gate Summary

The cell now installs exactly the marketplace plugins an admin approved, and nothing else.

**How an install runs**
- The executor downloads the pinned artifact from the configured ClawHub origin only and verifies the approved sha256 and npm integrity.
- It installs through `openclaw plugins install npm-pack:<file> --force --accept-capabilities`. The command is an argv array; no shell is involved.
- OpenClaw's own `security.installPolicy` then re-hashes the staged archive and asks the API whether this exact (package, version, sha256) is an approved install in flight. Any other answer, an error, or an unreachable API blocks the install.

**After the install**
- The cell inspects what it got, turns its hooks off, and reports the declared tools.
- The API re-scores the report. A plugin that turns out to declare a refused surface (or another id or version) is rejected and uninstalled.
- Accepted tools become per-bot capabilities behind the existing tool gate.

**Across restarts**
- The boot render re-allows installed plugins from `GET /agent-channel/v1/plugins`.
- The gateway-writable cache is used only if the API is unreachable at boot, and never approves an install.

## Spike findings (for ADR-0011)

All of these were read from the 2026.9.7 image (`docker create` + `docker cp` of `/app/docs`, `/app/dist`, `/app/node_modules`; no OpenClaw container started). They were then confirmed by running OpenClaw's own CLI on the host against a temp state dir, with no gateway running.

- **Install command.** `openclaw plugins install npm-pack:<abs .tgz> --force --accept-capabilities`.
  - `npm-pack:` is an "arbitrary source", so a non-interactive run needs `--force`.
  - A third-party plugin needs `--accept-capabilities` (capability consent).
  - `--pin` applies to `npm:` installs only.
  - There is no `--json` flag. Success prints `Installed plugin: <id>`; a policy refusal prints `Install blocked by policy … Reason: <reason>` and exits 1.
  - With a running gateway the CLI applies the install through it; without one it prints `Saved for the next Gateway start`.
- **Uninstall.** `openclaw plugins uninstall <id> --force`. It removes the install record, the allowlist entry and the directory, and leaves `plugins.entries.<id>.enabled: false`. A second uninstall exits 1 with "not associated with a tracked package install", which the executor treats as already gone.
- **Inspect.** `openclaw plugins inspect <id> [--runtime] --json` returns:
  - `plugin.{id, version, packageName, contracts, toolNames, hookNames, channelIds, providerIds, webSearchProviderIds, …}`;
  - `tools[].names` (runtime);
  - `typedHooks`, `gatewayMethods`, `mcpServers`, `httpRouteCount`;
  - `install.{integrity, version}`.
  - Real outputs are kept as test fixtures.
- **Policy contract** (dist `install-policy-*.mjs`, `install-security-scan.runtime-*.mjs`).
  - **Process:** no shell, empty base env plus `passEnv`. The request arrives on stdin as JSON with `protocolVersion: 1`, `targetType`, `targetName`, `sourcePath`, `sourcePathKind`, `source`, `origin`, `request {kind, mode, requestedSpecifier}` and `plugin {packageName?, version?, pluginId}`. The answer goes to stdout: `{protocolVersion: 1, decision: allow|warn|block, reason}`.
  - **Fail-closed cases:** non-zero exit, timeout, invalid JSON, or a block without a reason.
  - **Calls per `npm-pack:` install: three.**
    1. Preflight on the **archive file** (`sourcePathKind: "file"`).
    2. The unpacked package directory.
    3. The dependency tree.
  - **Specifier:** every call carries `requestedSpecifier: "npm-pack:<archive path>"`. The gate therefore hashes the exact staged archive, so the "only the unpacked package" gap does not exist for this source.
  - **Script checks:** the command and the script argument must be absolute, regular files, not symlinks, owned by root or the current user, not group/world-writable, with secure ancestor directories, inside `trustedDirs`. Config requires `exec.source: "exec"`.
  - **When it runs:** install and update only. It never runs at gateway startup. `doctor` only validates and prints a note.
- **Where installs live.**
  - Package roots: `<state>/npm/projects/<pkg-slug>/node_modules/<pkg>`, a managed npm project per plugin, with the tarball copied to `_openclaw-pack-archives/`.
  - Install records: SQLite machine state (`plugins.installedIndex`), not `openclaw.json`. Both survive a container restart.
  - Config: the install adds the id to `plugins.allow` and sets `plugins.entries.<id>.enabled: true`. Our boot render rewrites the config, so the allowlist entry comes back from the API.
- **`clawhub:` installs and `CLAWHUB_URL`.** Not used. The gate blocks any non-`npm-pack:` source ("only admin-approved marketplace installs staged by the workspace are allowed"). Whether `clawhub:` honours `CLAWHUB_URL` is moot for this design.
- **npm without registry egress.** OpenClaw plans each plugin's `openclaw` peer with `npm install --package-lock-only` in a temp project. With the registry unreachable this took **473 s** on npm's default retries. With `npm_config_fetch_retries=1` and short timeouts it took **5 s**. Both the cell entrypoint and the executor's child env set these bounds.
- **Hooks.** `plugins.entries.<id>.hooks {allowConversationAccess, allowPromptInjection}` validates against the 2026.9.7 schema. Non-bundled plugins already lack conversation access by default; prompt injection is allowed by default, so we set it to `false`. Hook policy changes hot-reload.
- **Remaining window for ADR-0011.** While a row is `installing`, someone with a shell in the cell could run the install of that same approved tuple by hand. The gate binds the sha256, so the result is the approved artifact. Every other tuple, source or time is blocked.

## What was built

- **Executor** (`plugin-installer.ts`, Task 1). It follows the plan's interface and adds:
  - argument hygiene: plugin id, package, version and sha256 are validated before anything runs, so a value can never become a flag or a path;
  - a `refresh` once for an event not yet in the snapshot;
  - ClawHub's `X-ClawHub-Artifact-Sha256` header must agree with the digest;
  - redirects refused;
  - an inspect cross-check of id, version and npm integrity; a mismatch is removed again;
  - a process-global queue, so installs run one at a time even across plugin module instances; the boot cache write is deliberately outside it, which avoids a deadlock found in a contract test;
  - the CLI is not tied to the account's abort signal, and a replay of an installed row re-reports without reinstalling.
- **Install gate** (`install-policy.mjs`). Node builtins only. It reads and gunzips the staged archive (minimal ustar/pax reader), takes name and version from the archive's own `package.json`, cross-checks them with `plugin.*` / `origin.*`, then asks the API with the cell token.
- **Boot.** `render-config` adds `security.installPolicy` and `installedPlugins`; the entrypoint fetches `GET /plugins`; the Dockerfile copies the gate root-owned `0644`.
- **API** (Task 2).
  - `verify-install`: approves only an `installing` row with the same tuple; refusals are audited as `plugin.install_blocked` with a reason (`not_approved`, `not_in_flight`, `version_mismatch`, `digest_mismatch`).
  - `GET /plugins`: lists ids, packages, versions and status.
  - `report`: applies `recordPluginReport`, as described in Decisions.
  - `GET /cell`: now delivers `plugins`, and the `agent_cell.config_read` audit names the row ids.
- **Smoke `marketplace`** (Tasks 1 and 3). Described in "What CI cell-smoke must show" below.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 - Bug] `defaultRunCli` passed the CLI path twice.**
- **Found during:** the host end-to-end run (Task 1). Unit tests used a fake runner.
- **Issue:** OpenClaw answered `does not know the command "/app/openclaw.mjs"`, so every real install would have reported `install_failed`.
- **Fix:** the runner now executes exactly the argv it is given. A new test runs the real runner against a script: the argv round-trips, including spaces and `$(…)`; the exit code and the timeout come back.
- **Commit:** 28f2e9e (before the first commit).

**2. [Rule 1/3 - Blocking] About 8 minutes per install without npm registry egress.**
- **Found during:** a host spike with the registry unreachable (473 s).
- **Cause:** OpenClaw's peer planning ran npm on its default retries. That exceeds the 120 s CLI limit and would have failed every offline-cell install, including the smoke.
- **Fix:** bounded `npm_config_fetch_*` in the cell entrypoint (gateway env) and in the executor's child env. An operator's own setting wins.
- **Commit:** 28f2e9e.

**3. [Rule 2 - Security] The gate binds the digest itself.**
- `verify-install` requires `sha256`; the plan had it optional.
- The gate accepts only `npm-pack:` sources and re-hashes the staged archive on every one of OpenClaw's three policy calls. It cross-checks the archive's `package.json` against what OpenClaw claims to install.

**4. [Rule 2 - Security] Additions beyond the behaviour list.**
- In the cell: the ClawHub digest header check, redirects refused, the inspect cross-check (id, version, npm integrity) with removal on mismatch, and argv hygiene on every event value.
- In the API: rejection for builtin or malformed tool names and for a plugin id or version mismatch, grants removed on rejection and for tools an update dropped, `surfaceGrew` in the `plugin.installed` audit, and late transitions refused (409).

**5. [Open item from 03.1-10, addressed] Plugin runtime deps without a lockfile.**
- `infra/openclaw/plugin-runtime/{package.json, package-lock.json}` is installed with `npm ci` in the Dockerfile and in the smoke's plugin copy.
- `overrides` pin `hono` 4.13.9, `@hono/node-server` 2.1.1 and `ip-address` 10.7.2 to pnpm-lock's versions. Plain npm resolution picked versions published 1–6 days ago, against the repo's 7-day `minimumReleaseAge`.
- `plugin-runtime.test.mjs` keeps the manifest equal to the plugin's dependencies, every tarball from the registry with sha512, and the overrides applied. All 95 locked packages match `pnpm-lock.yaml`.
- Verified on the host: `npm ci` from the lock, then the built plugin imports `mcp-probe`, `plugin-installer`, `ws` and `zod`.

### Plan wording

**6. `trustedDirs` and `source`.**
- The plan said `trustedDirs: ["/opt/ocw"]`. OpenClaw checks the node command against `trustedDirs` too, so the list is `[dirname(node), "/opt/ocw"]`.
- `exec.source: "exec"` is required by the 2026.9.7 schema.

**7. The smoke cell bundles only SearXNG.**
- The plan said `OCW_BUNDLED_PLUGINS=none`. The capabilities scenario runs in the same cell and needs SearXNG, so the cell uses `searxng`. DuckDuckGo is not bundled either way.
- Restart persistence is proven by the boot allowlist line and `plugins list … enabled`, not by "loaded at boot". DuckDuckGo is `onStartup: false` and is not the search provider, so OpenClaw would not load it at boot.

**8. The echo fixture version is 0.1.0, not 1.0.0.** That is the version the 03.1-11 fake ClawHub catalog serves (`ocw-test-echo-plugin-0.1.0.tgz`).

**9. Interfaces.**
- The installer's `exec` is a `RunCli` (argv including the CLI path), not `typeof execFile`. Extra deps: `refresh`, `restrictHooks`, `maxBytes`, `tmpDir`, `cliPath`.
- `OpenClawPort.restrictPluginHooks` is new; files outside the plan's list are `channel.ts` and `openclaw-port.ts`.
- `reconciler.ts` is unchanged. Uninstall already takes grants off every bot in the API (`tools.updated`), the per-turn `toolsAllow` caps the turn, and the plugin is gone; the smoke proves the stale-grant case.

**10. Other files outside the plan's list.**
- `plugins/risk.ts` (`refusedReportedSurface`) and `plugins/index.ts`.
- The inspect fixtures.
- `plugin-runtime/*` and its test.
- `apps/openclaw-channel/README.md`.

**11. Rejected rows stay `failed` after the cell removed them**, with a `(removed from the cell)` suffix, so the admin sees the verdict. `GET /cell` includes `failed` rows so the executor can carry out the rejection's uninstall. 03.1-11 listed only installing, installed and uninstalling.
