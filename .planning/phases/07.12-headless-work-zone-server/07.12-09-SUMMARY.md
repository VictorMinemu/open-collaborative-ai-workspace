## Accomplishments

The spec runs five serial cases on the desktop project. The mobile project skips them in `beforeAll` (one headless
device per run).

1. **install.sh, setup, approval, daemon online.** `beforeAll` builds the bundle with `build-bundle.mjs`. The helper
   then checks each step:
   - `curl -fsSL <api>/api/v1/runtime/install.sh | sh` exits 0 and prints `Installed ocw-runtime <v> (<sha12>).`.
   - `~/.local/bin/ocw-runtime` exists.
   - The installed `current/ocw-runtime.mjs` hashes to the `sha256` of `GET /api/v1/runtime/version`.
   - `install.json` has exactly the five keys, and its `serverUrl` is the API.
   - The fake npm was called once, with `install --prefix … --ignore-scripts @anthropic-ai/claude-agent-sdk@<x>`.

   The installed `setup` prints `<web>/settings/devices?pair=XXXX-XXXX`, and the owner approves it with
   `approvePairingInUi`. Setup then exits 0, and its output has these lines in order: `Paired "E2E headless"`,
   `Registered "headless-repo"`, `No service installed`, `Settings › Devices: <web>/settings/devices` and the share
   line. The installed `ocw-runtime run` brings the device online with its project, and the device card shows
   `data-status="online"`.
2. **Direct share.** `shareDevice` uses the default mode. Sam opens New session, picks `headless-repo` and Claude Code,
   and starts the session. He sees "I'll start by reading". He allows `notes/ocw-change-1.md` from the approval banner.
   The session goes idle with "Done. I created".
3. **Team project.** `createTeamProject("Headless team project", [Sam])` and `linkRepo`. Sam opens
   `/work-zone/projects/<unit>` and clicks the page's New session. The dialog preselects `headless-repo`, and the same
   approval runs. `GET /api/v1/work-sessions/:id` as Sam shows `teamProject.id` equal to the unit.
4. **`doctor --json`.**
   - The check ids come in the order of `DOCTOR_CHECK_IDS`.
   - `runtime`, `pairing`, `server`, `daemon` and `projects` are `ok`, and `service` is `warn`.
   - The exit code is 1 exactly when `counts.fail > 0`.
   - `device` is "E2E headless" and `link` is `<web>/settings/devices`.
   - The raw stdout contains neither the token from `<OCW_HOME>/device-token` nor `ocwd_`, the scratch HOME or the
     scratch root.
   - The projects line is `headless-repo (~/…)`.
5. **`remove-project headless-repo`** runs while the daemon is up. It prints `Removed "headless-repo"`, and the API
   lists the repository as unavailable within 30 s.

Cleanup always runs: the sessions are archived, `removeTeamProject` runs, the daemon (and any setup still waiting)
gets SIGTERM, the device is revoked and the scratch root is removed.

## Deviations from Plan

### Execution order

**1. Tasks 1 and 2 were written and committed together.** The spec's Task 2 cases (team project, doctor JSON,
remove-project) were written in the same RED commit as Task 1. The helper and fake npm then landed in one GREEN commit,
so there is no separate Task 2 commit. All of Task 2's acceptance criteria and verify commands pass.

### Adjustments (Rule 2: PD-19 defence in depth, and correctness)

**2. The scratch PATH holds a `node` symlink, not node's directory.** The plan's PATH was [fake-npm bin, node's dir,
`/usr/bin`, `/bin`]. Node's nvm directory also holds the real `npm`, `npx`, `pnpm` and `yarn`. The helper symlinks
`node` into its scratch bin, beside the `npm` wrapper, and adds the scratch `~/.local/bin`. `install.json`'s `nodePath`
is then that symlink, which lives exactly as long as the install does.

**3. `TMPDIR` and `OCW_HOME` are set explicitly.** `TMPDIR` is the scratch root, so install.sh's `mktemp -d` stays
inside it. `OCW_HOME` is `<HOME>/.ocw`, the same as the default, but explicit.

**4. The control socket path is guarded.** The helper refuses a scratch `OCW_HOME` whose `runtime.sock` path would be
longer than 100 bytes; macOS caps a Unix socket path at 104. The scratch root uses the short prefix `ocw-hs-` and its
real path (`/private/var/…`), so HOME and the registered repository agree for the doctor's home-relative display.

**5. `startHeadlessServer` takes an optional `apiUrl`.** It defaults to `OCW_E2E_API_URL`, as `tests/env.ts` does. The
helper cannot import `tests/env.ts`, which imports Playwright's `test` at runtime, because its vitest unit test loads
the same module.

**6. Sam allows the write from the approval banner.** With the default (Supervised) share, the fake runtime asks before
writing. Sam approves once, then the spec waits for idle and "Done. I created". The plan only said "assistant-message
and the session idle". This also proves the approval relay through the bundled daemon.

**7. The team-project case also checks the session's `teamProject.id` through Sam's API**, in addition to what the plan
asked.

**Total deviations:** 1 execution-order note and 6 small adjustments. No architectural change, no product code
touched, and `e2e/support/work-zone-device.ts` was not modified.

  - `fake-npm.mjs` is not for the container: 10 runs the real `npm install`.

    ok; `service` warn with `--service none`. On macOS, doctor's `runtimes` was not asserted. It can be a fail with

- **11 (gate):**
  - The full e2e run builds `apps/local-runtime/dist` in this spec's `beforeAll`. The API caches the first verified
    dist it loads until it restarts. If an earlier spec in the same run (headless-pairing's Server tab) asks for
    `/runtime/version` while a stale `dist` exists, install.sh still installs a consistent pair: the cached bundle and
    its sha. That bundle is built from older sources, though. Run `pnpm --filter @ocw/local-runtime build:bundle`
    before a gate run.
  - Rate-limit budget per API process: this spec uses 1 pairing start (per IP) and 2 admin lookup/approve calls (the
    per-member bucket). Spec order is alphabetical, so it runs long after headless-pairing.
