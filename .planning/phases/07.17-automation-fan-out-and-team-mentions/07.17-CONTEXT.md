# Phase 07.17: Automation fan-out and team mentions - Context

**Gathered:** 2026-11-09
**Status:** Ready for planning (after 07.16)
**Mode:** owner request + `--auto` defaults. The owner's scenario (2026-11-09): an automation detects new orders every
10 minutes through an MCP; for each, it creates a new thread in a channel or a new card on a kanban board, reads the
documentation (in their case the vehicle's), starts working in the Work Zone and keeps orchestrating, reading the
output; when it finishes or needs help it mentions a team or a person so they get a notification; it can change the
card's status.

<domain>
## Phase Boundary

Automations open one conversation per new item and the bot works each one with its 07.16 Work Zone profile; people and
bots can mention teams; bots move the cards their automation opened.

Not in this phase: new trigger sources beyond schedules/webhooks/mail (the "poll" is a scheduled run whose bot calls the
MCP); editing card text or fields by bots (ADR-0022 P-03 stays); `@channel`/`@here` for bots.

</domain>

<decisions>
## Implementation Decisions

- **D-01:** Schedule minimum interval 5 minutes (ADR-0028 had 15); the existing cost/limit guards still apply.
- **D-02:** **Fan-out tool** `ocw_conversation_open` (Agent Channel API) on automation run turns: opens a new
  conversation in the run's target only (a new top-level message + thread in a channel target, a new card via
  `createBoardCard` in a board target, column = the target's), with a title, a short body and an `externalKey`
  (the item's id). Capped per run (default 10) and per day.
- **D-03:** **Dedupe:** `(automation_id, external_key)` unique; opening an existing key returns the existing
  conversation (`opened: false`) and never posts again.
- **D-04:** Each opened conversation gets its own bot turn (child of the run, same run-as person and tools, including the
  07.16 Work Zone profile), carrying the item's body as untrusted content (tainted turn). The run turn itself stays
  short (list, dedupe, open).
- **D-05:** Allowed on tainted turns (the run read the MCP): opening conversations in the run's own target is not a
  write outside the platform; still audited (`automation.conversation_opened`).
- **D-06:** **Board moves:** a bot may move and set waiting on any card its automation opened, from any turn in that
  card's thread (extends ADR-0022's "card it created in this conversation"), also on tainted turns when the bot's profile
  has `actOnOutsideContent` (BWZ-05). Never edits text or fields.
- **D-07:** **Team mentions:** `@team` resolves an org unit (team or department, stable id) in the mention directory;
  notifies members who can read the conversation (resolver), for human and bot authors; bot mentions capped per message
  (default 3 targets); a team mention by a bot never wakes other bots (ADR-0027 unchanged).
- **D-08:** An automation may name default escalation targets (people/teams by id) that its bot is told about.
- **D-09:** Documents: the bot reads them through existing tools (connectors, memory, attachments, sandbox); nothing new.

</decisions>

## Addendum after research (2026-11-10, orchestrator, `--auto` defaults)

- **D-10 (OQ1, run anchor):** fan-out automations post their run cards as replies in one per-automation run-log thread (no
  board card per run); the open call marks the run answered (an empty list = "nothing new"). If a top-level non-card
  message is not allowed in a board channel, the run log is a single pinned log card in the board's first column.
- **D-11 (OQ2, caps):** minimum interval 5 min and org cap 288 runs/day; rows still holding the old defaults (15 / 96)
  are updated by the migration; the editor warns when the bot's daily turn limit is too low for the schedule.
- **D-12 (OQ3):** the D-06 board-move exemption also lifts the session-output mark for that same card move (only move /
  set waiting, only the turn thread's card, only a card this bot's automation opened, only with `actOnOutsideContent`).
- **D-13 (OQ4):** a department mention reaches its subtree members (path), capped at 200 recipients per message.
- **D-14 (OQ5):** units get a stored `org_units.handle`, generated once, unchanged by renames; editing deferred.
- **D-15 (OQ6):** card titles on boards with a naming rule: the bot's typed title, like run and inbound cards.
- **D-16 (OQ7):** fan-out only from schedule and Run now; webhook/mail keep one item per event.
- **D-17 (OQ8, changed from the research default to avoid a regression):** the bot cap of 3 targets per message applies
  to TEAM mentions only; bot @person mentions keep today's behaviour (no new cap).
- **D-18 (OQ9):** no new grain for human team mentions: posting rights + `unit.read`; a confirmation above 20 recipients.
