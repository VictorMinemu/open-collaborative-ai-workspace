# Phase 07.14 Plan 04: OAuth client — client credentials, D-10 failure steps and the Test sign-in diagnosis Summary

**The connector OAuth client now gets client-credentials tokens through the egress guard (SDK `fetchToken` plus `ClientCredentialsProvider`, with a lenient RFC 8414 read for servers that have no authorization endpoint). Every OAuth error names its D-10 step while the 07.4 member codes stay the same. `diagnose()` runs the ordered Test sign-in without registering a client or storing anything.**

## Decisions Made

See `key-decisions` in the frontmatter. In short:
- A guard refusal against the authorization server is `token_endpoint_untrusted`.
- `invalid_scope` is reported as step `scope_rejected` everywhere, but it is terminal only for client credentials.
- With client credentials, metadata wins over the admin's Token URL. Without metadata the `issuer` step is skipped and the admin URL is checked before the grant.
