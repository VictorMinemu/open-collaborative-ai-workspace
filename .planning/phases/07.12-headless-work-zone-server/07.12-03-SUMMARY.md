# Phase 07.12 Plan 03: Terminal pairing client, project removal by any handle, and service.env — Summary

**`ocw-runtime enroll --server <url>` now pairs a headless machine by device code (link + `XXXX-XXXX`, polls per RFC
8628, saves the token and `pairedWith` through the same `saveEnrollment` as the typed code). `remove-project` takes a
directory, a name or an id with the daemon up or down, and `run` loads `~/.ocw/service.env` (0600, owner-checked, names
only) before the daemon starts.**

## Accomplishments

- **Terminal pairing (D-03).** Without `--code`, `enroll` posts `/api/v1/devices/pairings` with the proposed name,
  platform and `RUNTIME_VERSION`, prints:
  `To pair this computer, open:` / the `?pair=` link / `or open <verificationUri> and enter the code:` / the code /
  `Waiting for approval (expires in 10 minutes). Press Ctrl-C to cancel.`
  It then polls `/pairings/token` with the device code in the body. Once approved it prints
  `Paired "<name>" with <organization> as <owner>.`, the token path, `Settings › Devices: <webUrl>/settings/devices` and
  the start line. Denied, expired and refused answers end with one line and exit 1; Ctrl-C prints `Pairing cancelled.`
  and exits 130 with nothing written. A plain `http://` URL to a non-loopback host gets a stderr warning.
- **Server default.** `--server` > `OCW_SERVER_URL` > `install.json`'s `serverUrl` > usage error.
- **Typed code unchanged**, plus `webUrl`, `deviceId` and `pairedWith` saved and the Settings link printed when known.
- **`remove-project <dir|name|id>` (D-07).** Resolved against projects.json first; removed through the daemon when it is
  up, straight from projects.json when it is down. Output: `Removed "<name>" (<localId>).` (was the JSON
  `{ "removed": true }`; `e2e/support/work-zone-device.ts` passes a localId and ignores the output, so it still works).
- **service.env (D-12).** `run` applies it before `Daemon.create()`; one info line with the key names (and which keys
  the environment already set), or one error with `chmod 600 ~/.ocw/service.env`.
- **Unpaired daemon** now says: "no device token found; pair this device with `ocw-runtime setup` (or from the desktop
  app), then restart the runtime". No existing test asserted the old text.

## Decisions Made

- **Poll cadence.** The runtime waits `interval` before every poll, the first included (RFC 8628 §3.5). `slow_down` and
  HTTP 429 add `PAIRING_SLOW_DOWN_STEP_SECONDS`; network errors and 5xx keep the interval and retry until `expiresIn`.
- **Stale ownership.** `saveEnrollment` removes a previous `webUrl`/`pairedWith` when the new answer lacks them.
- **Deleted directories.** `resolveRef` falls back to the plain resolved path when `realpath` fails.
- **Strict mode check.** service.env is refused on any group/other bit (`mode & 0o077`), since a group-writable
  secrets file is as unsafe as a readable one; the message says "readable or writable by other users".
