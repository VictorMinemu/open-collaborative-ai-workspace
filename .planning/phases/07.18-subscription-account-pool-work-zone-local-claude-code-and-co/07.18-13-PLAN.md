## Phase Goal

See 07.18-01 (the hub). **This plan's slice:** the API side of ChatGPT accounts that live on a device: an admin signs
one in on a service device from Settings (the device shows Codex's own code through the API), the device's slots become
pool accounts usable only on that device, and removing one signs it out there.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| admin → API | Starts sign-ins on organization devices |
| device → API | Code, outcome and slot frames are untrusted |
| API → browser | The one-time code reaches admins only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.18-13-01 | Information disclosure | the user code on a stream or in audit | high | mitigate | Only in the Redis record and the admin GET; realtime says "changed"; audit carries codes of errors only |
| T-07.18-13-02 | Elevation of privilege | a device owner adding usable pool accounts | medium | mitigate | CLI slots arrive disabled (PD-11); only `provider.manage` enables |
| T-07.18-13-03 | Spoofing | a device reporting another device's slots or sign-in | high | mitigate | Rows keyed by the reporting device; sign-in frames matched to its own command id (E11) |
| T-07.18-13-04 | Elevation of privilege | sign-ins on personal laptops | medium | mitigate | Service devices only (D-10); 409 otherwise |
| T-07.18-13-05 | Repudiation | sign-ins and removals | low | mitigate | `account_pool.sign_in_*`, `slot_reported`, `account_removed` audited |
</threat_model>
