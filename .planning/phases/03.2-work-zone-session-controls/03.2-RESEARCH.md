# Phase 03.2: Work Zone session controls - Research

**Researched:** 2026-10-05
**Domain:** Runtime session controls (Claude Agent SDK 0.3.282 + Claude Code CLI 2.1.289; `codex app-server` 0.160.0), Device Link command/event protocol, org policy capping
**Confidence:** HIGH for the inventory (type definitions + read-only probes against the installed CLIs); MEDIUM for runtime behaviour that still needs a recorded fixture (marked UNCONFIRMED)

## Summary

Every control in the reference composer exists in at least one runtime, and almost all of them can change **inside one session, from the next turn**, without restarting the runtime. Claude Code exposes them as control requests on the streaming `Query` (`setModel`, `setPermissionMode`, `applyFlagSettings({effortLevel, fastMode, ultracode})`). Codex exposes them as **stable per-turn overrides on `turn/start`** (`model`, `effort`, `summary`, `serviceTier`, `approvalPolicy`, `sandboxPolicy`, `approvalsReviewer`), which "become the defaults for later turns on the same thread". Both runtimes report their model list **for the logged-in subscription**: Claude via `initializationResult().models` / `supportedModels()`, Codex via `model/list`, which needs no thread. I ran both read-only, without sending a turn (evidence below).

The reference UI over-promises in four places, so the phase must not copy it literally. (1) **Context window 200k/1M is a real choice only on Opus 4.6 / Sonnet 4.6.** On Opus 5.5, Sonnet 5.5 and Fable the runtime reports 1M for the base model; a "200k" option there would be fake. (2) **Claude fast mode is billed from paid usage credits.** On this account the runtime reports `extra_usage_disabled`. (3) **"Ultrathink" is not an effort level.** It is a prompt keyword. (4) **"Full access" conflicts with AGENTS.md:** "Never enable a runtime's bypass-permissions mode (`bypassPermissions`, `danger-full-access` or equivalents)". That conflict is an owner decision (options in §Full access).

Two existing gaps must be fixed in this phase whatever is decided. First, in the Codex adapter `default` and `acceptEdits` are **identical** (`workspace-write` + `on-request`), so "Supervised" on Codex does not ask before edits. Second, the Claude mapper forwards only the **first** `system/init`, so the effective model and mode after a change never reach the server.

**Primary recommendation:** add one device command `session.configure` and one device event `session.settings`, both carrying the same `SessionSettings` contract. The API intersects every request with org policy ∩ runtime-reported catalog before it reaches the device. The adapter applies pending settings **between turns** (Claude: control requests before pushing the next user message; Codex: overrides on the next `turn/start`) and reports the effective values back. The existing `work_session.updated` broadcast then propagates them to every controller.

## User Constraints

No CONTEXT.md exists for this phase (no `/gsd-discuss-phase` yet). Binding constraints come from ROADMAP Phase 03.2 and AGENTS.md:

- An option is never shown as available unless the adapter has confirmed it (ROADMAP 03.2 goal, SC4)
- Changes apply from the next turn, keep the conversation, are audited and visible live to every controller; the single execution authority is unchanged (SC1, SC3, SC5)
- Org policy caps the mode server-side, whatever the client sends (SC3)
- AGENTS.md security rules: never enable `bypassPermissions` / `danger-full-access` or equivalents; never weaken an approval gate; secrets via `SecretReference`; no absolute host paths leave the device; every sensitive action emits an audit event
- AGENTS.md: Zod contracts first in `packages/contracts`; adapters normalise at the edge; adapters tested against recorded fixtures per pinned runtime version; flag any paid or metered API before adding it (Developer Profile)

## Full access: the conflict and options (owner decision)

The facts:

- **AGENTS.md** forbids it: "Never enable a runtime's bypass-permissions mode (`bypassPermissions`, `danger-full-access` or equivalents)."
- **Contracts** forbid it: `packages/contracts/src/session-events.ts:14-15`: "`bypassPermissions` is never accepted, anywhere." and `export const PermissionMode = z.enum(["default", "acceptEdits", "plan"]);`
- **Claude adapter** fails closed: `disableBypassPermissionsMode: "disable"` and `allowDangerouslySkipPermissions: false` (`claude-runtime.ts:205-218`), and it aborts if init reports `bypassPermissions` (`claude-runtime.ts:329-343`).
- **Codex adapter** fails closed: it aborts on `resp.sandbox?.type === "dangerFullAccess" || resp.approvalPolicy === "never"` (`codex-runtime.ts:229-234`).
- **ROADMAP Phase 7** adds a Semgrep gate against permission-bypass tokens.
- **T3 Code** (the reference app) implements Full access as exactly what we forbid: Claude `permissionMode:"bypassPermissions"` + `allowDangerouslySkipPermissions:true`; Codex `approvalPolicy:"never"` + `sandboxPolicy:{type:"dangerFullAccess"}` (CodexAdapterV2.ts:686-693).

| Option | What "Full access" does | Fits AGENTS.md? | Trade-off |
|---|---|---|---|
| **1. Keep it blocked** | Shown disabled: "Blocked by workspace security policy" | Yes | Zero risk. Diverges from the reference (SC3 already allows "only when the organization policy allows it") |
| **2. Platform auto-approve (recommended)** | The runtime stays in `acceptEdits` (Claude) / `workspace-write`+`on-request` (Codex). The **adapter** answers every approval request `once` itself. Secret deny rules, the PreToolUse hook, `redact()/contain()` and the Codex sandbox stay active. Every auto-approval emits an audited `approval.resolved` with actor = policy. Org policy flag `allowFullAccess` is **off by default**, an org admin turns it on, and every switch is audited | Yes: no runtime bypass mode is enabled and the gate stays in code | No prompts for the user. Not "no sandbox": Codex sandbox escalations (network, writes outside the repo) are auto-approved through the normal request path. Needs a sentence in AGENTS.md/ADR naming it as the sanctioned "no prompts" mode |
| **3. Real runtime bypass, org-admin opt-in** | `bypassPermissions` / `danger-full-access`+`never` | No: requires superseding the AGENTS.md rule with an ADR, removing three fail-closed checks and the Phase 7 Semgrep rule | Fastest runtime path. Loses per-action approval audit (Claude never calls `canUseTool` in bypass). Deny rules and hooks still apply in Claude ("Deny rules block in every mode, including `bypassPermissions`", permission-modes docs) |

### Anti-patterns to avoid

- **Hard-coding the catalog** (T3 Code ships a hand-maintained `model-manifest.json`): this violates "never shown unless the adapter has confirmed it". Render only from `ModelInfo` / `Model`.
- **Calling `applyFlagSettings` with a `permissions` key**: "a second call with `{permissions: {...}}` replaces the entire `permissions` object from a prior call" (`sdk.d.ts:2921-2927`). That would drop our `secretDenyRules()` and `disableBypassPermissionsMode`. Only send scalar keys (`effortLevel`, `fastMode`, `ultracode`, `disableAutoMode`, `maxEffortLevel`).
- **Treating the client-sent mode as authoritative**: always intersect server-side, then re-validate on the device.
- **Persisting the "requested" value as if it were effective**: the runtime can override it (fast mode switching the model to Opus, auto mode unavailable → Manual, auto-mode fallback to prompting). Show the effective value.

## Common Pitfalls

1. **Codex "Supervised" doesn't ask before edits today.** `sandbox: mode.data === "plan" ? "read-only" : "workspace-write"` with `approvalPolicy: "on-request"` (`codex-runtime.ts:216-221`) makes `default` ≡ `acceptEdits`. Fix with a mapping table and a fixture per mode.
2. **Only the first `system/init` is forwarded** (`claude/mapper.ts:121-123`: `if (this.started) return [];`), so a model, mode or fast-mode change never reaches the server. Forward later inits as `session.settings`.
3. **Slash commands can change runtime state behind the platform's back.** `/model`, `/effort`, `/fast`, `/config`, `/update-config`, `/agents`, `/mcp` appear in the probe's built-in list, and a prompt starting with them would bypass policy and audit. The adapter must intercept platform-owned commands (`/model`, `/effort`, `/fast` → `session.configure`) and refuse a denylist. Pass through an allowlist (`/compact`, `/context`, `/usage`, skills).
4. **The fast-mode "On" state is not the effective state.** Fast mode can be refused (`extra_usage_disabled`, `model_not_allowed`, `preference`, `cooldown`). Read `fast_mode_state` after applying. It is also metered.
5. **The adapter's Claude CLI is not the SDK's bundled CLI.** The adapter runs the PATH `claude` (2.1.289); the SDK bundles 2.1.282. Fixtures must name the CLI version actually used (today `claude-code-2.1.287.*`). Record new ones at 2.1.289.
6. **Ultracode and Codex `ultra` start multi-agent work inside the runtime.** Sub-agents write in the same tree, which principle 4 tolerates only as one process. WORKZONE-MULTI-AGENT.md says to show them as read-only sub-lanes. Gate them behind policy `allowUltracode` (default off) or defer.
7. **Codex `ReasoningEffort` is `string`.** Validate against the selected model's `supportedReasoningEfforts`, not a fixed enum. Re-validate on model switch.
8. **Experimental Codex fields fail without `experimentalApi:true`.** Don't send `collaborationMode`, `permissions` or `thread/settings/update` in 03.2.

## Org policy capping (server-side)

- Follow the Phase 3.1 `bot_policies` pattern (`apps/api/src/modules/bot-capabilities/policy.ts`: one row per org, defaults when absent): a `work_zone_policies` row with `allowedPermissionModes` (default `default, acceptEdits, plan, auto`), `allowFullAccess=false`, `allowedModels` per runtime (patterns), `maxEffort` per runtime, `allowFastMode=false` (metered), `allowUltracode=false`.
- API decision = request ∩ policy ∩ device catalog. A denied request returns 403 + audit `work_session.settings_changed` result `denied`. When the policy tightens, live sessions are downgraded by the server (enqueue `session.configure`), the same live-reauthorization idea as ADR-0009.
- Defence in depth on the device: the adapter allowlist stays hard-coded (never bypass). For Claude, also send `disableAutoMode:"disable"` and `maxEffortLevel` as flag settings when the policy forbids or caps them. **U:** whether flag-tier `availableModels` restricts `setModel` (docs describe it for managed/policy settings).
- New permission `work_session.configure` or reuse `work_session.prompt`: decide in planning (SC3 says "visible to every controller", so every prompting controller probably may change it).
