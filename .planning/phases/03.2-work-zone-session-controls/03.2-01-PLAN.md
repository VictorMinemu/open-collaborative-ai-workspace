## Phase Goal

**As a** controller of a Work Zone session, **I want to** change the model, the thinking level and the permission mode — up to a real Full access on devices whose owner allows it — and reach every option Claude Code and Codex expose, from a composer and a session screen that match the reference layout, **so that** I can steer long coding work without restarting sessions while my organization stays in control of what each runtime may do.

(ROADMAP Phase 03.2 goal restated as a user story, verbatim intent: "Inside one Work Zone chat, a controller changes the model, the thinking level and the permission mode, and reaches every option Claude Code and Codex expose, from a composer that matches the reference layout (provider-grouped model picker, reasoning menu, permission menu). Every control is driven by what the runtime reports: an option is never shown as available unless the adapter has confirmed it". D-17 extends the reference to the whole session screen.)

**This plan's slice (tracer):** one model change in a live session flows composer → API (catalog check, audit) → Device Link `session.configure` → daemon → fake runtime applies it between turns → `session.settings` back → a second controller sees it. It also lands every contract and the only migration of the phase.

## Planner decisions (binding for Plans 03.2-01 … 03.2-11; referenced as P-01 … P-13)

The owner decisions are D-01 … D-17 in `03.2-CONTEXT.md` and ADR-0012. These planner decisions fill Claude's discretion and do not override any D-xx.

- **P-01 Contracts once.** Every Zod contract of the phase is defined in this plan (interfaces block below). Later plans import these names and never rename them; a plan that needs a contract change stops and reports it.
- **P-02 One migration** `work_zone_controls`, generated here. Later plans add code only; a plan that needs a schema change stops and reports it.
- **P-03 Mode ladder.** `plan`(0) < `default`(1) < `acceptEdits`(2) < `auto`(3) < `fullAccess`(4). Every cap (policy, device grant, per-turn) is a rank on this ladder. UI labels: default = "Supervised", acceptEdits = "Auto-accept edits", auto = "Auto", fullAccess = "Full access", plan = "Plan".
- **P-04 Settings storage.** `work_sessions.model` and `work_sessions.permission_mode` stay the requested (authorized) session values; `work_sessions.settings` jsonb holds the other requested keys (`effort`, `contextWindow`, `fastMode`); `effective_settings` jsonb is what the device last reported; `settings_pending` is true from a change until the device reports; `work_prompts.permission_mode` records the authorized mode of each dispatched turn.
- **P-05 Catalog transport.** The daemon's `hello` carries `fullAccessOptIn`; a separate `capabilities` frame (catalogs + opt-in) follows after connect and whenever either changes. The API stores it on `devices.runtime_catalog` / `devices.full_access_opt_in` (never writable through user routes). Collecting a catalog never sends a model turn.
- **P-06 Grain.** A member's cap on a device = owner → `fullAccess`; otherwise the highest of `shareMaxMode` (when `shared`, i.e. everyone) and every matching grant (user grant, or unit grant whose unit is on one of the member's unit paths). The resolver gets relation `full_access_grantee` and permissions `device.full_access` (relation-only), `work_session.configure` (developer and up) and `work_zone.manage` (admin, non-delegable).
- **P-07 Per-turn mode.** At dispatch the API computes turn mode = min(session mode, cap of the prompt's author = org policy ∩ device opt-in ∩ the author's device cap ∩ grain) and sends it as `PromptPayload.permissionMode`; the adapter lowers to it before the turn and refuses the turn if it cannot; `work_prompt.dispatched` is audited for every turn with the effective mode. A controller with no relation to the device (not owner, not listed, no everyone-share) keeps the pre-03.2 multiplayer right to run turns in sessions others started up to Auto-accept edits (`CONTROLLER_FLOOR = "acceptEdits"`), never Auto or Full access; Full access always needs the author's own `device.full_access` grain. The same author cap applies when a controller changes a session's settings.
- **P-08 Denials.** Settings or mode denials throw `AuthzDeniedError` with permission `work_session.configure` and reason `org_policy` (layer org), `device_opt_in` / `device_grant` (layer device), `denied_for_you` (layer user), `runtime` / `not_in_catalog` (layer resource). The global handler audits `authz.denied` in its own transaction (the request transaction rolls back).
- **P-09 Inventory is code.** `packages/contracts/src/runtime-controls/` holds every option with status exposed / deferred / impossible, a reason and evidence; the web renders a control only when `isExposed(area, uiKey)`; Plan 11 writes `docs/workzone/runtime-controls-inventory.md` with a parity test.
- **P-10 Slash commands.** `slashDisposition()` in contracts decides: `/model`, `/effort`, `/fast`, `/permissions` go through the settings path (policy-checked, audited); a per-runtime passthrough allowlist runs as a prompt; everything else is refused with a visible notice. The composer sends `/` text to `POST /work-sessions/:id/commands` (Plan 07); `POST /prompts` refuses non-passthrough commands; adapters refuse them as a backstop (Plans 02/03).
- **P-11 Full access in the adapters.** Claude: a session process carries `allowDangerouslySkipPermissions` only while its authorized mode is `fullAccess` (entering or leaving relaunches the query with `resume` between turns). Codex: per-turn `approvalPolicy: "never"` + `sandboxPolicy: dangerFullAccess` only for an authorized fullAccess turn.
- **P-12 Device opt-in lives on the device.** `runtime.json` `fullAccess.optIn` (default false), env `OCW_ALLOW_FULL_ACCESS=1` for headless servers, `ocw-runtime full-access on|off|status`, and the desktop Runtime menu with a native confirmation. Never settable from the web origin or the server.
- **P-13 Test and infra rules.** E2E only via `bash scripts/e2e-isolated.sh` (API :4290, web :3290); never the demo (ports 4000/3000, `ocw-demo-*`, the `ocw` database, `~/.ocw-demo`), never `pnpm demo:*`, never `docker compose down/rm/stop/restart`, never `docker exec` into `t3code-81d72154-postgres-1`, never start OpenClaw containers. Real fixtures: at most one subscription turn per runtime per fixture, in a throwaway temp git repo, never in bypass/full access. Unset `ELECTRON_RUN_AS_NODE` before anything that launches Electron. Every UI task captures 1440 and 390 screenshots, light and dark, into `.planning/phases/03.2-work-zone-session-controls/screenshots/` and reviews each with the Read tool before closing.
