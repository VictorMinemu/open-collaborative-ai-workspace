## Objective

Per D-08, D-09, PD-08, PD-11, PD-23, PD-29 (hub `07.13-01-PLAN.md`). This plan builds on 04's offline proof: the
`-c mcp_servers.ocw_browser.*` channel, the `mcpToolCall` item shapes, the image result and the approval/elicitation
behaviour recorded from the real Codex 0.172 binary against the fake model (`codex-0.172.0.browser-mcp.rpc.jsonl`,
`07.13-SPIKES.md` A-1 … A-3). Codex sessions get the same browser tools through a stdio MCP shim that the app-server
starts and that relays every call to the daemon over the local control socket, so the daemon's manager owns the
browser in both runtimes. If 04 recorded `-c` failing, use the thread `config` channel instead with the same keys (the
only allowed deviation). Like 04, nothing here uses a real login: the live check runs the real binary against the fake.

Purpose: WZB-01 for Codex. Output: shim, CLI entry, app-server arguments, server-request handling, mapper branch,
tests and fixture replay.
