# Phase 07.4 Plan 03: Public-only, IP-pinned egress guard Summary

One guard, `lib/egress.ts`, through which every outbound call of 07.4 goes: undici `fetch` + an `Agent` whose
`connect.lookup` resolves the host once, refuses the request if any address is loopback, unspecified, link-local,
metadata, RFC 1918, CGNAT, ULA, multicast, reserved or an IPv4-embedding IPv6 form (unless the exact host:port is
allowed for that call), refuses platform hosts always, and connects only to the address it validated.

## What was built

- **`createEgress({ platformHosts, testHosts?, lookup? })`** → `{ fetch(input, init?, policy?), bound(policy) }`.
  - URL checks before any resolution: `bad_url`, `scheme` (http/https only), `userinfo`, `platform_host` by name and
    host:port, `private_address` for `localhost`/`*.localhost`/metadata names, `https_required` unless the host is
    a test host or in `privateAllow` (or `requireHttps: false`).
  - Literal-IP URLs are classified up front (the connector never looks them up).
  - Connect time: a fresh `Agent` per request with `connect: { lookup: pinnedLookup(...) }`; the lookup resolves
    once, checks every address (platform address/address:port, then class), and hands back only the first validated
    address. `redirect: "manual"` is forced over the caller's value.
  - Body: capped stream (`maxBytes`, default 1 MiB, fails with `too_large` after handing over exactly the cap);
    overall `timeoutMs` (default 15 s) via `AbortSignal.timeout` combined with the caller's signal.
  - Errors: `EgressRefusedError(code, host)`; codes `bad_url | scheme | userinfo | https_required | private_address |
    platform_host | dns_failed | timeout | too_large | network_error`. No path, query or header ever appears.
- **`bound(policy)`**: fetch-compatible (accepts a string, URL or `Request`) for the MCP SDK `fetchFn` / transports.
- **`readCapped(res, maxBytes)`**: text up to `maxBytes`, `truncated` when more existed.
- **`platformHostsFromEnv(env)`**: postgres, redis, garage, openbao, openclaw, api, web, caddy, otel-collector,
  host:port of DATABASE_URL, AUTH_DATABASE_URL, REDIS_URL, OCW_S3_ENDPOINT, OCW_OPENBAO_ADDR, OCW_PUBLIC_API_URL,
  and `127.0.0.1` / `[::1]` / `localhost` on the API's PORT.
- **`egressFor(env)`**: memoised per env object.
- **Env**: `OCW_EGRESS_TEST_HOSTS` (`name=loopback,…` → Map; refused when NODE_ENV is production) and
  `OCW_OPENBAO_ADDR` (optional URL, was only read inside `loadConfig`).
- **Semgrep `ocw.raw-egress`** (ERROR): `fetch(...)`, `globalThis/global/window.fetch(...)`, `new WebSocket/EventSource`,
  imports/requires/dynamic imports of `undici`, `http`, `https`, `http2`, `tls`, `dgram`, default/namespace imports of
  `net` and `{ connect | createConnection | Socket }` from `net`, in `modules/connectors/**`, `modules/keychain/**`,
  `agent-channel/connectors.ts`, `agent-channel/http-requests.ts`, excluding `*.test.ts`. `isIP`/`BlockList` from
  `node:net` and type-only imports stay allowed.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Body cap dropped the chunk that crossed the limit**
- **Found during:** Task 3 (readCapped at 256 KB returned 261979 bytes, not 262144)
- **Fix:** hand over the bytes up to the cap, then fail with `too_large` on the next pull (erroring right after
  `enqueue` would reset the queue and lose them when no read is pending).
- **Files:** apps/api/src/lib/egress.ts · **Commit:** 600e1821

**2. [Rule 3 - Blocking] `OCW_OPENBAO_ADDR` added to `EnvSchema`**
- `platformHostsFromEnv(env)` must list it, but it was only read from `process.env` inside `loadConfig`. Added as an
  optional URL (empty = unset); `loadConfig` behaviour unchanged. Commit a74b697d.

**3. [Rule 2 - Critical] Env change moved into the tracer commit**
- `egressFor(env)` needs `OCW_EGRESS_TEST_HOSTS` to typecheck, so the env schema and its tests landed with Task 2
  instead of Task 3.

**4. [Rule 2 - Critical] Extra hardening beyond the interface block**
- `network_error` code added so connection failures are also sanitised (code + host, no cause chain).
- `classifyAddress` and `PLATFORM_SERVICE_NAMES` exported for tests and later plans.
- Platform names are resolved (cached 30 s, 2 s bound) so an allowed host resolving to a platform container is refused.
- `OCW_EGRESS_TEST_HOSTS` accepts loopback addresses only; a test host is exempt only for its mapped address.
- Always-refused set widened to all special-purpose IPv4/IPv6 ranges (NAT64, 6to4, TEST-NETs, reserved…).
- Semgrep rule also covers `http2`, `tls`, `dgram`, `WebSocket`, `EventSource` and dynamic imports.

## Threat Flags

None beyond the plan's threat model: the module adds no endpoint; its outbound surface is the one T-07.4-03-01..07
cover. Note for later plans: the MCP SDK's auth helpers and transports default to the global `fetch` when no
`fetchFn` is passed. The Semgrep rule cannot see a missing argument, so every SDK call site in 07.4 must pass
`egress.bound(policy)` explicitly.

## Broken-windows candidates (not recorded; WINDOWS.md is the owner's)

- `ocw.raw-egress` message cites ADR-0025, which 07.4-01 writes in parallel; it resolves only after merge.
- Default MCP SDK fetch (above): an SDK call without `fetchFn` would bypass the guard and no rule catches it.
- Per-request Agent means no keep-alive reuse across calls (a new TCP/TLS connection per request). This is fine for
  OAuth and keychain calls. Revisit if MCP streamable-HTTP latency matters.
- `privateAllow` admission over the network is proven only as "gets to connect" (timeout or network_error against an
  unroutable 10.x); the tests have no reachable private interface for a full round trip.
