## Decisions Made

- Control and bidi characters are checked by code point, never a regex character class (see deviation 1).
- On a limit tie, the outer level is named (server, then organization), because a person cannot raise it from the bot's profile.
- In the plugin mirror, the new optional fields read an unknown value as absent (`.catch(undefined)`), as the mirror already does for `reason` / `field`. The contracts copy stays strict, so `source: "user"` is refused there.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Biome's fixer turned the `\u` escapes in the path regex into literal bidi characters**
- **Found during:** Task 1, after `biome check --write`
- **Issue:** `UNSAFE_PATH_CHARS` (contracts) and `UNSAFE_FILE_PATH_CHARS` (plugin) ended up holding literal U+200E/U+200F/U+202A–U+202E/U+2066–U+2069. That breaks PD-03 ("no bidi characters in any source file"), and Semgrep's `contains-bidirectional-characters` fails CI on it. The coordinator flagged the same two lines while I was working.
- **Fix:** I replaced both regexes with `hasUnsafePathChar` / `hasUnsafeFilePathChar`, which compare code points (`<= 0x1f`, `0x7f`, `0x200e`, `0x200f`, `0x202a–0x202e`, `0x2066–0x2069`). Biome cannot rewrite these, and the `biome-ignore` is no longer needed. I did not copy the coordinator's example regex: it arrived with the escapes rendered as literal characters.
- **Files modified:** packages/contracts/src/work-session-files.ts, apps/openclaw-channel/src/agent-channel-protocol.ts
- **Verification:** a Python code point scan of every touched file finds 0 bidi characters (one existing `"a\u202eb.md"` literal at plugin-contract.test.ts:2793 predates this plan and is untouched). `pnpm guard` prints `guard semgrep: ok`. The bidi path tests (built with `String.fromCodePoint`) pass in both copies.
- **Committed in:** d0e1e0d3 (the fix went in before the first feat commit; no commit ever contained the literal characters)

**2. [Rule 3 - Blocking] `device_commands.kind` type did not accept the new command kinds**
- **Found during:** Task 2 (`pnpm typecheck --force`)
- **Issue:** `apps/api/src/modules/device/hub.ts(239,9): error TS2769`. `EnqueueCommand.kind: CommandKind` is inserted into a Drizzle `text(..., { enum })` column that lists the kinds.
- **Fix:** I added `session.file.write` and `session.file.read` to that enum list. It is type-level only: the column has no check constraint (07.11's `runtime.update` was added the same way), so no migration is needed. Plan 03, which owns this file in wave 2, will regenerate the snapshot.
