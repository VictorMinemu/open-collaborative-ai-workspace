# Phase 07.10 — UI Design Contract

> Visual and interaction contract for the reorganised **Work Zone sidebar**: the desktop column and the mobile drawer
> (the same component, portalled by `SectionSidebar`). It groups team projects by department, the way the chat sidebar
> groups channels. The sidebar shows: "Needs you" on top, one collapsible section per department, project rows that
> open the project page, at most 3 active sessions per project, "Personal" for unlinked repositories, a collapsed
> "Settled" history, and "Browse projects · Devices" at the foot. Generated by gsd-ui-researcher, verified by
> gsd-ui-checker. Every value comes from existing tokens in `apps/web/app/globals.css`, existing primitives in
> `apps/web/components/ui/*` and existing sidebar patterns in `components/chat/sidebar-sections.tsx` and
> `components/shell/section-sidebar.tsx`. This phase adds **no new primitive, no new CSS variable, no new font and no
> new web dependency**. Where this file and a plan differ, this file wins and the difference goes to
> **§ Plan reconciliation**.

**The owner's brief:** "como por canales según el equipo… piénsalo bien para que sea usable para mucha gente". The
layout below was approved ("perfecto, ponte a ello de forma autónoma"). The 07.9 N-rules still apply (N1 one place per
thing, N2 silence on the default, N3 the answer not the rule, N4 plain words, N5 no colour for visibility). This
phase adds three sidebar rules, and every element below names the rule that justifies it:

| # | Rule | Consequence |
|---|------|-------------|
| S1 | The chat sidebar is the model | Same section header, same chevron, same collapse behaviour, same team pill, same "+" placement. Nothing a chat user has to learn again |
| S2 | Only what you belong to | The sidebar never grows with the organisation. It grows with the viewer's own memberships. Everything else is one click away (Browse projects, search) |
| S3 | Activity, not inventory | Under a project only **active** sessions show, at most 3. A count appears only when something is live. Idle projects are one quiet line |

Sources: `07.10-CONTEXT.md` (C-01…C-03, D-01…D-10, Claude's discretion, deferred), ROADMAP Phase 07.10, `07.9-UI-SPEC.md`

## Information Architecture

### Anatomy (top to bottom)

| # | Block | Shows | Hidden when |
|---|-------|-------|-------------|
| 0 | Header | "Work Zone" + New session "+" | never |
| 1 | Search field | Existing borderless field, unchanged (`session-search`) | never |
| 2 | **Needs you** | Sessions waiting on the viewer, from any project or personal repository (D-05) | empty |
| 3 | **Department sections** | One per top-level unit that holds a team project the viewer belongs to (D-01, D-02) | no member projects (the onboarding line shows instead) |
| 4 | Onboarding line | "Share sessions with your team → Create project" (D-08) | the viewer belongs to at least one team project |
| 5 | **Personal** | The viewer's repositories not linked to a team project, with their active sessions (D-06) | no personal repository and no session under it |
| 6 | **Settled** | Settled sessions in the viewer's scope, 10 then "Show N more" (D-04 decision below) | no settled session in scope |
| 7 | Foot links | Browse projects · Devices (pinned to the bottom, `mt-auto`, existing position) | never |

While the search field has text, blocks 2–6 are replaced by the grouped results (§ Search). Blocks 0, 1 and 7 stay.

### Decision on the global "Settled" list (D-04, Claude's discretion)

**It survives, as a collapsed section at the end.** Collapsed by default. Persisted with the other sections.

The reasons:
1. Personal repositories have no project page, so without it their history would have no home.
2. C-02 forbids removing the Settled list as a side effect.
3. "Collapsed by default" keeps it at one quiet line (S3) while history stays one click away.

Its scope narrows to the **viewer's sidebar scope** (§ Scope rule), so an admin no longer sees the whole organisation's
history here. Their history is on each project page and in search. Rows, paging (10, then "Show N more") and test ids
are unchanged.

### Scope rule (who appears where)

The sidebar reads only `GET /work-sessions` and `GET /work-projects`. Both are already filtered by the resolver
(ADR-0030). It never infers access (C-01).

| Session or project | Where it appears |
|--------------------|------------------|
| Team project with `membership` ∈ {member, team, lead} | Its department section (row + up to 3 active sessions) |
| Team project with `membership` = manager (admin, or lead of a parent unit) | **Not in the sidebar** (D-02). Browse projects and search only |
| Session whose `teamProject` is a sidebar project | Under that project |
| Session with `teamProject: null` (personal repository) | Personal, under its repository |
| Session whose project the viewer can't open (`teamProjectHidden: true`, D-14 of 07.9: the device owner, D-11, or a creator who left, D-12) | Personal, under its repository name (`projectName`). The project is **never named**: no pill, no tooltip, no search hit on the project name |
| Session in a project the viewer opens only as an admin or manager, not created by them and not on their device | Not in sections, Needs you or Settled. It is reached through search, the project page or Browse projects (S2) |

"Viewer's sidebar scope" = the first four rows. Needs you and Settled draw only from this scope, so an admin's
sidebar never fills with every approval in the organisation.

## Surface contracts

### 1. Header and search

- `SectionSidebar title="Work Zone"` (was "Sessions"). The actions slot holds the existing "+" (`sidebar-new-session`,
  `aria-label="New session"`, tooltip "New session"), which gains `max-md:size-11`.
- The search field is unchanged in markup and position. The owner's sketch puts 🔍 in the header; the always-visible
  borderless field directly under the header satisfies it with zero clicks and keeps every existing spec. It is not
  turned into an icon toggle.

### 2. Section header (`SidebarSectionHeader`, shared by every section)

Exact copy of the chat header (S1). It has a toggle button (`section-toggle`, `aria-expanded`, `aria-controls` → the
section's list) with a chevron that rotates 90° when expanded, and the title. When collapsed **and** something is
hidden, a count pill follows the title (`rounded-full bg-muted px-1.5 text-[10.5px] tabular-nums`, chat
`section-count`), plus the optional "+".

| Section | Key | Default | Count when collapsed | "+" |
|---------|-----|---------|----------------------|-----|
| Needs you | `needs` | expanded | rows hidden | none |
| Department | top unit id | expanded | projects hidden | "New project in {unit}", only when the viewer may create a project under that unit or any unit inside it (D-07) |
| Personal | `personal` | expanded | repositories hidden | none |
| Settled | `settled` | **collapsed** | none (silence: history is not news) | none |

Collapse state: one map `{ [key]: boolean }` in localStorage key `ocw.workzone.sidebar.v1`, per browser (the chat
precedent; D-01 "per user" is met per browser, as chat does). A key that is absent takes the default above. Corrupt
JSON means defaults. Private mode means in-memory only.

### 3. Needs you (`NeedsYouSection`, D-05)

The "mentions" of the Work Zone. It shows a session when **either** reason holds and the session is in the viewer's
sidebar scope:

| Reason | Rule (computed in `needsViewer`) | Right-slot text | Tone |
|--------|----------------------------------|-----------------|------|
| `approval` | `attention.approval` is true. The server sets it when the session has a pending approval **and the viewer may decide it** (§ R2) | `Hand` 12 + "Needs approval" | existing warning: `font-medium text-amber-700 dark:text-amber-400` |
| `turn` | The session is idle, its queue is empty, its last turn ran **the viewer's** prompt (`attention.lastTurnEndedAt` not null), that turn ended within 24 h, it ended after the viewer last opened the session (`seen` map), and the session is not the one open now | "Your turn" | `text-foreground` 12/400 (no colour: it is an invitation, not an alarm) |

**Interpretation of D-05's "queued prompt waiting".** A prompt the viewer queued runs by itself. Nothing in it asks
the viewer to act, so it is **not** a third reason. Two cases already cover it:
- The row's status already says "{n} queued".
- When the queue is blocked by an approval, the `approval` reason covers it.

Adding a third reason later needs no layout change: one more right-slot label. This is flagged as U-3 for the
coordinator.

Row (`needs-you-row`, also `data-testid="session-row"` for continuity):
- Markup: `sectionItemClass(active)`, then `ProjectBadge` 16 (the session's project, or its repository when personal
  or hidden), the title (13.5/400, truncate), the 07.9 visibility marker, and the right-slot reason.
- The project or repository name is `sr-only` (`row-project`) and in the link's `title` ("{title} · {project}").
- Order: `approval` rows first, then `turn`. Within a reason, the most recent `updatedAt` comes first.
- Cap: 5 rows, then a more row "Show {n} more" that expands inline ("Show fewer" to fold back).
- A session leaves Needs you live: when the approval is decided (by anyone), when the viewer opens the session (for
  `turn`), when a new turn starts, or after 24 h. There is no toast and no animation beyond the row disappearing.

`seen` map: localStorage `ocw.workzone.seen.v1`, `{ [sessionId]: isoTime }`. The session view writes it on open and at
each turn end while the session is open. Writes prune entries older than 7 days and keep at most 300. Nothing in it
leaves the browser.

### 4. Department section (`UnitSection`, D-01, D-02)

- **Grouping** (`buildWorkZoneSidebar`, mirroring `groupChannelsByUnit`): key = the project's top-level unit id, title
  = its name. A project whose parent is not the top unit gets the **team pill** with its parent's name (chat sub-label
  rule). A project directly under the department gets no pill.
- **Section order:** first the sections whose top unit the viewer belongs to (`top.viewerIsMember`), then the rest.
  Each group is alphabetical (`localeCompare`, `sensitivity: "base"`, numeric).
- **Project order inside a section:** alphabetical, so positions are stable (muscle memory, S1). Activity is carried by
  the live count and Needs you, never by reordering.
- **Scale cap:** with more than 15 projects, the section shows these, in alphabetical order:
  1. every project with an active session,
  2. the project that is open now,
  3. alphabetical fill up to 15.

  Then comes a more row "{n} more projects" that expands inline ("Show fewer").
- **Collapsed:** the section shows only the projects that hold a Needs-you session or the open session/project. Under
  each, only those sessions show. The header count = projects not shown.

### 7. Personal (`PersonalSection`, D-06)

- **Repositories listed:** the index's `personalRepos`, plus the repository of any session in scope with
  `teamProject: null` or `teamProjectHidden: true` (deduplicated by `projectId`). The order is: repositories with an
  active session (most recent first), then the rest alphabetically. **Cap 5**, then "{n} more repositories", which
  expands inline.
- **Repository row** (`repo-row`): a non-link `<div>` styled with `sectionItemClass(false)` minus hover. It holds
  `FolderGit2` 16 muted, the name (13.5/400, truncate), the live count (same rule as projects), and "+"
  (`repo-new-session`, `aria-label="New session in {repo}"`). The "+" is hover-revealed on desktop and visible on
  touch. It opens the new-session dialog on that repository. There is no page to open, so the row itself is not
  clickable. A `title` "Linked to a project you can't open" appears only on hidden-project repositories (07.9 D-14
  wording). That is the only hint, and it is never a visible label.
- **Sessions under a repository:** the sub-row rule (§ 6), at most 3. "+{n} more" here **expands inline** ("Show
  fewer"), because a personal repository has no page.
- The section is hidden when it would be empty.

## Interaction Contract

### Pointer
- Section toggle: a click toggles and persists. The chevron rotates (existing `transition-transform`, none under
  `motion-reduce`). There is no height animation.
- A project row click opens the project page, as a channel row opens the channel (D-03).
- A session row click opens the session. A more row click opens the project page (team) or expands inline (Personal,
  Needs you, section caps).
- "+" buttons never navigate. They open a dialog.
  - Section "+": `NewProjectDialog` with `defaultParentId` = the section unit when the viewer may create there, else
    the first unit inside it they may create in.
  - Project "+" / repository "+": the new-session dialog, preselected.
  - Header "+": the new-session dialog, no preselection (unchanged).

### Keyboard
- Tab order follows the DOM: header "+", search, then each section toggle → section "+" → its rows (each project row
  link → its "+" → its sub-rows → more row), then the foot links. "+" buttons become visible on focus.
- **↑ / ↓** move focus between the sidebar's row-level targets: section toggles, project links, session links, more
  rows, and Needs-you and Personal sub-rows. The "+" buttons and repository rows are skipped, because they are not
  links (the repository's "+" stays reachable with Tab). **Home / End** jump to the first and last. This is a ~20-line
  handler on the `<nav>`, using DOM order and no roving tabindex, so Tab still behaves natively.
- On a section toggle: **←** collapses, **→** expands, **Enter / Space** toggles.
- On search: as in § 11.
- Focus survives live updates. If the focused row disappears (session settled, approval decided), focus moves to the
  next row in the same section, else to the section toggle. It never jumps to the top.

### Live behaviour (D-09)
- Sessions update through the existing per-user delivery (07.9-07) and the existing `useWorkSessions` cache. Projects
  update through `useWorkProjectsLive`. There is **no new subscription** and no org-wide broadcast.
- A session that becomes active appears under its project in the computed position, without animation. A session that
  settles leaves the project and joins Settled. The live count and Needs you recompute from the same cache.
- Joining or leaving a project (membership change) adds or removes its row live. A project the viewer can no longer
  open disappears, and so do its sessions (07.9 access-loss rule), with no toast.
- The clock: the existing `useNow` (1 s while a turn is under a minute old, else 30 s). It also expires 24-hour "Your
  turn" entries.

### Mobile drawer
- It is the same component, rendered through `SectionSidebar`'s portal (no fork).
- Rows, headers and "+" buttons are 44 px below 768.
- Touch shows the section "+" and the repository "+". It never shows the project "+" (§ Geometry).
- Opening a row closes the drawer (existing). The drawer keeps its scroll position between openings (existing portal
  slot).

## Accessibility Contract

**Structure decision: nested lists inside a landmark, not `role="tree"`.** A WAI-ARIA tree forbids interactive
children inside a `treeitem` (the "+" buttons) and requires the full arrow-key model to be correct. The chat sidebar
already uses sections plus links, and screen-reader users know that pattern. ↑/↓ (§ Keyboard) gives sighted keyboard
users the speed of a tree.

| Element | Markup |
|---------|--------|
| Sidebar | `<nav aria-label="Work Zone" data-testid="session-list">` (test id kept) |
| Section | `<section aria-labelledby="wz-section-{key}" data-testid="sidebar-section" data-section="{key}" data-collapsed>`; header toggle `<button id="wz-section-{key}" aria-expanded aria-controls="wz-list-{key}">` whose name is the title plus `sr-only` ", {n} hidden" when collapsed |
| Project list | `<ul id="wz-list-{key}" role="list">`; each project `<li>` holds the project link, its "+" and a nested `<ul aria-label="Active sessions in {project}">` |
| Live count | The visual part is `aria-hidden`; the link's name carries ", {n} running" |
| Session sub-row | Link name: "{title}, {status text}" + the 07.9 `sr-only` visibility suffix; `aria-current="page"` when open |
| Needs-you row | Link name: "{title}, {reason}, in {project or repo}" |
| Glyphs, icons | `aria-hidden`; the status always exists as text |
| "+" buttons | Named with their target: "New project in {unit}", "New session in {project}", "New session in {repo}" |
| More rows | Links: "{n} more active sessions in {project}". Buttons: `aria-expanded` |
| Repository row | `<li>` with plain text (not focusable), its "+" and its nested list |
| Search results | `<section aria-label="Search results">` with one `<h3>` per group; a `role="status" aria-live="polite"` node announces "{n} results" (debounced 300 ms) |
| Contrast | Text ≥ 4.5:1, icons and dots ≥ 3:1, both themes; axe clean on the sidebar at 1440 and the drawer at 390, light and dark |
| Touch | ≥ 44×44 below 768 for every row, header and "+" of this phase |
| Zoom | 200 % at 1440: rows truncate, no sideways scroll |
