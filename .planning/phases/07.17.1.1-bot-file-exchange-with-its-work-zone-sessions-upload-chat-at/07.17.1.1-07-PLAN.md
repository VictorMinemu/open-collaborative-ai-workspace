## Phase Goal

See `07.17.1.1-01-PLAN.md` (PD-05, PD-16, PD-17). **This plan's slice:** the byte transport: a device-authenticated,
single-use, bounded HTTP stream between the device and object storage, through the API, for any size up to the
ceiling.

<objective>

routes (`work-session/file-transfer-routes.ts`), multipart streaming storage (`ObjectStorage.putStream`) with
`streamServerAttachment` / `recordServerAttachment`, and a `FakeDevice` helper that performs a real transfer (D-02,
D-03, D-07, D-08).

Purpose: 08 enqueues commands whose bytes travel here; 04's daemon calls exactly these routes.
Output: three new source files, six edited, one new integration file.
</objective>

## Trust Boundaries

|----------|-------------|

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.17.1.1-07-01 | Spoofing | another device or organization using a transfer id | high | mitigate | JWT → device; the row must name that device; RLS by the device's organization; 404 cases |
| T-07.17.1.1-07-02 | Tampering | replayed or late transfers | high | mitigate | Single use (`pending` → `streaming` under `FOR UPDATE`), `expires_at`, 410 cases |

| T-07.17.1.1-07-04 | Information disclosure | file names or paths in logs | medium | mitigate | Logs carry ids and codes; a captured-log assertion (P1) |

| T-07.17.1.1-07-06 | Elevation of privilege | legacy raw device tokens on a new route | medium | mitigate | JWT only; a 401 case |
