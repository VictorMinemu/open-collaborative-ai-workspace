# Phase 03.2 Plan 12: Automatic Session Titles Summary

An untitled Work Zone session now gets a short title (3–6 words, at most 48 characters, in the prompt's language) from its first prompt. The title is generated on the session's own device by its own runtime's small model: Claude Code uses Haiku in a one-shot query with no tools that is not persisted; Codex uses GPT-6-Luna in an ephemeral read-only thread. It reaches the sidebar, the breadcrumb and the tab of every controller live. The session falls back to the prompt's first line when the policy or catalog rules out the model, or when the call fails or takes longer than 20 s. A typed title is never replaced.

## What was built

- **Contracts:**
  - `session-title.ts`: `TitleSource`, `SessionTitle`, `normalizeSessionTitle`, `titleWords` (based on `Intl.Segmenter`), `TITLE_MODEL`, `TITLE_TIMEOUT_MS`, `TitleFailureCode`.
  - The `session.title` command, `SessionTitlePayload`, the `title.result` frame and `WorkSession.titleSource`.
- **Migration** `20261006012933_session_title_source`: `ADD COLUMN title_source text DEFAULT 'user' NOT NULL` and a check constraint. Additive, proven on fresh testcontainers PostgreSQL; `_check` generation reports no changes.
- **API:**
  - `heuristicTitle`, a move of the old `firstLine` with unchanged behaviour.
  - `decideTitleRequest`, which requires the model to pass catalog ∩ policy ∩ inventory.
  - `requestTitle`, which runs on the first prompt that is not a slash command. A session created without a prompt first switches from its placeholder to the first line.
  - `hub.onTitleResult` accepts a result only for this device's own `session.title` command. `service.onTitleResult` checks the model and the `SessionTitle` shape, then makes one conditional update `where title_source = 'heuristic'`, updates `conversations.name`, records the audit and emits `work_session.updated`.
  - A failed ack only audits `title_failed` with its code.
- **Daemon:**
  - `runTitle` checks, in order: runtime match, model in the catalog, the 20 s timeout with abort, normalization, then refuses anything `contain()`/`redact()` would change.
  - `session.title` runs outside the per-session chain. It answers with `title.result` followed by an ack; a failure is only a failed ack whose error starts with the code.
- **Adapters:** `generateClaudeTitle` and `generateCodexTitle` (options per ADR-0014). `ClaudeCodeRuntime` and `CodexRuntime` gain `generateTitle`; Codex uses the catalog's lowest effort (`low`).
- **FakeRuntime:** deterministic, abortable titles, and `gpt-6-luna` added to the codex fake catalog.
- **Inventory:** a `session.title` row per runtime, exposed with its fixture as evidence; the doc was regenerated.
- **Docs and web:** ADR-0014 and DEMO.md item 4 "Session titles". Web: `title` attributes, plus the sidebar grid fix.

## Recording observations

1. **Claude: Haiku thought for 31 s.** It spent 3,664 thinking tokens; `duration_api_ms` was 31,492, which is past the daemon's 20 s timeout. On a real device this would have timed out every title. I set `thinking: { type: "disabled" }` in the title query (Rule 1). As the plan requires, I kept the recording and did not re-record. Latency without thinking is therefore not proven by a recording; it is part of the owner's manual check.
2. **Claude ran the requested model in default mode.** The init reports `claude-haiku-4-5-20251001` in `default` mode with `apiKeySource: none`, so no model substitution happened.
3. **Codex ran the requested model, with a low turn effort.** The thread reports `gpt-6-luna`, `untrusted`, `readOnly` and `ephemeral: true`. Its own `reasoningEffort` is `high`; the turn override sent `low`. The turn completed in 6.9 s.
4. **Codex emitted two identical final `agentMessage` items.** The owner's local Codex hooks also ran on the title thread. The recorder dropped their `hookPrompt` items and the personal notifications (32 of 107 messages kept). The adapter ignores `hookPrompt` and keeps the last message.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 1 - Bug] Claude title calls would always time out.**
- **Found during:** Task 2, while recording.
- **Issue:** The recording shows Haiku spending 31 s on extended thinking, against the 20 s daemon timeout.
- **Fix:** `thinking: { type: "disabled" }` in `titleQueryOptions`; tested; ADR and inventory updated.
- **Commit:** cf80e12.

**2. [Rule 2 - Isolation] `strictMcpConfig: true` on the Claude title query.**
- **Reason:** `settingSources: []` alone does not stop MCP servers from the owner's config.
- **Commit:** cf80e12.

**3. [Rule 1 - Bug] Settled sidebar rows overflowed the 256 px sidebar.**
- **Found during:** Task 3, in the first fit screenshot. A 36-character settled title widened the `grid` track, clipping the row at the panel edge and hiding the time column and the Settled chevron. The bug predates this plan; generated titles of this length make it common.
- **Fix:** `grid-cols-1` on the active and settled groups.
- **Commit:** b1aa866.

**4. [Plan conflict] "At 1440 the auto title's row-title is not truncated" cannot hold in the ref-4 sidebar.**
- The 36-character auto title measures 224 px; the row has 219 px. The reference layout (ref-4) uses the same width and itself truncates row titles.
- I kept the approved layout. The e2e now asserts: an ellipsis inside the row when the title is cut, the row stays within the sidebar, and the full text is in the `title` attribute. The breadcrumb is still asserted not truncated at 1440.
- The fallback header is required to truncate only at 390, because at 1440 the 78-character line fits.
- **Commit:** e260483.

**5. [Plan typo] The fallback prompt is 113 characters, not 112.** The assertion now checks `> 80`; behaviour unchanged (77 characters + "…").

**6. [Test only] `FakeDevice.connect` gained an optional `{ codexLoggedIn }`.** It is needed to create codex sessions in `title.int.test.ts`.
