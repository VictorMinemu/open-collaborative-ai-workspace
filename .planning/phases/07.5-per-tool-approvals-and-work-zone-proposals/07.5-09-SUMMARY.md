# Phase 07.5 Plan 09: Settings › Approval policies Summary

Admins and unit leads now decide in Settings › Approval policies which bot actions need a person. They set a rule per
tool or for a whole MCP server or connector: Never ask, Ask after outside content, or Always ask. They also choose who
approves: the person who asked, leads of the unit, admins, or specific people.

The page is built on the 07.5-03 API:

- Leads see only the units they lead. Rules from above are read-only and show their source and the reason.
- A concurrent edit shows the conflict notice with Reload.
- Remove asks first.
- Change history is the audit link.
- Settings › MCP servers shows the status chip next to tools that have an organization rule.

### Fixes made after reviewing the screenshots

1. **Row columns did not line up across rows.** Each row is its own grid, so the chip column now has a fixed width
   (`12.5rem`).
2. **Heading order.** Group headings changed from `h3` to `h2` (the page `h1` comes first). This clears the moderate
   `heading-order` notice.
3. **Initials contrast in the people list.** The list sat on the selected option's tint, so it now uses
   `bg-background`. Initials use `AVATAR_AA`, because the shared tones fail at 12 px. The text sizes now reach the
   fallback (`*:text-…`), so "MG" no longer spills out of the 16 px chip avatar.

## Broken-windows candidates (not written to WINDOWS.md)

1. **The shared avatar tones are under AA.** `components/ui/avatar.tsx` `TONES` uses `*-700` text on a `*-500/15`
   tint, which measures 4.25–4.48:1 at 12 px. Any spec that axe-checks an initials avatar fails or passes depending on
   the person's random id. Raising the text to `*-800` fixes it everywhere. This plan worked around it locally with
   `AVATAR_AA`.
2. **testcontainers leak Redis when Postgres fails to start.** The leaking files:
   - `apps/api/src/testing.ts:31`
   - `schema-guard.int.test.ts`, `telemetry.int.test.ts`, `upgrade.int.test.ts`, `lib/openbao.int.test.ts`

   They start Postgres and Redis together in `Promise.all`. When Postgres fails, the Redis container is never stopped.
   During this run about 210 `redis:8` containers accumulated under one shared Ryuk session while parallel worktrees
   ran `pnpm verify`. That fed the Postgres `No space left on device` cascade that failed three Task 1 verifies.
3. **The history shows the raw pattern of a deleted server.** A rule on a server that was later deleted shows
   `m…__*` in Change history, because the catalog no longer names it.
4. **The 07.5-03 caps reach the page.** The access probe returns at most 500 unit ids, and the catalog at most 200
   tools per group. The page shows no hint when a cap cuts the list.
