## Layout Contract

### Shell geometry

At 1440 the app sidebar (240) and the settings sidebar (256, `SectionSidebar w-64`) leave a **944 px content column**;
the Bots page has no section sidebar (1200 px column). Settings pages scroll inside `scrollbar-thin min-h-0 flex-1
overflow-y-auto` under a `PageHeader` (existing).

| Page | Container | Section gap |
|------|-----------|-------------|
| Settings › MCP servers (existing) | `mx-auto max-w-4xl px-4 py-6 sm:px-6 sm:py-8 grid gap-5` (unchanged) | 20 (existing) |
| Settings › Connections (new) | `mx-auto max-w-3xl px-4 py-6 sm:px-6 sm:py-8 grid gap-10` (= Settings › AI chat) | 40 between sections, 12 inside |
| Settings › Keychain (new) | same as Connections | same |
| Bots › Templates section | the existing bots `Grid` paddings (`px-4 py-4 sm:px-6 sm:py-6`), below the bots grid | 24 above the section heading |

Navigation: `ACCOUNT_SECTIONS` gains **Connections** (`Link2`, `/settings/connections`) and **Keychain** (`KeyRound`,
`/settings/keychain`) after "AI chat", in that order. `Plug` stays the MCP servers glyph so a member never confuses
"my accounts" with "the workspace's servers". The mobile settings drawer (existing) lists them the same way.

Section heading pattern (all new pages): `h2` 15/600 `tracking-tight` + one-line description 14/400
`text-muted-foreground` + optional right-aligned action (`Button` default or outline, `w-full sm:w-auto`), exactly as
"Connected servers" on the MCP page.

List pattern (all new lists): one `rounded-xl border bg-card shadow-xs divide-y` container, rows `px-4 py-3`
(`sm:px-5`), never one card per row (denser than the MCP cards, which carry tools and flags).

Status pill (connections, template "needs" rows): `inline-flex h-6 items-center gap-1.5 rounded-full px-2.5 text-xs
font-semibold` + 6 px dot or 14 px icon, colours from § Color › Connection state. Text is always written out.

#### Mode switch and delete confirmations (`mcp-clear-connections-confirm`)

│ (⏏)                                                  │
│ Switching Acme CRM to Organization secret deletes    │

- Mode switch: opened on Save when the mode changes away from a per-member mode (or between the two per-member modes)
  and the server has connected members. Primary design reads the count from the server DTO before saving (see
  § Reconciliation R4); fallback: Save → 409 `connections_exist {count}` → this dialog with that count → confirm

- Delete: the existing delete dialog keeps its title and gains the member sentence when `count > 0`; its button
  becomes `Delete and disconnect {n}`. With the 409 fallback, the same dialog updates in place (no second dialog).
- Both actions are audited server-side; the dialogs never promise revocation at the provider (07.4-06 Task 2 deletes
  tokens locally only).

## Interaction Contract

### Admin
- Choosing a mode updates the mode explanation, the mode fields and the hidden/visible Headers block instantly;
  values typed in a hidden block are discarded on save (never sent for another mode).
- Copy buttons: `useCopy`; the icon swaps to `Check` for 2 s and a polite live region says `Copied`.
- Save with a mode change on a server with members → confirmation (§ 1); Save without connections → normal toast
  `{name} saved`.
- Private hosts: Enter in the input adds the chip (same as the Add button); duplicates and invalid entries show the
  inline error and keep the text; Save hosts sends the full list; leaving with unsaved chips does not prompt.

### Member Connections
- `Connect` is single-click (no pre-dialog): the meta line already says what happens. The button disables and shows
  `Opening {Connector}…` until navigation.
- `?connect=<id>` auto-starts once per page load (desktop hand-off); `?connector=` only highlights; `?share=` opens
  the shared-use dialog; `?connected=` / `?error=` render the return banner. Unknown ids are ignored silently.
- After a successful return with a stored `return` route, the banner shows `Back to chat` (validated client-side with
  `isAgentCardRoute` before rendering; otherwise omitted).
- Disconnect and Revoke update the list optimistically only after the server responds (no optimistic removal of a
  credential state).

### Keychain
- Hosts are lower-cased and trimmed on add; validated with the contract's `VaultHostPattern`; personal keys refuse
  private literals client-side and server-side.
- Create sends `POST /keychain` then `PUT /keychain/:id/agents` when bots were ticked; if the second call fails the
  key exists: toast `Key saved, but its bots weren't updated. Try again in Edit.`
- Every write-only field is cleared from state after a successful save and when the dialog closes.

### Templates
- Start → preview → Create; the gallery card never creates without the dialog (the preview shows what is left out).
- Editor: unsaved changes + close → confirm `Discard changes?` (`Keep editing` / `Discard`).
- Update banner appears only for the owner (`GET /agents/:id/template` is owner-only) and only when `update` is
  non-null; `Not now` closes the dialog, the banner stays.

### Focus management
- Dialogs focus their first input (or Cancel for confirmations) and return focus to the trigger on close.
- Return banners receive focus on arrival (`tabIndex={-1}`) so screen readers announce the outcome.
- `?connector=` moves focus to the row's primary action; `?share=` focuses the dialog title.

### Reduced motion
- The highlight ring does not pulse; skeletons `motion-reduce:animate-none`; `scrollIntoView` uses `behavior:
  "auto"`. Existing dialog/sheet transitions are untouched.
