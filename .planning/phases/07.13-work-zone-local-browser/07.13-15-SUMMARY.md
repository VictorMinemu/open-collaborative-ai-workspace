# Phase 07.13 Plan 15: Live frames and takeover input on the device Summary

The device now streams its page to the web only while someone watches. While a person holds the lease it pauses the agent, applies only that person's input through CDP, and redacts what they typed from the agent's view. A takeover ends in one of two ways: the page goes back to the agent, or the page is closed when the takeover was abandoned.

## What was built

- **frames.ts**: `LiveFrames` per session.
  - `ping` starts the stream or re-arms the 25 s lapse. `stop` ends it.
  - `onJpeg` encodes the frame with `encodeWorkBrowserFrame` and sends it with `link.sendBinary`, or drops it. A frame over 256 KiB is dropped and counted. If the link cannot send, the frame is dropped and the watch ends.
  - The counters are `sent`, `oversize`, `linkDown`, `unwatched` and `malformed`. Frame bytes are never logged.
  - `encodeChildJpeg` / `decodeChildJpeg` handle the child payload.
- **agent/ops.ts**:
  - `frames { on }`: `startScreencast` with `SCREENCAST` (960×600, q55, `fps: WORK_BROWSER_LIMITS.fps`). The setting is remembered for the next page.
  - `takeover { on }`: re-registers the world script with the takeover flag, resets the focus hint and reports focus.
  - `input { events }`: 1 to 64 `LiveInputFrame`s, parsed with the contracts schema. They are dispatched as brw does through `Input.dispatchMouseEvent`, `Input.dispatchKeyEvent` and `Input.insertText`; wheel and touch become mouse events. The op sets `humanInput` and then reports focus.
  - A new agent event, `{ event: "focus", sensitive }`, carries a boolean only.
- **agent/main.ts**: `onJpeg` writes `FRAME_TYPES.jpeg` frames and drops them while more than 2 MiB is still waiting on stdout.
- **takeover.ts**: `Takeover` keeps the held lease per session.
  - `isPaused` is the manager's gate.
  - `onLease`: `held` tells the child `takeover on` when the holder is new. `released` ends the pause and re-arms idle. `abandoned` closes the page with `takeover_abandoned`. A frame for any other lease does nothing.
  - `onInput` forwards input only for the current held lease. It re-arms idle and never logs.
  - `onFocus` sends `browser.focus { sessionId, leaseId, sensitive }`, but only while a lease is held.
  - `onHandback`: a save with an `uploadId` calls `onSaveHandback` first; then the pause ends and the page stays.
  - `end` forgets the lease.
- **manager.ts**:
  - Routes `browser.frames`, `browser.lease`, `browser.input` and `browser.handback`.
  - The child's `onFrame` goes to `LiveFrames`. A new child starts frames when someone already watches.
  - The `paused` gate (3 places) and the idle re-arm now use `takeover.isPaused`. `s.leaseId` is removed.
  - Focus events are forwarded. A crash or any page close ends the lease, and `endSession` stops watching.
  - New test seam: `liveClock`.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 3 - Blocking] `agent/main.ts` and `test-site.ts` changed (both outside `files_modified`)**
- **main.ts:** the child must write the screencast JPEGs to stdout. `onJpeg` is now passed to `createBrowserAgent`; it has a 2 MiB drop-on-slow, like brw. The op table itself is unchanged (AGENT_OPS/runOp only).
- **test-site.ts:**
  - an `/animate` route (the plan names it);
  - a `/takeover` route with the login fields at fixed positions (`TAKEOVER_LAYOUT`), so mouse input can aim at a field;
  - `lastLogin()`, which records the posted login form.
- **Commits:** 5cb08eca, e584d395, 24bbb0ea

**2. How the tests check that typed values reached the page**
- The plan says "read through a test-only CDP evaluate". The agent has no evaluate path, and there is no debugging port to attach a second client. The test therefore submits the form with the holder's Enter key and checks what the fixture site received. The check still never reads through the agent, and no production code gained a read path.

**3. Lease state moved out of `SessionState`**
- `s.leaseId` now lives in `Takeover`. A page close and a crash also end the lease, matching the API. Before this, only a close through `closePage` cleared it.

## Known Stubs

- `Takeover.onSaveHandback(sessionId, leaseId, uploadId)` is empty. A save hand back only ends the pause and exports nothing. This is a planned hand-off: 07.13-19 adds the export and the PUT to the one-use upload. The routing and its order (save first, still paused, then resume) are tested.

## Threat surface

All five threats in the plan's register are mitigated and tested:

| Threat | Mitigation | Test |
| --- | --- | --- |
| T-01: typed text logged | input is never logged | logger and console spy tests |
| T-02: the agent reads what a person typed | `[redacted]` in snapshots, masks in screenshots | ops and takeover tests |
| T-03: input for a stale lease | stale lease, other session and released lease are ignored | takeover test |
