<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Codex app-server → shim | The shim process runs as the same OS user, started by Codex with our overrides |
| shim → daemon control socket | 0600 Unix socket / named pipe, token-bound to one session |
| organization / project → title model | Naming rules enter a one-shot model call with no tools |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.13.1.1-05-01 | Spoofing | a shim acting for another session | medium | mitigate | Token file path fixed per session, 64 hex, constant-time check in the relay; strict control schemas (Task 1) |
| T-07.13.1.1-05-02 | Information disclosure | the token in argv or env | medium | mitigate | Only the token FILE path is passed (`codexSessionToolArgs` test asserts no token value) |
| T-07.13.1.1-05-03 | Elevation of privilege | a listening port | high | mitigate | stdio + control socket only; the browser shim's no-listen check reused |
| T-07.13.1.1-05-04 | Information disclosure | arguments or titles in the timeline or logs | medium | mitigate | Mapper branch drops arguments; failures logged by error code only |
| T-07.13.1.1-05-05 | Tampering | naming rules steering the title model | low | mitigate | Delimited, framed as data, limits restated; the title call keeps no tools and a read-only sandbox; the result is still normalized and `SessionTitle`-checked |
| T-07.13.1.1-05-06 | Denial of service | app-server restarts on every rule change | low | accept | Only an offered-state change restarts; rules apply at the next start (documented staleness) |
</threat_model>
