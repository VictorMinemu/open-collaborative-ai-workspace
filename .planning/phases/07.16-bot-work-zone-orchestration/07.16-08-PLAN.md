<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| model → plugin tool | The model chooses arguments (untrusted) |
| plugin → API | Thin calls with the turn's ids; the API decides |
| API → model | Session output (untrusted work product) returned in the read answer |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.16-08-01 | Spoofing | a model naming a user, device or audience | high | mitigate | Closed schemas refuse extra keys locally; the API's strict bodies refuse them too |
| T-07.16-08-02 | Tampering | session output steering other tools | high | mitigate | Output rendered inside the untrusted block; the local session-output mark blocks other side-effecting tools (D-20); the API enforces the same in the claim (15) |
| T-07.16-08-03 | Elevation of privilege | a tainted start bypassing review | high | mitigate | `ROUTE_DECIDES_TAINT` sends it to the route, which allows it only with the admin flag or answers with a proposal (19); the proposal tools stay in `ALWAYS_SIDE_EFFECTING` |
| T-07.16-08-04 | Information disclosure | logs | medium | mitigate | Ids and codes only; a test greps log lines for the prompt and a file path |
| T-07.16-08-05 | Repudiation | double counting through `/tool-calls` | low | mitigate | Self-validated names; the route claims and audits once |
</threat_model>
