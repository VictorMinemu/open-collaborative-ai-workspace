# Phase 07.15 Plan 04: Bot read layer (text and images) Summary

**`readAttachmentForAgent` in `artifact/extract`: a stored file is classified once (sniffer for images and PDF, declared type or extension allow-list for text), text comes from one 256 KiB range read decoded BOM -> UTF-8 -> UTF-16 -> windows-1252 and cut in UTF-16 code units, images come as the `large.webp` rendition or an original up to 5 MiB, and every failure is a fixed code. The untrusted block now has a single definition that AI chats share.**

## Accomplishments

- Text read for bots: `rangeGet(original, 262 144)` only (the test double proves no `stream` call), `truncated` when the file is larger than what was read or the text is over `charsPerFile`; 0-byte files give `chars: 0`; a 262 144-byte file is read whole and not truncated.
- Decode chain: UTF-8 BOM, UTF-16LE/BE by BOM or by the NUL pattern, strict UTF-8 that holds back a character the range cut split, windows-1252 as the last step (`caf\xE9` -> `café`). A NUL in the first 8 KiB outside UTF-16 gives `unsupported_type`.
- `cutChars`: 64 000 code units are kept as they are, 64 001 are cut, and a cut that would land after a high surrogate keeps one unit fewer.
- Images: `large.webp` with `image/webp` and the rendition's dimensions computed from the row (4000x3000 -> 2048x1536); without a rendition, the original with its sniffed type up to 5 MiB; larger rows give `too_large` before any storage call, and an object that turns out larger than the cap also gives `too_large`.
- SVG, HTML and JS come back as text; nothing is rendered, evaluated or executed.
- `untrustedFileBlock` and `labelName` moved to `artifact/extract/text.ts` unchanged. AI chats re-export them (the test checks it is the same function), and all 86 AI chat unit tests and the 16 integration tests pass.

## Decisions Made

See `key-decisions` in the frontmatter. The one that is not obvious: the plan expected `fitImageWithin(4000, 3000, 2048)` to give the dimensions, but `fitImageWithin(bytes, maxEdge)` actually resizes the image with sharp. A local `renditionSize` therefore computes the box from the row's dimensions. It is documented next to `fitImageWithin`/`renderRenditions`, and nothing is decoded at read time.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug in plan interface] Rendition dimensions are not `fitImageWithin`**
- **Found during:** Task 3
- **Issue:** `fitImageWithin` is `(bytes, maxEdge) => Promise<Uint8Array>` (a sharp resize), not a dimension calculator. Calling it would decode the image at read time, which T-07.15-04-03 forbids.
- **Fix:** a pure `renditionSize(width, height)` from `RENDITIONS`' 2048 px, matching sharp's `fit: "inside"` and `withoutEnlargement`. Unknown dimensions give null.
- **Files modified:** apps/api/src/modules/artifact/extract/read.ts
- **Verification:** `read.test.ts` images (4000x3000 -> 2048x1536, 800x1200 kept, null kept)
- **Committed in:** 6b303984

**2. [Rule 3 - Blocking] Import cycle between artifact/index.ts and extract/read.ts**
- **Found during:** Task 3
- **Issue:** the image path needs `readAttachmentBytes` and `AttachmentTooLargeError`, which lived in `artifact/index.ts`. That file now re-exports `extract/read.ts`, so importing them back would create a cycle.
- **Fix:** moved both, verbatim, to `artifact/read-bytes.ts`; `index.ts` re-exports them, so every caller (`ai-chat`, `agent-channel/sandbox`, `work-session/images`) is unchanged.
- **Files modified:** apps/api/src/modules/artifact/read-bytes.ts, apps/api/src/modules/artifact/index.ts
- **Verification:** `pnpm --filter @ocw/api typecheck`, full `pnpm verify`
- **Committed in:** 6b303984

**3. [Rule 2 - Missing critical] Store failures are logged by name only**
- **Found during:** Task 1
- **Issue:** the must-have says a storage failure "logs only the error name", but the three-argument contract has no logger.
- **Fix:** an optional fourth argument `{ log?: Pick<FastifyBaseLogger, "warn"> }`, which logs `{ err: { name } }` (the codebase's pattern). The contract's three-argument form is unchanged. A test checks that the message (`secret-content`) is never logged.
- **Committed in:** 2187fd2f, test in 1651200e
