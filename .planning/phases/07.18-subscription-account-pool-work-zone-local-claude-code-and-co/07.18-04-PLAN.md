  <name>Task 2: Round-robin and smooth weighted round-robin</name>
  <read_first>apps/api/src/modules/account-pool/select.ts (after Task 1), the hub's PD-07 and D-04</read_first>
  <files>apps/api/src/modules/account-pool/select.ts, apps/api/src/modules/account-pool/select.test.ts</files>
  <behavior>
    - round_robin: a never-used candidate wins over used ones (two never-used → tie-break); otherwise the smallest `lastUsedAt`.
    - weighted: weights A 5, B 1, C 1 (B before C in the comparator, so the step-3 tie goes to B) starting from zero state, fed back its own `wrr` each call, gives A A B A C A A, and the state returns to all zeros after those seven picks.
    - weighted with one candidate always returns it; weights 2/1 over six picks give A B A A B A.
    - weighted ignores `lastUsedAt`; a weight outside 1…100 is clamped to the bounds of `POOL_LIMITS`.
  </behavior>
  <action>
Per D-04, PD-07. RED first. Round-robin: least recently used, never-used first, then the comparator. Weighted (the
nginx smooth algorithm): add each candidate's weight to its current value, pick the largest current (ties by the
comparator), subtract the total weight from the picked one; return the new state for every candidate as `wrr`. A
candidate missing from the state starts at 0 (a newly added account).
  </action>
