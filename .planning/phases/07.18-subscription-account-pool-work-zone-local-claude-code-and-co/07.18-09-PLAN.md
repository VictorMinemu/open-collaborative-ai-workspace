## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API → device | The token rides the sent start and prompt frames |
| member → API | Starts and previews from people who may not manage the pool |
| device → API | `hello.accountPool` is device-reported |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07.18-09-01 | Information disclosure | token persisted with a command | high | mitigate | Stored payload has no token; prepare/hydrate adds it to the sent copy only; E8 scan of commands, audit and stream events |
| T-07.18-09-02 | Information disclosure | token sent to the wrong device | high | mitigate | The token is added only for the session's own device's flush; slot rows match the device |
| T-07.18-09-03 | Elevation of privilege | cross-tenant selection | high | mitigate | Selection inside the tenant tx (RLS); test with a ready account in organization B |
| T-07.18-09-04 | Information disclosure | members reading the pool | medium | mitigate | Members get labels on their sessions and a preview without labels or ids; preview needs device use |
| T-07.18-09-05 | Spoofing | a device claiming pool support | low | accept | A device that lies only receives tokens for sessions started on it by members who may use it; its owner already runs those sessions |
| T-07.18-09-06 | Tampering | concurrent starts racing the strategy | medium | mitigate | Policy row locked `FOR UPDATE`; concurrency test |
</threat_model>
