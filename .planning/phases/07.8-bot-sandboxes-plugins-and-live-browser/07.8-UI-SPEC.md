> `apps/web/app/globals.css` and the existing primitives in `apps/web/components/ui/*`. This phase adds **no new

## Information Architecture and Navigation

| Entry | Route / place | Shows | Who (the API decides; the web renders what it returns) |
|-------|---------------|-------|----------------------------------------------------------|
| Live view | Global overlay mounted in the app shell (no route); survives in-app navigation; one at a time | One browser context (bot × conversation × member) | `viewerCan.watch` from the live-view socket's resolver decision; `viewerCan.control` for Take control |
| Live chip | Conversation header right cluster (channel, DM, thread panel header) | "Live browser" while a context of this conversation is open and watchable | Readers of the conversation the resolver allows to watch |
| "Watch" link | Browser steps in the chat activity | Opens the live view on that context | Same |
| Sign-in card | In the DM or thread where the bot asked | Platform-owned card; "Open and sign in" opens the live view and takes control | Everyone who reads the conversation sees the card; only the requester acts |
| Bot page › Sandbox | `/bots/<agentId>?tab=sandbox` | Status, limits, isolation, Stop / Restart, file browser | Module `sandbox` on for the viewer **and** the viewer may configure the bot (`viewerCan.configure`); otherwise the tab is absent |
| Bot page › Browser | `/bots/<agentId>?tab=browser` | Open contexts the viewer may watch, recent activity by host | Module `browser` on for the viewer; rows filtered by the resolver |
| Settings › Modules | `/settings/modules` (existing) | Two new rows: Sandbox, Browser (off by default) | `unit.modules.manage` (existing) |
| Settings › Sandbox & Browser | `/settings/sandbox` (new `SETTINGS_SECTIONS` entry after "Bot policy", icon `Container`, `permission: "bot.manage"`) | Isolation, limits, network, packages, kill switch | `bot.manage`; the Packages section also needs `plugin.manage` (read-only list otherwise) |
| Settings › Keychain › Browser sessions | `/settings/keychain` (existing page, new section) | The member's own sealed sign-ins | Owner only (no admin view, ever) |
| Approval card / review | 07.5 surfaces | Signed-in browser actions | 07.5 rules |

Tab bar on the bot page: `Memory · Capabilities · Sandbox · Browser`, in that order; absent tabs collapse (no disabled
tabs). URL `?tab=sandbox|browser` falls back to Memory when the tab is absent for the viewer. At ≥ 1024 the list keeps
`px-4` (existing); below 1024 the list drops the existing `grid grid-cols-2` and uses the underline variant's
scrollable row (4 tabs measure ≈ 347 px at 14 px, they fit 390 without scrolling; the row scrolls on narrower screens).

## Layout Contract

### Shell geometry

| Viewport | Live view | Bot page tabs | Settings |
|----------|-----------|---------------|----------|
| ≥ 1024 | Small window 320 wide, floating, draggable, snaps to 4 corners; large view is a centred dialog | Sandbox: status card + files card with tree column 320 and preview pane (flex) | Rail 240 · settings sidebar 256 · content 944; container `mx-auto max-w-3xl px-4 py-6 sm:px-6 sm:py-8 grid gap-10` (= Keychain, Connections) |
| 768–1023 | Same small window (touch: 44 px controls via `pointer-coarse:`) | Sandbox: status card, then tree screen; a file opens the preview pane in place of the tree with "← All files" | Same container |
| < 768 | Bottom dock (mini h-14 / peek ≈ 332) + full-screen sheet | Stacked; a file opens the full-screen file sheet | Single column `px-4 py-6`; existing mobile settings drawer |

Nothing scrolls sideways at any width. Commands, output, file previews and hosts scroll or truncate inside their own
containers.

Stacking: the small window and the phone dock are `fixed z-45` (above the phone top bar `z-40`, below dialogs, sheets
and toasts `z-50`), so every confirmation covers them. The large view and the phone full sheet are modal (`z-50`).

|-------|-------|---------------------|

## Interaction Contract

### Live view: open, move, close

- One live view at a time (`LiveViewProvider` store). Opening a context connects the dedicated binary socket with the
  realtime gateway's authentication; the server replies with `viewerCan` and the initial `state`.
- Drag (desktop): pointer down on the header (outside buttons) starts a drag with `setPointerCapture`; the window
  follows the pointer; on release it snaps to the nearest corner (`transition-[left,top] duration-200`, instant under
  reduced motion). Keyboard: the `GripHorizontal` handle is a button "Move live view"; with it focused, arrow keys move
  the window to the adjacent corner (polite announcement "Moved to bottom left"). The corner persists.
- Expand / Minimize swap small window ↔ large view without reconnecting (the server switches the screencast size).
- Close ends viewing only; while in control it hands back first.
- Phone dock: tap Expand or swipe up → full sheet; swipe down on the handle → mini; the system Back gesture in full
  closes the sheet to the dock (never hands back silently: while in control, Back asks "Hand back to {bot}?" with
  `Keep control` / `Hand back`).
- Live re-authorization: losing read access mid-stream (membership change, module off) switches to `no_permission`
  or `ended` within the realtime gateway's re-check; no frame arrives after that.

### Take control and hand back

- Take control is one press, no confirmation. The client shows "Taking control…" until the server grants a lease (the
  bot pauses after its current step, ≤ 2 s typical). Refusals show a toast with the fixed sentence and keep watching.
- While in control: the bot's browser tools answer `paused`; frames go only to the controller (F-5); other viewers
  receive `private`.
- Input (desktop): when the frame has focus, every key goes to the page (including Tab, Enter, Backspace, arrows,
  shortcuts the OS lets through) as `Input.dispatchKeyEvent`; `Shift+Esc` is never forwarded and moves focus to Hand
  back. Paste (`paste` event) sends the clipboard text (≤ 1,000 characters) as `Input.insertText`; IME composition
  sends on `compositionend`. Mouse move (≤ 30 Hz), buttons and wheel map to `Input.dispatchMouseEvent` with
  coordinates scaled from the frame's displayed size to the page viewport.
- Input (phone): taps map to `Input.dispatchTouchEvent` (tap = touchStart/End); pinch and pan are local zoom only when
  the phone viewport is not active. `Show keyboard` focuses a visually hidden input (`sr-only` but focusable,
  `text-[16px]` so iOS does not zoom, `autocomplete="off" autocorrect="off" autocapitalize="off" spellcheck=false`);
  `beforeinput` text → `insertText`, Backspace / Enter / arrows → key events. When the agent reports that the focused
  field is sensitive, the hidden input switches to `type="password"` so the OS keyboard does not learn it.
- Nothing typed is logged, stored, audited or echoed back by the client (no console logging of input frames; the
  frame socket handler has no logger). Audit gets `browser.takeover_started` / `_ended` with ids and host only.
- Hand back: one press; "Handing back…" until the server confirms; then `live`. On a sign-in card flow, the server
  seals the session and the card turns "Signed in".
- Idle lease: warning at 9 min without input, automatic hand back at 10 min (§ 1.3).

### Sign-in card

- `Open and sign in` and `Return to sign-in` open the live view on the card's context and take control (large view /
  full sheet). `Not now` records a skip at once.
- The card's host comes from the page, never from the bot's reason. If the page leaves that host during takeover,
  the live view's host chip shows the new host; the card keeps the original.
- Expiry: the card shows the server's countdown, refreshing every minute (every second under 60 s, but announced only
  at 5 min and 1 min).

### Sandbox tab

- Tree: 07.2 keyboard contract (↑ ↓ → ← Home End Enter Space typeahead `*`), plus Delete key = Delete…
  (confirmation). Enter on a file opens its preview and focuses its `<h2>`; on phones it opens the file sheet.
- Download: an API URL with `Content-Disposition: attachment` (D-04: never a direct sandbox URL); the button shows a
  Spinner until the response starts; failures toast "Couldn't download {name}. Try again.".
- Upload: dialog flow above; uploads run sequentially, one progress bar per file; leaving the page during upload asks
  "Leave while uploading?" (`Stay` / `Leave`).
- The tree refreshes when the bot writes (a `sandbox.files.changed` event for this bot) without moving focus; a
  changed open file shows "This file changed. Reload" (link) above the preview instead of swapping content.
- Status card refreshes from the bot's sandbox events (state, disk) and every 30 s while visible.

### Chat activity

- The group is collapsed by default once the reply arrives; while running it shows only the live label. Expanding is
  local state; it does not persist.
- A step with details toggles with Enter / Space / click (`aria-expanded`). `Watch` opens the live view.
- Activity updates arrive with the turn (`message.updated` or the turn's activity event); steps append without
  re-rendering the reply text.

### Settings

- Module switches: turning Sandbox or Browser on at organization scope confirms first; off keeps the existing
  confirmation. Locked unit rows use the existing inherited line.
- Limits and Network save explicitly (no autosave). Unsaved changes + leaving the page: no prompt (07.4 precedent).
- Kill switch: confirmation; Resume is immediate.
- Packages: Add → Review → Approve; switches save on toggle (existing InstalledPlugins behaviour, toast on failure
  with the previous state restored).
- Keychain Revoke: confirmation; the list updates after the server responds (no optimistic removal of a credential).

### Focus management

- Opening the large view focuses the header's primary button (Take control or Hand back); closing returns focus to the
  trigger (chip, card button, Watch, Open live view). The small window never steals focus when it opens; a polite
  announcement says "Live view of {bot}'s browser opened. Press F6 to reach it." and F6 moves focus between the page
  and the small window.
- Entering control focuses the frame (keyboard capture on). `Shift+Esc` → Hand back button.
- Phone full sheet traps focus (modal); the dock does not.
- Dialogs focus Cancel on destructive confirmations and the first field elsewhere.

### Reduced motion

- No corner snap animation, no live-dot pulse, no ping on running pills (existing), skeletons
  `motion-reduce:animate-none`, the dock and sheets keep their existing transitions only when motion is allowed.

## UX risks in D-01…D-11 (flagged for the owner and the planner)

| # | Decision | Risk | Contract choice / recommendation |
|---|----------|------|----------------------------------|
| U-1 | D-09 + F-6 ("an admin turns them on per organization **or unit**"; default-off as an org `everyone` deny) | Deny beats allow (principle 6), so a unit can never turn on a module the organization denies. "On for one team only" is not expressible; admins will flip a unit switch that is locked | The unit row stays locked with the inherited line and the hint "turn it on for the organization, then off for the teams that shouldn't have it". If per-unit opt-in matters, it needs a different default (no org row; seed deny rows per top-level unit) — an owner decision before 07.8-02 |
| U-2 | D-06 (the bot's **owner** watches) vs D-08 / 07.4 audience rule | After a member signs in, the page shows **their** private account (inbox, orders). A team bot's owner, or a personal bot's owner who is not the member, would watch it. F-5 protects only the typing phase | Recommended: a context with a member's saved session loaded is watchable only by that member (the resolver withholds frames from the owner; they get `no_permission`). The owner keeps watching contexts without a member session |
| U-3 | D-08 / F-10 (sealed per member × **site**, not per bot) | Any bot the member talks to privately reuses the session: signing in to a bank for Scout also lets a team bot in a DM use the member's bank account | Recommended: key the session by member × bot × site (`with {bot}` in Keychain). Fallback copy if declined: "Bots in your private chats can use it" replaces "with {bot}" |
| U-4 | D-07 (person types the password in a remote page) | Password managers and autofill can't fill a remote page; passkeys, security keys and device-bound 2FA cannot work in the server browser; OAuth pop-ups open new pages; some IdPs block automated Chromium | Paste is supported and explained in the takeover footer; the live view follows the active page (pop-ups included) and shows the host; card copy never promises success. The bot's fixed sentence for a blocked sign-in should point to a 07.4 connector when one exists. Hidden phone input uses `type="password"` on sensitive fields; the Wave 0 spike checks that OS suggestions for the OCW origin are not offered |
| U-5 | D-11 (session-scoped approvals deferred; per-action approvals under `when_tainted`) | A signed-in flow of 8 clicks raises 8 cards (approval fatigue), and 07.5's 24 h expiry outlives the 5-minute browser idle stop, so approvals go stale | Browser-action approvals expire in 15 min and the page is held while one is pending (R8, R9); the live view shows "Waiting for approval". Measure card counts in the journey e2e and revisit session-scoped approvals after the phase |
| U-6 | Research idle stop (brw 5 min) vs the sign-in card | A member who opens the card 6 minutes later finds the page gone and the card still saying "Sign-in needed" | The server holds the context 15 min while a sign-in card waits; the card shows the countdown and turns "Expired" (R9) |
| U-7 | D-06 / § 9 (phone bottom sheet) | A 1280×800 page in a 390 px sheet is unreadable for typing a password | During a phone takeover the page switches to a phone-sized viewport and restores on hand back (R10); fallback pinch zoom |
| U-8 | F-8 (team bot workspace) | Files are shared by every conversation of a team bot; a member may upload something private believing it stays in their DM | Team-bot notice on the Sandbox tab and in the Upload dialog |
| U-9 | D-09 (module on = capability on) | Turning Sandbox or Browser on gives every bot, including every personal bot, a shell and a browser at once; there is no per-bot switch | Recommended: two rows "Sandbox" and "Browser" in the existing `CapabilitiesPanel`, default off per bot, same look as Internet (R11). Without it, the turn-on dialogs say "Bots used by everyone…" explicitly |
| U-10 | D-11 A6 (Public egress lets bots self-install) | Admins may read "approved packages" as vetting, while a public-egress bot can `pip install` anything | Packages footnote states it; the shell defaults to Allowlist |
| U-11 | D-09 kill switch | Stops a person mid-sign-in; nothing is sealed | The dialog says "including anyone signing in"; the live view ends with "An admin stopped all bot browsers." |
| U-12 | D-01 fallback (hardened runc) | Dev machines and macOS self-hosters always see the weaker boundary; admins may enable modules without noticing | The isolation sentence is in the turn-on dialog, the settings page and the Sandbox tab; never hidden |
| U-13 | D-08 revoke | Members assume Revoke signs them out at the site | Revoke dialog and Keychain footnote say it doesn't |
