# Phase 07.14 Plan 08: The organization's account through the connector proxy Summary

**When an admin has connected an `org_oauth` server once, every member's bot can call its tools through `POST /agent-channel/v1/connectors/call` with the organization's token. Which token the proxy uses is decided by the server's stored mode, never by a body field. Audits record `credential: "organization"`, and the token never reaches the cell. These tools are offered where organization-headers tools are, not where the member audience rule would allow. When the organization's credential cannot be used, the 409 names the server and says an admin can fix it, and no connect card is posted.**

## Intended change (plan mode, CLAUDE.md: permissions / audit)

- **Turn policy (`turn-policy.ts`).** The old member-account check is now two:
  - `proxiedSource` (`usesConnectorProxy`) decides logical names, `ocw_connector_list` / `ocw_connector_call` and the skip in the cell-wide view.
  - `memberAccountSource` (`isPerMemberMode`) decides only the per-asker audience rule. Org-mode tools go on to the organization-resource checks (`shared_with_group`, `not_every_participant`), exactly like `org_secret` tools.
  - No check was relaxed for member modes.
- **Proxy (`agent-channel/connectors.ts`).**
  - Servers are looked up with `inArray(authMode, CONNECTOR_PROXY_MODES)`.
  - `credentialKeyOf(server, { organizationId: cell, userId: turn.userId })` gives the key. Status, token, forced refresh, `needs_reconnect` and last-used all go through that key.
  - The turn's human is still the tenant user, the claim user and the audit user.
  - Approvals, caps and taint run unchanged and before any token is read.
- **No new route, table, RLS policy or permission.** No cross-principal fallback was added.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The fake could not produce "a second 401 after a forced refresh that succeeded"**
- **Found during:** Task 3.
- **Issue:** `revoke_all` also refuses the refresh, so the proxy's `upstream_unauthorized` branch could not be reached on an OAuth server.
- **Fix:** added the fake scenario `reject_access_tokens`. It refuses every access token at the MCP endpoint but revokes no grant, so the refresh succeeds and its new token is refused too.
- **Files modified:** `infra/fake-model/fake-mcp-oauth.mjs`, `infra/fake-model/fake-mcp-oauth.d.mts`
- **Commit:** 0ad6eab9

**2. Test-shape adjustment (no product change): `not_every_participant` / `shared_with_group` are shown in a shared AI chat, not a channel**
- The plan's Task 2 behaviour puts the `not_every_participant` case in a channel. In the code, those two checks run only when the turn has an audience, which only an AI chat has.
- `org_secret` tools are offered in channels the same way today ("the org tool stays").
- The org-tool cases therefore use a shared AI chat for both reasons, and the channel case asserts that the tool is offered with no `member_account` entry. That is the PD-09 truth, "never withheld member_account in a channel with several readers".

**3. Audit metadata before the server is known**
- `credential` was a fixed `"member"` in the call route's base metadata, which also went on `no_trigger` and unknown-connector audits.
- It is now added once the server is resolved, from its mode. Audits written before the server is known carry no `credential`.
- No test asserted the old field on those audits. Every member audit written after the server is found still says `"member"`.
