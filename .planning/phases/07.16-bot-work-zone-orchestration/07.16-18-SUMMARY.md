# Phase 07.16 Plan 18: Back link, agent author and taint marks, live card in chat Summary

**The round trip works: the bot's live Work Zone card in the thread opens the session in one tap, and the session page leads a reader of that conversation straight back to the card ("Back to #eng"). Every viewer sees which prompts the bot wrote, for whom, and which came after outside content.**

## Accomplishments

- **Origin per viewer (D-13, PD-19, E14).** `GET /api/v1/work-sessions/:id` loads the `bot_work_sessions` row and answers
  `origin { conversationId, kind, name, threadRootId, messageId }` only when the viewer `isReadable` the conversation
  (a thread conversation is judged through its parent, as `liveTurn` does). `messageId` is the card, or the asker's
  message once the card is gone. Null for the sponsor (an admin outside private #eng), for Bob after he left #eng
  (still in the session's audience), and for person-started sessions. Never on `ws:` events or the list DTO (the
  `user:` frames' shape). Another organization's member gets a 404 that names nothing.
- **Back link.** `SessionBackLink` sits above the breadcrumb: ghost, 12.5 px, `ArrowLeft`, truncating, 44 px below
  768. Targets come from `sessionBackLink`: channel → `permalinkPath` with the thread and the card, DM/group →
  `/chat/dm/<id>?m=<card>`, AI chat → `/chat/ai/<id>`. No client return URL is read anywhere. Without `origin`
  nothing renders, and the existing "Back to Work Zone" links are untouched.
- **Who wrote it (D-06, D-08).** One `agentRefs` lookup loads the proposer and the author bots of the prompts. The
  session list/detail use the same lookup for `startedByAgent`. `toPrompt` adds `authorAgent` and `tainted`, so the
  detail and the `ws:` `prompt.updated` frames carry them. Soft-deleted bots and cleared columns name nothing.
- **Marks in the UI.** `AgentAuthorLine` renders the bot avatar (16), the name and "· for Víctor" (muted, first name).
  Screen readers hear one phrase, "Atlas, for Víctor Ruiz". `OutsideContentChip` is amber, uses tokens only, and gives
  its reason both as a tooltip and as hidden text. In the queue and the stream, a bot's prompt shows the agent line
  instead of the person line. Any tainted prompt adds the chip. Person prompts keep the same markup and classes.
- **Live card (D-12, PD-12, PD-20).** `AgentCardView` keeps the shell: the "WORK ZONE" kind row, "Created by the
  workspace" badge, status pill and notices. When `workSessionCardOf(card)` is non-null, it adds
  `WorkSessionCardHeading` and `WorkSessionCard`:
  - Heading: runtime logo, the server's title, then "Claude Code · Supervised", or the Full access badge instead of
    the mode.
  - Facts: Device, Model, Step and Updated. Updated is relative and refreshes every 30 s. One column, two from md.
  - Actions: a primary "Open session" to `/work-zone/<id>` and Follow, both 44 px and full width below md.
  - Pill words: Working, Approval, Offline, Stopped, Idle, Ended and Failed.
  - No prompt, output or title text, even when a field carries one.
  - Proposal cards (with `approval`), a bot's own `work_zone` card and a platform card whose Open is not a session
    all render as before.

## Decisions Made

- The heading and the body of the live card live in `work-session-card.tsx`, and `AgentCardView` composes them in the
  shell. This avoids an `agent-card` ↔ `work-session-card` import cycle and keeps the status pill, workspace badge and
  notices identical to every other platform card.
- `origin.name` for a DM or group is the counterpart name from the viewer's own `listDms`. When that is missing (e.g.
  an archived DM) it falls back to the conversation name, or "Direct message"/"Group".
- The relative Updated time uses `relativeTime` ("2 minutes ago"), the same as the queue. A value that is not a time is
  shown as it came.
