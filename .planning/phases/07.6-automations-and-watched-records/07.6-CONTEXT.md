## Implementation Decisions

### Common to phases 07.1–07.7 (orchestrator, 2026-10-08)
- **C-01:** The Control Plane owns the feature. Agents act only through `ocw_*` plugin tools that the Agent Channel API
  decides (resolver, agent ∩ human, taint) and audits; OpenClaw's in-cell equivalents (file memory, cron, webhooks,
  `sessions_send`, exec approvals, per-requester MCP OAuth) stay off (principles 6, 9, 12).
- **C-02:** Contracts first (Zod in `packages/contracts`), RLS on every organization-scoped table with a cross-tenant
  test, an audit event for every sensitive action, `pnpm verify` (incl. `pnpm guard`) green before every commit, TDD.
- **C-03:** UI work is verified at 1440 and 390, light and dark, with reviewed screenshots and e2e through
  `scripts/e2e-isolated.sh`; Woodpecker CI must stay green.
- **C-04:** No new paid or hosted service; any new dependency is pinned, license-checked by `pnpm guard`, and justified.
- **C-05:** Research for this phase: `.planning/research/OPS-FEATURES.md` (the F-numbers below). Code references there
  were taken at `main` 4644fcd; re-check them.

### Phase decisions
- **D-01:** Postgres job scheduler (pg-boss or graphile-worker, MIT; pick in research) — no Temporal, no OpenClaw cron.
  `Automation` = standing order + trigger + delivery target (stable IDs) + run-as person + budget (PRD §73-75) — F9.
- **D-02:** Triggers: signed webhooks (Standard Webhooks, secret in SecretStore) and IMAP mail (verify ImapFlow's
  current license); inbound content is untrusted → read-only turns. Gmail push and WhatsApp are **out of scope**
  (WhatsApp is paid per message and restricts AI assistants; owner decision needed).
- **D-03:** Proactive delivery: extend Agent Channel `/messages` for automation turns to a target; NL creation via the
  existing `automation` card kind, confirmed by a person.
- **D-04:** Watched records (F13): API-computed sha256 over canonical JSON (RFC 8785) of template-watched fields;
  check on access and on schedule through 07.4 connectors; report before → after in the card thread; compare-and-set
  before writes; changes by the agent noted back in the external system when the connector allows it.
- **D-05:** Personal digest (F8): deterministic OCW query, optional LLM summary (metered, opt-in), DM delivery.
- **D-06:** Work Zone → memory (F6): on completed/archived, a server-side summary becomes a 07.2 proposal in the
  project's memory; needs a repository → project unit mapping (design in research); the session owner pays.

- **D-07 (orchestrator, after research):** research design accepted — pg-boss 12 (installed by `ocw_migrator` in
  `runMigrations`; API runs it with `migrate:false`, `reindex:false`, no partitioned queues; enqueue inside our
  transaction; graceful `stop()`); schedules and time zones live in RLS-protected `app.automations` with a one-minute
  tick over an ids-only SECURITY DEFINER function; jobs carry ids only and handlers re-open `withTenant`; each run posts
  a platform-owned `automation` card and delivers `agent.automation_run.v1` with the run-as person as author;
  `turnPolicy.taintedAtStart` for webhook/mail runs, and later turns in a thread started by inbound content start
  tainted; the platform (not the model) creates/updates the thread or board card from inbound content; Standard
  Webhooks via `standardwebhooks` (±5 min, idempotent by `webhook-id`); ImapFlow (MIT); watched-record hash with
  `canonicalize` (RFC 8785) computed by the API, reads through 07.4 connectors, writes through a server-side
  compare-and-set `ocw_record_update`; linking member-credential data into a shared board thread needs a 07.4
  `activeShare` unless the connector uses an org secret; Work Zone repositories map to project units by normalized git
  remote; new usage kinds `digest` and `session_summary`. Owner-facing defaults: the digest is sent by a bot the user
  can DM (personal bot preselected); an automation always runs as its creator (admins may pause/delete others' but not
  run as them); only leads and admins create webhook endpoints (`automation.webhook`); Work Zone summaries = manual
  "Propose to memory" button + opt-in automatic setting, **off by default** (the owner pays). One phase (no sub-split).
  ADR-0028.
- **D-08 (orchestrator):** the existing gap found here — Agent Channel `/messages` and `/cards` accept agent posts with
  no `inReplyToMessageId`, so the cell can post wherever its bot is a member without a human or run behind it — is
  fixed **before phase execution** in a standalone hardening fix together with 07.5's D-05 (delegated-reply check);
  07.6-06 then only adds the automation-run trigger to the allowed triggers.

- **D-09 (orchestrator, after plan check):** watched-record hashes use 07.5's `canonicalJson` (no `canonicalize`
  dependency); only the owner may resume an automation (managers list, pause and delete); the webhook rate limit is
  Redis-backed so it holds across replicas; pg-boss queues are created by the migrator; PR #25 owns the D-08 fix.
