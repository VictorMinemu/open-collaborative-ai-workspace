## Phase Goal

An agent consults or delegates to another agent through the platform, within a permission matrix of who may message
whom, with every hop visible in the thread, audited and bounded (ROADMAP Phase 07.7; A2A-01, A2A-02, A2A-03).

**This plan's slice (tracer, contract level):** one consult round-trips through the contracts: the tool request, the
origin-carrying delivery to the target, the reply event back to the asker, and the thread DTO that renders the hop. Then
the grain, the rule-tool refine, the 07.3 catalog entry and the turn additions.

## Planner decisions (P-01 … P-19)

- **P-01 Split.** 11 plans in 5 waves instead of the research's 5 in 4: the research's API core (decide, deliver,
  return, guard, sweeper, cancel: 12 files and every hard test) and its web plan were each beyond one executor's budget,
  and its split had no owner for the admin rules API before the last wave. ≤ 15 files per plan; no shared file in a wave.
- **P-02 Hardening fix (revised 2026-11-02, D-06).** It is on `main` as PR #25: `/agent-channel/v1/messages` and
  `/cards` accept a post only for a live turn of the posting bot in that conversation, named by `eventId` (when the post
  also names `inReplyToMessageId`, it must be that turn's `message_id`; older cells may name only the message), take the
  human from `agent_turns.user_id` (or a run anchor's run-as person) and let chat re-check that human's `channel.read`;
  anything else is 403 `no_trigger` (`findTurn` / `resolveReplyTarget`, `agent-channel/cards.ts:111-215`). 07.7 never
  re-plans it and adds no trigger code (P-08). 07.7-01 Task 1 asserts the fix is present.
- **P-03 Org switch** ("Bots may consult each other", Settings › Bot policy, off by default, D-04) = exactly one
  organization-scope rule `{subjectKind: "everyone", permission: "agent.message", tool: null, effect: "allow"}`; off = no
  such row = closed. Written through 07.3's `insertRuleRow` / `deleteRuleRow` / `rulesChanged` (per-row audit).
- **P-04 Per-bot rules (admins only in v1, D-04).** Outbound mode `default` (no row) | `any` (`{agent A, allow, tool null}`)
  | `only` (`{agent A, allow, tool agent:<B>}` per B) | `none` (`{agent A, deny, tool null}`); "Never ask" list =
  `{agent A, deny, tool agent:<B>}`; inbound "Other bots can ask A" off = `{everyone, deny, tool agent:<A>}`. All
  organization scope, permission `agent.message`. Deny always wins, so `only` cannot narrow below the org switch: the UI
  disables it while the switch is on and every view shows a server-computed "Right now" summary. Seen with `rule.read`,
  edited with `rule.manage` (both admin-only). Team and unit bots only (personal bots are out of v1).
- **P-05 One canonical decision (D-02, D-04).** `perms.decide(tx, {kind:"agent", agentId: source, onBehalfOfUserId: H},
  "agent.message", {...agentResource(target, null), tool: agentMessageTool(target.id)}, {...agentResource(target, H), tool:
  agentMessageTool(target.id)})`. Agent pass: rules only (closed by default). Human pass: H's role grant, rules, and the
  `unit_agent` + personal-bot preconditions extended to `agent.message` (target visibility). 07.7-03 tests it, 07.7-04 uses
  it for both the offered targets and the request, 07.7-06 proves it at the route for a hidden unit persona.
- **P-06 07.3 module rows stay truthful.** Adding `agent.message` to the Bots catalog would turn every existing complete
  Bots-off set into "custom"; the 07.7-02 migration inserts the missing `agent.message` deny row next to each complete set.
- **P-07 Consult flow (D-01, D-04; revised 2026-11-02, D-07, D-08).** Asynchronous; same thread as the asking turn;
  channels (and their threads) only; the target must already be a member. One route transaction, run as H: the claim,
  then the question posted with `postAgentMessageIn` (author the source agent, body `@<handle> <question>`, key
  `consult:<idempotencyKey>`, in reply to the turn's message, on behalf of H), the chain upsert, conditional budget and
  hop insert in the post's `onInserted` hook, then the target's turn built with `buildMentionEvents` (structural author H,
  `trigger: "consult"`, `chain`) and appended as `agent.mention.v1{origin}` (delivered iff committed). Refusals answer
  `{ok: false, code, sentence}` (403/409 per the table above), nothing posted, recorded by the claim. Agent-typed
  `@handles` stay inert (chat never emits an agent-authored mention; `mentions.ts:92-93` is untouched).
- **P-08 Triggers (revised 2026-11-02, D-06).** No code: a consult hop turn is an ordinary ledger turn, so a post naming
  its `eventId` (and, when given, `inReplyToMessageId` = that turn's `message_id`: the question for the target, the
  answer or the question for the asker) is already accepted by PR #25's rule with H re-checked. 07.7-06 pins the
  positive and negative cases in tests.
- **P-09 Turn done (revised 2026-11-02).** The bridge's `finally` calls `POST /turns/:eventId/done` (`replied` |
  `failed`) for every turn that can belong to a chain (offered `ocw_consult_agent`, carrying `origin`, or a consult
  reply); every other turn sends nothing, as today. A turn that opened a pending `consult` hop never closes its own
  parent; the answer is `agent_turns.reply_message_id`, recorded by the `/messages` and `/cards` `onInserted` hooks
  (first post with that event, D-15). Idempotent: conditional `pending →` update.
- **P-10 Ledger.** A chain is created by the first consult of a root turn (`root_event_id` unique). Every hop counts
  against the budget (refused ones too). Deadline 5 min; opening a child bumps the parent to `≥ child deadline + 2 min`.
- **P-11 Taint (D-04; revised 2026-11-02, D-09).** The consult tool is always side-effecting (the route's claim refuses a
  tainted turn; the plugin's `ALWAYS_SIDE_EFFECTING` blocks it locally); a turn that starts tainted is never offered it;
  the asker's return turn starts with the target turn's taint through 07.6's `AgentMention.taintedAtStart`
  (`agent_turns.tainted` at insert, `turn.tainted` on the event) and its member data like a 07.5 re-run.
- **P-12 The root human pays (D-03, D-04, ADR-0019).** Every hop turn records `user_id = H` (the run-as person for an
  automation root, D-12) and decides tools agent ∩ H; each turn meters its own bot's `dailyLimit`; cell bots run on
  organization models; no `ai_usage_records` row.
- **P-13 07.5 approvals break the chain (D-04; revised 2026-11-02, D-10).** No code: `isApprovableTool` already refuses
  `ocw_consult_agent` (an `ocw_` built-in outside `APPROVABLE_BUILTINS`), so no policy can gate it; card-action turns
  (07.5 re-runs and `applyOwn` decisions included) never carry chain context.
- **P-14 Stop.** The chain's human or a channel moderator (`message.delete_any`); immediate; chain and pending hops
  `cancelled`; late answers still post (visible) but deliver nothing. No in-flight model abort (the cell has none).
- **P-15 Automatic cancel is lazy (07.7-09):** at request, return and sweep time a chain whose thread root is deleted or
  whose human no longer reads the channel is cancelled `auto`.
- **P-16 ADR-0027** (D-04; revised 2026-11-02, D-16) is written in 07.7-02 with `Status: Proposed` so every executor
  reads the design, and 07.7-11 records what shipped and sets it `Accepted` (the 07.6-19 pattern; an accepted ADR is
  never edited). The OpenClaw pins are locked by D-04: if the real cell refuses one of them, 07.7-07 stops and reports
