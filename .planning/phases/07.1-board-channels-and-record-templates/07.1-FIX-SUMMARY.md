# Phase 07.1 Fix: dark destructive contrast, title-only card roots, card editor past 100 Summary

**All three open UI defects from 07.1-14 are fixed test-first on `wt/07.1-fix`.**

1. In dark mode, destructive buttons now meet AA: white text on the fill went from 3.3:1 to 4.9:1, and destructive
   text stays at 5.7:1.
2. A card with a typed title and no description now shows its title in the thread root.
3. *Edit message* on any card root now opens the card editor, including cards past the first 100 of their column. It
   uses one new read route with an org-B case.

## Deviations

1. **[Scope, API change] A new read route.**
   - The web cannot tell a card root from a plain top-level message without the card. A board's Messages view also has
     plain messages, and the editor needs the card's version and fields.
   - The only no-API option was paging every column with `hasMore`, which costs up to N/100 requests per click.
   - The route is contract-first: the response is the existing `BoardCard` and its doc names the route. It has an
     org-B case, and the authz registry guard counts 15 routes.
   - It is not in ADR-0022's text, because accepted ADRs are not edited. ADR-0022's Consequences still list the dark
     destructive contrast as open; this fix closes it.
2. **[Rule 1] The thread panel had the same bug.** *Edit message* on the root of a card past 100 also fell back to
   the inline editor. It now uses the same lookup. That card still has no strip in its thread (07.1-11 open item,
   unchanged).
3. **[Copy] `Join the channel to edit this card.`** This toast appears when the looked-up card's author is no longer a
   member: the card editor is not offered, and the API would refuse the edit.
4. **[Test] Defect 2's e2e was not RED on a pre-fix build.** The unit test was RED first. The e2e was written with the
   fix and is GREEN.
5. **[Process] Commits `f57dda5a` and `6ebdb2e6` are subsets of one verified tree.** `pnpm verify` ran on the combined
   tree.
6. **[Screenshots] Before shots without axe.** The RED run stops at the first axe failure, so the `-before` images came
   from a throwaway copy of the spec with the axe calls removed, run on the same pre-fix build. The copy was deleted
   and not committed.
