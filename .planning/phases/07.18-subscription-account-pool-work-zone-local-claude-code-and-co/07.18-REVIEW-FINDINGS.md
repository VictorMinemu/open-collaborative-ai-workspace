## Gap closure items (07.18-19)

### R1: the daemon and Claude Code (local-runtime)

**R1.1: Overage is not a limit.**
- `status: "rejected"` with `isUsingOverage === true`, or with `overageStatus` set to `allowed` or `allowed_warning`,
  must not send `session.account_limited`. At most it sends a usage reading.
- Evidence: CLI 2.1.331 computes `isUsingOverage = status==="rejected" && (overageStatus==="allowed" || "allowed_warning")`.
- Without the fix, the same turn runs twice and the account is cooled down wrongly.
- File: `apps/local-runtime/src/claude/limits.ts:97`.

**R1.2: Only subscription windows count.**
- An account limit means a rejected `five_hour` or `seven_day*` window. That is CLIProxyAPI's rule: only the 5h/7d
  unified windows take an account out.
- Any other rejection must never cool the account. This covers per-minute limits, overage-only limits and fast-mode
  credits.
- An unknown `rateLimitType` with `status: "rejected"` counts as a limit only when overage is not in use.

**R1.3: No false limits from normal text.**
- Match `USAGE_LIMIT_ERROR_PREFIXES` only on an assistant message that has `error` set, or on a result with `is_error`.
- Never match it on normal reply text.

**R1.4: Unmapped account errors.** Assistant errors `account_on_hold` and `verification_required` map to `auth_failed`.

**R1.5: Complete the strip and pin lists** in `apps/local-runtime/src/claude/pool-env.ts`.
- Add `CLAUDE_CODE_USE_GATEWAY`, `CLAUDE_CODE_USE_MANTLE`, `CLAUDE_CODE_USE_ANTHROPIC_AWS`,
  `CLAUDE_CODE_USE_ANTHROPIC_GOOGLE_CLOUD`, `CLAUDE_CODE_API_KEY_FILE_DESCRIPTOR`,
  `CLAUDE_CODE_OAUTH_TOKEN_FILE_DESCRIPTOR` and `ANTHROPIC_UNIX_SOCKET`.
- The child process has them stripped, and the flag settings pin them empty.

**R1.6: Codex spend-limit errors.** Map `apiKeySpendLimitExceeded`, `projectSpendLimitExceeded` and
`organizationSpendLimitExceeded` to `billing` (`codex/limits.ts`).

**R1.7: Codex credential store.**
- Start each slot's app-server with `-c cli_auth_credentials_store="file"`.
- Check whether Codex 0.172 guards concurrent refresh across processes that share a `CODEX_HOME`. Refresh tokens are
  single-use and rotate; CLIProxyAPI keeps one refresher per account.
- If it does not, serialise so that only one app-server per slot can refresh at a time, for example one shared
  app-server per slot or a per-slot lock around starts. Record the evidence either way.

**R1.8: A device without its own Claude login.**
- When the device's own Claude CLI is not signed in, collect the Claude model catalog with a ready pool token.
- Session titles run on the session's own pool token when the session has one. They must never bill the device
  owner's subscription for a pool session, and they must not fail on a pool-only device.
- Files: `apps/local-runtime/src/daemon.ts:857`, `claude/claude-runtime.ts:342`.

### R2: bots (OpenClaw cell, API, bot model picker)

- Bots then run on subscriptions with no Anthropic API key. When a key exists, it stays last (D-15).
- Files: `apps/openclaw-channel/src/reconciler.ts:447-453`, `apps/api/src/modules/agent/service.ts:369-385`.

**R2.2: Report Claude token health.**

- Files: `openclaw-auth.ts:62-72`, `subscription-auth.ts:310`.

**R2.3: Stable token variable names.** The `OCW_POOL_TOKEN_<n>` name comes from a stable id, such as a short hash of
the account id, never from the account's position in the list (`agent-channel/cell-pool.ts:95`).

### R3: everything from the admin panel

**R3.1: Connect a Claude account from Settings, with no terminal.**
- Reproduce what `claude setup-token` does, the same way CLIProxyAPI runs logins remotely: show the authorize URL,
  then the admin pastes the code or the callback URL back into the panel.
- Read the exact parameters from the installed Claude Code CLI 2.1.331 (the setup-token flow): authorize URL,
  `client_id` `9d1c250a-e61b-44d9-88ed-5944d1962f5e`, the manual redirect URI, scope(s), PKCE S256, `state`, and the
  long-lived `expires_in` it requests.
- The code may arrive as `code#state`; split it.
- The token endpoint takes a JSON body. Every outbound call goes through `apps/api/src/lib/egress.ts`.
- The PKCE verifier lives in Redis for 10 minutes, read once with GETDEL and bound to the admin and the organization,
  following the ADR-0017 pattern.
- The resulting long-lived token is sealed exactly like a pasted setup-token.
- Pasting a token stays as a fallback. The audit and the response never carry a token.
- If the exchange is refused, the panel says so in clear words.

**R3.2: ChatGPT for the Work Zone on a desktop device.**
- An admin who owns the device, or a device whose owner allows it, can start the device-code sign-in from the panel.
- Otherwise the dialog shows the exact `ocw-runtime account add codex --label …` command.
- Files: `add-chatgpt-account-dialog.tsx:86-87`, `device-sign-ins.ts:291`.
