# Phase 07.14 Plan 12: Every connector mode in the MCP server dialog, with Test sign-in Summary

**The MCP server dialog now offers all five auth modes in two groups. It takes client credentials in a single Save, and it asks before a mode switch deletes the organization's account. "Test sign-in" lists every OAuth step, marks which one fails, and shows the fix line. It works before or after saving and never shows provider text.**

## Accomplishments

- **COA-04, every mode in one place.** The Authentication fieldset has two groups, in this order:
  - **For the whole organization:** Organization headers, Organization sign-in, Client credentials.
  - **Each member's own account:** Member sign-in, Member key.
  - Labels, hints and explanations follow PD-12. Cards sit three or two per row at 1440 and stack at 390. The e2e test asserts the order by position at both widths.
  - **Disabled cards say why:**
    - Sandboxed stdio: the four account modes read `Needs a remote server`.
    - No HTTPS: both sign-in modes read `Needs HTTPS`, and the notice reads `Sign-in needs HTTPS. Run pnpm ocw enable proxy on the server, then reload this page.`
- **COA-02, client credentials in one Save.** The fields:
  - **Client ID:** mono font.
  - **Client secret:** write-only. Once saved it reads `Secret set` + `Replace`, and is never prefilled.
  - **Token URL:** optional. It is checked in the browser with the same rule as the API's `trusted()`.
  - **Scopes:** the same field the sign-in modes use.

  Save creates (or updates) the server, then sends the credentials. The row turns `Ready` with the fake's tools and reads `Client ocw-e2e-cc · by … · just now`.
- **When the provider refuses the credentials,** the dialog stays open with `Client credentials failed at: Token.` and the contract's fix line. The server already exists at that point, so the next Save only retries the credentials and never adds the server twice.
- **Organization sign-in** shows the same redirect URI, client metadata URL, pre-registered client, Scopes and CIMD switch as Member sign-in. Switching between the two sign-in modes keeps the typed client fields (D-14).
- **D-08 / PD-11, the confirmation.** Leaving an organization mode while its account is connected asks `Disconnect the organization's account?` before any request is sent:
  - Focus starts on Cancel, and the dialog has `data-kind="org"`.
  - It also opens on a 409 `org_connection_exists`.
  - Only its confirm button sends `clearConnections: true`.
- **D-10, Test sign-in.** The panel shows:
  - the outline `Test sign-in` / `Testing…` button;
  - an `<ol>` of steps, each with an icon and a status word (`Passed` / `Failed` / `Not checked`);
  - the ready line, or `Sign-in fails at: {step}` with the fix line;
  - a polite live region that reads the outcome.

  Around the panel:
  - the redirect URI and client metadata URL copy fields sit under it, and their buttons announce `Copied`;
  - the CIMD hint sits under the client metadata URL;
  - the public-URL warning names both hosts. It is computed in the browser and does not depend on the API's answer.

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The e2e harness needs a `.env`, and this worktree has none**
- **Fix:** same approach as 07.14-11. I generated a throwaway one with `node scripts/setup-env.mjs --project ocw-e2e-0714-12 --ports 39` and never read or printed it.
- **Clean-up:** after the last run, `docker compose -p ocw-e2e-0714-12 down -v` removed its postgres, redis, volume and network, and `rm .env` removed the file. The demo stack was never touched.

**2. [Rule 2 - Correctness] A refused credentials save must not create a duplicate server**
- **Issue:** the plan's sequence is create, then PUT. If the PUT fails, a plain re-Save would POST again.
- **Fix:** the dialog keeps the server as last saved (`saved`) and turns the next Save into an edit of that server, with the update hook keyed by its id.
- **Verification:** the e2e test asserts two creates in total (Records and Billing) and three PUTs after the retry. Commit: `a1da2cfc`.

**3. [Rule 2] `secret_required` (400) handling**
- When the API needs the secret typed again, the dialog opens the secret field and shows the API's sentence under it, instead of a generic form error. Commit: `a1da2cfc`.

The server keeps these values between the two sign-in modes and resets them when it leaves both, so nothing changes for the three 07.4 modes (their e2e PATCH bodies are unchanged). Moving between Organization sign-in and Member sign-in no longer re-sends unchanged fields.
