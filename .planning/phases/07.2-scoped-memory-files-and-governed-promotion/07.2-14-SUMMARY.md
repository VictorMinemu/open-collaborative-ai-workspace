# Phase 07.2 Plan 14: Agent page and the DM memory panel's way into Memory Summary

**Every bot a person can see now has a page at `/bots/<id>`. The Memory tab shows the bot's notebook and the
person's own private memory with it as a tree. On desktop the file renders read-only in place, with "Open in Memory".
The Capabilities tab lists the bot's capabilities, tools and skills, read-only even for its owner. The DM memory panel
keeps all its existing behaviour and now says where the notes live and opens the private `MEMORY.md` in the viewer.
That file updates live when the bot saves a note.**

## What was built

- **Route and page.** `/bots/<agentId>` (`?tab=capabilities`) sits behind `ModuleGate("bots")`.
  - Header: bot avatar (40), name (18/600), Personal or scope badge, owner or unit line, description (1 line on
    desktop, 2 on phones), and Message. On phones Message is full width and 44 px tall, under the header.
  - Underline tabs "Memory · Capabilities", using 07.1's wrapper (R8, no second wrapper).
- **Memory tab.**
  - The tree shows `MemoryTree scopeFilter={{agentId}}`, labelled "{bot} memory files". The notebook comes first, then
    "You & {bot}" if the viewer has private memory with the bot.
  - The notebook scope is ensured once. A 404 means the viewer can't read it, and nothing is shown.
  - From 1024 px: a 280 px tree column next to a `MemoryFile readOnly` pane, with "Open in Memory" (outline sm, ↗) in
    its header. The default file is the notebook's `MEMORY.md`, else the private one. Clicking another file renders
    it in the same pane (R9).
  - Below 1024 px the page is the tree only, and tapping a file opens `/memory/<scope>/<path>`.
  - Live updates are mounted, so an open private file refreshes when the bot saves.
  - States: a skeleton while loading, "Couldn't load memory." with Try again, and "No memory you can open for
    {bot}.".
- **Capabilities tab.** "Read only. Bot settings change these." sits above `CapabilitiesPanel readOnly`. No switch,
  select or input is enabled, even for the owner. The tools section is titled "Tools and skills".
- **Not found.** Someone else's personal bot (admins included) and unknown ids all show one state: "This bot doesn't
  exist or you can't open it" with "Back to Bots".
- **Links.** "Open page" (ghost sm link) on every bot card and in the bot detail sheet (both variants).
- **DM memory panel (additions only).**
  - A note "Kept in your private memory file with {bot}." under the list.
  - "Open in Memory" (ghost sm, ↗) between the count and Clear all. It ensures the private scope, then navigates.
  - In the empty state an outline "Open in Memory" appears once the private scope exists.
  - Footer buttons are 44 px below 1024 and the footer wraps. Every test id, label and behaviour is unchanged.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 3 - Blocking] MemoryFile `readOnly` still showed History and the file menu (`memory-file.tsx`, outside
files_modified)**
- **Issue:** `readOnly` only hid Edit. History (a button at ≥ 1280, a tab at 1024–1279) and the ⋯ menu stayed. There
  was also no place for "Open in Memory".
- **Fix:** with `readOnly` the pane is always one read-only view. There is no Edit, History or ⋯ menu, and a new
  `actions` slot sits in the header.
- No other caller uses `readOnly`. 07.2-13 does not touch this file.
- **Commit:** 4dd93731.

**2. [Rule 1 - Bug] Tree order on the agent page (`memory-tree.tsx`, outside files_modified)**
- **Issue:** `buildMemoryTree` always ranks private scopes first, but the UI-SPEC asks for the notebook first on the
  agent page.
- **Fix:** with `scopeFilter`, the notebook is moved first (stable sort). The viewer's order is unchanged.
- **Commit:** 4dd93731.

**3. [Rule 1 - Regression caught in review] Bot cards overflowed at 390 after adding "Open page" (`bot-card.tsx`)**
- **Issue:** the footer's min-content (full model chip + # + Open page + Message) widened the gallery's single
  implicit grid column, so the page scrolled sideways.
- **Fix:**
  - The card is `min-w-0`.
  - The actions sit in a right-aligned group that wraps to a second row when the model chip would get less than
    8 rem.
- The agent-memory spec now asserts no sideways scroll on the gallery.
- Visible effect: team bot cards at 1440 now have a two-row footer (chip, then # · Open page · Message).
- **Commit:** 4dd93731.

**4. [Rule 2] ToolsSection gained `readOnly` and `title` (`tools-section.tsx`, outside files_modified)**
- `CapabilitiesPanel readOnly` must reach the tool switches; the section decided read-only itself.
- **Commit:** 4dd93731.

### Interpretations

- **The agent page header is not `PageHeader`.** PageHeader's 15 px h1 and single description line can't carry the
  UI-SPEC header. The page uses the same surface (border-b, px-4/px-6).
- **Tab height.** The underline tabs are 40 px from 1024 px (`lg:min-h-10`, wireframe h-10) and the wrapper's 44 px
  below.
- **Phone threshold.** The stacked layout starts below 1024 px (the memory `split` query), not 768. That matches the
  memory viewer and the 44 px rule.
- **"Open page" in the DM settings sheet too.** It is the same `BotDetailSheet`, so the bot page is reachable from a
  DM.
- **Tests run once per project, with no skips.** The bot-memory additions take its axe helper through a dynamic
  `import()`, so the existing import line is unchanged (acceptance: 0 removed lines).
- **Admin fixture.** The team bot's notebook is filled by the admin, who is its owner by default for unit personas,
  not by a unit lead. The admin-blindness assertions are the same either way.
- **Extra screenshots.** `review-bots-gallery-open-page-1440/390`, added for the regression fix.
- **Not committed.** The other specs' screenshots generated during the runs were deleted, not committed.

   it filters by the live bot's id.
