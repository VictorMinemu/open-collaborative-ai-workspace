# Phase 07.6 Plan 02: Automations schema, RLS and ids-only definer functions Summary

**One additive migration (`20261030071129_automations`) creates the 07.6 data model under tenant RLS, makes D-07's
rules database constraints, and gives the job ticks and the public webhook route six ids-only SECURITY DEFINER entry
points; 07.9's `work_project_repos` is reused untouched (D-10).**

## Design (plan mode, P-19)

Tables (all with `organization_id`, so post-migrate forces RLS and adds `tenant_isolation`):

| Table | Key rules |
|---|---|
| `automations` | `run_as_user_id = created_by`; schedule ⇔ cron + zone; target shapes (`dm` none, `channel` conv, `thread` conv + root in that conv, `board` conv + column of that board); inbound action ⇔ webhook/mail, `board_card` ⇒ `board`; digest ⇒ schedule + dm, one per person; runs/day 1..288; status/kind enums; FKs agent/conversation cascade, thread root (root, conv) → messages cascade, column (column, conv) → board_columns NO ACTION |
| `automation_runs` | unique (automation, scheduled_for) and (automation, inbound_event); `trigger = schedule` ⇔ `scheduled_for`; inbound event only for webhook/mail; event FK SET NULL (`inbound_event_id`) |
| `automation_drafts` | stored action of `automation.create`; channel/thread/dm shapes; schedule required |
| `webhook_endpoints` | global unique `public_id` (26 Crockford base32, case-insensitive); automation FK SET NULL (`automation_id`), unique while linked; secret ids plain uuids (as planned) |
| `mailboxes` | one per automation (cascade); keychain item FK SET NULL (`vault_item_id`); port, folder, interval (5,10,15,30,60) checks |
| `automation_events` | exactly one source; unique (endpoint, external_id) and (mailbox, external_id); caps (998/500/320/32768, body_json 128 KiB); purge requires every content column null |
| `watched_records` | one per card; (card, conv) → board_cards cascade; agent, MCP server, conversation composite cascade; sha256 checks; interval in (15,30,60,240,1440) |
| `watched_record_changes` | append-only for `ocw_app` (UPDATE, DELETE, TRUNCATE revoked); cascades with its record |
| `work_session_memory` | PK session (composite cascade); unit FK SET NULL (`unit_id`); 07.9 `audience_backstop` |
| `work_memory_prefs` | PK (organization, user); `auto_propose` default false |

Columns: `bot_policies` caps (10 / 15 / 30 / 96, bounded checks); `message_cards.status_label` (1..24) and `notices`
(array ≤ 3); `secrets.kind` + `webhook_secret`; `ai_usage_records` kinds + `digest`, `session_summary`, nullable
`generation_id` / `conversation_id`, `subject_id`, one two-branch check, unique (subject_id, kind).

Grants: six functions `REVOKE ALL … FROM PUBLIC; GRANT EXECUTE … TO ocw_app`; `REVOKE UPDATE, DELETE` (+ TRUNCATE) on
`watched_record_changes`.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `upgrade.int.test.ts` lists HEAD-only migrations**
- **Found during:** Task 2 verify. The test pins the exact list of migrations after the N-1 baseline, so a new
  migration must be appended (07.11-02 did the same).
- **Fix:** appended `20261030071129_automations` to `HEAD_ONLY`. Plan 03 also edits this file (pg-boss); the change is
  one line at the end of the array.

**2. [Rule 1 - Bug] Board column SET NULL contradicted the board target check**
- **Found during:** Task 1 design. `board_column_id → board_columns set null` would make deleting a targeted column
  fail on `automations_target_check` (a board target needs a column, which Task 2 tests).
- **Fix:** the composite FK (column, conversation) → board_columns is NO ACTION: the column stays until the automation
  moves. Tested (delete refused; a deleted board conversation still takes its automations).

**3. [Rule 2 - Missing critical] Composite FKs and three new composite keys**
- Per the repo rule (FKs bypass RLS, 07.4 #169) every 07.6 reference to a keyed table carries the organization;
  `mcp_servers_org_id_uq`, `vault_items_org_id_uq` and `board_cards_message_conversation_uq` were added as targets.
  Message references (run card, posted item, change reply) stay single-column, as in earlier phases.

**4. [Rule 2 - Missing critical] `work_session_memory` audience backstop**
- The 07.9 backstop covers every table hanging off a session (prompts, approvals, grants); the memory state follows
  the same rule (D-11). User-less job transactions pass, as for the other tables.

**5. [Rule 2] Usage check requires `generation_id IS NULL` for the new kinds**
- The plan's truth says these rows carry "a subject_id and no generation"; the check now enforces both.

**6. Extra bounds** (cheap, no behaviour change): `bot_policies` cap ranges, `notices` array ≤ 3, content caps on
`automation_events`, `content_purged_at` ⇒ content cleared, FK-support indexes.

**Not changed:** `apps/api/src/modules/ai-chat/dto.ts`. `pnpm typecheck --force` is green with the nullable columns;
its only reader already filters `kind = 'chat'`, so no narrowing was needed.

**Process:** RED was not committed separately: AGENTS.md requires `pnpm verify` green before every commit, so each
task's test and implementation share one commit.

- **Usage report (plan 08):** `usageReport` groups by model and counts answers only for `chat`; `digest` /
  `session_summary` rows would show as model rows with 0 answers until labelled like titles.

  (`webhook_endpoints_public_id_check`, case-insensitive).

  event id; a `missed` skip keeps its instant. Reason codes ≤ 64 chars.

- **Usage writers (plans 08/13):** new kinds need `subject_id`, no `generation_id`; one row per (subject, kind).
- **Work Zone memory (plan 08):** user-request writes of `work_session_memory` pass only for people who can see the
  session (backstop); the auto path runs user-less.
