Work goes on when a subscription runs out. An organization keeps a pool of Claude and ChatGPT subscription accounts;
when one reaches its usage limit, the same turn continues on the next one. Once an admin adds accounts, every Work Zone
session and every bot uses them automatically: members do nothing.

## What's new

- **Subscription account pool** (ADR-0044). **Settings › Account pool** (admins) has a Claude section and a ChatGPT
  section, each with its accounts in order, their status (Ready, Cooling until 15:40, Paste a new token / Needs
  sign-in, Off), when each was last used and its usage when the runtime reports it. Subscriptions come first, the
  device's own login next, an API key only last where one is already configured. Guide:
  [docs/self-hosting/account-pool.md](https://github.com/VictorMinemu/open-collaborative-ai-workspace/blob/main/docs/self-hosting/account-pool.md).
- **Claude accounts, from Settings with no terminal:** **Connect a Claude account** opens Anthropic's sign-in page in a
  new tab; paste the code it shows and the server makes the same one-year token as `claude setup-token`. Pasting a
  setup-token still works (**Paste a setup-token instead**). The token is sealed on the server and never shown again.
  **Used by**: Work Zone and bots, Work Zone only, or Bots only.
- **ChatGPT accounts**, signed in where they are used, with a device code:
  - **For bots:** inside the bots runtime, one sign-in per account.
  - **On a device:** for that device's Work Zone sessions, from Settings (any server device, or a computer that is
    yours or shared with you) or with `ocw-runtime account add codex --label …` on the device (it arrives off until an
    admin turns it on). For a computer that is not shared with you, the dialog shows that command with a Copy button.
- **Three strategies** per section: **Use one until its limit, then the next** (the default), **Round-robin** and
  **Weighted**. A session keeps its account until that account hits its limit; accounts are never rotated per request.
- **The switch at a limit.** The limited account cools down until its reset, and the same turn runs again on the next
  ready account, in the same session (up to three times a turn). When none is ready, sessions use the device's own
  login (an admin can turn that off).
- **Members see which account runs their work.** The new-session dialog says "Account: pool (failover)", "This device's
  login" or "No pool account is ready · resets at 15:40". The session header shows the account's label, and the
  timeline says "Switched to account B: A reached its limit until 15:40".
- **Fixes for bots on ChatGPT:**
  - A new ChatGPT sign-in after every bot account was removed now reaches the bots.
  - Turning every ChatGPT bot account off no longer signs them out: turn one back on and it works without a new
    sign-in.
  - Disconnecting ChatGPT in **Settings › Models** also removes its bot accounts from the pool, instead of leaving them
    listed as Ready.

## Upgrade

In `/opt/ocw` (or wherever the server is installed), upgrade the server first:

```bash
sudo node scripts/ocw.mjs upgrade --check   # current and newest release; changes nothing
sudo node scripts/ocw.mjs upgrade           # backup, this release, new keys, rebuild; never goes backwards
```

- **One migration**, additive (`account_pool`). Nothing changes until an admin adds accounts: sessions and bots keep
  running exactly as before.
- **The ChatGPT account already signed in for bots** (Settings › Models) appears as the pool's first ChatGPT account.
  No new sign-in is needed.
- **Devices update so they report pool support.** Headless Work Zone servers on v0.3.1 or later update their runtime
  with one click (Settings › Devices › the server › Runtime updates › **Update**), or by themselves at the *Automatic*
  level. A device that is not updated keeps using its own login.

The desktop app does not update itself: install the new files below. Its runtime ships inside it.

## Known limits

- **Continuing a conversation on another account** (Claude Code and Codex) is built and tested with fakes, but not yet
  checked with real accounts. If it fails, the session says "This conversation could not continue on the next account.
  Start a new session." and the turn fails; it never silently starts over.
- A project whose `.claude/settings.json` sets `apiKeyHelper` gets no pool token; its sessions use the device's own
  login.
- Bots treat **Weighted** as round-robin; Settings says so.
- On a device with only pool accounts (no Claude login of its own), sessions start on the default model and the
  automatic session title is not generated yet.
- AI chats are not in the pool: each member still uses their own ChatGPT plan there.
- **The providers' terms.** Anthropic's and OpenAI's terms restrict sharing subscription credentials; the guide quotes
  them. The organization that adds the accounts owns them and that risk.
